# 화면을 만지는 세션의 기준 (CLAUDE.md §6·§7 — 이 파일이 정본이 되면 CLAUDE.md에서 두 절을 뺀다)

## 프론트엔드 + 화면 검증
- 모든 화면의 기준은 `docs/design/SYSTEM.md`(151KB). 통째로 읽지 말고 목차에서 절을 찾아 Grep + 범위 Read로 필요한 절만 읽는다. 없으면 화면을 만들지 않고 `docs/DESIGN.md` §1부터 시작한다.
- 새 화면·컴포넌트는 `docs/DESIGN.md` §4 절차대로. 새 색·서체·radius 생성 금지, 토큰은 `docs/design/tokens.css`에서만.
- 시스템을 벗어나야 하면 `docs/design/DECISIONS.md`에 이유를 기록한 뒤 SYSTEM.md를 고친다. 화면 하나만 예외 금지.
- UI 완료 판정은 `/design-review`(SYSTEM.md 일관성) → `/qa` 통과 후. 묶음(PR)마다 한 번.
- **화면 검증 순서: 싼 게이트(lint·typecheck·build) → 독립 DOM 감사 → 수정 → 전체 게이트 한 번.** 감사는 실행자가 아닌 별도 에이전트(Sonnet)가 `CI=true`로 DOM을 실측 판정한다(스크린샷 육안 금지). 전체 게이트의 "한 번"은 CI다 — 로컬은 건드린 스펙만.
- 컴포넌트가 된 계약은 지켜지고 산문으로 남은 계약은 어긋난다(Phase 3 실측 26건). 반복되는 지적(폰 44px 터치 영역, 320px 가로 넘침, 포커스 링)은 `test/e2e/mobile-320-no-overflow.spec.ts`처럼 E2E로 만든다.

## 화면 사용성 원칙
- 목표: 사람이 읽고 고민하지 않아도 화면이 다음 행동으로 이끈다.
- 안내 문구는 최소로. 설명문·도움말·자리 표시 설명 대신 이름·아이콘·배치로 뜻이 통하게 한다. 문구는 오류, 되돌릴 수 없는 작업, 잠김 같은 상태에만 한 줄로 쓰고 무엇을 하면 되는지를 말한다(명사형, PR #87 규약). 빈 화면에는 설명 대신 첫 행동 버튼.
- 사용자가 할 결정은 최소로. 알 수 있는 값은 기본값으로 채운다(오늘 날짜, 내 팀, 이전 입력값). 시스템이 계산할 수 있는 것(합계, 세금, 상태 전환 조건)은 묻지 않는다. 할 수 없는 선택지는 숨기거나 비활성화한다. 확인 창 대신 되돌리기, 확인은 되돌릴 수 없는 일에만.
- 행동은 동작·컴포넌트·디자인으로 유도한다. 화면마다 다음 할 일을 주 버튼 하나로. 순서가 있는 일은 단계로, 필요한 값이 채워져야 다음 버튼이 켜진다. 입력 칸이 형식을 잡아 준다(숫자 쉼표, 날짜 선택, 검색해서 고르기). 키보드만으로 엑셀처럼 입력·이동·저장. 상태는 색·배지로, 위험한 동작은 떨어뜨려 둔다.
- UI-SPEC·플랜·`/plan-design-review`·`/design-review`는 "문구 없이 이해되는가, 사용자가 하지 않아도 될 결정이 남았는가"를 점검한다. 사용자가 이미 정한 결정은 바꾸지 않는다.
