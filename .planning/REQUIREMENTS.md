# Requirements: PLANT8 ERP — 프로젝트·지출·손익 관리 시스템

**Defined:** 2026-09-17
**Core Value:** 기획본부와 경영관리본부가 프로젝트마다 같은 숫자를 본다. 기획본부는 계산식·근거 없이 결과 숫자로 납득하고, 경영관리·대표는 근거 줄까지 본다.

## v1 Requirements

Requirements for initial release. Each maps to roadmap phases.

### 인증·계정 (AUTH)

- [ ] **AUTH-01**: 관리자가 직원 계정을 만들고 초기 비밀번호를 발급하면, 직원은 이메일+비밀번호로 로그인한다
- [ ] **AUTH-02**: 로그인 세션은 브라우저를 다시 열어도 유지되고, 어느 화면에서든 로그아웃할 수 있다
- [ ] **AUTH-03**: 직원은 비밀번호를 바꿀 수 있고, 관리자는 비밀번호를 재발급할 수 있다
- [ ] **AUTH-04**: 로그인 방식은 환경 변수로 선택된다(기본 이메일). Google 로그인 추가가 코드 구조를 바꾸지 않는다

### 마스터·코드표 (MAST)

- [ ] **MAST-01**: 거래처·클라이언트를 등록·수정하고, 미사용은 삭제 대신 숨김 표시한다. 입력 시 자동완성된다
- [ ] **MAST-02**: 직원 등록 = 사람 + 계급 + 팀 선택. 입사자 추가에 코드 수정이 없다
- [ ] **MAST-03**: 법인카드 마스터: 직원별 개인 지급 카드와 팀 전용 카드를 등록하고, 카드마다 소지자(직원) 또는 소속 팀을 지정한다
- [ ] **MAST-04**: 견적 대분류·소분류, 지급 방식, 프로젝트 상태 같은 코드표를 관리 화면에서 추가·수정·비활성화한다

### 프로젝트·견적 (PROJ)

- [ ] **PROJ-01**: 프로젝트를 등록·목록·상세로 다룬다(클라이언트, 담당 PM, 팀, 기간, 상태)
- [ ] **PROJ-02**: 견적 줄 원장에 견적가·실행가(예상 원가)를 입력하면 차익은 서버가 계산한다. 브라우저 계산값은 저장하지 않는다
- [ ] **PROJ-03**: 프로젝트에 매출 최소 칸(계약 금액, 세금계산서 발행일·발행액, 입금일·입금액)을 기록한다. 별도 매출 모듈은 없다
- [ ] **PROJ-04**: 프로젝트 상태를 진행 → 완료(정산)로 바꿀 수 있고, 완료된 프로젝트에는 새 지출결의를 올릴 수 없다
- [ ] **PROJ-05**: 이전 프로젝트·견적 줄을 복사해 새로 만들 수 있고, 반복 입력 칸은 기본값이 채워진다
- [ ] **PROJ-06**: 완료(정산) 처리 시 시스템이 미결 지출결의·미매칭 견적 줄·매출 미입력을 점검해 이유와 함께 막는다. 강행 허용 여부는 설정

### 지출결의·결재·법인카드 (EXP)

- [ ] **EXP-01**: 견적 줄에서 "지출결의 올리기"를 누르면 거래처·금액·프로젝트가 자동으로 채워진다. 같은 값을 다시 적지 않는다. 지출결의는 견적 줄 단위로 생성된다(여러 줄을 골라도 문서는 줄마다 하나)
- [ ] **EXP-02**: 지출결의 한 건을 화면 하나에서 작성·증빙 첨부·제출까지 끝낸다
- [ ] **EXP-03**: 결재는 기본 4단(팀장→본부 책임자→경영관리→대표), 빈 자리는 건너뛴다. 승인·반려(기안자에게 복귀)·회수가 된다
- [ ] **EXP-04**: 결재선은 제출 시점에 문서에 고정된다. 이후 설정 변경이 진행 중 문서에 영향을 주지 않는다
- [ ] **EXP-05**: 결재자는 결재 대기함에서 폰으로도 승인·반려한다
- [ ] **EXP-06**: 결재를 통과하지 않은 지출결의는 지급 완료 처리가 되지 않는다
- [ ] **EXP-07**: 직원은 자기 카드·자기 팀 카드의 사용을 등록하고 견적 줄(또는 팀 비용)에 연결한다. 연결 없는 카드 사용은 서버가 막는다(이중 계산 방지)
- [ ] **EXP-08**: 프로젝트 없이 팀 이름으로 지출(수주 실패 비용, 팀 관리비)을 올릴 수 있고 종류를 구분한다
- [ ] **EXP-09**: 경영관리가 지급 예정일을 정하고 지급 완료 처리한다
- [ ] **EXP-10**: 온라인 구매 요청: 직원이 품목·링크·금액·연결할 견적 줄(또는 팀 비용)을 적어 경영관리에 신청하면, 경영관리가 법인카드로 구매하고 구매 완료 처리한다. 완료된 요청은 법인카드 사용 건으로 연결된다(신청/구매 완료/취소, 결재 없음)
- [ ] **EXP-11**: 지급 예정일을 적지 않아도 시스템이 거래처별 지급 기한(기본 작성일+60일, 거래처별 조정)과 "기한 전 마지막 금요일" 규칙으로 자동 계산해 보여 준다. 규칙은 설정
- [ ] **EXP-12**: 결재 마감은 지급일 전 영업일 14시(설정). 마감이 지나면 그 주 지급 대상에서 빠지고, 공휴일이 끼면 마감일과 알림이 함께 앞당겨진다
- [ ] **EXP-13**: 증빙 없이 먼저 결제한 지출결의는 "선결제" 표시와 사유가 필수이고, 14일(설정) 안에 증빙이 없으면 독촉 알림이 가되 처리는 막지 않는다
- [ ] **EXP-14**: 지출결의는 제출 시 금액이 0보다 커야 하며 음수를 입력할 수 없다. 매출·조정 항목은 환불·할인을 위해 음수를 허용한다

### 증빙 (EVID)

- [ ] **EVID-01**: 세금계산서·영수증·카드 전표 파일을 지출결의·법인카드 건에 첨부한다(폰 사진 포함)
- [ ] **EVID-02**: 증빙 필수 규칙이 켜져 있으면 증빙 없는 건은 지급 완료가 되지 않는다. 규칙은 설정에서 on/off
- [ ] **EVID-03**: 증빙 금액을 기록하면 그 줄의 확정 비용이 된다
- [ ] **EVID-04**: 증빙을 떼면 그 줄의 비용은 다시 예상(견적 실행가 또는 지출결의 승인액) 상태로 돌아간다

### 손익 (PNL)

- [ ] **PNL-01**: 프로젝트 상세 상단에 네 숫자(견적 / 예상 비용 / 확정 비용 / 수익금액·수익률)가 보인다
- [ ] **PNL-02**: 줄마다 가장 굳은 값 하나만 비용으로 든다: 증빙액 > 지출결의 승인액 > 견적 실행가. 진행 중에는 예상값이 든다
- [ ] **PNL-03**: 매출 기준(계산서 발행액 / 계약 금액 / 입금액)과 연도 귀속 날짜(발행일 / 종료일 / 입금일)를 설정에서 고르고, 화면에 현재 기준이 표시된다. 완료 전(매출 미확정)에는 상세 견적 합(없으면 사전 견적)을 분모로 쓰고, 완료 뒤에는 설정된 매출 기준을 쓴다
- [ ] **PNL-04**: 경영관리·대표는 손익 숫자에서 근거 줄(견적 줄·지출결의·증빙)까지 내려가 보고, 계산식은 설정 화면에 보인다
- [ ] **PNL-05**: 기획본부는 결과 숫자만 본다. 자기가 입력한 견적·지출과 숫자가 어긋나지 않고, 같은 용어·단위로 즉시 반영된다
- [ ] **PNL-06**: 완료(정산) 처리된 프로젝트의 손익은 스냅샷으로 고정되고, 이후 설정 변경에 소급되지 않는다. 완료 뒤 계약 금액·매출이 정정되면 스냅샷은 재계산하지 않고 차이만 표시한다
- [ ] **PNL-07**: 팀 손익 = 팀 프로젝트 손익 합 − 수주 실패 비용 − 팀 직접 관리비. 팀장은 자기 팀, 대표·경영관리는 전체를 본다
- [ ] **PNL-08**: 프로젝트·팀 손익 목록을 Excel로 내보낸다. 정보 노출표가 내보내기에도 적용된다
- [ ] **PNL-09**: 모든 금액 입력·계산·표시는 공급가액(부가세 제외) 기준이며 화면에 명시된다. 부가세율(기본 10%)은 적용 시작일이 있는 이력형 설정이다

### 연간 목표·인센티브 (GOAL)

- [ ] **GOAL-01**: 팀별 연간 목표(매출·이익)를 입력하고 달성률·진행률이 보인다. 팀장까지 열람한다
- [ ] **GOAL-02**: 인센티브 계산 규칙을 설정에 두고 달성 시 금액을 계산한다. 대표·경영관리만 열람한다
- [ ] **GOAL-03**: 어느 프로젝트가 어느 해 성과인지는 손익과 같은 연도 귀속 설정을 쓰고 화면에 표시된다

### 알림 (NOTI)

- [ ] **NOTI-01**: 앱 안 알림함과 미읽음 배지가 있다
- [ ] **NOTI-02**: 같은 알림이 이메일로도 간다
- [ ] **NOTI-03**: 관리자가 설정에서 알림 규칙을 새로 만든다: 대상 문서(지출결의·구매 요청·결재·증빙·프로젝트·연차), 조건(상태 + 기준일로부터 N일 전/후), 받는 사람(계급·담당자·팀장), 채널. 기본 규칙 4개(종료 후 지출결의 없음, 지급 예정일 임박, 결재 대기 초과, 증빙 미첨부)는 시드로 제공
- [ ] **NOTI-04**: 같은 건이 두 번 발송되지 않는다. 스케줄러가 하루 몇 번 호출하는 단일 엔드포인트로 동작한다(큐 없음)

### 연차 (LEAV)

- [ ] **LEAV-01**: 직원이 연차를 신청하면 결재 모듈로 승인되고 잔여 일수가 차감된다. 연차 일수는 관리자가 연 1회 설정한다

### 기타소득 확인증 (CERT)

- [ ] **CERT-01**: 외부 인력에게 1회성 링크를 보내면 폰에서 서명·주민등록번호·계좌를 제출한다(로그인 없음)
- [ ] **CERT-02**: 주민등록번호는 앱 단에서 암호화 저장되고, 열람은 권한자로 제한되며 열람 기록이 남고, 보존 기간 뒤 파기된다
- [ ] **CERT-03**: 제출된 확인증을 해당 지출결의 건에 연결한다
- [ ] **CERT-04**: 개인 지급(기타소득·사업소득) 건에는 원천징수 제안 금액이 자동 계산되어 뜨고(세율·면제 기준은 이력형 설정, 기본 기타소득 8.8%·사업소득 3.3%·5만원 이하 면제), 경영관리가 확정하면 지급액에 반영된다
- 활성화 조건: `/cso` 보안 감사 통과

### 코드 없는 운영 (ADMN)

- [ ] **ADMN-01**: 권한표: 계급 × 메뉴 × 동작(보기/쓰기/승인) 체크박스
- [ ] **ADMN-02**: 정보 노출표: 계급 × 정보 항목(손익 숫자·팀 비용·목표·인센티브·거래처 금액 등). 기획본부 기본값은 인트라넷 수준, 새 기능 정보는 기본 숨김
- [ ] **ADMN-03**: 정보 노출은 화면·API·Excel 내보내기·자동완성·검색에 동일하게 적용된다(우회 경로 없음)
- [ ] **ADMN-04**: 결재 단계·담당 계급, 규칙 on/off, 알림 시점·대상, 세율·수식을 설정 화면에서 바꾼다
- [ ] **ADMN-05**: 설정 키는 레지스트리 한 곳에 등록되며 설정 화면이 자동 생성된다. 등록된 키를 서버가 읽는지 테스트가 강제한다
- [ ] **ADMN-06**: 설정을 JSON으로 내보내고 빈 환경에 가져온다
- [ ] **ADMN-07**: 관리자가 프로젝트·견적 줄·거래처에 텍스트/숫자/날짜/선택 4종 칸을 추가하면 입력·목록·검색·내보내기에 반영된다
- [ ] **ADMN-08**: 계급 종류를 추가·이름 변경한다(데이터)
- [ ] **ADMN-09**: 문서 번호 서식(프로젝트·견적·지출결의·구매 요청·연차 등)을 설정에서 정의한다: 접두어·연도·순번 자릿수·구분자·순번 범위(전사/프로젝트별). 예: 프로젝트 26001, 지출결의 26001-0001. 번호 부여 시점: 지출결의는 제출 시, 구매 요청은 생성 시
- [ ] **ADMN-10**: 대표·경영관리·관리자가 행동 로그 화면에서 핵심 로그 위주로 보고, 사람·기간·행동 종류·문서로 걸러 Excel로 내보낸다(사고 증거·인사평가 참고용). 어떤 행동을 핵심으로 남길지는 설정에서 고른다. 열람 권한은 정보 노출표로 통제
- [ ] **ADMN-11**: 영업일·공휴일: 법정 공휴일 규칙으로 매년 후보가 자동 생성되고 관리자가 검토·확정·수동 추가한다. 지급일·마감·알림 계산이 이 표를 쓴다
- [ ] **ADMN-12**: "지우지 않는다": 사용자가 무엇을 삭제해도 보관함으로 이동하며, 관리자만 보관함에서 보고 복원할 수 있다. 삭제·복원은 행동 로그에 남는다

### 데이터 이전·전환 (MIG)

- [ ] **MIG-01**: 인트라넷 데이터를 옛 표 구조 그대로 가져오지 않고, 새 시스템의 표·코드표·상태·번호 서식에 맞게 변환해 입력한다. 원본 행마다 새 시스템의 대응 행이 있음을 검증한다(멱등·재실행)
- [ ] **MIG-02**: 차익 불일치(66줄)·고아 견적 줄(5)은 고치지 않고 표시만 한다
- [ ] **MIG-03**: 결재 상태를 인트라넷 3단 → 새 4단으로 매핑하고, 법인카드 433건의 견적 줄 연결을 유지한다
- [ ] **MIG-04**: 평문 비밀번호는 이전하지 않고 계정을 새로 발급한다
- [ ] **MIG-05**: 리허설을 반복한 뒤 전환일에 인트라넷을 조회 전용으로 바꾸고 새 시스템만 입력한다

### 배포·운영 (OPS)

- [ ] **OPS-01**: 배포 스크립트 한 번으로 새 GCP 프로젝트에 기동한다. 프로젝트 ID·리전·DB 접속은 환경 변수
- [ ] **OPS-02**: 사용 없을 때 비용이 0에 가깝고(스케일-투-제로), 월 비용 목표가 문서화된다
- [ ] **OPS-03**: DB가 자동 백업되고 복원 절차가 문서화되며 복원 리허설을 1회 한다
- [ ] **OPS-04**: 린트(`any` 금지)·타입체크·핵심 흐름(로그인→지출결의→결재→손익) 통합 테스트가 CI에서 돈다
- [ ] **OPS-05**: 직원 계정별 핵심 행동만 로그로 남긴다: 로그인, 문서 생성·제출·승인·반려·회수·삭제, 지급·구매 처리, 설정·권한 변경, 민감 정보(손익·인센티브·주민등록번호) 열람. 단순 조회·화면 이동 같은 잡음은 남기지 않는다. 관리자는 로그를 정리(수정·삭제)할 수 있다

### 기획본부 편의·디자인 (UX)

기준: 260907의 화면·정보구조·UI 흐름은 참고하지 않는다. 세련되고 깔끔하며 사용자 편의 우선으로 `docs/DESIGN.md` 절차로 새로 설계한다.

- [ ] **UX-01**: `docs/design/SYSTEM.md`를 먼저 확정하고 모든 화면이 그 토큰·컴포넌트만 쓴다
- [ ] **UX-02**: 역할별 첫 화면: PM(내 프로젝트·내 지출결의), 경영관리(나갈 돈·결재·미증빙), 대표·팀장(손익)
- [ ] **UX-03**: 폰에서 결재·조회·지출결의 작성이 된다(반응형)
- [ ] **UX-04**: 잘못된 입력은 서버 검증으로 즉시 안내되고, 저장 실패·중복 저장·입력값 유실이 없다
- [ ] **UX-05**: 모든 데이터 입력을 키보드만으로 끝낼 수 있고, 표 입력(견적 줄·법인카드·목표 등)은 엑셀과 같은 키 구성을 따른다: Tab/Enter·방향키로 칸 이동, 여러 칸 복사·붙여넣기, Esc 취소, 단축키로 저장·새 줄
- [ ] **UX-06**: 화면에 안내 문구를 두지 않는다. 규칙과 절차는 행동 유도로 습관이 되게 한다: 다음 할 일이 한 곳에 보이고, 선행 단계가 끝나기 전에는 다음 동작이 비활성이며, 필수 항목·증빙이 빠지면 제출 버튼 자체가 이유와 함께 막힌다
