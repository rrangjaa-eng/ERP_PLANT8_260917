(1) **서체 자산.** `docs/design/NEXT-SESSION.md` §B의 명령대로 `pretendard@1.3.9` tarball에서 파일만 복사한다 — npm 의존성으로 넣지 않는다(D-32 locked). 받는 곳은 `public/fonts/pretendard/`이고 라이선스 파일, 동적 서브셋 스타일시트, woff2 디렉터리 셋을 옮긴다. 서브셋 CSS는 원본 그대로 쓴다 — unicode-range 92분할과 `font-display: swap`과 variations 포맷이 이미 들어 있어 고칠 것이 없다. 외부 CDN을 쓰지 않는다.

(2) **토큰과 전역 CSS.** `app/layout.tsx`에서 `docs/design/tokens.css`를 상대 경로로 직접 import한다(D-21 — 복사본을 만들지 않는다). `<head>`에 서체 스타일시트 링크 한 줄을 넣는다. `metadata` export와 `<SessionRefresh />`는 손대지 않는다 — SessionRefresh는 sliding 세션 쿠키 연장 장치이고 빠져도 화면은 똑같아 보인다. `app/globals.css`는 기존 box-sizing 블록을 그대로 두고 body의 서체를 `--font-sans`로 지정하는 선언만 덧붙인다. 그 밖의 어떤 컴포넌트 스타일도 globals.css에 넣지 않는다 — 전부 CSS Modules다(D-19).

(3) **첫 `ui/` 컴포넌트.** `ui/button/Button.tsx`와 그 옆의 CSS Module을 만든다. props로 위계(1차·2차·3차), 진행 중 여부, 비활성 사유 문자열, 단축키 표기를 받는다. §7-1이 규정한 것을 그대로 옮긴다: 위계별 면·테두리·글자색, 높이 PC 32 · 폰 40, 좌우 패딩, radius 0, 진행 중이면 자신과 같은 폼의 다른 버튼이 비활성이 되고 라벨 뒤에 진행 표시가 붙는다, 비활성이면 사유를 옆에 글자로 쓴다(사유 없는 비활성 금지, UX-06). 스피너를 만들지 않는다. 붉은 버튼을 만들지 않는다. CSS Module의 모든 색·서체·radius 값은 `var(--…)` 참조여야 한다 — 02-02의 stylelint가 리터럴을 막는다. 실물 HTML의 흰색 리터럴은 같은 계산값의 배경 토큰 참조로 옮긴다.

**1차 버튼 위 `kbd` 테두리는 §7-1이 적은 대로만 쓴다.** 실물의 `.btn.p kbd` 덮어쓰기 한 줄은 `tokens.css`에 대응 토큰이 없는 유일한 선언이고, 그 처리 방식은 02-01 Task 1 항목 I에서 사람이 골라 §7-1에 문장으로 들어와 있다. 세 가지 중 무엇이 골라졌느냐에 따라 이 태스크가 하는 일이 다르다 — 기존 토큰(①)이면 §7-1이 적은 그 토큰을 참조하고, 새 토큰(②)이면 02-01 Task 3이 `tokens.css`에 정의한 그 이름을 참조하고, 덮어쓰기 제거(③)면 1차 버튼용 `kbd` 규칙 자체를 이관하지 않는다. **어느 경우에도 §7-1에 없는 색 값을 새로 고르지 않는다.** 그리고 **세 경우 모두 이 파일에 색 리터럴이 0개여야 한다** — 02-01이 「좁은 stylelint 예외」를 선택지에서 뺐으므로 `stylelint.config.mjs`에 이 선언을 위한 예외는 없고, 이 태스크에는 그 파일을 고칠 권한이 없다(02-02의 `files_modified`다). §7-1이 리터럴을 요구하는 형태로 적혀 있다면 그것은 재계획 신호이므로 멈춘다.

(4) **한 경로 연결.** `app/(auth)/login/login-form.tsx`의 제출 버튼을 이 `Button`으로 갈아끼운다. 나머지 동작은 전부 보존한다 — 자격 호출, 이메일/비밀번호를 구분하지 않는 실패 문구, 성공 시 이동, 오류 문단의 alert 역할, Google 로그인 버튼의 조건부 표시. 입력 요소는 아직 그대로 둔다(Task 2가 바꾼다). 버튼 이름으로 찾는 E2E 선택자가 그대로 동작해야 하므로 보이는 라벨 문자열을 바꾸지 않는다.
