`ui/status-tag/StatusTag.tsx`와 CSS Module: §7-5 그대로. 의미 토큰 다섯(위험·경고·강조·성공·흐림)에 대응하는 종류 prop, 테두리는 현재 글자색, 배경 없음, radius 0. 표 상태 열용 변형(테두리 없이 색 글자만)을 같은 컴포넌트의 변형 prop으로 둔다 — §7-5가 그 둘을 구분한다. 태그 내용은 두~네 글자 명사 문자열이고 문장을 받지 않는 것을 호출부 규약으로 SUMMARY에 남긴다.

**이 컴포넌트를 02-06이 아니라 여기서 만드는 이유**: §7-5는 「테두리 태그는 「내 차례」와 화면 제목 옆에서만」이라고 규정했고, 이 페이즈에서 태그가 실제로 쓰이는 첫 자리가 바로 아래의 「내 차례」 한 줄이다. 뒤 플랜에서 만들면 이 플랜이 태그 자리를 문자열 슬롯으로 두게 되고, 만든 쪽은 꽂을 곳이 없어 아무 화면에도 배선되지 않은 컴포넌트가 남는다.

`ui/next-turn/NextTurn.tsx`와 CSS Module: Task 1의 계산 결과를 받아 그대로 그린다. **한 줄의 첫 요소인 태그는 위 `StatusTag`로 렌더한다** — 문자열 자리표시자를 두지 않는다. 컴포넌트 안에서 정렬·절단을 다시 하지 않는다. 결과가 「블록을 그리지 않음」이면 아무것도 렌더하지 않는다 — 빈 상태 문구를 대신 넣지 않는다(§7-4가 명시적으로 금지). 넘침 건수가 있으면 남은 건수를 담은 3차 버튼을 마지막 줄에 둔다. 한 줄에서 이유와 다음 한 수가 반드시 같은 줄에 있어야 한다(브리프 검증 질문 1). 폰에서는 두 줄로 접힌다 — 1행 태그·대상·행동, 2행 금액·이유. 이 접힘은 CSS 미디어 쿼리로 한다.

`ui/list-empty/ListEmpty.tsx`와 CSS Module: §7-7 EMPTY의 한 줄. props는 무엇이 없는지와 다음 한 수(3차 버튼 또는 링크)다. 그림·일러스트·아이콘을 넣지 않는다. 안내 문구를 넣지 않는다. 다음 한 수 없이 원인만 렌더할 수 없도록 다음 한 수를 필수 prop으로 둔다 — 타입이 §8 규칙 3을 강제하게 한다.

**표 뼈대를 만들지 않는다.** §7-7의 표 행이 전제하는 머리글·합계 뼈대는 표 컴포넌트가 있어야 성립하고 그것은 Phase 4다. 이 페이즈의 EMPTY는 표 없이 서는 한 줄이고, 그 이탈은 02-01이 DECISIONS.md에 기록했다.
