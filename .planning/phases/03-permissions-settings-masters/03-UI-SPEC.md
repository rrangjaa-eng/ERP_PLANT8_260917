## SYSTEM.md §7 신설 초안 (D-40 핵심 산출물)

> 아래 두 절은 `docs/design/SYSTEM.md` §7(컴포넌트 규칙)에 그대로 삽입될 초안이다. 기존 §7-1~§7-12와
> 같은 문체·구조를 따른다. 코드 작성 전에 실제 `SYSTEM.md`에 옮겨 적고 `DECISIONS.md`에 신설 사실을
> 남기는 것이 계획 단계의 첫 태스크여야 한다(CLAUDE.md 프론트엔드 규칙).

### 7-13. 체크박스 매트릭스 (권한표 · 정보 노출표)

§7-3 표와 분리된 별개 컴포넌트다(D-40) — 정적 격자 + 체크박스이며 다행 편집·범위 복사·오류 셀
inset 선 같은 §7-3의 기계장치가 없다. `ui/permission-grid/`에 둔다(두 화면이 재사용, `DESIGN.md`
§4 규칙 3).

**구조**
- `<table>` + 시각적으로 숨긴 `<caption>`. `role="grid"`가 아니다 — 셀 편집이 없어 §7-3의 grid
  기계장치(활성 셀·`aria-selected`·`aria-readonly`)가 필요 없다. 행 머리글 `<th scope="row">`(계급
  이름), 열 머리글 `<th scope="col">`
- **권한표**: 행 = 계급(시드 5종 + 추가분), 열 = 메뉴 × 동작(보기/쓰기/승인) 2단 머리글 — 1행은
  메뉴 이름(`colspan=3`), 2행은 동작 이름. 셀 = 체크박스 1개
- **정보 노출표**: 행 = 계급, 열 = 정보 항목(단일 단 머리글, 그룹 없음). 셀 = 체크박스 1개
- 머리글: `--fs-sm --muted` 600, §7-3의 "편집 가능한 표" 신호를 그대로 물려받아 `--g-100` 바탕 +
  `--g-950` 글자 — 체크박스 격자도 값을 바꾸는 컨트롤이기 때문이다
- **열이 많아지면(권한표, 메뉴×동작 조합) 가로 스크롤.** 행 머리글(계급 열)은
  `position: sticky; left: 0` + 오른쪽 `1px --line-strong` 구분선. 열 머리글은
  `position: sticky; top: 0`(정보 노출표는 항목 수가 늘면 세로 스크롤도 생기므로 함께 필요). 두
  sticky가 겹치는 좌상단 모서리 셀은 `--g-100`으로 채워 배경이 끊기지 않게 한다
- 세로선 없음(§4-2). 메뉴 그룹 경계만 `1px --line`으로 표시

**체크박스**
- 네이티브 `<input type="checkbox">`. `accent-color`는 §4-4의 `--native-accent` — §1-3의 "포인트
  색 다섯 곳" 규칙과는 별개이며 새 accent 사용처를 추가하는 것이 아니다
- 터치 목표: 체크박스를 감싸는 `<td>`의 클릭 영역을 PC 32×32 · 폰 44×44로 채운다(§3). 셀 전체가
  클릭 가능
- 화면에 텍스트 라벨을 두지 않는다(격자 좌표가 라벨이다) — 대신
  `aria-label="{계급} · {메뉴} · {동작}"`(권한표) / `aria-label="{계급} · {정보 항목}"`(정보
  노출표)로 접근성 트리에 좌표를 문장으로 만든다

**전체 · 행 · 열 선택**
- **열 머리글에 체크박스 하나** — 그 열 전체를 켜고 끈다. 값이 섞여 있으면 네이티브
  `indeterminate` 상태로 보인다
- **행(계급) 단위 전체 선택은 두지 않는다.** 계급 하나에 딸린 모든 항목을 한 번에 켜는 것은 실수로
  광범위한 권한을 부여하는 사고 위험이 크고, 열 단위 선택으로 이미 대량 변경이 가능하다(YAGNI —
  D-38과 같은 결)
- 열 머리글 체크박스 클릭 = 그 열의 모든 셀에 개별 저장 호출을 순차로 보낸다(배치 API 없음 — 이
  페이즈의 액션은 셀 단위 하나뿐, D-38)

**저장 시점과 피드백**
- **셀 하나 = 즉시 저장.** 클릭하면 체크 상태가 먼저 바뀌고(낙관적) 서버 호출이 뒤따른다. 「일괄
  저장」 버튼이 없다 — 성공 기준 2("바꾸면 즉시 메뉴·동작·응답 필드가 바뀐다")가 이것을 요구한다
- 성공: **체크 상태 자체가 결과다.** 별도 토스트·완료 표시 없음(§7-1 SUCCESS "행동한 자리에서
  결과가 보인다"와 같은 논리)
- 300ms 넘게 걸리면 그 셀만 `--surface` 배경으로 지연 표시(§7-7 LOADING 지연 규칙), 짧으면 아무것도
  보이지 않는다
- 실패: 체크 상태를 원래 값으로 되돌리고(낙관적 되돌림) 그 셀에 `1px --danger` 테두리 + hover/focus
  시 이유 한 줄(§7-2와 같은 자리, "원인 · 다음 행동": `저장하지 못했습니다 · 다시 시도`) + **§7-6
  토스트**로도 같은 메시지(`권한 저장 실패 · 다시 시도`) — 화면을 안 보고 있어도 알아야 하는 드문
  실패라 토스트를 쓴다(§7-3 "표 저장 결과는 토스트 없음"의 예외 — 이 격자는 합계 행이 없어 결과를
  모아 보여줄 자리가 없다)
- 열 머리글 일괄 토글 중 일부만 실패하면(PARTIAL) 실패한 셀만 원위치 + 오류 표시, 나머지는 성공
  상태 유지, 토스트는 한 번(`권한 저장 · N칸 중 M칸 실패 · 다시 시도`)

**다섯 상태**

| 상태 | 모양 |
|---|---|
| LOADING | 머리글 뼈대 + `--surface` 행 3개(§7-7과 같음) |
| EMPTY | **해당 없음** — 계급은 시드 5종이 항상 있고(ADMN-08) 메뉴·정보 항목도 코드 레지스트리 시드가 항상 있다. 빈 격자가 되는 경우가 없다 |
| ERROR | 격자 자리에 한 줄 `--danger`: `권한표를 불러오지 못했습니다 · 다시 시도`(정보 노출표는 같은 문구를 그 이름으로) |
| SUCCESS | **해당 없음** — 「저장 시점과 피드백」대로 체크 상태 자체가 결과이고 별도 SUCCESS 표시가 없다 |
| PARTIAL | 열 일괄 토글 중 일부 실패(위) 또는 계급별로 서버가 아예 안 보낸 열(정보 노출표가 자기 자신에게 적용될 때 — §7-3 "칸 수 가변" 규칙과 같은 논리, 서버가 안 보낸 열은 클라이언트가 숨기지 않고 처음부터 없다) |

**키보드 · 스크린리더**
- 별도 방향키 로빙 없음 — 네이티브 `<table>` + 체크박스이므로 `Tab`/`Shift+Tab`이 DOM 순서(행
  우선, 왼쪽→오른쪽)대로 이동하는 것으로 충분하다(§7-3의 `role="grid"` 방향키 기계장치를 다시
  만들지 않는다 — D-40의 취지)
- `Space`로 체크 토글(네이티브 동작)
- 스크린리더 읽기 순서는 DOM 순서와 같다: 계급 행 진입 시 `<th scope="row">`가 먼저 읽히고, 각
  체크박스는 `aria-label`로 메뉴·동작(또는 정보 항목)을 반복해 말한다 — 좌표를 시각적 위치가 아니라
  문장으로 전달한다
- 열 머리글 체크박스의 `aria-label`: `"{메뉴} · {동작} 전체 선택"`(권한표) /
  `"{정보 항목} 전체 선택"`(정보 노출표)

**폰(375px)**
- 격자를 그대로 그리지 않는다(가로 스크롤 금지 원칙은 §7-3과 같다 — 이 컴포넌트는 §7-3이 아니지만
  같은 원칙을 물려받는다). 대신 **선택→목록**으로 축을 접는다: 화면 위에 계급을 고르는 네이티브
  `<select>`(§7-2) 하나, 그 아래 선택된 계급의 항목을 §7-8 「시트 상세」와 같은 `dl` 골격(`KvList`
  재사용 — 라벨 = 메뉴·동작 또는 정보 항목, 값 자리에 체크박스, 터치 44×44)으로 세로 나열
- 이 화면은 관리자 전용 설정 화면이라(ADMN-01/02, 관리자 운영 콘솔) PC 사용이 기본이고 폰은
  확인·긴급 수정용이다 — 위 대안은 그 용도로 충분하다(모든 조합을 폰에서 빠르게 편집하는 것을
  목표로 하지 않는다)

### 7-14. 이력 목록 (이력형 설정 값 · 발령일 이력)

두 곳에서 재사용된다: 설정 레지스트리의 이력형 키(예: 부가세율)와 사람 폼의 팀 소속 발령일
이력(MAST-02) — `DESIGN.md` §4 규칙 3(두 곳 이상)을 만족해 정식 컴포넌트로 둔다(`ui/history-list/`).

**구조**
- §6-3 폼 화면의 한 섹션(2px 선으로 시작)에 §6-1 목록과 같은 얇은 표: 열 = **적용 시작일 · 값 ·
  상태 · (동작)**. 적용 시작일 내림차순(최신이 위)
- 오늘 기준으로 유효한 행(가장 최근의 `적용 시작일 ≤ 오늘`인 행)에 §7-5 상태 태그 `적용 중`
  (`--success`, text 변형 — 표 안이므로). 미래로 예정된 행은 `예정`(`--muted`)
- 각 행 값은 레지스트리 스키마 타입에 따라 §7-2 규칙대로 렌더(아래 「필드 렌더 규칙」과 같은
  매핑) — 읽기 전용 텍스트, 입력이 아니다
- **추가는 새 행, 수정은 없다.** 「새 이력 추가」 3차 버튼이 폼 하단에 열리고(모달 아님 — §7-8
  모달은 위험 행동 확인용이라 이 목적에 맞지 않는다) 적용 시작일(날짜 입력) + 값(타입별 §7-2
  입력) 두 칸을 이 표의 맨 위 행 자리에 편집 가능한 행으로 펼친다. 저장하면 새 행이 되고
  취소(Esc)하면 사라진다
- **미래로 예정된(`예정`) 행만 삭제할 수 있다.** 3차 「취소」 버튼 + §7-8 확인 모달(사유
  불필요 — 아직 적용되지 않은 예정값을 지우는 것은 되돌릴 수 있는 일이다). 이미 적용된(`적용 중`
  또는 과거) 행은 동작 칸이 비어 있다 — 이력은 append-only다(행동 로그·보관함과 같은 감사 원칙)

**다섯 상태**

| 상태 | 모양 |
|---|---|
| LOADING | 행 3개 `--surface` 뼈대 |
| EMPTY | `이 값의 이력이 없습니다 · 새 이력 추가`(§7-7 규칙대로 다음 한 수 포함) — 대부분 시드가 항상 1행 있어 드문 경우다 |
| ERROR | `이력을 불러오지 못했습니다 · 다시 시도` |
| SUCCESS | 새 행 추가 성공 시 그 행이 목록에 나타나는 것 자체가 결과(§7-7 표 SUCCESS와 같은 논리), 토스트 없음 |
| PARTIAL | **해당 없음** — 이력 목록은 전부 오거나 오류이거나 둘 중 하나다 |

## 적용 규칙 (기존 §7 항목에 붙는 세부 규칙 — 새 절 아님)

### 자동 생성 설정 화면 필드 렌더 규칙

registry 타입 → §7-2 입력 매핑:

| registry 타입 | §7-2 입력 | 비고 |
|---|---|---|
| boolean | 체크박스(네이티브, §4-4 `accent-color`) | 라벨 = 설정 이름, 라벨 자체가 클릭 영역 |
| number | 텍스트 입력, 우측 정렬 `tabular-nums` | 퍼센트·정수 등 단위는 입력 밖 정적 글자로 병기(`10` `%`) — 단위를 입력 안에 넣지 않는다(§7-2 "자리표시자는 형식 예만") |
| string | 텍스트 입력 기본 | |
| enum | 네이티브 `<select>`(§7-2) | 커스텀 드롭다운 금지 규칙 그대로 |
| 이력형(모든 하위 타입) | §7-14 이력 목록 | 이력형 여부는 값 타입과 독립된 별도 축 — 이력형 + number면 이력 목록의 "값" 칸이 숫자 입력 |

**설정 저장 시점**: 비이력형 필드는 §7-13과 같은 즉시 저장(텍스트는 blur, 체크박스·select는
change) — 검증 실패(zod)는 §7-2 오류 규칙(입력 아래 원인·다음 행동)으로, 별도 「저장」 버튼·일괄
저장 없음. 이력형은 §7-14의 「새 이력 추가」 자체가 저장 동작이다.

**설정 화면 구성**: §6-2 상세 화면처럼 탭 없이 섹션(2px 선)으로 이어진다. 섹션 = registry 키의
namespace(예: 「세율」 「로그인 잠금」 「번호 서식」). 섹션 안 필드는 §6-3 폼의 라벨-입력 규칙(라벨
96px, `--fs-sm --muted`)을 그대로 쓴다.

### 마스킹된 값의 표시와 해제 (거래처 계좌번호, MAST-01)

- 목록·상세 기본 표시: 뒤 4자리만, 나머지 `*`(예 `****-**-1234`) — 텍스트, 입력 아님
- 「번호 보기」 3차 버튼이 값 옆에 있다 — **단, 마스킹 해제 권한(정보 노출표 항목)이 없는 계급에게는
  서버가 이 버튼이 필요로 하는 기능 자체를 노출하지 않으므로 버튼이 처음부터 렌더되지 않는다**
  (§7-1 "이유 있는 비활성" 대신 "버튼 자체가 없음" — ADMN-03의 우회 경로 없음 원칙과 일치. 권한이
  없다는 사실 자체를 화면에 노출하지 않는 편이 안전하다)
- 클릭하면 §7-1 진행 중 패턴(라벨 뒤 `…`, `번호 보기…`) → 성공 시 라벨 자리가 실제 번호로 바뀌고
  3차 버튼이 「가리기」로 바뀐다(다시 누르면 마스킹 복귀, 클라이언트 상태일 뿐 재복호화 호출 없음)
- 실패: §7-2와 같은 자리에 `번호를 불러오지 못했습니다 · 다시 시도`
- 이 해제 호출은 OPS-05가 요구하는 핵심 행동 로그(설정으로 못 끄는 로그)를 남긴다 — 화면에는 로그
  남김을 알리는 별도 표시를 두지 않는다(사용자가 매번 알아야 할 정보가 아니다, §8 규칙5)

### 비활성화 표현 (코드표 · 거래처, MAST-01/04)

- **"보관함"(ADMN-12, 삭제→복원)과는 다른 메커니즘이다.** 코드표·거래처의 "숨김"/"비활성화"는
  되돌리기 쉬운 상태 플래그이고 목록·수정 화면에 계속 보인다(완전히 사라지는 삭제가 아니다). 보관함은
  실제 "삭제" 행동에 대한 것이다 — 둘을 같은 UI로 섞지 않는다
- 목록(§6-1)의 상태 열에 §7-5 상태 태그(text 변형, `muted` kind): 코드표는 `비활성`, 거래처는
  `숨김`(REQUIREMENTS 원문 용어를 그대로 따른다, §8 규칙7)
- 목록은 **기본적으로 비활성/숨김 항목을 빼고 보여준다.** 표 위 필터 줄(§6-1)에 3차 토글 `숨김
  포함`을 두면 전부 보인다
- 상태를 바꾸는 동작은 행 안 3차 버튼(`숨기기`/`보이기`, `비활성화`/`활성화`) — 되돌릴 수 있는 상태
  변경이라 확인 모달 없음, 즉시 반영. 상태 태그 자체가 결과라 토스트 없음(§7-13과 같은 논리)
- 비활성/숨김 항목은 자동완성·선택 목록에서 **서버가** 제외한다(리포지토리 필터 지점 — ADMN-03과
  같은 지점이지 화면 쪽 필터가 아니다)

### 계급 5종 전환 시 §6-0 임시 행 제거

`SYSTEM.md` §6-0의 폰 하단 탭 표에 있는 「관리자·직원」 두 임시 행(D-14 시절 계급 모델)은 이
페이즈가 계급 5종 + `role-menu.ts` 데이터 교체로 실제로 없어진다(`DECISIONS.md` 2026-09-19 항목이
이미 이 해소 시점을 이 페이즈로 지정해 두었다) — 이 UI-SPEC이 그 해소를 실행한다는 사실만 기록,
표 내용 자체는 이미 §6-0에 있어 다시 옮기지 않는다.
