# Phase 4 — UI Design Contract

> 프로젝트·견적 원장. `docs/design/SYSTEM.md`(950행) + `docs/design/tokens.css`(196행)가 이미 확정돼
> 있으므로 **이 문서는 새 시각 언어를 만들지 않는다.** 이 페이즈의 표면 9개(컴포넌트 4 + 화면 5)가
> 만족해야 할 계약을 SYSTEM.md 절 번호에 못 박고, SYSTEM.md가 다루지 않는 지점을 숨기지 않고
> 이름을 붙여 남기는 것이 산출물이다.
>
> **인용 규칙**: 아래 모든 계약은 절 번호를 단다. 절 번호 없이 적힌 문장은 계약이 아니라 이
> 문서의 판단이며, 그런 항목은 §「SYSTEM.md가 다루지 않는 것」에 전부 모아 두었다.

## Typography

`SYSTEM.md` §2-2·§2-3·§2-4 그대로. 굵기는 **400 · 600 · 700 세 단계만**(§2-1).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body(표 셀 · 목록 행 · 폼 입력) | `--fs-base` 14px(폰 15px) | 400 | 1.5(표) / 1.6(본문) |
| Label(폼 라벨 · 표 머리글 · 서버 계산 한 줄 · 외화 2행 · 오류 한 줄) | `--fs-sm` 12px | 600(라벨·머리글) / 400(부가 정보) | 1.5 |
| Heading(화면 제목 = 프로젝트 이름) | `--fs-lg` 18px | 700 | 1.4 |
| Display | **이 페이즈에 없음** — `--fs-xl`/`--fs-2xl`은 인쇄·외부 수령자·대시보드 KPI 전용(§2-2). 원장·상세·폼에 큰 숫자를 두지 않는다(§2-2 안티슬롭 문장) |
| 상태 태그 · 행 번호 · `kbd` | `--fs-xs` 11px | 600 | 1.4 |

**한 화면 4단계 이하**(§2-2). 이 페이즈의 모든 화면은 xs·sm·base·lg 넷으로 끝난다.

**숫자 형식(§2-4, 이 페이즈가 전부 쓴다)**
- 원화: 정수 + 천 단위 쉼표, 단위 기호 없음, 열 머리글에 「(원)」도 쓰지 않는다.
- 음수: 하이픈 마이너스. **괄호 금지 · 붉은색 금지** — 매출·조정 항목의 환불·할인(EXP-14)이 여기 걸린다.
- 0은 `0`, 값 없음은 `—`. 빈칸 금지. 계산 불가는 `계산 불가 · 환율 없음`.
- 외화: **두 줄 병기**. 1행 원화 환산액(정수), 2행 `--fs-sm --muted` `USD 4,400.00 @1,318.1818`.
- 날짜 `2026-09-18` · 표 안 같은 해 `09-18` · 기간 `09-12 ~ 09-16` · 시각 `14:00`.
- 문서 번호: 서버 서식 그대로, 모노 아님, `tabular-nums` (`26001` · `26001-1차`).
- 모든 숫자 칸: **우측 정렬 · `tabular-nums` · `white-space: nowrap`**. 폭이 모자라면 숫자를 꺾지 않고
  열을 접는다. 합계 행만 700.

## Color

`SYSTEM.md` §1 의미 토큰만. **새 색 0개.**

| Role | Value | Usage |
|------|-------|-------|

| Accent (10%) | `--accent` = `--g-700` `#005446` | §1-3의 **다섯 곳만** |
| Destructive | `--danger` `#9B1C1C` + `--danger-weak` `#FBE9E9` | 오류 셀 배경·좌측 인셋 선·이유 한 줄. **붉은 버튼 없음**(§7-1 — 위험 행동은 색이 아니라 확인 모달) |
| 보조 | `--success`(저장됨·승인) · `--warning`(이 페이즈 사용처 없음) · `--muted`(대기·미착수) · `--line`/`--line-ui`/`--line-strong` | §1-2 |

**Accent reserved for** (§1-3 규칙 1, 다섯 곳에서 늘리지 않는다):
① 「내 차례」 태그·행동 링크(이 페이즈 사용처 없음) ② **편집 중 셀·행**(§7-3 셀 밑줄 + 활성 셀 2px
외곽선) ③ **1차 버튼**(「일괄 저장 N」 · 「프로젝트 등록」) ④ `:focus-visible` 링 ⑤ 현재 위치(상단 바
밑줄, 셸이 이미 구현).

- 표 상태 열의 상태 색은 §7-5 **색 글자만**(테두리 태그 아님). 테두리 태그는 「내 차례」와 화면
  제목 옆에서만.
- 오류 **셀**만 `--danger-weak`으로 채운다. 행 전체를 붉게 칠하지 않는다(§1-3 규칙 3).
- 그린 틴트는 상단 바를 빼면 면이 아니다 — 딥그린 면은 앱에서 상단 바 하나뿐이다(§1-3 규칙 4).

## 컴포넌트 계약 1 — `ui/form` (§6-3)

**골격**
- 한 열, `max-width: var(--form-max)`(720, `tokens.css:116`), **왼쪽 정렬**(§3 「가운데 정렬하지 않는다」).
- 머리 줄(제목 · 번호 · 상태 태그)도 같은 720 기둥에 맞춘다(§6-3 원문).
- 묶음 사이 `--s-6` + `1px --line`, 항목 사이 `--s-4`, 라벨-입력 세로 `--s-1`(§3).
- 라벨: PC 왼쪽 열 고정폭 `--label-w`(96) `--fs-sm --muted` 600, 폰은 위로(§6-3·§7-2). **`TextField`가
  이미 이 규칙을 구현하고 있다** — `ui/form`은 그것을 폼 전체로 넓히는 그릇이다.
- 칸 폭 변형: `select` 200 · `short` 280 · `long` 480 · 폰 전폭(§6-3). API 형태(prop vs 변형 클래스)는
  Claude 재량(04-CONTEXT).
- 필수 표시 `*` 없음(§7-2) — 필수인데 비면 **제출 버튼이 이유를 말한다**.

**A-H3을 닫는 지점(이 컴포넌트의 존재 이유 절반)**
- `<form noValidate>`. 네이티브 `required` 말풍선을 첫 관문에서 **걷어낸다**.
- 빈 필수 칸이 있으면 1차 버튼 비활성 + 옆에 이유(§7-1 「비활성 버튼은 이유를 옆에 글자로」 ·
  §6-5의 「막힘 = 1차 버튼 비활성 + 빈 칸 전부 나열」과 같은 형태): `등록할 수 없음 — 클라이언트 ·
  기간 2칸`.
- 그 이유 텍스트는 `role="alert"`가 **아니라** 버튼의 `aria-describedby`로 연결한다(§10 — 사용자가
  누르기 전에 읽힌다).
- 서버 검증 오류는 §7-2: 입력 테두리 `--danger` 1px + 입력 아래 `--fs-sm --danger` 한 줄
  「원인 · 다음 행동」 + `aria-invalid` + `aria-describedby`. **입력값은 지우지 않는다**(§7-2).
- 서버 계산 값은 입력 **바로 아래 한 줄**(§6-3): `--fs-sm --muted`, 숫자만 700. 읽기 전용 행을 따로
  두지 않는다.

**다섯 상태(§7-7 「폼(지출결의)」 행을 그대로 옮긴다)**

| 상태 | 모양 |
|---|---|
| LOADING | 자동 채움 칸 `—` + 상단 2px 진행 바. 누른 버튼은 라벨 뒤 `…`, 같은 폼의 다른 버튼도 비활성(§7-1) |
| EMPTY | **해당 없음** — 등록 폼은 항상 칸 전체가 렌더되고 빈 상태가 없다(§6-7 로그인 폼과 같은 논리) |
| ERROR | 입력 아래 `원인 · 다음 행동`, 값 보존, 1차 버튼은 **살려 둔다**(§6-3) + 버튼 옆 `등록하지 못했습니다 · 기간 1칸 · 값은 남아 있습니다` |
| SUCCESS | 버튼 자리에 `등록됨 · 26001`(`--success`) + 3차 `프로젝트 열기` + 토스트. 입력은 읽기 전용(§6-3) |
| PARTIAL | 1차 버튼 비활성 + 옆에 `등록할 수 없음 — 이유 · 다음 한 수`(§7-7 폼 행) |

**폰**: 제출 줄은 하단 탭 위에 얹혀 고정, 1차 버튼 `--touch-min`(44) 넓게, 막힘 이유는 그 아래
한 줄. 본문 아래 여백 = 탭 44 + 제출 줄 높이(§6-3).

## 컴포넌트 계약 3 — `ui/table` (§6-1 읽기용 원장)

**구조(§7-3 「구조」 블록은 읽기용·편집용 공통이다)**
- `<table>` + **시각적으로 숨긴 `<caption>`**(§10) + 열 머리글 `<th scope="col">` + 행 머리글이
  성립하면 `<th scope="row">` → **A-M3을 닫는다.**
- 머리글: `--fs-sm --muted` 600, 아래 `1px --line-strong`, 스크롤 시 sticky(`--z-sticky`).
  **읽기용 표는 흰 바탕**(§7-3) — `--g-100` 바탕은 편집용 신호이므로 쓰지 않는다.
- 행: 아래 `1px --line`, hover `--surface`, 높이 `--row-min`(36 / 폰 44), **고정 높이 금지**.
- 그룹 머리글 행: `--fs-sm --muted` 600, 위 `--s-3`, 아래 `1px --line-strong`.
- 합계 행: 위 `2px --line-strong`, `--fs-base` 700. (읽기용이므로 `--g-100` 바탕 없음)
- **세로선 없음**(§4-2). 첫 칸(행 번호) `--fs-xs --faint`, 폭 28.
- 열 폭: 문자 열 `auto`, 숫자 열은 자릿수 고정(`ch`). 항목명은 `keep-all` 줄바꿈 허용, 거래처는
  한 줄 말줄임(§7-3).
- 페이지네이션 대신 `더 보기 50건` 3차 버튼(§6-1).

**폰 칸 접기(§7-3 — `ui/grid`와 공유하는 유일한 로직, D-46)**
- 모든 열이 **P1 / P2 / P3**을 선언한다. `<700px`에서 P1만 열로 남고, P2는 행 아래 **접힌 줄**
  하나(`--fs-sm --muted`, 라벨 없이 `값 · 값 · 값`, 열 순서대로), P3은 숨는다.
- **P1은 최대 3열 — 항목(문자 1) + 금액(숫자 1) + 상태 또는 행동(1).** 넘기면 시스템 위반이고
  `/design-review`가 잡는다(§11).
- 합계 행 부제는 폰에서 숨기고 합계는 P1 금액 열만. 그룹 머리글·합계 행은 폰에서도 남는다.
- **가로 스크롤 금지 · 카드 전환 금지**(§7-3). 태블릿 700–1023은 P3만 숨긴다(§6-0).

**행 동작의 접근 가능한 이름 → A-M7을 닫는다**
- 행 안 3차 버튼·링크는 `aria-label="{행 이름} · {동작}"`으로 행 맥락을 문장에 넣는다 —
  §7-13이 이미 쓴 「좌표를 문장으로」 규약과 같은 형태. 예: `aria-label="26001 아이오닉9 쇼케이스 · 견적 열기"`.

**칸 수 가변(정보 노출표, §7-3)**: 열은 **서버가 계급에 따라 아예 보내지 않는다.** 클라이언트에서
숨기지 않는다. 빠진 열의 폭은 문자 열이 흡수하고, 합계 행은 남은 열만으로 성립한다. 빈 칸을 `—`로
채우지 않는다(있는데 값이 없을 때만 `—`).

**다섯 상태(§7-7 「표(목록·편집)」 행)**

| 상태 | 모양 |
|---|---|
| LOADING | 머리글·합계 행 뼈대 + 본문 자리 `--surface` 행 3개. 반짝임 없음, 300ms 안에 끝나면 아무것도 보이지 않음 |
| EMPTY | 본문 자리 한 줄 `무엇이 없다 · 다음 한 수` + 3차 버튼(`ListEmpty` 재사용) |
| ERROR | 본문 자리 `--danger` 한 줄 + 2차 `다시 시도` |
| SUCCESS | **해당 없음** — 읽기 전용 표는 행동 결과를 표시할 자리가 없다(§7-7 「손익 원장」 행과 같은 논리) |
| PARTIAL | `계산 불가 N건` 배지(`--fs-xs --muted` 테두리 태그) + 합계는 계산된 것만. 빈 자리를 0으로 채우지 않는다 |

**D-47 경계**: 이 페이즈는 컴포넌트만 만들고 **프로젝트 목록·리저브 대장에만 쓴다.** 관리자 읽기

Phase 7까지 열려 있다.

## 컴포넌트 계약 4 — `ui/grid` (§7-3 편집용, D-45 자체 구현)

**표 골격은 `ui/table`과 같고(위) 아래가 더해진다.**

**편집 가능 신호(§7-3)**: 머리글 **`--g-100` 바탕 + `--g-950` 글자**. 합계 행도 `--g-100` 바탕.
「읽기 모드/편집 모드를 나누지 않는다 — 편집 권한이 있으면 표는 항상 편집 가능하다」(§7-3).

**키 구성(§7-3 · UX-05 — 계약이다, 재량 아님)**

| 키 | 동작 |
|---|---|
| 셀 클릭 · Enter | 편집 시작 |
| Tab / Shift+Tab | 좌 / 우 이동 |
| Enter | 아래 이동 |
| ↑ ↓ ← → | 이동 |
| Esc | 취소(값 되돌림) |
| ⌘C / ⌘V | 범위 복사 · 붙여넣기. **붙여넣기 범위가 표를 넘으면 새 줄 자동** |
| ⌘↵ | 새 줄 |
| ⌘S | 일괄 저장 |
| ⌘D | 줄 복제 |
| Delete | 줄 삭제(**확인 모달** — GAP-2) |
| ⌘E | 현재 줄로 지출결의 — **Phase 5**. 이 페이즈에서는 배선하지 않고 힌트 줄에도 넣지 않는다 |

클립보드는 **네이티브 `copy`/`paste` DOM 이벤트 + `clipboardData.getData("text/plain")` TSV 파싱**
(04-CONTEXT Claude 판단). `navigator.clipboard`를 쓰지 않는다 — 권한 프롬프트·보안 컨텍스트 조건이
붙고 Playwright에서 `grantPermissions`가 필요하다.

**셀 상태(§7-3 · tokens.css 130~132행 — 전부 기존 토큰)**

| 상태 | 모양 | 토큰 |
|---|---|---|
| 편집 중 행 | 배경 `--g-50` + 셀에 `--accent` 밑줄(테두리 없음, §7-2 「표 안 입력」) | `--g-50` · `--accent` |
| 저장 대기(dirty) 셀 | `inset 0 0 0 1px --g-600` 외곽선 | `--inset-dirty` |
| 선택 범위 | 배경 `--g-50`, 활성 셀 `2px --accent` 외곽선 | `--g-50` · `--accent` |
| 오류 셀 | `--danger-weak` 배경 + 좌측 `2px --danger` 인셋 선. **다른 셀을 편집해도 고정된다** + hover/포커스에 이유 한 줄(`--fs-sm --danger`, 셀 아래 인라인) | `--danger-weak` · `--inset-error` |
| 충돌 셀 | 오류 셀과 **같은 모양**, 이유 = `다른 사람이 14:01에 9,800,000으로 바꿈 · 덮어쓰기 / 그 값으로`(D-48 — 서버가 바뀐 값을 함께 돌려주면 「그 값으로」가 성립한다) | 위와 같음 |

**일괄 저장(§7-3 · UX-05)**: **전부 저장 또는 전부 거부.**
- 실패: 오류 셀 고정 + 합계 행 오른쪽 `오류 1칸 · 전부 거부`(`--danger`). 나머지 입력은 보존.
- 성공: 같은 자리에 `저장됨 6줄 14:02`(`--success`), 편집 행 배경이 600ms 동안 `--g-50` → `--bg`
  (`--dur-saved`).
- **토스트를 띄우지 않는다**(§7-6 — 합계 행에 이미 있다).
- 합계 행의 저장 결과는 `aria-live="polite"`(§10).

**외화 2행(§7-3 · §2-4)**
- 금액 셀 `vertical-align: top`. 외화가 있는 행만 금액 셀이 두 줄이 되고 같은 행의 다른 셀은 첫 줄
  기준 정렬. **행 높이 고정 금지.**
- **편집은 원화가 아니라 외화 금액·환율 두 칸에서 하고 원화는 계산값(읽기 전용)이다.**
- 합계 행은 **원화만**. 외화 합계를 만들지 않는다.
- 폰에서는 2행이 접힌 줄(P2)로 내려가고 P1 셀 안의 2행은 숨긴다(같은 정보를 두 번 보이지 않는다).

**폰(§7-3)**: **셀 편집 없음.** 행 탭 → 하단 시트(§7-8)에서 상세와 행동. 접힌 줄에 외화 2행·거래처·
날짜·오류 이유가 들어간다.

**접근성(§10 — 이 컴포넌트에만 붙는 계약)**
- `role="grid"` · 셀 `role="gridcell"` · 활성 셀 `aria-selected` · 편집 중 `aria-readonly="false"`.
- 오류 셀 `aria-invalid="true"` + `aria-describedby`로 이유 연결.
- 단일 tabbable 셀 + roving tabindex(ARIA grid 패턴). 포커스 순서 = 시각 순서.
- 단축키 힌트 줄(§7-9)은 이 표가 있는 화면 하단에 **항상** 보이고 폰에서는 숨는다.

**다섯 상태**: §7-7 「표(목록·편집)」 행 그대로. SUCCESS·PARTIAL이 `ui/table`과 달리 **해당 있음**이다
(합계 행이 결과 자리를 갖는다).

## 화면 계약 5 — 프로젝트 목록 (§6-1)

- **템플릿 §6-1 목록 = 원장.** 「내 차례」 블록은 **없다**(§6-1 — 역할별 첫 화면에만 있다).
- 필터 줄 한 줄(표 위): `프로젝트 125` · `[상태 ▾]` · `[내 것만]` · `[2026 ▾]` · 검색 · 1차
  `프로젝트 등록`. 필터 패널·사이드바 없음. 열 머리글 클릭 = 정렬(§6-1).
- 그룹 머리글로 나눈다(§6-1) — 기본 그룹은 **상태**(수주중 / 진행 / 완료(정산) / 미수주).

## 화면 계약 7 — 프로젝트 상세 (§6-2)

**§6-2 상세 화면 = 견적 원장. 탭 없음 — 섹션(2px `--line-strong`)으로 아래로 이어진다.**

**머리 줄**: 화면 제목 = 프로젝트 이름(`--fs-lg` 700) · 부제 `{번호} · 상세 견적 2차 · 진행`
(§6-2 원문 형태) · 오른쪽 2차 `복사해 새 차수` + 1차 `일괄 저장 N ⌘S`(§7-1 1차 1개).

**「네 숫자 줄」(PNL-01)은 이 페이즈에 렌더하지 않는다.** §6-2가 요구하는 넷 중 **확정 비용·수익**은
지출이 생기는 Phase 5·6과 손익 Phase 9의 몫이고, 비어 있는 자리를 0이나 `—`로 채우는 것은 §7-3
(「있는데 값이 없을 때만 `—`」)·§7-7 PARTIAL(「빈 자리를 0으로 채우지 않는다」) 둘 다에 어긋난다.
이 페이즈에서 견적 · 실행가 · 차익 합계는 **견적 줄 표의 합계 행**이 담당한다(§7-3).

**섹션 1 — 매출 칸(PROJ-03)**: `ui/form` 골격을 상세 화면 안의 한 섹션으로 쓴다.

| 칸 | 기준 | 컨트롤 | 폭 |
|---|---|---|---|
| 계약 금액 | 공급가액 | 금액 | 280 |
| 세금계산서 발행일 | — | 날짜 | 280 |
| 발행액 | 공급가액 | 금액 | 280 |
| 입금일 | — | 날짜 | 280 |
| 입금액 | **통장에 들어온 합계(부가세 포함)** | 금액 | 280 |

- 계약 금액·발행액 아래 §6-3 서버 계산 한 줄: `부가세 10% 1,240,000 · 합계 13,640,000 · 서버 계산`.
- 입금액 아래 같은 자리: `공급가액 12,400,000 역산 · 계산값과 30,000 차이 · 서버 계산`
  (`grossFromTotal()`, ROADMAP 기준 5). 차이가 0이면 뒷 조각을 쓰지 않는다.
- **음수 허용**(EXP-14 환불·할인). 표시는 §2-4 하이픈 마이너스, 괄호·붉은색 금지.

**섹션 2 — 견적 차수 + 고객 승인**
- 차수 선택: `ui/select` 200 — `사전 견적` / `상세 견적 1차` / `상세 견적 2차`(D-51 — 정수 저장,
  표시 시점 조립).
- 고객 승인 표시: §7-5 색 글자 `승인`(`--success`) / `승인 전`(`--muted`) + 3차 `고객 승인 표시`.
- **이전 차수는 `ui/grid`가 아니라 `ui/table`로 렌더한다**(D-55 읽기 전용). 근거: §7-3이 머리글
  색(`--g-100`)을 **편집 가능하다는 신호**로 규정하므로, 편집할 수 없는 차수를 편집용 표로 그리면
  그 신호가 거짓이 된다. §7-3의 「읽기 모드/편집 모드를 나누지 않는다」는 같은 데이터에 모드
  토글을 두지 말라는 규칙이고, 여기서는 게이트가 편집 권한 자체를 거부한다(D-56).

**섹션 3 — 견적 줄 표**: `ui/grid`. 열과 우선순위(§6-2 실물 + §7-3 P1 3열 상한):
- 행 번호(28px) · 대분류/소분류(P3) · 항목(**P1** 문자) · 거래처(P2) · 견적가(P2) ·
  실행가(**P1** 금액) · 차익(P3, 정보 노출표로 빠질 수 있음) · 상태(**P1**).
- 「견적 외 비용」 줄은 견적가 0인 같은 표의 한 종류다(`docs/inputs` §8) — 별도 표·별도 화면을
  만들지 않는다. 상태 열에 §7-5 `--muted` 색 글자 `견적 외`.
- 「취소」 상태 줄(PROJ-02 — 연결 문서가 있어 삭제할 수 없는 줄): 상태 열 `--muted` `취소`, 견적가 0,
  이력 유지. 행 전체를 회색으로 칠하지 않는다(§1-3 규칙 3).
- 화면 하단에 §7-9 단축키 힌트 줄(위 카피 계약의 6개).

**섹션 4 — 상태 전환**: 섹션 머리에 2차 버튼들.

| 전이 | 컨트롤 | 확인 |
|---|---|---|
| 수주중 → 진행 | 2차 `진행으로 전환` | 없음(비파괴) |
| 수주중 → 미수주 | 2차 `미수주로 닫기` | §7-8 확인 모달(비용 귀속이 팀 손익으로 내려간다) |
| 진행 → 완료(정산) | 2차 `완료(정산)` | §7-8 확인 모달(견적 줄 잠금) |
| 미수주 → 진행 | 2차 `되살리기`(D-44) | 없음(비파괴) |

결과는 §7-7 SUCCESS 「행동한 자리에서 결과가 보인다」 — 머리 줄의 상태 태그가 바뀌는 것 자체가
결과이고 **토스트를 띄우지 않는다**(§7-6 — 화면 이동이 따르는 행동만 토스트).

완료(정산) 프로젝트: 견적 줄 표가 잠긴다 → `ui/table`로 렌더 + 새 지출을 받지 않는 상태가 화면에
보인다(ROADMAP 기준 4). 잠김 이유는 §7-1 비활성 규칙대로 버튼 옆 글자로: `완료(정산) 프로젝트 ·
잠김`.

`ui/shell/role-menu.ts` `TOP_BAR_MENU`), 리저브는 그중에 없다. 관리자 화면 10개는
`ADMIN_MENUS`(같은 파일)가 PC 사용자 메뉴·「더보기」 시트로 노출하지만 그 목록은 `admin.*` 키
전용이고 리저브는 관리 콘솔이 아니라 경영관리 **업무** 화면이다.
→ **기본값**: 1차 메뉴 다섯은 건드리지 않고, `role-menu.ts`의 권한 기반 메뉴 목록을 `admin.*`
전용에서 「권한이 있는 사람에게만 보이는 메뉴」로 한 칸 넓혀 리저브를 넣는다(§6-0의 「메뉴가
빠지면 남은 메뉴가 왼쪽으로 붙는다」 규칙이 그대로 적용된다).
→ **대안**(사용자가 고르면): 1차 메뉴를 여섯으로 늘린다 — 그러면 §6-0 그림과 D-22를 함께 고쳐야
하고 `DECISIONS.md` 기록이 필요하다.

**GAP-2 — §7-8 확인 모달·시트 컴포넌트가 D-60 목록에 없다.** §7-3이 「Delete 줄 삭제(확인 모달)」를,
§7-1이 「위험 행동은 색이 아니라 확인 모달로 구분한다」를 요구하는데 `ui/`에 §7-8 골격이 없다
(`ui/shell/MoreSheet`가 네이티브 `<dialog>`로 시트를 구현한 선례는 있다).
→ **기본값**: `ui/confirm`을 다섯 번째 컴포넌트로 만든다(사용처 3: 견적 줄 삭제 · 미수주로 닫기 ·
완료(정산)). 폰 행 상세 시트도 같은 골격의 변형으로 둔다. 계획자는 D-62(플랜 수 상한)에서 이
한 개를 계산에 넣어야 한다.

**GAP-3 ★ — 프로젝트 상태 네 개의 §7-5 색 매핑이 없다.** §7-5는 다섯 색의 **의미**만 주고
(danger 막힘·반려 / warning 오늘·마감 / accent 내 차례·결재 중·편집 중 / success 승인·연결·저장됨 /
muted 대기·미착수·임시), §6-4 대시보드 현황 칩은 「진행·완료·정산 대기·다음 달 시작, **뒤 둘은**
`--muted`」라고만 적어 앞 둘의 색을 말하지 않는다.
→ **기본값**: 수주중 `--muted`(§7-5 「미착수」) · 진행 `--accent`(§7-5가 accent를 태그 색 중 하나로
이미 명시 — §1-3 다섯 곳 규칙에 여섯 번째를 더하는 것이 아니다) · 완료(정산) `--success`
(§1-1이 `--g-600`의 용도를 문자 그대로 「성공·**완료** 텍스트」로 적었다) · 미수주 `--muted`.
수주중과 미수주가 같은 색을 쓰는 것은 §10(「색은 의미의 유일한 매체가 아니다 — 상태는 항상
글자다」) 아래에서 허용된다.

**GAP-4 — 등록 폼 진입 방식의 적용 범위.** §6-1에 추가된 문단(`DECISIONS.md` 2026-09-21)은 검색
파라미터 토글(`?new=1`)을 **「관리자 마스터 화면」에 한정해** 적고 있다. 프로젝트 목록은 관리자
마스터가 아니다. 다만 §6-1의 일반 규칙(「등록은 목록 머리글의 행동」)은 「새 지출결의」 예시로
비관리자 목록에도 이미 적용돼 있다.
→ **기본값**: 같은 토글 메커니즘을 프로젝트에도 쓴다(`?new=1` 등록 · `?editId=` 수정). 새 라우트를
만들지 않는 이유는 `DECISIONS.md`가 적은 것과 같다(목록 필터 상태를 폼과 주고받는 배선이 없다).
계약을 벗어나는 것이 아니라 **적용 범위를 넓히는 것**이므로 DECISIONS.md 기록은 필요 없고, 계획
문서에 한 줄 남기면 충분하다.

**GAP-5 ★ — 「자동완성」과 §7-2 「커스텀 드롭다운 금지」의 접점.** ROADMAP 기준 1은 클라이언트·
거래처 자동완성을 요구하고, §7-2는 「선택(select): 네이티브 `<select>` 그대로 + 커스텀 드롭다운
만들지 않는다」만 적는다. 타이핑으로 걸러지는 컨트롤은 SYSTEM.md에 없다.
→ **기본값**: 네이티브 `<input list>` + `<datalist>`(브라우저 기본 컨트롤이므로 「커스텀 드롭다운을
만들지 않는다」를 지킨다). 고정된 소수 목록(담당 PM · 팀 · 통화 · 상태 · 차수)은 `ui/select`.
→ **대안**: §6-3의 「바꾸기」 목록 골라내기(PC 모달 480 · 폰 시트 · 검색 한 칸 첫 포커스)를 쓴다 —
SYSTEM.md에 이미 있는 계약이라는 장점이 있지만, 견적 줄 그리드의 거래처 셀에서는 셀마다 모달이
열려 엑셀식 키 흐름(⌘V로 거래처명이 텍스트로 붙는 경로 포함)이 끊긴다. 그래서 골라내기는 **줄
단위 「바꾸기」와 Phase 5 지출결의**에 남기고 이 페이즈에서 신설하지 않는다.

**GAP-6 ★ — 단축키 표기 `⌘`와 Windows.** §6-0·§7-3·§7-9가 힌트 줄과 `kbd` 표기를 전부 `⌘`로
고정했는데, §2-1은 **「회사 PC는 Windows가 많아」**를 서체 결정의 근거로 삼았다. 같은 문서 안에서
표기와 사용자 환경이 어긋난다.
→ **기본값**: 키 **처리**는 `metaKey || ctrlKey` 둘 다 받는다(기능은 논쟁 대상이 아니다). 키
**표기**는 플랫폼에 따라 `⌘` / `Ctrl`로 바꿔 렌더한다 — 그렇지 않으면 다수 사용자가 읽을 수 없는
힌트 줄이 된다. **이것은 SYSTEM.md 원문(`⌘` 고정 표기)을 벗어나므로**, 채택하면
`docs/design/DECISIONS.md`에 이유를 남기고 §7-9에 한 문장을 더하는 절차가 필요하다(CLAUDE.md
프론트엔드 · `DESIGN.md` §4 규칙 6).

**GAP-7 — §6-3의 `--success` 500 표기.** §6-3 「다섯 상태」 줄이 SUCCESS 텍스트를 `(--success 500)`로
적었는데 §2-1은 굵기를 **400 · 600 · 700 세 단계**로 고정했고 `tokens.css`에 500이 없다.
→ **기본값**: `--fw-medium`(600)으로 구현하고 §6-3의 500을 오탈자로 본다. 새 굵기를 만들지 않는다.
