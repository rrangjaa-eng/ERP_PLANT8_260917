## 컴포넌트 계약 0 — `ui/button` 수선 (F4 · F5, D-72)

**새로 만들지 않는다. 이미 있는 것을 두 군데 고친다.** 이 페이즈가 이유 있는 비활성 버튼을 세 곳
(삭제 불가 · 완료(정산) 잠김 · 폼 제출 불가)에서 쓰므로, 한 번 고치면 셋이 함께 닫힌다.

**F4 — 비활성 이유를 `aria-describedby`로 연결한다.**
- 실측: `ui/button/Button.tsx:55`가 `disabledReason`을 **`id` 없는 형제 `<span>`**으로 렌더한다 —
  눈에는 보이지만 버튼과 프로그램적으로 연결되지 않는다.
- §10(`SYSTEM.md:911`): 「제출 불가 이유는 `role="alert"`가 아니라 **버튼의 `aria-describedby`**
  (사용자가 누르기 전에 읽힌다)」.
- 계약: `Button` 안에서 `useId()`로 이유 `<span>`에 `id`를 주고 `<button aria-describedby>`로 잇는다.
  **`ui/form`이 아니라 `Button`에 둔다** — 표 안 삭제 버튼·상세 화면 잠김 버튼은 폼 밖이다.

**F5 — 단축키 표기를 플랫폼별로 만든다.**
- 실측: `Button.tsx:16` `shortcut?: string` — 문자열 리터럴을 받는다. 지명이 없으면 화면 작성자가
  `⌘`를 하드코딩한다.
- 계약: `shortcut`은 `ui/kbd/format-shortcut.ts`가 만든 문자열만 받는다(표기 중립 선언 `"mod+S"` →
  Mac `⌘S` / Win `Ctrl+S`). 키 **처리**는 `event.metaKey || event.ctrlKey` 둘 다 받는다(D-67).

**건드리지 않는 것**: `:34-39`의 이유 없는 비활성 dev warn은 그대로 둔다 — F1이 따를 선례다.

## Typography

`SYSTEM.md` §2-2·§2-3·§2-4 그대로. 굵기는 **400 · 600 · 700 세 단계만**(§2-1).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body(표 셀 · 목록 행 · 폼 입력) | `--fs-base` 14px(폰 15px) | 400 | 1.5(표) / 1.6(본문) |
| Label(폼 라벨 · 표 머리글 · 서버 계산 한 줄 · 외화 2행 · 오류 한 줄) | `--fs-sm` 12px | 600(라벨·머리글) / 400(부가 정보) | 1.5 |

**한 화면 4단계 이하**(§2-2). 이 페이즈의 모든 화면은 xs·sm·base·lg 넷으로 끝난다.

**SUCCESS 텍스트 굵기 = 600**(D-69). §6-3의 `(--success 500)` 표기는 오탈자다 — §2-1이 굵기를
「400 · 600 · 700 **세 단계만**」으로 못박았고 `tokens.css`에 500이 없다. **새 굵기를 만들지 않고
`--fw-medium`(600)으로 구현하며, 문서는 고치지 않는다**(오탈자 정정은 이 페이즈의 범위가 아니다).

**숫자 형식(§2-4, 이 페이즈가 전부 쓴다 — F3으로 열 선언에 딸려 온다)**
- 원화: 정수 + 천 단위 쉼표, 단위 기호 없음, 열 머리글에 「(원)」도 쓰지 않는다.
- 음수: 하이픈 마이너스. **괄호 금지 · 붉은색 금지** — 매출·조정 항목의 환불·할인(EXP-14)이 여기 걸린다.
- 0은 `0`, 값 없음은 `—`. 빈칸 금지. 계산 불가는 `계산 불가 · 환율 없음`.
- 외화: **두 줄 병기**. 1행 원화 환산액(정수), 2행 `--fs-sm --muted` `USD 4,400.00 @1,318.1818`.
- 날짜 `2026-09-18` · 표 안 같은 해 `09-18` · 기간 `09-12 ~ 09-16` · 시각 `14:00`.
- 문서 번호: 서버 서식 그대로, 모노 아님, `tabular-nums` (`26001` · `26001-1차`).
- 모든 숫자 칸: **우측 정렬 · `tabular-nums` · `white-space: nowrap`**. 폭이 모자라면 숫자를 꺾지 않고
  열을 접는다. 합계 행만 700.

② **편집 중 셀·행**(§7-3 셀 밑줄 + 활성 셀 2px 외곽선)
③ **1차 버튼**(「일괄 저장 N」 · 「프로젝트 등록」)
④ `:focus-visible` 링
⑤ 현재 위치(상단 바 밑줄, 셸이 이미 구현)

- 표 상태 열의 상태 색은 §7-5 **색 글자만**(테두리 태그 아님). 테두리 태그는 「내 차례」와 화면
  제목 옆에서만. **상태 4종 매핑은 D-65** — 아래 화면 계약 5 본문의 표가 정본이다.
- 오류 **셀**만 `--danger-weak`으로 채운다. 행 전체를 붉게 칠하지 않는다(§1-3 규칙 3).
- 그린 틴트는 상단 바를 빼면 면이 아니다 — 딥그린 면은 앱에서 상단 바 하나뿐이다(§1-3 규칙 4).

  `--danger`(6.48:1) · `--g-800`(8.85:1) 셋만이다. `--success`(4.18:1 — D-71)와 `--faint`
  (`tokens.css:25`가 「`--g-100` 위 금지」를 이미 달아 뒀다)는 이 바탕에 올리지 않는다.

## 컴포넌트 계약 1 — `ui/form` (§6-3)

**골격**
- 한 열, `max-width: var(--form-max)`(720, `tokens.css:116`), **왼쪽 정렬**(§3 「가운데 정렬하지 않는다」).
- 머리 줄(제목 · 번호 · 상태 태그)도 같은 720 기둥에 맞춘다(§6-3 원문).
- 묶음 사이 `--s-6` + `1px --line`, 항목 사이 `--s-4`, 라벨-입력 세로 `--s-1`(§3).
- 라벨: PC 왼쪽 열 고정폭 `--label-w`(96) `--fs-sm --muted` 600, 폰은 위로(§6-3·§7-2). **`TextField`가
  이미 이 규칙을 구현하고 있다** — `ui/form`은 그것을 폼 전체로 넓히는 그릇이다.
- 칸 폭 변형: `select` 200 · `short` 280 · `long` 480 · 폰 전폭(§6-3). API 형태(prop vs 변형 클래스)는
  Claude 재량(04-CONTEXT).
- 필수 표시 `*` 없음(§7-2) — 필수인데 비면 **제출 버튼이 이유를 말한다**.

**A-H3을 닫는 지점(이 컴포넌트의 존재 이유 절반)**
- `<form noValidate>`. 네이티브 `required` 말풍선을 첫 관문에서 **걷어낸다**.
- 빈 필수 칸이 있으면 1차 버튼 비활성 + 옆에 이유(§7-1 「비활성 버튼은 이유를 옆에 글자로」 ·
  §6-5의 「막힘 = 1차 버튼 비활성 + 빈 칸 전부 나열」과 같은 형태): `등록할 수 없음 — 클라이언트 ·
  기간 2칸`.
- 그 이유 텍스트는 `role="alert"`가 **아니라** 버튼의 `aria-describedby`로 연결한다(§10:911).
  **배선은 `ui/form`이 아니라 `Button` 안에 있다**(F4 — 컴포넌트 계약 0). `ui/form`은 문자열만 넘긴다.
- 서버 검증 오류는 §7-2: 입력 테두리 `--danger` 1px + 입력 아래 `--fs-sm --danger` 한 줄
  「원인 · 다음 행동」 + `aria-invalid` + `aria-describedby`. **입력값은 지우지 않는다**(§7-2).
- 서버 계산 값은 입력 **바로 아래 한 줄**(§6-3): `--fs-sm --muted`, 숫자만 700. 읽기 전용 행을 따로
  두지 않는다.

**자유 입력 자동완성(D-66)**: 클라이언트·거래처처럼 **목록이 열려 있는** 칸은 네이티브
`<input list>` + `<datalist>`를 쓴다. §7-2의 「네이티브 `<select>` 그대로 · 커스텀 드롭다운을 만들지
않는다」(`SYSTEM.md:633`)는 enum select를 다루는 문장이고, `<input list>`도 **브라우저 기본
컨트롤**이라 그 규칙을 지킨다. 키보드 흐름이 끊기지 않아 견적 줄 그리드 셀 안에서도 쓸 수 있다
(UX-05 「키보드만으로 끝난다」). 고정된 소수 목록(담당 PM · 팀 · 통화 · 상태 · 차수)은 `ui/select`다.
§6-3의 「바꾸기」 목록 골라내기(모달·시트)는 **줄 단위 「바꾸기」와 Phase 5**에 남기고 여기서
신설하지 않는다 — 셀마다 모달이 열리면 엑셀식 키 흐름이 끊긴다.

**다섯 상태(§7-7 「폼(지출결의)」 행을 그대로 옮긴다)**

| 상태 | 모양 |
|---|---|
| LOADING | 자동 채움 칸 `—` + 상단 2px 진행 바. 누른 버튼은 라벨 뒤 `…`, 같은 폼의 다른 버튼도 비활성(§7-1) |
| EMPTY | **해당 없음** — 등록 폼은 항상 칸 전체가 렌더되고 빈 상태가 없다(§6-7 로그인 폼과 같은 논리) |
| ERROR | 입력 아래 `원인 · 다음 행동`, 값 보존, 1차 버튼은 **살려 둔다**(§6-3) + 버튼 옆 `등록하지 못했습니다 · 기간 1칸 · 값은 남아 있습니다` |
| SUCCESS | 버튼 자리에 `등록됨 · 26001`(`--success` **600** — D-69, `--bg` 위 5.3:1) + 3차 `프로젝트 열기` + 토스트. 입력은 읽기 전용(§6-3) |
| PARTIAL | 1차 버튼 비활성 + 옆에 `등록할 수 없음 — 이유 · 다음 한 수`(§7-7 폼 행) |

**폰**: 제출 줄은 하단 탭 위에 얹혀 고정, 1차 버튼 `--touch-min`(44) 넓게, 막힘 이유는 그 아래
한 줄. 본문 아래 여백 = 탭 44 + 제출 줄 높이(§6-3).

## 컴포넌트 계약 2 — `ui/select` (§7-2)

- **네이티브 `<select>` 그대로 + 시스템 테두리. 커스텀 드롭다운을 만들지 않는다**(§7-2 원문).
- 라벨 배치·오류 표시·`aria-*` 배선은 **`TextField`와 정확히 같아야 한다** — 한 폼에 라벨 배치가
  두 가지인 A-H2의 본문이 정확히 이 불일치다(`.selectLabel`이 화면마다 복사돼 전폭 블록 라벨을 쓴다,
  HANDOFF 함정 10 실측).
- 높이 `--control-h` 32(폰 40) · 테두리 `1px --line-ui` · 배경 `--bg` · `--fs-base` · radius 0 ·
  focus `outline 2px --focus offset 2px`(§7-2).
- 기본 폭 **200**(§6-3 「select 200」), 폰 전폭.
- 이 페이즈의 사용처: 담당 PM · 팀 · 프로젝트 상태(등록 폼) · 통화 · 견적 차수 선택 · 리저브 종류(입금/출금).
- **자유 입력 자동완성은 이 컴포넌트가 아니다** — `<input list>`(D-66, `ui/form` 계약).

**다섯 상태**: LOADING = 폼과 같음(값 `—`) / EMPTY = **해당 없음**(선택지 0개인 select는 이 페이즈에
없다 — 팀·계급은 Phase 3 시드가 보장) / ERROR·PARTIAL·SUCCESS = `ui/form`과 동일.

## 컴포넌트 계약 3 — `ui/table` (§6-1 읽기용 원장)

**구조(§7-3 「구조」 블록은 읽기용·편집용 공통이다)**
- `<table>` + **시각적으로 숨긴 `<caption>`**(§10) + 열 머리글 `<th scope="col">` + 행 머리글이
  성립하면 `<th scope="row">` → **A-M3을 닫는다.**
- 머리글: `--fs-sm --muted` 600, 아래 `1px --line-strong`, 스크롤 시 sticky(`--z-sticky`).
  **읽기용 표는 흰 바탕**(§7-3) — `--g-100` 바탕은 편집용 신호이므로 쓰지 않는다.
- 행: 아래 `1px --line`, hover `--surface`, 높이 `--row-min`(36 / 폰 44), **고정 높이 금지**.
- 그룹 머리글 행: `--fs-sm --muted` 600, 위 `--s-3`, 아래 `1px --line-strong`.
- 합계 행: 위 `2px --line-strong`, `--fs-base` 700. (읽기용이므로 `--g-100` 바탕 없음)
- **세로선 없음**(§4-2). 첫 칸(행 번호) `--fs-xs --faint`, 폭 28.
- 열 폭: 문자 열 `auto`, 숫자 열은 자릿수 고정(`ch`). 항목명은 `keep-all` 줄바꿈 허용, 거래처는
  한 줄 말줄임(§7-3).
- 페이지네이션 대신 `더 보기 50건` 3차 버튼(§6-1).

**열 선언 타입 — §2-4를 선언으로 딸려 오게 한다(F3, D-72)**
`column-fold.ts`가 정의하는 열 타입에 **`kind: "money" | "date" | "text" | "status"` 축**을 둔다.
열이 `kind: "money"`라고 선언하면 §2-4의 **포맷터(천 단위 쉼표 · 하이픈 마이너스 · `—` · 외화 2행) +
우측 정렬 + `tabular-nums` + `white-space: nowrap`**이 자동으로 따라온다. `kind: "date"`는 §2-4
날짜 서식(표 안 같은 해는 `09-18`), `kind: "status"`는 §7-5 색 글자 변형을 딸려 온다. 화면 작성자가
열마다 기억하는 형태로 두지 않는다 — 그것이 함정 10의 「산문으로 남은 계약」 패턴이다.

**폰 칸 접기(§7-3 — `ui/grid`와 공유하는 유일한 로직, D-46)**
- 모든 열이 **P1 / P2 / P3**을 선언한다. `<700px`에서 P1만 열로 남고, P2는 행 아래 **접힌 줄**
  하나(`--fs-sm --muted`, 라벨 없이 `값 · 값 · 값`, 열 순서대로), P3은 숨는다.
- **P1은 최대 3열 — 항목(문자 1) + 금액(숫자 1) + 상태 또는 행동(1).**
- **강제 지점(F1, D-72)**: `column-fold.ts`가 열 선언을 받는 곳에서 **P1 개수 > 3이면 개발 모드
  warn/throw**. 선례는 `ui/button/Button.tsx:34-39`(이유 없는 비활성을 dev warn으로 막는다, 실측).
  산문으로 두면 어긋난다는 증거가 이 페이즈 안에 이미 있다 — 리저브가 P1 4열 후보로 걸렸다
  (화면 계약 8). `/design-review`(§11:932 「P1 열 3개 이하」)는 두 번째 그물로 그대로 남는다.
- 합계 행 부제는 폰에서 숨기고 합계는 P1 금액 열만. 그룹 머리글·합계 행은 폰에서도 남는다.
- **가로 스크롤 금지 · 카드 전환 금지**(§7-3). 태블릿 700–1023은 P3만 숨긴다(§6-0).

**행 동작의 접근 가능한 이름 → A-M7을 닫는다**
- 행 안 3차 버튼·링크는 `aria-label="{행 이름} · {동작}"`으로 행 맥락을 문장에 넣는다 —
  §7-13이 이미 쓴 「좌표를 문장으로」 규약과 같은 형태. 예:
  `aria-label="26001 아이오닉9 쇼케이스 · 견적 열기"`. **API가 이것을 요구한다**(옵션이 아니다).

**칸 수 가변(정보 노출표, §7-3)**: 열은 **서버가 계급에 따라 아예 보내지 않는다.** 클라이언트에서
숨기지 않는다. 빠진 열의 폭은 문자 열이 흡수하고, 합계 행은 남은 열만으로 성립한다. 빈 칸을 `—`로
채우지 않는다(있는데 값이 없을 때만 `—`).

**다섯 상태(§7-7 「표(목록·편집)」 행)**

| 상태 | 모양 |
|---|---|
| LOADING | 머리글·합계 행 뼈대 + 본문 자리 `--surface` 행 3개. 반짝임 없음, 300ms 안에 끝나면 아무것도 보이지 않음 |
