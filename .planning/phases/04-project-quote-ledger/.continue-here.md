## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| 한 세션에 여러 단위 | 게이트 리뷰 뒤 같은 세션에서 plan-phase까지 이어 감 | blocking | hook(세션 경계) + 위 제약 |
| 확인 없는 커밋 | 커밋·완료 보고 전 verification-before-completion 미호출 | blocking | hook(문서 커밋도 관문) |
| 말없이 판단 | 강제 푸시 회피 방식·PR 선생성·정지 감시 중단을 사용자에게 먼저 알리지 않음(세션 C) | blocking | 워크플로와 다르게 하거나 기록 밖 판단을 하면 그 자리에서 한 줄로 알린다 |
| 정지 감시 거짓 양성 | gsd_stall_watch가 출력 JSONL(프롬프트 포함)에서 완료 마커 문구를 잡음 | advisory | 프롬프트에 마커 문자열을 넣지 않거나 완료 알림에 의존하고 그 사실을 알린다 |
| 테스트 환경만 보는 검토 | 임시 저장소 테스트가 초록이어도 실제 저장소(표시 없는 마이그레이션)에서 스크립트가 죽음(세션 D) | blocking | 에이전트 diff를 실제 저장소에 대입해 재현 — 빈 입력·기본 상태 경로 확인 |
| 기록된 결정 오판 | 이미 확정된 결정을 미결로 올림 | advisory | 묻기 전에 CONTEXT·UI-SPEC·OPEN-ITEMS·HANDOFF 검색 |
| 테스트 계약에 맞추려 범위를 넓힘 | executor가 tx-safety (c)(「거부는 전부 UserFacing」)를 통과시키려 saveProjectLedger 전체를 시간 초과 변환으로 감쌈 — 커밋 뒤 실패에도 「잠시 뒤 다시 저장」이 나가 새 줄 중복 저장(세션 F, 4f54fcf로 고침) | advisory | 오류 변환·재시도 문구를 넓히는 diff는 「이미 저장된 뒤에도 이 경로를 타는가」를 실제 호출 순서로 확인 |
| 얕은 clone을 부재로 오판 | executor가 플랜의 기준 커밋 d6b41cf를 못 찾자 「저장소에 없음」으로 SUMMARY에 적고 기준을 b0fc281로 바꿈(세션 E) — 이러면 플랜 전체 기간이 아니라 한 플랜 구간만 검사된다 | advisory | 없다고 판단하기 전 is-shallow 확인 → deepen fetch → 원래 기준으로 재검 |
| 테스트를 계약보다 느슨하게 | 세션 I: executor가 Tab 가두기 단언을 「body에 계속 머물러도 통과」로 두었음 — 오케스트레이터가 조이고 show() 변이로 실패 확인(cae45c0) | advisory | 실행자가 단언을 바꾸거나 느슨하게 하면 변이 한 번으로 그 단언이 실제 결함을 잡는지 확인 |
| 게이트를 executor와 병행 | 세션 G: 속도를 위해 전체 게이트를 실행 중인 executor와 같은 작업 트리에서 띄움 — 제약 재확인으로 즉시 중지(피해 없음) | advisory | 게이트·통합·E2E는 executor 종료 뒤에만. 병행하려면 별도 worktree |
| 백그라운드 대기만 하는 감시 | 세션 K: DOM 감사 작업자가 테스트를 띄우지 못한 채 `until [ -f log ]` 루프로 1시간 넘게 대기, 오케스트레이터도 알림만 기다려 사용자가 「왜 멈추냐」고 지적 | advisory | 작업자에게 긴 테스트를 전경(foreground, timeout 지정)으로 돌리라고 명시. 오케스트레이터는 작업자를 띄운 뒤 결과 파일·프로세스·DB 활동이 실제로 늘어나는지 한 번 확인한다 |
