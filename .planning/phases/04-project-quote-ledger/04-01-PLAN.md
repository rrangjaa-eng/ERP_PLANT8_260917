<objective>
**As a** 기획 PM, **I want to** 프로젝트를 등록하면 번호가 자동으로 붙고 그 상세 화면에서 견적 줄을 넣어 차익을 서버 계산으로 저장하고 싶다, **so that** 엑셀과 인트라넷에 흩어져 있던 프로젝트의 돈이 한 원장에 모이고 브라우저가 계산한 숫자가 저장되는 일이 구조적으로 사라진다.

이 플랜은 이 페이즈의 **트레이서**다. 프로젝트 하나 · 차수 하나 · 견적 줄 하나를 이 페이즈가 새로 만드는 모든 계층에 한 번에 꿰어 실제로 동작시킨다 — `docs/design/SYSTEM.md` 개정 → 스키마 3표 → `document_counters` 원자 증가 → `domain/money` → `domain/rules.gate` → `scopeFor`를 쓰는 리포지토리 → `project(viewer, row, spec)`을 지나는 domain → `authedActionClient` Server Action → `ui/form`·`ui/select`·`ui/table` → `/projects`·`/projects/[id]` 화면 → 행동 로그. 뒤따르는 여섯 플랜은 전부 이 증명된 경로 위의 **확장**이다.

Purpose: 이 페이즈가 세우는 세 「단일 지점」(`domain/money` · `domain/rules.gate` · 문서 번호 카운터 증가)은 전부 "지금 옳게 만들지 않으면 이후 여섯 페이즈가 각자 다르게 재발명한다"는 성격을 공유한다(04-RESEARCH.md Key insight). 세 지점의 계약은 층을 따로 쌓으면 마지막에야 성립 여부가 드러난다 — 여섯 층을 커밋한 뒤 "액션이 금액 산술을 직접 하고 있었다"를 발견하면 여섯 커밋을 되돌려야 한다. 그래서 가장 얇은 한 경로를 먼저 끝까지 배선해 증명한다.

- Pro: "통화·외화 금액·환율·원화 환산액" 묶음이 한 곳에 정의되고 견적 줄·매출·리저브가 같은 모양을 물려받는다. 목록·합계·손익이 전부 `amount_krw` 정수 하나로 집계된다

- 대안: 원화도 `numeric`으로 통일 — 정수 원이 보장되지 않아 반올림 지점이 둘이 된다(D4 위반). 채택하지 않는다

**② `document_counters`의 `counter_key`·`period` 의미와 프로젝트 번호 서식**

**⑤ `domain/money` (최소·진짜)**

**⑨ `ui/form` · `ui/select`**
§7-15 계약대로 만든다: `Form`(`<form noValidate>`, 한 열, 최대 폭은 기존 `--form-max` 토큰, 항목 간격 `--s-4`·묶음 간격 `--s-6`), `Form.Field`(라벨 열 `--label-w`, 폰에서 라벨이 위로), `Form.Hint`(서버 계산 값 자리), `Form.Error`(`aria-describedby`가 가리키는 한 줄), `Form.Actions`(1차 + 막힘 이유 + 3차 + 오른쪽 2차, 1차의 `aria-describedby`가 이유를 가리킨다). 칸 폭은 세 종류만. `Select`는 네이티브 `<select>` 래퍼이고 고를 것이 없으면 첫 옵션이 em dash이며 제출이 막힌다. **네이티브 `required`·`pattern`·`type="number"` 검증 위임을 쓰지 않는다**(A-H3).

**자동완성이 무엇인지 여기서 확정한다(ROADMAP 기준 1 · D-62의 계획 단계 판단).** 기준 1의 「클라이언트·거래처는 자동완성되고, … 반복 입력이 없다」와 D-62의 「소분류(코드표 자동완성)」는 **이 `ui/select` 하나로 만족시킨다** — 근거 둘이다. ⑴ 세 칸 모두 값의 출처가 서버가 보낸 목록(클라이언트·거래처 행, 소분류 코드표)뿐이라 사람이 이름을 **타이핑해 넣는 자리 자체가 없다**. 기준 1이 말하는 「반복 입력이 없다」가 이것이다. ⑵ 포커스 상태에서 글자를 치면 그 글자로 시작하는 옵션으로 건너뛰는 타이핑 점프를 브라우저가 네이티브 `<select>`에 이미 준다 — 구현할 것이 아니라 이미 있는 동작이고, 회사 규모(거래처·클라이언트 수백 건)에서 실용적이다. **별도 콤보박스·`<datalist>`·검색 입력 컴포넌트를 만들지 않는다** — 이 페이즈는 신규 런타임 의존성 0이고(D-61), 자유 입력을 열면 FK 칸의 값이 목록 밖으로 새어 소분류의 그룹 머리글 파생(D-62)이 깨진다. 이 판단과 근거를 SUMMARY에 한 줄로 남긴다 — 규모가 커져 타이핑 점프가 모자라지는 날이 오면 그때 `ui/select` 한 파일만 바꾸면 된다. 새 색·서체·radius를 만들지 않고 토큰만 쓴다. 관리자 폼 8개와 `/account`는 **건드리지 않는다**(Phase 7).

`types.ts`에 셀 편집 단계(`edit`·`readonly`·`locked`)와 열 우선순위(`p1`·`p2`·`p3`), 열 정의, 행 정의, 그룹 머리글 정의를 둔다. `Table.tsx`는 서버가 보낸 셀 단계에서 렌더 형태를 **파생**한다 — 편집 가능한 셀이 하나라도 있으면 `role="grid"` + 머리글 `--g-100` 바탕, 하나도 없으면 `<table>` + 시각적으로 숨긴 `<caption>` + 흰 머리글(§7-3 (가)). 폰 폭에서 P2는 행 아래 접힌 줄로, P3는 숨긴다(가로 스크롤 0). 그룹 머리글 행은 포커스를 받지 않는다. 합계 행은 `aria-live="polite"`. 열 머리글은 정렬 가능 여부를 prop으로 받아 클릭 시 정렬 요청을 올리고 현재 정렬 상태를 `aria-sort`로 말한다 — 방향 아이콘은 글자 라벨이 있는 버튼 안의 장식이라 `aria-hidden`이다(S11). 합계 행 아래에 호출자가 「더 보기」 같은 3차 버튼을 끼울 수 있는 자리를 둔다. **정렬·「더 보기」의 정렬 상태·페이지 크기는 이 컴포넌트가 갖지 않고 호출자가 준다** — 그래야 04-05(목록)가 이 파일을 고치지 않고 쓴다. 편집은 **한 칸 클릭/Enter 진입 + Esc 되돌리기 + dirty 표시 + 화면 1차 「일괄 저장」 한 번**까지만 — 방향키 로빙·범위 선택·⌘C/⌘V·버전 충돌 렌더·미저장 복원·힌트 줄은 04-04가 더한다. **⑬ [BLOCKING] 마이그레이션 0004 생성·검사·적용 — 트레이서가 실제로 도는 조건**
이 리포의 ORM은 Drizzle이지만 `drizzle-kit push`를 쓰지 않는다 — 생성·검사·적용 세 단계(`pnpm db:generate` → `pnpm lint:sql` → `pnpm db:migrate`)가 이 프로젝트의 스키마 반영 경로다(Phase 1~3 선례). **이 단계를 건너뛰면 타입·빌드는 통과하는데 DB에 표가 없는 거짓 통과가 되므로, 트레이서는 여기까지 끝나야 「관통했다」고 말할 수 있다.** `pnpm db:generate`로 파일을 만든 뒤 생성된 SQL을 **직접 읽고** 손으로 더한다: 첫 락 요구 문장 앞에 `SET LOCAL lock_timeout`·`SET LOCAL statement_timeout` 한 쌍(0003과 같은 값), Task 1 ④가 확정한 상태 코드 항목 네 개의 INSERT와 옛 값 네 개의 DELETE.

**DELETE 앞에 가드를 둔다 — 전제가 깨진 곳에서는 지우는 대신 거부한다.** 이 마이그레이션의 유일한 파괴적 문장이 「프로젝트 데이터가 아직 없다」는 전제 위에 서 있으므로, 그 전제를 **적용 시점에 대상 DB에서 직접 측정**해야 한다(Task 1 ④의 실측은 사람이 판단하기 위한 입력이고, 닿지 못한 DB는 이 가드가 맡는다). 표 생성문 **뒤**, DELETE **앞**에 `DO` 블록 하나를 손으로 넣어 둘을 확인하고 어느 하나라도 걸리면 `RAISE EXCEPTION`으로 마이그레이션 전체를 되돌린다: ⑴ `code_items` 중 `table_key = 'project_status'`이면서 값이 Phase 3이 시드한 다섯 값 밖인 행이 하나라도 있으면 중단한다(사람이 손댄 코드표다 — 무엇을 지울지 계획이 알지 못한다) ⑵ 방금 만든 `projects` 표에 행이 있으면 중단한다(이 표가 비어 있다는 전제가 깨진 것이다). 예외 메시지는 무엇이 전제를 깼는지와 다음 한 수(Task 1 ④의 대안 B — 옛 값을 비활성으로 내리기)를 한국어로 말한다. **조용히 건너뛰지 않는다** — `NOT EXISTS` 조건을 DELETE에 붙여 지울 것이 없으면 통과시키는 형태는 쓰지 않는다. 그러면 코드표에 다섯 값과 네 값이 섞여 여덟 줄이 남은 채로 마이그레이션이 성공했다고 보고한다. DELETE 대상은 네 값을 그대로 적고 와일드카드를 쓰지 않는다. 가드가 `pnpm lint:sql`에 걸리면 `.squawk.toml`이 아니라 SQL을 고친다(아래 규칙과 같다). **고정된 것은 `DO` 블록이라는 형태가 아니라 「전제가 깨지면 거부한다」는 결과다** — Squawk가 `DO` 블록을 거부하면 트랜잭션을 중단시키는 다른 어떤 형태로 써도 좋고(예: 위반 행이 있을 때 실패하는 문장), 조용히 건너뛰어 성공을 보고하는 형태만은 어느 경우에도 금지다.

`meta/_journal.json`의 tag가 파일명과 맞는지 확인한다. 인덱스는 비동시 형태여야 한다. `pnpm lint:sql`이 걸리면 `.squawk.toml`을 고치는 대신 SQL을 고친다. 적용 뒤 `pnpm db:seed`를 두 번 돌려 멱등성을 확인한다. `test/integration/setup.ts`의 TRUNCATE 목록에 새 표 세 개를 더한다(자식 → 부모 순서).
