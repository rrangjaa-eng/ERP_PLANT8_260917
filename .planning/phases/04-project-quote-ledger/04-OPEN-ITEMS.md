# Phase 4 미해결 항목 통합 대장

Phase 4는 **아직 계획도 실행도 되지 않았다**. 이 대장은 계획 전 단계(D-41 보강 ·
`04-UI-SPEC.md` 작성·검증·UI-consideration 프로브)에서 나온 미결 항목을 한곳에 모은
것이고, `/gsd-plan-phase 4`가 첫 입력으로 읽어야 하는 문서다.

**이 파일이 누락 방지 장치다.** 항목을 처리하면 여기 상태를 바꾸고, 새 항목이 나오면
여기 추가한다. Phase 3의 `03-OPEN-ITEMS.md`와 같은 규약이다.

## 도구 이슈 — 다음 페이즈에서도 물린다

**UI-consideration 프로브(`/gsd-ui-phase` §9.5)의 휴리스틱 분류기가 영어 큐 전용이다.**

2026-09-22 실측:

```
같은 내용 한국어 서술 10건 → unclassified 10/10 (적용 대상 0건)
같은 내용 영어 서술  1건 → empty·loading·error·populated·partial·overflow·
                            zero-one-many·long-text 8건 정상 제기
분류기 소스의 큐 문자열: text · list · form · nav · input … (영어 낱말)
```

이 프로젝트는 계획 문서가 전부 한국어라 **분류가 구조적으로 항상 실패한다.**
`ui-consideration-probe.md`가 정한 해법인 작성자 지정 `elements` 오버라이드를 매번
직접 써야 한다. 모르고 지나가면 "적용 대상 0건"으로 읽고 **상태 커버리지 축을 통째로
조용히 건너뛰게 된다** — 워크플로의 zero-applicable 가드는 `applicable`이 0일 때만
울리는데, `unclassified`는 applicable로 세어지므로 그 가드에 걸리지 않는다.

Phase 4에서 쓴 오버라이드(참고용): S1 `list-collection`+`interactive-control` ·
S2 `form` · S3 `static-content`+`interactive-control` · S4 `list-collection`+`form` ·
S5 `list-collection` · S6 `form`+`list-collection` · S7 `interactive-control` ·
S8 `static-content`+`interactive-control` · S9 `list-collection`+`form` ·
S10 `static-content`.

## 검증 때 증거를 요구할 자리 — backstop 11건

`## UI Considerations`의 `verification: backstop` 항목은 소스 단언이 아니라 held-out
또는 시각 상태 테스트로만 증명된다. 증거가 배선되지 않으면 검증 시점에
`insufficient_spec → human_needed`로 올라오고 **조용히 통과하지 않는다**. 그중 근거가
특히 얇은 둘:

- **S6 overflow** — S6는 §7-3이 요구하는 P1/P2/P3 선언을 하지 않았다. 열이 셋이라
  자동 충족될 뿐이니 계획 단계가 명시적으로 선언하는 편이 낫다.
- **S9 zero-one-many** — 「더 보기 50건」이 S9 본문이 아니라 머리글의 `(§6-1 + §7-3)`
  상속으로만 성립한다. **잔액 누적 열과 페이지네이션의 상호작용은 아무도 검토하지
  않았다** — 50건씩 끊어 불러올 때 잔액이 어느 범위 기준인지가 정의되지 않았다.
