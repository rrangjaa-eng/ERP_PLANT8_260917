# Phase 4 — UI Design Contract

> **2026-09-23 개정 (rev 4, D-75~D-95).** 04-01·02·05 실행 뒤 사용자가 실제 화면을 보고 정한 결정을
> 반영했다. 바뀐 표면과 이유만 적는다 — 나머지 절은 rev 3 그대로다.
>
> | 표면 | 무엇이 바뀌나 | 결정 |
> |---|---|---|
> | S1 프로젝트 목록 | 클라이언트 별도 열 · 금액 열 매출·견적·실행가·기준·수익금·수익률 · **합계 줄을 표 위로** · 기본 보기 올해 + 기간 필터(겹침) · 귀속 연도 표시·제외 건수 · 번호 페이지 50건 · `종료일 지남` | D-81·D-87~D-91 |
> | S3 상세 머리 줄 | 상태 다섯 · 정산 자동(버튼 없음) · 전환 컨트롤의 주인 · **기간 칸(표 밖 편집 칸)** 신설 | D-75~D-82 |
> | S4 견적 줄 표 | 30줄 페이지 · 그룹 머리글 반복 · 300줄 상한 · 「조정」 줄 · 정산 = 실행가만 편집 · 페이지 경계의 키보드·범위·붙여넣기 | D-78·D-83·D-86·D-91 |
> | S6 매출 섹션 | **계약 금액 입력 칸 삭제 → 승인 차수 합계 파생 표시** · 발행 표 기획본부 공개(읽기) · 입금 표는 숨김 유지 | D-84·D-85 |
> | S7 상태 전환 | 다섯 상태 전이표 · 시작일 게이트 · 정산 → 진행은 종료일 늦추기 · 완료는 대표·시스템 관리자 | D-75~D-82 |
> | S12~S15(신설) | 페이지 이동 · 기간 칸 · 코드표 설명 · 숫자 입력·표시 | D-82·D-91·D-93·D-95 |
> | 전역 | 단축키 `Ctrl` 표기·동작(`⌘` 0개) · 모든 숫자 천 단위 쉼표(외화·환율·수량 포함, 입력 중 자동) | D-94·D-95 |
>
> `SYSTEM.md` 개정은 아래 「SYSTEM.md 개정 — 2026-09-23」 절의 **열한 항목**이다(DECISIONS.md 먼저).
> 이 문서 안의 단축키 표기는 전부 `Ctrl`로 바꿨다(D-94). 상태 라벨 `완료(정산)`은 `완료`가 됐다(D-75) —
> 아래 rev 1~3 기록 안의 옛 라벨은 당시 기록이라 그대로 둔다.

> 프로젝트·견적 원장. `docs/design/SYSTEM.md` + `tokens.css`가 이미 확정돼 있으므로 이 문서는 새 시각
> 언어를 만들지 않는다. 기존 계약을 이 페이즈의 표면 11개에 적용하고, **`SYSTEM.md` 개정 네 건의
> 초안**(§7-3 표 구현 계약 보강 · §7-5 상태 태그 보강(의미 목록 + 길이 규칙) · §7-8 2차 라벨 충돌
> 규칙 · §7-15 폼(`ui/form`·`ui/select`) 신설)을 쓰는 것이 핵심 산출물이다.
>
> 엑셀식 표의 **동작** 계약(Tab/Enter·방향키·범위 복사·붙여넣기·Esc·Ctrl+S/Ctrl+Enter·전부 저장 또는 전부
> 거부·충돌 표시)은 Phase 2에서 §7-3으로 이미 고정됐고 D-61~D-69가 그것을 확인했다. 여기서 더하는
> 것은 §7-3이 아직 말하지 않은 것들이다: **셀 편집 가능성 3단계 · 줄 버전 충돌의 실제 문구 ·
> 붙여넣기 정규화 · 줄 순서와 그룹 머리글 · 미저장 편집 복원 · 폰 행 시트 · 저장 범위**.
> 자체 구현/라이브러리 선택은 D-61이 **자체 구현**으로 이미 닫았다(CEO OV-7의 선택권은 소진됐다) —
> 아래 계약은 그 결정을 전제로 쓰였고, 만약 계획 단계가 라이브러리로 되돌린다면 그 라이브러리가
> 「(가)~(아)」 여덟 항목을 **전부** 만족하고 토큰·마크업 계약(D-20 stylelint, radius 0, 카드 없음)을
> 깨지 않는지가 채택 조건이다.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn 미사용. 자체 디자인 시스템(`docs/design/SYSTEM.md` §0~§11 확정, `docs/design/tokens.css`) |
| Preset | 해당 없음 |

| Icon library | Lucide 세트 하나, 패키지 의존 없이 SVG를 `components/icons/`에 인라인 복사(§9). 이 페이즈가 새로 쓰는 아이콘: 정렬 방향(arrow-up/down, 목록 열 머리글) · 닫기(x, 시트·모달) 뿐. **페이지 이동은 아이콘 없이 글자**(`이전`·`다음`, S12) |
| Font | Pretendard Variable, 자체 호스팅 `public/fonts/pretendard/`(woff2 동적 서브셋, §2-1) |

컴포넌트는 `tokens.css`의 변수만 참조한다(D-21). **이 페이즈는 새 색·서체·radius·그림자·토큰을 0개
만든다.** §7-3이 지정한 `--g-50`(편집 중 행·범위 선택)은 의미 토큰 `--accent-weak`로 참조한다(§1-2
"컴포넌트는 의미 토큰만"). 표 머리글의 `--g-100`/`--g-950`은 대응하는 의미 토큰이 없어 §7-3 원문
그대로 `--g-*`를 직접 참조한다 — 이미 `ui/permission-grid`가 같은 자리에서 같은 예외를 쓰고 있어
새 예외가 아니다.

이 페이즈가 `SYSTEM.md`를 고치는 지점은 **네 건**이고 전부 아래 §7 초안과 「DECISIONS.md에 남길 것」에
적혀 있다: **§7-3 보강**(편집 표 구현 계약) · **§7-5 보강**(상태 태그 — **의미 목록 + 길이 규칙**
두 가지가 ② 한 항목의 범위다) · **§7-8 보강**(2차 라벨 충돌 규칙) · **§7-15 신설**(폼·셀렉트).
네 건 모두 시스템 자체를 고치는 개정이고, **화면 하나만의 예외는 하나도 남기지 않는다**
(CLAUDE.md 프론트엔드 규칙). 이 네 건은 04-01이 `SYSTEM.md`에 이미 옮겼다(`DECISIONS.md`
2026-09-22 네 항목).

**2026-09-23 개정이 더하는 것은 열한 항목**이다(D-75~D-95 + U-4 이월 한 건 + rev 4 체커 수정 네 건 —
⑧ §7-16 페이지 줄 · ⑨ §7-15 `Form.Hint` 결과 미리보기 · ⑩ §7-4 `대기` 색 정정 · ⑪ §8 담당자 표기). 목록·정확한 절 번호는
아래 「SYSTEM.md 개정 — 2026-09-23」 절. 역시 화면 예외 0건이다 — 이 문서에만 있던 시스템 수준 규칙
(페이지 줄 · 결과 미리보기 · 기간 필터 `10ch` · 읽기 목록의 좁은 PC 열 접기)을 전부 그 절로 옮겼다.

## Typography

`SYSTEM.md` §2-2·§2-3 그대로(굵기 3단계: 400·600·700):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body(표 셀·목록 행·폼 입력·본문) | `--fs-base` 14px(폰 15px) | 400 | 1.5(표 `--lh-table`) / 1.6(본문 `--lh-body`) |

| Heading(화면 제목 = 프로젝트명, 합계 금액) | `--fs-lg` 18px | 700 | 1.4 |
| Micro(상태 태그·행 번호·kbd·`계산 불가` 배지) | `--fs-xs` 11px | 600 | 1.4 |
| Display | **사용 없음** — `--fs-xl`/`--fs-2xl`은 인쇄·외부 수령자·손익 대시보드 KPI 전용(§2-2). 원장·상세·폼에 큰 숫자를 두지 않는다(안티슬롭) |

- **화면당 4단계를 넘지 않는다**(§2-2). 이 페이즈의 모든 화면은 `xs · sm · base · lg` 정확히 넷이다.

  `letter-spacing: 0`(§2-4). 폭이 모자라면 숫자를 꺾지 않고 **열을 접는다**(§7-3 폰 전략).
- 문자 열: 항목명·프로젝트명은 `word-break: keep-all` 줄바꿈 허용, 거래처·클라이언트는 한 줄 말줄임.
- 합계 행만 700. 네 숫자 줄(PNL-01)은 이 페이즈에서 렌더하지 않는다(Phase 9).
- **(2026-09-23) 목록 합계 줄(S1, D-88)** — 라벨 `--fs-sm --muted` 600 + 금액 `--fs-lg` 700 `tabular-nums`.
  위 Heading 행의 「합계 금액」 자리다. 목록 화면의 크기는 여전히 `xs · sm · base · lg` 넷이다
  (제목 `lg` · 표 `base` · 라벨·접힌 줄 `sm` · 상태 글자·kbd `xs`). `--fs-xl` 이상은 쓰지 않는다 —
  「눈에 띄게」는 크기가 아니라 **자리**(표 위, 필터 바로 아래)와 굵기로 만든다.
- **(2026-09-23) 숫자 서식(D-95)** — 원화뿐 아니라 **외화 금액·환율·수량·건수까지 천 단위 쉼표**.
  외화 금액은 소수 2자리 고정(`USD 1,000.00`), 환율은 끝의 0을 떼고 최대 4자리(`@1,350` ·
  `@1,318.18` · `@1,318.1818`), 수량은 끝의 0을 떼고 최대 2자리(`1` · `1.5` · `1,200`), 비율은 소수
  1자리(`25.2%` · `-3.4%`). **쉼표를 쓰지 않는 식별자형 숫자**: 프로젝트·문서 번호(`26001`), 연도
  (`2026`, `2027 귀속`), 날짜, 전화·사업자 번호, 카드 뒤 4자리. 표시 서식은 **한 모듈**이 만든다 —
  지금 파일마다 흩어진 `toLocaleString("ko-KR")`·`toFixed()` 표시 호출(`quote-table.tsx` 130·667·942행,
  `revenue-section.tsx` 33행, `projects-table.tsx` 32행, `ui/next-turn/NextTurn.tsx` 51행,
  `domain/quotes/lines.ts` 263행)을 그 모듈 호출로 바꾼다. 저장 직렬화용 `toFixed`(`domain/money`
  87·88행, `domain/quotes/lines.ts` 493행)는 표시가 아니라 대상이 아니다.

**DECISIONS.md에 남길 것 — §7-5 보강 한 건(②). 범위는 둘이다: 의미 목록(낱말 다섯) + 길이 규칙.**

§7-5는 태그 색마다 **괄호 안에 의미 목록**을 달아 둔다: `--danger`(막힘·증빙 없음·반려) ·
`--warning`(오늘·마감 임박) · `--accent`(내 차례·결재 중·편집 중) · `--success`(승인·연결·저장됨) ·
`--muted`(대기·미착수·임시). 이 페이즈는 **다섯 목록이 전부 닫힌 목록이라고 읽는다** — §7-5 원문에
「예」·「등」 같은 여지가 없고, 열린 목록으로 읽으면 색 선택이 화면마다 갈려 §7-5가 규칙 구실을
못한다. 그 읽기 아래에서 이 페이즈가 들여오는 상태 낱말 중 **다섯이 목록 밖**이다:

| 낱말 | 색 | §7-5의 어느 목록에 더하는가 |
|---|---|---|
| `진행` | `--accent` | 내 차례·결재 중·편집 중 **+ 진행 중** |
| 차수 `현재` | `--accent` | 〃 **+ 지금 기준이 되는 것**(최신 차수, D-54) |
| `완료(정산)` | `--success` | 승인·연결·저장됨 **+ 끝남(잠김)** |
| `미수주` | `--muted` | 대기·미착수·임시 **+ 닫힌 정상 결과** |
| 견적 줄 `취소` | `--muted` | 〃 **+ 무효가 된 줄** |

(`수주중`은 `대기`, 견적 줄 `미착수`는 `미착수`, 차수 `승인`은 `승인`에 이미 있다 — 보강 대상이 아니다.)

**② 길이 규칙 보강 — `완료(정산)`.** §7-5의 다음 줄은 「태그 글자는 두 글자~네 글자 명사: `막힘`
`오늘` `결재` `대기` `승인` `반려` `편집 중`. 문장 금지」다. 이 페이즈가 들여오는 여덟 낱말 중 일곱
(수주중·진행·미수주·미착수·취소·현재·승인)은 두~세 글자로 규칙 안이지만 **`완료(정산)` 하나가
규칙 밖**이다 — 일곱 예시 어디에도 괄호가 없다. 이 값은 제목 옆 `tag`와 목록 상태 열 `text`에
그대로 쓰이므로 규칙이 걸린다.

**라벨은 바꾸지 않는다.** `완료(정산)`은 **D-41**(「프로젝트 상태는 수주중 → 진행 → 완료(정산) +
미수주 네 가지다」, Reversibility costly)과 ROADMAP Phase 4 성공 기준 4가 잠근 업무 용어다.
(상태 **전환 주체**가 팀장 이상이라는 것은 D-46이고 라벨 잠금과는 다른 결정이다 — 두 결정을
섞지 않는다.) 그러므로 고치는 쪽은 라벨이 아니라 §7-5이고, 화면 예외가 아니라 시스템 규칙으로
고친다: **「상태 값이 업무 용어로 잠긴 경우 네 글자 명사 + 괄호 한정어 하나를 허용한다
(`완료(정산)`). 괄호 안은 두 글자, 문장 금지는 그대로.」** 괄호를 장식으로 쓰는 길을 열지 않으려고
「업무 용어로 잠긴 경우」라는 조건을 붙였다 — 앞으로 같은 자리에서 같은 답이 나온다.

계획 단계의 첫 태스크가 `docs/design/DECISIONS.md`에 **한 항목**으로 남긴다: 「§7-5 상태 태그를 두
가지로 보강한다. ⑴ 의미 목록에 낱말 다섯을 더한다(accent: 진행 중 · 지금 기준 / success: 끝남 /
muted: 닫힌 정상 결과 · 무효) — 프로젝트 목록 기본 보기가 전체 상태(D-51)라 네 상태가 한 화면에
섞이고, 지금 돌아가는 건과 끝난 건·안 된 건을 글자만으로 훑기 어렵다. 차수·견적 줄 상태도 같은
§7-5 태그를 쓴다. ⑵ 길이 규칙에 한 줄을 더한다 — 업무 용어로 잠긴 상태 값은 네 글자 명사 + 괄호
한정어 하나를 허용한다(`완료(정산)`, D-41이 잠근 값). 괄호 안은 두 글자, 문장 금지는 그대로」.
그리고 `SYSTEM.md` §7-5를 그대로 고친다. **둘 다 한 번에 고친다** — 한쪽만 고치고 나머지를 화면

막는 일이다.

### S2. 프로젝트 등록 폼 (form)

- **empty** — 폼 EMPTY는 「해당 없음」으로 이미 닫혀 있다(폼은 항상 칸이 있다). 진짜 빈 데이터인 Select 옵션 0개는 첫 옵션이 `—`이고 제출이 막히며 이유가 `Form.Actions`에 쓰인다. (§7-15 다섯 상태 EMPTY 행, §7-15 `Select` 항목)
- **loading** — 초기 렌더에 클라이언트 로딩 구간이 없다(서버 컴포넌트가 기본값을 채운다). 제출 중에만 1차 라벨 뒤 `…` + 같은 폼의 다른 버튼 비활성, 300ms 넘으면 상단 2px 진행 바. (§7-15 LOADING 행, §7-7 버튼 행)
- **error** — 서버 필드 오류는 해당 `Form.Error` 한 줄, 폼 전체 오류는 `Form.Actions`의 이유 자리. 폼 상단 오류 상자를 두지 않고 입력값은 오류 뒤에도 남는다(UX-04). 문구는 Copywriting `Error — 등록 폼 제출`. (§7-15 검증 관문)
- **partial** — 필수 4칸 중 하나라도 비면 제출 버튼이 비활성 + 옆에 막힘 한 줄(Copywriting `막힘 — 등록 폼 필수`)이고 `*` 표시를 쓰지 않는다. 복사 등록은 기간·번호·총 매출 예상가·매출 칸·연결 문서가 따라오지 않은 부분 채움 상태로 열리고 폼 위 한 줄이 출처를 밝힌다. (§7-15 PARTIAL 행, S2 복사 등록)
- **long-text** — statement: 긴 프로젝트명·긴 값을 넣어도 칸 폭이 3종(select 200 · 짧은 칸 280 · 긴 칸 480)을 벗어나지 않고 폼이 `--form-max` 720을 넘지 않는다 — 최장 입력으로 확인. · verification: backstop

### S3. 프로젝트 상세 골격 (static-content · interactive-control)

- **loading** — 상세는 서버 컴포넌트 렌더라 초기 로딩 구간이 없고, 「일괄 저장 Ctrl+S N」 등 서버 액션 중에만 §7-1 진행 상태(라벨 뒤 `…` + 다른 버튼 비활성, 300ms 후 상단 2px 진행 바)가 보인다. (§7-15 LOADING 행, Component Inventory `Button` `pending`)
- **error** — 화면 로드 실패는 Copywriting `Error — 상세` 한 줄 + `다시 시도`. 저장 실패는 화면 전체 거부이고 결과는 고친 자리에 붙는다(표는 그 표 합계 행, 표 밖 칸은 칸 아래). ((사), §7-7 ERROR)
- **overflow** — (U-1 해소, 04-01) 머리 줄은 `flex-wrap` — 좁은 폭에서 제목·부제·상태 태그·`종료일 지남`이 위에 남고 버튼군이 아래 한 줄로 내려간다. 버튼은 숨기거나 접지 않는다. 머리 줄도 375px 가로 스크롤 0. (2026-09-23) 부제에 `기간 …` + 「기간 바꾸기」가 더해져도 같은 규칙이고, 기간 칸이 열리면 머리 줄 **아래**에 붙는다(머리 줄 안에 입력을 두지 않는다, S13).
- **partial** — (2026-09-23) 상태별로 머리 줄 컨트롤 수가 다르다: 수주중 = 새 차수·복사·상태 바꾸기(팀장+)·저장 / 진행 = 새 차수·복사·저장(상태 바꾸기 없음, ⚠ S7) / 정산 = 복사·상태 바꾸기(대표·시스템 관리자)·저장(PM은 실행가 때문에 있음) / 완료 = 복사(+ 경영관리 저장) / 미수주 = 새 차수·복사·상태 바꾸기(팀장+)·저장. 없는 컨트롤 자리에 빈칸·비활성 버튼을 두지 않는다. (S3·S7 본문)
- **⚠ unresolved — planner must treat as assumption. 상태별 고객 승인.** D-56은 「담당 PM이 켠다 · 취소는 연결 문서가 없을 때만」까지이고 상태별 가용성은 정해지지 않았다. **권장 기본값(계획이 쓴다):** 3차 「고객 승인 표시」·「승인 표시 취소」는 **수주중·진행·미수주·정산에서 렌더**(담당 PM, 취소는 D-56 조건 그대로), **완료에서는 둘 다 렌더하지 않는다.** 정산을 여는 이유: 승인 표시는 견적 줄 편집이 아니라 D-78 잠금 밖이고, 정산에는 새 차수가 없으므로(⚠ S4) 현재 차수의 승인이 계약 금액(D-84)을 정하는 마지막 길이다. 완료를 닫는 이유: 완료는 잠김이고 되돌리기가 없어(D-47·D-79) 계약 금액도 거기서 굳는다. (Copywriting `Destructive — 고객 승인 표시 취소`, S3 본문 「고객 승인」)
- **long-text** — statement: 상세 제목의 긴 프로젝트명은 말줄임 없이 `word-break: keep-all`로 줄바꿈되고 부제·상태 태그가 그 아래로 밀리지 않는다(Typography가 프로젝트명을 명시) — 40자 이상 이름으로 확인. · verification: backstop

### S4. 견적 줄 표 (list-collection · form)

- **empty** — 표 본문 자리 한 줄, **상태 × 보는 사람마다 다른 변형 일곱**(0줄 프로젝트도 D-82 시작일만으로 진행 → D-76 자동 정산까지 가므로 정산·완료의 0줄은 실제로 닿는다): 수주중·진행·미수주의 줄 추가 권한자 = `… · 첫 줄 만들기 Ctrl+Enter`(`onClick`, 이동이 아니다) / 같은 상태의 권한 없는 사람 = `… · 담당 PM {이름}` / 정산의 기간 편집자 = `… · 정산 · 기간 바꾸기` / 정산의 그 밖 = `… · 정산 · 기간 늦추기는 팀장 {이름}` / 완료 = `… · 완료 · 견적 줄이 잠김` / 경영관리(상태 무관) = `… · 조정 줄 추가` / 이전 차수 읽기 표 = `이 차수에 견적 줄이 없습니다`. 어느 변형에도 **그 사람에게 렌더되지 않는 행동을 적지 않는다** — 정산·완료에 「첫 줄 만들기」가 없는 것(아래 ⚠ 정산 구조 잠금 · `SYSTEM.md` 개정 ④)과 문구가 맞는다. 0줄이면 표 위 잠김 한 줄은 그리지 않는다. 버튼 없는 변형은 `ListEmpty`의 `action` 생략. (Copywriting `Empty — 견적 줄 표` 여덟 행, Component Inventory `ListEmpty` 행, §7-7 EMPTY) — 다섯 상태 × 세 계급(담당 PM · 팀장 · 경영관리) + 권한 없는 사람 렌더로 문구·버튼 유무 확인. · verification: backstop
- **loading** — 머리글·합계 행 뼈대 + `--surface` 행 3개, 반짝임 없음, 300ms 지연 표시. 저장 중은 화면 1차 버튼 하나에서만 보인다. (§7-7 표 LOADING, §7-1)
- **error** — 오류 셀은 `--danger-weak` 배경 + 좌측 2px 인셋으로 **고정**되고(다른 셀을 편집해도 남는다) 이유 한 줄이 셀 아래 붙으며, 합계 행 오른쪽에 `오류 1칸 · 전부 거부`(충돌이면 `충돌 1줄 · 전부 거부`)가 온다. 셀 오류 다섯 갈래(형식·환율·읽기 전용·잠김·충돌) 문구는 Copywriting `Error — 셀(…)` 행. 로드 실패는 `Error — 상세` 한 줄. (§7-3, (나))
- **populated** — 대분류 그룹 머리글 + 11열 + 합계 행 `합계 (공급가액 · 6줄)`. 외화가 있는 행만 금액 셀이 두 줄이 되고 행 높이가 그 셀을 따른다(고정 높이 금지). (S4 본문, §7-3 외화 병기)
- **partial** — 값이 없는 거래처는 `—`, 수량 기본 1, 환율이 없으면 표시값 `계산 불가 · 환율 없음` + `계산 불가 N건` 배지이고 합계는 계산된 것만 더한다(빈 자리를 0으로 채우지 않는다). 붙여넣기가 오른쪽을 넘치면 합계 행에 `붙여넣기 · 오른쪽 2칸 버림`. 한 표에 편집·읽기 전용·잠김 셀이 섞여도 머리글 바탕은 화면 안에서 바뀌지 않는다. ((가), (다), Copywriting PARTIAL 행, §7-7 PARTIAL)

- **(2026-09-23) partial — 상한·정산·조정** — ① 300줄에 닿으면 「줄 추가」 비활성 + 이유, `Ctrl+Enter`·`Ctrl+D`는 아무 줄도 만들지 않고 합계 행에 같은 이유. 상한을 넘기는 붙여넣기는 한 칸도 바꾸지 않고 전부 거부. ② 정산: 실행가 셀만 편집, 나머지 셀은 잠김 + 표 위 한 줄 `정산 · 실행가만 고칠 수 있음`, 머리글은 `--g-100`(PM에게 편집 셀이 있다). ③ 조정 줄: 맨 아래 `조정` 그룹, PM에게는 행 전체가 읽기 전용. - **(2026-09-23) error — 다른 페이지의 오류** — 저장이 거부되면 오류 칸이 있는 **첫 페이지로 옮기고 첫 오류 셀에 포커스**한다. 페이지 줄의 번호 옆 `오류 N`이 나머지 페이지의 오류를 말한다(색만이 아니라 글자, §10). dirty·오류·충돌 표시는 페이지를 오가도 남는다. (S12, Copywriting `표시 — 페이지`)
- **⚠ unresolved — planner must treat as assumption. 정산 중 구조 잠금.** D-78 본문은 「실행가만」이고, 「줄 추가·삭제·새 차수도 잠근다」는 CONTEXT의 *Claude 해석(계획 검토 때 확인)*이다. **권장 기본값: 해석대로 잠근다** — 정산에서는 「줄 추가」·「첫 줄 만들기」·「복사해 새 차수」를 렌더하지 않고 Delete·`Ctrl+Enter`·`Ctrl+D`·`Alt+↑↓`는 아무 일도 하지 않으며, 표 위 한 줄 `정산 · 실행가만 고칠 수 있음`이 이유를 말한다. 경영관리의 「조정 줄 추가」만 예외(D-83). 0줄 정산 표의 EMPTY도 이 기본값을 따른다(「첫 줄 만들기」 대신 `정산 · 기간 바꾸기` / `정산 · 기간 늦추기는 팀장 {이름}`). 계획 검토에서 사용자가 뒤집으면 이 행과 정산 EMPTY 두 변형만 바뀐다.
- **(rev 4 체커 수정) partial — 조정 줄 추가 상한** — 경영관리의 「조정 줄 추가」도 300줄 상한에 닿으면 비활성 + 옆 `조정 줄 추가할 수 없음 — 300줄 상한 · 상한은 관리자 설정`. (Copywriting `막힘 — 조정 줄 추가(상한, 경영관리)`)
- **⚠ unresolved — planner must treat as assumption. 조정 줄과 복사.** D-53(「이전 차수 전체 복사」)·D-70(「현재 차수 줄」)은 D-83 이전 결정이라 조정 줄을 말하지 않는다. **권장 기본값(계획이 쓴다): 조정 줄은 「복사해 새 차수」도 「프로젝트 복사」도 복사하지 않는다** — 경영관리가 그 프로젝트에 붙인 원가 보정이지 PM의 견적 구조가 아니다. 사용자가 보는 것:
  - **새 차수**: 확인 모달의 `N줄`은 조정 줄을 빼고 센다. 조정 줄이 있으면 결과 줄 `조정 2줄은 복사하지 않고 3차에서도 그대로 보입니다`. 새 현재 차수의 표 맨 아래 `조정` 그룹에 **같은 줄이 그대로**(복사본·계보 없음, 값·작성자 그대로) 보이고, 목록의 실행가·수익금은 차수가 바뀌어도 조정 금액만큼 그대로다(D-87 「현재 차수 실행가 합계 + 조정 줄」). 「차수 열기」로 보는 **이전 차수 읽기 표에는 `조정` 그룹이 없다**(그 차수의 줄만).
  - **프로젝트 복사**: 폼 위 한 줄 `26001 아이오닉9에서 복사 · 6줄`의 줄 수에서 조정 줄을 뺀다. 새 프로젝트의 표에 `조정` 그룹이 없다. 따라오지 않는 목록(S2)에 조정 줄을 더한다.
  - **접은 대안**: 조정 줄을 차수에 묶고 새 차수에서 버리는 읽기 — PM이 새 차수를 만드는 순간 경영관리가 넣은 송금 수수료 같은 실제 원가가 실행가·수익금에서 사라진다. 조정 줄을 차수 복사에 포함하는 읽기 — PM이 고칠 수 없는 줄(D-83)이 PM의 행동으로 두 벌이 된다.
  - 데이터 모델(프로젝트 소속 vs 차수 소속 + 이월)은 D-83이 계획에 맡긴 그대로다 — 이 행은 **화면에 보이는 결과**만 고정한다.

### S5. 차수 섹션 (list-collection)

- **empty** — 0행 상태가 존재하지 않는다: 프로젝트를 등록하면 상세 견적 1차가 항상 함께 생기므로 EMPTY 자리를 만들지 않는다(빈 차수 금지). (Copywriting `Empty — 차수 섹션`, D-53)
- **loading** — 섹션 단독 로딩이 없고 상세 화면 한 번의 로딩에 들어간다. 그 형태는 §7-7 표 LOADING(머리글·합계 뼈대 + `--surface` 행 3개)과 같다. (§7-15 LOADING 행, §7-7 표 행)
- **error** — statement: 차수 섹션은 제 오류 자리를 갖지 않고 상세 로드 실패 한 줄(Copywriting `Error — 상세`)에 흡수된다 — 섹션 단독 오류 렌더가 없음을 확인. · verification: backstop
- **populated** — 6열(차수·생성일·줄 수·견적 합계·상태·동작) · 최신이 위 · 상태 열은 `현재`/`승인` 두 낱말 · 이전 차수 행에만 「차수 열기」. 편집 가능한 셀이 0이므로 `role="grid"`가 아니라 `<table>` + 시각적으로 숨긴 `<caption>`이고 머리글은 흰 바탕이다. (S5 본문, (가))
- **partial** — (U-2 사용자 확정) ⓐ 최신이면서 고객 승인된 차수 = `승인`만(`success`, `현재` 없음 — 맨 위 위치가 「현재」를 말한다) ⓑ 승인 없이 지나간 이전 차수 = **빈 칸**(`—`로 채우지 않는다, 새 낱말 없음). 딸린 조건: 폰 P2 접힌 줄은 **빈 값 자리를 건너뛴다**(`· 2026-09-19 · 6줄`이 아니라 `2026-09-19 · 6줄`). 현재 차수 행의 동작 칸도 `—`로 채우지 않는다.
- **overflow** — P1 = 차수 · 견적 합계 · (동작), P2 접힌 줄 = 상태 · 생성일 · 줄 수, P3 없음. 375px 가로 스크롤 0이고 `현재` 행의 빈 동작 칸을 `—`로 채우지 않는다. (S5 열 우선순위 선언, §7-3 폰 전략, S11)
- **zero-one-many** — 0은 구조적으로 없고(위 empty), 차수가 하나뿐이면 `현재` 한 행에 동작 칸이 비어 「차수 열기」가 표에 하나도 없으며, 여럿이면 최신이 맨 위이고 그 아래 행에만 버튼이 붙는다. (S5 본문, D-53·D-54)

### S6. 매출 섹션 (static-content · list-collection) — 2026-09-23 개정

- **empty** — 발행 줄 표와 입금 줄 표가 각각 제 EMPTY 한 줄을 갖는다. 경영관리에게는 + 제 3차 추가 버튼, 표를 읽기로만 받는 사람에게는 버튼 없이 담당자 — 발행 `· 발행은 경영관리`(기획본부 포함, D-85) · 입금 `· 입금은 경영관리`(입금액을 볼 수 있는 계급만. 못 보는 사람은 입금 표 자체가 없다). 계약 금액은 값이라 EMPTY가 아니라 `—`(현재 차수 미승인). (Copywriting `Empty — 발행 줄 / 입금 줄`·`표시 — 계약 금액(파생)`)
- **loading** — 두 표 모두 §7-7 표 LOADING 뼈대이고 계약 금액 줄은 서버 렌더라 로딩 구간이 없다. 저장 중 표시는 화면 1차 버튼 하나에만 난다. (§7-7 표 행, (사))
- **error** — 표 셀 오류는 그 표 합계 행에 `오류 1칸 · 전부 거부`로 나오고 화면 전체가 거부된다. 계약 금액은 입력이 아니라 오류 자리가 없다(D-84). (S6 본문, Copywriting `Error — 표 배치 저장 실패`)
- **populated** — 계약 금액 한 줄(KvList, 값 + 2행 부가세·합계·출처) + 발행·입금 두 표. 입금 셀은 통장 합계 1행 + 공급가액 역산 2행이고 외화면 같은 2행에 이어 쓴다(3행으로 늘리지 않는다). (S6 본문, §2-4 외화 두 줄 병기)
- **partial** — 입금 합계 ≠ 발행 합계면 입금 표 합계 행 오른쪽에 `미수` 또는 `초과 입금`(`--warning`). **기획본부(D-85)**: 계약 금액 + 발행 표(읽기, 흰 머리글, `<caption>`)만 받고 **입금 표는 표 단위로 빠진다** — 미수·초과 입금 표시는 입금 표 합계 행에 있으므로 함께 빠진다(발행액과 미수를 둘 다 보이면 입금액이 역산된다). 섹션 부제도 `공급가액 기준`만. (S6 본문, D-58·D-85)
- **overflow** — statement: 발행·입금 표는 열이 셋(발행일/입금일 · 금액 · 메모)이라 §7-3 P1 최대 3열 안에 전부 들어가고 375px에서 가로 스크롤이 0이다. 계약 금액 2행은 폰에서 줄바꿈하되 숫자는 꺾지 않는다 — DOM 감사로 확인. · verification: backstop
- **zero-one-many** — (U-3 해소, 04-02) 발행 줄이 있고 입금 줄이 0이면 입금 표의 EMPTY 한 줄과 합계 행이 **공존**한다 — 합계 금액 0 + 오른쪽 미수 전액.
- **long-text** — statement: 발행·입금 표의 메모 셀은 긴 칸(480) 규칙 아래 PC에서 한 줄 말줄임으로 렌더되고 행 높이를 늘리지 않는다(S4 비고와 같은 취급) — 긴 메모 DOM 감사. · verification: backstop

- **long-text** — statement: 리저브 메모 셀은 긴 칸(480) 규칙 아래 PC에서 한 줄 말줄임으로 렌더되고 행 높이를 늘리지 않는다(S4 비고와 같은 취급) — 긴 메모 DOM 감사. · verification: backstop

### S10. 문서 번호 표시 (static-content)

- **overflow** — 번호 열은 자릿수 고정 폭(`ch`)이고 `white-space: nowrap`이라 어떤 폭에서도 줄바꿈하지 않으며, 폭이 모자라면 숫자를 꺾는 대신 열을 접는다(목록의 번호 열은 폰 P3). (S10 본문, §2-4, §7-3 폰 전략)
- **long-text** — 문서 번호는 서버 서식 그대로의 고정 길이 문자열(`26001` · `26001-1차`)이고 모노 서체가 아니라 `tabular-nums`이며 말줄임·줄바꿈을 적용하지 않는다. 결번이 생겨도 화면에 설명을 덧붙이지 않는다. (S10 본문, §2-4 문서 번호, D-42)

### S12. 페이지 이동 (interactive-control) — 신설 2026-09-23

- **empty** — 해당 없음: 한 페이지에 다 들어가면(목록 50건 이하 · 견적 줄 30줄 이하) 페이지 줄 자체가 없다. 빈 페이지 줄을 두지 않는다. (S12 본문)
- **loading** — 목록은 GET 이동이라 상단 2px 진행 바 + 표 LOADING 뼈대(§7-7). 견적 줄 표는 이미 받은 줄을 화면 안에서 나누므로 로딩 구간이 없다. (S12 본문)
- **error** — 목록: 범위 밖 페이지 번호(`?page=99`)는 오류가 아니라 **마지막 페이지로** 보인다. 견적 줄: 저장 거부 뒤 번호 옆 `오류 N`(S4 error). (Copywriting `표시 — 페이지`)
- **populated** — `51–100 / 125건` + `이전 · 1 2 3 · 다음`. 현재 번호는 `--fg` 700 링크 아님(`aria-current="page"`), 나머지는 3차. 첫 페이지에서 `이전`, 끝 페이지에서 `다음`은 **렌더하지 않는다**(이유 없는 비활성 버튼 0개, §11). (S12 본문)
- **overflow** — 페이지가 8개 이상이면 `1 … 4 5 6 … 12`(첫·끝·현재 ±1, 사이는 `…`). 폰에서 번호 버튼은 44×44, 한 줄에 안 들어가면 범위 텍스트가 위 줄로 올라간다. 가로 스크롤 0. · verification: backstop
- **zero-one-many** — statement: 1쪽이면 페이지 줄 없음, 2쪽이면 `1 2`, 12쪽이면 생략 부호 — 렌더로 확인. · verification: backstop

### S13. 상세 기간 칸 (form) — 신설 2026-09-23

- **empty** — 해당 없음(칸은 항상 둘). 값이 없으면 부제에 `기간 미정`이 보이고 칸을 열면 빈 입력 둘(자리표시자 `2026-09-18`). (S13 본문)
- **loading** — 해당 없음 — 서버 렌더 값. 저장은 화면 1차 「일괄 저장」 하나의 진행 상태를 따른다. ((사))
- **error** — 칸 아래 `Form.Error` 한 줄, 화면 전체 거부(각 표 합계 행에는 `전부 거부 · 다른 칸 오류 1칸`, U-6). (Copywriting `Error — 기간 칸`)
- **partial** — 결과 미리보기 `Form.Hint`(진행 복귀 · 정산 전환 · 종료일 비움)는 조건이 맞을 때만 한 줄. 편집 권한이 없으면 「기간 바꾸기」 자체가 없다. (Copywriting `표시 — 기간 칸 결과 미리보기`)
- **long-text** — 해당 없음(날짜 두 칸, 고정 폭 280).
- **⚠ unresolved — planner must treat as assumption. 기간을 누가 언제 고치나.** D-80은 「정산 → 진행 되돌리기는 팀장 이상이 종료일을 늦출 때」만 말하고, 수주중·진행에서 PM이 기간을 고칠 수 있는지는 정해지지 않았다. **권장 기본값:** 수주중·진행·미수주 = 담당 PM + 팀장 이상, 정산 = 팀장 이상만(D-78이 PM의 정산 편집을 실행가로 좁혔다), 완료 = 아무도(잠김). 진행에서 종료일을 오늘 이전으로 당기면 다음 날이 아니라 **다음 판정 때 바로** 정산이 된다(D-76의 「종료일 다음 날 00:00」을 이미 지났으므로) — Hint가 그것을 말한다.
- **⚠ unresolved — planner must treat as assumption. 진행 중 PM의 종료일 앞당기기(위 기본값의 결과).** 위 기본값대로면 진행의 PM이 종료일을 어제 이전으로 적어 저장하는 순간 프로젝트가 정산이 되고, 정산 → 진행은 팀장 이상(D-80)이라 **PM이 제 손으로 되돌릴 수 없는 전환**을 일으킨다. 상태 전환은 팀장의 일이라는 D-46의 취지와도 어긋난다. **권장 기본값(계획이 쓴다): 진행에서 PM은 종료일을 오늘(KST) 이후로만 적을 수 있다. 오늘보다 이른 종료일은 팀장 이상만.** PM이 그런 날짜를 적으면 칸 아래 `Form.Error` `종료일은 오늘부터 적을 수 있습니다 · 앞당기려면 팀장 {이름}`이고 칸은 `aria-invalid`, 저장은 화면 전체 거부(서버도 같은 규칙으로 거부 — 클라이언트 판정은 편의일 뿐이다). 그래서 `저장하면 정산이 됨` Hint는 팀장 이상에게만 닿는다. 시작일·수주중·미수주에는 이 제한이 없다(수주중은 종료일이 지나도 자동 전환이 없다, D-81). (Copywriting `Error — 기간 칸`)

### S14. 코드표 설명 (form · list-collection) — 신설 2026-09-23

- **empty** — 설명이 없는 값: 코드표 화면 설명 칸 `—`, 고르는 자리에서는 설명 줄 자체가 없다(`—`를 힌트로 띄우지 않는다). (S14 본문)

- **error** — 코드표 화면에서 설명 저장 실패는 이름 칸과 같은 자리·같은 모양(칸 아래 `--danger` 한 줄, 값은 서버 값으로 되돌림 — `CodeItemLabelInput` 선례). (Copywriting `Error — 코드표 설명`)
- **populated** — 코드표 표 6열(값 · 이름 · 설명 · 정렬 · 상태 · 동작). 고르는 자리: 폼 `Select` 아래 `Form.Hint` 한 줄, 표 셀은 편집 중에만 셀 아래 한 줄, 상태 고르기 목록은 행 2행. (S14 본문)

### S15. 숫자 입력·표시 (전역 — D-95) — 신설 2026-09-23

### 7-3 보강 — 편집 표의 구현 계약 (Phase 4)

§7-3 본문(구조·편집 키·외화 병기·폰 칸 접기·칸 수 가변)은 그대로 둔다. 아래 여덟 항목을 그 절 끝에
더한다. 표는 **자체 구현**이다 — HTML `<table>` + 키보드 포커스 이동·범위 선택·붙여넣기를 직접 쓰고
새 런타임 의존성을 더하지 않는다(D-61).

**(가) 셀 편집 가능성 3단계 — 서버가 셀마다 판정해 보낸다(클라이언트 추론 금지)**

| 단계 | 언제 | 모양 | ARIA |
|---|---|---|---|
| 편집 | 기본 | 흰 셀. 클릭 또는 Enter로 편집 | `aria-readonly="false"` |
| 읽기 전용 | 연결 문서가 있는 줄의 금액 셀(수량·단가·실행가·환율) — 항목명·비고는 편집(D-66). 계산 열(견적가·차익·잔액)도 항상 이 단계 | 값만, 배경 없음. 포커스는 되지만 편집에 들어가지 않는다. 편집 시도 시 셀 아래 한 줄 `--fs-sm --muted` 이유(§7-2와 같은 자리) | `aria-readonly="true"` |
| 잠김 | 완료(정산) 프로젝트의 견적 줄 전체(D-47) | 읽기 전용과 같고, 표 위에 한 줄 `--fs-sm --muted` `완료(정산) · 견적 줄이 잠김` | 〃 |

- **머리글 바탕은 "이 사람이 이 표에서 편집할 수 있는 셀이 하나라도 있는가"로 정한다.** 있으면
  `--g-100` + `--g-950`(편집 가능 신호), 없으면 흰 바탕(읽기용 표). 완료 프로젝트를 보는 PM은 흰
  바탕, 같은 화면을 보는 경영관리는 `--g-100`(「견적 외 비용 줄 추가」가 가능하므로)이다. 사람마다
  다르고 **화면 안에서 바뀌지 않는다**.
- 편집 가능한 셀이 하나도 없는 표는 `role="grid"`가 아니라 `<table>` + 시각적으로 숨긴 `<caption>`로
  렌더한다(§10).
- **이것은 모드 토글이 아니다.** §7-3 본문의 「읽기 모드와 편집 모드를 나누지 않는다 — 편집 권한이
  있으면 표는 항상 편집 가능하다」는 그대로다. 위 두 줄은 사용자가 켜고 끄는 모드가 아니라 **편집
  가능한 셀 수가 0일 때 컴포넌트가 자동으로 취하는 렌더 형태**이고, 그 판정은 서버가 보낸 셀 단계에서
  파생된다. 이 문서에서 「`ui/table` 읽기 모드」라고 적은 곳은 전부 이 파생 형태를 가리킨다.

**(나) 줄 버전 충돌(D-65)**

- 각 줄은 `version`을 함께 받고 함께 보낸다. 저장 요청이 읽은 버전과 다르면 **그 줄에서 실제로 값이
  달라진 셀만** §7-3 충돌 모양(오류 셀과 같은 고정)으로 표시하고, 이유 한 줄에 **실제 바뀐 값·사람·
  시각**을 적는다: `다른 사람이 14:01에 9,800,000으로 바꿈 · 덮어쓰기 / 그 값으로`. 두 다음 한 수는
  3차 버튼이다.
- 충돌이 **하나라도** 있으면 §7-3 「전부 저장 또는 전부 거부」대로 배치 전체를 거부하고 합계 행에
  `충돌 1줄 · 전부 거부`. 다른 셀의 편집값은 그대로 남는다.

**(다) 붙여넣기 정규화(D-67)**

- 클립보드 `text/plain`을 TSV로 읽는다(행 `\n`, 칸 `\t`). 활성 셀에서 오른쪽·아래로 채운다.
- 숫자 열: 쉼표·공백·통화 기호를 지우고 숫자로 읽는다. 그래도 숫자가 아니면 **그 셀을 오류 셀로
  고정**한다(조용히 버리지 않는다).
- 문자 열: 그대로, 앞뒤 공백만 지운다.
- 읽기 전용·잠김 셀에 값이 떨어지면 **건너뛰지 않고 오류 셀로** 표시한다 — 조용히 버리면 값이
  유실된 것처럼 보인다.
- 아래를 넘으면 새 줄 자동(§7-3 원문). **오른쪽을 넘는 칸은 버리고** 합계 행에
  `붙여넣기 · 오른쪽 2칸 버림`(`--warning`)을 남긴다.
- Ctrl+C 범위 복사도 같은 TSV를 클립보드에 쓴다 — 그래서 **다른 프로젝트의 표에서 그대로 붙는다**
  (별도 가져오기 모달을 만들지 않는 이유, D-70·PROJ-05).

**(라) 줄 순서와 그룹 머리글(D-62·D-63)**

- 그룹 머리글 = 대분류. 줄의 **소분류 열 값에서 파생**되고 그룹 순서는 코드표 `sort_order`다. 대분류
  열을 따로 두지 않는다.
- 그룹 머리글 행은 편집 대상이 아니고 포커스를 받지 않는다 — 방향키가 건너뛴다.
- 그룹 안에서 만든 새 줄(Ctrl+Enter)은 그 그룹의 대분류를 물려받는다(소분류가 미리 채워지고 그 셀이 편집
  상태로 열린다).
- 줄 이동은 `Alt+↑` / `Alt+↓`. 그룹 경계를 넘으면 소분류가 비워지고 그 셀이 편집 상태로 열린다.
- 줄 순서는 입력 순서 값으로 저장한다(정렬이 아니라 값이다).

**(마) 미저장 편집 복원(D-68)**

- dirty 셀이 하나라도 있으면 `beforeunload`로 이탈을 경고한다.
- 편집은 브라우저 저장소에 임시 보관한다. 키는 `프로젝트 id + 차수 id`(리저브는 화면 id). 저장
  성공·「버림」에 지운다.
- 다시 열었을 때 보관된 편집이 있으면 **표 위 한 줄**로 알린다(`--fs-sm`):
  `저장 안 한 편집 3칸 · 복원 / 버림`, 둘 다 3차 버튼. **§7-11 배너가 아니다** — 배너는 화면 제목 위
  전역 조건의 자리이고 이것은 한 표에 붙은 상태다.
- 「복원」하면 그 셀들이 dirty 모양으로 들어온다. 그 사이 줄의 `version`이 올라갔으면 저장 시점에
  (나)의 충돌로 간다. 「버림」은 확인 모달 없이 즉시(저장된 값은 그대로다).

**(바) 폰 행 시트(D-69)**

- §7-8 시트 골격. 머리 = 항목명(`--fs-lg`) + 부제 `{소분류} · {거래처}`.
- 본문 = `KvList`(`dl`)로 접힌 P2·P3 전부: 수량 · 단가 · 견적가 · 차익 · 환율 · 비고 · 상태. 외화는
  값 아래 2행(`--fs-sm --muted`).
- **행동 줄을 두지 않는다 — 보기 전용이다.** 「지출결의 올리기」는 그 문서가 생기는 페이즈가 더한다.
- 폰에서 셀 편집은 없다(§6-2). P1 3열은 **항목 · 실행가 · 상태**(D-64).

**(사) 저장 범위와 1차 버튼**

- 화면의 1차 버튼 **「일괄 저장 Ctrl+S N」 하나**가 그 화면의 **모든 편집 표**(견적 줄 + 매출 발행 줄 +
  입금 줄) **+ 표 밖의 편집 칸(매출 계약 금액)**의 dirty를 **한 트랜잭션**으로 저장한다.
  `N` = 화면 전체 dirty 칸 수(표 셀 + 계약 금액 칸).
- **저장 범위는 「이 화면에서 고칠 수 있는 것 전부」이지 「표」가 아니다.** 표 밖에 편집 칸이 하나라도
  있으면 그 칸도 같은 1차 버튼·같은 트랜잭션에 들어간다. 그러지 않으면 그 칸이 제 저장 버튼을 갖게
  되고 한 화면에 1차가 둘이 된다(§7-1 「한 화면에 1개」).
- 결과는 **고친 자리에 붙는다**(§7-7 SUCCESS): 표의 dirty는 그 표의 합계 행에, 표 밖 칸의 dirty는 그
  칸 자리에(성공 = 600ms `--accent-weak` 틴트, 오류 = 칸 아래 `Form.Error` 한 줄).
- 오류·충돌이 한 칸이라도 있으면 **화면 전체가 거부**된다(§7-3 「전부 저장 또는 전부 거부」). 표 밖
  칸의 오류도 같은 거부에 걸리고, 각 표의 합계 행에도 거부가 표시된다.
- 쓰기 권한이 갈려도(계약 금액 = PM, 발행·입금 = 경영관리, D-57) 버튼은 하나다 — 권한 판정은
  서버가 칸마다 하고(위 (가)), 한 사람에게 dirty가 되는 칸은 애초에 그 사람이 고칠 수 있는 칸뿐이다.
- 표가 여럿이어도 저장 자리는 하나다 — 사용자가 「저장」의 위치를 하나만 기억한다.

**(아) `role="grid"` 키보드 계약(§10 보강)**

- 표 전체가 탭 정지 **1개**. 안에서는 방향키 로빙 `tabindex`로 움직인다.
- `Esc`: 편집 중이면 그 셀 값을 되돌리고, 편집 중이 아니면 범위 선택을 해제한다.
- `Delete`: 줄 삭제 확인 모달(§7-3 원문). 셀 값 비우기는 편집에 들어가 지운다.
- 오류·충돌 셀은 `aria-invalid="true"` + `aria-describedby`로 이유 줄을 가리킨다. 합계 행의 저장
  결과는 `aria-live="polite"`.
- 힌트 줄(§7-9, 최대 7개)은 이 화면에서 정확히 일곱이다:
  `이동 Tab ↑↓←→ · 범위 복사 Ctrl+C / 붙여넣기 Ctrl+V · 취소 Esc · 새 줄 Ctrl+Enter · 줄 이동 Alt+↑↓ · 줄 복제 Ctrl+D · 저장 Ctrl+S`.
  지출결의 `Ctrl+E`가 붙는 페이즈에서 `줄 복제 Ctrl+D`를 뺀다(일곱을 넘지 않는다).

### 7-8 보강 — 2차 라벨이 1차와 겹칠 때 (Phase 4)

§7-8은 확인 모달·시트의 2차를 「취소 Esc」로 고정한다. 그런데 **취소하는 것이 행동 자체인 모달**이
이 페이즈에서 둘 생긴다(`견적 줄 취소` · `승인 표시 취소`). 같은 줄에 「견적 줄 취소」와 「취소 Esc」가
나란히 서면 어느 쪽이 되돌리기인지 읽히지 않는다. 아래 한 줄을 §7-8에 더한다.

- **1차 라벨에 「취소」가 들어가면 그 모달·시트의 2차는 「닫기 Esc」로 적는다.** 그 밖에는 언제나
  「취소 Esc」다. 라벨만 바뀌고 동작(Esc · 포커스 복귀 · 아무 일도 일어나지 않음)은 그대로다.
- 화면별 예외가 아니라 **1차 라벨에서 기계적으로 파생되는 규칙**이다 — 앞으로 「반려 취소」·
  「예약 취소」 같은 모달이 생겨도 같은 자리에서 같은 답이 나온다.

### 7-15. 폼 (`ui/form` · `ui/select`) — 신설

§6-3이 폼 **화면**의 레이아웃이고 §7-2가 **입력 하나**의 규칙이라면, 이 절은 그 둘을 잇는 **컴포넌트
계약**이다. Phase 4가 만들고(**사용처 둘 — 프로젝트 등록 폼 · 매출 계약 금액 칸.** 리저브 줄은 폼이
아니라 §7-3 편집 표다, S9) **Phase 7**이 관리자 폼 8개와
`/account`를 이 계약으로 이관한다(03-OPEN-ITEMS A-H2·A-H3).

**구성**

- `Form` — `<form noValidate>` + 한 열, `max-width: var(--form-max)`(720), 왼쪽 정렬. 항목 사이
  `--s-4`, 묶음 사이 `--s-6` + `1px --line`.
- `Form.Field` — 라벨 열(PC `--label-w` 96, `--fs-sm --muted` 600) + 컨트롤. 폰(<700px)에서 라벨이
  위로 올라가고 컨트롤은 전폭.
- 칸 폭 **3종만**: select 200 · 짧은 칸(금액·날짜·수량·환율) 280 · 긴 칸(이름·비고) 480.
- `Form.Hint` — 컨트롤 바로 아래 한 줄 `--fs-sm --muted`, 숫자만 700. **서버 계산 값의 자리**(§6-3):
  `부가세 10% 4,800,000 · 합계 52,800,000 · 서버 계산`. 읽기 전용 행을 따로 두지 않는다.
- `Form.Error` — 컨트롤 아래 한 줄 `--fs-sm --danger` 「원인 · 다음 행동」. `TextField`의
  `aria-describedby`가 이 줄을 가리킨다.
- `Form.Actions` — 폼 맨 아래 한 줄: 1차(제출) + 옆에 막힘 이유(`--fs-sm --danger`) + 다음 한 수 3차,
  오른쪽 끝에 2차. 1차 버튼의 `aria-describedby`가 이유를 가리킨다(`role="alert"`가 아니다 — 누르기
  전에 읽혀야 한다, §10).
- **`Form.Actions`는 폼이 자기 제출을 가질 때만 둔다.** `Form.Actions`는 1차 버튼을 데려오므로, 이미
  1차를 가진 화면 안에 섞여 들어간 칸에 이것을 두면 한 화면에 1차가 둘이 된다(§7-1 「한 화면에 1개」,
  §11 `/design-review`가 잡는다). 그런 칸은 `Form.Field` + `Form.Hint` / `Form.Error`만 쓰고
  **`Form.Actions` 없는 단일 칸 폼**으로 렌더한다 — 제출은 그 화면의 1차 「일괄 저장 Ctrl+S N」 하나이고,
  칸이 dirty면 `N`에 1칸으로 합류해 §7-3 「전부 저장 또는 전부 거부」에 같이 걸린다(위 (사)).
  `<form>` 요소는 그대로 두되 `Enter` 기본 제출을 막고 Ctrl+S에 맡긴다.
  **이것은 화면별 예외가 아니라 §7-15의 일반 규칙이다** — 「이 칸의 저장은 누구 책임인가」를 폼이
  아니라 화면이 답한다. 대안으로 §7-2 설정 화면식 blur 즉시 저장도 검토했으나, 같은 화면의 표가
  Ctrl+S 일괄 저장이라 한 화면에 저장 의미가 둘이 되고 「전부 저장 또는 전부 거부」가 칸 하나를 비켜
  가므로 접었다.
- `Select` — 네이티브 `<select>` + 시스템 테두리(§7-2). 커스텀 드롭다운을 만들지 않는다. 고를 것이
  없으면 첫 옵션이 `—`이고 제출이 막히며 이유는 `Form.Actions`에 쓴다.
- 자동으로 채워진 칸은 입력이 아니라 텍스트 + 「바꾸기」 3차 버튼(§6-3).

**검증 관문은 서버 하나** (A-H3 해소)

- 네이티브 `required`·`pattern`·`type="number"` **검증 위임을 걷어낸다.** 브라우저 기본 말풍선(영문·
  시스템 서체)이 §7-2의 「원인 · 다음 행동」을 가로채기 때문이다. `noValidate`를 `<form>`에 둔다.
- 필수 표시 `*`를 두지 않는다(§7-2). 필수인데 비면 **제출 버튼이 이유를 말한다**:
  `등록할 수 없음 — 클라이언트 · 담당 PM 2칸 · 클라이언트 고르기`.
- 서버가 돌려준 필드 오류는 해당 `Form.Error`에, 폼 전체 오류는 `Form.Actions`의 이유 자리에.
  **폼 상단 오류 상자를 두지 않는다**(§7-7 폼 행 "상단 한 줄 없음").
- 입력값은 오류 뒤에도 남는다(UX-04).

**다섯 상태**

| 상태 | 모양 |
|---|---|
| LOADING | **해당 없음** — 서버 컴포넌트가 기본값을 채워 렌더한다. 제출 중은 §7-1 버튼 규칙(라벨 뒤 `…`, 같은 폼의 다른 버튼도 비활성, 300ms 넘으면 상단 2px 진행 바) |
| EMPTY | **해당 없음** — 폼은 항상 칸이 있다 |

- §8 규칙 3(「오류 = 원인 · 다음 행동」) 아래에 한 줄: **「다음 한 수가 그 사람의 권한 밖이면 버튼을 비활성으로

    기준 수익금 + 실행가를 알면 발행 합계가 역산되기 때문이다. 합계 줄도 같은 규칙.

  `?page=`(04-05의 `count` 누적 파라미터는 없어진다).

### S2. 프로젝트 등록 `/projects?new=1` (§6-1 토글 + §7-15)

- 칸: 클라이언트(Select 200, 자동완성) · 프로젝트명(480) · 담당 PM(Select 200) · 팀(Select 200) ·
  시작일(280) · 종료일(280) · **총 매출 예상가**(280 + 통화 Select 200 + 환율 280).
- 필수는 클라이언트·프로젝트명·담당 PM·팀 넷(`docs/inputs` §9). **기간은 선택**(D-49) — 진행 전환
  게이트가 그때 말하므로 폼에 설명을 두지 않는다(§8 규칙 5).
- 「총 매출 예상가」는 사전 견적이다(D-52). 견적 줄이 아니라 프로젝트 속성이고 이 칸에서 지출결의를
  올릴 수 없다. 라벨은 사용자 용어 그대로.
- 상태·번호는 폼에 없다 — 등록은 항상 수주중이고 번호는 서버가 매긴다(D-42). 둘은 등록 후 상세
  머리 줄에서 처음 보인다.
- **폼이 열려 있으면(`?new=1`) 목록 필터 줄의 1차 「프로젝트 등록」은 렌더되지 않는다.** S1과 S2는
  §6-1·D-39에 따라 **같은 라우트**이므로, 그러지 않으면 한 화면에 1차 버튼이 둘 된다(§7-1 「한
  화면에 1개」 위반이고 §11 `/design-review`가 잡는다). 그 자리에는 아무것도 두지 않는다 — 돌아가는
  길은 폼 자신의 2차 「취소 Esc」다(§6-1 원문). 이 규칙은 `?new=1&copyFrom=`에도 같이 적용된다.
- **복사 등록**(D-70): `?new=1&copyFrom={id}`. 기본 정보 + 현재 차수 줄이 미리 채워지고 폼 위 한 줄
  `--fs-sm --muted` `26001 아이오닉9에서 복사 · 6줄`. 기간·번호·총 매출 예상가·매출 칸·연결 문서·줄
  계보·**조정 줄**(⚠ UI Considerations S4 「조정 줄과 복사」 — 줄 수 `6줄`에도 세지 않는다)은 따라오지 않는다. 별도 가져오기 모달은 없다.
- 제출 → 상세로 이동 + 토스트 `프로젝트 등록 · 26001`.

### S3. 프로젝트 상세 = 견적 원장 `/projects/[id]` (§6-2)

- 머리 줄: 제목 = 프로젝트명(`--fs-lg` 700) · 부제 = `26001 · 상세 견적 2차 · 고객 승인 2026-09-19
  박서연 · 기간 2026-09-12 ~ 2026-09-16 · 정산 2026-09-17` + 상태 태그(§7-5 `tag`, **`kind`는 Color
  매핑표** — 지금 실물의 `muted` 고정은 고친다) + (해당 시) `종료일 지남`. 오른쪽 버튼군: 2차 「복사해 새
  차수」 · 2차 「프로젝트 복사」 · 2차 「상태 바꾸기」 · **1차 「일괄 저장」 + kbd `Ctrl+S`**. 부제의
  상태 항목은 D-50의 「현재 상태 + 마지막 변경일」이고 라벨은 상태 이름 그대로(`정산 2026-09-17`).
- **(2026-09-23) 부제의 `기간`** — 상세에서 기간을 고치는 유일한 자리다(S13). 날짜는 연도까지 쓴다
  (상세는 표가 아니다, §2-4). 없으면 `기간 미정`, 한쪽만 있으면 `2026-09-12 ~ —`. 고칠 수 있는
  사람에게만 바로 오른쪽 3차 「기간 바꾸기」.
- **(2026-09-23) `종료일 지남`**(D-81) — 수주중이고 종료일이 지났을 때만, 상태 태그 오른쪽
  `--fs-sm --warning` 글자. 「상태 바꾸기」가 있는 사람에게는 그 버튼이 곧 다음 한 수라 글자만,
  없는 사람에게는 `종료일 지남 · 팀장 {이름}`(팀장이 없으면 글자만).
- **이 화면의 1차는 「일괄 저장」 하나뿐이다.** `N`은 견적 줄 표 + 매출 발행·입금 표 + **기간 칸**
  (S13, 2026-09-23 — 계약 금액 칸은 D-84로 없어졌다)의 dirty를 전부 센다(위 (사)). 표 밖 칸도 여기로
  들어오므로 섹션마다 저장 버튼이 생기지 않는다 — 그래서 §7-1 「한 화면에 1개」가 유지된다.
  dirty 0이면 비활성 + `바뀐 칸 없음 · 고칠 칸을 눌러 주세요`(`--muted`, U-4), 편집할 수 있는 칸이
  구조적으로 0인 사람에게는 버튼이 없다(U-5).
- **(2026-09-23) 「복사해 새 차수」는 수주중·진행·미수주에서만 렌더한다**(정산 = D-78 해석 ⚠ S4,
  완료 = D-47 잠김). 「상태 바꾸기」의 렌더 조건은 아래 S7 전이표 — 「팀장 이상」 한 줄이 아니라
  **그 사람이 지금 상태에서 갈 수 있는 곳이 하나라도 있는가**다.
- 「상태 바꾸기」는 팀장 이상에게만 **렌더된다**(D-46; 2026-09-23부터 정산에서는 대표·시스템 관리자만, D-79). PM에게는 비활성 버튼이 아니라 **버튼이 없다**
  — 상태 전환이 팀장의 일이라는 조직 규칙이고, 이유를 보여 줄 다음 한 수가 그 사람에게 없다.
  이것은 §7-1 「이유 있는 비활성」의 **예외가 아니라** 이 시스템이 이미 쓰는 권한·정보 노출 패턴의
  적용이다: **할 수 없는 사람에게는 서버가 그 컨트롤을 아예 보내지 않는다**(§7-3 「칸 수 가변」과
  같은 논리 — 클라이언트에서 숨기지 않는다). 같은 패턴이 이 페이즈에 셋 더 있다: 기획본부에게 매출
  발행·입금 표를 보내지 않는 것(S6) · 기획본부에게 리저브 메뉴가 없는 것(S9) ·
  `ui/permission-grid` 마스킹. 비활성 규칙은 **렌더된 버튼**에 적용되는 규칙이고, 보내지 않은 것은
  그 규칙의 대상이 아니다 — 그래서 `SYSTEM.md` 개정 네 건 어디에도 등록하지 않는다(새 규칙이 아니다).
  (2026-09-23: 기획본부에게 빠지는 것은 이제 **입금 표 하나**다 — 발행 표는 D-85로 읽기 공개.)
- **네 숫자 줄(PNL-01)은 이 페이즈에서 렌더하지 않는다.** 그 자리의 마크업을 미리 만들지 않는다
  (Phase 9). 표가 머리 줄 바로 아래 붙는다.
- 탭 없음. 섹션(2px `--line-strong`으로 시작) 순서 **① 견적 줄 표 → ② 매출 → ③ 차수**. 연결 문서
  섹션은 그 문서가 생기는 페이즈가 더한다 — 빈 섹션을 미리 두지 않는다.
- 고객 승인(D-56)은 머리 줄 부제 옆 3차 버튼: 승인 전 `고객 승인 표시`(담당 PM에게만), 승인 후
  `승인 표시 취소`(같은 사람, 연결 문서가 없을 때만). 승인일은 부제에 `고객 승인 2026-09-19 박서연`.
  **상태별(⚠ UI Considerations S3 기본값 — 계획이 쓴다)**: 수주중·진행·미수주·**정산** = 렌더, **완료** = 둘 다
  렌더하지 않는다(승인일은 부제에 그대로 보인다).
- 힌트 줄(§7-9)이 화면 하단에 항상 보인다. 폰에서는 숨는다.

### S4. 견적 줄 표 (§7-3 + 위 보강)

- 열(D-64): 번호(28px, `--fs-xs --faint`) · 소분류(Select) · 항목 · 거래처(비우면 `—`) · 수량(기본
  1) · 단가 · 견적가 · 실행가 · 차익 · 상태 · 비고.
- **견적가 = 수량 × 단가, 차익 = 견적가 − 실행가. 둘 다 서버 계산·저장이며 셀은 읽기 전용**(D-63,
  PROJ-02). 브라우저 계산값은 저장하지 않는다.
- 상태 열 값은 이 페이즈에서 **미착수 · 취소** 둘뿐(D-64). 지출결의 중·증빙 없음·지급 완료는 이후
  페이즈가 연결 문서에서 파생한다(저장 상태가 아니다).
- `견적 외 비용` 줄은 **별도 표가 아니라 견적가 0인 견적 줄의 한 종류**다(D-48, `docs/inputs` §8).
  소분류 자리에 그 이름이 오고 그룹 머리글도 `견적 외 비용`이 된다. 실행가 음수를 허용한다(EXP-14).
- 외화: 편집은 **외화 금액·환율 두 칸**, 원화는 계산값(§7-3). 통화 Select가 금액 칸 왼쪽에 있고
  KRW면 환율 칸이 숨는다(1 고정, D-71). 환율 기본값은 `fx.recent_rate.USD`에서 실제 값으로 채워진다
  (자리표시자가 아니다). 표시는 §2-4 두 줄 병기, 합계 행은 원화만.
- 비고는 자유 텍스트 한 열, PC 말줄임 · 폰 P3(D-64).
- 삭제(D-56): 연결 문서가 없으면 Delete → 확인 모달 → 보관함(`archived_at`). 있으면 삭제 대신 `취소`
  상태(견적가 0, 이력 유지)만, FK는 RESTRICT.

  센다(보관된 줄은 세지 않는다). 닿으면 「줄 추가」 비활성 + 옆 `줄 추가할 수 없음 — 300줄 상한 · 상한은
  관리자 설정`(`--danger`), `Ctrl+Enter`·`Ctrl+D`는 합계 행에 같은 이유. 상한을 넘기는 붙여넣기는 한 칸도
  바꾸지 않고 합계 행에 `붙여넣기 전부 거부 · 300줄 상한을 20줄 넘음 · 줄 수를 줄여 다시 붙여 주세요`.
  경영관리의 「조정 줄 추가」도 같은 상한을 따른다.
- **힌트 줄(§7-9, 일곱 그대로, D-94 표기)**: `이동 Tab ↑↓←→ · 범위 복사 Ctrl+C / 붙여넣기 Ctrl+V · 취소 Esc ·
  새 줄 Ctrl+Enter · 줄 이동 Alt+↑↓ · 줄 복제 Ctrl+D · 저장 Ctrl+S`. `Ctrl+A`는 넣지 않는다(일곱 상한,
  범용 키). 정산·완료처럼 그 사람에게 새 줄·줄 이동·복제가 없으면 **그 항목을 뺀다**(실제로 되는 것만) —
  정산의 PM: `이동 Tab ↑↓←→ · 범위 복사 Ctrl+C / 붙여넣기 Ctrl+V · 취소 Esc · 저장 Ctrl+S`. PC에서 넘치면
  항목 단위로 줄바꿈한다(항목 안은 꺾지 않는다).
- **코드표 설명(D-93)**: 소분류 셀을 편집하는 동안 셀 아래 한 줄에 고른 소분류의 설명(S14).

### S5. 차수 섹션 (`ui/table` 읽기 모드 — §7-14가 아니다)

**왜 §7-14가 아닌가.** 차수 섹션을 `ui/history-list`의 세 번째 사용처로 삼는 안을 먼저 검토했고,
실제 구현 계약(`ui/history-list/HistoryList.tsx`)을 읽고 접었다. 넷이 맞지 않는다.

| 맞지 않는 곳 | §7-14 / `HistoryList`의 계약 | S5가 필요한 것 |
|---|---|---|
| 열 | `HistoryEntry = { effectiveFrom, displayValue, status }` — 값 칸 **하나** | 차수·생성일·줄 수·견적 합계·상태·동작 **여섯**. 셋을 `displayValue` 한 칸에 욱여넣어야 한다 |
| 상태 | `"active" \| "past" \| "scheduled"` → 화면 글자 `적용 중`·`예정` 고정 | `현재`·`승인` — 날짜가 아니라 **승인 여부**에서 나오고, 위 유니언의 어느 값에도 대응하지 않는다 |
| 행 동작 | 동작 칸은 `onCancel` 하나이고 `scheduled` 행에만 렌더된다 | 이전 차수 행의 3차 「차수 열기」 — 취소가 아니라 이동이고, 차수에 `scheduled`가 없다 |
| 추가 | 「새 이력 추가」 3차 버튼 + 표 안에 펼쳐지는 편집 행. §7-14가 **"모달 아니다"라고 명시**한다 | 「복사해 새 차수」는 머리 줄 **2차 버튼 + §7-8 확인 모달**(D-53). §7-14가 배제한 바로 그 경로다 |

**그래서 차수 섹션은 `ui/table`을 읽기 모드로 쓴다.** 이 페이즈가 어차피 만드는 컴포넌트이고, 읽기
모드가 이미 필요한 것을 전부 준다(열 수 가변 · `<table>` + 시각적으로 숨긴 `<caption>` · 흰 머리글 ·
행 안 3차 버튼 · 폰 칸 접기). `HistoryList`를 넓히면 「이력형 설정 값·발령일 이력」이라는 §7-14의
정체가 흐려지고, 쓰지 않을 열·상태·동작 슬롯이 설정 화면 쪽에 남는다 — 새 계약을 쓰는 것보다 비싸다.
**§7-14는 이 페이즈에서 손대지 않는다.**

- 열: 차수 · 생성일 · 줄 수 · 견적 합계 · 상태 · (동작). 최신이 위. 편집 가능한 셀이 하나도 없으므로
  위 (가)대로 `role="grid"`가 아니라 `<table>` + `<caption>`(시각적으로 숨김), 머리글은 흰 바탕.
- **「읽기 모드」는 모드 토글이 아니다**(위 (가) 마지막 줄). 사용자가 켜고 끄는 상태가 아니라 편집
  가능한 셀 수가 0일 때 `ui/table`이 자동으로 취하는 렌더 형태다. 차수 섹션은 편집 가능한 셀이
  구조적으로 0이라 누구에게나 이 형태이고, 그래서 §7-3의 「읽기/편집 모드를 나누지 않는다」와
  충돌하지 않는다.
- **열 우선순위(§7-3 폰 전략)**: **P1 = 차수 · 견적 합계 · (동작)** — 문자 1 + 숫자 1 + 행동 1로
  §7-3의 P1 세 자리를 정확히 채운다. **P2 접힌 줄 = 상태 · 생성일 · 줄 수**(`현재 · 2026-09-19 ·
  6줄`). **P3 없음.**
  세 번째 P1 자리를 상태가 아니라 동작으로 준 이유: 상태 값이 `현재`·`승인` 둘뿐이고 **`현재`는 항상
  맨 위 한 행**이라 순서가 이미 그것을 말하는 반면, 이 표에서 사용자가 실제로 하는 일은 이전 차수로
  가는 것 하나뿐이다. 상태는 접힌 줄 첫 값으로 폰에서도 계속 읽힌다.
  현재 차수 행에는 동작이 없다(지금 보고 있는 차수다) — 그 칸을 `—`로 채우지 않는다(§7-3).
- 상태 열은 §7-5 `text` 변형 색 글자: 최신 차수 `현재`(`accent`), 승인된 차수 `승인`(`success`).
  **최신 차수만 현재이고** 승인 차수와 편집 중 차수가 동시에 살아 있는 상태는 없다(D-54).
  두 낱말 중 `현재`는 위 Color 절의 §7-5 보강 대상이다. (U-2 사용자 확정: 최신이면서 승인된 차수는
  `승인`만, 승인 없이 지나간 이전 차수는 빈 칸 — UI Considerations S5.)
- 이전 차수 행의 3차 **「차수 열기」**(§8 규칙 1 「버튼 = 실제 동작」, §7-1의 3차 예시 「견적 열기」와
  같은 꼴 — 동사만 두지 않는다) → 그 차수를 **잠김 모양의 읽기 표**로 본다(위 (가), 같은 렌더 형태).
  되돌리기는 없다(D-53).
- 「복사해 새 차수」(머리 줄 2차) → 확인 모달 → 이전 차수 전체 복사 + 토스트. 빈 차수를 만들지
  않는다. 「전체」는 그 차수의 견적 줄이다 — 조정 줄은 복사하지 않고 새 차수에서도 같은 줄이 보인다(⚠ UI
  Considerations S4 「조정 줄과 복사」). 견적 번호 `26001-2차`는 표시용 파생값이다(D-56) — 저장 컬럼이 없다.

### S6. 매출 섹션 (§6-2 섹션 + §7-3 편집 표)

- 섹션 제목 「매출」 + 부제 `--fs-sm --muted` `공급가액 기준 · 입금액만 통장 합계`(PNL-09). 입금 표를
  받지 않는 사람(기획본부 기본값)에게는 `공급가액 기준`만.
- **계약 금액 = 파생 값(D-84, 2026-09-23)** — **입력 칸이 없다.** 고객 승인이 표시된 **현재 차수**의 견적
  합계(공급가)다. `KvList` 한 줄: 라벨 `계약 금액` · 값 `48,000,000`(`--fs-base` 700 `tabular-nums`) ·
  2행 `--fs-sm --muted` `부가세 10% 4,800,000 · 합계 52,800,000 · 2차 고객 승인 합계`. 견적 합계가
  원화라 통화·환율 칸도 없다. 현재 차수가 미승인이면(새 차수를 만든 직후 등) 값 `—` + 2행
  `3차 고객 승인 전` — 이전 승인 차수의 합계로 대신하지 않는다(D-84 원문: 「현재 차수」). 고객 승인
  표시의 다음 한 수는 머리 줄 3차에 이미 있으므로 여기 되풀이하지 않는다. 네고로 금액이 바뀌면 새
  차수로 반영한다(D-84).
- **실물에서 걷어낼 것**: `revenue-section.tsx`의 `Form.Field id="contract-amount"`와 통화·금액·환율
  입력 셋, 그 dirty가 `N`에 합류하던 배선, 「매출 계약 쓰기」 권한 동작(D-84 — 컬럼 처리는 계획).
  이것으로 **`Form.Actions` 없는 칸 폼의 사용처가 매출 섹션에서 기간 칸(S13)으로 옮겨 간다**(§7-15 규칙
  자체는 그대로).
- **발행 줄 표**(열: 발행일 · 발행액 · 메모) · **입금 줄 표**(열: 입금일 · 입금액 · 메모) — 각각
  독립한 §7-3 편집 표이고 쓰기 = 경영관리(D-57·D-58). 3차 「발행 줄 추가」 / 「입금 줄 추가」.
  **발행 표는 기획본부에게도 온다(D-85)** — 쓰기 권한이 없으니 (가)대로 흰 머리글 `<table>` + 캡션
  읽기 표이고 추가 버튼이 없다(EMPTY는 `· 발행은 경영관리`). 목록의 「매출」 열·「발행」 기준과 같은
  숫자다.
- **입금액 셀만 통장 합계**(부가세 포함)로 적고 `grossFromTotal()`로 공급가액을 역산한다. 셀 2행
  (`--fs-sm --muted`)에 `공급가액 12,400,000 · 서버 계산`. 외화 입금이면 같은 2행에 이어 쓴다:
  `USD 4,400.00 @1,318.1818 · 공급가액 12,400,000` — §2-4의 두 줄 병기를 3행으로 늘리지 않는다.
- 미수(D-58): 입금 합계 ≠ 발행 합계면 입금 표 합계 행 오른쪽에 `미수 3,400,000` 또는
  `초과 입금 500,000`(`--warning`). 넓은 면을 칠하지 않는다.
- 음수 허용(EXP-14): 환불·할인 줄은 음수 금액, 하이픈 마이너스, 괄호·붉은색 금지(§2-4).
- 정보 노출(2026-09-23, D-85): **발행액은 기획본부 기본 공개, 입금액은 기본 숨김 유지.** 기획본부에게는
  **입금 표를 서버가 보내지 않는다**(표 단위로 빠진다) — 미수·초과 입금 표시는 입금 표 합계 행에 있으므로
  함께 빠진다. 섹션에는 계약 금액 + 발행 표(읽기)가 남는다. 정보 노출표의 `revenue.issued_amount` 기본값을
  바꾸는 것이 전부이고 화면 분기를 새로 만들지 않는다(04-02의 표 단위 배제 경로 그대로).

### S14. 코드표 설명 (신설 2026-09-23 — D-93)

- **코드표 관리 화면**(`/admin/code-tables`): 표 열을 `값 · 이름 · **설명** · 정렬 · 상태 · 동작` 여섯으로.
  설명 칸은 이름 칸과 같은 인라인 편집(blur 저장, 실패 시 서버 값으로 되돌림 — 기존
  `CodeItemLabelInput` 패턴, §7-2 설정 즉시 저장과 같은 결). 긴 글자 열이라 `keep-all` 줄바꿈, 비면 `—`.
  「코드 추가」 폼에 `설명`(긴 칸 480, 선택) 한 칸을 더한다. 상한 **40자, 한 문장**(§7-2 설정 설명 규칙과
  같은 결 — 한 줄에 들어가야 고르는 자리에서 읽힌다). 기본 제공 값은 시드가 설명을 채운다(D-93).
  (관리자 화면의 `ui/form` 이관은 Phase 7 그대로 — 이 페이즈는 칸 하나만 더한다.)
- **값을 고르는 자리** — 설명은 **고른 값 하나의 설명만** 보인다. 선택지 전체 설명 목록·툴팁·커스텀
  드롭다운을 만들지 않는다(§7-2 「커스텀 드롭다운 만들지 않는다」, 네이티브 `<option>`의 `title`은 브라우저마다
  안 보여 기대지 않는다):
  | 자리 | 보이는 법 |
  |---|---|
  | 폼 `Select`(등록 폼 등, 코드표 값일 때) | 컨트롤 바로 아래 `Form.Hint` 한 줄. 값을 바꾸면 즉시 바뀐다 |
  | 편집 표의 코드표 셀(견적 줄 소분류 · 리저브 증빙 종류) | **편집 중일 때만** 셀 아래 한 줄 `--fs-sm --muted`(§7-2 이유 줄 자리). 편집이 끝나면 사라진다 — 읽기 상태의 행 높이를 늘리지 않는다. 같은 자리에 오류 이유가 있으면 오류가 이긴다 |
  | 상태 고르기 목록(S7) | 행마다 상태 라벨 + 2행 설명(`--fs-sm --muted`, §7-8 시트 상세의 2행 모양) |
  | 목록 필터 줄 | **보이지 않는다** — 필터는 값을 저장하는 자리가 아니고, §6-1 「필터 한 줄」에 힌트 줄 자리가 없다 |
  | 폰 행 시트(S8) | 보이지 않는다(보기 전용, 값만) |
- 설명이 없는 값은 힌트 줄 자체가 없다(`—` 힌트 금지).

### S15. 숫자 입력·표시 (전역 — D-95)

- 표시: Typography 절 「숫자 서식」 그대로 — 한 모듈. 외화 2행 예: `USD 1,000.00 @1,350`.
- 입력: 원화·외화 금액·환율·수량 칸(표 셀 · 폼 칸 · 설정 화면 number 칸)은 **타이핑 중 정수부에 쉼표를
  넣는다.** 소수점은 입력 가능하고 자리 상한(외화 2 · 환율 4 · 수량 2)을 넘는 글자는 받지 않는다. 쉼표가
  들어가도 커서는 친 글자 바로 뒤에 남는다. 원화 금액은 소수점을 받지 않는다(정수 원, CEO D4).
  음수는 맨 앞 `-` 하나.
- 서버로는 **쉼표를 뗀 값**을 보낸다 — 서버 스키마는 바뀌지 않는다. 붙여넣기 정규화((다))가 이미 쉼표를
  지우므로 같은 도우미를 쓴다.
- 식별자형 칸(번호·연도·날짜·전화·사업자·카드 뒤 4자리)에는 쉼표를 넣지 않는다.
- 이 규칙은 이 페이즈의 화면(목록·상세·매출·리저브·등록 폼)과 **공용 `ui` 입력**에 건다. 공용 입력을 쓰지
  않는 기존 화면(관리자 설정 number 칸 등)은 계획이 grep으로 찾아 같은 도우미로 바꾼다 — 화면마다 따로
  구현하지 않는다.
