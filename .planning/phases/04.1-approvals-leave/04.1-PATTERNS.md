## Pattern Assignments

### `db/schema/approvals.ts` (model, CRUD)

**Analog:** `db/schema/quote-lines.ts`

**Version 컬럼 + FK 패턴** (`db/schema/quote-lines.ts:6-40`):
```typescript
export const quoteLines = pgTable(
  "quote_lines",
  {
    id: uuid("id").primaryKey().defaultRandom(),
    revisionId: uuid("revision_id").notNull().references(() => quoteRevisions.id, { onDelete: "restrict" }),
    ...
    version: integer("version").notNull().default(1),
    source: text("source").notNull().default("demo"),
    customFields: jsonb("custom_fields").notNull().default({}),
    createdAt: timestamp("created_at").notNull().defaultNow(),
    updatedAt: timestamp("updated_at").notNull().defaultNow(),
  },
  (table) => [index("quote_lines_revision_sort_idx").on(table.revisionId, table.sortOrder)],

```
`approval_instances`에 그대로 적용: `version integer default(1)`, 승인·반려·회수는 이 컬럼을 WHERE 절 비교에 쓴다. `approval_steps`는 role×scope를 **문자 그대로**(FK 아님, text 컬럼) 저장 — EXP-04 요구사항 그대로(정규화된 담당자 FK를 쓰면 안 된다).

### `repositories/approval-instances.ts` (repository, CRUD + 낙관적 잠금)

**Analog:** `repositories/quote-lines.ts:98-131` (검증된 선례, 그대로 복사할 패턴)

```typescript
export async function updateQuoteLineIfVersionMatches(
  viewer: Viewer, id: string, expectedVersion: number, input: QuoteLineUpdateInput, tx: DbOrTx = db,
): Promise<QuoteLineRow | null> {
  void viewer;
  const [row] = await tx
    .update(quoteLines)
    .set({ ...input, version: sql`${quoteLines.version} + 1`, updatedAt: new Date() })
    .where(and(eq(quoteLines.id, id), eq(quoteLines.version, expectedVersion)))
    .returning();
  return row ?? null; // null = 충돌 또는 존재하지 않음 — 호출자(domain)가 구분해 처리
}
```
`approveStep`/`rejectStep`/`withdraw`의 UPDATE는 이 패턴을 그대로 쓴다 — 0행 반환 = 동시성 거부, UI-SPEC의 「거부 — 동시 처리」 문구로 이어진다.

### `domain/org/index.ts` `teamAtDate()` — 결재선 해석의 재사용 축 (transform)

**Analog:** `domain/org/index.ts:188-204`

```typescript
export async function teamAtDate(
  viewer: Viewer, userId: string, date: string, deps?: Partial<TeamAtDateDeps>,
): Promise<TeamDto | null> {
  const findMembershipAtDate = deps?.findMembershipAtDate ?? defaultFindMembershipAtDate;
  const membership = await findMembershipAtDate(viewer, userId, date);
  if (!membership) return null;
  const findTeamById = deps?.findTeamById ?? defaultFindTeamById;
  const team = await findTeamById(viewer, membership.teamId);
  if (!team) return null;
  return (await (deps?.project ?? project)(viewer, team, TEAM_DTO_SPEC)) as TeamDto;
}
```
`resolve-step.ts`는 이 함수를 그대로 쓸 수 없다(방향이 반대: 팀/본부 → 현재 담당자들). 같은 "발령일 이력 기준 최신 1건" 조회 패턴을 역방향으로 다시 구현해야 한다 — RESEARCH Pattern 2·Pitfall 2 그대로.
