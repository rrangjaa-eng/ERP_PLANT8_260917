## Typography

`SYSTEM.md` §2-2·§2-3 그대로. **이 페이즈의 모든 화면은 `xs · sm · base · lg` 정확히 넷**이다(§2-2 「화면당 4단계」).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body(표 셀 · 목록 행 · 폼 입력 · KvList 값 · 결재선 사람 이름 · 잔고 줄) | `--fs-base` 14px(폰 15px) | 400 | 1.5(표 `--lh-table`) / 1.6(본문 `--lh-body`) |
| Label(라벨 · 표 머리글 · 그룹 머리글 · 접힌 줄 · 힌트 · 결과 줄 · 결재선 단계 이름·시각 · 사유 2행) | `--fs-sm` 12px | 600(라벨·머리글) / 400(나머지) | 1.5 |
| Heading(화면 제목 · 시트/모달 제목) | `--fs-lg` 18px | 700 | 1.4 |
| Micro(상태 태그·표 상태 글자 · 행 번호 · kbd) | `--fs-xs` 11px | 600 | 1.4 |
| Display | **사용 없음** — `--fs-xl`/`--fs-2xl`은 인쇄·외부 수령자·KPI 전용. 잔고 숫자도 큰 숫자 타일이 아니라 **한 줄 텍스트**다(§6-2 「네 숫자 한 줄」과 같은 모양) |

- **굵기 예외 — 상속 값(새 값 아님):** 굵기는 둘이 아니라 **셋(400 · 600 · 700)**이다. `SYSTEM.md` §2-1 「400 · 600 · 700 세 단계만」과
  `tokens.css` `--fw-regular`·`--fw-medium`·`--fw-bold`에서 상속했다. 600은 라벨·버튼·태그, 700은 제목과 **잔고·일수 숫자**(§6-3 서버 계산
  한 줄 「숫자만 700」 규칙)에만. 이 페이즈가 더하는 크기·굵기는 0이다.
- **일수 표기(이 페이즈의 숫자 형식)**: 숫자 + `일` 붙여쓰기(§2-4 「건수 = 숫자 + 단위」와 같은 규칙) — `1일` · `0.5일` · `0.25일` · `10.5일` ·
  `0일`(재택). 소수는 끝의 0을 떼고 최대 2자리. 음수는 하이픈 마이너스 `-1.5일`(잔여 초과 승인 뒤 남음이 음수가 될 수 있다, 막지 않으므로).
  `tabular-nums` · 우측 정렬(표) · `white-space: nowrap` · `letter-spacing: 0`.
- **날짜**: 표·접힌 줄·결재선 시각은 같은 해면 `09-18` · `09-18 14:02`, 다른 해면 ISO. 문서 화면·시트의 기간 값은 ISO 전체
  `2026-09-18 ~ 2026-09-20`(§2-4 기간 = 물결 양쪽 공백). 하루짜리는 `2026-09-18`.
- 문자 열(종류·기간·기안자)은 `keep-all` 줄바꿈 허용. 사람 이름은 줄바꿈하지 않는다.

- **종류에 따라 칸이 바뀐다**(서버가 아니라 폼이 즉시): 종일·재택 = `시작일` + `종료일`(하루면 같은 날) / 반차·반반차 = `날짜` 하나 + `시간`(Select 200, `오전` · `오후`). 숨겨진 칸의 값은 제출에 싣지 않는다
- 일수 힌트·잔고 행·결재선은 **서버 계산값**(§6-3 「서버 계산 값은 입력 바로 아래 한 줄」). 종류·날짜가 바뀌면 다시 받는다. 계산 전·날짜 미입력이면 일수 힌트 없음, 잔고 1행은 `연차 남음 10.5일 · 월차 남음 3일 · 결재 중 1일`까지만
- 일수 = 기간 안의 평일 수(주말 제외). 공휴일 제외는 Phase 04.2 공휴일 표(ADMN-11) 이후 — Assumptions #4
- **잔여 초과는 막지 않는다**(입력 §5). 1차는 살아 있고 `잔여 초과` 줄만 보인다 — 막힘 이유 자리에 쓰지 않는다(막힘이 아니다)
- 결재선은 제출하면 지금 보이는 모양으로 고정된다(EXP-04). 이 줄은 읽기 전용, 「바꾸기」 없음
- `Enter` 기본 제출은 막고 `Ctrl+Enter`만 제출(§7-15 · Phase 4 등록 폼 선례, 연타 가드 포함). `Esc` = 2차 `취소`(입력이 있으면 `입력 버리기` 확인)
- 폰: 라벨이 위로, 칸 전폭. **행동 줄은 하단 탭 위에 고정**(§6-3), 1차 `--touch-min` 넓게 + 옆에 `취소`, 막힘 이유는 그 아래 한 줄. 본문 아래 여백 = 탭 44 + 행동 줄 높이
- 제출 중: `연차 신청…` + 같은 폼의 다른 버튼 `aria-disabled`. 성공하면 `/leave/[id]`로 이동 + 토스트

- 폰: 행동 줄은 하단 탭 위 고정(S2와 같음), 1차가 2차의 두 배 폭(§7-8 시트 행동 줄 비율과 같게)
- 거부(동시 처리): 행동 줄 1차 왼쪽 막힘 자리에 Copywriting 「거부 — 동시 처리」 한 줄 + 3차 `새로 고침`

### S5. 폰 결재 시트 (§7-8 시트 · 실물 `sheet-modal.html` `#sheet-approve`)

- <700px에서 결재함 행을 탭하면 열린다. 머리(고정): 제목 `연차 · 종일 09-18 ~ 09-20`(`--fs-lg`) + 부제 `{번호} · 박서연`(`--fs-sm --muted`) + 닫기 x 20. 본문(스크롤, 최대 85vh): S3와 같은 KvList 행(종류 · 기간 · 일수 · 비고 · 잔고 · 기안 · 결재선 목록형). 행동 줄(고정): 2차 `반려` + 1차 `승인`(높이 `--touch-min`, 1차가 2차의 두 배 폭)
- `처리함` 행을 탭하면 같은 시트가 **행동 줄 없이** 열린다(보기 전용 — D-69 행 시트와 같은 결)
- 열릴 때 포커스 = `승인`(실물 `autofocus`), 행동 줄이 없으면 닫기 x. `Esc`·가림막·x로 닫히고 포커스는 탭한 행으로 돌아온다. 포커스 트랩은 네이티브 `<dialog>`
- `승인` → `승인…` → 성공: 시트 닫힘 + 토스트 + 목록 다시 그림 / 거부: 시트가 닫히지 않고 행동 줄 위에 Copywriting 「거부 — 동시 처리」 한 줄
- `반려` → 결재 시트가 닫히고 **반려 확인 시트**(S6)가 열린다. 반려 확인 시트의 `취소`는 결재 시트로 돌아가지 않고 목록 행으로 포커스를 돌려준다(시트 중첩 없음)

### S6. 반려 · 회수 확인 (`ui/confirm-dialog` — §7-8 · Phase 4 개정 ⑭⑮)

- 반려: 확인 근거 한 칸 `사유`(자유 입력 필수, 코드표·칩 없음 — 입력 §4). 첫 포커스 = 사유 칸. 비면 1차 `aria-disabled` + 왼쪽 막힘 이유. 서버도 `trim()` 뒤 1자 이상을 검증한다(zod `.min(1)`, RESEARCH Security)
- 회수: 근거 칸 없음. 첫 포커스 = 1차(§7-17 순서)
- PC(≥700, 태블릿 포함) = 480 모달, 폰 = 시트. 문구는 Copywriting 「Destructive」 행. 제출 중 `반려…`/`회수…` + 나머지 `aria-disabled`, `Esc` 무시. 서버 거부는 막힘 자리, 다이얼로그는 닫히지 않는다. 성공하면 닫히고 호출한 화면이 토스트를 띄운다. 닫히면 트리거로 포커스 복귀(트리거가 사라졌으면 화면 제목)

### S7. 결재선 표시 `ui/approval-route` (개정 제안 A3)

- **제출 전 한 줄**(S2 · S3 반려 편집): §6-3 원문 그대로 — `기안자 → 사람 단계 → … · 결재 규칙`. 기안자 700, `→` `--faint`, 단계 이름 `--fs-sm --muted`, `결재 규칙`은 링크가 아닌 글자(실물 `form-expense.html` `.why`). 건너뛴 단계는 그리지 않고 끝에 한 마디(자기 승인 건너뜀만 — 빈 자리 건너뜀은 말하지 않는다, §6-3 결정 7)
- **제출 뒤 목록형**(S3 · S5): KvList `결재선` 행의 값 = `<ol>`(번호 표시 없음). 단계마다 한 줄 `[사람 --fs-base] [단계 이름 --fs-sm --muted] · [결과 StatusTag text] [시각 --fs-sm --muted tabular-nums]`, 항목 사이 `--s-2`. 반려 단계는 다음 줄에 사유(`--fs-sm`, `keep-all`, 줄 수 제한 없음)
- **사람 해석 규칙(EXP-04)**: 이미 처리한 단계 = **처리한 그 사람**(저장된 값, 그 뒤 소속·계급이 바뀌어도 그대로) / 지금 단계와 남은 단계 = **표시 시점의 현재 담당**(단계에 고정된 계급 × 조직 범위를 매번 다시 해석 — 저장하지 않는다). 서버가 해석해 넘기고 컴포넌트는 그리기만 한다
- 결과 글자·색은 Color 절 매핑표. 보는 사람이 그 단계 담당이면 이름 뒤 `(나)`, 결과 `내 결재`
- 끝 줄(해당할 때만): 자기 승인 건너뜀 · 회수 시각. 설정 변경으로 단계가 바뀌어도 이 목록은 제출 때 고정된 단계 그대로다(EXP-04 — 표시가 그 증거)

### S8. 관리자 설정 — `연차` · `연차 결재선` 섹션 `/admin/settings` (§7-2 자동 생성 설정 화면 · §7-14)

- 새 화면 없음. 설정 레지스트리에 키를 등록하면 기존 화면이 섹션을 그린다(ADMN-05, RESEARCH 「Don't Hand-Roll — 결재 단계 전용 커스텀 폼 금지」). Phase 4 04-05 선례대로 **JSON 한 개가 아니라 필드 단위 키 묶음**이다(`document_number.project.*`와 같은 모양)
- `연차` 섹션: `연차 일수` = **이력형 number**(§7-14 이력 목록, 적용 시작일 = 회계연도 1월 1일). 과거 연도 잔고가 소급해 바뀌지 않게 하는 장치다(RESEARCH Pitfall 4). 적용 시작일이 1월 1일이 아니면 칸 아래 오류
- `연차 결재선` 섹션(문서 종류 = 연차): 맨 위 `자기 승인`(enum, 기본 `건너뜀` — 입력 §3) → `1단 사용`(boolean) · `1단 담당 계급`(enum) · `1단 조직 범위`(enum) · `1단 특정 부서`(enum) → 2단 → 3단 → 4단. **네 칸 고정 슬롯**(기본 4단, 입력 §1): 기본값 1단 팀장 × 기안자 팀 · 2단 본부 책임자 × 기안자 본부 · 3단 경영관리 담당 × 특정 부서 = 경영관리본부(⚠ U1) · 4단 대표 × 전사, 넷 다 `사용`
- 저장 = 비이력형 즉시 저장(체크박스·select는 change, §7-2). 별도 저장 버튼 없음. 바꾼 값은 **새로 제출하는 문서부터** 적용된다(진행 중 문서는 제출 때 고정된 단계를 가진다 — 스키마가 보장, RESEARCH Pattern 4)
- `담당 계급`·`특정 부서` select의 옵션은 **서버가 지금의 계급·조직 목록으로 채운다**(저장값 = id, 보이는 값 = 이름). 지금 레지스트리 `enum` 기술자는 정적 옵션이라 계획이 동적 옵션 경로를 정한다(⚠ U3)
- 다른 문서 종류(Phase 5 지출결의·정산 결재)는 같은 모양의 섹션을 더한다. 테스트 전용 두 번째 문서 종류(성공 기준 1)는 설정 화면에 나타나지 않는다
- 권한: `admin.settings` view가 없으면 404(기존). 섹션 폭 = `.single-column` 720(§3)

### S9. 관리자 사람 상세 — `연차` 섹션 `/admin/people/[id]` + 등록 폼 입사일 (D-96 · D-97 · 05-CONTEXT Discretion 「결근 차감은 관리자 수동 조정」)

## Assumptions made (confirm later)

사용자에게 물을 수 없는 자리에서 `SYSTEM.md`와 잠긴 결정에 가장 가까운 기본값을 골랐다. 뒤집으면 해당 표면만 바뀐다.

1. **연차 진입점 = 계정 그룹 「연차」**(A1, S10). 1차 메뉴 여섯째로 두지 않는다
2. **「결재 옆판」 = 폰 결재 시트(S5) + PC 문서 화면(S3)**. 옆 패널을 만들지 않는다(§0 · §6-1이 금지) — A3
3. **반차·반반차의 시간 = `오전`/`오후` 선택 하나.** 정확한 시각 칸은 없다(필요하면 비고)
4. **종일·재택은 기간(시작~종료), 일수 = 기간 안 평일 수.** 공휴일 제외는 Phase 04.2 공휴일 표(ADMN-11) 뒤(PR #50으로 옮겨짐) — 그 전에는 공휴일을 낀 기간이 하루 더 세진다(힌트에 일수가 보이므로 신청자가 나눠 낼 수 있다)
5. **비고 = 선택 칸 하나**(긴 칸 480)
6. **승인된 연차는 회수·취소가 없다.** 회수는 결재가 끝나기 전(결재 중)만. 승인 뒤 정정은 관리자 연차 조정(S9)
7. **반려되면 같은 문서를 고쳐 다시 신청한다**(입력 §4 「기안자에게 복귀 → 고쳐 재상신」). 번호는 유지, 결재선은 다시 신청한 시점에 새로 고정
8. **결재함 = 지금 내 차례 + 내가 처리한 문서(최근 50건).** 앞으로 차례가 올 문서는 보이지 않는다. 처리함 페이지 이동 없음
9. **「내 차례」(첫 화면) 블록 연동은 이 페이즈에 없다** — `ui/next-turn/NextTurn.tsx`·첫 화면을 Phase 4 04-08·04-09가 고치므로 병렬 충돌을 피한다. 결재자의 폰 동선은 하단 탭 「결재」(대표·본부 책임자·팀장·시스템 관리자의 탭 2)에서 시작한다. `[결재]` 행은 Phase 4 머지 뒤(Phase 5 또는 퀵 태스크)
10. **결재선 설정 = 네 칸 고정 슬롯 × (사용 · 담당 계급 · 조직 범위 · 특정 부서)** + 문서 종류별 `자기 승인`. 다섯째 단계는 키 추가(코드)가 필요하다
11. **PC 결재함 행의 3차 `승인`은 확인 없이 즉시 실행**(되돌리기 없음). 폰은 항상 결재 시트를 거친다(근거가 보인 뒤 승인)
12. **관리자 사람 상세에 `입사일` · `퇴직일` · 잔고 · 연차 조정 폼을 둔다**(S9) — D-96(입사일로 월차 적립)·D-97(퇴직 시 잔여 일수)·05-CONTEXT Discretion(결근 = 관리자 수동 조정)의 전제. 사람 등록 폼에 입사일 필수
13. **재택은 잔고 행을 그리지 않는다**(차감 0, 기록만 — 입력 §5)
14. **잔고 숫자 정의**(2026-09-24 11:43 사용자 요구로 개정): `연차 남음` · `월차 남음` = 잔고별 남은 일수(승인된 사용·조정 반영, 진행 중 제외) — 둘을 더한 합계는 쓰지 않는다 · `결재 중` = 이 문서를 뺀 기안자의 다른 진행 중 신청 합 · `이번 신청` = 이 문서 일수. 경고 = 결재 중과 이번 신청을 배분 규칙(소멸 빠른 순 · 같으면 월차)대로 나눴을 때 유효한 부여를 넘는 만큼
15. **Phase 4 개정을 따른다**(P0 · `Ctrl+` · 진행 바 없음 · `reasonTone`/`aria-disabled` · 토스트 = 누른 1차 라벨). `ui/confirm-dialog`는 **실행 시점에 main에 있으면 그것을 쓰고, 없으면 04.1이 `04-UI-SPEC.md` S16 · 개정 ⑮ 계약 그대로 같은 경로에 만든다**(뒤에 머지되는 쪽이 앞의 것을 쓰도록 rebase).
