# Phase 04.2 Plan 03: Account lock action log + setting-driven lock message Summary

**The Nth login failure now records `account_lock` (actor null, detail email) in the same transaction as the failure record, serialized per email by a Postgres advisory lock, and the lock message's minute number comes from `auth.lockout.window_minutes`.**

## Performance

- **Duration:** ~28 min
- **Started:** 2026-09-26T08:48:00Z
- **Completed:** 2026-09-26T09:16:41Z
- **Tasks:** 2
- **Files modified:** 10

## Accomplishments
- `recordLoginFailure(email, ip, deps?)`: reads the lockout config and looks up the user first, then in a single `withTransaction` it takes the email advisory lock, inserts the failure, counts open failures, and, when locked, calls `recordAction(SYSTEM_VIEWER, { actionType: "account_lock", … }, { tx })`. If the audit write fails, the failure record rolls back.
- The `after` hook's failure branch is now the one call `recordLoginFailure(email, ip)`. The success branch behaves the same as before (`recordAttempt` just moved inside it).
- Added three always-on core action types (`account_lock` 계정 잠금, `account_unlock` 잠금 해제, `holiday_change` 공휴일 변경). They were added to all three arrays in one commit.
- `lockedMessage(minutes)` / `isLockedMessage(text)` replace the fixed `LOCKED_MESSAGE` constant. The `before` hook uses `windowMinutes`. `loginErrorMessage` shows the server text only when the status is 403 and `isLockedMessage` matches.
