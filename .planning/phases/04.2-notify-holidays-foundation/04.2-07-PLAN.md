- **D-4218 한 문장 열기와 키셋(Codex #20):** 첫 계획은 서버 렌더 시각 `openedAt`을 클라이언트가 보내 `created_at <= openedAt`인 행을 읽음 처리했다. Codex #20 — `created_at DEFAULT now()`는 트랜잭션 시작 시각이라, 열기 전에 시작해 열기 뒤에 커밋된 tick 행이 화면에 없었는데도 읽음이 된다. 그래서 `openInbox(viewer, { recipientId, retentionFrom, limit })`(저장소)를 **한 SQL 문장**으로 만든다 — `WITH opened AS (SELECT now() AS at), marked AS (UPDATE notification_log SET read_at = (SELECT at FROM opened) WHERE recipient_id = $1 AND read_at IS NULL AND created_at >= $2 RETURNING id) SELECT … FROM notification_log WHERE recipient_id = $1 AND created_at >= $2 ORDER BY created_at DESC, id DESC LIMIT $3`와 `openedAt`, `marked` id 목록. 한 문장은 READ COMMITTED에서도 한 스냅샷을 보므로 UPDATE와 SELECT가 같은 행 집합을 보고, 스냅샷 뒤에 커밋된 행은 둘 다에 없다. SELECT 쪽은 UPDATE 전 값을 보므로 도메인이 `marked`에 든 행의 `readAt`을 `openedAt`으로 채워 돌려준다. 클라이언트는 더 이상 `openedAt`을 보내지 않는다. 목록 넘김은 `(created_at, id)` 키셋 커서(`InboxCursor = { createdAt: string; id: string }` — `WHERE (created_at, id) < ($c, $i)`)로 해서 페이지 사이 삽입에 중복·누락이 없다. **정밀도(Codex 2차 #11):** PostgreSQL `timestamp`는 마이크로초까지 담고 Drizzle `Date`는 밀리초에서 잘라, `…00.123456`인 마지막 행의 커서가 `…00.123`이 되면 `< …00.123` 비교가 같은 시각의 나머지 행을 건너뛴다. 불투명 커서 문자열 대신 저장 자체를 밀리초로 묶는 작은 방법을 쓴다 — 04.2-01이 `created_at`을 `timestamp(3)`로 만든다(이 플랜은 그 계약을 쓰고 증명한다).
