# Phase 04.2 Plan 08: Account unlock action log with operator identity Summary

**Unlocking an account now writes `account_unlock` in the same transaction that resolves the open failures. The real path (account.yml → Cloud Run Job → CLI) records who ran it: `github.actor` is passed as `--operator` and stored in `detail.operator`.**

- **Duration:** ~25 min
- **Completed:** 2026-09-26T09:51Z

- **Files modified:** 7

## Accomplishments
- `unlockAccount(viewer, email, opts?)`: checks permission, then runs `findUserByEmail` before the transaction (eng E5). Inside `withTransaction` it makes only two calls: `resolveOpenFailures(…, "admin_unlock", tx)` and `recordAction(viewer, { actionType: "account_unlock", entity: "user", entityId, detail: { email, resolved, operator } }, { tx })`. `log.info("auth.unlock")` still runs after commit.
- CLI `unlock` requires `--operator`, which must match `^[A-Za-z0-9](?:[A-Za-z0-9-]{0,38})$`. `create` and `reset` reject it. All of these are `UsageError`, exit 2. The output line is unchanged.
- `account.yml`: the env has `INPUT_OPERATOR: ${{ github.actor }}`, and one `if` line appends `,--operator,$INPUT_OPERATOR` only for unlock (+2 lines, 0 removed).
