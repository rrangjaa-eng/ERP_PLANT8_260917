- **D-4220 공휴일 로그(개정 — Codex #12, 04.2-11과 같은 규칙):** 추가·삭제는 끌 수 없는 `holiday_change`(04.2-03)로, `entity: "holiday"`, `entityId`는 행 id, `detail: { op: "add" | "delete", date, name, kind }`. 호출은 `recordAction(viewer, entry, { tx })`(04-32). 행 변경·재계산·로그가 한 트랜잭션이다.
- **D-4210 도메인 연결(Codex #2):** 04.2-06이 저장소 수준에서 「수동 날짜는 대체일을 막는다」와 두 삽입 순서를 증명했다. 여기서는 사람이 쓰는 경로가 그 규칙을 부른다.
  - 추가: write 검사 → 구분·날짜 검사 → `ensureHolidayCandidates(year)`(멱등 — 후보가 없는 해에 대체일만 생기지 않게. 음력 표 밖 해는 `LunarTableRangeError`가 그대로 나가 날짜 칸 오류가 된다) → `withTransaction`: 그 날짜 행이 **미래 대체공휴일**이면 그 행을 지운다(규칙이 옮길 자리) · 법정 공휴일이나 수동 행이면 `DuplicateHolidayError(기존 이름)` → `insertManualHoliday(…, tx)`가 거짓이면(동시 삽입) 다시 찾아 같은 중복 오류 → `recomputeFutureSubstitutes(year, { today }, tx)` → 로그.
  - 삭제: write 검사 → `withTransaction`: `deleteHolidayById(viewer, id, tx)`(RETURNING) → null이면 이미 지워진 것이라 로그 없이 `{ deleted: false }`(동시 중복 삭제 — 뒤 사람도 성공 모양) → 지운 행이 수동 구분이 아니거나 날짜 ≤ KST 오늘이면 `HolidayNotDeletableError`를 던져 트랜잭션째 되돌린다 → `recomputeFutureSubstitutes` → 로그.
  - 전년도는 다시 계산하지 않는다 — 12월 기독탄신일 대체일은 12월 안에 끝나 1월 수동 날짜가 전년도 대체일을 막는 경우가 없다(04.2-06이 다음 해 1월을 막는 날에 넣는 것은 생성 쪽 안전장치다).
  - U-3과의 관계: 관리자는 규칙 행을 직접 지우거나 고치지 못한다. 미래 대체일이 옮겨지는 것은 법 규칙(공휴일법 제3조 — 대체일은 다음 비공휴일)이 입력 변화에 따라 다시 적용되는 것이고, 지난 대체일은 건드리지 않는다.
