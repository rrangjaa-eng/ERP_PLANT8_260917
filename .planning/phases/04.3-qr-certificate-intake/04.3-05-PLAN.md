**As a** 경영관리(세무 보관 담당), **I want to** 수령자가 제출한 서명 이미지가 회사 GCP의 비공개 저장소에 남고, 파기 때 확실히 지워지기를 바란다, **so that** 세무 보관용 인쇄물에 서명이 실리면서도 개인정보가 공개 경로나 로컬 디스크에 새지 않는다.

① **RED:** 위 `behavior`를 `test/unit/gcp/gcs.test.ts` · `test/unit/storage/signature-store.test.ts`에 먼저 쓴다. 네트워크는 쓰지 않는다 — 어댑터가 받는 `request` 함수를 가짜로 주입해 (메서드, URL, 헤더, 본문)을 기록하고 상태 코드를 돌려준다(`cloud-sql-admin.ts`의 `options.list` 주입과 같은 결). `test/unit/env.test.ts`에 새 변수 한 줄을 더한다.

② **`lib/gcp/gcs.ts`(GREEN):** `createGcsObjectClient({ bucket, request? })` → `{ putObject(key, bytes, contentType), getObject(key), deleteObject(key) }`. 기본 `request`는 `new GoogleAuth({ scopes: ["https://www.googleapis.com/auth/devstorage.read_write"] }).getClient()`가 돌려준 클라이언트의 `request`(한 번 만들어 재사용)이고, 호출마다 시간 초과 10초 · 응답 본문은 바이트(`arraybuffer`) · 상태 코드 판정은 어댑터가 직접 한다(라이브러리가 4xx에 던지지 않게 `validateStatus`를 연다). URL은 behavior의 셋만 — 객체 이름은 `encodeURIComponent`로 한 조각으로 인코딩한다. 업로드는 **simple upload(`uploadType=media`)만**, 조건 `ifGenerationMatch=0`(이미 있으면 412 → `GcsObjectExistsError`). 읽기 404 → `null`, 지우기 404 → 성공. 그 밖의 실패는 `GcsUnavailableError`(메시지 = 연산 이름 + 상태 코드). 실패 때 `log.warn("gcs.request_failed", { op, status })`만 남긴다 — 키·버킷·본문은 로그와 메시지에 넣지 않는다(`lib/crypto.ts` 머리 주석과 같은 원칙). `COVERAGE.md`의 OPT-OUT 연산(여러 조각 업로드 · 재개형 업로드 · 목록 · 메타데이터 · 복사 · 서명 URL)을 부르는 코드를 만들지 않는다.

③ **`lib/storage/signature-store.ts`:** 드라이버 선택을 고친다 — `env.APP_ENV === "local"` → 기존 로컬 드라이버(그대로), 아니고 `env.CERT_SIGNATURE_BUCKET`이 있으면 GCS 드라이버(포트의 `put`/`get`/`delete`를 어댑터의 세 함수로 잇는다, `get`의 404 = `null`), 둘 다 아니면 `SignatureStoreNotConfiguredError`(메시지에 변수 이름만). 키 검사는 두 드라이버 앞에서 한 번 — 04.3-02의 검사 함수를 그대로 쓴다. 테스트가 GCS 드라이버에 가짜 `request`를 넣을 수 있게 `getSignatureStore(deps?)`로 주입 자리를 둔다(기존 deps 주입 관례).
