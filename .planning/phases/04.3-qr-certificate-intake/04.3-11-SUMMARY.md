**2. [Rule 3] E2E 「PM 404」 단언 범위**
- 플랜 문장은 「→ 404 · 활동 행 0줄」이다. 처음엔 HTTP 상태 404까지 단언했으나 받은 값이 200이었다 — 원인: `loading.tsx`가 있어 페이지 안쪽의 `notFound()`는 로딩 화면이 스트리밍된 뒤 던져지므로 상태 200이 고정되고 not-found 화면이 그려진다(`loading.md` 103 · 118행, 플랜 C3가 설명한 바로 그 메커니즘). 플랜이 HTTP 404를 요구한 것은 게이트 꺼짐뿐이라(레이아웃에서 해결) PM은 「페이지 찾을 수 없음」 제목과 번호 없음 · 활동 행 0줄로 단언한다. 권한 없음 · 파기 · 없음 · 정보 항목 꺼짐의 404는 **화면상 404이고 HTTP 상태는 200**이다(값 · 서명 없음 — 정보 노출 없음, 플랜이 loading.tsx를 남기기로 한 결과).

**3. [Rule 1] 「13자리 번호 없음」 단언을 범위를 좁혀**
- 플랜: 「페이지 HTML에 13자리 번호 없음」. 전체 HTML에 `\d{13}`을 걸면 빌드 ID · 타임스탬프 · base64 서명 데이터 URL에서 우연히 걸릴 수 있어 거짓 실패가 난다. 대신 (a) HTML에 알려진 뒤 7자리 `2123458` 없음 (b) HTML에 `\d{6}-\d{7}` 없음 (c) **보이는 글자**(`body.innerText`)에 13자리 숫자 없음 — 셋으로 단언했다.

**4. [Rule 3] aria-disabled 버튼은 `click({ force: true })`**
- Playwright 동작 가능성 검사가 `aria-disabled`를 「사용 불가」로 보아 일반 클릭이 끝나지 않았다. force로 눌러 컴포넌트의 클릭 막기(새 탭 수 불변)를 그대로 재며 단언은 바꾸지 않았다(`665edde3`).

**5. [설계 손질] 출력 시각은 DTO 밖**
- 출력 시각(KST `yyyy-MM-dd HH:mm`)은 개인정보가 아니라 `project()` 투영 대상이 아니다. 결과 `{ kind: "ok", print, printedAt }`의 `printedAt`으로 돌려준다(플랜 ③ 「개인정보가 아닌 출력 시각만 붙여」와 같은 뜻).

**6. [설계 손질] 저장소 조회에 `wonOn` 한 칸**
- `CertReviewSourceRow`에 `wonOn`을 더해 기존 함수 모양을 유지했다(플랜 ② 첫 갈래). I4는 그 칸을 쓰지 않는다.
