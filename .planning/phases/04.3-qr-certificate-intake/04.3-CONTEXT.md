## Phase Boundary

담당자가 행사를 만들고 당첨자 목록(이름·전화번호·경품명·수량·현장/택배)을 넣으면 행사 QR 하나가 생긴다. 경품 당첨자(외부 수령자)가 그 QR을 폰으로 찍고 로그인 없이 들어와 목록에서 자기 이름을 고르고 전화번호 뒤 4자리로 확인한 뒤, 본인 정보(이름·주민등록번호·연락처, 택배면 주소)와 개인정보 동의·터치 서명을 제출한다. 주민등록번호는 앱 단 암호화·권한자 열람·열람 기록·보존 기간 뒤 파기를 지킨다. 경영관리는 제출 내용을 행동 로그를 남기며 고치고 세무 보관용 인쇄물을 연다. `/cso`를 두 번 하고, 프로덕션에서는 플래그로 꺼 둔다. 요구사항: CERT-01, CERT-02 (`.planning/ROADMAP.md` Phase 04.3 기준 1~5).

이 페이즈는 Phase 11에서 Phase 4·5 미완성 코드(경품 지출결의·세금 규칙)에 기대지 않는 부분을 떼어 낸 것이다(2026-09-24 사용자 결정). 결정 번호는 Phase 11 논의의 D-11xx를 그대로 쓴다. 이 파일만 읽으면 계획할 수 있게 필요한 결정을 옮겨 두었다 — `11-CONTEXT.md`를 다시 읽을 필요가 없다.

**Phase 11에 남은 것:** 행사 QR을 경품 지출결의 화면에서 만들고 제출된 확인증을 그 지출결의에 자동으로 붙이는 일(CERT-03, D-1104), 경품 회사 대납 세금 제안·확정(CERT-04, D-1105), 프로덕션 플래그 켜기. 이 페이즈는 행사를 나중에 경품 지출결의에 붙을 자리(연결 어댑터)를 가진 단위로 만들고, 만들기 진입점은 내부 행사 화면으로 둔다. D-1104의 「따로 모았다가 나중에 연결하는 경로는 두지 않는다」는 기능이 켜졌을 때의 최종 모양이고, 이 페이즈의 내부 행사 화면은 플래그가 꺼진 동안의 임시 진입점이다 — Phase 11이 진입점을 경품 지출결의 화면으로 옮긴다.

범위 밖: 경품 지출결의 연결(Phase 11, D-1104), 세금 제안·확정(Phase 11, D-1105), 현금 개인 지급(계좌 입력) 확인증(D-1101), 확인증 PDF(CERT-05, v2), 본인인증 API(v2), 확인증 미기입 재촉 알림(Deferred 참고).

**로드맵 문구와 달라진 점(계획 단계에서 `gsd_run`으로 REQUIREMENTS 문구를 맞춘다):**
- CERT-01의 「계좌 입력」「지급 금액·소득 종류·원천징수액을 미리 채워 보여 줌」은 D-1101(경품만, 2026-09-18 화면 결정)로 대체한다. 수령자 화면에는 경품명만 보인다.
- CERT-01의 「QR(1회성 링크)」「링크는 1회 제출 후 만료」는 D-1102(행사당 QR 하나, 사람마다 1회 제출)로 대체한다.

### 이미 확정된 입력 (다시 묻지 않음 — 출처가 정본)
- 수령자 화면 골격·문구·다섯 상태: `docs/design/SYSTEM.md` §6-5, 실물 `docs/design/system/external-cert.html` (2026-09-18 `docs/design/DECISIONS.md` 「외부 수령자 화면 실물 확정」). 경품 블록은 경품명 한 줄, 시가·원천징수·지급액·계좌 없음. 원천징수·지급명세서라는 단어는 수령자 화면에 쓰지 않는다
- 주소 칸은 택배일 때만(담당자가 정함, 현장 기본) — DECISIONS 9/18 #2
- 주민등록번호 확인 = 서버 검사 규칙만(형식·실제 날짜·성별 코드·2020-10 이전 발급분 검증번호). 신분증 첨부·본인인증 없음 — DECISIONS 9/18 #3
- 개인정보 동의 = 서명 위 체크박스 + 요약 문장 + 「전문 보기」, 문장은 법무 확인 전 초안(근거법령·보관기간 자리표·제공처 국세청만) — DECISIONS 9/18 #4, 260907 3-18
- 주민등록번호 저장 = Phase 3 `lib/crypto.ts` `encrypt()/decrypt()`(`v1:` 키 버전 접두어). `/cso` 통과 뒤 키 보관을 Cloud KMS 봉투 암호화로 승격하되 헬퍼 인터페이스·접두어는 그대로 — ROADMAP 기준 4, Issue 7
- 열람: 기본은 뒷자리 마스킹, 전체 보기는 경영관리만(대표도 불가), 전체 보기마다 행동 로그(`mask_reveal`, 끌 수 없는 핵심 로그 OPS-05) — 260907 3-18·권한 예외
- 개인정보취급자(경영관리) 전용 비활동 세션 만료 2시간(10분~2시간 범위만 조정) — 260907 권한 예외. `/cso`가 조정할 수 있다
- 링크 만료 기본 72시간, 전화번호 뒤 4자리 5회 틀리면 3분 잠금, 사람마다 1회 제출 — 260907 3-18·설정 항목(확인증 탭)
- 파기 시점 = 제출한 해 종료 + 법정 신고기한 + 보존 기간(설정, 기본 5년). 파기 시 이름·전화·주민등록번호·주소·서명 이미지를 지우고 줄(건수·금액·연결)은 세무 기록으로 남긴다. DB를 먼저 비우고 파일을 나중에 지운다. 확인증은 보관함(soft delete) 예외 — 반드시 지운다 — 260907 3-18·기본 정책
- 확인증 PDF(CERT-05)는 v2. v1에서 수령자는 인쇄물을 보지 않는다 — DECISIONS 9/18
- 기능 플래그: `/cso` 결과가 반영되기 전 프로덕션에서 꺼져 있다. 두 감사를 통과해도 Phase 11의 경품 지출결의 연결이 끝나기 전에는 켜지 않는다 — ROADMAP Phase 04.3 기준 1, Phase 11 기준 1

### 받는 대상
- **D-1101:** **확인증은 경품(현물) 수령자에게만 받는다.** 수령자 화면은 SYSTEM §6-5 그대로이며 계좌·지급액 칸이 없다. 현금 개인 지급(사업소득·현금 기타소득)은 확인증 없이 기존 지출결의·거래처 흐름(Phase 5·6)으로 처리한다. — **Reversibility:** costly — 나중에 현금 지급을 받으려면 계좌 칸이 붙은 화면 변형(SYSTEM 개정)과 계좌 암호화 필드·동의 문구 수집 항목이 함께 늘어난다

### 링크와 수령자 찾기
- **D-1102:** **QR 링크는 행사(경품 지출결의)당 하나이고 여러 명이 같이 쓴다.** (이 페이즈에서는 행사가 독립 단위이고, Phase 11이 행사를 경품 지출결의 하나에 붙인다.) 한 사람은 한 번만 제출할 수 있고, 제출하면 그 사람 자리만 닫힌다. 링크 전체는 만료 시간(기본 72시간)이 지나거나, 등록된 당첨자가 모두 제출하거나, 담당자가 닫으면 닫힌다. — **Reversibility:** costly — 링크 모델(행사 단위 토큰 + 사람별 제출 상태)이 스키마·E2E·`/cso` 위협 모델의 기준이 된다
- **D-1103:** **담당자가 당첨자 목록(이름·전화번호·경품명·수량·현장/택배)을 미리 넣고, 수령자는 QR로 들어와 목록에서 자기 이름을 고른 뒤 전화번호 뒤 4자리로 확인한다**(260907 방식). 확인이 끝나야 §6-5 입력 폼이 열린다. 현장/택배는 사람마다 정한다(DECISIONS 9/18 #2의 「링크를 만들 때」가 「당첨자를 등록할 때」로 바뀐다). — **Reversibility:** costly — 수령자 흐름에 선택·확인 단계가 붙어 SYSTEM §6-5 개정이 필요하다

### 지출결의 연결 (Phase 11 몫 — 참고)
- **D-1104:** 행사 QR은 경품 지출결의 화면에서 만들고, 제출된 확인증은 그 지출결의에 자동으로 붙는다(지출결의 하나에 확인증 여러 장). 이 페이즈는 그 연결이 붙을 자리(연결 어댑터)와 플래그가 꺼진 동안 쓰는 내부 행사 화면만 만든다(위 Phase Boundary)

### 세금 (Phase 11 몫 — 참고)
- **D-1105:** 경품 확인증은 회사 대납(company_borne) 규칙으로 계산하고 기본값을 세율 22% · 역산(gross-up) · 시가 5만원 이하 면제로 둔다. **사용자 확정(2026-09-24, 프로젝트 채팅에서 확정·프로젝트 지침에 기록): 회사가 이미 이 방식으로 처리하고 있어 세무 확인은 필요 없다.** 논의 당시(PR #48)에는 Claude의 추론이며 세무 확인이 필요하다고 적었던 것을 고쳤다. 이 페이즈는 세금을 계산하지 않는다

### 제출 후 정정
- **D-1106:** **제출 내용이 틀리면 경영관리가 내부 화면에서 직접 고친다**(주민등록번호 포함). 고칠 때마다 행동 로그에 누가·언제·어느 칸을 고쳤는지 남기되 주민등록번호 평문은 로그에 담지 않는다. 서명 이미지는 고칠 수 없다(수령자 본인의 것). 주민등록번호를 고치려면 전체 보기 권한이 있어야 한다.

### 보안 감사
- **D-1107:** **`/cso`를 두 번 한다.** `/gsd-plan-phase 04.3`과 계획 게이트 뒤 설계(계획) 감사를 한 번 하고 결과를 계획에 반영한 뒤 실행하며, 구현 뒤 Post-build `/cso`를 한 번 더 한다. 둘 다 통과해야 프로덕션 플래그를 켠다. (분리로 더한 조건, 2026-09-24: 켜는 시점은 Phase 11의 지출결의 연결과 그 Post-build `/cso` 통과 뒤다.) 설계 감사는 특히 행사당 공유 링크(D-1102)의 노출 범위, 목록에 보이는 당첨자 이름(D-1103), 뒤 4자리 추측 공격, 직원의 주민등록번호 수정(D-1106)을 본다

### 인쇄물
- **D-1108:** **세무 보관용 확인증 인쇄물(SYSTEM §6-6 「기타소득 지급 확인증」)을 이번 페이즈에 만든다.** 경영관리만 연다. 주민등록번호는 인쇄물에서도 뒷자리 마스킹(§6-6). PDF 파일 저장은 v2(CERT-05). (분리로 더한 경계, 2026-09-24: 이 페이즈는 틀과 수령자 칸, 지출결의 번호·프로젝트·지급일·금액·회사 대납 세금 칸은 Phase 11이 채운다)

### Claude's Discretion
- 목록에 보이는 당첨자 이름의 가림 방식(예: 가운데 글자 마스킹)과 목록 크기 — `/gsd-ui-phase 04.3`·설계 `/cso`에서 정한다
- 확인 단계 뒤 폼의 「이름」 칸을 등록된 이름으로 미리 채울지 — UI 계약에서 정한다
- 내부 행사 화면에서 행사를 만들 수 있는 사람(기획 PM·경영관리를 기본으로)과 연결 어댑터의 모양(행사가 나중에 경품 지출결의를 가리키는 방식)
- 파기 실행 방식(Cloud Scheduler 작업 또는 수동 스크립트), 서명 이미지 저장 위치(비공개 GCS 버킷 경로)
- 토큰 형식·길이, 속도 제한 세부
- 제출하지 않은 당첨자 명단(이름·전화번호)의 파기 시점(행사가 닫힌 뒤 언제 지울지) — 설계 `/cso`가 본다
- 개인정보취급자 세션 만료(비활동 2시간)를 플래그 뒤에 둘지 — 플래그가 꺼진 동안에는 주민등록번호 열람이 없다
- 연결 어댑터: 당첨자 명단에는 경품 시가가 없으므로 Phase 11이 경품 시가를 지출결의 줄에서 가져올 수 있는 모양
- 인쇄물(§6-6)의 지출결의·금액·세금 칸을 Phase 11 전에 어떻게 보일지(비워 두는 것을 기본으로)
- 마이그레이션 번호: Phase 4가 0011~0016을 쓰므로 0017부터, 04.1·04.2와 겹치지 않게 계획 때 정한다

- **D-1103 폐기.** 담당자가 당첨자 명단(이름 · 전화번호 · 경품명 · 수량 · 현장/택배)을 미리 넣지 않는다. 수령자는 이름을 고르지 않고 전화번호 뒤 4자리로 확인하지 않는다. 대신 **수령자가 현장에서 QR로 들어와 받은 경품을 목록에서 고르고 → 이름 · 연락처 · 주민등록번호(택배 경품이면 주소)를 적고 → 수집 안내를 확인하고 서명해 → 제출한다.** 당첨자 확인 단계가 없어서 생기는 대리 제출 위험은 **행사 뒤 경영관리가 링크를 닫고 제출 건을 현장 추첨 결과와 대조**해 막는다.
- **D-1102 일부 변경.** QR 링크는 여전히 행사당 하나이고 여러 명이 같이 쓴다. 「사람마다 한 번 제출 · 제출하면 그 사람 자리만 닫힘 · 등록된 당첨자가 모두 제출하면 링크가 닫힘」은 명단이 없어 사라진다. 링크는 **기한이 지나거나 경영관리가 닫으면** 닫힌다.
- **행사 전 준비 = 「QR 생성 신청」 → 경영관리 「QR 생성」.** 기획본부가 시스템 안에서 「QR 생성 신청」을 하면(행사는 `신청됨`, QR · 토큰 없음) 경영관리 알림함으로 간다. 경영관리가 **5만원 넘는 경품 목록(경품명 · 1개 가액(예정) · 현장/택배)**을 넣고 QR을 생성한다. **행사를 만들 때 QR을 자동으로 만들지 않는다**(구현된 04.3-04의 동작이 바뀐다). 신청 권한은 `certs.events` 쓰기, QR 생성 · 경품 목록 편집 · 링크 닫기는 경영관리(새 권한 키 — 위험 경로 `domain/permissions/`, 사용자가 머지).
- **가액은 경품 단위(행사 한 값 · 제출 뒤 잠금 대체).** 판정은 `가액 × 수량`. 경영관리는 경품을 산 뒤 언제든 실제 가액으로 고친다 — 제출해도 잠기지 않는다. 고친 가액 × 수량이 5만원 이하가 되면 그 경품으로 낸 제출 건의 주민등록번호를 **파기 대상**으로 표시한다. 행사 단위 가액 · 가액 잠금(앞 요청의 D-B1 · D-B2 — 04.3-15 옛 초안)은 대체되었다.
- **5만원 이하 경품은 확인증을 받지 않는다.** 5만원 이하에는 택배가 없다. 가액 × 1이 5만원 이하인 경품은 수령자 목록에 오르지 않는다. **확인증을 내는 사람은 모두 주민등록번호를 낸다 — 「주민등록번호 안 받는 변형」은 없다.**
- **가액은 수령자 쪽으로 가지 않는다(5905714131 그대로).** 수령자에게 가는 HTML · RSC 페이로드 · 서버 액션 응답 · 오류 문구 어디에도 가액 숫자와 가액 필드 이름이 없다 — 양성 · 차등 대조군이 있는 누수 검사 테스트로 고정한다.
