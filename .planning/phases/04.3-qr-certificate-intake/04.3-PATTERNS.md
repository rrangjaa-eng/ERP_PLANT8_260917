## Pattern Assignments

### `lib/actions/client.ts` — `publicActionClient` 신설 (middleware, request-response)

**Analog:** 같은 파일의 `authedActionClient` (`lib/actions/client.ts:26-38`)

**핵심 패턴 — 세션 체크만 빼고 payload 크기 검사는 그대로 유지:**
```typescript
export const authedActionClient = actionClient.use(async ({ next, clientInput }) => {
  const sizeCheck = checkPayloadSize(clientInput);
  if (!sizeCheck.ok) {
    throw new UserFacingError(sizeCheck.reason);
  }

  const session = await getSession();
  if (!session) {
    throw new UserFacingError("로그인이 필요합니다.");
  }
  return next({ ctx: { viewer: session.viewer, user: session.user } });
});
```
`publicActionClient`는 `getSession()`·`session` 분기를 통째로 제거하고 `checkPayloadSize`만 유지, `ctx: {}`를 반환한다(RESEARCH.md 코드 예시와 동일). **권한 판정 함수(`can`/`visible`)를 이 클라이언트 체인 안에서 호출하지 않는다** — 토큰이 곧 경계이고, `domain/certs/intake.ts`는 `SYSTEM_VIEWER`(`domain/viewer.ts`)로 `recordAction`만 남긴다.

**동반 변경 — `eslint.config.mjs`:**
```javascript
"plant8/require-action-client": ["error", { clients: ["authedActionClient", "publicActionClient"] }],
```
`eslint/rules/require-action-client.mjs`의 `DEFAULT_CLIENTS = ["authedActionClient"]`(1행)와 `schema`의 `clients` 배열 옵션(47-58행 부근)을 그대로 이용한다 — 규칙 파일 자체는 수정하지 않는다.

### `domain/certs/intake.ts` (service, request-response + 상태 전이)

**Analog:** `domain/auth/lockout.ts` 전체

**설정 레지스트리 조회 + 순수 함수 분리 패턴:**
```typescript
export type LockoutConfigDeps = { getSettingValue: typeof defaultGetSettingValue };

export async function lockoutConfig(deps?: Partial<LockoutConfigDeps>) {
  const getSettingValue = deps?.getSettingValue ?? defaultGetSettingValue;
  const [threshold, windowMinutes] = await Promise.all([
    getSettingValue(AUTH_LOCKOUT_THRESHOLD),
    getSettingValue(AUTH_LOCKOUT_WINDOW_MINUTES),
  ]);
  return { threshold, windowMinutes };
}

export function windowStart(now: Date, windowMinutes: number): Date { ... }
export function isLocked(openFailures: number, threshold: number): boolean { ... }
```
`isEventExpired`, `verifyLast4`의 잠금 판정(`cert.verify.max_attempts`/`cert.verify.lock_minutes` 읽기)은 이 `deps` 주입형 async 함수 + 별도 순수 함수 분리 구조를 그대로 쓴다. **주의(Pitfall 3):** 잠금은 `domain/auth/lockout.ts`처럼 IP/이메일 계정이 아니라 `cert_winners` 행(슬롯) 단위로 건다 — `repositories/login-attempts.ts`의 스키마를 재사용하지 않는다.

### `domain/certs/review.ts` — `revealRrn` (service, CRUD)

**Analog:** `domain/vendors/index.ts:368-393` `revealAccountNumber` (그대로 복제 대상, RESEARCH.md에 이미 구체 예시 있음)

```typescript
export async function revealAccountNumber(
  viewer: Viewer,
  id: string,
  deps?: Partial<RevealAccountNumberDeps>,
): Promise<string> {
  const visibleFn = deps?.visible ?? defaultVisible;
  if (!(await visibleFn(viewer, REVEAL_INFO_ITEM))) {
    throw new ForbiddenError("계좌번호 마스킹 해제 권한이 없습니다.");
  }
  const row = await repoFindVendorById(viewer, id);
  if (!row?.accountNumberEncrypted) return "";
  const recordAction = deps?.recordAction ?? defaultRecordAction;
  await recordAction(viewer, { actionType: "mask_reveal", entity: VENDOR_ENTITY, entityId: id });
  return decrypt(row.accountNumberEncrypted);
}
```
`revealRrn(viewer, submissionId)`는 `REVEAL_INFO_ITEM` 자리에 `"cert.rrn_unmasked"`(신규 등록, `domain/permissions/info-items.ts`), `VENDOR_ENTITY` 자리에 `"cert_submission"`을 넣어 **순서(visible→recordAction→decrypt)를 그대로** 지킨다 — 기록 실패 시 평문을 돌려주지 않는 fail-closed 불변식이 핵심.

**정정(`correctSubmission`)의 행동 로그:** `recordAction(viewer, { actionType: "document_update", entity: "cert_submission", entityId, detail: {...바뀐 칸만...} })` — RRN 평문은 `detail`에 절대 넣지 않는다(`lib/crypto.ts:1-3` 헤더 주석 규칙과 동일 선상).

### `repositories/cert-files.ts` — GCS 서명 이미지 저장 (service, file-I/O)

**Analog:** `lib/gcp/cloud-sql-admin.ts` 전체 — `@google-cloud/storage` SDK 대신 이미 저장소에 있는 `google-auth-library`(`GoogleAuth`)로 인증한 뒤 GCS JSON API를 REST로 직접 호출하는 방식(오케스트레이터 지시: `@google-cloud/storage` 미사용).

```typescript
import { GoogleAuth } from "google-auth-library";

const auth = new GoogleAuth({ scopes: ["https://www.googleapis.com/auth/sqlservice.admin"] });
const client = sqladmin({ version: "v1", auth });
const res = await client.backupRuns.list({ project, instance, maxResults: 1 });
```
`cert-files.ts`는 `@googleapis/sqladmin` 같은 타입 SDK가 없는 대신, `GoogleAuth.getClient()`가 반환하는 인증된 클라이언트로 GCS JSON API(`https://storage.googleapis.com/upload/storage/v1/b/{bucket}/o?uploadType=media&name={key}`)에 직접 `fetch`/`request`한다. `timeout`(20-24행)·`try/catch`+`log.warn(reason)` 실패 처리 구조(41-55행)를 그대로 복제한다. 스코프는 `https://www.googleapis.com/auth/devstorage.read_write`로 바꾼다.

**Anti-pattern:** `@google-cloud/storage` npm 패키지를 추가하지 않는다(RESEARCH.md의 후보였으나 오케스트레이터가 기각 — 이미 있는 `google-auth-library`로 충분).

## Shared Patterns

### 인증/권한 경계 — 두 갈래
1. **내부 화면(행사·정정·인쇄):** `authedActionClient` + `can(viewer, 'certs.events'|'certs.submissions', 'write')` — 기존 `domain/vendors/index.ts` 패턴 그대로.
2. **외부 제출(`/c/[token]`):** `publicActionClient`(신규) — 세션 없음, 토큰이 경계. `proxy.ts`(matcher `["/api/auth/:path*"]`만)를 거치지 않으므로 속도 제한·잠금은 전부 도메인 로직(`domain/certs/intake.ts`)에 넣는다(Pattern 2·Pitfall 3).

### PII 암호화·마스킹 해제·행동 로그
**Source:** `lib/crypto.ts`(`encrypt/decrypt`, `v1:` 접두어) + `domain/vendors/index.ts:368-393`(`revealAccountNumber`) + `domain/action-log/record.ts`(`recordAction`, `mask_reveal`)
**Apply to:** `domain/certs/review.ts`의 `revealRrn`/`correctSubmission` 전부. 순서 불변식(visible → recordAction → decrypt)을 위반하는 코드는 즉시 재검토 대상.

### 물리 삭제 금지 불변식
**Source:** `domain/archive/index.ts:16` 주석
**Apply to:** `domain/certs/purge.ts`, `scripts/purge-expired-certs.ts` — `UPDATE ... SET col = NULL`만 허용, `DELETE FROM`은 저장소 전역 금지.

### 설정 레지스트리(이력 없는 운영 파라미터)
**Source:** `domain/settings/keys.ts`의 `kind: "simple"` 항목들, `domain/settings/registry.ts`
**Apply to:** 확인증 탭 키 5개. 환경 변수(`lib/env.ts`)로 만들지 않는다 — `cert.production_enabled`는 특히 런타임 즉시 반영이 필요하므로 레지스트리가 맞다.

### 서버 액션 클라이언트 — payload 크기 검사 공유
**Source:** `lib/actions/client.ts`의 `checkPayloadSize`(`lib/actions/payload-size.ts`)
**Apply to:** `publicActionClient`도 동일 검사를 유지한다(세션 체크만 뺀다).
