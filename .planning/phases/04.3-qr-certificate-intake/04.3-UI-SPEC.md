1. **새 토큰 0개.** 색·서체·radius·그림자·간격 토큰을 만들지 않는다(`git diff docs/design/tokens.css` 0줄). 전부 `tokens.css` 변수로 그린다.

## Copywriting Contract

§8 카피 규칙 그대로: 버튼 = 실제 동작, 결과 = 버튼과 같은 단어, 오류 = 원인 · 다음 행동, 사과·느낌표 없음, 안내 문구 없음. **외부 수령자 화면과 오류의 「다음 행동」만 `~해 주세요`체.** `{…}`는 서버 값이고, 예시 값은 실물의 값을 쓴다. 담당자 표기 `{담당자}` = 행사를 만든 사람 이름(예: `박서연`). **`{문의 전화}`** = 확인증 탭 설정 `수령자 문의 전화`(새 설정 키, 기본값 없음 — 가정 A12)의 값이고 외부 화면에서 `<a href="tel:…">` 3차 링크로 그린다. 값이 비어 있으면 번호 없이 `PLANT8 경영관리에 연락해 주세요`로 줄이고, E2 문의 줄과 E3 잠김 2행은 렌더하지 않는다.

## 화면 계약

라우트 이름은 가칭이고 계획이 확정한다: 외부 `/c/[token]` · 내부 `/certs/events`(목록 · `?new=1` 만들기) · `/certs/events/[id]`(상세) · `/certs/submissions/[id]`(정정) · `/print/certs/[id]`(인쇄).

**기능 플래그(`cert.enabled` 류 설정 키, 환경마다 값이 다르다 — 프로덕션 꺼짐(Phase 11까지, CONTEXT 「이미 확정된 입력」 기능 플래그 줄) · 개발·검증 켜짐):**
- **꺼짐:** 외부 `/c/[token]` → E6-c(HTTP 404). 내부 `/certs/events`(`?new=1` 포함) · `/certs/events/[id]` · `/certs/submissions/[id]` → §6-9 404(셸 안). **인쇄 `/print/certs/[id]` → 404**(셸 없는 라우트라 §6-9 404 문구를 인쇄 라우트 바탕에). 이 화면들의 서버 액션은 전부 거부된다. 「관리」 인덱스의 `확인증` 그룹은 렌더하지 않는다
- **켜짐:** 「관리」 인덱스 `확인증` → `확인증 행사`(I1)가 행사 만들기의 유일한 진입점이다. CONTEXT 13행의 「플래그가 꺼진 동안의 임시 진입점」은 Phase 11 전 기간(= 프로덕션 플래그가 꺼져 있는 기간)을 가리키고, 그 기간에 이 화면은 플래그가 켜진 환경(개발·검증)에서만 열린다. Phase 11이 진입점을 경품 지출결의 화면으로 옮긴 뒤 프로덕션 플래그를 켠다
- 켜짐/꺼짐으로 화면이 달라지는 곳은 위의 셋(외부 라우트 · 내부·인쇄 라우트 넷 · 인덱스 그룹)뿐이다

**E1 공통**
- 폰 전용 한 열, `main` 최대 폭 480(실물값), PC에서도 왼쪽 정렬 480 한 열로 선다. 셸 없음(상단 바만, 하단 탭 · 메뉴 · 사용자 없음). `<main>` 랜드마크 하나, `<header>`는 상단 바
- 본문·문장 `--fs-md`, 입력·1차 48, `~해 주세요`체(§6-5 · §8-6 · 개정 ①-k)
- LOADING: 상단 바 아래 2px `--accent` 진행 바만, 글자 없음(§7-7 확정). 300ms 안에 끝나면 보이지 않는다. 버튼은 §7-1 진행 중(라벨 뒤 `…` + `.sr-only` `처리 중`, 다른 버튼 비활성)
- **서버 왕복 공통(E2 `selectWinner` · E3 `verifyLast4` · E4 제출):** 클라이언트는 20초 안에 응답이 없으면 그 요청을 응답 없음으로 본다. 응답 없음 = 「처리되지 않음」이 아니라 「결과를 모름」이다 — E3·E4는 요청마다 **멱등 키**(클라이언트가 만든 추측 불가 값)를 보내고, 같은 입력으로 다시 누르면 같은 키를 다시 보낸다. 서버는 같은 키의 두 번째 요청에 첫 결과를 돌려주고 새로 세거나 새로 저장하지 않는다(키 형식·보관 시간은 설계 `/cso` 몫). 입력을 바꾸면 새 키다
- **포커스 이동:** E2 → E3 = 뒤 4자리 칸 · E3 → E4 = 경품 블록(`tabindex=-1`, 라벨 「경품」과 값이 읽힌다) · E3·E4 → E2 = 방금 고른 행 · E5·E6 = 결과 블록 첫 줄(`tabindex=-1`). 단계가 바뀔 때 `document.title`도 `{단계} · 기타소득 지급 확인`(예 `전화번호 확인 · 기타소득 지급 확인`)으로 바꾼다

**E2 이름 고르기**
- 목록 = 그 행사에 등록된 당첨자 **전부**, 한 목록, 페이지 나눔·검색 없음. 순서 = 서버가 **실제 이름의 가나다순**으로 정렬한 뒤 가린다(같으면 등록 순서). 제출한 사람도 같은 모양으로 남는다 — 제출 여부를 목록에서 드러내지 않는다(누가 냈는지 목록만 보고 알 수 없게). 행을 고르는 것만으로는 제출 여부가 드러나지 않는다 — E6-a는 전화번호 확인을 통과한 뒤에만 선다(E3)
- **이름 가림 규칙(서버에서만, 클라이언트는 실제 이름을 받지 않는다):** 공백을 뺀 글자 수 n으로 — n=1 → `*` · n=2 → 첫 글자 + `*`(`김*`) · n≥3 → 첫 글자 + `*`×(n−2) + 끝 글자(`김*늘` · `남**수` · `J********h`). 공백은 자리를 지킨 채 그대로 둔다. 목록 DTO에는 가린 이름 + 추측 불가능한 행 식별자만 있다(순번 id 금지 — 누수 스캔 대상)
- **겹침 규칙:** 가린 이름이 같은 행이 둘 이상이면 그 행들만 2행에 `{경품명} {수량}개`를 보인다. 겹치지 않는 행은 한 줄
- **묶음 규칙(보이는 모양이 같은 사람들):** 가린 이름과 2행까지 같아 화면에서 구별할 수 없는 사람들(예: 김민수·김문수가 같은 경품)은 **한 행**으로 보인다 — 같은 모양의 행을 둘 늘어놓아 본인이 운에 맡겨 고르게 하지 않는다. 그 행의 식별자는 서버가 만든 묶음 식별자이고, 누가 몇 명 묶였는지는 화면에 쓰지 않는다. 사람의 확정은 E3에서 서버가 한다(아래). 새 개인정보를 보이지 않는다
- 행 = `<li><button>` 전폭, 최소 높이 48, 좌우 패딩 0(메인 패딩 안), 아래 `1px --line`, 첫 행 위는 라벨 아래 여백 `--s-2`. hover·active `--surface`. `:focus-visible`는 기본 바깥 링(행이 메인 패딩 안에 있어 링을 그릴 여백이 있다 — §4-4 inset 예외에 넣지 않는다)
- 행을 누르면 곧바로 E3. 확인 버튼 없음. 이 단계에 1차 버튼이 없다(0개 — §7-1 「1개」 상한 안)
- **행 누름 = 서버 왕복(`selectWinner`).** 기다리는 동안 누른 행 오른쪽 끝에 `…`(§7-1 진행 중과 같은 표기) + 목록 전체 비활성(두 번 누름 방지), 300ms 넘으면 E1 진행 바. 응답에 따라: 보통 → E3 · 잠긴 자리 → E3 잠김 상태 · 링크 닫힘 → **E6-b**(서버가 준 사유) · 네트워크/서버 실패·응답 없음 → E2에 남고 목록 라벨 아래 한 줄 `이름을 불러오지 못했습니다 · 잠시 뒤 다시 골라 주세요`(`--fs-md --danger`, `role="alert"`), 목록은 다시 살아나고 포커스는 누른 행에 남는다. 이 줄은 다음 행 누름에서 지워진다(고르기는 읽기라 다시 눌러도 세는 것이 없다)
- **문의 줄(개정 ①-l):** 목록 아래 `--s-4` 띄워 한 줄 `목록에 이름이 없으면 PLANT8 경영관리 {문의 전화}에 전화해 주세요`(`--fs-md --muted`, 번호는 `tel:` 3차). 「이름이 목록에 없다」는 막힌 상태의 다음 한 수라 §8-5 안내 문구가 아니다(§11 브리프 1). `{문의 전화}`가 비면 렌더하지 않는다
- EMPTY: **해당 없음** — 당첨자가 0명인 행사는 만들 수 없다(I2 1차 막힘). 모두 제출하면 E6-b

**E3 전화번호 확인**
- 고른 이름은 가린 이름 그대로 `--fs-lg` 700. 오른쪽 3차 「다른 이름 고르기」 → E2, 포커스는 방금 고른 행
- 입력: `TextField size="external"`, `inputmode="numeric"` · `autocomplete="off"` · `maxlength=4`, 숫자 아닌 글자는 입력 중 지운다. 폼은 `noValidate`(§7-15). 진입 시 포커스는 이 칸
- 1차 「전화번호 확인」(`Button size="external"`): 숫자 4개가 아니면 비활성 + 이유(§7-1, 개정 ⑦ (b)로 `aria-describedby` 연결). 누르면 진행 중 `전화번호 확인…`. 버튼이 살아 있을 때 이유 자리에 오는 문장(응답 없음)은 화면이 직접 그린 `<p id>` 줄이고 버튼 `aria-describedby`에 그 id를 준다 — 같은 자리(버튼 아래)
- **서버 판정(묶음 행이면 묶음 전원과 대조):** 적은 4자리와 맞는 사람이 — 하나면 그 사람으로 확정 · 없으면 틀림(그 행 단위로 센다 — 묶음 행이면 묶음 전체가 한 자리) · **둘 이상이면 구별할 수 없는 자리**(같은 번호를 함께 쓰는 가족 등). 틀림 횟수가 엉뚱한 한 사람에게 쌓이지 않고, 남의 자리로 확인을 통과할 수 없다
- **틀림:** 칸 `--danger` 테두리 + `aria-invalid` + 아래 한 줄(남은 횟수 포함, `aria-live="polite"`). 입력값은 지운다(4자리 재입력이 자연스럽고, 틀린 값을 남길 이유가 없다) — §7-2 「입력값은 지우지 않는다」의 예외가 아니라 비밀 값 재입력이라 개정 ①-b가 §6-5에 적는다. 포커스는 칸에 남는다
- **잠김(서버가 판정, 목록 행 단위 — IP 아님):** 입력 비활성 · 1차 비활성, 제출 줄 이유 1행 `{한도}번 틀려 확인이 잠겼습니다 · {18:45}부터 다시 해 주세요` + 2행 문의(Copywriting). `{한도}` = 확인증 탭 설정의 틀림 한도, 시각 = 서버가 준 잠금 해제 시각 `HH:mm` — 둘 다 서버 값, 클라이언트에 5·3을 박지 않는다. 카운트다운을 그리지 않는다(§5 모션). 잠긴 자리를 E2에서 다시 고르면 E3가 곧바로 잠김 상태로 선다
- **잠금 풀림(클라이언트):** 서버는 해제 시각과 함께 남은 초를 준다. 클라이언트는 받은 순간 + 남은 초로 마감을 잡고(기기 시계 차이 무시), 그 순간 또는 화면이 다시 보일 때(`visibilitychange` visible · `pageshow`) 마감이 지났으면 곧바로: 잠김 두 줄을 지우고 · 칸 `--danger` 테두리·`aria-invalid`를 지우고 · **입력을 다시 살리고** · 1차는 칸이 비어 있으니 비활성 + 원래 막힘 이유(`뒤 4자리 숫자를 적으면 확인할 수 있습니다`)로 돌아간다. 포커스가 문서 바깥(잠김 동안 비활성 칸에서 빠진 상태, `document.activeElement === body`)이면 칸으로 옮기고, 사용자가 다른 곳에 있으면 옮기지 않는다. 판정은 여전히 서버가 한다(일찍 눌러도 서버가 잠김을 다시 준다)
- **맞음:** 그 사람으로 E4. 그 사람이 이미 제출했으면 E4 대신 **E6-a**
- **구별할 수 없는 자리:** 입력·1차 비활성, 제출 줄 이유 `이 자리는 전화번호로 확인할 수 없습니다 · PLANT8 경영관리 {문의 전화}에 전화해 주세요`. 틀림으로 세지 않는다. 드러나는 것은 「같은 번호를 쓰는 다른 당첨자가 있다」뿐이고, 이는 그 번호를 이미 아는 사람에게만 보인다(가정 A11)
- **링크 닫힘(`verifyLast4` 응답):** 확인 중에 기한이 지났거나 · 모두 제출했거나 · 담당자가 닫았으면 화면 전체가 **E6-b**(서버가 준 사유)로 바뀐다. 적은 4자리는 버린다. 틀림 횟수를 세지 않는다
- **응답 없음(네트워크·서버·20초):** 제출 줄 이유 자리에 `확인 결과를 받지 못했습니다 · 다시 눌러 주세요`(`--danger`, 1차 `aria-describedby`). 1차는 살아 있고 적은 4자리는 남는다 — 칸 테두리를 붉히지 않고 남은 횟수를 말하지 않는다(서버가 셌는지 모른다). 다시 누르면 같은 멱등 키로 보내 서버는 첫 결과(틀림 · 잠김 · 맞음)를 돌려준다 — 이미 잠겼으면 그때 잠김 상태가 선다. 4자리를 고치면 이 줄은 원래 막힘 이유 자리로 돌아가고 다음 요청은 새 키다
- 확인 상태는 페이지 메모리에만 있다. 새로 고침 → E2부터(주민등록번호 등 입력값은 어디에도 저장하지 않는다 — `localStorage`·`sessionStorage` 금지). 서버 확인 증표의 형식·유효 시간은 계획·설계 `/cso` 몫
- **뒤로 가기(기록 항목은 둘뿐):** 첫 화면 E2 = 페이지 기록 항목. E2 → E3에서 `history.pushState({step:"verify"})` 한 번. E3 → E4에서는 `history.replaceState({step:"form"})`(새 항목을 쌓지 않고 E3 항목을 바꾼다). 그래서 브라우저 뒤로는 E3에서도 E4에서도 한 번에 E2다(확인을 버리고 이름부터). E5·E6으로 갈 때도 `replaceState`. `popstate`로 E2에 오면 E3·E4 상태를 메모리에서 지운다(아래 「값의 주인」). 앞으로 가기로 E2보다 뒤 단계 항목에 오면 메모리에 그 단계가 없으므로 E2를 그리고 `replaceState`로 항목을 E2로 맞춘다. URL은 바뀌지 않는다(토큰 외 정보를 URL에 두지 않는다)

**E4 입력 — §6-5 폼 그대로 + 아래만 확정**
- **값의 주인:** E4의 모든 입력(이름 · 주민등록번호 · 주소 · 연락처 · 동의 · 서명 획)은 E3에서 서버가 확정한 **그 사람**(서버가 준 불투명 식별자)에 묶여 메모리에만 있다. 확인 시간이 지나 E3로 돌아간 뒤 — 다시 확인해 **같은 사람**이 확정되면 값을 되살리고 · **다른 사람**이 확정되거나(묶음 행) · 「다른 이름 고르기」·뒤로 가기로 E2에 가거나 · E6으로 가면 값을 전부 버린다. 남의 자리에 앞사람의 주민등록번호·서명이 넘어가지 않는다
- **이름 칸은 비워 둔다(등록 이름을 미리 채우지 않는다) — Claude 재량 결정.** 이유: ① 뒤 4자리 확인은 10,000가지뿐이라 약한 확인이다 — 확인을 통과한 뒤에도 목록이 이미 보인 것(가린 이름) 이상의 개인정보를 화면에 내지 않는다(DECISIONS 9/18 #6 「링크가 남에게 넘어갔을 때 주민등록번호가 보이면 안 된다」와 같은 원칙). ② 세무 서류의 이름은 수령자 본인이 적은 법적 이름이어야 하고, 등록 이름은 담당자가 적은 별칭·오타일 수 있다. ③ 비용은 세 글자 타이핑. 등록 이름과 다르면 I4가 `등록 이름 …` 힌트로 경영관리에게 보인다. **연락처도 같은 이유로 비워 둔다.** → 설계 `/cso`가 다시 볼 수 있는 가정(A3)
- 경품 블록: `{경품명} {수량}개` 한 줄, 등록된 값(§6-5 확정). 전달 방법은 **그 당첨자에게 등록된 값**이 정한다(현장 기본 / 택배면 주소 칸). 수령자가 고르는 선택지는 없다(잘못 등록됐으면 E5·E6의 문의 전화)
- **주민등록번호(화면 전용 부품 「주민등록번호 두 칸」):** 보이는 라벨 `주민등록번호`가 묶음(`role="group" aria-labelledby`)의 이름이고, 칸마다 접근 이름이 있다 — 앞 6(`aria-label="주민등록번호 앞 6자리"`, `inputmode=numeric`, maxlength 6) - 뒤 7(`aria-label="주민등록번호 뒤 7자리"`, `type=password`, `inputmode=numeric`, maxlength 7, `autocomplete="off"`). 뒤 칸은 가려진 글자 수로 읽힌다(값을 읽어 주지 않는다 — 브라우저 기본)
  - **자동 이동은 한 경우만:** 앞 칸 끝에서 글자를 쳐 넣어(`inputType === "insertText"`, 캐럿이 끝) 6자리가 채워질 때만 포커스가 뒤로 간다. 앞 칸 중간을 고칠 때 · 지울 때는 움직이지 않는다
  - **붙여넣기:** 앞 칸에 13자리(`9304122123456` 또는 `930412-2123456`)를 붙여 넣으면 숫자만 골라 앞 6 · 뒤 7로 나눠 채우고 포커스는 뒤 칸 끝. 그 밖의 길이는 앞 칸에 숫자만 남긴다
  - 검사는 서버만(형식 · 실제 날짜 · 성별 코드 · 2020-10 이전 발급분 검증번호, §6-5 확정). 오류는 두 칸 모두 `--danger` 테두리 + `aria-invalid`, 칸 아래 한 줄의 id를 두 칸의 `aria-describedby`에 넣는다

  - 모양: `<canvas>` 높이 160, 폭 100%, `1px --line-ui` 테두리, 기준선(아래 36px, `1px dashed --line`), 빈 칸일 때만 왼쪽 위 `손가락으로 서명해 주세요`(`--fs-sm --faint`). 선 색 `--fg`(`getComputedStyle`로 읽는다 — 리터럴 없음), 굵기 3px(CSS px), `touch-action: none`(서명 중 스크롤 막기). 획이 하나라도 있으면 오른쪽 아래 3차 「다시 쓰기」(44 높이, §6-5 확정) → 칸을 비우고 버튼이 사라지며 포커스는 캔버스로
  - **획 보존:** 획은 점 배열로 메모리에 두고 좌표는 캔버스 CSS 폭·높이에 대한 비율(0~1)이다. 캔버스 크기가 바뀌면(폰 회전 · 확대 · 창 크기 — `ResizeObserver`) 비율 좌표로 다시 그린다(획이 사라지거나 늘어나지 않고 굵기는 3px 그대로). `pointercancel`·`pointerleave`는 그 획을 거기서 끝낸다(지우지 않는다). 확인 시간 지남으로 E3에 다녀와도 같은 사람이면 남는다(「값의 주인」)
  - **「서명 있음」 판정:** 모든 획 길이의 합이 CSS 24px 이상. 점 하나·짧은 스침은 서명이 아니다 — 제출 줄 이유는 계속 `서명을 해 주세요`. 「다시 쓰기」는 잉크가 조금이라도 있으면 보인다(9/18 #5 「서명이 있을 때만」은 칸에 잉크가 있을 때로 읽는다 — 지울 것이 있으니까)
  - **키보드·보조기술로 그리기(§10 「키보드 전 행동」·§11):** 캔버스 `tabindex=0` · `role="application"` · `aria-roledescription="서명 칸"` · `aria-label="서명 칸"`(서명 있음이면 `서명 칸 · 서명함`) · `aria-describedby` → `.sr-only` 설명(Copywriting). 포커스되면 펜 위치를 8px 십자(`1px --fg`)로 그린다 — 처음 위치는 기준선 위 왼쪽 24px. `Space`/`Enter` = 펜 대기/떼기, 방향키 = 8px 이동(`Shift`+방향키 24px), 펜을 댄 채 움직이면 획이 된다. 칸 밖으로 나가지 않는다. `Tab`은 캔버스를 떠난다(트랩 없음). 화면 읽기 프로그램 사용자는 VoiceOver·TalkBack의 통과 제스처(두 번 탭한 뒤 누른 채 끌기)로 손가락 획을 그릴 수 있다 — Pointer Events가 그대로 받는다. 어느 방법이든 수령자가 칸에 직접 그은 획이라 서명의 뜻(§6-6 수령자 서명 이미지)은 같다
  - **보내기:** 제출할 때 PNG(base64)로 한 번 보낸다(용량은 서버 액션 한도 안 — RESEARCH). PNG는 **바탕 투명**(칸 바탕 `--bg`는 CSS로만 칠한다) + 획만. 기준선 · 자리표시 · 펜 십자는 넣지 않는다
- 제출 줄: `main` 안 sticky 하단, 위 2px `--line-strong`, 1차 「확인증 제출」(`Button size="external"`, 48, 폭 100%) + 아래 이유 한 줄(`--fs-md`, `aria-describedby` — 개정 ⑦ (b), 버튼이 살아 있을 때의 오류 문장은 E3와 같이 화면이 그린 `<p id>`). 안전 영역 `env(safe-area-inset-bottom)` 더함(실물 그대로)
- 제출 뒤 서버 결과에 따라: 성공 → E5 · 칸 오류 → 칸 아래 + 제출 줄, **포커스는 시각 순서상 첫 오류 칸** · 확인 시간 지남 → E3(값은 「값의 주인」대로) · 그새 그 자리가 제출됨 → E6-a · 그새 링크가 닫힘 → E6-b(값 버림) · 응답 없음(네트워크·서버·20초) → 제출 줄 `제출됐는지 확인하지 못했습니다 · 다시 눌러 주세요 · 적은 내용은 남아 있습니다`, 1차 살아 있음. 다시 누르면 **같은 멱등 키**로 보낸다 — 첫 요청이 이미 저장됐으면 서버가 그 결과를 돌려줘 E5가 선다(두 번 저장되지 않는다). 값을 고친 뒤 누르면 새 키(서버는 그 사람이 이미 제출했으면 E6-a를 준다 — 사람마다 1회, D-1102)

**E6 닫힌 상태** — 모양은 E5와 같은 결과 블록. **E6-a는 전화번호 확인을 통과한 뒤에만**(자리 단위) 선다 — E3 확인 결과가 「이미 제출」이거나 E4 제출 결과가 「그새 제출됨」일 때. 행을 고르는 것만으로는 서지 않는다. E6-b는 링크 단위로 **서버 왕복 네 곳 전부** — 진입 즉시 · E2 행 누름(`selectWinner`) · E3 확인(`verifyLast4`) · E4 제출 — 에서 서버가 「닫힘 + 사유」를 돌려주면 선다(사유 셋의 문장은 Copywriting E6-b, 고른 이름·적은 값은 버린다). 클라이언트는 기한 시각을 스스로 재지 않는다 — 다음 서버 왕복이 판정한다. E6-c는 공통 머리의 부제 없이 제목 + 결과 블록만(행사를 모르므로). 어느 것에도 1차 버튼이 없다.

  - **자동 가리기:** ① 화면이 가려지면(`visibilitychange` hidden) ② 개인정보취급자 비활동 시간(설정값, 기본 2시간 — 서버가 분을 준다)이 이 화면에서 지나면 — 위 「가리기」를 저절로 누른 것과 같다(고친 값은 보존). 세션이 끝난 뒤에도 평문이 화면에 남지 않는다. 다음 행동은 §6-9 세션 만료로 간다
  - **저장에 성공하면** 칸은 곧바로 새 값의 마스킹 텍스트로 돌아간다(평문이 화면에 남는 시간을 줄인다)
  - **브라우저 인쇄 보호:** 이 화면의 `@media print`에서 주민등록번호 입력 칸 · 가린 고친 값 · 「전체 보기/가리기」를 숨기고, **저장된 값의** 마스킹 텍스트(`930412-2******`, 서버가 렌더에 함께 준다)만 보인다. `⌘P`·브라우저 메뉴 인쇄로도 전체 번호가 종이·PDF에 나가지 않는다(D-1108 「인쇄물에서도 뒷자리 마스킹」을 이 화면의 브라우저 인쇄에도 적용)
  - 전체 보기 없이 주민등록번호를 고칠 길은 없다(입력 칸이 전체 보기 뒤에만 생긴다 — D-1106 「고치려면 전체 보기 권한」이 화면 구조로 성립)
  - 검사는 외부와 같은 서버 규칙. 오류 문장은 명사형(Copywriting I4)
- 읽기 전용(`KvList`): 경품(`{경품명} {수량}개 · 현장 수령|택배`) · 동의(`동의함 · 일시`) · 서명(서버가 권한 확인 뒤 내려주는 이미지, CSS `width: 320px; aspect-ratio: 520 / 200; object-fit: contain` — 높이 리터럴 123을 CSS에 쓰지 않는다. 폰은 `width: 100%` 같은 비율, `1px --line` 테두리 없이 아래 1px `--line`, `alt="{제출 이름} 서명"`) + `수령자 서명 · 고칠 수 없음`. 서명에는 어떤 컨트롤도 없다(D-1106). **이미지를 못 불러오면**(`onerror`) 이미지 자리에 `서명 이미지를 불러오지 못했습니다 · 다시 시도`(`--danger` 글자, 3차 「다시 시도」 = 같은 주소를 다시 부른다) — 빈 테두리나 깨진 이미지 아이콘을 두지 않는다
- `Form.Actions`: 1차 「고친 내용 저장」 — 바뀐 칸이 없으면 비활성 + 이유. 성공 → 버튼 자리 결과 텍스트(바뀐 칸 이름 나열, `--success`), 입력은 새 값을 기준으로 **계속 고칠 수 있다**(정정 화면은 한 번 제출하고 끝나는 폼이 아니다 — 개정 ⑧이 §7-15 SUCCESS에 「정정 폼」 한 줄을 더한다), 토스트 없음(화면 이동이 없다). 실패 → 버튼 옆 이유 + 칸 아래 `Form.Error`, 값 유지
- **동시 정정:** 폼은 불러온 `version`을 함께 보낸다. 다른 직원이 그 사이 저장했으면 거부 → 버튼 옆 `저장하지 못했습니다 · {이수아}가 {14:01}에 먼저 고침 · 다시 불러오기`. 값은 남아 있고, 3차 「다시 불러오기」를 누르면 새 값을 불러오며 내 고친 값은 버린다(한 사람의 서류라 칸별 병합을 하지 않는다). 남의 변경을 덮어쓰는 길은 없다
- 행동 로그(누가 · 언제 · 어느 칸)는 서버가 남기고 **이 화면에 이력 목록을 그리지 않는다**(요청 범위 밖 — 기존 「행동 로그」 관리자 화면에서 본다). 주민등록번호 평문은 로그에 없다(D-1106)
- 머리 2차 「인쇄」 → 새 탭 `/print/certs/[id]`(§6-6 「화면에서 인쇄는 2차, 새 탭 + 자동 `window.print()`」). 인쇄물은 **저장된 값**을 찍는다 — 그래서 고친 칸이 하나라도 있으면 「인쇄」는 비활성 + 이유 `인쇄할 수 없음 — 저장 안 한 칸 {N} · 먼저 저장`(화면에 보이는 값과 인쇄물이 달라지는 순간을 없앤다)
- 세션: 경영관리(개인정보취급자)는 비활동 2시간 만료. 만료 뒤 행동하면 §6-9 세션 만료 화면(→ 로그인). 이 화면에 남은 시간 표시·경고 배너를 두지 않는다(만료 순간의 자동 가리기는 위)
- 폰(<700): 라벨이 위로, 칸 전폭, 서명 이미지 전폭(비율 유지). 1차는 §6-3 폰 규칙(하단 탭 위 고정 제출 줄)
- 다섯 상태: LOADING = 해당 없음(서버 렌더) · EMPTY = 해당 없음 · ERROR = `Form.Error` + 이유 · 전체 보기 실패 한 줄 · 동시 정정 · 서명 이미지 실패 · SUCCESS = 버튼 자리 결과 · PARTIAL = 1차 비활성 + 이유 · 인쇄 비활성 + 이유

### P1. 확인증 인쇄물 `/print/certs/[id]` — `SYSTEM.md` §6-6 · `print-cert.html`

- 템플릿은 `print-cert.html` 그대로(A4 세로 · 여백 22/22/20mm · 색 토큰 셋 `--print-ink` `--print-rule` `--print-line` · 세로선 없음 · 수령자 서명 64mm). **새 줄·새 블록을 더하지 않고 값만 채운다**
- **화면 미리보기 틀은 실물을 옮기지 않는다:** 실물 15행의 `@media screen{body{background:#E9ECEA} .sheet{outline:1px solid #CFD3D0}}`은 실물 보기용 리터럴이라 앱에 옮기지 않는다(D-20 리터럴 금지). 앱의 인쇄 라우트 화면 바탕은 `--surface`, 종이 외곽은 `1px solid var(--line)`(개정 ⑬). 인쇄 미디어에서는 tokens.css가 둘을 흰색·검정으로 접고 외곽은 그리지 않는다
- 이 페이즈가 채우는 칸: 확인증 번호 · 항목(행사 이름 + 2행 당첨일) · 소득 종류(`기타소득`) · 경품 · 수령자 표 전부(이름 · 주민등록번호 마스킹 · 주소(현장이면 `—`) · 연락처 · 계좌 `—`) · 수령자 이름 · 제출 일시 · 서명 이미지 · 출력 시각 · 바닥줄
- Phase 11이 채우는 칸(이 페이즈는 `—`): 지출결의 번호(부제 `지출결의 —`) · 프로젝트 · 지급일 · 금액 블록 세 값 · 지급자 줄의 지급일. 원천징수 내역 2행 · 한글 금액 줄은 렌더하지 않는다(§2-4 「있는데 값이 없을 때만 `—`」 — 파생 줄은 「있는」 칸이 아니다)
- 주민등록번호는 인쇄물에서도 `930412-2******`(D-1108). 인쇄 라우트는 복호화하지 않는다(마스킹 값만 서버에서 만든다 — `mask_reveal` 기록 대상 아님)
- **서명 이미지 색:** PNG는 바탕 투명 + `--fg` 획이다(E4). 인쇄 라우트는 `<img>`에 `filter: brightness(0)`을 걸어 불투명한 모든 픽셀을 검정(= `--print-ink` 값 `#000000`)으로 찍는다 — CSS 색 토큰 교체는 PNG 픽셀에 닿지 않기 때문이다. 새 색 없음(개정 ⑬)
- **서명은 필수 이미지다 — 없으면 인쇄하지 않는다:** 자동 `window.print()`는 서명 `<img>`의 `decode()`가 성공한 뒤에만 부른다. 불러오기 실패(`decode()` 거부 · `onerror`)면 인쇄하지 않고 ERROR `인쇄물을 만들지 못했습니다 · 다시 시도`(§7-7 확정 문장, 2차 「다시 시도」 = 라우트 다시 불러오기). 서명 없는 확인증 종이가 나가지 않는다
- 경영관리만 연다(권한 없으면 404 · 플래그 꺼짐이면 404). 다섯 상태는 §7-7 인쇄 라우트 행 그대로(LOADING 빈 A4 + 진행 바 · ERROR 화면 한 줄(서명 실패 포함) · SUCCESS 자동 `window.print()` · EMPTY 해당 없음 · PARTIAL 해당 없음 — 첨부가 없는 문서이고, 서명 누락은 PARTIAL이 아니라 ERROR다)
