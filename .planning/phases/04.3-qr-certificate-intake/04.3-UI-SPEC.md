**이 페이즈의 디자인 원칙 셋**
1. **새 토큰 0개.** 색·서체·radius·그림자·간격 토큰을 만들지 않는다(`git diff docs/design/tokens.css` 0줄). 전부 `tokens.css` 변수로 그린다.
2. **새 템플릿 0개.** 외부 흐름은 §6-5, 내부 목록은 §6-1, 내부 상세는 §6-2, 정정은 §6-3, 인쇄는 §6-6, 진입은 §6-10에서 시작한다. §6-5에 앞 단계 둘(이름 고르기 · 전화번호 확인)을 붙이는 것은 **SYSTEM 개정**이며 화면 예외가 아니다 — 개정 목록은 「SYSTEM.md · DECISIONS.md 개정 목록」 절에 있고, **이 문서는 `docs/design/*`를 고치지 않는다.** 계획이 그 목록을 실행 태스크(첫 웨이브)로 만든다(`DESIGN.md` §4 규칙 1·6).
3. **수령자에게는 무엇을 받는지만 보인다(D-1101).** 수령자 화면 어디에도 `원천징수` `지급명세서`라는 낱말, 시가 · 세금 · 지급액 · 계좌가 없다. 이 규칙을 지키려고 현재 §6-5의 동의 요약 문장(「기타소득 **원천징수** 신고와 경품 전달」)을 고친다(개정 ①-g) — 현재 SYSTEM·실물이 이 규칙을 어기고 있어 발견 즉시 개정 대상에 넣었다.

## Typography

`SYSTEM.md` §2 그대로. 한 화면 크기 4단계 이하. 굵기는 **SYSTEM §2-1이 잠근 세 단계(400 · 600 · 700)** 를 그대로 쓴다 — 「굵기 2개」 기본값보다 시스템이 우선한다(CLAUDE.md: 새 서체 규칙 금지, 시스템을 벗어나려면 DECISIONS가 먼저). 800은 워드마크에만.

§8 카피 규칙 그대로: 버튼 = 실제 동작, 결과 = 버튼과 같은 단어, 오류 = 원인 · 다음 행동, 사과·느낌표 없음, 안내 문구 없음. **외부 수령자 화면과 오류의 「다음 행동」만 `~해 주세요`체.** `{…}`는 서버 값이고, 예시 값은 실물의 값을 쓴다. 담당자 표기 `{담당자}` = 행사를 만든 사람 이름(예: `박서연`).

### E. 외부 수령자 흐름 — `SYSTEM.md` §6-5 (개정 ①)

한 라우트, 단계 넷: **E2 이름 고르기 → E3 전화번호 확인 → E4 입력(§6-5 폼) → E5 제출됨.** 닫힌 상태 E6은 어느 단계 대신에도 선다. 상단 바 · 제목 · 부제(E1)는 E6-c를 뺀 모든 단계에서 같다.

**E1 공통**
- 폰 전용 한 열, `main` 최대 폭 480(실물값), PC에서도 왼쪽 정렬 480 한 열로 선다. 셸 없음(상단 바만, 하단 탭 · 메뉴 · 사용자 없음). `<main>` 랜드마크 하나, `<header>`는 상단 바
- 본문 `--fs-md`, 입력·1차 48, `~해 주세요`체(§6-5 · §8-6)
- LOADING: 상단 바 아래 2px `--accent` 진행 바만, 글자 없음(§7-7 확정). 300ms 안에 끝나면 보이지 않는다. 버튼은 §7-1 진행 중(라벨 뒤 `…`, 다른 버튼 비활성)

**E2 이름 고르기**
- 목록 = 그 행사에 등록된 당첨자 **전부**, 한 목록, 페이지 나눔·검색 없음. 순서 = 서버가 **실제 이름의 가나다순**으로 정렬한 뒤 가린다(같으면 등록 순서). 제출한 사람도 같은 모양으로 남는다 — 제출 여부를 목록에서 드러내지 않는다(누가 냈는지 목록만 보고 알 수 없게)
- **이름 가림 규칙(서버에서만, 클라이언트는 실제 이름을 받지 않는다):** 공백을 뺀 글자 수 n으로 — n=1 → `*` · n=2 → 첫 글자 + `*`(`김*`) · n≥3 → 첫 글자 + `*`×(n−2) + 끝 글자(`김*늘` · `남**수` · `J********h`). 공백은 자리를 지킨 채 그대로 둔다. 목록 DTO에는 가린 이름 + 추측 불가능한 행 식별자만 있다(순번 id 금지 — 누수 스캔 대상)
- **겹침 규칙:** 가린 이름이 같은 행이 둘 이상이면 그 행들만 2행에 `{경품명} {수량}개`를 보인다. 겹치지 않는 행은 한 줄
- 행 = `<li><button>` 전폭, 최소 높이 48, 좌우 패딩 0(메인 패딩 안), 아래 `1px --line`, 첫 행 위는 라벨 아래 여백 `--s-2`. hover·active `--surface`. `:focus-visible`는 기본 바깥 링(행이 메인 패딩 안에 있어 링을 그릴 여백이 있다 — §4-4 inset 예외에 넣지 않는다)
- 행을 누르면 곧바로 E3. 확인 버튼 없음. 이 단계에 1차 버튼이 없다(0개 — §7-1 「1개」 상한 안)
- **행 누름 = 서버 왕복(`selectWinner`).** 기다리는 동안 누른 행 오른쪽 끝에 `…`(§7-1 진행 중과 같은 표기) + 목록 전체 비활성(두 번 누름 방지), 300ms 넘으면 E1 진행 바. 응답에 따라: 보통 → E3 · 잠긴 자리 → E3 잠김 상태 · 링크 닫힘 → **E6-b**(서버가 준 사유) · 네트워크/서버 실패 → E2에 남고 목록 라벨 아래 한 줄 `이름을 불러오지 못했습니다 · 잠시 뒤 다시 골라 주세요`(`--fs-sm --danger`, `role="alert"`), 목록은 다시 살아나고 포커스는 누른 행에 남는다. 이 줄은 다음 행 누름에서 지워진다
- EMPTY: **해당 없음** — 당첨자가 0명인 행사는 만들 수 없다(I2 1차 막힘). 모두 제출하면 E6-b

**E3 전화번호 확인**
- 고른 이름은 가린 이름 그대로 `--fs-lg` 700. 오른쪽 3차 「다른 이름 고르기」 → E2, 포커스는 방금 고른 행
- 입력: `TextField size="external"`, `inputmode="numeric"` · `autocomplete="off"` · `maxlength=4`, 숫자 아닌 글자는 입력 중 지운다. 폼은 `noValidate`(§7-15)
- 1차 「전화번호 확인」: 숫자 4개가 아니면 비활성 + 이유(§7-1). 누르면 진행 중 `전화번호 확인…`
- **틀림:** 칸 `--danger` 테두리 + `aria-invalid` + 아래 한 줄(남은 횟수 포함). 입력값은 지운다(4자리 재입력이 자연스럽고, 틀린 값을 남길 이유가 없다) — §7-2 「입력값은 지우지 않는다」의 예외가 아니라 비밀 값 재입력이라 개정 ①-b가 §6-5에 적는다
- **잠김(서버가 판정, 당첨자 자리 단위 — IP 아님):** 입력 비활성 · 1차 비활성, 제출 줄 이유 `{한도}번 틀려 확인이 잠겼습니다 · {18:45}부터 다시 해 주세요`(`{한도}` = 확인증 탭 설정의 틀림 한도, 시각 = 서버가 준 잠금 해제 시각 `HH:mm` — 둘 다 서버 값, 클라이언트에 5·3을 박지 않는다). 카운트다운을 그리지 않는다(§5 모션). 클라이언트 타이머가 그 시각에 1차를 다시 살린다(서버가 여전히 판정). 잠긴 자리를 E2에서 다시 고르면 E3가 곧바로 잠김 상태로 선다
- **맞음:** E4로. 이미 제출한 자리면 E4 대신 **E6-a**
- **링크 닫힘(`verifyLast4` 응답):** 확인 중에 기한이 지났거나 · 모두 제출했거나 · 담당자가 닫았으면 화면 전체가 **E6-b**(서버가 준 사유)로 바뀐다. 적은 4자리는 버린다. 틀림 횟수를 세지 않는다
- **확인 실패(네트워크·서버):** 제출 줄 이유 자리에 `확인하지 못했습니다 · 잠시 뒤 다시 눌러 주세요`(`--danger`, `aria-describedby`로 1차에 연결). 1차는 살아 있고 적은 4자리는 남는다 — 틀림이 아니므로 칸 테두리를 붉히지 않고 남은 횟수도 줄지 않는다. 4자리를 고치거나 1차를 다시 누르면 이 줄은 원래 막힘 이유 자리로 돌아간다
- 확인 상태는 페이지 메모리에만 있다. 새로 고침 → E2부터(주민등록번호 등 입력값은 어디에도 저장하지 않는다 — `localStorage`·`sessionStorage` 금지). 서버 확인 증표의 형식·유효 시간은 계획·설계 `/cso` 몫
- **뒤로 가기:** 단계마다 같은 경로로 `history.pushState` 한 번. 브라우저 뒤로 = 앞 단계(E4 → E2 — 확인을 버리고 이름부터. E3 → E2). URL은 바뀌지 않는다(토큰 외 정보를 URL에 두지 않는다)

**E4 입력 — §6-5 폼 그대로 + 아래만 확정**
- **이름 칸은 비워 둔다(등록 이름을 미리 채우지 않는다) — Claude 재량 결정.** 이유: ① 뒤 4자리 확인은 10,000가지뿐이라 약한 확인이다 — 확인을 통과한 뒤에도 목록이 이미 보인 것(가린 이름) 이상의 개인정보를 화면에 내지 않는다(DECISIONS 9/18 #6 「링크가 남에게 넘어갔을 때 주민등록번호가 보이면 안 된다」와 같은 원칙). ② 세무 서류의 이름은 수령자 본인이 적은 법적 이름이어야 하고, 등록 이름은 담당자가 적은 별칭·오타일 수 있다. ③ 비용은 세 글자 타이핑. 등록 이름과 다르면 I4가 `등록 이름 …` 힌트로 경영관리에게 보인다. **연락처도 같은 이유로 비워 둔다.** → 설계 `/cso`가 다시 볼 수 있는 가정(A3)
- 경품 블록: `{경품명} {수량}개` 한 줄, 등록된 값(§6-5 확정). 전달 방법은 **그 당첨자에게 등록된 값**이 정한다(현장 기본 / 택배면 주소 칸). 수령자가 고르는 선택지는 없다
- 주민등록번호: 앞 6(`inputmode=numeric`, maxlength 6) - 뒤 7(`type=password`, `inputmode=numeric`, maxlength 7). 앞 6자리를 채우면 포커스가 뒤로 넘어간다. 검사는 서버만(형식 · 실제 날짜 · 성별 코드 · 2020-10 이전 발급분 검증번호, §6-5 확정). 오류는 두 칸 모두 `--danger` 테두리
- 동의: 서명 바로 위, 위아래 1px `--line`으로 묶은 체크박스(20×20, 클릭 영역은 라벨 전체 — 44 확보) + 라벨 `--fs-md`(개정 ①-j — 실물의 `--fs-base`를 쓰지 않는다) + 요약 `--fs-sm` + 3차 「전문 보기」

- 폰: QR 160 그대로, 링크 줄 · 「링크 복사」 아래, 당첨자 표는 칸 접기 — P1 이름 · 수량 · 제출, P2 접힌 줄 `010-4821-7730 · 갤럭시 탭 S10 · 현장`. 셀 편집 없음, 행 탭 → `RowSheet`(보기 전용, 「제출 내용」은 경영관리에게만 시트 본문 아래 3차로). 「링크 닫기」는 폰에서도 2차(시트 확인)
- 다섯 상태: LOADING = 표 뼈대 · EMPTY = 해당 없음(당첨자 ≥1명으로만 만들어진다) · ERROR = 조회 실패 `행사를 불러오지 못했습니다 · 다시 시도` / 저장 실패 §7-3 · SUCCESS = 합계 행 `저장됨 N줄` / 링크 닫기 토스트 · PARTIAL = 오류 셀 고정 + `오류 N칸 · 전부 거부`

### I4. 확인증 확인·정정 `/certs/submissions/[id]` — `SYSTEM.md` §6-3 · §7-15 (경영관리 전용)

```
│ 기타소득 확인증 — 김하늘 [제출됨]                                   [인쇄] │ ← 머리 줄도 720
│ CERT-2026-0031 · 아이오닉9 쇼케이스 현장 SNS 이벤트 · 2026-09-20 18:42 제출      │
╞══════════════════════════════════════════════╡
│ 이름         [김하늘                         ] (480)                      │
│ 주민등록번호  930412-2******   전체 보기                                   │ ← 기본: 텍스트 + 3차

├──────────────────────────────────────────────┤

╞══════════════════════════════════════════════╡
```

- 진입: I3 제출된 줄의 3차 「제출 내용」. 이 화면·「전체 보기」·「인쇄」는 서버가 경영관리에게만 연다(대표 불가, 260907). 권한 없는 사람은 §6-9 404(D-17)
- 폼(`Form`, 한 열 720, 라벨 96): 이름(480) · 연락처(280) · 주소(480, 그 당첨자가 택배일 때만)는 입력 칸에 제출값이 채워져 곧바로 고칠 수 있다. 이름 아래 `Form.Hint` `등록 이름 {등록 이름}` — 제출 이름과 등록 이름이 다를 때만
- **주민등록번호(D-1106 · CERT-02):**
  - 기본 = 텍스트 `930412-2******`(앞 6 + 성별 1자리 + `*` 6개 — §6-6 실물과 같은 형식, 개정 ⑥이 §2-4에 올린다) + 3차 「전체 보기」. 전체 보기 권한이 없으면 서버가 3차를 보내지 않는다
  - 「전체 보기」 → 서버가 **기록 먼저, 복호화 나중**(`mask_reveal`, vendors 선례) → 값이 `TextField`(280, `000000-0000000`, `.num`)로 바뀌어 고칠 수 있게 되고 옆 3차 「가리기」. 「가리기」는 클라이언트 상태만 되돌린다(서버 재호출 없음 — 누를 때마다 기록이 쌓이지 않게, `account-number.tsx` 선례)
  - **고치던 주민등록번호가 있으면(dirty) 「가리기」를 렌더하지 않는다** — 저장하거나 페이지를 떠나야 가려진다. 저장에 성공하면 칸은 곧바로 새 값의 마스킹 텍스트로 돌아간다(평문이 화면에 남는 시간을 줄인다)
  - 전체 보기 없이 주민등록번호를 고칠 길은 없다(입력 칸이 전체 보기 뒤에만 생긴다 — D-1106 「고치려면 전체 보기 권한」이 화면 구조로 성립)
  - 검사는 외부와 같은 서버 규칙. 오류 문장은 명사형(Copywriting I4)
- 읽기 전용(`KvList`): 경품(`{경품명} {수량}개 · 현장 수령|택배`) · 동의(`동의함 · 일시`) · 서명(서버가 권한 확인 뒤 내려주는 이미지, CSS `width: 320px; aspect-ratio: 520 / 200; object-fit: contain` — 높이 리터럴 123을 CSS에 쓰지 않는다. 폰은 `width: 100%` 같은 비율, `1px --line` 테두리 없이 아래 1px `--line`, `alt="{제출 이름} 서명"`) + `수령자 서명 · 고칠 수 없음`. 서명에는 어떤 컨트롤도 없다(D-1106)
- `Form.Actions`: 1차 「고친 내용 저장」 — 바뀐 칸이 없으면 비활성 + 이유. 성공 → 버튼 자리 결과 텍스트(바뀐 칸 이름 나열, `--success`), 입력은 새 값을 기준으로 **계속 고칠 수 있다**(정정 화면은 한 번 제출하고 끝나는 폼이 아니다 — 개정 ⑧이 §7-15 SUCCESS에 「정정 폼」 한 줄을 더한다), 토스트 없음(화면 이동이 없다). 실패 → 버튼 옆 이유 + 칸 아래 `Form.Error`, 값 유지
- 행동 로그(누가 · 언제 · 어느 칸)는 서버가 남기고 **이 화면에 이력 목록을 그리지 않는다**(요청 범위 밖 — 기존 「행동 로그」 관리자 화면에서 본다). 주민등록번호 평문은 로그에 없다(D-1106)
- 머리 2차 「인쇄」 → 새 탭 `/print/certs/[id]`(§6-6 「화면에서 인쇄는 2차, 새 탭 + 자동 `window.print()`」)
- 세션: 경영관리(개인정보취급자)는 비활동 2시간 만료. 만료 뒤 행동하면 §6-9 세션 만료 화면(→ 로그인). 이 화면에 남은 시간 표시·경고 배너를 두지 않는다
- 폰(<700): 라벨이 위로, 칸 전폭, 서명 이미지 전폭(비율 유지). 1차는 §6-3 폰 규칙(하단 탭 위 고정 제출 줄)
- 다섯 상태: LOADING = 해당 없음(서버 렌더) · EMPTY = 해당 없음 · ERROR = `Form.Error` + 이유 · 전체 보기 실패 한 줄 · SUCCESS = 버튼 자리 결과 · PARTIAL = 1차 비활성 + 이유
