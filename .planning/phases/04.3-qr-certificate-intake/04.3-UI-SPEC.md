## Typography

`SYSTEM.md` §2 그대로. 한 화면 크기 4단계 이하. 굵기는 **SYSTEM §2-1이 잠근 세 단계(400 · 600 · 700)** 를 그대로 쓴다 — 「굵기 2개」 기본값보다 시스템이 우선한다(CLAUDE.md: 새 서체 규칙 금지, 시스템을 벗어나려면 DECISIONS가 먼저). 800은 워드마크에만.

**외부 수령자 화면(E1~E6) — 4단계: 12 · 15 · 18 · 24.** §10 「산문·외부 수령자 화면은 15px 이상」에 따라 **읽고 판단하거나 복구해야 하는 문장은 전부 15**이고, 12는 이름표 구실만 한다(개정 ①-k).

| Role | Size | Weight | Line Height | 쓰는 곳 |
|------|------|--------|-------------|---------|
| Label / 부제 | 12px `--fs-sm` | 600(라벨) · 400(부제) | 1.5 | 칸 라벨(한두 낱말 이름표) · 부제(행사 이름 · 당첨일) · E2 겹침 2행(`{경품명} {수량}개 · {구별 표시}` — 낱말 나열이지 문장이 아니다) · 서명 칸 자리표시 `여기에 서명`(서술어 없는 이름표, `--faint`) · 동의 블록 안 3차 「전문 보기/접기」와 서명 칸 3차 「다시 쓰기」(실물 `.consent .b3` · `.b3.sm`). **이 줄에 문장은 없다** |
| Body / 입력 / 문장 | 15px `--fs-md` | 400 · 1차 버튼 600 · E2 목록 머리 600 | 1.6 | 본문 · 입력 값 · 이름 목록 행 · 1차 버튼 · 3차 「다른 이름 고르기」 · 전화 링크 · **동의 체크박스 라벨**(개정 ①-j: 실물 58행 `--fs-base` 14 → 15) · **모든 문장**(개정 ①-k): E2 목록 머리 `이름을 골라 주세요 · 12명`(`--muted` 600) · 주소 칸 부제 `택배로 보내 드립니다`(`--muted`, 개정 ①-h: 실물 `--fs-xs` → `--fs-md`) · 칸 오류 · 제출 줄 이유·오류 · E2 목록 오류 줄 · E2 문의 줄 · E3 상태 줄 · E4 경품 아래 문의 줄 · 서명 키 안내 줄 · 동의 요약 · 전문 · 결과 블록(E1 오류 · E5 · E6)의 모든 줄 |

| Heading | 24px `--fs-xl` | 700 | 1.3 | 화면 제목 「기타소득 지급 확인」(§6-5 확정) |

크기 목록은 **닫혀 있다** — E1~E6에 이 네 값 밖의 `font-size`가 있으면 결함이다. 현재 실물에는 넷 밖의 값이 둘 있고(`.lbl-sub` `--fs-xs` 11 · `.consent label` `--fs-base` 14) 개정 ①-h(→ `--fs-md`) · ①-j가 둘 다 지운다. 개정 ①-k는 실물 `.ferr` `.blocked` `.consent small` `.state .who`와 E2 목록 머리를 `--fs-sm` → `--fs-md`로 올린다(크기 수는 그대로 넷). 판정 기준: **서술어로 끝나는 줄(`~니다` · `~주세요` · `~습니다`)은 전부 15**, 12는 서술어 없는 이름표·낱말 나열만. 셋 다 SYSTEM §6-5 「이 화면만 `--fs-md` 본문」 · §10 규칙을 실물이 어긴 자리라 화면 예외가 아니라 실물 수정이다. 실행 확인: 개정 뒤 `grep -o "font-size:var(--fs-[a-z]*)" docs/design/system/external-cert.html | sort -u`가 `--fs-sm` `--fs-md` `--fs-lg` `--fs-xl` 넷만 돌려준다(상단 바 `.bar`의 `--fs-sm`·워드마크 `--fs-md` 포함)

**인쇄물(P1)** — `print-cert.html` 실물(§6-6 확정 템플릿)의 크기를 **그대로** 쓴다(11 · 12 · 14 · 15 워드마크 · 24). 이 페이즈가 정한 값이 아니라 잠긴 템플릿이며, 칸 값만 채운다.

## Copywriting Contract

§8 카피 규칙 그대로: 버튼 = 실제 동작, 결과 = 버튼과 같은 단어, 오류 = 원인 · 다음 행동, 사과·느낌표 없음, 안내 문구 없음. **외부 수령자 화면과 오류의 「다음 행동」만 `~해 주세요`체.** `{…}`는 서버 값이고, 예시 값은 실물의 값을 쓴다. 담당자 표기 `{담당자}` = 행사를 만든 사람 이름(예: `박서연`). **`{문의 전화}`** = **그 행사에 저장된 번호**(행사별 사본)이고 외부 화면에서 `<a href="tel:{숫자만}">{하이픈 표시값}</a>` 3차 링크로 그린다(예 표시 `02-1234-5678` · `tel:0212345678`). 행사를 만드는 순간 서버가 확인증 탭 설정 `수령자 문의 전화`(새 설정 키 — 가정 A12)의 값을 행사에 복사하고, 그 행사의 E2~E6-b는 언제나 이 사본만 읽는다. 설정은 **새로 만드는 행사**에만 쓰인다 — 설정을 바꾸거나 비워도 이미 만든 행사(접수 중이든 닫혔든)의 번호는 그대로다. **그래서 행사가 있는 외부 화면에는 언제나 유효한 번호가 있다:** 서버가 형식을 검사해 정규화한 값만 설정에 저장하고, 설정이 비어 있으면 행사를 만들 수 없다(I2 1차 막힘). 번호 없는 대체 문장은 두지 않는다. 행사를 모르는 두 화면(E1 첫 진입 실패 · E6-c)만 번호가 없다.

## 화면 계약

라우트 이름은 가칭이고 계획이 확정한다: 외부 `/c/[token]` · 내부 `/certs/events`(목록 · `?new=1` 만들기) · `/certs/events/[id]`(상세) · `/certs/submissions/[id]`(정정) · `/print/certs/[id]`(인쇄).

**기능 플래그(`cert.enabled` 류 설정 키, 환경마다 값이 다르다 — 프로덕션 꺼짐(Phase 11까지, CONTEXT 「이미 확정된 입력」 기능 플래그 줄) · 개발·검증 켜짐):**
- **꺼짐:** 외부 `/c/[token]` → E6-c(HTTP 404). 내부 `/certs/events`(`?new=1` 포함) · `/certs/events/[id]` · `/certs/submissions/[id]` → §6-9 404(셸 안). **인쇄 `/print/certs/[id]` → 404**(셸 없는 라우트라 §6-9 404 문구를 인쇄 라우트 바탕에). 이 화면들의 서버 액션은 전부 거부된다. 「관리」 인덱스의 `확인증` 그룹은 렌더하지 않는다
- **켜짐:** 「관리」 인덱스 `확인증` → `확인증 행사`(I1)가 행사 만들기의 유일한 진입점이다. CONTEXT 13행의 「플래그가 꺼진 동안의 임시 진입점」은 Phase 11 전 기간(= 프로덕션 플래그가 꺼져 있는 기간)을 가리키고, 그 기간에 이 화면은 플래그가 켜진 환경(개발·검증)에서만 열린다. Phase 11이 진입점을 경품 지출결의 화면으로 옮긴 뒤 프로덕션 플래그를 켠다
- 켜짐/꺼짐으로 화면이 달라지는 곳은 위의 셋(외부 라우트 · 내부·인쇄 라우트 넷 · 인덱스 그룹)뿐이다

- LOADING: 상단 바 아래 2px `--accent` 진행 바만, 글자 없음(§7-7 확정). 300ms 안에 끝나면 보이지 않는다. 버튼은 §7-1 진행 중(라벨 뒤 `…` + `.sr-only` `처리 중`, 다른 버튼 비활성). 첫 진입은 서버 렌더라 진행 바가 없다(브라우저가 페이지를 받는 중)
- **첫 진입 실패(ERROR):** 서버가 토큰 조회 중 5xx로 실패하면(라우트 `error.tsx`) 상단 바 + 제목(부제 없음 — 행사를 모른다) + 결과 블록 `확인증 화면을 불러오지 못했습니다 · 잠시 뒤 다시 시도해 주세요` + 3차 「다시 시도」(`location.reload()` — 같은 URL). 포커스 = 결과 블록 첫 줄(`tabindex=-1`), `document.title` `오류 · 기타소득 지급 확인`. 1차 없음. **E6-c(404)와 섞지 않는다** — 404는 토큰이 없다는 판정이고 5xx는 판정을 못 한 것이다. 네트워크가 아예 끊겨 응답이 없으면 브라우저 자체 오류 화면이라 이 앱이 그리지 않는다
- **서버 왕복 공통(E2 `selectWinner` · E3 `verifyLast4` · E4 제출):** 응답은 둘로만 가른다. **확정 판정** = 서버가 업무 판정을 담아 돌려준 응답 — 틀림(1회 셈) · 맞음 · 이미 제출 · 제출 저장 · 잠김 · 링크 닫힘 · 확인 시간 지남 · 칸 오류(next-safe-action `validationErrors`). **결과 불명** = 그 밖 전부 — 연결 끊김 · 20초 안에 응답 없음 · 5xx · next-safe-action `serverError`(처리 중 예외) · 해석할 수 없는 응답. 결과 불명은 「처리되지 않음」이 아니라 「결과를 모름」이다
- **멱등 키(E3·E4) — 규칙은 하나다: 키는 확정 판정을 받을 때만 끝난다.**
  - 키는 **시도** 단위다. 1차를 누를 때 직전 요청이 **결과 불명**으로 끝났고 입력이 그대로면 직전 키를 다시 쓴다(재전송). 직전 요청이 **확정 판정**을 받았으면(위 여덟 가지 중 무엇이든) 그 키는 끝났고 다음 누름은 새 키다. 입력을 바꾸면 결과 불명 뒤라도 새 키다(다른 시도). 잠금 풀림 · E3 재통과 뒤의 누름이 새 키인 것은 이 규칙의 결과다(잠김 · 확인 시간 지남도 확정 판정이다). E3 · E4의 결과 불명 문단은 이 규칙을 따를 뿐 따로 정하지 않는다
  - 서버는 **상태를 바꾼 결과만** 키에 묶어 둔다: 틀림 1회 셈 · 맞음(확인 증표, 원래 만료 시각 그대로) · 제출 저장. 같은 키가 다시 오면 그 결과를 돌려주고 다시 세거나 저장하지 않는다 — 셈·저장을 마친 뒤 5xx가 나가도 재전송이 두 번 세거나 「이미 제출」로 빠지지 않고 원래 결과를 받는다. **상태를 바꾸지 않은 판정**(잠김 · 링크 닫힘 · 확인 시간 지남 · 칸 오류)은 묶어 두지 않고 같은 키라도 **지금 다시 판정**한다 — 잠금이 풀린 뒤의 재전송이 옛 「잠김」에 갇히지 않고, 재확인 뒤의 제출이 옛 「확인 시간 지남」을 받지 않는다
  - 잠김 응답의 해제 시각은 서버가 가진 **절대 시각**(잠금이 걸린 순간 + 잠금 시간)이고 남은 초는 응답을 만드는 순간에 계산한다 — 재전송·재판정으로 잠금이 늘어나지 않는다
  - 키 형식·보관 시간은 설계 `/cso` 몫
- **포커스 이동:** E2 → E3 = 뒤 4자리 칸 · E3 → E4 = 경품 블록(`tabindex=-1`, 라벨 「경품」과 값이 읽힌다) · E3·E4 → E2 = 방금 고른 행 · E5·E6 = 결과 블록 첫 줄(`tabindex=-1`). 단계가 바뀔 때 `document.title`도 `{단계} · 기타소득 지급 확인`(예 `전화번호 확인 · 기타소득 지급 확인`)으로 바꾼다

**E2 이름 고르기**
- 목록 = 그 행사에 등록된 당첨자 **전부**, 한 목록, 페이지 나눔·검색 없음. 순서 = 서버가 **실제 이름의 가나다순**으로 정렬한 뒤 가린다(같으면 등록 순서). 제출한 사람도 같은 모양으로 남는다 — 제출 여부를 목록에서 드러내지 않는다(누가 냈는지 목록만 보고 알 수 없게). 행을 고르는 것만으로는 제출 여부가 드러나지 않는다 — E6-a는 전화번호 확인을 통과한 뒤에만 선다(E3)
- **이름 가림 규칙(외부 화면에는 서버가 가린 값만 — 외부 클라이언트는 실제 이름을 받지 않는다. 내부 I2·I3 미리 보기는 같은 규칙 함수를 쓴다):** 공백을 뺀 글자 수 n으로 — n=1 → `*` · n=2 → 첫 글자 + `*`(`김*`) · n≥3 → 첫 글자 + `*`×(n−2) + 끝 글자(`김*늘` · `남**수` · `J********h`). 공백은 자리를 지킨 채 그대로 둔다. 목록 DTO에는 가린 이름 + 추측 불가능한 행 식별자만 있다(순번 id 금지 — 누수 스캔 대상)
- **한 행 = 한 사람.** 행을 묶지 않는다(1차 개정의 「묶음 규칙」은 2차에서 없앴다 — 한 사람의 오입력이 남의 자리를 확정하거나 여러 사람을 함께 잠그기 때문, Codex 2차 #1·#4)
- **2행 규칙(서버가 한 번에 계산):** 행의 2행은 ⓐ 가린 이름이 다른 행과 같거나 ⓑ 그 당첨자에게 구별 표시가 있으면 보이고, 내용은 `{경품명} {수량}개`에 구별 표시가 있으면 ` · {구별 표시}`를 붙인다. ⓐ·ⓑ 어느 것도 아니면 한 줄. 2행이 있는 행은 **언제나** 2행을 보인다(상태에 따라 사라지지 않는다)
- **모양 유일성(등록 때 보장):** 한 행사 안에서 행의 모양(가린 이름 + 2행)은 서로 다르다. 서버가 I2 만들기 · I3 일괄 저장 때마다 저장될 모든 당첨자의 모양을 위 규칙으로 계산해, 같은 모양이 둘 이상이면 **저장을 거부**하고 편집 가능한 그 줄들의 `구별 표시` 칸을 오류 셀로 고정한다(Copywriting I2 「수령자 화면 모양 중복」). 담당자가 서로 다른 구별 표시(개인정보가 아닌 짧은 글, 예 `오전 조` · `3시 추첨`)를 적어야 저장된다. 그래서 수령자 화면에 같은 모양의 행은 생기지 않는다
- **구별 표시는 공개 값이다 — 개인정보 통로가 되지 않게 셋을 건다(I2 「구별 표시 제한」):** ① 서버 거부 — 10자 초과 · 숫자가 3개 이상 이어짐(공백·하이픈·점을 끼워도 이어진 것으로 본다 — 전화번호 조각) · 그 행사에 등록된 당첨자 이름(공백 뺀 전체)이 들어 있음 ② 편집 표 위 상시 힌트 `구별 표시는 수령자 목록에 그대로 보입니다 · 이름·전화번호는 쓰지 마세요`(오류 때만이 아니라 늘) ③ 편집 표의 `수령자 화면` 계산 열이 E2 행 모양을 그대로 미리 보인다 — 담당자가 QR 보유자에게 보일 글을 저장 전에 본다. 서버 거부가 못 잡는 글(별명 · 이름 일부 등)은 ②·③이 막고, 남는 위험은 설계 `/cso`가 본다(A11)
- 행 = `<li><button>` 전폭, 최소 높이 48, 좌우 패딩 0(메인 패딩 안), 아래 `1px --line`, 첫 행 위는 라벨 아래 여백 `--s-2`. hover·active `--surface`. `:focus-visible`는 기본 바깥 링(행이 메인 패딩 안에 있어 링을 그릴 여백이 있다 — §4-4 inset 예외에 넣지 않는다)
- 행을 누르면 곧바로 E3. 확인 버튼 없음. 이 단계에 1차 버튼이 없다(0개 — §7-1 「1개」 상한 안)
- **행 누름 = 서버 왕복(`selectWinner`).** 기다리는 동안 누른 행 오른쪽 끝에 `…`(§7-1 진행 중과 같은 표기) + 목록 전체 비활성(두 번 누름 방지), 300ms 넘으면 E1 진행 바. 응답에 따라: 보통 → E3 · 잠긴 자리 → E3 잠김 상태 · 링크 닫힘 → **E6-b**(서버가 준 사유) · 네트워크/서버 실패·응답 없음 → E2에 남고 목록 라벨 아래 한 줄 `이름을 불러오지 못했습니다 · 잠시 뒤 다시 골라 주세요`(`--fs-md --danger`, `role="alert"`), 목록은 다시 살아나고 포커스는 누른 행에 남는다. 이 줄은 다음 행 누름에서 지워진다(고르기는 읽기라 다시 눌러도 세는 것이 없다)
- **문의 줄(개정 ①-l):** 목록 아래 `--s-4` 띄워 한 줄 `목록에 이름이 없으면 PLANT8 경영관리 {문의 전화}에 전화해 주세요`(`--fs-md --muted`, 번호는 `tel:` 3차). 「이름이 목록에 없다」는 막힌 상태의 다음 한 수라 §8-5 안내 문구가 아니다(§11 브리프 1). `{문의 전화}`는 행사별 사본이라 늘 있다(Copywriting 머리말)
- EMPTY: **해당 없음** — 당첨자가 0명인 행사는 만들 수 없다(I2 1차 막힘). 모두 제출하면 E6-b

**E3 전화번호 확인**
- 고른 이름은 가린 이름 그대로 `--fs-lg` 700. 오른쪽 3차 「다른 이름 고르기」 → E2, 포커스는 방금 고른 행. **이 이동은 `history.back()`으로 한다**(E3 항목을 걷어 내고 E2 항목으로 돌아간다 — `popstate` 처리가 E2를 그린다). `pushState`로 E2를 새로 쌓지 않으므로 「기록 항목은 둘뿐」이 그대로다
- 입력: `TextField size="external"`, `inputmode="numeric"` · `autocomplete="off"` · `maxlength=4`, 숫자 아닌 글자는 입력 중 지운다. 폼은 `noValidate`(§7-15). 진입 시 포커스는 이 칸
- 1차 「전화번호 확인」(`Button size="external"`): 숫자 4개가 아니면 비활성 + 이유(§7-1, 개정 ⑦ (b)로 `aria-describedby` 연결). 누르면 진행 중 `전화번호 확인…`. 버튼이 살아 있을 때 이유 자리에 오는 문장(결과 불명)은 화면이 직접 그린 `<p id>` 줄이고 버튼 `aria-describedby`에 그 id를 준다 — 같은 자리(버튼 아래). **링크가 든 줄(잠김 2행)도 같은 방식이다:** `disabledReason`(문자열)은 1행만 받고, 2행은 화면이 Button 바로 뒤(`.wrapExternal` 아래, 같은 세로 흐름)에 그린 `<p id>`이며 호출부 `aria-describedby`로 넘겨 개정 ⑦ (b)가 자기 id와 합친다. Button API 변경 없음
- **서버 판정 = 그 행의 한 사람과만 대조:** 맞으면 그 사람으로 확정 · 틀리면 그 사람의 틀림 1회. 행마다 사람이 하나라(E2 「한 행 = 한 사람」) 오입력이 다른 당첨자의 번호와 우연히 맞아도 그 사람으로 확정되지 않는다
- **틀림:** 칸 `--danger` 테두리 + `aria-invalid` + 아래 한 줄(남은 횟수 포함, `aria-live="polite"`). 입력값은 지운다(4자리 재입력이 자연스럽고, 틀린 값을 남길 이유가 없다) — §7-2 「입력값은 지우지 않는다」의 예외가 아니라 비밀 값 재입력이라 개정 ①-b가 §6-5에 적는다. 포커스는 칸에 남는다
- **잠김(서버가 판정, 당첨자 한 사람 단위 — IP 아님):** 잠김 상태로 들어오는 순간(틀림 응답이 한도에 닿았을 때 · 재전송·재판정 응답이 잠김일 때 · E2에서 잠긴 자리를 골랐을 때 모두) **칸의 값을 지우고** 입력 비활성 · 1차 비활성, 제출 줄 이유 1행 `틀린 번호가 {한도}번 들어와 확인이 잠겼습니다 · {18:45}부터 다시 해 주세요` + 2행 문의(Copywriting, 링크 줄 방식은 위). `{한도}` = 확인증 탭 설정의 틀림 한도, 시각 = 서버가 준 잠금 해제 시각 `HH:mm` — 둘 다 서버 값, 클라이언트에 5·3을 박지 않는다. 카운트다운을 그리지 않는다(§5 모션). 잠긴 자리를 E2에서 다시 고르면 E3가 곧바로 잠김 상태로 선다
- **잠금 풀림(클라이언트):** 서버는 해제 시각과 함께 남은 초를 준다. 클라이언트는 받은 순간 + 남은 초로 마감을 잡고(기기 시계 차이 무시), 그 순간 또는 화면이 다시 보일 때(`visibilitychange` visible · `pageshow`) 마감이 지났으면 곧바로: 잠김 두 줄을 지우고 · 칸 `--danger` 테두리·`aria-invalid`를 지우고 · **입력을 다시 살리고** · 1차는 칸이 비어 있으니(잠김 진입 때 지웠다) 비활성 + 원래 막힘 이유(`뒤 4자리 숫자를 적으면 확인할 수 있습니다`)로 돌아간다 — 1차 상태는 언제나 「칸이 숫자 4개인가」 하나로 계산한다. 다음 누름은 새 멱등 키다. 포커스가 문서 바깥(잠김 동안 비활성 칸에서 빠진 상태, `document.activeElement === body`)이면 칸으로 옮기고, 사용자가 다른 곳에 있으면 옮기지 않는다. 판정은 여전히 서버가 한다(일찍 눌러도 서버가 잠김을 다시 준다)
- **맞음:** 그 사람으로 E4. 그 사람이 이미 제출했으면 E4 대신 **E6-a**
- **링크 닫힘(`verifyLast4` 응답):** 확인 중에 기한이 지났거나 · 모두 제출했거나 · 담당자가 닫았으면 화면 전체가 **E6-b**(서버가 준 사유)로 바뀐다. 적은 4자리는 버린다. 틀림 횟수를 세지 않는다
- **결과 불명(연결 끊김 · 20초 · 5xx · `serverError` · 해석 불가 — E1 「서버 왕복 공통」):** 제출 줄 이유 자리에 `확인 결과를 받지 못했습니다 · 다시 눌러 주세요`(`--danger`, 1차 `aria-describedby`). 1차는 살아 있고 적은 4자리는 남는다 — 칸 테두리를 붉히지 않고 남은 횟수를 말하지 않는다(서버가 셌는지 모른다). 다시 누르면 같은 멱등 키로 보내(E1 「멱등 키」 — 확정 판정 전이라 키가 살아 있다) 서버는 첫 요청이 바꾼 결과(틀림 · 맞음)를 돌려주거나, 첫 요청이 아무것도 바꾸지 않았으면 지금 다시 판정한다 — 이미 잠겼으면 그때 잠김 상태가 선다. 4자리를 고치면 이 줄은 원래 막힘 이유 자리로 돌아가고 다음 요청은 새 키다
- 확인 상태는 페이지 메모리에만 있다. 새로 고침 → E2부터(주민등록번호 등 입력값은 어디에도 저장하지 않는다 — `localStorage`·`sessionStorage` 금지). 서버 확인 증표의 형식·유효 시간은 계획·설계 `/cso` 몫
- **뒤로 가기(기록 항목은 둘뿐):** 첫 화면 E2 = 페이지 기록 항목. E2 → E3에서 `history.pushState({step:"verify"})` 한 번. E3 → E4에서는 `history.replaceState({step:"form"})`(새 항목을 쌓지 않고 E3 항목을 바꾼다). 그래서 브라우저 뒤로는 E3에서도 E4에서도 한 번에 E2다(확인을 버리고 이름부터). E5·E6으로 갈 때도, E4에서 확인 시간 지남으로 E3에 돌아갈 때도 `replaceState`. 화면 안 버튼으로 E2에 돌아가는 이동(「다른 이름 고르기」)은 `history.back()` 하나뿐이다 — 어떤 이동도 E2 항목을 새로 쌓지 않는다. `popstate`로 E2에 오면 E3·E4 상태를 메모리에서 지운다(아래 「값의 주인」). 앞으로 가기로 E2보다 뒤 단계 항목에 오면 메모리에 그 단계가 없으므로 E2를 그리고 `history.back()`으로 E2 항목에 돌아간다(`replaceState`로 그 항목을 E2로 바꾸면 E2 항목이 둘이 된다 — 뒤 항목을 버리지 않고 E2 항목으로 되돌아가야 「기록 항목은 둘뿐」이 그대로다). URL은 바뀌지 않는다(토큰 외 정보를 URL에 두지 않는다)

**E4 입력 — §6-5 폼 그대로 + 아래만 확정**

- **서명 이미지 색:** PNG는 바탕 투명 + `--fg` 획이다(E4). 인쇄 라우트는 `<img>`에 `filter: brightness(0)`을 걸어 불투명한 모든 픽셀을 검정(= `--print-ink` 값 `#000000`)으로 찍는다 — CSS 색 토큰 교체는 PNG 픽셀에 닿지 않기 때문이다. 새 색 없음(개정 ⑬)
- **서명은 필수 이미지다 — 없으면 인쇄하지 않는다:** 자동 `window.print()`는 서명 `<img>`의 `decode()`가 성공한 뒤에만 부른다. 불러오기 실패(`decode()` 거부 · `onerror`)면 인쇄하지 않고 ERROR `인쇄물을 만들지 못했습니다 · 다시 시도`(§7-7 확정 문장, 2차 「다시 시도」 = 라우트 다시 불러오기). 서명 없는 확인증 종이가 나가지 않는다
- **준비 전 수동 인쇄도 막는다:** 확인증 본문(`.sheet`)은 서명 `decode()`가 성공해 문서에 `data-ready` 표시가 붙은 뒤에만 인쇄 미디어에 보인다. 그 전(LOADING)과 ERROR 때 사용자가 `⌘P`·메뉴로 인쇄하면 본문은 숨고 인쇄 미디어 전용 한 줄 `인쇄물이 아직 준비되지 않았습니다 · 화면이 다 뜬 뒤 다시 인쇄해 주세요`만 찍힌다(Copywriting P). 자동이든 수동이든 서명 없는 종이가 나가지 않는다
- 경영관리만 연다(권한 없으면 404 · 플래그 꺼짐이면 404). 다섯 상태는 §7-7 인쇄 라우트 행 그대로(LOADING 빈 A4 + 진행 바 · ERROR 화면 한 줄(서명 실패 포함) · SUCCESS 자동 `window.print()` · EMPTY 해당 없음 · PARTIAL 해당 없음 — 첨부가 없는 문서이고, 서명 누락은 PARTIAL이 아니라 ERROR다)
