```yaml
  id-token: write

    steps:

      - id: auth

          workload_identity_provider: projects/${{ vars.GCP_PROJECT_NUMBER }}/locations/global/workloadIdentityPools/github/providers/erp-repo

      - uses: google-github-actions/setup-gcloud@v3
```

**Anti-injection pattern — env: mapping before run:** (lines 49-64):
```yaml
      - shell: bash
        env:
          INPUT_ENV: ${{ inputs.env }}
          INPUT_ACTION: ${{ inputs.action }}
          PROJECT: ${{ vars.GCP_PROJECT_ID }}
          REGION: ${{ vars.GCP_REGION }}
        run: |
          source infra/names.sh
          ENV_SHORT="$INPUT_ENV"
          if [ "$ENV_SHORT" = "production" ]; then
            ENV_SHORT="prod"
          fi
```
**Never** write `${{ inputs.* }}` directly inside a `run:` shell string — always map to `env:` first and reference via `$INPUT_X` (RESEARCH.md Anti-Patterns / Security Domain — this is the mandatory mitigation for GitHub Actions script injection).

**Job-name / naming helper reuse** (line 73): `JOB="$(job_name "$ENV_SHORT" account)"` — reuse `infra/names.sh`'s `job_name` helper for both the account Job invocation (step 8 of the RESEARCH architecture diagram) and any new restore-verify Job name.

### `scripts/restore-record-cli.ts` (new CLI)

**Analog:** `scripts/account-cli.ts` (full file read, 147 lines)

**Strict argv parser pattern** (lines 42-77):
```typescript
export async function parseArgs(argv: string[], deps?: Partial<ParseArgsDeps>): Promise<ParsedArgs> {
  const [cmd, ...rest] = argv;
  if (cmd !== "create" && cmd !== "reset" && cmd !== "unlock") {
    throw new UsageError(`알 수 없는 서브커맨드: ...`);
  }
  const flags: { email?: string; ... } = {};
  for (let i = 0; i < rest.length; i++) {
    const token = rest[i];
    if (token === "--email" || ...) {
      const value = rest[i + 1];
      if (value === undefined || value.startsWith("--")) {
        throw new UsageError(`${token} 뒤에 값이 필요합니다.`);
      }
      flags[...] = value;
      i++;
    } else {
      throw new UsageError(`알 수 없는 플래그: ${token}. ...`);
    }
  }
  ...
}
```
Reuse this exact shape for `restore-record-cli.ts`'s subcommand (e.g. `record --source staging --success true|false --backup-id ID --failed-stage ... --started-at ISO --finished-at ISO --run-id ID`) — unknown flags rejected, `--flag value` as two argv tokens (never `--flag=value`), a `UsageError` class distinct from runtime errors.

**Entry-point + exit-code + closeDb() pattern** (lines 108-146):
```typescript
export async function main(): Promise<void> {
  try {
    const parsed = await parseArgs(process.argv.slice(2));
    await run(parsed);
  } catch (error) {
    console.error(error instanceof Error ? error.message : String(error));
    process.exitCode = error instanceof UsageError ? 2 : 1;
  } finally {
    await closeDb();
  }
}

if (process.argv[1] && import.meta.url === pathToFileURL(process.argv[1]).href) {
  void main()
    .then(() => { process.exit(process.exitCode ?? 0); })
    .catch((error: unknown) => {
      console.error(error instanceof Error ? error.message : String(error));
      process.exit(process.exitCode || 1);
    });
}
```
Copy verbatim (including the `import.meta.url` guard so tests can `import { parseArgs }` without triggering `main()`, and the double catch so Cloud Run Job task-timeout hangs don't recur — see the file's own comment about incident `plant8-staging-account-txfcr`).

**deps-injection for testability** (lines 20-25): use the same `ParseArgsDeps`/`Partial<Deps>` idiom if the CLI needs to look anything up (e.g. validating `--source` against known environments) — not strictly required here since `source` is a closed enum, but keep the pattern available if validation logic grows.
