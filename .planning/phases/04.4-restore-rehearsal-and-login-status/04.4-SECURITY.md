## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|

| 관리자 화면 접근 | `can(viewer, "admin.system-status", "view")` 기존 가드 | 리허설 결과 (내부) |
| 워크플로 → Job 실행 인자·env 덮어쓰기 | `--target`·`CLOUD_SQL_CONNECTION_NAME`이 읽을 인스턴스를 정한다 | 인스턴스 이름 (내부) |
| Job → 임시 Cloud SQL(사설 IP, IAM) | 런타임 SA가 프로젝트 수준 권한으로 붙는다 | 복원된 운영 데이터 (민감) |
| 사람(write 협업자) → `workflow_dispatch` 입력 | env · confirm_production 문자열 | 입력 문자열 |
| GitHub 러너(WIF, `gha-deployer`) → Cloud SQL Admin API | 잘못된 대상이면 운영 인스턴스를 덮어쓸 수 있는 권한 — 실제 통제는 저장소 write 권한 | 인스턴스 생성·복원·삭제 (critical) |
| 세션 생성 → better-auth `session.create.after` | 만들어진 세션의 `userId`로만 쓴다 | first_login_at |
| 투영된 DTO → 계급별 사람 목록 | 노출표가 `person.value`를 끈 계급은 새 필드를 받지 않는다 | 로그인 상태 (내부) |
| 저장소 마이그레이션 → 운영 DB | 병합 뒤 journal 순서가 운영 적용 순서 | 스키마 · 백필 |
