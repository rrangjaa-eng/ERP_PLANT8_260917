## Top 3 Priority Fixes

1. **[WARNING] `person.value`가 꺼진 계급에서 `Fragment key={person.id}`가 `undefined`** — 모든 행이 같은 key(React 경고, 재조정 오류), 「상세」 링크가 `/admin/people/undefined`, 접힌 줄이 `· 계급 · 소속`처럼 빈 이메일로 시작 — `key`를 행 머리글 id와 같은 순번 기반(`nameId`)으로 바꾸고, `person.id`가 없으면 「상세」·보관 버튼을 렌더하지 않는다(UI-SPEC이 이미 id 부재를 전제로 행 머리글 id를 순번으로 바꿨는데 key와 링크에는 같은 논리가 적용되지 않았다). `app/(app)/admin/people/page.tsx:98,128,140`
2. **[WARNING] PC(≥700px) 배지 묶음 `.peopleTable .badges { white-space: nowrap }`** — 700~900px 폭(태블릿·좁은 창)에서 6열 표에 `첫 로그인 전 · 임시 비밀번호 사용 중`이 한 줄로 고정돼 가로 넘침 가능. UI-SPEC 검증 조건은 360px·640px(폰 레이아웃)만 다뤄 이 구간은 측정 대상 밖 — `nowrap`을 지우고(각 `StatusTag`가 이미 자체 nowrap) 구분자 앞에서 줄바꿈되게 하거나, 독립 DOM 감사에 700px·768px 조건을 추가한다. `people.module.css:261-264`
3. **[WARNING] 폰 `.runLink`의 `display:inline-flex; min-height:44px`가 KvList `dd` 텍스트 흐름 중간에 들어감** — `실패 · 검증 · … · 4분 · 실행 기록` 줄에서 마지막 줄만 44px로 부풀어 줄 간격이 불균일해지고 기준선이 어긋난다. `.detailLink`는 셀에 단독으로 있어 문제가 없지만 여기는 인라인 문장 속이다 — 링크를 dd 안 별도 블록(줄바꿈 뒤)으로 두거나, `min-height` 대신 `padding-block` + 음수 `margin-block`으로 히트 영역만 키운다. `system-status.module.css:236-244`

## Detailed Findings

### Pillar 1: Copywriting (4/4)
- 「복원 리허설」 빈 상태 `리허설 기록 없음 — 첫 리허설 전`(`system-status/page.tsx:143`), 오류 `확인 불가` muted tag(`:144`) — 스펙 표와 일치, 빈/오류 구분 유지.
- 결과 헤드 `성공`/`실패 · {복원|검증|정리}`, 원본 `스테이징`/`프로덕션`, `백업 ` 접두, `1분 미만`/`N분`, `실행 기록` — `restore-rehearsal-view.ts:179-222` 전부 스펙 문구 그대로.
- 배지 문구 `첫 로그인 전`·`임시 비밀번호 사용 중`은 타입 리터럴로 고정(`person-status.ts:395`), 순서 고정, 보관됨 우선 억제 규칙 구현(`:402`).
- 접힌 줄 sr-only 라벨 `이메일`·`계급`·`현재 소속`(`people/page.tsx:139-141`) 스펙 ③ 일치.
- 일반 라벨(Submit/OK 등)·새 안내 문구 추가 없음 — §7 "문구 최소" 충족.

### Pillar 2: Visuals (3/4)
- 필드 순서(결과 · 원본 · 일시 · 백업 id · 소요 · 실행 기록)와 세그먼트 생략(#7) 구현 확인(`page.tsx:147-166`).
- 행 머리글 `th scope="row"`가 열 머리글 스타일을 받지 않도록 `.table th` → `.table thead th`로 좁힘(`people.module.css:202`) — 계급 화면 영향 없음.
- [WARNING] 폰 「실행 기록」 44px inline-flex가 문장 줄 높이를 깨뜨림(Top 3 #3).
- [INFO] 폰 접힌 줄은 주 행 hover(`--surface`)를 받지 않아 hover 시 한 사람의 두 줄 중 윗줄만 칠해진다(`people.module.css:219-221,242-244`). 터치 기기 중심이라 영향 작음.

### Pillar 3: Color (4/4)
- 새 hex/rgb 0건. 사용 색: `--accent`(`.runLink` 1곳, 기존 `.detailLink`와 동일 패턴), `--muted`(배지·구분자·접힌 줄), `--surface`(hover). 실패 행에 `--danger`를 새로 쓰지 않음 — 스펙대로 muted/본문 유지.
- 두 로그인 배지 모두 `StatusTag kind="muted" variant="text"` — 경고색으로 과장하지 않음(스펙 일치).

### Pillar 4: Typography (3/4)
- 사용 토큰: `--fs-xs`(구분자, StatusTag와 동일 크기), `--fs-sm`(링크·접힌 줄), `--fs-base`(행 머리글), `--fw-regular`/`--fw-medium`, `--lh-table` — 모두 tokens.css에 존재 확인. 새 크기·굵기 없음.
- `.backupId` nowrap + tabular-nums(§2-4) 구현.
- [WARNING] PC 배지 묶음 `nowrap`(Top 3 #2).
- [INFO] 「일시」 `2026-09-24 03:14`는 `.num`/tabular-nums가 없다 — 같은 KvList의 「알림 발송」은 `styles.num`으로 감싼다(`page.tsx:28`). 숫자 표기 일관성 차원에서 `head` 중 일시에도 tabular-nums를 적용 권장.

### Pillar 5: Spacing (3/4)
- 새 간격은 `--s-1`(폰 배지 세로 간격), `--cell-pad-x/y`, `--touch-min`만 — 토큰 외 리터럴 없음(기존 KvList `7px/6px`는 이 페이즈 변경 아님).
- 폰에서 주 행 아래선 제거 후 접힌 줄 아래에 긋기(`:282-285`) — §7-3 준수.
- [INFO] 접힌 줄 셀 `padding-top: 0`이라 주 행 셀의 `padding-bottom`에만 의존 — 행 머리글 이름이 두 줄로 줄바꿈되면 접힌 줄과 간격이 좁아 보일 수 있다. DOM 감사에서 긴 이름 행으로 확인 권장.

### Pillar 6: Experience Design (3/4)
- 상태 커버리지: 리허설 none/unavailable/success/failure(+runUrl 방어적 생략), 사람 목록 4조합 + 보관됨 억제 + 노출표 가림(키 부재 시 배지 생략, `person-status.ts:404`) — 모두 구현.
- 목록 0건 `ListEmpty` + 등록 행동, 확인 창 대신 기존 보관 버튼 흐름 유지 — 새 파괴적 행동 없음.
- 접근성: 행 머리글 id 순번 기반·`headers` 연결·`aria-hidden` 없음·PC `display:none` — 스펙 ①~④ 충족.
- [WARNING] `person.id` 부재 시 key·링크 결함(Top 3 #1).
- [INFO] 「실행 기록」은 외부 GitHub로 이동하지만 같은 탭에서 열린다 — 관리자가 상태 화면을 잃는다. `target="_blank" rel="noopener noreferrer"` 여부는 사용자 결정 사항으로 남긴다(스펙 미정).
