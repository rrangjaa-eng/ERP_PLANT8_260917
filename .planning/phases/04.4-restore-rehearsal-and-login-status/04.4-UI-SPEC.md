## Color

**가정(도메인 규칙, RESEARCH.md의 Discretion 항목을 이 화면 계약이 성립하도록 명시적으로 확정한다 — 계획 단계에서 도메인 로직으로 재확인 필요):**
1. `password_is_temporary`가 참이면 항상 `first_login_at`도 비어 있다(로그인 없이 비밀번호를 바꿀 방법이 없으므로) — 따라서 "첫 로그인 전인데 임시 비밀번호 아님"이라는 네 번째 조합은 존재하지 않는다.
2. 관리자 재발급(`account.yml reset`)은 `password_is_temporary`만 다시 켜고 `first_login_at`은 되돌리지 않는다(RESEARCH.md 코드 예시 `setFirstLoginAtIfUnset`의 "최초 1회만" 전제와 일치) — 재발급 뒤에는 `임시 비밀번호 사용 중`만 다시 보이고 `첫 로그인 전`은 보이지 않는다. 이는 RESEARCH.md 통합 테스트 시나리오("관리자 재발급 → 「임시 비밀번호」 다시 표시")와 정확히 일치한다.

**§7-5 길이 규칙 이탈 — 명시적 System Deviation (내가 SYSTEM.md·DECISIONS.md를 직접 고치지 않는다):**
`§7-5`는 상태 태그 문구를 "두~네 글자 명사"로 제한하고(Phase 4 보강도 "네 글자 + 괄호 한정어"까지만 허용), `첫 로그인 전`(5글자)·`임시 비밀번호 사용 중`(10글자)은 이 한도를 넘는다. 이는 D8-07이 문구 자체를 지정한 잠긴 업무 용어이므로(§7-5의 `완료(정산)` 예외와 같은 성격 — "업무 용어로 잠긴 상태 값") 새로 만든 표현이 아니라 이미 결정된 문구다. **계획 단계가 `DECISIONS.md`에 이유를 남기고 `SYSTEM.md` §7-5의 "Phase 4 보강" 목록에 이 두 문구를 추가하는 작업을 Task로 포함해야 한다** — 화면 하나만 예외로 두지 않는다는 CLAUDE.md 원칙에 따라, 이 문서(UI-SPEC)만으로 SYSTEM.md를 대신할 수 없다.

**§6-8 사실 갱신 필요 (System Deviation 아님 — 단순 계수 오류 수정):**
SYSTEM.md §6-8 본문은 현재 "세 항목: 배포 버전 · DB 커넥션 · 마지막 백업"이라고 못박고 ASCII 와이어프레임도 세 줄뿐이다. 이 페이즈가 네 번째 항목(복원 리허설)을 더하므로, **계획 단계는 §6-8의 "세 항목"을 "네 항목"으로 고치고 와이어프레임에 `복원 리허설` 줄을 추가하는 문서 Task를 포함해야 한다.** 이것은 색·서체·radius를 벗어나는 것이 아니라 이미 있는 화면 설명을 사실과 맞추는 일이라 DECISIONS.md 항목이 필요한 이탈이 아니다(§4-6 절차의 "새 템플릿이 필요하면 먼저 SYSTEM.md에 추가"와 같은 결 — 기존 템플릿 안에서 항목 하나가 느는 것).
