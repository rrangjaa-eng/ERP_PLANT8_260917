## 적용 규칙 (표면별 계약 — 새 템플릿 아님)

표면 S1~S14. 각 머리의 괄호는 출발 템플릿이다. 이 절은 배치 · 열 · 동작을 정하고, 문구는 위 Copywriting 표 행을 가리킨다.

### S1. 견적 줄 표 — 행 행동 · `Ctrl+E` · 상태 파생 (Phase 4 S4 + §7-3)

```
PC ≥1280 (편집 표 — Phase 4 열 11개 뒤에 행동 열 하나)
│    소분류   항목                    거래처         … 실행가     차익   상태       비고                          │
│ 1  무대     메인 스테이지 구조물 설치  (주)스테이지원 … 12,400,000 …    지출결의 중  …   지출결의 열기    │
│ 2  무대     LED 월 W12000×H4000      한빛무대예술   …  6,900,000 …    미착수      …   지출결의 올리기  │
│ 3  음향     음향 시스템 렌탈           —             …  6,500,000 …    미착수      …   거래처 없음 거래처 고르기 │
│ 이동 Tab ↑↓←→ · 범위 복사 Ctrl+C / 붙여넣기 Ctrl+V · 취소 Esc · 새 줄 Ctrl+Enter · 줄 이동 Alt+↑↓ · 줄 복제 Ctrl+D · 지출결의 올리기 Ctrl+E │
```

- **행 행동 열**: 표의 맨 오른쪽(비고 뒤) 열 하나. 보이는 머리글 글자 없음 + 숨긴 머리글 `행동`(`.sr-only`). 폭 = 가장 긴 셀 내용(`지출결의 올리기`), `white-space: nowrap`.
  **보는 사람에게 `expenses` 쓰기 권한과 그 프로젝트 쓰기 권리가 있을 때만 서버가 열을 보낸다**(§7-3 칸 수 가변 — 클라이언트가 숨기지 않는다). 폭: ≥700에서 열(좁은 PC도 —
  지출결의 만들기는 셀 편집이 아니다), <700에는 열 없음(S2 행 시트). 열 우선순위는 P1 밖이다(행동은 데이터가 아니다 — 04.1 결재함 행동 칸과 같은 해석, B4). 1024~1279 ·
  700~1023의 숨는 열은 Phase 4 표 그대로이고 이 열은 숨지 않는다.
- **셀 값 — 서버가 줄마다 판정해 보낸다**(`rules.gate` + 줄의 문서 목록, 클라이언트 추론 금지):

  | 줄 | 셀 |
  |---|---|
  | 문 열림 — 거래처 있음 · 게이트 통과 · 제출 문서 없음(또는 분할 줄의 남은 실행가 > 0) | 3차 `지출결의 올리기` — 누르면 **작성 중 문서를 만들고**(idempotency key = 줄 id + 회차 자리) `/expenses/[id]`로 간다. 내가 그 줄로 만든 작성 중 문서가 이미 있으면 새로 만들지 않고 그 문서를 연다(EXP-01 「두 번 눌러도 겹치지 않는다」) |
  | 문 닫힘 — 분할 아닌 제출 문서가 있음 · 분할 줄의 남은 실행가 0 | 3차 `지출결의 열기` → 가장 최근 제출 문서 |
  | 거래처 없음 | `거래처 없음`(`--fs-sm --danger`) + 3차 `거래처 고르기`(그 줄 거래처 셀로 포커스 + 편집 진입, ≥1024). 700~1023은 표가 보기 전용(DR-36)이라 `거래처 없음 · PC 견적 표에서 고르기` 대신 **셀에는 `거래처 없음`만** 쓴다(그 폭도 PC다 — 1024 이상 창에서 고른다) |
  | 취소 줄 · 조정 줄(D-83) · 견적 외 비용 줄(D-48) | 빈 셀 — 글자도 `—`도 없다(이 줄에는 지출결의라는 행동이 없다, §7-3 「렌더하지 않는다」) |
  | **표 전체 게이트** — 진행 · 현재 차수 고객 승인 전(D-43 · D-54) / 완료(D-47) | 문 열림 줄의 `지출결의 올리기`를 렌더하지 않는다. 이유는 **표 위 한 줄 하나**(고객 승인 전 — Copywriting 「막힘 — 견적 줄 행 행동」, 완료 — Phase 4의 `완료 · 견적 줄 잠김`이 이미 있다). `지출결의 열기`는 그대로 선다 |

  현재 차수 = 최신 차수(D-54)만 행 행동을 가진다. 이전 차수 표(차수 섹션)에는 행동 열이 없다.
- **`Ctrl+E`**(편집 중이 아닐 때, `preventDefault` — D-94): 활성 셀의 줄 = 그 줄 셀과 같은 동작. **범위 선택이 여러 줄이면** 고른 줄 중 문이 열린 줄마다 작성 중 문서를 만들고
  목록으로 간다(확인 대상 #5, 토스트). 고른 줄의 문이 전부 닫혔거나 막혔으면 이동하지 않고 합계 행 오른쪽 한 줄에 첫 막힌 줄의 이유(셀과 같은 문자열). 표 전체 게이트가 막혀 있으면
  표 위 한 줄이 이미 말하므로 합계 행에 다시 쓰지 않는다(같은 사실 두 번 금지).
- **미저장 편집**(`N ≥ 1`): `지출결의 올리기` · `지출결의 열기` · `Ctrl+E`는 이동하지 않고 합계 행 오른쪽 한 줄에 `저장 안 한 편집 3칸 · 먼저 일괄 저장`(DR-6과 같은 함수).
  버튼을 비활성으로 여럿 세우지 않는다(§7-3 「비활성 버튼을 여럿 세우지 않는다」) — 누른 뒤 한 자리에서 이유를 본다.
- 누른 뒤: 누른 버튼 `지출결의 올리기…`, 같은 열의 나머지 버튼 `aria-disabled`(04.1 제출 중 규칙). 실패는 합계 행 오른쪽 한 줄(Copywriting 「Error — 지출결의 만들기 실패」).
- **상태 열 파생값**: `지출결의 중` · `반려`를 이 페이즈가 켠다(Color 매핑표, 한 값 규칙). **D-66 읽기 전용**은 제출된 문서가 연결된 줄의 금액 셀에 선다 — 이유
  `지출결의 26001-0004 연결됨 · 고치려면 새 차수`(Phase 4 계약, UA-609). 작성 중 문서는 연결로 세지 않는다(Assumptions #3).
- **힌트 줄**: `지출결의 올리기 Ctrl+E`를 끝에 더한다(행동 열이 서는 사람에게만 — Copywriting 「힌트 줄 항목」의 7개 규칙).
- 접근성: 셀의 3차는 격자 로빙에서 빠지고(DR-25 충돌 버튼과 같은 처리) 행의 `Ctrl+E`가 키보드 경로다. 버튼의 `aria-describedby` = 그 줄 항목 칸 id — 「지출결의 올리기, LED 월 W12000×H4000」.

### S2. 폰 행 시트 — 행동 줄 (§7-3 (바) + D-69)

- <700에서 견적 줄 행을 탭하면 열리는 Phase 4 행 시트(보기 전용 본문)에 **행동 줄 하나**를 더한다(B4 — §7-3 (바) 「행동 줄을 두지 않는다」를 D-69대로 고친다).
- 행동 줄(고정, 높이 `--touch-min`): S1 셀과 같은 서버 판정 — 문 열림 1차 `지출결의 올리기` / 문 닫힘 1차 `지출결의 열기` / 거래처 없음 = 버튼 없이 `거래처 없음 · PC 견적 표에서 고르기`
  (`--fs-sm --danger`, 폰에는 셀 편집이 없다 — §6-2) / 취소 · 조정 · 견적 외 비용 줄 = 행동 줄째 없음 / 표 전체 게이트 = 버튼 없이 표 위 한 줄과 같은 문자열.
- 1차 하나라 전폭. 열릴 때 포커스는 Phase 4 그대로(닫기 x) — 행동은 보기 뒤에 온다.
- 누르면 시트가 닫히고 폼(S3)으로 간다. 폰에서는 범위 선택이 없어 여러 줄 만들기가 없다.

- **제어 기본값 — 알 수 있는 값은 채운다**(CLAUDE.md §7): 거래처 · 공급가액(= 줄의 남은 실행가) · 통화(= 줄의 통화) · 환율(= 설정의 통화별 최근 환율, Phase 4 D-71) ·
  증빙 종류(= 거래처 기본 증빙, 없으면 `—`) · 지급 방식(= 코드표 `지급 방식`의 기본값) · 팀(= `teamAtDate(사용일)`) · 사용일(= 오늘, `seoulToday()`).
  **팀 비용 `종류`는 알 수 있는 값이 없어 `—`로 연다** — 사용자의 유일한 결정이다. 지급 예정일은 비워 둔다(자동 계산은 Phase 7).
- **칸 순서와 이유**: 통화 → 공급가액 → (외화면) 환율 → 계산 한 줄. 계산 한 줄은 **마지막 금액 칸 바로 아래**다(KRW = 공급가액 아래 · 외화 = 환율 아래) — 입력을 다 적은 자리에서
  결과를 본다(§6-3 「입력 바로 아래 한 줄」). Phase 4 등록 폼(금액 → 통화 → 환율)과 순서가 다른 이유가 이것이다(B1). 환율 칸은 KRW면 없다.
- **자동 채움 칸은 텍스트 + 3차 `바꾸기`**(§6-3 · DECISIONS 2026-09-18 #3 — 폰은 `바꾸기`가 값 줄 오른쪽 끝, 부제는 아래 한 줄). 견적 줄 `바꾸기`는 S14 → 거래처 · 증빙 종류 · 통화 ·
  공급가액 · 분할 지급이 새 줄 값으로 다시 채워진다(결과 줄이 미리 말한다). 거래처 `바꾸기`는 S14 → 증빙 종류가 새 거래처의 기본값으로 바뀐다.
- **증빙 종류**: 코드표 설명은 Select 아래 `Form.Hint`(D-93, 설명이 없으면 줄 없음). 바꾸면 계산 한 줄이 즉시 다시 온다(EXP-15, S5).
- **공급가액**(EXP-14 · EXP-15): 사람이 적는 금액은 이것 하나다. `numberKind` 원화(외화면 외화 소수 2자리) — 쉼표 자동, `-` 글자는 입력되지 않는다(서버도 > 0 검증).

  (Copywriting 「표시 — 분할 지급」). 회차 합계 > 실행가는 공급가액 칸 오류(서버 판정 — 이 문서와 그 줄의 다른 제출 문서 합으로).
- **지급 예정일**(UA-617): 선택 칸, 자리표시자 `2026-09-19`(형식 예만). 원천징수 · 회사 대납 규칙이면 날짜를 바꾸는 순간 계산 한 줄이 다시 온다(기준일, D-101). Phase 7이 이 칸 아래에
  §6-3 원문의 `결재 마감 … · 지급일 규칙 …` 한 줄을 더한다 — 이 페이즈는 그 줄을 그리지 않는다.
- **팀 비용 칸**(EXP-08): `종류`(Select 200, `미수주 비용` · `팀 관리비`) · `팀`(읽기 텍스트) · `사용일`(280) · `내용`(480, 필수 — 문서 제목 `지출결의 — 기획1팀 · {내용}`이 된다).
  사용일을 바꾸면 팀이 그날의 소속으로 다시 온다. 소속이 없으면 칸 오류(Copywriting).
- **증빙 묶음**: S4. 06 S6의 `선결제` 칸이 첨부 영역 바로 아래에 온다(이 페이즈는 자리만 비운다).
- **결재선**: 04.1 S7 제출 전 한 줄(서버가 기안자 · 문서 종류 `지출결의`의 결재선 설정으로 해석). 자기 승인 설정이 `본인 승인`이면 그 단계가 빠지지 않고 `김도윤(나) 팀장`으로 선다 —
  `박서연 → …`이 아니라 `김도윤 → 김도윤(나) 팀장 → 이수아 경영관리 → 최대표 대표 · 결재 규칙`. `건너뜀`이면 §6-3 원문대로 끝에 `· 팀장 단계 건너뜀(자기 승인 없음) · 결재 규칙`.
- **행동 줄**(`Form.Actions`): 1차 `지출결의 제출 Ctrl+Enter` + 왼쪽→오른쪽 막힘 이유(S6) + 다음 한 수 3차, 오른쪽 끝 2차 `임시 저장`. `Enter` 기본 제출은 막고 `Ctrl+Enter`만 제출
  (§7-15 · 연타 가드). `Ctrl+U` = 파일 고르기(폼 어디서든, `preventDefault`).
- **첫 포커스 = 막힘 이유가 가리키는 칸**(증빙 없음이면 첨부 영역, 빈 칸이면 그 칸, 막힘이 없으면 1차). 「채울 건 하나뿐」(§11 동선 A 2단계)이 포커스로 보인다.
- **머리 줄**(§6-3 「720」): 제목 `지출결의 — {프로젝트명} · {항목}`(팀 비용 `지출결의 — {팀} · {내용}`, 내용 전 `지출결의 — {팀}`) · 상태 태그(`작성 중` · `반려` · `회수`) · 번호(반려 · 회수 —
  제출 때 받은 번호, 작성 중에는 없음 — D-42) · 오른쪽 2차 `지출결의 삭제`(작성 중에만. 즉시 삭제 + 토스트 `되돌리기`, `/expenses`로 이동 — 확인 창 대신 되돌리기, CLAUDE.md §7).
  폰에서 머리 줄 오른쪽 버튼은 행동 줄 아래로 내려오지 않고 숨는다(실물 `.sec .right` — 폰 삭제는 목록에서 하지 않는다, Assumptions #10).
- **반려 · 회수 뒤**(확인 대상 #2): 같은 폼이 값이 채워진 채 선다 — 맨 위 읽기 행 `반려`(`김도윤 · 09-16 14:02` + 2행 `사유 · {원문}`, 04.1 S3 선례) 또는 `회수`(`09-17 10:00`),
  결재선은 제출 전 한 줄(지금 다시 해석한 모양), 1차 `지출결의 다시 제출 Ctrl+Enter`. 증빙은 그대로 남는다.
- **제출 중**: `지출결의 제출…` + 같은 폼의 나머지 버튼 · 칸 `aria-disabled`(04.1 제출 중 규칙). 성공 → 제자리 결과 + 토스트 + 화면이 S7 문서 화면으로 다시 그려진다(주소 그대로).
- **떠날 때**: 저장 안 한 칸이 있거나 **올리는 행**(메타 `올리는 중…` — S4)이 하나라도 있으면 브라우저 기본 `beforeunload` 경고만(커스텀 모달 없음 — 문서는 이미 서버에 있고 `임시 저장`이 있다. 올리던 파일은 떠나면 사라진다 — design-review D2).
- **올리는 중 제출**: 올리는 행이 하나라도 있는 동안 1차는 S6 「올리는 중」 규칙으로 막힌다(`증빙 올리는 중 · 잠시 뒤 제출` — design-review D2).
- **폰**(UX-03): 라벨이 위, 칸 전폭. **제출 줄은 하단 탭 위 고정**(§6-3 · DECISIONS #5): 1차 `--touch-min` 넓게 + 옆 `임시 저장`, 막힘 이유는 그 아래 한 줄. 본문 아래 여백 = 탭 44 + 제출 줄.
- **권한**: 폼은 기안자에게만(작성 중 문서는 기안자 말고는 404 — D-17). `expenses` 쓰기 권한이 없으면 `/expenses/new`도 404.

### S4. 증빙 첨부 · 업로드 `ui/attachments` (§7-10 + EVID-01)

- **자리**: 폼(S3)의 `증빙` 행 · 문서 화면(S7)의 2px 섹션 `증빙`. 값 폭 480(긴 칸, §6-3).
- **빈 영역**: `--surface` 면 + `1px dashed --line-ui`, 높이 96(PC) / 72(폰), 글자 한 줄(Copywriting). 영역 전체가 `<button>` — 클릭 · `Enter` · `Space` · 폼의 `Ctrl+U`가 파일 고르기를 연다
  (`<input type="file" accept="image/*,application/pdf" multiple>`, `capture` 없음 — 폰 OS가 카메라 · 사진 · 파일을 고르게 둔다, §7-10). PC는 끌어 놓기도 받는다(끌고 있는 동안 영역 테두리 `--accent`가
  아니라 `--line-strong` 1px — 포인트 색 다섯 곳 밖이다).
- **파일마다 흐름**(사용자에게 보이는 것은 파일 행 하나): 고르는 즉시 행이 생긴다 — 썸네일(이미지면 축소한 로컬 미리보기 48, 아니면 paperclip 16) · 파일명 · 메타 `올리는 중…`(`--muted`).
  그 뒤 브라우저가 이미지를 **최대 변 2000px JPEG로 줄이고**(PDF는 원본) SHA-256을 계산해 서버 검사(크기 한도 · 형식 · 중복) → GCS 서명 PUT URL → 직접 올림 → 완료 통보 → 서버가 GCS 메타데이터를
  다시 확인하고 `incoming/` → `evidence/`로 옮긴 뒤 파일 행을 만든다(ROADMAP Phase 6 기준 2 방식 · 사용자 결정 E2). 옮기는 동안에도 메타는 `올리는 중…`이다(새 상태 없음). 성공하면 메타가 `212KB · 09-19`(크기는 올린 뒤의 크기)로 바뀌고 오른쪽 3차가 선다.
- **올리는 행이 있는 동안(design-review D2)**: 폼(S3)의 제출 1차는 `증빙 올리는 중 · 잠시 뒤 제출`로 막히고(S6 — 파일 완료 전에는 서버상 증빙이 0개라 ⑧ `증빙 없음`이 틀린 안내가 된다) 떠나면 `beforeunload` 경고가 뜬다(S3 「떠날 때」). 마지막 올리는 행이 끝나면(성공 · 실패 모두) 이 막힘이 풀린다.
- **`다시 올리기`(완료 통보 실패 — design-review D3)**: 사용자에게는 문구 `올리지 못함 · 다시 올리기` 하나 · 버튼 하나다. 누르면 서버가 거부 때 돌려준 갈래를 따른다 — `complete`(의도가 열려 있고 메타데이터가 맞았는데 `incoming/` → `evidence/` 옮기기만 실패해 원본이 `incoming/`에 남음) = **완료 통보만 다시**, `restart`(그 밖 전부 — 의도 없음 · 남의 것 · 만료 · 이미 완료 · 객체 없음 · 메타데이터 불일치 · 트랜잭션 거부) = **같은 파일로 처음부터**(선언 → 서명 PUT → 완료 — 브라우저가 줄이고 해시한 결과를 다시 쓴다). 서명 PUT 자체가 실패하면 `restart`, 완료 통보 응답이 오지 않으면(네트워크) `complete`로 한 번 더 부르고 서버 답을 따른다. 다시 하는 동안 메타는 `올리는 중…`(새 상태 · 진행 표시 없음).
  **진행 바는 그리지 않는다** — §7-10 「행 아래 2px 진행 바」는 DECISIONS 2026-09-23 C-10(진행 막대 미구현 · §1-3 충돌 기록)의 대상이라 그 결정이 날 때까지 `올리는 중…` 글자가 신호다(B6).
- **실패 행**: 오류 셀 모양(`--danger-weak` 면 + `--inset-error` 좌측 2px) + 행 안 한 줄 `--fs-sm --danger`(Copywriting 「Error — 증빙 업로드」) + 그 줄의 다음 한 수 3차 + 오른쪽 3차 `지우기`.
  여러 파일 중 일부만 실패하면 성공 행과 실패 행이 각각 남는다(§7-7 첨부 PARTIAL). 실패 행은 서버에 없다 — 새로 고치면 사라진다.
- **파일이 있을 때**: 파일 행 목록(`<ul>`, 행 사이 `1px --line`) + 아래 「하나 더」 영역 44px(`하나 더 · Ctrl+U`).
- **파일 행 3차(보는 사람 · 문서 상태로 서버가 정한다)**:

  | 보는 사람 · 문서 | 3차 |
  |---|---|
  | 기안자 · 작성 중 · 반려 · 회수(폼) | `삭제`(모든 파일 — 즉시, 모달 없음, §7-10. 다시 올릴 수 있으니 되돌리기도 없다) |
  | 기안자 · 결재 중 | 「하나 더」 영역 있음 · **마지막이 아닌 파일에만** `삭제`. 마지막 파일에는 `삭제`를 렌더하지 않는다 — 06 SP-6이 확인 모달과 함께 연다 |
  | 기안자 · 승인 | 「하나 더」 영역만(`삭제` 없음 — 사용자 결정 U1 2026-09-26: 승인 뒤 증빙은 지우지 않고 무효 처리) |
  | 승인 문서 · `expenses.evidence_void` 쓰기 권한자 | 살아 있는 파일마다 3차 `무효 처리`(아래 「무효 처리」) |
  | 결재선 사람 · 목록 범위로 보는 사람 | `크게 보기`(새 탭에서 원본 — 서명 GET URL). 「하나 더」 없음 |
  | 무효 행(누구나) | `크게 보기`만 |

- **무효 처리(사용자 결정 U1 2026-09-26 · 05-09 Task 3 ②)**: 승인된 지출결의의 잘못 붙은 증빙은 지우지 않고 무효로 남긴다. 3차 `무효 처리` → 04.1 S6 반려 사유 확인 창과 같은 컴포넌트(제목 `증빙 무효 처리` · 부제 `{파일명}` · 사유 칸 한 줄(필수 · 1~500자) · 확인 `무효 처리`). 사유가 비면 확인 버튼 `aria-disabled` + `사유 없음 · 한 줄 적어 주세요`(04.1 반려 사유와 같은 규칙 · 문구). 되돌릴 수 없는 일이라 확인을 거친다(CLAUDE.md §7). **무효 해제 동작은 없다**(버튼 · 액션 · 되돌리기 모두 없음 — 사유와 함께 영구 기록, 사용자 결정 G3). 잘못 무효로 했으면 같은 파일을 다시 올린다(무효 파일은 중복 검사에서 빠진다). **마지막 살아 있는 파일도 무효로 할 수 있다**(사용자 결정 G2 — 승인 문서라 제출 경로가 없어 ⑧과 무관하고, 살아 있는 파일이 0이 되면 기안자의 「내 차례」 [막힘] 줄(S11 — G1)과 Phase 6 점검이 잡는다). 누르는 동안 1차 `무효 처리…` · 나머지 `aria-disabled`(04.1 제출 중 규칙). 성공하면 확인 창이 닫히고 그 파일 행이 그 자리에서 무효 행으로 바뀐다 — **토스트 없음**(결과가 행동한 자리에 보이고 첨부 `aria-live`가 읽는다 — §7-6 「화면 이동이 따르는 행동만 토스트」 · §7-7 SUCCESS, design-review D10). 실패 · 서버 거부는 확인 창 사유 칸 아래 한 줄이고 창은 닫히지 않는다(Copywriting 「Error — 증빙 무효 처리」): 네트워크 · 서버 `무효 처리하지 못했습니다 · 다시 시도`, 이미 무효 `{처리자}이/가 HH:MM에 무효 처리함 · 새로 고침`(design-review D9), 승인 아님 `승인 뒤에만 무효 처리`(버튼이 렌더되지 않는 상태라 서버에서만). 권한은 메뉴 키 `expenses.evidence_void` 쓰기 ∧ 문서 보임 — 역할 이름으로 판정하지 않고 시드에서 아무 계급에도 켜지 않는다(사용자 결정 2026-09-26 A)
- **무효 행 표시**: 파일 행은 그대로 남고 `ui/status-tag` 「무효」(`--muted` — §7-5, 견적 줄 `취소`와 같은 색) + 파일명 취소선 + 2행 `무효 · {처리자} · MM-DD HH:mm · {사유}`(`--fs-sm --muted`). 썸네일 · `크게 보기`는 그대로. 결재 시트(§7-8 72×96) · 폰에서도 같은 표시. 무효 증빙은 「살아 있는 파일」이 아니어서 증빙 개수 게이트 ⑧ · 중복 검사 · 마지막 파일 판정에서 빠진다. 표기는 개정 제안 B8(취소선 — DECISIONS 2026-09-18 #7과의 충돌 기록)
- **무효 행 접근성(design-review D6)**: 취소선은 스크린리더가 읽지 않으므로 **DOM 순서 = 「무효」 태그 → 파일명**(보이는 순서도 같다 — 낱말이 먼저 읽힌다). 파일명 요소의 `aria-describedby` = 2행 요소 id(처리자 · 시각 · 사유가 파일명과 함께 읽힌다). 무효 처리 결과는 기존 첨부 목록의 `aria-live="polite"` 영역이 읽는다(새 live 영역 없음). 폰(<700) 파일 행의 3차 두 개(`크게 보기` · `무효 처리`)는 각각 높이 `--touch-min` 영역이고 둘 사이 `--s-4`(위험 동작을 떨어뜨림 — CLAUDE.md §7)

- 결재 시트(S9)에서는 §7-8 시트 상세 첨부 모양(썸네일 72×96 + 파일명 · 장수 · 용량 + 3차 `크게 보기`).
- 기안자가 결재 중 파일을 더하거나 떼면(승인 뒤에는 더하기만) 결재 인스턴스 `version`이 오른다 — 그 전에 문서를 연 결재자의 승인은 동시 처리 거부로 막힌다(Copywriting 「거부 — 동시 처리」 이 페이즈 문구).
- 접근성: 업로드 상태 변화(`올리는 중…` → 메타 · 실패 이유)는 목록 옆 `aria-live="polite"` 영역이 읽는다. 실패 행의 3차는 그 행 파일명을 `aria-describedby`로 잇는다.

### S5. 세금 자동 계산 한 줄 · 세율 바뀜 (§6-3 「서버 계산 값」 + EXP-15)

- **계산은 서버 하나**: `domain/money.applyTaxRule()` 호출 하나(이 페이즈는 계산을 새로 쓰지 않는다 — ROADMAP 기준 7). 클라이언트 컴포넌트는 `domain/money`를 import하지 않는다(린트).
  입력(증빙 종류 · 공급가액 · 통화 · 환율 · 지급 예정일)이 바뀌면 서버 액션 응답으로 한 줄이 다시 온다. 오는 동안 **이전 값이 `--faint`로 남고** 빈칸 · 뼈대로 바꾸지 않는다(06 금액 표시 절과 같은 규칙).
- **기준일**(D-101 — 코드표 증빙 종류의 「적용 기준일 종류」 필드, 시드 기본값): 부가세 = 증빙일, 없으면 작성일 — 이 페이즈에는 증빙일 칸이 없어 **작성일**(문서를 만든 날)이다(Assumptions #7) /
  원천징수 · 회사 대납 = 지급일, 미지급이면 지급 예정일, 비면 오늘. 기준일은 화면에 쓰지 않는다(세율 `%`가 결과를 말한다).
- **문자열**: Copywriting 「표시 — 계산 한 줄」의 규칙 넷 + 외화 + 계산 불가. 같은 서버 함수가 폼(S3) · 문서 화면(S7) · 결재 시트(S9) · 06 S4의 문자열을 만든다.
- **제출 때 저장되는 것**: 규칙 · 세율 버전 id · 세액 · 지급 총액(또는 실지급액) · 원화 환산액. 제출 뒤 화면(S7 · S9)은 **저장된 값**을 보인다 — 결재자가 승인하는 숫자는 기안자가 제출한 숫자다.
- **세율 바뀜**(ROADMAP 기준 7 「재계산 시 차이가 표시된다」): 제출된 문서를 볼 때 서버가 지금의 설정 · 기준일로 다시 계산해 저장값과 다르면 계산 한 줄 바로 아래 `--warning` 한 줄
  (Copywriting 「표시 — 세율 바뀜」). 막지 않는다 — 지급 때 무엇으로 계산할지는 06 S5 · 금액 표시 절이 정한다. 작성 중 폼은 늘 지금 기준으로 다시 계산하므로 이 줄이 없다.
- **회사 대납 세금**은 그 줄의 프로젝트(팀 비용이면 팀) 비용에 더해진다(EXP-15) — 손익 쪽 표시는 Phase 9 · 10. 이 한 줄은 세액만 보인다.

### S6. 제출 막힘 이유 (UX-06 + `domain/rules.gate`)

- **판정은 서버 하나**: 폼이 서버 계산을 받을 때마다 `rules.gate(doc, 'expense.submit', ctx)`의 결과(첫 막힘 규칙 + 그 규칙의 이유 문자열 + 다음 한 수의 대상 칸)가 같이 온다. 화면은 그 문자열을
  1차 왼쪽에 그대로 쓰고, 3차 다음 한 수는 대상 칸으로 포커스(칸) · 골라내기 열기(거래처) · 파일 고르기 열기(증빙) · 프로젝트 상세로 이동(고객 승인 표시)을 한다. 제출 액션도 같은 게이트로 다시 거부한다.
- **순서 고정**: Copywriting 「막힘 — 제출」 ①~⑨. 한 번에 하나만 보인다(빈 칸은 한 묶음 문자열로 센다 — §7-15 원문 꼴). 막힘이 풀리면 이유와 3차가 사라지고 1차가 산다(§11 동선 A 3단계).
- 1차는 `aria-disabled` + `aria-describedby` → 이유 글자(§7-1 · §10 — 누르기 전에 읽힌다). 비활성 1차를 눌러도 서버를 부르지 않고 다음 한 수의 대상으로 포커스를 옮긴다.
- **올리는 중(클라이언트 상태 — design-review D2)**: 폼에 올리는 행(`올리는 중…`)이 하나라도 있고 서버 첫 이유가 **없거나 ⑧**(대상 `evidence`)이면 그 자리에 `증빙 올리는 중 · 잠시 뒤 제출`이 선다(`reasonTone: "info"` — 막힘이 아닌 진행 상태, §7-1 U-4). 1차는 `aria-disabled` + `aria-describedby` → 그 글자, 다음 한 수 3차는 없고 눌러도(`Ctrl+Enter` 포함) 서버를 부르지 않는다. 서버 첫 이유가 ①~⑦ · ⑨면 그 이유가 그대로 선다(기다려도 풀리지 않는 막힘이 먼저다). 파일 완료 전에는 서버상 증빙이 0개라 ⑧이 「이미 올리는 중인데 올리라」는 틀린 안내가 되는 것을 막는다. 판정은 순수 함수 하나(05-05 `submitBlockReason`)이고 05-06이 서버 첫 이유를 그 함수에 넘긴다.
- 06이 이 게이트에 `선결제`(증빙 없음 규칙의 예외)를 더한다. 이 페이즈의 증빙 규칙은 「파일 1개 이상」 하나다(Assumptions #5).

### S9. 결재함 · 결재 시트에 지출결의 · 정산 결재 싣기 (04.1 S4 · S5 위)

- **문서 종류 등록**: 문서 종류가 자기 문서 화면 경로를 등록한다(04.1 S4 「Phase 5부터는 문서 종류가 자기 화면 경로를 등록한다」) — 지출결의 `/expenses/[id]` · 정산 결재 `/projects/[projectId]/settlement`.
  결재함의 문서 칸 링크 · 폰 `처리함` 행 링크가 이 경로를 쓴다.
- **숫자 열 머리글**(04.1 S4 「Phase 5가 다시 정한다」의 답): 열 하나. 값 = 지출결의 공급가액(원화 + 외화 2행) · 연차 `3일` · 정산 결재 `—`. 머리글은 **지금 표에 있는 종류로 서버가 정한다** —
  금액 문서만 `금액` · 연차만 `일수` · 섞이면 `금액 · 일수`. 우측 정렬 · `tabular-nums`. 폰 P1 세 칸(문서 · 숫자 · 상태)은 그대로이고 외화 2행은 접힌 줄로 내려간다(§7-3).
- **문서 칸 문구**: Copywriting 「표시 — 결재함 행」. 기안 칸 · 상태 칸 · 그룹 · 정렬 · PC 행 행동 · 폰 행 갈래는 04.1 S4 그대로. PC 행 `승인`은 지출결의 · 정산 결재에도 즉시다(확인 대상 #3).
- **결재 시트 본문**(04.1 S5 골격 · 행동 줄 · 포커스 그대로): 머리 제목 = 문서 화면 제목(`지출결의 — {프로젝트명} · {항목}` · `정산 결재 — {프로젝트명}`) + 부제 `{번호} · {기안자}`.
  본문 = 그 문서 종류의 서버 DTO가 준 KvList 행 — 지출결의: S7 읽기 칸과 같은 순서(프로젝트 · 견적 줄 · 거래처 · 증빙 종류 · 공급가액 + 계산 한 줄 + 세율 바뀜 · 지급 예정일 · 지급 방식 · **증빙**(§7-8 썸네일 72×96 + `크게 보기`) · 비고 · 기안 · 결재선) /
  정산 결재: S10 (나)의 읽기 칸. 폰 KvList 라벨 84.
- **거부 문구**: 04.1 + `박서연이 14:01에 증빙을 바꿈 · 새로 고침`(Copywriting — 추가 · 삭제 공통). 결재 시트 · 문서 화면이 연 뒤 증빙이 바뀌면 승인이 막힌다.
- **막힌 `승인`(종류가 준 `approveBlockedReason` — 정산 결재 `진행으로 바뀜 · 반려` · `지금 담당이 아님 · 새로 고침`, Copywriting 「막힘 — 정산 결재」)**: 결재 시트 · 문서 화면은 `승인` `aria-disabled` + 이유 글자(행동 줄에 자리가 있다). **결재함 PC 행 · 「내 차례」 PC 행**의 행동 셀에는 이유가 설 자리가 없으므로 `승인`을 **렌더하지 않고** 그 자리에 이유 글자(서버 원문 그대로, `--fs-sm --danger`) + 3차 `반려`(그 문서의 가능 행동에 `반려`가 있을 때 — 04.1 S4 그대로, 04.1 S6 반려 확인)를 둔다 — S1 행 행동 셀(`거래처 없음` + 3차)과 같은 「이유 글자 + 3차」 규칙(§7-3 B4, design-review D4). 폰 행은 탭 → 결재 시트라 시트 규칙을 따른다.
- **결재 시트의 `ui/` 이동**: S11이 두 번째 사용처다 — `ui/approval-sheet/ApprovalSheet`로 옮기고 결재함 · 「내 차례」가 같은 것을 쓴다(Component Inventory).

### S10. 정산 결재 (D-98 · D-79, 프로젝트 상세 + 문서 화면)

**(가) 기안 — 프로젝트 상세 `/projects/[id]` 머리 줄 (Phase 4 S3 · S7 위)**

- **자리**: 프로젝트 상태가 **정산**일 때 머리 줄 오른쪽 버튼군의 「상태 바꾸기」 자리. Phase 4 전이표의 `정산 → 완료`(「상태 바꾸기」 → `완료로 바꾸기`, 대표 · 시스템 관리자)는 **이 페이즈에서 사라진다** —
  완료는 정산 결재 승인으로만 일어난다(D-79 「전환 함수는 그대로, 호출자만 결재 승인」). 정산에서 사람이 「상태 바꾸기」로 갈 곳이 없어지므로 정산에는 「상태 바꾸기」가 렌더되지 않는다(Phase 4 `statusDestinations` 규칙 그대로).
- **정산 결재 문서가 없을 때**: 담당 PM(그 프로젝트 쓰기 권한)에게만 2차 `정산 결재 올리기`. 누르면 **확인 없이 즉시** 기안 → `정산 결재 올리기…` → 성공: 토스트(`되돌리기` = 회수, 확인 없음) + 그 자리가 3차 `정산 결재 중`(확인 대상 #4).
  미저장 편집이 있으면 비활성 + DR-6 문구(Copywriting 「막힘 — 정산 결재」). 06 S18이 같은 버튼에 완료 전 점검 막힘을 더한다.
- **문서가 있을 때**: 같은 자리에 3차 링크 `정산 결재 {상태 낱말}`(`중` · `반려` · `회수` · `승인`) → `/projects/[id]/settlement`. 보이는 사람 = 그 문서를 볼 수 있는 사람(기안자 · 결재선 · 경영관리 · 대표 — 서버 판정).
  완료된 프로젝트에도 `정산 결재 승인` 링크가 남는다(완료의 근거 문서).
- 결재선 기본값: 문서 종류 `정산 결재`의 결재선 설정(S13) — 1~3단 꺼짐 · 4단 대표 × 전사. 자기 승인 `본인 승인`.

### S11. 「내 차례」 공급 — [결재] · [막힘] (§7-4 + `ui/next-turn`, 06 UA-611)

- 첫 화면(`/`)의 「내 차례」에 항목을 공급하는 함수를 이 페이즈가 만든다(지금 홈은 빈 배열). 06 S19가 같은 함수에 경영관리 · PM 항목을 더한다.
- **[결재]**: 지금 내가 담당인 모든 문서(지출결의 · 연차 · 정산 결재) — 한 문서 한 줄, 문구 Copywriting 「표시 — 「내 차례」」. PC 행 3차 `승인`(즉시, 확인 대상 #3) · `반려`(04.1 S6 반려 확인). 그 문서에 `approveBlockedReason`이 있으면 `승인` 대신 이유 글자(`--fs-sm --danger`) + 3차 `반려`(S9 「막힌 `승인`」 — design-review D4). 폰은 두 줄(§7-4)이고
  행 탭 → 결재 시트(`ui/approval-sheet`, S9). `승인` · `반려`의 `aria-describedby` = 그 행 대상 글자(04.1 #13과 같다).
- **[막힘]**: 내가 기안한 문서 중 ① **반려**된 것 — 3차 `지출결의 열기` / `정산 결재 열기` / `연차 열기`(→ 그 문서 화면 = 고칠 수 있는 폼). 회수는 내가 한 일이라 넣지 않는다.
  ② **증빙이 무효 처리된 승인 지출결의**(사용자 결정 G1) — `[막힘] {대상} — 증빙 무효  {숫자}  증빙 올리기`, 3차 `증빙 올리기` → 문서 화면(S7)의 `증빙` 섹션(`#evidence` — 기안자에게 「하나 더」가 있다, S4). 신호 규칙: 그 문서의 무효 파일 중 가장 늦은 무효 시각이 살아 있는 파일 중 가장 늦은 올린 시각보다 나중이거나 살아 있는 파일이 0개(지운 파일은 세지 않는다 — 05-09). 새 증빙을 올리면 줄이 사라진다.
- 작성 중 문서는 넣지 않는다(목록 `작성 중` 그룹이 그 자리다 — 6줄 상한을 초안이 먹지 않게).
- 태그 순서 고정 막힘 → 오늘 → 결재 → 대기, 최대 6줄 + `더 보기 N건`(§7-4). 폰 하단 탭 `내 차례 N`의 N = 항목 수. 0이면 블록째 없다(§7-4).
- 처리한 행은 사라지고 다음 행이 올라온다(§7-7 내 차례 SUCCESS). 이 표면을 퀵 태스크로 떼어도 다른 표면은 바뀌지 않는다(Assumptions #12).

  행 금액은 **실행가**다(지출결의 금액의 기본값 · 상한이 실행가 — 06 S10과 같다, Assumptions #6).
- **키보드**: 검색 칸에서 `↓` → 목록 첫 행, 목록 안 `↑↓`(로빙, `role="listbox"` · 행 `role="option"` · 고른 행 `aria-selected="true"`), `Enter` = 1차(고른 행이 없거나 고를 수 없으면 무반응), `Esc` = 2차.

- 골격: §7-17과 같은 네이티브 `<dialog>` · `--scrim` · 포커스 트랩 · 닫힐 때 트리거로 복귀 · 폰 시트(머리 · 행동 줄 고정, 본문만 스크롤, 행동 줄 `--touch-min` · 1차가 2차의 두 배 폭 · 결과 줄은 행동 줄 위 전폭).
  검색은 서버 조회(입력 뒤 짧은 지연) — 오는 동안 이전 목록 유지. 새 시각 요소 없음(실물 `form-expense.html` `#pick` 그대로, `↵` → `Enter`) — 개정 제안 B5.

## SYSTEM.md 개정 제안 (실행 때 `DECISIONS.md` 먼저 → `SYSTEM.md` → 코드, CLAUDE.md §6 순서)

화면 하나만의 예외는 0건이다. 아홉 다 **토큰을 늘리지 않는다**(규칙 · 낱말 · variant · 문구). 거부되면 해당 표면을 이 문서에서 고친다. B8 · B9는 `/plan-design-review` D7(Round 3)이 더했다.

**B1. §6-3 보강 — 지출결의 폼의 칸 · 계산 한 줄 · 두 입구**

- 칸 순서 통화 → 공급가액 → 환율, 계산 한 줄은 **마지막 금액 칸 아래**(S3). `분할 지급` 체크박스와 회차 힌트(확인 대상 #1). 팀 비용 칸 넷(종류 · 팀 · 사용일 · 내용)과 `/expenses/new`의 늦은 문서 생성(S3).
- 계산 한 줄 원문의 꼬리 `· 서버 계산`을 지운다(P0 개정 ⑯ — 안심 글자). `%` 세율 조각은 남긴다(S5) — 06 S4 문자열이 이 원문을 따른다.
- 제출 막힘 이유 원문 `제출할 수 없음 — 증빙 없음`을 `증빙 없음 · 증빙 올리기 Ctrl+U`로(P0 이미 확정 — 실물만 옛 글), 제출 오류 꼬리 `· 값은 남아 있습니다` 삭제.
- 토스트 `되돌리기` = 확인 없는 즉시 회수이고 회수된 지출결의는 기안자의 폼으로 돌아온다 — 04.1 A4의 「연차 신청 토스트에는 되돌리기가 없다」와 나란히 한 줄로 적는다(문서 종류마다 다른 이유: 지출결의는 견적 줄에 묶여 있어 다시 제출해야 한다).
- 이유: §6-3은 칸 하나하나의 모양을 정했지만 통화 · 분할 · 팀 비용 · 문서가 생기는 시점은 비어 있다. 버린 대안: 통화 칸을 공급가액 오른쪽 한 칸에 붙이기 — 칸 폭 3종 규칙(§7-15) 밖이다.

**B2. §7-5 · 04.1 A2 의미 목록 보강 — 낱말 넷**

## Assumptions made (confirm later)

사람에게 물을 수 없는 자리에서 `SYSTEM.md` · CLAUDE.md §7 · 잠긴 결정에 가장 가까운 기본값을 골랐다. 뒤집으면 해당 표면만 바뀐다. 「확정된 결정」 표의 다섯은 여기서 되풀이하지 않는다.

1. **견적 줄 입구의 작성 중 문서는 줄 · 기안자마다 하나다**(idempotency key = 줄 id + 회차 자리 + 기안자). 다른 사람이 같은 줄에서 먼저 제출해 문이 닫히면, 늦은 쪽의 폼은 제출 막힘 ④ `이 줄에 지출결의 26001-0004 있음 · 지출결의 열기`를 받는다(서버의 1줄 1문서 판정 — 분할 줄이면 남은 실행가 칸 오류로 간다)
2. **실행가 상한은 줄의 모든 제출 문서 합에 걸린다**(분할이든 아니든 — 문서 하나도 「1회차」다). 실제 청구가 실행가보다 크면 기안 전에 실행가를 고친다(작성 중 문서는 D-66 잠금을 걸지 않으므로 고칠 수 있다). 분할 문서에만 걸면 S3 칸 오류가 분할일 때만 선다
3. **작성 중 문서는 「연결 문서」로 세지 않는다** — D-66 금액 셀 잠금 · 견적 줄 파생 상태 · 06 이중 연결 판정에 들지 않는다. 제출된 적이 있는 문서(결재 중 · 승인 · 반려 · 회수)만 센다. 회수된 문서는 번호가 있어 연결로 세고 파생 상태는 바꾸지 않는다(내가 멈춘 일이라 `미착수`로 보인다)
4. **회수 뒤 다시 제출**(확인 대상 #2)은 04.1 엔진이 반려 뒤 다시 신청(차수 +1)과 같은 경로로 `withdrawn → submitted`를 문서 종류 옵션으로 받아야 한다. 계획이 04.1 `nextStep()` · 문서 종류 등록 모양에서 확인한다 — 받지 못하면 확인 대상 #2의 「뒤집으면」 갈래로 간다
5. **증빙 1개 이상이 제출 조건이다**(S6 ⑧ — ROADMAP 기준 3 「증빙 전에는 제출 버튼이 비활성」 · §6-3 원문). 06이 `선결제`로 예외를 연다. 06의 `증빙 필수` 설정(지급 게이트)이 이 제출 조건도 끌지는 06 계획이 정한다
6. **견적 줄 부제와 골라내기 행 금액 = 실행가**(실물은 `견적 18,000,000` · 견적가). 지출결의 금액의 기본값과 상한이 실행가이고 06 S10도 실행가다. 실물대로 견적가로 되돌리면 S3 부제 · S14 행 두 자리만 바뀐다
7. **이 페이즈에는 증빙일 칸이 없다** — 부가세 기준일은 작성일(D-101 「없으면 작성일」). 06이 증빙 금액과 함께 증빙일을 더하면 S5 기준일이 따라간다
8. ~~제출 뒤 마지막 증빙 파일에는 `삭제`를 렌더하지 않는다~~ → **사용자 결정 U1(2026-09-26, PR #89)로 대체**: 결재 중에는 마지막이 아닌 파일만 삭제(마지막 파일 삭제는 06 SP-6), 승인 뒤에는 삭제 없음 · 추가 허용 · `expenses.evidence_void` 권한자의 사유 필수 무효 처리(S4)
9. **`/expenses/new`는 문서를 늦게 만든다**(첫 저장 때). 견적 줄 입구는 첨부 때문에 먼저 만든다. 둘 다 idempotency key를 싣는다
10. **폰에서 작성 중 문서 삭제는 없다**(머리 줄 오른쪽 2차가 폰에서 숨는 실물 규칙). 남은 작성 중 문서는 PC에서 지우거나 그대로 둔다(아무것도 잠그지 않는다 — #3)
11. **목록 필터는 `상태` 하나**다(§6-1 「필터 한 줄」, 원문 예의 `[내 것만]` · `[2026-09 ▾]`는 두지 않는다). 범위는 `scopeFor`가 이미 정하고, 월별 조회는 06 · 09가 필요할 때 더한다
