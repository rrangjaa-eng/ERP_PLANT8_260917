## 발견 (파일:줄)

### P1
**D1. 정본 UI-SPEC이 플랜과 어긋났다** — `05-UI-SPEC.md:267 · :548`(옛 `증빙을 더함`), `:426 · :67 · :810`(승인 문서에서 삭제 허용 — U1과 정면 충돌), F1 문구 없음. 구현자는 UI-SPEC을 정본으로 읽으므로 U1을 어기는 화면이 만들어진다 → **이 게이트에서 해소**(위 표)

### P2 — 반영 세션(Round 3)
**D2. 올리는 중 제출의 막힘 이유가 틀린 안내가 된다** — S4 · S6. 파일 완료 전에는 서버상 증빙 0개라 막힘 ⑧ `증빙 없음 · 증빙 올리기 Ctrl+U`가 뜨는데 사용자는 이미 올리는 중이다
- 수리: 올리는 행이 하나라도 있으면 1차 `aria-disabled` + `증빙 올리는 중 · 잠시 뒤 제출`(막힘 ⑧ 앞의 클라이언트 상태). S3 「떠날 때」에 올리는 행이 있으면 `beforeunload` 경고 추가

**D3. E2(`incoming/` → `evidence/` 이동) 뒤 `다시 올리기`의 뜻이 정해지지 않았다** — `05-UI-SPEC.md:263 · :414-418`, 05-04 완료 통보
- 서명 PUT은 끝났는데 완료(이동 · 확인)만 실패하는 경우가 새로 생긴다
- 수리: 문구는 `올리지 못함 · 다시 올리기` 하나로 두고, 서버가 갈래를 돌려준다 — 의도가 살아 있으면 완료 통보만 다시, 만료면 처음부터. 이동 중에도 메타는 `올리는 중…`(새 상태 없음)

**D4. 결재함 행 · 「내 차례」 행에서 `승인`이 막힐 때 이유가 설 자리가 없다** — S9 · S11(04.1 행 위). `진행으로 바뀜 · 반려` · `최종 승인 담당 아님 · 새로 고침`
- 수리: 그 셀에서 `승인`을 빼고 이유 글자(`--fs-sm --danger`) + 3차 `반려`(S1 행 행동 셀과 같은 규칙)

**D5. 무효 처리 상태가 UI Considerations 표에 없다** — `05-UI-SPEC.md:690~`
- 수리: 무효 처리의 loading(확인 버튼 pending) · error(`무효 처리하지 못했습니다 · 다시 시도`) · populated(무효 행) · a11y 행 추가. Color 매핑(`무효` → `--muted`) · 「Accent reserved for」 목록 점검

**D6. 무효 행 접근성** — 취소선은 스크린리더가 읽지 않는다
- 수리: DOM 순서 「무효」 → 파일명, 파일명에 `aria-describedby` = 2행, 결과는 기존 첨부 `aria-live="polite"`가 읽음. 폰 파일 행 3차 두 개(`크게 보기` · `무효 처리`)는 각각 `--touch-min` 영역, 둘 사이 `--s-4`(위험 동작 분리)

**D7. 새 표기 두 가지가 디자인 정본에 기록되지 않았다** — 취소선(DECISIONS 2026-09-18 #7 「취소선이라는 새 표기를 만들지 않는다」와 충돌 — U1이 사용자 결정이라 유지)과 `무효` 낱말 · 정산 즉시 승인 §7 예외
- 수리: 05-02의 개정 제안 목록에 B8(§7-10 무효 행 · §7-5 `무효` 낱말 · 충돌 기록)과 정산 즉시 승인 예외 한 항목 추가 → DECISIONS.md 먼저, SYSTEM.md 다음(CLAUDE.md §6)
