## 운영 메모

- SheetJS 보안 공지(cdn.sheetjs.com/advisories)는 레지스트리 밖이라 `pnpm audit`이 추적하지 않음 — 수동 확인 대상(B-F21).
- zip 사전 검사의 남은 한계: 크기 칸이 정직하면(로컬 = 중앙 · 합 20MB 이하) SheetJS 순수 JS inflate는 그 크기만큼만 버퍼를 잡지만 deflate 스트림 끝까지 CPU로 푼다 — 1MB 파일의 최악 풀림은 약 1GB 분량 계산(수 초)이다. 메모리는 묶였고 CPU만 남는다. SheetJS `CFB.utils.use_zlib`(네이티브 zlib)를 켜면 크기 묶음이 사라지므로 켜지 않는다(지금 저장소에 호출 0).
- 정상 엑셀 파일이 bit 3을 쓰는지: 저장소 밖 260907의 xlsx 셋(엑셀 · 다른 도구 저장)을 구조만 재 보니 bit 3 · 크기 불일치 · ZIP64 0. Java · .NET 계열 도구가 만든 xlsx는 bit 3을 쓸 수 있어 `엑셀·CSV 파일 아님`으로 거절된다(fail-closed) — 실물 견본에서 나오면 보정 PR.
- `merchant` · `nameOnDocument`는 원문 그대로라 `=` · `+` · `-` · `@`로 시작할 수 있다 — 뒤 플랜이 CSV로 내보낼 때 수식 이스케이프가 필요하다(독립 검토 P3-3 · xlsx 쓰기 `buildTextSheetXlsx`는 `t: "s"`라 안전).
- 실물 미검증으로만 갈리는 자리(독립 검토 P2-1 — 모두 거절 쪽으로 닫힘): 비씨 `국내외사용구분`이 `국내` 글자인지 코드값인지, 비씨 `합계` 줄이 취소를 순액으로 더하는지, 롯데 · 비씨 면세 줄 부가세 칸이 `0`인지 빈칸인지(빈칸이면 부가세 읽지 못함으로 파일 거절).
- 가린 픽스처는 실물 특이점(병합 셀 · 코드페이지 · 고정폭 패딩 · 실제 xls 레코드 배치)을 다 재현하지 못한다 — 실물 견본 스위트가 그 몫이다(B-F22).
