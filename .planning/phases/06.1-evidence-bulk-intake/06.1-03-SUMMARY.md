- **P-05b 값**: 플랜은 2라 적었으나 main에서 실측하니 3이었다(실행 때 3으로 따랐다).

- **S3 제목 태그**: `SidePanel`의 `title`이 문자열이라 제목 옆 상태 태그를 `KvList` 첫 줄에 두었다.
- **미리 고른 단일 행 모양**: UI-SPEC은 「현재 행(700 + 왼쪽 선)」인데 main 단일 변형은 `row.current`만 그 모양이다. 호출 화면이 `current`를 속이게 하지 않으려고 `preselected && active`일 때만 `.current`를 켠다(활성이 옮겨 가면 풀림). CSS는 무변경.
- **`retryable` 뜻**: 플랜 초안은 꼬리를 정한다고 적었으나 main이 맞다(꼬리 = 사유 끝 ` · 새로 고침`, `retryable` = 1차를 막지 않음). main 그대로 따랐다(재검토 2회차 Codex C).
- **떼기 확인 사유 칸(디자인 검토 D)**: UI-SPEC:112는 S7 사유 칸을 `ui/input`(한 줄)로 적었으나 SYSTEM §7-17 「사유형」과 기존 사유형 확인 넷(`textarea` + `approvals/decision-dialogs.module.css` `.reason`)이 여러 줄이다. SYSTEM이 이기므로 쇼케이스 표본을 같은 `textarea`로 고쳤다(오케스트레이터 결정). 06.1-06 떼기 모달도 같은 모양을 쓴다.
- **단일 거부 해제(디자인 검토 F)**: `retryable: false` 거부는 거부된 행과 다른 「고를 수 있는」 행을 가리킬 때만(또는 새로 고침) 걷힌다. 처음 구현은 활성 행이 바뀌기만 하면 걷었다(막힌 행을 눌렀다 돌아오면 1차가 풀림). 순수 도우미 `pickRejectionClears(rejectedId, next)`로 고쳤다.
- **일괄 등록 영역 안내 글(디자인 검토 G) — 미해결**: SYSTEM §7-10 「영역 한 줄」은 UI-SPEC:239 글자 그대로(`파일을 끌어 놓거나 Ctrl+U · 홈택스·카드사 엑셀·CSV 1MB`)가 쇼케이스 영역(PC 폭 480, 안내 칸 가용 약 290px)에서 2줄(320은 3줄)이 된다. UI-SPEC에 짧은 꼴이 없어 코드를 바꾸지 않고 오케스트레이터 결정을 기다린다.
- **게이트 보충**: 단일 거부 후 가리키는 행이 바뀌면 거부를 걷는다(`activate()` 한 줄 도우미) — 플랜 ⑷의 「다중 `toggleRow`와 같은 규칙」을 단일 활성 이동에 옮긴 것.
