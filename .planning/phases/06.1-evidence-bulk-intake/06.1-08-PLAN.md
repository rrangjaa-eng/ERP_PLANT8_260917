**권리 작성자 칸(C5 · E7).** 06.1-06 `documentEvidenceRights` 출력에 작성자 칸 둘(`authorAttach` · `authorDetach`)을 더한다 — UI-SPEC S7 표 작성자 줄 그대로(편집 가능 = 둘 다 · 결재 중 = 없음 · 승인 · 지급 완료 = 붙이기만 · 완료 프로젝트 = 어느 문서 상태든 없음 — `readOwnerLockState`의 `projectDone`이 작성자 칸에만 닿는다, 사용자 결정 2026-10-05 「사후 처리 열기」). 경영관리 칸(`attach` · `detach`)은 `projectDone`과 무관하게 06.1-06 그대로 — `attachEvidenceBatch`는 완료 프로젝트 문서에도 문서 상태 규칙대로 붙인다. 잠김 줄 차례는 06.1-06 그대로(완료 프로젝트 줄은 작성자에게만). `attachEvidenceAsAuthor`의 Task 1 임시 제한을 이 판정으로 바꾼다(사전 판독 · 잠금 뒤 둘 다). 문서 섹션 트리거 렌더 = `countEvidencePool` ≥ 1 ∧ (모드 `author` ∧ `authorAttach`) 또는 (모드 `registrar` ∧ 권리 `attach`).

**구매 요청(E30 · DB-10).** `evidencePickerMode`의 구매 요청 갈래: `requested_by` = 나 · 취소 아님 · 살아 있는 붙임 0 — 셋 중 하나라도 아니면 `none`(상태 `requested` 조건은 없다). 트랜잭션 안에서 구매 요청 행을 잠근 뒤 취소 · 붙임 0을 다시 본다. 확정 실행가 칸은 어떤 갈래에서도 쓰지 않는다. ⓪ P-PR 목록 파일: 내 요청 행의 행동 칸에 3차 `증빙 고르기 {N}`(모드 author이고 N ≥ 1일 때만), 누르면 같은 `pick-evidence-dialog.tsx`(문서 = 그 구매 요청 · `selection="many"`). 붙은 요청 행은 2행 `증빙 {거래처} · {합계}` — `linked.ts`에 `listLinkedEvidenceForOwners(viewer, { kind: "purchase_request", ids })`(06.1-06 `listLinkedEvidence`와 같은 읽기 판정 · 같은 DTO · 쪽마다 한 번 — PA-PRLINE)를 더한다. 목록 RSC(`page.tsx`)가 N(PA-POOLN)과 2행 자료를 한 번씩 읽어 행들에 넘긴다.
