### Auto-fixed Issues

**1. [Rule 1 - Bug] PR #255 GitHub Codex 봇 P2 (댓글 4327523903) — `useSearchParams().toString()`이 `%20`을 `+`로 바꿔 SidePanel 정확 일치가 어긋나 back 대신 replace로 빠짐**
- **Found during:** Task 1 (검증 스레드가 실행 때 반영하라고 넘김, 플랜 밖)
- **Issue:** 플랜의 클라이언트 `from` = `pathname + '?' + searchParams.toString()`은 주소창에 `%20`(또는 `~` 등 URLSearchParams가 다시 쓰는 글자)이 있으면 직전 기록 항목 URL과 글자가 달라진다. 서버가 `URLSearchParams`로 다시 만들어도 같은 문제.
- **Fix(더 작은 변경을 고른 근거):** SidePanel(공용, 금지 대상)에서 양쪽을 정규화하는 길은 공용 코드를 건드리고 모든 패널에 번지므로 버렸다. 대신 (1) 표가 `useSyncExternalStore(noSubscribe, () => window.location.search.slice(1), () => searchParams.toString())`로 수화 뒤 주소창 원문을 싣고(서버 스냅숏은 정규화 값 — `useEffect`+`setState`는 `react-hooks/set-state-in-effect` lint에 막힘), (2) `evidenceReturnHref`가 쿼리를 다시 인코딩하지 않고 `registered`만 걷는다(플랜 문구 「URLSearchParams로 다시 만든다」와 다른 점 — 허용 목록 검증은 경로와 출처에서 이미 끝나고 값은 클라이언트 라우터에만 쓰여 인젝션 면이 늘지 않는다).
- **Tests:** 단위 `쿼리 글자는 다시 인코딩하지 않는다 (%20 · ~ 보존)`, E2E `(G-06.1-40 공백 거르개)` — `q=a%20b` 출발에서 연 S8을 닫으면 `navigation.currentEntry.index`가 목록 항목으로 돌아오고(history back) 주소 원문이 `%20` 그대로. RED는 위 RED 줄.
