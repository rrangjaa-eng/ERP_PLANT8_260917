## Phase Boundary

경영관리가 홈택스·카드사에서 내려받은 엑셀 파일을 올려 증빙을 한 번에 등록하고, 각 증빙을 바로 문서에 붙이거나 팀·기획본부 전체에 공개한다. 기획본부 작성자는 공개된 증빙 중 자기 것을 골라 지출결의·구매 요청·법인카드 사용 건에 붙인다. 카드사 이용내역 파일로 법인카드 사용 건을 대사한다.

근거: 옛 시스템 확정 규칙(`.planning/research/ERP260907-CONTEXT.md`:52, 65, 67, 69, 76-79, 81, 83)이 요구사항으로 옮겨지지 않았던 것을 되살린다(`/mnt/project-files/notes/260907-gap/gap-audit.md` 6.1 행: 53, 72, 74, 77, 78, 82, 84, 166). 06 뒤 새 페이즈로 두기로 한 결정은 사용자 카드 답(2026-10-04 18:18 KST).

선행: Phase 5(지출결의·증빙 첨부 경로·`files` 표, 05-04)와 Phase 6(법인카드 사용·구매 요청·「증빙 확인」 D-602·증빙 수명 주기 06-11)이 main에 들어온 뒤 실행한다. 이 페이즈는 그 위에 「주인 없는 증빙 → 공개 → 고르기」 층을 얹는다.

범위 밖: 홈택스·위하고 API 연동(`.planning/REQUIREMENTS.md`:174, 178), 영수증 OCR(:180), 홈택스 매출 파일 읽기(아래 Deferred), 공용 카드 배정(Phase 3 후속), 홈 일감 띠(홈 화면 없음).

### 이미 확정된 입력 (다시 묻지 않음 — 옛 시스템 확정 규칙이 정본)
- 공개 범위 3단계: 어느 문서인지 알면 즉시 붙임 / 팀을 알면 그 팀만 공개 / 모르면 기획본부 전체 공개. 공개된 증빙은 금액까지 다른 팀에 보인다(사용자가 인지하고 채택) — ERP260907-CONTEXT.md:77
- 붙이기 1차 = 경영관리가 등록하면서 바로 붙임, 2차 = 작성자가 공개된 것 중 골라 붙임. 2차는 반드시 작성자 본인만, 팀장 대리 불가 — :76
- 구매 요청 2차 붙이기는 내가 올린 요청 + 공개된 증빙 + 아직 미배정일 때만. 확정 실행가는 경영관리만 적는다 — :69, :65
- 결재 중인 지출결의에는 아무도 증빙을 못 뗀다. 결재 중 붙이기는 경영관리만, 작성자는 결재가 끝난 뒤 붙인다. 결재 중에는 금액·부가세를 다시 계산하지 않는다 — :79
- 증빙을 떼면 그 줄 실행가는 예상값으로 돌아가고 뗀 기록이 남는다 — :78, EVID-04
- 일괄 등록은 여러 파일을 한 창에서, 파일 단위 전부-아니면-전무 검증 — :83
- 카드 사용 대사 순서: 승인번호 → 결제일+금액+카드 끝 4자리 → 사람이 고름 — :83
- 카드는 사람이 고르지 않고 카드사 파일이 정한다. 사람이 등록한 값과 다르면 파일이 이긴다 — :67
- 사업자번호가 있는 증빙(세금계산서·계산서·현금영수증)은 거래처가 없으면 협력사를 자동 생성하고, 보관함에 있으면 되살리고, 이름이 다르면 알림만 한다 — :81
- 「지출결의에 파일은 붙었는데 증빙 미등록」은 알림 대신 증빙 목록의 거르개(필터)로 보여 준다 — design-conflicts:13(gap-audit.md:166). 홈 일감 띠는 뺀다(아래 Deferred)

### 자료 출처와 파일 읽기 (사용자 결정 2026-10-04 18:42 KST)
- **D-6101:** **자료는 홈택스·카드사에서 내려받은 엑셀 파일을 그대로 올려 읽는다.** 위하고 내보내기, 홈택스·위하고 API는 쓰지 않는다. — **Reversibility:** costly — 출처를 바꾸면 파일 읽기 모듈을 새로 써야 한다.
- **D-6102:** **읽는 파일: 홈택스 매입 전자세금계산서(계산서 포함) 목록, 홈택스 매입 현금영수증 목록, 법인카드 이용내역 — 신한·비씨·롯데 세 곳**(사용자 결정 「그대로 세 곳」). 칸 구성은 실제 견본 파일로 확정한다. 옛 저장소 `rrangjaa-eng/ERP_PLANT8_260807`의 `docs/11_보관/2026-09-01/견본/`에 신한·비씨·롯데 이용내역과 홈택스 매입·매출 세금계산서 견본이 있고, 다섯 개 모두 OLE2 이진 .xls다(첫 4바이트 d0cf11e0 확인). 서식별 머리줄 위치·열·승인번호·카드번호 가림 여부는 `/mnt/project-files/06.1-prep/old-samples.md`에 정리했다. 옛 구현 `rrangjaa-eng/ERP_PLANT8_260907`의 `app/src/domain/receiptImport.ts`(SheetJS, 머리글 낱말로 서식 판별, 서식별 열 매핑)와 서식 명세 `ERP_PLANT8_260807/docs/09_설계/2026-09-01_들여오기-서식-명세.md`를 리서치가 참고한다(그대로 복사하지 않고 이 저장소 4계층·린트 규칙에 맞춘다). **현금영수증 매입 견본은 두 저장소에 없다** — 플래너는 현금영수증 읽기 태스크 앞에만 「견본 확보」 확인 지점을 둔다. 파일 형식은 확장자가 아니라 내용으로 판별한다. 견본에는 실명·카드번호가 있으니 이 저장소에 커밋하지 않고 가린 픽스처를 만든다.
- **D-6103:** **카드사마다 읽기 규칙을 하나씩 둔다**(공통 양식 없음 전제, 추정). 새 카드사가 생기면 규칙 하나를 더하는 구조로 한다.

### 무엇을 증빙으로 인정하나
- **D-6104:** **홈택스 전자세금계산서·계산서는 목록 한 줄로 증빙 완료다**(사용자 결정 「목록 한 줄로 인정」). 별도 PDF·사진을 붙이지 않아도 EVID-02 증빙 필수 게이트를 통과한다. 줄의 승인번호가 증빙 식별자다.
- **D-6105:** **현금영수증 목록 줄과 카드사 이용내역 줄도 목록 한 줄로 증빙 완료로 본다.** 영수증 사진은 따로 붙이지 않아도 된다(사용자 결정, 2026-10-04 19:11 KST).

### 증빙 금액
- **D-6106:** **파일에서 읽은 금액(공급가·세액·합계)이 증빙 금액이다.** 작성자는 금액을 다시 적지 않는다. 경영관리는 고칠 수 있고 전·후 값이 행동 로그에 남는다. Phase 6 D-602(PM이 첨부하며 금액을 적음)는 작성자가 직접 올리는 증빙에만 그대로 적용된다. 카드 이용내역 금액은 결제 합계로 읽는다. 세액 칸이 있는 비씨·롯데는 파일의 세액을 쓰고(면세 0 유지), 세액 칸이 없는 신한만 공급가를 `grossFromTotal()`로 역산한다(사용자 결정 2026-10-04 19:44 KST 「합계에서 역산」, Phase 6 D-607과 같음). 금액 계산은 `domain/money` 호출만 한다.

### 데이터 자리와 보이는 범위
- **D-6107:** **주인(문서) 없이 등록만 된 증빙을 담을 자리를 만든다.** 05-04의 `files` 표는 `owner_id` NOT NULL이라 공개 대기 증빙을 담을 수 없다(05 브랜치 `05-04-PLAN.md`). 새 표로 둘지 `files`를 넓힐지는 리서치·플래너가 05·06 머지 후 실제 스키마를 보고 정한다. — **Reversibility:** one-way — 마이그레이션과 기존 증빙 행 이관이 따른다.
- **D-6108:** **「팀만 공개」「기획본부 전체 공개」는 행 단위 보이는 범위가 새로 필요하다.** 지금 `scopeFor`는 all/none뿐이다(`domain/permissions/scope-for.ts`:11). 판정 단일 지점(can/visible/scopeFor/project)을 지키고 누수 스캔 테스트 생성기에 새 DTO를 넣는다. — **Reversibility:** costly — 판정 함수 계약이 바뀐다.

### 조사 뒤 사용자 결정 (2026-10-04 19:43~19:45 KST, 카드)
- **D-6109:** **엑셀 읽기는 SheetJS 공식 배포판(`cdn.sheetjs.com` tarball 0.20.3)을 쓴다.** npm `xlsx@0.18.5`는 보안 결함으로 쓰지 않고, 재배포판 `@e965/xlsx`도 쓰지 않는다. 설치 전에 plant8 환경 네트워크 허용 목록에 `cdn.sheetjs.com`이 추가됐는지 확인하는 지점을 둔다(추가는 사용자 할 일). 새 의존성 승인은 이 결정으로 끝났다.

- **D-6111:** **카드 대사에서 파일 금액과 직원이 등록한 카드 사용 금액이 다르면 파일 금액으로 덮는다.** 전·후 값은 행동 로그 설정으로 끌 수 없는 기록으로 남는다(「파일이 이긴다」 :67의 연장).
- **D-6112:** **새 이름 묶음을 승인했다:** 표 3개(증빙 등록 묶음·증빙·증빙 연결), 메뉴 키 `evidence`·`evidence.intake`, 정보 노출 항목 2개, 상태 낱말 6개, 끌 수 없는 행동 종류 1개. 구체 이름은 06.1-RESEARCH.md·06.1-UI-SPEC.md의 제안을 따른다.
- **D-6113:** **기획 PM·팀장에게 「증빙 보기」(`evidence` 보기) 권한을 시드에서 처음부터 켠다.**
