RESEARCH 「Code Examples — 바이트 판별」의 `sniff()` 본문이 이미 이 꼴이다. 서식 규칙마다 `read(rows) → { rows, errors, checksum }`, 모르는 서식은 fail closed. 날짜는 `Date`로 만들지 않고 문자열로 정규화한다(`lib/dates.ts` `seoulToday` 관례). 카드번호는 `lib/mask-tail4.ts`의 `maskTail4(last4)`로만 표시하고 뒤 4자리 밖은 저장하지 않는다.

**금액 칸 (`domain/money` 호출만 — 린트 `plant8/money-boundary`)** (`domain/money/index.ts` 202-205, 정의):
```typescript
export function grossFromTotal(totalKrw: number, vatRate: number, unit: RoundingUnit, method: RoundingMethod): number {
  const raw = totalKrw / (1 + vatRate);
  return round(raw, unit, method);
}
```
RESEARCH Pitfall 6: `round()`가 `Math.round`라 음수 합계에 그대로 부르면 취소가 원거래와 정확히 반대가 안 될 수 있다. 취소 줄은 `−grossFromTotal(|합계|, …)`로 셈한다. 서식 규칙 파일 안에서 `/ 1.1` 같은 산술을 쓰면 린트(`eslint/rules/money-boundary.mjs`)가 막으므로 항상 `domain/money` 함수를 부른다. 세율·단위·방식은 코드가 아니라 설정/코드표에서 읽는다(CLAUDE.md 0절).

### `domain/permissions/scope-for.ts` (utility, request-response) — 증빙 전용 행 범위 (D-6108)

**Analog:** 같은 파일 `scopeFor` (판정 단일 지점 유지).

**현재 계약 — 확장 금지** (`scope-for.ts` 11):
```typescript
export type Scope = { rows: "all" | "none"; includeArchived: boolean };
```
RESEARCH Pattern 4·Pitfall 3: 기존 리포지토리가 `if (opts.scope.rows === "none") return [];`(예: `repositories/vendors.ts` 14-18) 한 줄만 보고 나머지를 전 행으로 읽는다. `rows`에 셋째 값을 넣으면 타입 검사를 통과한 채 전 행이 열린다. 그래서 같은 파일에 **별도 타입·함수**(`EvidenceScope = { rows: "all" } | { rows: "published"; teamId; orgUnitId } | { rows: "none" }`)를 더하고 `Scope`는 건드리지 않는다. 소속은 `repositories/team-memberships.ts` `findMembershipAtDate(viewer, userId, date)`(11-23행)를 오늘(서울) 날짜로 부른다. 팀 이력이 없으면 team null → 공개 증빙이 안 보이게 한다.

**메뉴 판정 방식 그대로** (`scope-for.ts` 49-55):
```typescript
  const canFn = deps?.can ?? defaultCan;
  const [canView, canViewArchive] = await Promise.all([
    canFn(viewer, menu, "view"),
    canFn(viewer, ARCHIVE_MENU, "view"),
  ]);
  return { rows: canView ? "all" : "none", includeArchived: canViewArchive };
```
이 파일은 위험 경로(`domain/permissions/`)라 별도 PR로 떼어 사용자가 머지한다(CLAUDE.md §4). 리포지토리는 `switch(scope.rows)`에 `never` 검사로 세 갈래를 다 다룬다. 새 판정 단위 테스트는 `test/unit/permissions/scope-for.test.ts`(tracked)에 케이스를 더한다. 행 축 누수 통합 테스트는 누수 스캔이 못 본다(스캔은 칸 축만 봄) — 새 통합 테스트가 필요하다.

## Shared Patterns

### 판정 단일 지점 + DTO 투영 + 이중 게이트
**Source:** `domain/permissions/can.ts`, `visible.ts`, `project.ts`, `scope-for.ts`, `dto-registry.ts`; 사용 예 `domain/vendors/index.ts`·`domain/reserves/index.ts`
**Apply to:** 모든 새 domain 모듈과 리포지토리 호출부
domain은 `can(viewer, menu, action)`(메뉴)과 `visible(viewer, infoItem)`(정보 항목) 둘을 보고, 행 범위는 `scopeFor` 계열 한 곳에서만 만든다. DTO는 `DtoSpec`(필드 → 정보 항목)에서 `project()`로만 투영하고 `registerDto`로 등록해야 누수 스캔이 따라온다(`dto-registry.ts` 20-30: 중복 이름·빈 정보 항목 목록은 예외). 화면에서 숨기는 것은 통제가 아니다(CLAUDE.md 2절).

### 4계층과 린트 경계
**Source:** `eslint.config.mjs` 41-77, `eslint/rules/repository-viewer-param.mjs`, `no-row-type-escape.mjs`, `money-boundary.mjs`, `require-action-client.mjs`
**Apply to:** 전 파일
`app/ → domain/ → repositories/(viewer 첫 인자) → db/`; domain은 `@/db`를 import할 수 없어 트랜잭션은 `lib/db-transaction.ts`의 `withTransaction`을 거친다(`lib/db-transaction.ts` 3-15행 주석). Row 타입을 DTO로 노출하지 않는다. 금액 산술은 `domain/money` 안에서만. Server Action은 `authedActionClient`만.

### 트랜잭션·잠금 규약
**Source:** `lib/db-transaction.ts` 41-49 (`withTransaction`), `repositories/reserve-entries.ts` 14-24, `repositories/settings.ts` 189-193
**Apply to:** 등록 서비스, 붙이기·떼기, 거래처 자동 생성, 카드 대사
`SET LOCAL lock_timeout = '5s'` + 시간 초과를 UserFacing 오류로 변환. 잠금은 항상 id 오름차순. 키가 없는 행의 직렬화는 `pg_advisory_xact_lock(hashtextextended(...))`. 규약 전문은 `docs/ARCHITECTURE.md` §4-8 (필요할 때 Read, import 금지).

### 오류 문구 (명사형 · 원인+다음 행동)
**Source:** `lib/actions/user-facing-error.ts`, `lib/db-transaction.ts` 16행 (`"다른 저장이 끝나지 않음 · 잠시 뒤 다시 저장"`), `lib/actions/payload-size.ts` 18행, `test/unit/error-copy-noun-style.test.ts`
**Apply to:** 모든 사용자에게 보이는 오류·거절 문구
`UserFacingError` 서브클래스만 화면까지 전달되고 그 외 Error는 `handleServerError`가 가린다(`lib/actions/client.ts` 주석). 새 거절 문구(UI-SPEC Copywriting)는 `error-copy-noun-style` 테스트를 통과해야 한다.

### 낙관적 잠금 갱신 + 재전송 멱등
**Source:** `repositories/reserve-entries.ts` 93-131 (`insertEntry` `onConflictDoNothing`, `updateEntryIfVersionMatches`)
**Apply to:** 증빙 공개 범위 저장, 금액 고침, 일괄 등록 `dedupe_key`
화면이 만든 uuid를 id로 싣고 재전송은 `onConflictDoNothing`으로 무해하게, 수정은 `version` 일치 조건부 갱신으로 충돌을 null로 돌린다.

### 코드표 문자열 값 (FK 없음)
**Source:** `db/schema/reserve-entries.ts` 21-22 `evidenceType`, `domain/seed/index.ts` `EVIDENCE_TYPE_CODES`(69행~, `tax_invoice`·`card_receipt` 등, 카드 전표 `taxRule: { ruleKind: "none" }`)
**Apply to:** 증빙 종류 분기
라벨은 관리자가 바꾸므로 라벨 문자열로 분기하지 않고 코드값(`value`)이나 서식 키로 분기한다(RESEARCH Anti-Patterns).

### 한국 시간
**Source:** `lib/kst-date.ts` (`kstToday`, `addDays`), `lib/dates.ts` (`seoulToday`)
**Apply to:** 파일 날짜 정규화, 소속 조회 기준일, 이력 표시
`Date`로 만들지 않고 날짜 문자열로 다룬다. `current_date`를 쓰지 않는다(CLAUDE.md 4절).
