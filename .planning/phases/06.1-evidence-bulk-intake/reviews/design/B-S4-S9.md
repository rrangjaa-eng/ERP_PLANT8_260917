### DB-2 · P1 · 확신 8 — E45 다중 붙이기의 화면 계약이 없다(이 검토가 정한다)
- **대상:** `06.1-UI-SPEC.md:387-413`(S5) · `:207`, `:253` · `06.1-08-PLAN.md` truth 「S5 행 … 1차 `이 증빙 붙이기`」
- **근거:** 코디네이터 지시 「E45 다중 선택 모달의 모양은 이 검토가 정한다」 · eng-review `:65` E45 수용(전부-아니면-전무) · UI-SPEC `:485`(클라이언트는 더하기를 포함해 금액을 계산하지 않음) · eng E34(후보 `LIMIT 20`) · `SYSTEM.md:1215`, `:1004`(행동 줄).
  - **주의:** E45의 출처는 옛 시스템 대조(M6)다. 사용자 지시에 따라 이 지적은 옛 화면을 근거로 삼지 않는다. 다중 선택을 넣을지 여부 자체는 E45 수용에 기대고, 넣는다면 모양은 아래 계약을 따른다. E45를 빼기로 하면 DB-2는 통째로 지운다(DB-1의 `selection="many"`도 함께).
- **문제:** 영수증 다섯 장이면 모달을 다섯 번 열고 닫아야 한다. 다중 선택 모양·키·문구·부분 실패·검색과 선택의 관계가 모두 비어 있다.
- **수정안(S5에 넣을 계약):**

```
PC 모달 480 (지출결의 · 구매 요청 문서, 다중)          폰 375 시트
┌ 증빙 고르기                                  ✕ ┐     ┌ 증빙 고르기                    ✕ ┐
│ 26001-0004 · 후보 14                            │     │ 26001-0004 · 후보 14              │
│ [(검색) 거래처·금액·날짜                      ]  │     │ [(검색) 거래처·금액·날짜        ] │ 40
│ ☑ 10-02 (주)에이원                  1,100,000   │     │ ☑ 10-02 (주)에이원     1,100,000 │ ≥44
│        세금계산서 · 기획1팀 공개                │     │     세금계산서 · 기획1팀 공개     │
│ ☑ 10-02 스타벅스 강남R점                12,500   │     │ ☐ 09-28 (주)비투엘       550,000 │
│        카드 · 신한 1234 · 본부 공개             │     ├───────────────────────────────────┤
│ ☐ 09-28 (주)비투엘                    550,000   │     │ [취소] [   증빙 붙이기 2       ]  │ 44
│        세금계산서 · 본부 공개                    │     └───────────────────────────────────┘
│ 고른 2건                                        │ ← 결과 줄(--text-aux --text-muted)
│                 [취소 Esc] [증빙 붙이기 2  Enter] │
└─────────────────────────────────────────────────┘
```

  - **선택 방식은 문서 종류가 정한다**(사용자가 정하지 않는다). 지출결의·구매 요청 = 여러 개(`selection="many"`). 카드 사용(S9) = 하나(`selection="one"`). 카드 사용 한 건은 카드 줄 하나이기 때문이다(E23 「같은 카드 줄만」). S4(증빙 하나 → 문서 하나)도 하나.
  - **1차 문구:** 여러 개는 `증빙 붙이기 {n}`(n = 고른 수, `일괄 저장 3` 꼴, §8-1). 하나일 때는 지금 문구(`이 증빙 붙이기` / `이 문서에 붙이기`) 그대로. n = 0이면 `aria-disabled` + info `고른 후보 없음`(지금 `:253` 그대로).
  - **결과 줄:** `고른 {n}건`만 쓴다. 고른 것의 합계는 쓰지 않는다 — 클라이언트 더하기 금지(`:485`). 붙인 뒤 문서 「증빙 금액」이 서버 합으로 보여 준다.
  - **처음 상태:** 1위 행 하나만 미리 고른다(DB-5의 예외는 미리 고르지 않음). 대개 `Enter` 한 번이면 끝난다(지금 의도 유지).
  - **검색과 선택:** 고른 행은 검색어가 바뀌어도 목록 맨 위에 남는다(체크된 채). 검색 결과는 그 아래에 붙는다. `LIMIT 20` 밖의 증빙도 검색으로 찾아 더할 수 있다.
  - **상한:** 한 번에 20건(서버 상수). 21번째는 체크되지 않고 막힘 자리에 `20건 상한 · 나눠 붙이기`.
  - **키:** 열리면 검색 칸에 포커스(DB-4). `↓`(또는 `Tab`) → 목록으로 이동. 목록은 탭 정지 하나에 로빙 `↑↓`. `Space` = 체크 토글. `Enter`(검색 칸이든 목록이든) = 1차. `Esc` = 닫기.
  - **ARIA:** `role="listbox" aria-multiselectable="true"`, 행 `role="option" aria-selected`, 2행은 `aria-describedby`. 막힌 행은 `aria-disabled="true"`.
  - **전부-아니면-전무:** 한 건이라도 서버가 거부하면 아무것도 붙지 않는다. 막힘 자리에 `다른 사람이 먼저 붙임 · {거래처} 외 {k}건`(경합) 또는 서버 이유 한 줄. 후보를 다시 불러오고, 아직 붙일 수 있는 선택은 체크된 채 남긴다.
  - **성공:** 모달이 닫히고 문서 섹션에 읽기 행 n개가 생긴다. 포커스는 트리거로 가고, 트리거가 사라졌으면 첫 새 읽기 행으로 간다. 토스트 없음.
  - **폰:** 행동 줄은 2차 `취소` 왼쪽 + 1차 오른쪽(1차가 두 배 폭, DB-6). 체크박스 시각 크기는 16이고, 누르는 영역은 행 전체(≥44)다.
- **사용자 결정 필요:** 아니오(E45 수용 범위). 단 모양은 DB-1의 G-4 승인에 같이 실린다. E45가 옛 근거로만 섰다고 코디네이터가 판단하면, 「다중 붙이기를 넣는가」만 사용자에게 묻는다.

## 사용자 여정 점검 (관점 3)
- **작성자 2차:** 문서 → `증빙 고르기 N` → (검색 칸 포커스, 1위 미리 고름) → `Enter`. 지금은 한 장씩만 된다 → DB-2. 결재 중에는 숨김 ✅, 승인 뒤에는 붙이기만 되고 떼기는 없다 → DB-3. 고른 뒤 문서가 `확인 전`이 되는 것이 보여야 한다 → DB-7.
- **경영관리 1차:** S2 `붙이기` → S4 → `Enter`. 결재 중 문서가 1위일 때 위험하다 → DB-5. `evidence_attach` 키가 없으면 결재 중 후보가 숨어야 한다 → DB-3. 짝 없는 카드 줄의 두 행동 → DB-9.
- **결재 중 잠김:** 표는 좋다. 승인·회수·완료 프로젝트 축이 없다 → DB-3, DB-11.
- **대리 등록:** 06 폼 재사용은 좋다. 언제 서는지(E5) → DB-9.
- **「문구 없이 이해되는가」:** 잠김 줄은 섹션당 한 줄 원칙을 지킨다. 작성자 붙임을 문장 대신 2행 `{이름} 고름`으로 가르는 것(DB-7)이 유일한 새 글자다. **「하지 않아도 될 결정」:** 선택 방식(하나/여럿)은 문서 종류가 정하고(DB-2), 짝 없는 카드 줄의 행동은 후보 수가 정한다(DB-9) — 사람이 고르지 않는다.
