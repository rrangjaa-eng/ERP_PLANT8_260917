### F2 [P2 · 8] 1MB를 넘는 파일은 서버의 친절한 거절 문구에 닿지 못한다
- 04:43: 「파일 크기는 서버가 `File.size`로 직접 잰다 … 1,000,000바이트를 넘으면 바이트를 읽기 전에 `{n.n}MB · 1MB 초과 …`」. 02:249의 behavior는 1,000,001바이트 케이스다. UI-SPEC:219의 예는 `{1.4MB} · 1MB 초과`다.

- 고칠 곳: (a) 06.1-02에 xlsx를 import하지 않는 순수 상수 모듈 `domain/evidence-import/limits.ts`(`EVIDENCE_IMPORT_MAX_BYTES` · 문구 함수)를 두고 `registry.ts`가 그것을 다시 내보낸다. `registry.ts`를 클라이언트가 import하면 SheetJS가 클라이언트 번들에 딸려 온다. (b) 06.1-05 Task 1 ⑤: 「`file.size > EVIDENCE_IMPORT_MAX_BYTES`이면 액션을 부르지 않고 같은 거절 문구로 결과 행」을 넣고 E2E에 1.4MB 버퍼 케이스를 더한다. (c) 액션이 413 · 일반 오류로 끝나면 결과 행에 `거절 · 처리 중 오류`를 그리게 한다(빈 행 금지). 서버 검사는 그대로 둔다(심층 방어).

### F3 [P2 · 8] 세율 사전 조회와 `parseWorkbook`의 순서가 서로 맞물린다 (닭과 달걀)
- 02:175: `parseWorkbook(bytes, { vatRatesFor })` — 「… 서식 규칙 → 오류 있으면 거절 → 행 상한 → 열쇠 · 금액」. 금액(신한 역산)이 파싱 함수 **안**에서 동기 `vatRatesFor`로 셈해진다.
- 04:173: 「⑶ `parseWorkbook(bytes, { vatRatesFor })` … ⑷ 트랜잭션 **전** 사전 조회: … (Task 2의 세율 · 카드)」. 04:214: 「역산이 필요한 줄의 날짜 집합마다 `loadTaxRates(date)`를 한 번씩 읽어 `vatRatesFor(date)`로 넘긴다」.
- 날짜 집합은 파싱한 뒤에야 알 수 있는데, 파싱이 이미 세율을 요구한다. 실행자는 두 번 파싱하거나 가짜 세율로 한 번 돌리는 즉석 우회를 하게 된다.
- 고칠 곳(02 Task 1 ④ · 04 Task 1 ②): 진입을 둘로 나눈다. `parseWorkbook(bytes)` → `{ ok, format, lines, rateDates }`(금액 미결정 · 열쇠 포함), `finalizeAmounts(lines, ratesByDate)` → 등록용 줄. 「세율이 없는 날짜를 물으면 던진다」 단위 케이스를 둔다. 04 ②는 「⑶ 파싱 → ⑷ `rateDates`로 `loadTaxRates` → ⑸ `finalizeAmounts` → 사전 조회(sha · 카드) → tx」 순서로 고친다.

- **U3 (F7):** 비씨 `금액SIGN코드 = "-"` 줄 — ⒜ 파일 거절(권장, 견본 대기) ⒝ 음수로 뒤집어 등록 + 확인 필요.
- **U4 (F13):** 회사 사업자번호를 설정으로 두고 홈택스 파일의 0행 번호와 대조할지. 플랜 안 수정(파일 내부 일관성 · 자사 줄 거절)만으로도 대부분 막힌다. 설정 키를 새로 만들려면 D-6112 밖이라 승인이 필요하다.
