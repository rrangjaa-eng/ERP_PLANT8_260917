SYSTEM §1-4 역할 이름만 쓴다. 원시 토큰(`--g-*` `--n-*`) 직접 참조 금지.

Accent reserved for (SYSTEM §1-3 「다섯 곳」 안에서만):
1. 행동 링크(① 행동 링크) — 3차 링크 `참여자 더하기` · `되돌리기` · `다시 시도` · `새로 고침`의 `--text-link` 글자와 밑줄(`떼기`는 위험 색 글자라 제외)
2. 1차 버튼(③) — S3 `참여자 더하기 N` 하나
3. 포커스 링(④) — `:focus-visible` 2px `--focus`가 걸리는 이 페이즈의 컨트롤(select · 3차 링크 · 체크박스 행 · 버튼)

「모든 컨트롤」 같은 포괄 표현 없음. 새 색 0개, 새 틴트 0개, 틴트 위 틴트 0개(규칙 2).

## S1. 계급 화면 — 「보는 범위」 열

**결정:** `work_scope`(업무 범위)와 똑같이 **PC는 네이티브 `<select>` 즉시 저장 · 실패하면 값 되돌림, 폰은 읽기 글자**(D-6201 · 04-27 선례 `RoleWorkScopeCell`).

| 항목 | 계약 |
|---|---|
| 열 머리글 | **「보는 범위」** (기존 「업무 범위」는 이름 · 값 그대로 둔다 — 사용자가 이미 아는 낱말을 바꾸지 않는다). 낱말 구분 근거: 업무 범위 = 하는 일의 범위(쓰기), 보는 범위 = 보이는 행의 범위 |
| 열 자리 | 「업무 범위」 바로 오른쪽, 「시드 여부」 앞. 열 순서가 폰 접힌 줄 순서다 |
| 폰 우선순위 | **P2**(접힌 줄). P1은 이름 · 업무 범위 · 동작 3열이 이미 차 있고 P1은 최대 3열이다(SYSTEM §7-3). 계급 화면은 폰에서 읽기 전용이다(2026-10-03 사용자 결정) — 입력 칸은 폰에서 CSS로 숨고 값 글자만 보인다 |
| 선택지 (순서 고정) | `전사` · `본부` · `팀` · `본인` (값 `company` · `org_unit` · `team` · `own`). 넓은 범위 → 좁은 범위 순. 선택지에 설명 · 괄호를 달지 않는다(안내 문구 최소) |
| 접근 이름 | `aria-label="{계급 이름} 보는 범위"` (업무 범위 셀과 같은 꼴) |
| 폰 읽기 글자 | 값 그대로 `전사`/`본부`/`팀`/`본인`. 접힌 줄은 라벨 없이 값만이라(SYSTEM §7-3) 업무 범위 `전사`와 겹쳐 읽힐 수 있으나, 폰은 읽기용 확인 화면이라 수용한다(가정 A-1) |
| 저장 | 값을 고르면 곧바로 서버 액션(`setRoleViewScopeAction({ id, viewScope })`)을 부른다. **확인 창 없음 · 저장 버튼 없음**(SYSTEM §7-2 설정 즉시 저장 · §7-13). 성공 표시는 값 자체(토스트 · 완료 글자 없음). 다음 요청부터 반영(성공 기준 4)이라 화면에 반영 안내 문구를 두지 않는다 |
| 실패 | `onError`에서 select 값을 저장된 값으로 되돌리고 select 아래 한 줄 `--text-aux --status-danger`(기존 `registeredHint`와 같은 자리). 문구는 서버 `serverError` 원문, 없으면 `저장 실패 · 다시 시도` |
| 비활성 | 보관된 계급이면 select `disabled`(업무 범위 셀과 같다). 쓰기 권한 없음은 업무 범위 셀과 같은 동작(서버가 거부 — 이 페이즈가 둘의 렌더 조건을 바꾸지 않는다, 가정 A-14) |
| 새 계급 | 「계급 추가」 옆 패널(`RoleForm`)에 보는 범위 칸을 **더하지 않는다** — 기본값 `팀`으로 채운다(D-6203 「새 계급 기본 team」, 사용자 결정 최소). 만든 뒤 목록에서 고른다 |
| 시드 계급 | 시드 계급도 select로 바꿀 수 있다(업무 범위와 같음) |

## S2. 프로젝트 상세 — 「참여자」 섹션

**배치:** `QuoteLedger` children 순서 `… 법인카드 사용` → **`참여자`** → `차수`(260907 시안 `project-detail.html` 순서와 같다). `DetailScreen.Section title="참여자"` — 위 1px `--border-row`로 시작, 탭 없음, 카드 아님.
**데이터:** `CardUsageSection`처럼 독립 컴포넌트로 가둔다 — 이 섹션의 읽기 실패가 원장 · 매출 · 차수 섹션을 막지 않는다(RESEARCH Q7).

### 레이아웃 (PC ≥ 700)

```
참여자                                                              ← DetailScreen.Section 제목 (--text-subtitle)
┌─────────────────────────────────────────────────────────────────┐
│ 이름                     팀                         동작         │ ← 머리글 (--surface-head, --text-aux --text-muted 600)
├─────────────────────────────────────────────────────────────────┤
│ 이서연                   마케팅팀                    떼기          │ ← 행 44, 동작 = RowAction danger
│ 박민준 퇴직              전략팀                      떼기          │ ← 퇴직 글자 태그(muted) — 이름 칸 안
│ 최지우                   —                           떼기          │ ← 본부 없는 사람(대표)은 팀 `—`
└─────────────────────────────────────────────────────────────────┘
참여자 더하기                                                         ← 표 아래 3차 한 줄 (권리 있고 비잠금일 때만)
```

- 표는 `StaticTable`(읽기). 캡션(시각 숨김) `참여자`. 열: **이름(p1) · 팀(p2) · 동작(p1)**. 금액 열이 없는 표라 P1에 이름 + 동작 둘을 둔다(SYSTEM §7-3 P1 규칙 둘째 줄 — 비는 금액 자리를 행동에 쓴다).
- **이름 칸:** 이름 + (해당할 때) 글자 태그 한 개. `퇴직`(퇴직일이 오늘 이전) 또는 `보관됨`(보관된 사람) — `StatusTag variant="text"`(`--text-tag` 600 `--status-muted`). 이름 줄바꿈 허용(`keep-all`). 단 폰(<700)에서는 이름 칸을 한 줄 말줄임으로 두고 전체 이름은 `title`로 준다(행 두 줄 이내). 태그는 이름 뒤 `--s-1`. 태그는 표시일 뿐 행동을 막지 않는다 — **퇴직 · 보관된 참여자도 `떼기`는 된다**(D-6222: 자동으로 떼지 않으니 정리는 사람이 한다).
- **팀 칸:** 오늘(KST) 발령 팀 이름 한 줄 말줄임, 팀 없으면 `—`. 본부는 보이지 않는다(후보 규칙 근거일 뿐 화면 정보가 아니다).
- **정렬:** 붙인 시각 오름차순(방금 더한 사람이 맨 아래에 나타난다). 페이지 나눔 없음(회사 10→30명 상한, 한 프로젝트 참여자는 그 이하).

### 떼기 — 확인 창 대신 되돌리기 (SYSTEM §7-8 「04.2-09」 규칙 그대로)

떼기는 보관일 뿐이고 다시 붙이면 되살아나므로(D-6209) **확인 모달 없이** 바로 뗀다. 같은 값으로 돌릴 수 있는 목록 행 삭제의 기존 계약을 쓴다.

- 누르면 바로 서버 액션 → 행이 사라지고 표 **위**에 결과 줄 `role="status"`, `--text-aux --text-muted`: **`{이름} 뗌`** + 3차 **`되돌리기`**. 화면 이동이 없어 §7-6 토스트가 아니다.
- `되돌리기`: 같은 사람을 다시 더한다(보관 해제). 포커스는 `되돌리기`로 간다(지운 행의 `떼기`가 사라졌으므로). 되돌리면 행이 같은 자리(붙인 시각 순)에 돌아오고 포커스는 그 행의 `떼기`가 받는다. 줄은 마지막으로 뗀 한 명만 보이고, 다른 사람을 떼면 그 사람의 줄로 바뀐다(쌓아 두었다가 맨 나중 것을 보임 — `delete-undo.tsx`와 같은 규칙).
- `되돌리기` 실패: 줄 글자가 `--status-danger` **`되돌리기 실패 · 다시 시도`**(연결 실패). 서버가 거부하면(그 사이 프로젝트가 완료됨 · 그 사람이 담당 팀으로 옮김) **`되돌리기 실패 · {원인}`**이 되고 `되돌리기`를 치운다 — 다시 눌러도 같은 실패다.
- `떼기` 자체 실패: 그 행 안(`떼기` 옆 한 줄)에 `떼기 실패 · 다시 시도`(연결). 서버 거부는 서버의 「원인 · 다음 행동」 줄을 그대로 쓴다(예: `완료 프로젝트 · 참여자 잠김`) — 이때 `떼기`는 `aria-disabled` + 같은 이유(`disabledReason`)로 남는다(포커스를 잃지 않게 — `DeleteHoliday`와 같은 방식).
- `RowAction danger`: 맨 끝, `--status-danger` 글자 — SYSTEM §7-19(행의 보관 행동은 위험 색 글자 링크). 이 행에는 동작이 하나뿐이라 간격 규칙은 무관하지만 의미를 맞춘다. **붉은 버튼 면 없음.**
- 폰: `떼기`도 **보인다**(44 누르는 영역). 더하기만 「더보기」로 모은 REPORT.md:77과 어긋나지 않는다 — 폰에서 더할 수 있는데 뗄 수 없으면 되돌릴 길이 없다(가정 A-12).

## S3. 「참여자 더하기」 — 다중 선택 고르기

**종류:** `ui/pick-dialog`의 **다중 선택 변형**(SP-62-1). PC 가운데 모달 `--dialog-w` 480 + `--scrim-dialog`, 폰 아래 시트. 새 컴포넌트가 아니다(단일 선택 `PickDialog`와 같은 틀 · 검색 · 서버 조회) — **옆 패널이 아니다**: 옆 패널은 「한 건을 등록·수정하는 폼」이고 이 일은 목록에서 사람을 고르는 일이다(SYSTEM §7-8 표).

| 슬롯 (위 → 아래) | 계약 |
|---|---|
| 제목 | `참여자 더하기` (= 실제 동작, `--text-subtitle`) |
| 부제 | 프로젝트 이름 한 줄(`--text-aux --text-muted`) |
| 검색 칸 | 첫 포커스. 접근 이름 `사람 검색`. 서버 조회 · 입력 뒤 짧은 지연. 이름 · 팀으로 찾는다 |
| 목록 | `role="listbox"` `aria-multiselectable="true"`, 행 `role="option"`. 행 = 네이티브 체크박스(`accent-color: var(--native-accent)`, 행 전체가 클릭 영역) + 이름(`--text-body`) + 2행 팀 이름(`--text-aux --text-muted`, 팀 없으면 `—`). 한 번에 50행까지(넘으면 목록 끝 한 줄 — 기존 규칙). 후보는 서버가 이미 거른 사람만 보내므로 **모든 행이 고를 수 있다**(비활성 행 · 이유 2행 없음) |
| 결과 줄 | 고른 사람이 없으면 줄 없음. 1명 `{이름} 선택`, 2명 이상 `{이름} 외 {N-1}명 선택`(N = 고른 사람 전체 수, 이 문서 모든 곳에서 같다. `--text-aux --text-muted`) |
| 행동 줄 | 왼쪽 → 오른쪽: 막힘 이유 · 2차 `취소 Esc` · 1차 **`참여자 더하기 {N}`**(`Enter` kbd — N은 고른 수, 0이면 숫자 없음). 폰은 이유가 윗줄 전폭 · 버튼 줄 `--touch-min` · 1차가 2차의 2배 폭 |

- **1차 비활성:** 고른 사람 0명 → `aria-disabled` + 이유 **`고른 사람 없음`**(`--text-aux`, 막힘이 아닌 정상 상태이므로 `reasonTone="info"` = `--text-muted`). 다음 한 수 3차는 두지 않는다(목록이 바로 위에 있다).
- **키보드:** 검색 칸 `↓` → 목록 첫 행 · 목록 안 `↑` `↓` 이동 · **`Space`로 체크 토글** · `Enter` = 1차(고른 사람이 없으면 무반응) · `Esc` = 2차. 키보드만으로 끝낼 수 있다.
- **전체 취소 규칙:** 한 명이라도 규칙에 어긋나면 서버가 전체를 거부한다(260907 동작 · 사용자가 일부만 붙은 상태를 보지 않게). 거부는 행동 줄 왼쪽 막힘 자리에 붙고 다이얼로그는 닫히지 않는다(토스트 없음, SYSTEM §7-17).
- **닫힘 · 포커스:** 성공하면 바로 닫는다(결과는 표가 보인다). 포커스는 여는 요소로 — 트리거가 사라졌으면(EMPTY의 버튼) 표 아래 3차, 폰은 「더보기」 토글. 취소 · Esc는 아무 일도 일어나지 않고 여는 요소로 돌아간다.
- **후보 계산은 서버**(D-6211 · D-6221 — 클라이언트 목록을 믿지 않는다): 담당 팀의 본부 사람 + 본부 없는 사람 중 **대표 계급만** − 시스템 관리자 − 퇴직 · 보관 − 이미 붙은 사람 − 담당 팀 사람. 이 페이즈 UI는 규칙을 다시 계산하지 않는다.

## S4. 머리 줄 「더보기」(폰) 안의 `참여자 더하기`

- `HeaderCopyActions`(프로젝트 상세 머리 줄 — `quote-table.tsx`)의 **자식 하나**로 `참여자 더하기`를 더한다(2차 버튼 모양 · 높이 `--touch-min` 44 — 「더보기」로 펼친 「복사해 새 차수」 · 「프로젝트 복사」와 같은 클래스 `headerTouchButton`). 폰(<700)에서만 보이고 PC(≥700)에서는 **렌더는 하되 CSS로 숨긴다** — PC의 더하기는 표 아래 3차 한 곳뿐이다(같은 행동이 두 곳에 보이지 않는다). PC에서 숨은 자식 때문에 머리 버튼 줄 간격에 빈 틈이 생기지 않는지 DOM으로 확인한다(구현 확인 항목).
- 보이는 조건은 S2 `canEdit`과 같다. 권리 없음 · 완료 프로젝트면 자식을 그리지 않는다. 자식이 하나도 없으면 `HeaderCopyActions`가 아무것도 그리지 않으므로 「더보기」 토글도 없다(기존 계약).
- 누르면 S3(시트)이 열린다. 닫히면 포커스는 「더보기」 토글 또는 펼침 안의 이 버튼으로 돌아간다.

- **선택지 순서(고정):** `기안자 팀` · `행사 담당 팀` · `기안자 본부` · `전사` · `특정 부서`. 팀 단위끼리 붙인다. (`z.enum` 튜플을 이 순서로 선언한다 — 연차용 상수에 스프레드로 덧붙이면 맨 끝이 된다. 순서가 곧 select 순서이므로 계획이 명시적 튜플로 쓴다.)
- **연차 결재선에는 이 선택지가 없다.** 행사에 안 매이는 문서 종류에는 고를 수 없다(D-6215 · RESEARCH Pitfall 5). 연차 select는 지금 4값 그대로. 숨김이 아니라 **처음부터 목록에 없다** — 비활성 항목이나 안내 문구를 두지 않는다.
- **특정 부서 칸:** `행사 담당 팀`을 고르면 「특정 부서」 칸은 `기안자 팀`과 같이 **비활성**(활성은 조직 범위가 `특정 부서`일 때만 — 기존 규칙, 저장 전 화면 값으로 바로 바뀐다).
- **1단 기본값:** 코드 기본값 `행사 담당 팀`(D-6216). 저장 행이 `기안자 팀`으로 있는 환경은 그대로 `기안자 팀`을 보인다(D-6225 — 자동 이행 없음, 체크포인트에서 사람이 확인).
- 단계 저장은 기존 계약 그대로 `N단 저장` 하나(SYSTEM §7-2 예외 단락).
- 경고 줄: `행사 담당 팀`은 대상 부서 칸이 없어 설정 경고(`listApprovalRouteSettingWarnings`)가 없다 — 새 문구 0.
