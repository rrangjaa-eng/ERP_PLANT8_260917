### advisory 잠금 키 헬퍼 -> `repositories/seats.ts` (repository, lock)

**Analog:** `repositories/leave-requests.ts:38-43`
```ts

export async function lockLeaveDrafter(viewer: Viewer, drafterId: string, tx: DbOrTx): Promise<void> {
  void viewer;

}
```
복사 규칙: `viewer` 첫 인자 + `void viewer;`, `tx: DbOrTx` 필수, 키는 문자열 해시(`hashtextextended(키, 0)`). import는 `leave-requests.ts:1,3,5`와 같다(`sql` from drizzle-orm, `DbOrTx` from `@/db/client`, `Viewer` type).
새 함수 `lockSeatKeys(viewer, keys: string[], tx)`는 키를 하나씩 순서대로 잠근다. 키 문자열은 `"seat:person:"+id` -> `"seat:admin:last"` -> `"seat:team:"+id` -> `"seat:division:"+id`, 같은 계층은 id 정렬(RESEARCH 동시성 설계 표). 정렬 함수는 순수 단위 테스트 대상(Pitfall 3).

### 트랜잭션 + tx 스레딩 -> people/org/matrix 쓰기 진입점 (service, CRUD)

**Analog:** `lib/db-transaction.ts:16,41-50` (`withTransaction`: 콜백 전 `SET LOCAL lock_timeout='5s'`, 시간 초과를 `다른 저장이 끝나지 않음 · 잠시 뒤 다시 저장`으로 변환)
```ts
export async function withTransaction<T>(fn: (tx: DbOrTx) => Promise<T>): Promise<T> {
  return withTimeoutConversion(() =>
    db.transaction(async (tx) => {
      await tx.execute(sql`SET LOCAL lock_timeout = '5s'`);
      return fn(tx);
    }),
  );
}
```
domain은 `db`를 import하지 못한다(boundaries). `withTransaction`이 준 `tx`를 repositories 함수에 인자로 넘기기만 한다.

**수정 대상 현재 모양(전역 db 한 문장씩):**
- `repositories/users.ts:57-59` `updateUserRole(viewer, userId, roleId)` -> `tx: DbOrTx` 인자 추가(`insertLeaveRequest`의 `(…, tx: DbOrTx)` 규약, `(tx ?? db)` 대신 필수 인자 권장).
- `repositories/users.ts:62-76` `setUserArchived` -> 같은 `tx` 인자. 조건부 UPDATE(`isNull(archivedAt)` / `isNotNull`)와 `returning` 불리언은 그대로 둔다.
- `domain/people/index.ts:330-333`: `repoUpdateUserRole(viewer,userId,roleId)` 뒤 `recordAction(viewer,{ actionType:"permission_change", entity:"user", entityId:userId })` -> `recordAction(viewer, entry, { tx })`로 같은 tx에 묶는다.
- `domain/permissions/matrix.ts:114-127`: `upsertPermission`에 `tx`, `recordAction`에 `{ tx }`.
- 순서: 기존 사전 검증(`index.ts:311-328`의 권한 -> 자기 가드 -> 계급 실재)은 tx 밖에 그대로 두고, 그 뒤 `withTransaction`에서 잠금 -> `tx` 재조회 -> 판정 -> 쓰기 -> 로그.

**tx 안 로그 선례:** `restoreHoliday`의 `recordAction(viewer, {…}, { tx })` (`domain/holidays/admin.ts:351-360`).

주의: `registerPerson`은 `createAccount`(better-auth)가 같은 연결을 못 써서(`index.ts:200-206` 주석) 검사만 `:238` 앞의 별도 `withTransaction`에서 끝낸다. 풀 5에서 전역 `db`가 새면 교착한다(`approvals-concurrency.test.ts:27-40`).
