## Pattern Assignments

### `db/schema/expenses.ts` — `payee_user_id` (model, CRUD)

**Analog:** 같은 파일 `:28` (`vendorId`)와 `:76-88` CHECK 묶음.
```ts
vendorId: uuid("vendor_id").references(() => vendors.id),
...
check("expenses_line_or_team_check", sql`NOT (${table.quoteLineId} IS NOT NULL AND ${table.teamExpenseKind} IS NOT NULL)`),
check("expenses_installment_seq_check", sql`${table.installmentSeq} IS NULL OR ${table.installmentSeq} >= 1`),
```
복사 규칙: `payeeUserId: text("payee_user_id").references(() => users.id)`(users.id는 text — `updatedBy: text(...).references(() => users.id)` `:55`와 같다). 택일 CHECK는 `expenses_line_or_team_check`의 `NOT (A AND B)` 꼴을 따른다: `NOT (vendor_id IS NOT NULL AND payee_user_id IS NOT NULL)`. 제출 시점에 "둘 중 하나는 있어야 함"은 `expenses_submitted_amount_check`(`:80`, `number IS NULL OR …`)처럼 `number IS NULL OR (vendor_id IS NOT NULL) <> (payee_user_id IS NOT NULL)`로 건다. 팀 비용은 거래처가 없을 수도 있으니(`:81`) 제출 CHECK는 기존 행 영향을 `db:generate` 전에 확인한다. 마이그레이션은 `pnpm db:generate`만(`.claude/rules/db.md`).
