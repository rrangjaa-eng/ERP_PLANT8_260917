## 플래그된 가정

- **FA-1(이 플랜 몫):** 칸 구성 — `kind text PK` · `enabled boolean NULL` · `days integer NULL CHECK (days >= 0)` · `extra_role_ids text[] NOT NULL DEFAULT '{}'` · `email_enabled boolean NULL` · `enabled_at timestamp NULL` · `version integer NOT NULL DEFAULT 1` · `updated_by text → users.id` · `updated_at timestamp NOT NULL DEFAULT now()`. NULL = 「종류 기본값 따름」이라 코드 기본값이 바뀌면 관리자가 손대지 않은 칸은 새 기본값을 따른다. 계급 id 배열은 FK가 없다 — 보관된 계급은 07-10이 해석할 때 건너뛴다.
- **`enabled_at`을 `updated_at`과 따로 두는 이유:** 07-10의 사건 창 하한을 `updated_at`으로 잡으면 받는 계급 · 이메일만 바꿔도 하한이 움직여 그 사이 사건이 빠진다(C-P1-1과 같은 유실). 끔 → 켬일 때만 움직이는 칸이 필요하다. 시간대: 기존 표와 같은 `timestamp`(UTC 저장 — `updated_at`과 같은 꼴).
- **D-748 범위 칸 없음:** 공유 계약 §2가 「D-748 받는 계급 범위 칸(07-01 AQ-13 표의 「범위 칸 추가」) → 07-07」을 적었지만 그 칸은 AQ-13 답이 회사 전체가 **아닐 때**의 대안이었다(07-01 AQ 표 L239). 답이 회사 전체(D-748)라 칸을 만들지 않는다.
- 새 표를 `db/schema/notifications.ts` 안에 둔다(같은 기능 표 묶음 · `db/schema/index.ts` 변경 없음).
