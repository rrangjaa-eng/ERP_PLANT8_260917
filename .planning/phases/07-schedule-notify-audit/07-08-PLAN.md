## 플래그된 가정

- 섹션 이름은 기존 네임스페이스 `로그인 잠금` · `프로젝트` · `지급`을 그대로 쓴다(UI-SPEC SC-04의 `로그인`은 같은 묶음 — 이름 바꾸기는 하지 않음, 외과적). 잠금 두 키의 라벨은 SC-04대로 `잠금 횟수` · `잠금 시간`, 힌트는 범위만.
- **(옛 가정 정정 — C-P1-2)** 「범위 밖 저장값도 읽기는 그대로 된다」는 틀렸다: `getSettingValue`는 `parseStoredSimpleValue`(`domain/settings/registry.ts:160`)에서 스키마로 파싱하므로 범위를 좁히면 범위 밖 저장값이 **읽을 때마다 예외** → `lockoutConfig()`가 던져 로그인 전원 실패. 그래서 두 키에 `readInvalidAsDefault: true`(기존 선례 `domain/settings/keys.ts:314` 등)를 달아 범위 밖 저장값은 기본값으로 읽고 키 · 오류 코드만 `log.error`. 저장값을 고치는 데이터 작업은 하지 않는다(운영 값 보존 — 다음 저장 때 범위 검사).
- 기본값은 `env.LOCKOUT_THRESHOLD` · `env.LOCKOUT_WINDOW_MINUTES`(기본 5 · 15, `lib/env.ts:64-65`)라 env를 범위 밖으로 둔 환경이면 기본값 자체가 범위 밖이다 — 단위 시험이 시험 환경 기본값의 범위를 단언하고, 스테이징 · 운영 env 값은 위 머지 전 확인에 같이 적는다.
- **원가율 null:** `z.coerce.number()`만 쓰면 빈 입력이 `0`으로 저장된다. 빈 문자열 · null을 먼저 null로 바꾼 뒤 숫자 강제 변환하고 null을 허용한다. `describeSettingField`(`domain/settings/registry.ts:376`)는 지금 파이프만 벗겨 null 허용 숫자를 「문자」 칸으로 본다 — null 허용 래퍼도 벗기도록 고친다(이 키가 첫 null 단순 설정).
- **힌트 `0~100`(N6 강등):** 범위 조각은 형식 힌트라 그대로 둔다(설명 문장 아님).
