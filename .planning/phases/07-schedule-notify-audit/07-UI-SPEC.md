## Spacing Scale

SYSTEM.md 척도만 쓴다(`--s-1`~`--s-12`, 템플릿의 8점 척도가 아니라 이 프로젝트의 4px 기본 척도) [SYS §3].

| Token | Value | Usage |
|-------|-------|-------|
| `--s-1` | 4px | 라벨-입력 세로, 태그 안쪽 |
| `--s-2` | 8px | 행동 링크 사이, 인라인 칸 사이 |
| `--s-3` | 12px | 섹션 선 아래, 그룹 머리글 위 |
| `--s-4` | 16px | 폰 페이지 여백, 정보 면 안쪽 |
| `--s-5` | 20px | PC 페이지 좌우 |
| `--s-6` | 24px | 폼 항목 사이, 섹션 선 위 |
| `--s-8` | 32px | 화면 큰 구획 |
| `--s-12` | 48px | 사용하지 않음(이 페이즈 해당 없음) |

Exceptions: 행 높이 `--row-h` 44, 폰 시트·고정 행동 줄 버튼 `--touch-min` 44, 폼 입력 폰 40·PC 32 [SYS §3]. 폼·정보 면은 단일 기둥 `--form-max` 720, 표·정보 면 바깥 필터 줄은 컨테이너 폭 1280. 그 밖의 예외 없음.
**Exceptions(상속 예외, 새 값 아님)**: 12(`--s-3`)와 20(`--s-5`)은 템플릿의 8점 척도에 없지만 SYSTEM §3 확정 척도의 값이라 상속한다. 12 = 섹션 선 아래 여백·그룹 머리글 위 여백·옆 패널 폼 안쪽(SYSTEM §3 「섹션 사이」「그룹 머리글 행」), 20 = PC 컨테이너 좌우 패딩(SYSTEM §3 「`--s-5`=20, 예외 허용」). 이 페이즈가 12·20을 새로 도입하는 곳은 없다.

## 공통 계약 (모든 화면)

1. **버튼**: 화면당 1차 하나. 인라인 보조 동작은 3차(테두리 없음). 상태색 버튼 금지 [SYS §7-1].
2. **폰 표**: P1 최대 3열, P2 접힘 줄, P3 시트 `dl`. 폰 행 높이 44, 행 탭 = 시트 [SYS §7-3].
3. **오류 문구**: `원인 · 다음 행동` 한 줄, `--status-danger`, 입력 바로 아래 [SYS §7-2]. **제자리 행동의 결과는 결과 줄**(N4): 표 동작은 표 바로 위, 값 동작은 그 값 바로 아래에 `role="status"` 한 줄 `{동작} · {대상 또는 건수}`(`--text-aux`) + 되돌릴 수 있으면 3차 `되돌리기` [SYS §7-3·§7-6·§7-8 — SYSTEM 개정 아님]. 값이 바뀌는 것 자체가 결과인 동작(켬 체크박스·권한 칸·`로그인 상태`)은 결과 줄도 토스트도 없다 — 단 권한 칸이 다른 칸을 딸려 바꾸면 결과 줄(SC-10). 토스트는 화면·패널을 떠나는 행동(저장 뒤 패널 닫힘)의 결과에만 쓴다. 확인 창 대신 되돌리기. **결과 줄과 `되돌리기`는 다음 제자리 행동이나 화면 이탈까지 유지하고, 시간으로 사라지지 않는다.**
4. **다섯 상태**(LOADING·EMPTY·ERROR·SUCCESS·PARTIAL)는 화면마다 해당·비해당을 적는다. LOADING은 `--surface-muted` 뼈대, ERROR는 `불러오지 못했습니다 · 다시 시도` [SYS §7-7].
5. **문장**: 명사형, `-습니다` 금지(EMPTY 정형 한 줄은 SYSTEM 기존 문구를 따른다), 제목·버튼은 실제 동작 낱말 [SYS §8].
6. **날짜·금액**: SYSTEM §2-4 고정 형식(폰 `MM-DD`, PC `YYYY-MM-DD`, 금액 `Num` 우측 정렬, 음수 표기 SYSTEM 그대로).
7. **키보드**: 모든 동작은 Tab·Enter·Space·Esc로 닿는다. 표 안 입력은 엑셀식(방향키·Enter 이동) 기존 표 규칙 [SYS §7-3]. 아래 화면별 「키보드」 줄은 추가·변경분만 쓴다.
8. **권한 숨김**: 권한 없는 동작은 서버가 거르고 렌더하지 않는다(비활성이 아니라 숨김). 단 「할 수 없는 이유를 알려야 다음 행동이 나오는 경우」만 비활성 + 한 줄 이유(SC-13).
9. **위험 경로 PR 분리** [D-724]는 UI 계약에 영향이 없다(칸·마이그레이션은 화면 계약이 요구하는 것만 나열한다).
10. **즉시 저장 컨트롤의 저장 중**: 누르는 즉시 저장되는 컨트롤(SC-01 `이번 주로` · SC-05 켬 체크박스 · SC-10 권한 칸 · SC-11 `잠금 풀기` · SC-17 `확인됨으로 표시`)은 요청 중 그 컨트롤에 `aria-busy="true"` + `aria-disabled="true"`(누름 무시 — 연타 이중 저장 없음), 다른 행·칸은 그대로 조작할 수 있다. 실패 원복은 응답 뒤 한 번만.

## 확정 (오케스트레이터 판단, 근거)

처음에 사용자 확인 필요로 올렸던 7건을 오케스트레이터가 정했다. **Round 1: 1~7은 아침 카드 9-1~9-7에서 사용자가 그대로 확정했다(D-733~D-739), 8~10은 아침 카드 7 · 10-1 · 10-2 · 10-3에서 바뀐 화면 결정이다.** 남은 사용자 확인은 7번의 최종 기본값 하나(D-722 확인 카드)뿐이다.

1. **예산·사용액 (SC-21, W4·W5)** — 사용액 = 견적 줄 실행가 합(지급 완료 기준 아님), 예산 = PO 금액 × 원가율(PO 금액이 없으면 승인 견적 합계 × 원가율, 둘 다 없으면 0), 증액(PO 금액 변경·새 승인 차수)은 차이 × 원가율을 자동으로 더해 예산 이력 줄을 남긴다. 남은 예산 = 예산 − 사용액, 초과는 배지만. 근거: 사용자 결정 `/mnt/project-files/notes/fund-forecast/design.md` 맨 위 · 아침 카드 [D-733]. 초안의 「지급 완료+미지급」 정의는 이 결정과 어긋나 버렸다. **Round 1(아침 카드 4 · 5)**: 틀린 예산은 경영관리가 SC-21 패널 `예산 바꾸기`로 직접 고친다(사유 필수 · 이력 `직접 수정`) [D-729], 자동 반영은 증액만이고 감액은 직접 수정으로 [D-730]. 원가율 첫 저장은 진행 중 전부 첫 예산 줄 [D-747].
2. **원가율 기본값 (SC-04)** — 비움 [D-734]. 운영 시작 때 경영관리가 입력한다. 비어 있으면 예산 현황은 `원가율 미설정` 잠김 한 줄 + 설정 링크(경영관리만).
3. **폰 견적 표 구매 요청 (S3, SC-22)** — 현행 유지(행 탭 → 시트 1차 `구매 요청`) [D-738]. 근거: 폰 행 두 줄·주 버튼 하나 규칙, 시트가 한 번 탭 거리.
