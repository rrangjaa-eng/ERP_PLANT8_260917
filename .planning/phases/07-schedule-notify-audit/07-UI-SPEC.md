## Spacing Scale

SYSTEM.md 척도만 쓴다(`--s-1`~`--s-12`, 템플릿의 8점 척도가 아니라 이 프로젝트의 4px 기본 척도) [SYS §3].

| Token | Value | Usage |
|-------|-------|-------|
| `--s-1` | 4px | 라벨-입력 세로, 태그 안쪽 |
| `--s-2` | 8px | 행동 링크 사이, 인라인 칸 사이 |
| `--s-3` | 12px | 섹션 선 아래, 그룹 머리글 위 |
| `--s-4` | 16px | 폰 페이지 여백, 정보 면 안쪽 |
| `--s-5` | 20px | PC 페이지 좌우 |
| `--s-6` | 24px | 폼 항목 사이, 섹션 선 위 |
| `--s-8` | 32px | 화면 큰 구획 |
| `--s-12` | 48px | 사용하지 않음(이 페이즈 해당 없음) |

Exceptions: 행 높이 `--row-h` 44, 폰 시트·고정 행동 줄 버튼 `--touch-min` 44, 폼 입력 폰 40·PC 32 [SYS §3]. 폼·정보 면은 단일 기둥 `--form-max` 720, 표·정보 면 바깥 필터 줄은 컨테이너 폭 1280. 그 밖의 예외 없음.
**Exceptions(상속 예외, 새 값 아님)**: 12(`--s-3`)와 20(`--s-5`)은 템플릿의 8점 척도에 없지만 SYSTEM §3 확정 척도의 값이라 상속한다. 12 = 섹션 선 아래 여백·그룹 머리글 위 여백·옆 패널 폼 안쪽(SYSTEM §3 「섹션 사이」「그룹 머리글 행」), 20 = PC 컨테이너 좌우 패딩(SYSTEM §3 「`--s-5`=20, 예외 허용」). 이 페이즈가 12·20을 새로 도입하는 곳은 없다.

SYSTEM.md 역할 토큰만 쓴다. `font-size`·`font-weight` 직접 값 금지 [SYS §2-2·§11].

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (`--text-body`) | 14 (폰 15) | 400 (버튼 글자 600) | 표 1.5 · 산문 1.6 |
| Label·표 머리글·메타·오류 줄 (`--text-aux`) | 13 | 600 | 1.5 (머리글 1.6) |
| Tag (`--text-tag`) | 11 | 600 | 1.4 |
| Subtitle (`--text-subtitle`) | 18 | 700 | 1.4 (옆 패널·모달·섹션 제목) |
| Title (`--text-title`) | 22 | 700 | 1.3 (화면 제목 1개) |

한 화면의 본문 위계는 제목·부제·본문 3단계, aux·tag는 부속이다 [SYS §2-2]. **화면마다 실제로 쓰는 크기는 4개 이하**로 아래처럼 선언한다(tag 11은 `StatusTag` 컴포넌트 내부 크기로 위계 밖 — SYSTEM §2-2 「보조 크기는 본문 위계에서 뺀다」, 위 4개에 세지 않는다).

| 화면군 | 쓰는 크기 (4개 이하) |
|--------|----------------------|
| 목록·표 화면 (SC-01·06·08·11·16·21) | title 22 · body 14(폰 15) · aux 13 |
| 규칙 목록 (SC-05) 본체 / 그 옆 패널 | title 22 · body · aux / subtitle 18 · body · aux (옆 패널·모달은 subtitle만, title은 뒤 화면 것) |
| 폼 페이지 (SC-02·04·15) | title 22 · body · aux |
| 상세 (SC-03·12·19·20·22) | title 22 · subtitle 18(섹션 제목 — SC-19 정보 면 안 라벨은 aux) · body · aux |
| 옆 패널·시트 (SC-17·18·19 승인·20 계산서·21 이력) | subtitle 18 · body · aux |
| 모달 (SC-09·12·13) | subtitle 18 · body · aux |

굵기는 400·600·700 세 토큰이며 700은 title·subtitle에만 쓴다. **Exceptions(상속 예외, 새 값 아님)**: 템플릿의 「굵기 2개」 대신 SYSTEM §2-2·§3과 `tokens.css` L170-172가 확정한 세 토큰(`--fw-regular` 400 · `--fw-medium` 600 · `--fw-bold` 700)을 그대로 상속한다. 이 페이즈에서 새 크기·굵기 없음.

## Color

새 색 없음. 모든 값은 `tokens.css` 2단 역할 이름 [SYS §1-4].

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--surface-canvas` (#F2F5F4) / `--surface-base` (#FFFFFF) | 페이지 바탕 · 표·폼·패널 면 |
| Secondary (30%) | `--surface-head` · `--surface-foot` · `--surface-group` · `--surface-actions` | 표 머리글·정보 면·합계 면·그룹 줄·패널 행동 줄 |
| Accent (10%) | `--accent` (g-700 계열) | 아래 reserved-for 5곳만 |
| Destructive | `--status-danger` (red-800) | 글자·약한 태그 테두리만. 면·버튼 채움 금지 [SYS §1-3] |
| Warning | `--status-warning` (amber-700) | `마감 지나 밀림`·`계좌 바뀜`·`금요일 아님` 글자 |
| Muted | `--text-muted` · `--status-muted` | `수동 지정`·꺼 둔 규칙·보조 줄 |

Accent reserved for (이 페이즈 해당 요소): ① 내 차례 태그·행동 링크(`이번 주로`·`잠금 풀기` 등 행동 링크) ② 편집 중 셀(`고치기`로 열린 인라인 칸) ③ 화면당 1차 버튼 하나 ④ 포커스 링 ⑤ 현재 위치 밑줄. **알림함 안 읽음 왼쪽 선(1px `--accent`)은 SYSTEM §7-12 확정 예외**(기존). 그 밖에 accent 금지 — 알림 문장 링크·정보 면 제목·태그 장식에 쓰지 않는다. 상태 낱말 `결재 중`·`확인 전`·`구매 요청 중`의 색은 기존 `status-map.ts`가 정한 `--status-accent` 그대로이며(SYSTEM §7-5가 ①의 「태그」에 상태 태그 전반을 포함) 이 페이즈가 색을 바꾸거나 더하지 않는다.

## 공통 계약 (모든 화면)

1. **버튼**: 화면당 1차 하나. 인라인 보조 동작은 3차(테두리 없음). 상태색 버튼 금지 [SYS §7-1].
2. **폰 표**: P1 최대 3열, P2 접힘 줄, P3 시트 `dl`. 폰 행 높이 44, 행 탭 = 시트 [SYS §7-3].
3. **오류 문구**: `원인 · 다음 행동` 한 줄, `--status-danger`, 입력 바로 아래 [SYS §7-2]. 확인 창 대신 되돌리기 토스트가 가능한 동작은 토스트 3차 `되돌리기` [SYS §7-6].
4. **다섯 상태**(LOADING·EMPTY·ERROR·SUCCESS·PARTIAL)는 화면마다 해당·비해당을 적는다. LOADING은 `--surface-muted` 뼈대, ERROR는 `불러오지 못했습니다 · 다시 시도` [SYS §7-7].
5. **문장**: 명사형, `-습니다` 금지(EMPTY 정형 한 줄은 SYSTEM 기존 문구를 따른다), 제목·버튼은 실제 동작 낱말 [SYS §8].
6. **날짜·금액**: SYSTEM §2-4 고정 형식(폰 `MM-DD`, PC `YYYY-MM-DD`, 금액 `Num` 우측 정렬, 음수 표기 SYSTEM 그대로).
7. **키보드**: 모든 동작은 Tab·Enter·Space·Esc로 닿는다. 표 안 입력은 엑셀식(방향키·Enter 이동) 기존 표 규칙 [SYS §7-3]. 아래 화면별 「키보드」 줄은 추가·변경분만 쓴다.
8. **권한 숨김**: 권한 없는 동작은 서버가 거르고 렌더하지 않는다(비활성이 아니라 숨김). 단 「할 수 없는 이유를 알려야 다음 행동이 나오는 경우」만 비활성 + 한 줄 이유(SC-13).
9. **위험 경로 PR 분리** [D-724]는 UI 계약에 영향이 없다(칸·마이그레이션은 화면 계약이 요구하는 것만 나열한다).

## 확정 (오케스트레이터 판단, 근거)

처음에 사용자 확인 필요로 올렸던 7건을 오케스트레이터가 정했다. 남은 사용자 확인은 7번의 최종 기본값 하나(D-722 확인 카드)뿐이다.

1. **예산·사용액 (SC-21, W4·W5)** — 사용액 = 견적 줄 실행가 합(지급 완료 기준 아님), 예산 = PO 금액 × 원가율(PO 금액이 없으면 승인 견적 합계 × 원가율, 둘 다 없으면 0), 증액(PO 금액 변경·새 승인 차수)은 차이 × 원가율을 자동으로 더해 예산 이력 줄을 남긴다. 남은 예산 = 예산 − 사용액, 초과는 배지만. 근거: 사용자 결정 `/mnt/project-files/notes/fund-forecast/design.md` 맨 위. 초안의 「지급 완료+미지급」 정의는 이 결정과 어긋나 버렸고, 수동 `예산 바꾸기` 패널도 같이 없앴다.
2. **원가율 기본값 (SC-04)** — 비움. 운영 시작 때 경영관리가 입력한다. 비어 있으면 예산 현황은 `원가율 미설정` 잠김 한 줄 + 설정 링크(경영관리만).
3. **폰 견적 표 구매 요청 (S3, SC-22)** — 현행 유지(행 탭 → 시트 1차 `구매 요청`). 근거: 폰 행 두 줄·주 버튼 하나 규칙, 시트가 한 번 탭 거리.
4. **수금 지연 (N22, SC-20)** — 수금 예정일 = 매출 발행 줄 `revenue_entries.entry_date`(발행) + 설정 `수금 기한 일수`(기본 60, 옛 260907 `020_functions.sql:754` collect_due_date와 같은 식, 고객별 칸은 Phase 9 [D-720]). 발행 합계 > 입금 합계이고 오늘 > 수금 예정일이면 `수금 지연` 배지(프로젝트 목록·상세 매출 면). 규칙 하나는 시드 꺼 둠, 받는 사람 담당 PM.
5. **거래처 내려받기 상한 (V1, SC-16)** — 5,000곳. 넘으면 내려받기 막힘 한 줄.
6. **PO 번호 중복 (W2, SC-19)** — 허용, 경고 없음.
7. **거래처 권한 세분 (R8, SC-10)** — `거래처 보기` · `거래처 등록·수정` · `거래처 계좌·서류 수정` 세 줄. 최종 기본값은 D-722 계급 기본값 표 확인 카드에서 사용자가 확인.
