### 키보드만 (1280, backstop 2)

이 동선은 audit4로 쟀다.

1. 상세 D에서 Tab 17번이면 `서류 붙이기`(링)에 닿는다. Enter를 누르면 파일 고르기 창이 열린다 → **올린 뒤 포커스가 BODY다(#2)**.
2. Tab 1번이면 `종류` select에 닿는다.
3. Tab 2번이면 `삭제`에 닿는다. Enter → 확인 창이 열리고 첫 포커스는 1차 `서류 삭제`다(SYSTEM 규칙 「근거 칸 없으면 1차」).
4. 확인 창에서 Enter를 누르면 EMPTY로 돌아간다 → **포커스가 BODY다(#3)**.
5. 상세 A에서 두 장 중 하나를 지우면 포커스가 `하나 더`로 간다(통과).
6. Tab 25번이면 `계산서 1`에 닿는다. Enter → 패널이 열리고 첫 포커스는 `닫기`다. Tab 3번이면 `교체`에 닿고, Enter → 고르기 창이 열린다(6번 중 4번). 나머지 2번은 #1 경로로 패널이 닫혔다.
7. Esc를 누르면 포커스가 `계산서 1`로 간다.

정리하면, 붙이기 · 지우기 · 열기 · 교체 · 닫기는 키보드만으로 모두 닿고 움직인다. 포커스 유실 두 곳(#2 · #3)과 고르기 취소(#1)가 남는다.

## Backstop 두 줄

1. **4폭에서 서류 섹션 · 계산서 패널 · 상태 열 둘째 줄이 가로 넘침 없이 서고, 파일 이름이 말줄임으로 한 줄에 선다 → 통과.** 넘침 0이고, 이름은 `nowrap` + `ellipsis`로 1줄이다. 계산서 패널은 768 · 1280에서 쟀다. 폰에서는 패널에 닿을 길이 없다(계산서 열이 숨음).
2. **서류 붙이기 · 지우기 · 계산서 붙이기 · 교체가 키보드만으로 되고, 패널을 닫으면 포커스가 링크로 돌아온다 → 조건부 통과.** 동작과 패널 닫기 포커스 복귀는 통과다. 포커스 유실 #2 · #3과 고르기 취소 시 패널이 닫히는 #1은 고칠 것이다.

## 측정하지 못한 것

- 업로드 LOADING 줄 · ERROR 줄(서류 섹션)과 계산서 패널의 `계산서 불러오지 못함` 오류 상태. 서버 실패를 일으키지 않았다. 코드상 문구는 명사형 한 줄 + `다시 시도`다.
- 07-18 `발주서 파일 없음`이 첫 발주서와 함께 사라지는지(E2E `project-documents.spec.ts`가 덮는다).
- 실제 OS 파일 창의 「취소」. 헤드리스에서는 같은 `cancel` 이벤트를 직접 보내는 방법과, 가로채지 않은 고르기 창을 크로미움이 취소하는 방법 두 가지로 재현했다.
- Codex 디자인 검토는 이 감사 범위가 아니다(`/design-review`의 몫).
