## 검토자가 볼 것 (/review · /cso · Opus 독립 검토)

1. 허용 목록 7경로가 충분 · 최소한가 — `/ok` · `/error`는 D-E6 문자 그대로 넣지 않음(퇴사 · 보관 쿠키로 부르면 세션 삭제 · 401). `/sign-in/social`·`/callback/:id`는 로그인 쪽이라 열어 둠(google 공급자일 때 퇴사자 OAuth 로그인 거부는 이 플랜 밖 — 이메일 로그인 갈래만 퇴사 판정).
2. `ctx.request` 판별 — 서버 내부 `auth.api.*`에 호출자가 `request`를 넘기는 자리가 없는지(있으면 판정이 걸린다). 반대로 HTTP인데 `request`가 없는 경로가 없는지(dispatch.mjs `isRequestLike`).
3. 캐시 되돌림이 `getSessionFromCtx`가 쓰는 `responseHeaders`(set-cookie) 병합과 충돌하지 않는지 — 만료 세션 쿠키 삭제 헤더는 훅 응답에 합쳐진다.
4. 거부 응답 모양 `{ code: "UNAUTHORIZED", message: "Unauthorized" }`가 세션 없음 거부와 같아 퇴직 여부가 드러나지 않는지(SC-14). 쿠키 삭제 헤더는 붙이지 않음(행은 지워져 다음 요청은 세션 없음).
5. `deleteUserSessions` 실패 시 fail-closed 401 · 로그에 userId와 오류 이름만.
6. HTTP 요청마다(허용 목록 밖) 세션 조회가 한 번 더 든다(`/get-session` 등) — 성능 영향 수용 여부.
