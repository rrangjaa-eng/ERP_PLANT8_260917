## 미검증 / 위험 메모

- `gcloud run jobs deploy ... --args=""`가 실제 gcloud에서 기존 `--apply`를 지우는지는 가짜 gcloud로 확인할 수 없다(플랜 가정). 첫 apply -> dry-run 되돌림이 생기면 실제 Job 정의를 확인할 것.
- Scheduler -> `jobs/{job}:run`에 job 단위 `roles/run.invoker`로 충분한지는 플랜 가정 A1 그대로다. 모자라면 첫 실행 기록이 비어 `verify-gcp purge-scheduler`가 실패로 드러낸다.
- `--attempt-deadline=180s`는 notify-tick과 같은 꼴을 따랐다(`:run`은 비동기 시작 호출이라 충분하다고 본다. 미실측).
