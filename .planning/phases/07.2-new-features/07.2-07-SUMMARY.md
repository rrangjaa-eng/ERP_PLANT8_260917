## RejectDialog 쓰는 곳의 prop 연결 · 코드표 화면 변경 여부

- `RejectDialog.reasonOptions: string[]`는 **필수**. `inbox-table.tsx`(← `approvals/page.tsx`) · `home-approval-actions.tsx`(← `(home)/page.tsx`) · `document-actions.tsx`(← 서버 page)로 서버가 `listReasonOptions(viewer, "reject_reason")`를 읽어 내린다.
- 코드표 화면(`admin/code-tables`)은 **변경 0** — CODE_TABLES로 전환 링크가 자동 생성되어 세 표가 그대로 동작했다.

## Deviations / Decisions

1. **[Rule 2/3] DocumentActions 호출부 확장** — `reasonOptions`를 필수로 두자 `DocumentActions`를 쓰는 지출결의 문서(`expense-document.tsx` ← `expenses/[id]/page.tsx`)와 정산 결재 문서(`projects/[id]/settlement/page.tsx`)도 타입 검사에서 걸렸다. 그 두 화면의 반려 창도 자유 입력으로 남지 않게 같은 reader를 내렸다. 계획 files_modified에 `expense-document.tsx` · `settlement/page.tsx`는 없었다.
2. **[Rule 1] 기존 시험 문구 갱신** — 통합 `허용 코드표 네 개` 목록 단언(4 → 7)과 E2E `전환 링크 넷`(4 → 7, 형제 3 → 6, 한 줄이 아니면 같은 줄끼리만 간격 비교)은 CODE_TABLES 확장의 직접 결과라 고쳤다.
3. **시험 보조 파일 추가** — `test/e2e/reason-options.ts`(사유 항목 시드 + 끝에 비활성으로 되돌리는 정리). 사유 목록이 전역 코드표라 E2E가 `finally`로 비활성화해야 뒤따르는 「0건」 시험이 깨지지 않는다.
4. **Task 3 RED 없음** — 전환 링크는 Task 1의 CODE_TABLES 변경이 이미 만족한다(「RED 아님(Task 1이 이미 만족)」). 회귀 그물로 남겼다. 기존 형제 링크 수 단언만 갱신 전 RED였다.
5. **지출결의 폼 두 사유 칸이 한 줄 입력 → 여러 줄 글 칸**으로 바뀐다(계획 「여러 줄 TextField」). maxLength 480 · 오류 id(`…-error`) · 상태 매핑은 그대로. Enter로 줄바꿈이 들어갈 수 있다.
6. 반려 창 `.reason textarea` 규칙은 ReasonField CSS 모듈로 옮겼다(중복 제거 · 값 동일).
7. 로컬 `pnpm build`는 따로 돌리지 않았다 — `CI=true` E2E가 프로덕션 빌드로 떠서 빌드가 통과한 것이 확인된다(playwright webServer `next start`).
