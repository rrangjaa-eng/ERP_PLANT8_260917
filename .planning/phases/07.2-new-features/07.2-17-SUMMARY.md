돈 문서 7종 판정 하나로 프로젝트 삭제(보관) · 되돌리기 · 보관함 복원을 막고 풀며, 보관된 프로젝트로 들어오는 돈 문서 쓰기를 잠근 행의 archivedAt으로 거부하고, 정보 면 `고치기` 묶음에 행사명 · 고객사 · 담당 팀 · 담당 PM을 더해 기간 · PO와 같은 트랜잭션에서 version 동시 수정 판정과 함께 저장한다.

## 가정과 결정

- 플래너 가정 셋(must_haves)
  1. **예산 이력 = `manual`만** — `initial` · `po_amount_change` · `new_approved_revision`은 프로젝트 자기 숫자에서 나온 줄이라 세지 않는다(세면 모든 프로젝트가 못 지워진다).
  2. **입구 자리** — 삭제는 `HeaderCopyActions` 자식 끝(PC 버튼군 끝 · 폰 `더보기` 펼친 줄 끝). 새 팝오버 · 시트 0.
  3. **팀 범위** — 담당 팀 후보와 쓰기 권리는 고치는 사람의 업무 범위(쓰기 행 범위로 좁힘 · teamScopeForProject) 안. 서버가 잠근 tx에서 다시 잰다.
- 복원 때 돈 문서가 있으면 `돈 문서 {N}건 연결 · 복원 불가`(방어 판정 — 보관 프로젝트 쓰기 거부 때문에 정상 흐름에서는 나지 않는다).
- 기본 정보 권리는 계획 문장 그대로(projects.info 쓰기 + 담당 PM 또는 업무 범위). 기본 사원 계급은 projects.info 쓰기와 팀 업무 범위를 가져 **같은 팀 사원도 고친다** — UI-SPEC S3 DOM 합격의 「직원 계급 편집 칸 0」과 어긋난다. E2E는 projects.info 없는 임시 계급으로 읽기 전용을 쟀다. 아침 질문에 올렸다.
- 사람 id(인증 표)는 글자 id라 담당 PM 값은 소문자로 바꾸지 않는다(고객사 · 팀 uuid만 소문자).
- 등록 폼에 행사명 길이 상한이 없어 여기도 두지 않았다(새 숫자 0).
- 동시 수정 시각은 잠근 행 `updated_at`이다. 기간 · PO 저장도 그 시각을 올리므로 「누가 무엇을 바꿨나」와 시각이 어긋날 수 있다(문구는 시각만 말한다).
- 정산 보임(canSeeSettlement)에 지금 담당 PM을 더했다 — 다시 올릴 사람이 문서를 열 수 있어야 해서. 보임 넓힘이라 아침 질문에 올렸다.
- `projects.delete`만 있는 팀장은 보관함에서 자기 범위 프로젝트 행만 보고, `archive.value` 노출 없이도 이름을 본다(자기가 지운 프로젝트를 찾아야 해서).
- 상세에 돈 문서 수는 삭제 권리 또는 정보 편집 권리가 있을 때만 한 번 센다(7 하위 질의 1회).
