# Phase 07.2 Plan 19: 완료 되돌리기(S2 · PU2) Summary

대표 · 시스템 관리자(projects.reopen 쓰기)가 완료 프로젝트를 사유와 함께 정산으로 되돌린다. 같은 정산 결재 문서는 승인 → 작성 중(draft)으로 물리고, 담당 PM이 같은 문서를 다시 올려 결재선을 처음부터 다시 탄다. 결재선 끝에 `되돌림 · 이름 · MM-DD HH:mm · 사유 원문` 한 줄이 남는다(카드 11 사용자 확정 2026-11-02 14:23 KST).

## 엔진 전이 표(before → after)

| 상태 · 사건 | before | after |
|---|---|---|
| approved · reopen | 닫힘(사건 없음) | **draft** — 종류 `allowReopen`(정산만) + 브랜드 `ReopenAuthority` 일치일 때만 · 차수 그대로 |
| draft · resubmit | 닫힘 | **submitted** — 종류 `resubmitFrom`에 draft(정산만) · 차수 + 1 · 새 결재선 |
| rejected · withdrawn · resubmit | submitted | 그대로 |
| 그 밖의 칸(42칸 표) | — | 변경 0(next-step.test.ts 표) |

## 종류별 reopen 허용

| 종류 | allowReopen | resubmitFrom |
|---|---|---|
| settlement | true | rejected · withdrawn · draft |
| expense · leave · leave_cancel | 없음(거부 — 위조 authority도 UserFacingError, approvals-lifecycle) | 기존 그대로 |

## 브랜드 권한 흐름 · 트랜잭션 순서

1. `reopenCompletedProject`(domain/settlements/reopen.ts) — tx 전: UUID → 쓰기 범위 보임 · 보관 제외(없으면 `존재하지 않는 프로젝트`) → `can(projects.reopen, write)`(아니면 `완료 되돌리기 권한 없음`) → 사유 trim 1~500 → 상태 completed → 정산 인스턴스 approved · version 일치(아니면 충돌 문구).
2. 상태 전이 사실(`loadStatusChangeFacts` + `teamScopeForProject`) · 엔진 사전 읽기(`prepareReopen`)를 tx 전에 읽는다(잠근 tx 안 풀 읽기 0).
3. 비공개 `grantReopen`만 `{ project: ProjectReopenAuthority, document: ReopenAuthority }`를 만든다(export 0).
4. `withTransaction`: `reopenApprovedDocument`(인스턴스 먼저 — version 조건 UPDATE · document_reopen 로그 · 사유) → `changeProjectStatus(completed → settling, trigger reopen, reopenAuthority)`(프로젝트 잠금 · status_change 로그) — T-05-1106 순서.
5. tx 안 `ApprovalConflictError` · `NotCurrentHolderError` → `다른 사람이 먼저 바꿈 · 새로 고침`.
- `changeProjectStatus`: via reopen 전이를 manual로 부르면 `project.reopen-only` 거부, trigger reopen인데 via · authority projectId가 다르면 `project.reopen-authority` 거부.
