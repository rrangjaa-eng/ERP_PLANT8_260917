## Summary

27개 기능 중 **새 의존성이 필요한 것은 없다.** 가장 큰 위험은 (1) 견적 금액 공식 변경(PU6, `domain/money`)·수수료 줄 종류(PU3), (2) 결재 엔진 확장(일괄·연차 종류 힌트·`leave_cancel`·정산 되돌리기), (3) 지급 예정일 원자 반영(X4), 이 세 곳이다. 모두 `/cso` 대상이고 R1 스키마가 앞서야 한다.

핵심 발견 5건: ① **PU2/D-7215 충돌** — `approved` 상태는 전이가 없고(`approved: {}`), `submitSettlement`는 승인된 인스턴스를 `already_submitted`로 돌려보낸다. 「물림 후 같은 문서 재상신」은 지금 엔진으로 불가능 → 엔진에 `approved → (reopen) → draft` 같은 새 전이를 만들거나(결재 엔진 변경, 큰 위험) 새 `round`로 인스턴스를 되살리는 전용 함수가 필요하다. 사용자 재확인 거리(카드 11 후보). ② **X3 관리자 읽기 함정** — 사유 코드표를 읽는 함수가 관리자 전용이면 PM·기안자 화면에서 비어 보인다(`domain/code-tables`의 좁은 읽기 함수 패턴 `domain/projects/references.ts`를 따라 별도 reader 필요). ③ **X4 원자성** — `saveScheduledPayDate`가 쓰는 `writeScheduledPayDate`는 private라 요청 승인과 같은 트랜잭션에 못 묶는다 → export 또는 트랜잭션 인자 받는 변형 필요(`domain/payments` 접촉 = `/cso`). ④ **PU21** — Scheduler → Cloud Run Job `:run`(v2 REST) + OAuth 서비스계정 + `roles/run.invoker`가 정석, `overrides.args` 본문은 이 세션에서 문서 원문을 못 열어 `[ASSUMED]`. ⑤ **D-7298 조정 줄 반대 부호**는 260917 모델(프로젝트 내 `adjustment` 줄, 상대 프로젝트 없음)에 상대 칸이 없어 스키마 추가가 필요 → 카드 10 세부 결정 필요.

**Primary recommendation:** R1(스키마 0050~) + R2(권한 키) + R3(Scheduler)를 사용자 머지 PR로 먼저 올리고, S5 계산부(PU8·13·14)는 07.3 대기 없이 선행. 결재 엔진 변경분(일괄·`leave_cancel`·연차 힌트)은 기존 단건 함수를 루프로 부르는 얇은 래퍼로만 만들고 판정 로직은 복사하지 않는다.

### Pattern 1: 일괄 = 단건 루프 + 부분 성공 (`domain/payments/batch.ts`)
**What:** 권한은 루프 전 1회, 공유 읽기는 루프 전 1회, 행마다 단건 함수(자기 트랜잭션), 실패는 다른 행을 되돌리지 않음. 응답 `{processed, processedIds, blocked[{...reason}]}`. `[VERIFIED: domain/payments/batch.ts:7-30]` 주석 인용: 「이 함수는 트랜잭션을 열지 않는다」, 「한 행의 실패는 다른 행의 기록을 되돌리지 않는다」, 타입 `export type BatchBlockedRow = { expenseId: string; reason: string; newPayableKrw: number | null; selectable: boolean; selectableReason: string | null };`
**When:** PU15~17(결재 일괄), X1(증빙 일괄 보관).

### Pattern 2: 결재 종류 등록 (`registerDocumentKind`)
최종 승인 훅은 **쌍**으로만 등록(`kinds.ts`). 정산 종류는 `onFinalApprovalInTx`에서 `changeProjectStatus(... trigger: "approval")`를 부른다 `[VERIFIED: domain/settlements/index.ts:540-569 — 열람함, 인용: changeProjectStatus(... trigger: "approval")]`. `leave_cancel`은 이 쌍 훅으로 「취소 표시」만 기록한다.

### Pattern 3: 읽을 때 계산 (연차 잔고)
`domain/leave/balance-service.ts` `computeBalance`가 저장 없이 계산 `[CITED: CONTEXT code_context]`. 근속 가산 식을 `annualGrantQuarters` 쪽에 넣으면 과거 연도도 같이 바뀐다(D-7249 의도).

### Pattern 4: 셸 밖 인쇄 페이지
`app/print/certs/[id]/page.tsx` + `print-sheet.tsx` + CSS 모듈 선례, SYSTEM.md §6-6 `[CITED: docs/design/SYSTEM.md §6-6]`. 견적서도 `app/print/quotes/[id]/*`.

### Anti-Patterns to Avoid
- **일괄에서 판정 로직 복사** — 반드시 단건 함수를 부른다(D-7269).
- **계급 이름 판정** — 계급 id 상수 또는 메뉴키만(`domain/permissions/menus.ts:44-49`).
- **`validateRejectReason` 임의 변경** — 증빙 무효(05-09)와 공유(`REJECT_REASON_MAX = 500` at `domain/approvals/index.ts:774`).
- **인쇄 DTO에 내부 값 포함 후 CSS로 숨김** — DTO에서 아예 제외 + leak-scan 등록.

## Common Pitfalls

### Pitfall 1: 정산 되돌리기가 엔진에서 막힘 (PU2)
**What goes wrong:** `approved`는 종단 상태라 재상신 불가, `submitSettlement`는 `already_submitted`. **Avoid:** 엔진에 reopen 전이를 명시적 함수로 추가하고 사용자에게 재확인. **Signs:** 되돌린 프로젝트에서 정산 상신 버튼이 동작 안 함.

### Pitfall 2: 일괄 승인 stale (PU15~17)
화면이 본 version과 다른 문서가 승인됨. **Avoid:** 행마다 `{id, version}` 전송, 불일치는 `blocked`.

### Pitfall 3: 잔고와 겹침 조회의 취소 반영 불일치 (PU10)
`repositories/leave-usage.ts` 두 조회 중 하나만 취소 제외하면 이중 계산. 같은 서브쿼리/함수를 쓰고 통합 시험으로 고정.

### Pitfall 4: 연차 결재선 미리보기 ≠ 제출 (PU9)
힌트를 `previewRoute`에 안 넘기면 폼이 틀린 결재선을 보여줌.

### Pitfall 5: 금액 공식 변경의 누락 호출처 (PU6)
`quoteAmount`를 직접 쓰는 곳(조정 줄 동기화·붙여넣기 미리보기·정산 합계·데모 데이터)에서 일수 누락 → 합계 불일치. **Avoid:** 호출처 grep 목록을 Wave 0에서 만들고, 클라 미리보기와 서버 계산이 같은 함수를 쓰는 속성 시험.

### Pitfall 6: 사유 목록 관리자 전용 reader (X3), Pitfall 7: private 쓰기 함수 (X4)
위 §F-X3·F-X4.

### Pitfall 8: 병합 셀·계산 안 된 셀 (X2)
캐시값이 비어 있는 엑셀(미계산 저장)은 금액이 비어 건너뛴 줄이 폭증 → 건너뛴 줄 사유에 「값 없음(엑셀에서 다시 저장)」 안내 1줄.

### Pitfall 9: 마이그레이션 번호 충돌 / `_journal.json`

### 일괄 래퍼 골격 (판정 복사 없음)
```ts
// domain/approvals/batch.ts — Source: domain/payments/batch.ts 패턴 + approveDocument 재사용
export const BULK_APPROVAL_LIMIT = 100;
export type ApprovalBatchItem = { kind: string; id: string; version: number };
export type ApprovalBatchResult = { processedIds: string[]; blocked: { id: string; reason: string }[] };

export async function approveBatch(viewer: Viewer, items: ApprovalBatchItem[]): Promise<ApprovalBatchResult> {
  if (items.length === 0 || items.length > BULK_APPROVAL_LIMIT) throw new UserFacingError("선택 범위를 확인해 주세요");
  if (items.some((i) => i.kind === "settlement")) throw new UserFacingError("정산은 일괄 처리할 수 없습니다");
  const processedIds: string[] = [];
  const blocked: ApprovalBatchResult["blocked"] = [];
  for (const item of items) {
    try {
      await approveDocument(viewer, item.kind, item.id, { expectedVersion: item.version });
      processedIds.push(item.id);
    } catch (e) {
      blocked.push({ id: item.id, reason: reasonOf(e) });
    }
  }
  return { processedIds, blocked };
}
```

export function legalAnnualDays(base: number, fiscalYear: number, entryYear: number): number {
  const tenure = fiscalYear - entryYear;
  if (tenure < 3) return base;
  const statutory = Math.min(15 + Math.floor((tenure - 3) / 2) + 1, 25);

}

### Known Threat Patterns
| Pattern | STRIDE | Mitigation |
|---------|--------|------------|
| 일괄 승인 stale / 권한 우회 | Tampering/Elevation | 행별 단건 함수 + version + 상한 + 정산 제외 |
| 인쇄 DTO 협력사·실행가 누출 | Info disclosure | DTO 투영 + `registerDto` leak-scan |
| 악성 xlsx(압축 폭탄·거대 시트·수식 주입) | DoS/Tampering | 크기 상한 1MB, 행/셀 상한, 캐시값만 읽음, 내보내기 `csvCell` 점검 |
| 로고 파일 업로드(SVG 스크립트 등) | XSS | 래스터 이미지(PNG/JPEG)만, MIME+매직바이트, 크기 상한, 인라인 SVG 금지 |
| 지급 예정일 변경 경쟁/이중 승인 | Tampering | 부분 유니크 + 조건부 UPDATE + 같은 트랜잭션 |
| 연차 표로 타 팀 잔고 열람 | Info disclosure | 노출표 + viewScope 교집합 시험, PM 노출 금지 |
| 부족일(경영관리 전용) 본인 DTO 노출 | Info disclosure | 본인 DTO 미탑재 + leak-scan |
| Scheduler SA 과권한 | Elevation | job 단위 `run.invoker`만, 키 없음 |
