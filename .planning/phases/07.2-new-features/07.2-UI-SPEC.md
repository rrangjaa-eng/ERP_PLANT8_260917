### S1. 프로젝트 삭제 입구 · 보관함 프로젝트 복원 (PU1 · D-7210~7213)

- **삭제 입구(디자인 D-F1):** 프로젝트 상세 머리 행동 묶음(`HeaderCopyActions`)의 **맨 끝**(PC 버튼군 끝 · 폰 펼침 줄 끝), `--s-8` 떨어진 `danger` 3차 `프로젝트 삭제`(RowAction danger 규칙, §7-19). 새 팝오버 · 시트 부품 0(지금 PC 머리 줄에는 「더보기」가 없고 폰 「더보기」는 바로 아래 펼침 줄 — 07.2-17). 보는 사람 = `projects.delete` 보유자(기본 팀장 이상 · 관리자). 없으면 항목 DOM 없음.

- **1280/768:** 머리 버튼군 끝 3차. **375/320:** 머리 펼침 줄 끝, 높이 44, 앞 행동과 `--s-8`.

### S2. 완료 되돌리기 (PU2 · D-7214~7216 · 07.2 D-7302)

- **위치(디자인 D-F2 · 결정 최소):** 완료 프로젝트 상세 머리 「상태 바꾸기」 자리에 트리거 `정산으로 되돌리기` 하나(갈 곳이 하나라 목록 단계 없음 — `lost` 프로젝트의 `진행으로 되돌리기` 트리거와 같은 꼴). 보는 사람 = `projects.reopen` 보유자(대표 · 관리자). 그 밖 계급은 트리거 DOM 없음.
- **누르면:** 바로 확인 창을 연다(목록 창 0, §7-8). 제목 `정산으로 되돌리기` · 부제 `{번호} {프로젝트명}` · 결과 줄 `완료 해제 · 정산 결재 다시 받음` · **근거 칸 = 사유(여러 줄, 필수)** · 2차 `취소 Esc` · 1차 `정산으로 되돌리기 Ctrl+Enter`. 사유가 비면 1차 `aria-disabled` + 막힘 이유 `사유 없음 · 사유 적기`(§7-8 사유형).
- **누른 뒤:** 토스트 `정산으로 되돌리기 · {번호}`. 상태 낱말 `완료` → `정산`(warning, 기존). 정산 섹션 결재선 목록 끝에 줄 `되돌림 · {이름} · MM-DD HH:mm · 사유 {원문}`(`--text-aux --text-muted`, 반려 사유 줄과 같은 모양). 담당 PM의 기존 버튼 `정산 결재 다시 올리기`가 활성(문구 변경 0). 견적 표는 정산 모양(`정산 · 실행가와 새 줄만`). 되돌린 정산 결재(엔진 draft)의 상태 낱말 = 기존 `작성 중`(머리 줄 `정산 결재 작성 중` 링크 · 정산 목록 — 새 낱말 0) · 결재함 처리함은 기존 `임시` · PM 「내 차례」 줄은 반려된 정산과 같이 없다(다음 행동 = 머리 줄 링크 → 문서 화면 `정산 결재 다시 올리기`, eng D-19 보충).
- **375/320:** 확인 창은 아래 시트, 행동 줄 2차 왼쪽 · 1차 오른쪽(1차 2배 폭) · 이유는 버튼 윗줄 전폭.
- **상태:** ERROR = 막힘 자리 서버 문자열(`다른 사람이 먼저 바꿈 · 새로 고침` → 3차 `새로 고침`), 창 유지 · SUCCESS = 바로 닫힘 + 토스트 · LOADING/EMPTY/PARTIAL 해당 없음(§7-17).
- **결정·문구 점검:** 입력은 사유 한 칸뿐, 되돌릴 대상 단계는 「정산」 하나라 선택지 0.
- **DOM 합격:** 대표 계급 완료 프로젝트 → 트리거 `정산으로 되돌리기` 1개 · 누르면 목록 창 DOM 0 · 확인 창 1 / 팀장 · PM 0개. 되돌린 뒤 담당 PM 머리 줄 `정산 결재 작성 중`(원문 `draft` 0). 사유 빈 값에서 1차 `aria-disabled`, 입력 뒤 활성. 제출 뒤 상태 글자 `정산`(완료 0), 결재선 끝 줄에 입력한 사유 원문 포함. 동시 호출 2번째는 `새로 고침` 3차가 붙는 막힘.

### S3. 기본 정보 수정 (PU5 · D-7217~7220)

- **위치:** 프로젝트 상세 「정보 면」(§6-2 개정 5). 면 안 값 · 3차 `펼치기`/`고치기`/`고치기 취소`는 기존 그대로, **고치기 묶음에 행사명 · 고객사 · 담당 팀 · 담당 PM 4칸을 더한다**(DC-9). 값마다 따로 `고치기`를 두지 않는다(10/7 12:43 사용자 결정). 저장은 화면 1차 `일괄 저장 N` 하나가 기간 · PO와 같은 트랜잭션으로 받는다.
- **칸 모양:** 행사명 = 텍스트 입력. 고객사 · 담당 팀 · 담당 PM = 값 텍스트 + 3차 `바꾸기`(자동 채움 규칙, §7-2) → `PickDialog`(고르기). PM 후보 중 바뀐 담당 팀 소속도 참여자도 아닌 사람은 `selectable: false` + 2행 이유 `담당 팀 소속 아님`. 바꾼 칸은 `--surface-dirty` + 왼쪽 위 삼각형.
- **잠김:** 돈 문서가 붙으면 고객사 · 담당 팀은 값 텍스트만(`바꾸기` 없음) + 정보 면 안 한 줄 `고객사 · 담당 팀 잠김 · 돈 문서 연결`(`--text-aux --text-muted`, 편집 중에만). 행사명 · PM은 완료 뒤에도 편집(D-7218). `projects.info` 없는 사람은 4칸 모두 읽기 전용(기간 · PO는 `projects.period` 별개).
- **오류:** 팀을 바꿔 PM이 자격을 잃으면 PM 칸 오류 셀 + `담당 PM 소속 아님 · PM 다시 고르기`. 동시 수정(`projects.version`) = 면 아래 `다른 사람이 {HH:mm}에 바꿈 · 새로 고침`. 전부 저장 또는 전부 거부(§7-3).
- **1280:** 정보 면 3열 · **768:** 2열 · **375/320:** 1열, `바꾸기` 시트는 아래 시트. 접힘 기본(K22) 유지 — 접힌 줄은 PO 금액 그대로.
- **상태:** SUCCESS = 1차 자리 `저장됨 N칸 14:02` + 제목 갱신 · ERROR = 위 칸 오류 · LOADING = 1차 `…`.
- **결정·문구 점검:** 기본값 = 현재 값, 시스템이 후보를 걸러 준다(자격 없는 PM은 비활성), 확인 창 0.
- **DOM 합격:** `projects.info` 보유자(담당 PM · 팀장)만 `고치기`로 4칸 편집 칸이 나타남 / 직원 계급 편집 칸 0. 돈 문서 fixture → 고객사 · 담당 팀 `바꾸기` DOM 0 + 잠김 줄 1. 자격 없는 PM 행 `aria-disabled` + 2행 `담당 팀 소속 아님`. 두 브라우저 동시 저장 → 두 번째 `다른 사람이` 문구.

### S4. 견적 표 새 열 — 일수 · 고객 비고 · 중분류 (PU6 · D-7230~7233 · D-7240)

- **열 순서(논리 순서 = 붙여넣기 순서 = Tab 순서):** 번호 · 소분류 · 항목 · 거래처 · 수량 · 단가 · **일수** · 견적가(계산) · 실행가 · 차익(계산) · 상태 · **내부 비고**(기존 `비고`의 새 이름) · **고객 비고** · **중분류** · 행동. 행동 열은 격자 로빙 · 붙여넣기에서 빠진다(탭 정지 1개 · 단축키 `Ctrl+E`, SYSTEM.md:961 — 디자인 D-F8). 엑셀 양식(ITEM · QTY · COST/UNIT · NO. of DAY/SET · AMOUNT · REMARK) 순서와 맞춘다. 대분류는 열이 아니라 **그룹 머리글**(저장값이 있으면 그것, 없으면 소분류에서 파생 — D-62 개정).
- **일수:** 숫자 열 `Num`, 소수 2자리까지(끝 0 삭제), 기본 1, 우측 정렬, `nowrap`, P2(모든 ≥700 폭). 견적가 = 수량 × 단가 × 일수 — 계산 열이라 읽기 전용(기존). 폰 접힌 줄에는 **일수가 1이 아닐 때만** `{n}일`을 단가 뒤에 싣는다(1이면 생략).
- **고객 비고 · 중분류 · 내부 비고:** 텍스트 입력, **P3**(폰은 행 시트 `KvList`에 `고객 비고` · `중분류` · `내부 비고` 라벨로). 접는 순서(먼저 접힘 → 나중): 번호 → 내부 비고 → 중분류 → 소분류 → 고객 비고 → 차익. 기본 배정은 `collapseBelow` 1280 / 1024 두 폭만 쓰고, 1280(레일)에서 가로 넘침이 실측되면 표 본문 폭 기준 접기로 옮긴다(DC-5 조건부).
- **잠김:** 승인된 현재 차수 — 기존 줄의 일수 · 고객 비고는 수량 · 단가와 같은 잠김 모양(읽기 전용 + 표 위 한 줄 `{n}차 고객 승인됨 · 고치려면 새 차수`, 새 문구 0). 새 줄은 편집 가능.
- **768(700~1023):** 열은 보이고 편집 없음 · **375/320:** 위 폰 규칙.
- **상태:** 기존 표 5상태 그대로(오류 셀 · 충돌 셀). 일수에 숫자 아님 → 오류 셀 `숫자 아님 · 1.5처럼`.
- **결정·문구 점검:** 기본값 일수 1 · 계산은 시스템 · 새 안내 문구 0.
- **DOM 합격:** 1280 · 1024 · 768에서 표 `scrollWidth ≤ clientWidth`, 항목 열 폭 ≥ 기존 최소 폭, 숨는 열은 P3뿐, 머리글 순서 = 위 논리 순서. 수량 2 · 단가 1,000 · 일수 3 → 견적가 셀 `6,000`. 일수 비움 → 저장 시 1. 375 접힌 줄에 일수 3일 때만 `3일`. 승인 fixture → 기존 줄 일수 셀 `aria-readonly="true"`, 새 줄 `false`.

### S5. 수수료 줄 · 「계산」 옆 패널 (PU3 · D-7221~7223 · DC-7)

- **줄:** 새 줄 종류 `commission`이 **그룹 `수수료`**(조정 그룹 앞 순서는 `DISPLAY_KIND_ORDER`가 정함)로 선다. 항목명은 자유 입력(예 `Venue Commission`), 수량 1 · 일수 1, 금액은 단가 칸. 거래처 · 실행가 칸은 읽기 전용(`—`). 음수 허용. 「안 붙은 줄」 셈에서 빠진다.
- **추가:** 표 머리 2차 `수수료 줄 추가`(조정 · 견적 외 비용 줄 추가 버튼과 같은 자리 · 같은 규칙: ≥1024, 승인 차수 · 정산이면 렌더하지 않음 — 이유는 표 위 한 줄). 줄 상한 300 닿으면 비활성 + `300줄 상한 · 상한은 관리자 설정`.
- **계산:** 수수료 줄의 행 행동 열에 3차 `계산`(≥1024). 누르면 **옆 패널**(`SidePanel`+`PanelForm`, 폰은 아래 시트) 제목 `수수료 계산`. 칸 둘: `율(%)`(숫자 입력, 첫 포커스, 자리표시 `5`) · `기준`(네이티브 select: `전체` / `{대분류}만` / `{대분류} 제외` — 실제 대분류 이름으로 생성). 입력 아래 서버 계산 한 줄(`--text-aux --text-muted`, 숫자 700) `기준 합 120,000,000 · 수수료 6,000,000`. 행동 줄: 2차 `취소 Esc` → 1차 `금액 채우기 Ctrl+Enter`. 율이 비면 1차 `aria-disabled` + `율 없음 · 율 적기`.
- **채운 뒤:** 패널이 닫히고 그 줄 단가 = 계산액(dirty 칸), 고객 비고가 비어 있으면 `{율}%`를 채움(수정 가능), 포커스는 그 줄 단가 칸. **율은 저장하지 않는다** — 줄 금액이 보낸 숫자다. 기준 합에는 `commission` · 조정 · 견적 외 비용 줄이 들어가지 않는다. 기준 합 0이면 결과 줄 `기준 합 0 · 기준 바꾸기`.
- **1280:** 패널 오른쪽 480 · **768:** 편집 컨트롤 없음(보기 전용) → `계산` 없음 · **375/320:** 보기 전용, 수수료 그룹은 읽기 줄로 보임(행 시트에 고객 비고).
- **상태:** LOADING 해당 없음(합은 이미 로드된 표 값) · ERROR = 칸 아래 `숫자 아님 · 5처럼` · SUCCESS = 패널 닫힘 + dirty 칸 · EMPTY = 대분류가 없으면 select에 `전체`만.
- **결정·문구 점검:** 기준을 줄 이름에서 만든 한 select로 합쳐 3단계 선택을 1개로 줄였다. 수수료 줄 금액은 사용자가 정하지 않고 율만 적는다.

### S18. 연차 취소 요청 (PU10 · D-7252~7256)

- **보는 사람 · 폭:** `evidence.intake` 쓰기 보유자. **≥1024만** 선택 열 · 막대 — 증빙 목록의 기존 편집 경계(evidence-table.tsx:523 DR-36 「1024 미만 보기 전용」 · SYSTEM.md:362)와 같다. 1024 미만(700~1023 보기 전용 폭 · 폰)은 지금처럼 행 시트 + 단건 보관(Open questions 5). D-7268 「PC · 태블릿 ≥700」은 결재함(S13) 결정이라 여기 걸리지 않는다(디자인 r2 R2-B2).
- **선택 열:** `Table.selection`(§7-3 (카)). 고를 수 없는 행(붙은 문서가 있는 줄)은 체크박스 `aria-disabled` + 행 아래 줄 `붙은 문서 있음 · 먼저 떼기`(기존 07.1 W9 행동 칸 한 줄 자리). 이미 보관된 줄은 열 칸이 비어 있다.
- **막대(≥1건, DC-8 규칙 — 막대에는 요약과 2차만 · 이 화면에는 1차가 있어 막대 버튼은 2차, 디자인 D-B3):** 이 화면의 1차는 기존 `공개 범위 저장 Ctrl+S`(evidence-table.tsx:1055-1067 — 필터 줄 오른쪽 끝, SYSTEM.md:429 · 저장할 칸이 없으면 `aria-disabled` + info 이유) 그대로. 표 위 한 줄, 왼쪽 `선택 5건`, 오른쪽 2차 `보관 5` — **단축키 없음**(SYSTEM.md:973 「선택 표 안 Ctrl+Enter = 화면 1차」). 막대는 **DOM에서도 표 앞**(보이는 순서 = 탭 순서, SYSTEM.md:1392) — 키보드는 표 안에서 Space로 고른 뒤 Shift+Tab(머리글 「이 쪽 전체 고르기」 → 막대 `보관 N`) → Enter(디자인 r2 R2-B1). 저장 안 한 공개 범위 칸이 있으면 `보관 5` `aria-disabled` + 이유 `저장 안 한 칸 · 먼저 저장`(SYSTEM.md:937). 렌더 폭은 ≥1024 — 화면 1차 `공개 범위 저장`이 서는 폭과 같아 「`보관 N` = 2차」 전제가 폭마다 맞고 §7-20 예외가 필요 없다(§7-20 ≥700 예외 문장은 S13 결재함만, DC-8). 머리글 「이 쪽 전체 고르기」 뒤 더 있으면 같은 막대에 3차 `묶음 전체 고르기 {N}`(`?batch=` 필터 상태에서만, 300건 상한 — 넘으면 `300건까지`).
- **묶음 보관(D-7284):** 일괄 등록 결과의 묶음은 결과 행의 별도 단추가 아니라 **`?batch=` 필터로 그 묶음만 보고 → 머리글 전체 고르기 → `묶음 전체 고르기` → `보관`**. 필터 칩 · 해제는 기존.
