## Phase Boundary

자금 기능의 판정을 「계급 권한(권한표)」에서 **「계급 권한 ∧ 경영관리본부 소속」**으로 바꾼다. 자금 기능 = 증빙 등록·무효, 결재 중 증빙 붙이기, 견적 조정 줄, (카드 답에 따라) 지급 처리·구매 처리·예산 현황·매출 정산. 그리고 계급 「기획 PM」의 표시 이름을 **「사원」**으로 바꾼다(권한은 그대로).

배경: 권한은 지금 계급 단위뿐이다(`domain/permissions/can.ts:16-30`, 입력 `Viewer = {id, roleId}` `domain/viewer.ts:11`). 「본부 책임자」는 전 본부 공통 계급(`domain/permissions/roles.ts:52`)이라 자금 키를 켜면 기획본부 책임자도 전사 자금 권한을 받는다. 사용자가 처음엔 새 계급 두 개(경영관리 책임자·실무)를 골랐다가 10/27 16:43 KST 카드 「본부 조건 추가(코드)」로 뒤집었다 — **새 계급 두 개 방식은 폐기**. 사용자 말(16:41): 「본부 책임자 계급에 경영관리본부에 속한 본부 책임자는 증빙, 지급 처리 등의 자금 기능을 사용할 수 있게」.

범위 밖: 새 계급 만들기, 260907식 직책(역할×본부) 층 도입, 결재 엔진 구조 변경, 확인증 QR(`certs.qr` — 경영관리의 일이지만 돈이 아님, 계급대로 둠), 손익 정보 노출표(`visible()`) 변경.

### 사용자 확정 (2026-10-27 KST)
- **D-7301:** 자금 기능은 **「그 키가 켜진 계급」이면서 「경영관리본부 소속」인 사람만** 쓴다. 새 계급 두 개(경영관리 책임자·실무) 방식은 폐기한다(사용자 카드 16:43 「본부 조건 추가(코드)」). 260907 갈래 판정(`docs/04_기본-권한.md:85-112`)과 같은 뜻 — **Reversibility:** costly — 판정 접점(권한 확인 호출처 전부)이 이 조건을 전제로 바뀐다
- **D-7302:** 계급 「기획 PM」의 표시 이름을 **「사원」**으로 바꾼다. 권한·id(`role-pm`, `DEFAULT_ROLE_ID` `domain/permissions/roles.ts:68`)는 그대로다(사용자 채팅 16:44 「기획 PM이라는 직급은 사원으로 바꿔」「이름을 바꾸는거야」). 260907 계급 이름도 「사원」(staff, `db/schema/040_seed_roles_permissions.sql:41`, `docs/04_기본-권한.md:47-53`) — 「기획 PM」은 260917에서 생긴 이름
- **D-7303:** 본부 책임자의 증빙 **보기**는 자기 본부 것만(사용자 카드 16:39). 본부 책임자 계급에 `evidence` 보기를 시드로 켠다(지금 시드는 기획 PM·팀장만 `domain/seed/role-defaults.ts:37`). 범위는 공개 줄(오늘 팀 → 그 본부, 팀 없으면 사람 본부 칸 — 07.1-07). 보기는 본부 조건 대상이 아니다
- **D-7304:** 경영관리본부 실무(사원 계급)는 프로젝트·지출결의 보기, 본인 지출결의·연차 쓰기를 한다(사용자 카드 16:39). 사원(옛 기획 PM) 계급의 시드에 이미 있다(`role-defaults.ts:13-14` projects, `domain/seed/expenses.ts` 지출결의, `domain/seed/approvals-leave.ts` 연차) — 새로 켤 것 없음, 시험으로 확인만
- **D-7305:** 견적 조정 줄(`projects.adjustment` 쓰기)은 **경영관리본부 책임자만**(사용자 카드 16:41). 본부 책임자 계급에만 켜고 본부 조건을 건다. 260907 `quote.adjust` = 돈 틀 책임자 이상(`server/src/quotes.ts:2809`, `145_money_hand.sql:190`, 2026-09-15 결정 ②)
- **D-7306:** 결재선 ③단 「경영관리」 단계(지출결의·연차·정산)의 결재자는 **경영관리본부의 본부 책임자**다 — 실무(사원)는 결재 후보가 아니다(사용자 카드 16:39 「경영관리 책임자가 결재선 단계 담당, 실무는 결재 담당 아님」을 새 방식으로 옮김). 지금 기본값은 담당 계급 「계급 무관」(`""`) + 경영관리본부(`domain/settings/keys.ts:644·975·1508`, 시드 `domain/seed/approvals-leave.ts:15-16`·`expenses.ts:49-50`·`settlements.ts:75-76`)라 경영관리본부 사람 전원이 후보가 된다. ③단 담당 계급 기본값을 「본부 책임자」로 바꾼다. 260907은 `fixed_position`으로 경영관리 책임자 직책을 직접 지정(`db/schema/010_tables.sql:346-389`, `:435`)

### 계획 재량 (Claude 판단 — 사용자가 뒤집을 수 있다)
- **D-7310 자금 본부를 가리키는 방법:** 설정 값 하나(본부 uuid, `dynamicOptions: "org_units"`)로 둔다. 이름 문자열 판정은 하지 않는다(본부 이름은 `renameOrgUnit` `domain/org/index.ts:160`으로 바뀔 수 있다 — 260907도 「이름이 아니라 갈래로 판정」 `docs/04_기본-권한.md:28-30`). 선례 `EVIDENCE_VISIBILITY_DIVISION_ORG_UNIT`(`domain/settings/keys.ts:1383-1393`) — 기본값 없음, 시드가 「경영관리본부」 uuid를 없을 때만 채움(운영 값 안 덮음). 스키마·마이그레이션 없음. 값이 비어 있으면 본부 조건 대상 키는 아무에게도 열리지 않는다(대표·시스템 관리자 예외 D-7313은 그대로) — **Reversibility:** reversible
- **D-7311 사람의 소속 본부:** 오늘 발령 팀의 본부, 팀이 없으면 사람 본부 칸(`users.division_id`). 07.1-07이 정한 규칙(add-alongside, 팀이 이긴다 — `07.1-07-PLAN.md:110`)을 그대로 쓴다. 따라서 **07.1-07(칸·범위)과 07.1-14(사람 화면의 본부 고르기)가 main에 들어간 뒤** 실행한다. 경영관리본부 책임자는 보통 팀이 없어 본부 칸이 필요하다(260907 `server/src/receipts.ts:243-253` 「관리팀은 경영관리본부 소속이고 팀이 없다」)
- **D-7312 본부 조건 대상 키는 한 곳에 목록으로:** `evidence.intake`(쓰기) · `expenses.evidence_void` · `expenses.evidence_attach` · `projects.adjustment` + 카드 답(D-7307 추천: `expenses.payments`·`cards.purchases`·`projects.budget`, D-7309 추천: `projects.revenue`, D-7308 추천: `cards.proxy` 제외). 판정은 가능한 한 한 접점(권한 확인 함수)에 넣어 호출처마다 따로 고치지 않는다 — 호출처 목록은 `/mnt/project-files/07.3-prep/code-map.md` §3. 메뉴(레일 「증빙」 `docs/design/SYSTEM.md:328`, `app/(app)/layout.tsx:45-52`)·서버 액션(`registerAction` 메타)·도메인 직접 `can()` 호출·증빙 범위(`evidenceScopeFor`의 「등록 쓰기면 전 행」 `domain/permissions/scope-for.ts:167`)가 모두 같은 결과를 내야 한다
- **D-7313 본부에 속하지 않는 계급:** 대표·시스템 관리자처럼 회사 전체를 보는 계급(`viewScope: "company"`, `roles.ts:51·55`)은 본부 조건을 받지 않고 지금 동작 그대로다. 260907: 대표는 어느 본부에도 안 속하고(`docs/04_기본-권한.md:122-128`) 경영관리 부재 시 대행(`:130-135`). 시스템 관리자는 지금 시드 루프로 모든 키를 가진다(`domain/permissions/menus.ts:44-49` 주석) — 이번에 줄이지 않는다. 판정은 계급 칸으로 하고 계급 id·이름을 코드에 박지 않는다(`menus.ts:20-24` 원칙)
- **D-7314 자금 담당의 보는 범위:** 경영관리본부 소속이면서 자금 키가 있는 사람은 프로젝트·지출결의를 **회사 전체**로 본다. 그래야 조정 줄(프로젝트 상세)·지급 대상 목록·증빙 붙이기가 다른 본부 문서에 닿는다(본부 책임자 계급 보기 범위는 `org_unit`, 사원은 `team` — `roles.ts:52·54`). 260907 근거는 손익 열람에서 「대표·경영관리 책임자 = 전사, 기획본부 책임자 = 제 본부」(`.planning/research/ERP260907-CONTEXT.md:93`)와 증빙 흐름 「①경영관리 등록·공개 ②기획팀 첨부」(`:76`)뿐이다 — 프로젝트·지출결의 목록 범위를 직접 정한 줄은 찾지 못했다(계획이 260907 `positions.view_scope` 시드에서 경영관리 자리 값을 확인한다). 손익 숫자 노출(`visible()` 정보 노출표)은 바꾸지 않는다
- **D-7315 시드 기본값(없을 때만 넣기, 관리자 값 보존):** 260907 「사원 이상」 돈 틀을 따라 사원·팀장·본부 책임자 계급에 `evidence.intake` 쓰기·`expenses.evidence_void`·`expenses.evidence_attach`(사용자 16:39 「실무=증빙 키」), D-7307·D-7309 답이 「경영관리본부만」이면 `expenses.payments`·`cards.purchases`·`projects.budget`·`projects.revenue`도 켠다. `projects.adjustment`는 본부 책임자만(D-7305). 본부 조건이 실제 사람을 거른다. 팀장 계급은 경영관리본부에 팀장 자리가 없어도(260907 `docs/04_기본-권한.md:122-128`) 사원 이상 규칙대로 함께 켠다. 기존 DB(스테이징)에도 사람 손 없이 들어가는지(배포 때 시드가 도는지) 계획이 확인한다
