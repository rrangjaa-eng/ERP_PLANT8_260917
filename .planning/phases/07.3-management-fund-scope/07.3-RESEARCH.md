## Summary

**한 줄 결론:** 본부 조건은 `can()` 안(기본 경로)에 넣는 것이 맞다. 자금 8개 메뉴 키에 대해 `permission_matrix` 행이 허용이면 한 번 더 「계급 viewScope === company(면제) 또는 사람의 소속 본부 === 설정된 자금 본부」를 확인한다. 메뉴/레일(`layout.tsx:51`), 도메인 직접 호출 80여 곳, `evidenceScopeFor`(scope-for.ts:168)가 전부 `can()`을 거치므로 자동 적용된다. **`registerAction`은 런타임 권한 검사가 아니라 선언 레지스트리**(`lib/actions/registry.ts:15`)라서 고칠 호출처가 없다 — 사용자가 걱정한 「메타 검사」는 존재하지 않는다.

**`can()`을 우회하는 곳은 4곳이다 (이것이 이 페이즈의 숨은 구멍):** ① 알림 받는 사람 SQL `listPaymentManagerIds`(`repositories/notify-sources.ts:33`, `expenses.payments`)·`listMenuWriterIds`(`:375`, `evidence.intake`)가 `permission_matrix`를 직접 조인 — 기획본부 사원이 지급 알림·「임자 없는 증빙」 알림을 받게 됨. ② **결재 조직 스냅숏 `listOrgSnapshot`(`repositories/org-snapshot.ts:17-39`)이 본부를 팀 발령에서만 구함** — `users.division_id`만 있는 팀 없는 경영관리 책임자는 ③단(`resolveHolders`, `domain/approvals/route.ts` `p.orgUnitId === step.scopeTargetId`)의 후보가 못 된다. 07.1 어느 플랜도 이 파일을 고치지 않는다. ③ `computeRowScope`의 `org_unit` 갈래도 팀에서만 본부를 구해(scope-for.ts:138-143) 팀 없는 본부 책임자는 `orgUnitId: null` → 보이는 행 0(repositories/row-scope.ts `if (by.orgUnitId === null) return sql\`false\``) — D-7314 확대가 필요한 실제 이유. ④ 시드의 `evidence.intake` 행 직독(domain/seed/index.ts:250-254)은 보기 행 추가용이라 무해.

**가장 큰 함정 두 가지:** (a) 시드 PR(사원에 자금 키 켬)이 판정 PR보다 먼저 배포되면 기획 사원 전원이 지급·증빙을 갖는다 → 시드는 반드시 판정 뒤. (b) 판정이 배포되면 지금 자금 키를 쓰는 운영 계정이 경영관리본부(팀 또는 `users.division_id`) 소속이 아닐 때 즉시 접근을 잃는다 → 배포 전 확인 항목.

**Primary recommendation:** `domain/permissions/fund-scope.ts`(잎 모듈: 키 목록·설정 키 문자열) + `viewer-division.ts`(07.1-07의 인라인 규칙을 추출) + `can()` 한 접점 + `computeRowScope` 확대 + 우회 4곳 정렬을 **위험 경로 PR 하나**로, 시드·③단 보정은 그 뒤 무인 PR, 「사원」 이름은 마이그레이션 PR로 따로.

### Pattern 1: 요청 memo = viewer 객체 WeakMap
`rowScopeFor`가 이미 쓰는 방식 `[VERIFIED: scope-for.ts:93-97]`: `const requestMemo = new WeakMap<Viewer, Map<RowScopeEntity, Promise<RowScope>>>();` + `memoizeRowScopeForRequest(viewer)`를 `getSession`이 호출(`lib/viewer.ts:69` `memoizeRowScopeForRequest(viewer);`). 같은 함수에 자금 memo 초기화를 함께 넣으면 `lib/viewer.ts` 무변경. 주석이 이유를 적는다: 「React cache()는 렌더 안 memo만 문서화돼 서버 액션에서의 동작이 불명확하다」(scope-for.ts:91). repo의 `cache(` 사용은 `app/(app)/next-turn-request.ts:8`·`app/print/certs/[id]/layout.tsx:13`·`app/(app)/certs/submissions/[id]/page.tsx:23`·`app/c/[token]/page.tsx:10` 4곳뿐(전부 app 계층 RSC). `deps` 주입 시 memo 건너뜀(scope-for.ts:101) 규칙을 그대로 따른다 — 단위 시험이 DB 없이 돎.

### Pattern 2: 시드 「관리자가 안 만진 값만」
`upsertVisibilityIfUnedited`(repositories/permissions.ts:127, `where: isNull(visibilityMatrix.updatedBy)`)가 선례. `settings_simple`도 `updatedBy` 칸이 있다 `[VERIFIED: db/schema/settings.ts:12 updatedBy: text("updated_by")]`, 시드 삽입은 `updatedBy` 없이 `values({ key, value })`(repositories/settings.ts:126) → NULL, 화면 저장은 `updatedBy: by`(repositories/settings.ts:~41 `set: { value: stored, updatedAt: new Date(), updatedBy: by }`). 따라서 「옛 기본값 그대로」 = `value = '""'::jsonb AND updated_by IS NULL`로 **관리자가 같은 값("")을 명시 저장한 경우까지** 구분된다.

### Anti-Patterns
- 호출처 80여 곳마다 본부 확인을 덧붙이기 — 한 곳이라도 빠지면 구멍(06.2의 `scope.ts:36-41` 호출부 누락 교훈, row-scope.ts 머리 주석).
- 계급 id/이름 비교로 면제(`menus.ts:20-24` 원칙) — `roles.view_scope`로 한다.
- 본부 이름 문자열 `"경영관리본부"` 비교를 런타임에 두기 — 시드 1회만 허용(seed/approvals-leave.ts:15).

## Common Pitfalls
1. **시드가 게이트보다 먼저 배포됨** — 사원(기획 포함)이 지급·증빙 전권. 07.3-02 `depends_on` 01 머지·배포. 검증: 01 배포 환경에서 기획본부 사원 `can(payments)` false 확인 후 02.
2. **운영 계정 소속 누락** — 게이트 배포 즉시 현재 자금 키 보유 계정이 경영관리본부 소속이 아니면 접근 상실(설정이 비어 있어도 전원 닫힘). 배포 전 점검표: 자금 본부 설정 uuid 시드됨 · 대상 계정이 경영관리팀 발령 또는 `division_id` 보유 · company 면제 계급 확인.
3. **설정 미시드/본부 이름 불일치** — `findOrgUnitByName("경영관리본부")` 못 찾으면 설정 없음 → 닫힘. 시드 코드가 못 찾았을 때 경고 로그 1줄(요청 밖 추가지만 운영 장애 방지; 계획 재량).
4. **`computeRowScope` 확대로 대표 외 회사 전체 열람** — 확대는 `rows:"all"`이므로 `visible()` 정보 노출표는 그대로 걸러야 한다(D-7314 「손익 숫자 노출표는 안 바꿈」). 손익 화면(`pnl`)은 이 변경 대상 아님을 시험으로 고정.
5. **알림 B1/B2 누락** — 판정 PR에서 빠뜨리면 비소속 사원에게 지급 알림 발송(링크는 `can()`으로 사라지지만 알림 문구·건수는 감). 교집합 시험 필수.
6. **순환 import** — `can.ts`→`keys.ts` 직접 import 금지(`registry.ts:5`가 `can` import). 잎 모듈 경유.
7. **07.1-07 시험 회귀** — `evidenceScopeFor` 리팩터가 deps 이름을 바꾸면 07.1-07 단위·통합 시험이 깨짐. deps 시그니처 동결.
8. **게이트 하의 시험 파급(가장 큰 작업량)** — 비-company 계급에 자금 키를 준 시험은 모두 소속 지정이 필요. 공용 픽스처 `makeFundMember(world, role)`로 중앙 처리(Validation 절).
9. **`PERMISSION_REQUIRES`** — 시드가 쓰기만 넣고 보기를 빼면 권한표가 일관성 규칙을 어긴 상태가 됨(Q5).
10. **codex 디자인 리뷰 시드** — `scripts/codex-design-review/seeds.ts:155·372·512-517`이 `role-pm`에 자금 키를 켜고 `role-pm`을 경영관리팀에 둠(:72) → 게이트 후 화면 캡처가 비어 보일 수 있어 설정 시드 한 줄 필요(코드 지도에 없던 파일).
