## Summary

모든 코드 질문은 **마이그레이션 0 · 위험 경로 0 · 새 의존성 0**으로 풀린다. 설정 키 다섯은 `SETTING_DEFS.push(...)` 블록 하나로 끝나고(설정 화면은 `namespace`별로 자동 생성), `document_print` 행동 종류는 `action_log.action_type`이 자유 `text` 칸이라 `record.ts`의 상수 배열 3곳만 고치면 된다. 인쇄 CSS는 Chromium 153(Playwright 1.63 번들)에서 `@page` 여백 박스 `counter(page)/counter(pages)`와 `<thead>` 반복이 실제로 동작함을 프로브로 확인했다.

그러나 CONTEXT/UI-SPEC가 가정한 **데이터 출처 세 군데가 코드와 다르다**. 플래너가 반드시 새 읽기 함수/결정을 계획에 넣어야 한다: (1) `getExpense`는 결재 시트용 `ExpenseDetailDto`가 아니라 `ExpenseDocumentDto`를 돌려주고 증빙 파일 이름은 `listEvidence`로 따로 읽어야 한다. (2) 연차의 `소속 · 입사일 · 부여/사용/잔여`를 **결재자(관리자 아님)가** 읽는 함수가 없다 — `getLeaveBalanceForUser`는 `admin.people` 보기 권한, `getLeaveBalanceForRequest`는 `입사일 · 퇴직일 없음`·`남음` 위주. (3) 정산서의 `매출 기준`은 `loadProjectProfit` 결과에 없고(`수익금 · 수익률`만), 프로젝트별 지출결의/구매 요청 목록 읽기 함수가 없다(구매 요청 목록은 프로젝트 필터조차 없음). 또 `app/**`에서 `<table>`이 lint 금지(04.6 SC 2)인데 `<div display:table>`은 쪽마다 머리가 **반복되지 않음**을 실측했으므로 `eslint/restrictions.mjs`에 `app/print/**` 예외를 두는 결정이 필요하다.

**Primary recommendation:** 공용 틀(`app/print/_frame/`) + 회사 정보 키 + `document_print` 로그 + 지출결의서를 1플랜(규칙 문서·eslint 예외 포함)으로, 연차(새 `domain/print/leave` 읽기)와 정산서(새 프로젝트별 목록 읽기 + `loadProjectProfit` 확장)를 각각 뒤 플랜으로 쪼개고, 어느 플랜도 `domain/approvals|money|revenue|corp-cards`, `domain/permissions`, `db/**`, `.claude/`를 **수정하지 않게** 한다(읽기 import는 `/cso`·사용자 머지 게이트를 걸지 않음 — §Q7·Q8).

### Pattern 1: layout에서 응답 전 404 + 요청 단위 중복 제거
**What:** layout이 읽기 함수를 한 번 불러 null이면 `notFound()`; 같은 읽기를 `cache()`로 layout·`generateMetadata`·page가 공유.
**Example:**
```tsx
// Source: app/print/certs/[id]/layout.tsx (기존, 이 세션에서 읽음)
const judgePrintable = cache(async (id: string): Promise<boolean | null> => {
  if (!(await getSessionId())) return null;
  const { viewer } = await requireSession();
  return isCertificatePrintable(viewer, id);
});
export async function generateMetadata({ params }) {
  const { id } = await params;
  return (await judgePrintable(id)) === true ? { title: "확인증 인쇄" } : {};
}
export default async function CertPrintLayout({ children, params }) {
  const { id } = await params;
  if ((await judgePrintable(id)) === false) notFound();
  return children;
}
```
새 서류는 `cache`된 `loadExpensePrint(id)`를 별도 모듈(`app/print/expenses/[id]/load.ts`)에 두고 layout·metadata·page가 모두 import한다. `notFound()`를 던진 layout은 **자기 세그먼트의 not-found를 못 쓰고 상위 세그먼트의 `not-found.tsx`가 받는다** — 확인증이 `app/print/certs/not-found.tsx`(`[id]` 위)에 둔 이유. 새 서류는 `app/print/expenses/not-found.tsx` 등 `[id]`의 부모에 둔다(또는 `app/print/not-found.tsx` 하나 — certs는 자기 것이 우선).

### Pattern 2: 설정 키 블록 추가(마이그레이션 0)
**What:** `SettingDef` 객체 + `SETTING_DEFS.push(...)`. 섹션은 `namespace`가 만든다.
**Example:**
```ts
// Source: domain/settings/keys.ts:1408-1420 (기존 패턴) — 파일 끝에 같은 꼴로 추가
export const PRINT_COMPANY_NAME: SettingDef<string> = {
  key: "print.company_name", kind: "simple",
  schema: z.string().max(60, "길이 초과 · 60자 이내"),
  label: "회사명", namespace: "회사 정보", default: "",
};
SETTING_DEFS.push(PRINT_COMPANY_NAME, /* …주소·사업자번호·대표자·전화 */);
```
읽기는 `getSimpleSettingValuesOrDefault([...5 defs])`(`domain/settings/registry.ts:474`) — **SELECT 한 문장**이고 저장값이 스키마를 못 지나면 그 칸만 기본값으로 본다.

### Anti-Patterns to Avoid
- **`getExpense` 결과를 `ExpenseDetailDto`로 가정:** 타입이 다르다(§Q4-a).
- **합계를 화면에서 더하기:** `domain/money` 밖에서 `Money` 산술은 lint 금지(`eslint/rules/money-boundary.mjs`). 합계는 `payableKrw`(저장/계산된 지급 총액)를 그대로.
- **PrintTable을 `<div>`로:** 쪽 머리 반복이 안 된다(실측).
- **registry 키를 `domain/settings/` 안에서만 참조:** `registry-coverage.test.ts`는 `domain/settings` **밖**에서 상수 이름이 한 번 이상 참조돼야 통과 — `domain/print/company.ts`가 읽으면 충족.
- **`ui/`에 인쇄 컴포넌트 두기:** `ui/**` CSS는 px/mm 리터럴 금지(stylelint). 인쇄 전용 px/mm 예외는 `app/print/**/*.css`에만(`stylelint.config.mjs`).

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| 열람 판정 | 별도 권한 키/판정 | `getExpense`/`getLeave`/`getSettlement`(null → 404) | D-7408. 판정이 이미 내장 |
| 금액 노출 | 계급별 if | `project()` 투영 결과의 키 유무 | 투영에서 빠진 필드는 행째 없음(`buildExpenseDetailRows` 선례) |
| 손익 수치 | 수익금/수익률 재계산 | `loadProjectProfit` → `summarizeProjectProfit` | D-7402; 기준(발행합/견적합)을 SQL 한 곳이 정한다 |
| 결재선 | 별도 단계 계산 | `getApprovalView(...).steps` | D-7410 |
| 설정 읽기 | 직접 SELECT | `getSimpleSettingValuesOrDefault` | 1 SELECT + 기본값 대체 |
| 행동 로그 | 직접 INSERT | `recordAction(viewer, {actionType,…})` | append-only 트리거·UnknownActionTypeError 검증 |
| 시각 표기 | `Intl` 새로 | `kstDateTimeOf` (`lib/kst-date.ts:38`, `YYYY-MM-DD HH:mm`) | `seoulMinuteOf`는 연도가 없는 `MM-DD HH:mm`이라 종이용으로 부적합 |
| 사업자번호/전화 검증 | 새 정규식 | `businessNoProblem`(`domain/vendors/business-no.ts`, import 없는 순수) · `normalizeContactPhone`/`formatContactPhone`(`domain/certs/format.ts`) | **주의: 검증 숫자 포함 — §Pitfall 8** |

**Key insight:** 이 페이즈의 위험은 "만드는 것"이 아니라 "다시 계산하거나 우회하는 것"이다. 노출표·열람 판정·손익·결재선은 모두 기존 함수의 출구를 그대로 거쳐야 한다.

## Common Pitfalls

### Pitfall 1: 새 server action 파일의 등록 누락
**What goes wrong:** `app/print/_frame/actions.ts`만 만들면 `action-registry-completeness.test.ts`·`leak-scan-coverage.test.ts` 둘이 CI에서 빨갛다.
**How to avoid:** `actions.registry.ts` 동반 + `leak-scan.test.ts`에 `import "@/app/print/_frame/actions.registry";`. 예외 목록(`ACTIONS_WITHOUT_REGISTRY`)에 추가 금지.
**Warning signs:** 단위 시험 「등록 파일도 예외도 없음」.

### Pitfall 2: `ACTION_TYPE_LABELS` 누락 → typecheck 오류
`Record<CoreActionType,string>`이므로 키가 빠지면 TS가 막는다. 세 배열 동시 수정.

### Pitfall 3: 여러 쪽 서류에서 `.sheet` 고정 높이/패딩 여백
`print-cert.module.css`는 `@page margin: 0` + `.sheet height: 297mm`(한 쪽 전용). 여러 쪽에는 `@page margin: 22mm 22mm 20mm` + `.sheet min-height`(화면)·`@media print`에서 padding/width 0. **쪽 번호 박스는 실측 동작:** `@bottom-right { content: counter(page) " / " counter(pages); }` → `pdftotext`에 `PLANT8 ERP   1/4 … 4/4` [VERIFIED: 프로브, Chromium 153]. 확인증은 건드리지 않는다(회귀 0).

### Pitfall 4: `<div display:table-header-group>`은 쪽 머리가 반복되지 않는다
**실측:** 120행 표를 `<table><thead>`로 만들면 3~4쪽에 걸쳐 머리 텍스트 `번호`가 쪽마다 4회 나오고(프로브 1), 같은 표를 `<div role="table" style="display:table">`+`display:table-header-group`으로 만들면 3쪽인데 머리가 1회만 나온다(프로브 2, `break-inside: avoid` 유무와 무관) [VERIFIED: `/tmp/.../scratchpad/pdf-probe.cjs`, `pdf-probe2.cjs` + `pdftotext | grep -c 번호`]. → `PrintTable`은 **실제 `<table><thead>`** 여야 한다.

### Pitfall 5: `app/**`의 `<table>` lint 금지와 충돌
04.6 SC 2로 `app/**`에서 `<table>` 직접 금지이고 이관 전 표시는 래칫이 0개로 고정. 선택지:
1. **(권고) `eslint/restrictions.mjs`에 `app/print/**/*.tsx`용 override를 더해 `<table>`만 허용(`<dialog>` 금지 유지).** 파일 주의 사항: 「한 파일에 no-restricted-syntax를 둔 설정 객체가 둘이면 뒤가 앞을 교체한다」(`restrictions.mjs:5-6`) → 뒤 객체에 `<dialog>` selector를 다시 넣을 것. `DECISIONS.md`에 「인쇄 라우트는 쪽 머리 반복 때문에 `<table>` 허용」 기록 + `eslint-restrictions.test.ts`에 `app/print/…` 통과/`app/(app)/…` 여전히 금지 단언.
2. 마크업 전용 `ui/print-table`(className 주입, CSS는 app/print) — `ui/` 변경이 화면 게이트·`ui/` 컴포넌트 목록(UI-SPEC 29개)을 건드림. 비권고.
3. `StaticTable`/`Table` — 화면 토큰·폰 접힘으로 부적합.
이 선택은 정책이라 사용자/플랜 체커 확인 필요(A4).

### Pitfall 6: 서버 컴포넌트에서 `buttonLinkClassName`
`"use client"` 모듈 함수라 서버에서 호출 불가(§Q5). `Button.module.css` 클래스를 직접.

### Pitfall 7: 승인 완료 문서의 결재란 칸 수
종결 상태 `steps`는 처리된 단계만(§Q4-d). DOM 감사 「칸 수 = 1 + 단계 수」 픽스처 기대값을 "표시된 steps 길이"로 정의해야 한다.

### Pitfall 8: 사업자번호 검증 숫자와 힌트 예시
`businessNoProblem`은 자리수뿐 아니라 **국세청 검증 숫자**까지 본다. UI-SPEC 힌트의 예시 `123-45-67890`은 가중합 `1·1+2·3+3·7+4·1+5·3+6·7+7·1+8·3+9·5=165`, `+⌊9·5/10⌋=4` → 169, `(10−9)%10=1 ≠ 0`이라 **검증 숫자 실패**(직접 계산 `[VERIFIED: domain/vendors/business-no.ts 가중치 [1,3,7,1,3,7,1,3,5]]`). 설정 칸에서 `businessNoProblem`을 쓰면 힌트 예시 자체가 거부된다. 권고: 형식(숫자 10자리, 하이픈 허용)만 검사하고 검증 숫자는 보지 않거나(회사 번호 오타 방지 vs 시험 편의), 힌트 예시를 유효 번호로 바꾼다. 전화는 `normalizeContactPhone`이 `02-123-4567`(국번 3자리+4)을 `02\d{7,8}`로 받으므로 예시 OK. 저장 형식: 인증서 전화는 숫자만 저장(`CERT_CONTACT_PHONE`) — 종이에는 `formatContactPhone`으로 하이픈 복원.

### Pitfall 9: 행동 로그 화면의 대상 UUID 노출
§Q2: `entity`가 리졸버에 없으면 raw id. `detail.number`를 넣고 UI-SPEC 「화면에 아무것도 띄우지 않음」과 별개로 로그 화면 가독성은 번호 detail로.

### Pitfall 10: `generateMetadata`가 열람 불가 건에 제목을 내는 것
확인증 `layout.tsx` 주석(독립 DOM 감사 L3): 404 변종에는 제목을 내지 않는다(`{}` 반환).

### Pitfall 11: 인쇄 기록의 이중 호출
`beforeprint`+버튼 클릭이 모두 같은 액션을 부른다 → UI-SPEC 「5초 내 중복 1건」은 **클라이언트 가드**(모듈 변수 시각)이므로 서버는 매 호출마다 1건. 서버 중복 제거는 `[ASSUMED]` 불필요(append-only 로그에 호출당 1건 허용 여부는 사용자 확인).
