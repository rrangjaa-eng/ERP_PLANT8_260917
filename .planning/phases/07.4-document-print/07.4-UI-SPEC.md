## Typography

인쇄 글자 크기는 화면 역할 척도(`--text-*`)가 아니라 인쇄 템플릿 자체의 px 고정값이다(SYSTEM §6-6 :632 — 화면 척도가 바뀌어도 종이는 바뀌지 않는다). 본문 크기 3단(24 · 14 · 12) + 보조 11 + 워드마크 15. **checker 참고: 「크기 3~4개 · 굵기 2개」 일반 기준보다 많은 것은 §6-6이 2026-09-18에 확정한 `14 · 12 · 11 · 15 · 24` / `400 · 600 · 700 · 800(워드마크만)`을 그대로 따르기 때문이며, 이 페이즈가 새 크기·굵기를 만들지 않는다.**

| Role | Size | Weight | Line Height | 쓰는 곳 |
|------|------|--------|-------------|---------|
| Display | 24px | 700 (`--fw-bold`), 자간 `--ls-head` | 1.3 (`--lh-tight`) | 서류 제목 · 합계 금액 |
| Body | 14px | 400 (`--fw-regular`), 자간 `--ls-body` | 1.6 (`--lh-body`) | 값 · 표 본문(정산서 목록은 12) · 결재 칸 이름(700) |
| Label | 12px | 600 (`--fw-medium`) | 1.5 (`--lh-table`) | 라벨 · 표 머리 · 번호 줄 · 상태 글자 · 출력 일시 · 회사 정보 줄 · 정산서 목록 행 · 절 제목(자간 .08em) · 바닥줄 |
| Fine | 11px | 400 | 1.4 (`--lh-head`) | 결재 칸 일시·상태 · 외화 병기 보조줄 · 표 보조줄 |
| Wordmark | 15px | 800 (`--fw-mark`) | 1.3 | 머리 왼쪽 회사명 글자 자리 — `--print-rule` 색. 워드마크 전용 굵기 |

규칙:
- 숫자 · 날짜 · 문서 번호는 `font-variant-numeric: tabular-nums`, `--ls-num`, `white-space: nowrap`(SYSTEM §2-4). 형식도 §2-4 그대로(원화 정수+쉼표 · 날짜 `2026-11-04` · 시각 24시간 · 값 없음 `—` · 외화 두 줄 병기).

- 합계 금액 24px은 지출결의서 합계 행 하나뿐. 정산서에는 24px 숫자를 쓰지 않는다(제목만) — 손익 네 칸도 14px 700.

## Color

종이는 흰색 바탕에 **글자 검정 + 구조 선 그린 + 구분 가로선 회색**이 전부다. 새 색 없음.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--surface-base` (인쇄에서 `#FFFFFF`) | 종이 면 전체. 화면에서는 `--surface-canvas` 바탕 위에 종이 외곽 `1px --border-surface` |
| Secondary (30%) | `--print-ink` `#000` 글자 + `--print-line` 1px 가로선 | 모든 글자 · 숫자 · 라벨·값 행 구분선 · 표 행 구분선 · 정산서 손익 칸 윗선 |
| Accent (10%) | `--print-rule` (= `--g-700`) | 아래 「Accent reserved for」 일곱 곳뿐 |
| Destructive | 없음 | 이 페이즈에 파괴적 행동 없음. 종이에 `--status-danger` · 상태색 없음. 반려도 글자 |

Accent reserved for (이 밖에 쓰지 않는다):
1. 머리 왼쪽 워드마크 자리의 회사명 글자(15px 800)
2. 제목 아래 2px 괘선
3. 명세 표 · 목록 표 머리 아래 2px 선(`thead` 아래)
4. 지출결의서 합계 행 위 2px 선
5. 결재란 칸마다 위 2px 선
6. (화면 전용) 인쇄 라우트 1차 버튼 `인쇄 · PDF 저장`은 `ui/button` 1차(`--accent`) 그대로 — 종이에는 없다
7. (화면 전용) 포커스 링 `--focus`

흑백 인쇄 규칙(CONTEXT 「흑백 프린터에서도 읽혀야 한다」): 모든 구조 선은 **border**로 그린다(배경이 아니라서 브라우저 「배경 그래픽」이 꺼져 있어도 찍힌다). `--print-rule`은 흑백에서 짙은 회색이 되어도 선으로 읽힌다. **상태 · 결재 결과 · 권한 구분은 색이 아니라 글자로만 전한다.** `StatusTag` · 색 배지 · 굵기만 다른 구분 금지.

## 공용 인쇄 틀 (P0)

### 종이 · 용지

```
화면(screen)                          인쇄(print)
┌ .root  --surface-canvas ┐           (바탕·화면 바·외곽 없음)
│ ┌ 화면 바 min(210mm, 100%) ┐         @page { size: A4 portrait;
│ │ 닫기              인쇄 · PDF 저장 │             margin: 22mm 22mm 20mm }
│ └──────────────────────┘          .sheet { width:auto; padding:0 }
│ ┌ .sheet 210mm, min-height 297mm ┐   ← 쪽마다 브라우저가 22/22/20mm 여백을 준다
│ │ padding 22 / 22 / 20mm         │
│ └────────────────────────────────┘
└─────────────────────────────────┘
```

- **여러 쪽 서류의 여백은 `@page margin`으로 준다**(`.sheet` padding이 아니다). `.sheet`에 padding만 두면 여백이 첫 쪽 위와 마지막 쪽 아래에만 생기고 2쪽부터 위·아래가 0이 된다. 화면에서는 `.sheet`가 같은 값(22/22/20mm)의 padding으로 종이 모양을 흉내 내고, `@media print`에서 `.sheet`의 padding·width·outline·margin을 0/auto/none으로 접는다. (확인증 `print-cert.module.css`는 한 쪽 전용이라 `@page margin: 0` + 고정 `height: 297mm` 그대로 둔다 — 건드리지 않는다.)
- 화면: `.root` 바탕 `--surface-canvas`, 세로 패딩 `--s-4`; `.sheet` 면 `--surface-base` + `1px --border-surface` 외곽; 종이는 가운데 정렬, `width: 210mm` 고정(폭이 좁으면 가로 스크롤 — 인쇄 라우트는 SYSTEM §11 가로 넘침 점검에서 제외).
- 인쇄: `@page` 아래 바닥줄은 용지 margin box로 그린다(`@bottom-left` = `PLANT8 ERP` · `@bottom-right` = `{쪽} / {전체}`, 12px, 글자 색 지정 없음 = 기본 검정 = `--print-ink`, `padding-bottom: 8mm`로 용지 아래 12mm 위에 글자 바닥선). margin box를 지원하지 않는 브라우저에서는 바닥줄·쪽 번호가 없을 뿐 본문은 깨지지 않는다. 바닥줄은 화면에 나오지 않으므로 **PDF/인쇄 미디어 캡처로만 확인한다**.
- `document.title`(= 브라우저 PDF 저장 기본 파일 이름)은 서버가 `generateMetadata`로 낸다: `지출결의서 {번호}` · `연차 신청서 {번호}` · `프로젝트 정산서 {프로젝트 번호}`. 열람 판정이 `null`인 404 변종에는 제목을 내지 않는다(확인증 `layout.tsx:21-24` 패턴).
- 화면 바(`PrintBar`)는 종이 위 한 줄, 폭 `min(210mm, 100%)` · 가운데 정렬 — 창이 종이(≈793.7px)보다 넓으면 종이와 같은 폭, 좁으면 창 폭이라 1차 버튼이 화면 밖으로 밀리지 않는다(종이 폭 고정이면 768 창에서 약 26px · 700 창에서 약 94px 잘린다 — 디자인 검토 F5). 왼쪽 3차 `닫기`(`window.close()` — 로그인 리디렉트 등으로 열린 창이라 닫히지 않으면 그 서류의 상세 화면으로 이동: 지출결의 `/expenses/{id}` · 연차 `/leave/{id}` · 정산 `/projects/{id}/settlement`), 오른쪽 1차 `인쇄 · PDF 저장`. 인쇄에서 `display: none`. 폰 직접 주소 진입에서도 바는 창 폭 안에 있고 종이만 가로 스크롤된다.

### 머리 (`PrintHeader`)

```
(A줄)  [워드마크 자리]                                   출력 2026-11-04 14:02
(B줄)  서울시 … · 사업자번호 123-45-67890 · 대표 홍길동 · 전화 02-123-4567
```

- **A줄**: 왼쪽 워드마크 자리 = 회사명 글자(15px 800, `--print-rule`). 값이 비면 그 자리는 빈 채로 두고(D-7405 「비어 있으면 그 줄만 빼고」) 오른쪽 `출력 …`은 `margin-left: auto`로 제자리에 남는다. ### 결재란 (`PrintApproval`) — 동적 칸 수 (D-7410)

```
결재                                                    ← h2 12px 600, 자간 .08em
══════════  ══════════  ══════════  ══════════        ← 칸마다 위 2px --print-rule
기안         팀장         경영관리     대표               ← 단계 이름 12px
박서연       김도윤       이수아       —                 ← 이름 14px 700 (미처리는 400)
승인         승인         승인         대기               ← 상태 글자 11px 600
09-05 …     …                                         ← 일시 11px: YYYY-MM-DD HH:mm
```

- 칸 = **첫 칸 `기안`**(기안자 이름 · 상신 일시 · 상태 글자 `상신`) + **`getApprovalView(...).steps`의 단계마다 한 칸**(`domain/approvals/dto.ts:12-25`). 칸 수 N = 1 + 단계 수. `기안` 칸 일시 = **지금 차수 결재선의 상신 시각**(`domain/print/current-round.ts` — 세 서류 공용 한 출처). 반려 뒤 다시 제출한 문서도 새 차수 시각이 찍힌다 — 지출결의 행의 제출 시각 · 정산 문서 작성 시각은 다시 제출해도 첫 값이라 쓰지 않는다(eng 재검토 R2). 시각을 보일지는 서류의 원래 시각 칸 정보 항목 그대로(못 보던 계급은 일시 없음).
- 열 수 = `clamp(4, N, 5)`로 `repeat(열, minmax(0, 1fr))`, 열 간격 `--s-4`. N ≤ 4이면 정본 목업의 4열 그대로, N = 5(결재선 4단계 설정의 최대)이면 5열. 5를 넘으면(방어) 5열씩 다음 줄로 넘어간다. 칸 폭이 넓은 2~3칸 서류도 4열 트랙을 쓰므로 칸이 늘어지지 않는다(남는 칸은 빈 채로).
- 칸 구성 위에서 아래: 단계 이름(`label`, 12px) → 이름(14px 700) → 상태 글자(11px 600) → 일시(11px 400, 있을 때만). 칸마다 `data-state` 속성을 둬 DOM 감사가 읽는다 — `기안` 칸 `submitted`(상신됨) · `draft`(결재선 없음), 단계 칸 `approved | rejected | pending | skipped | empty | self`. 허용 값은 이 여덟뿐이다.

| `DisplayState` | 이름 칸 | 상태 글자 | 일시 |
|----------------|---------|-----------|------|
| `approved` (본인이 기안자) | `actedByName` | `본인 승인` | `actedAt` |
| `approved` | `actedByName` | `승인` | `actedAt` |
| `rejected` | `actedByName` | `반려` | `actedAt` |
| `current` · `pending` | `—` (400) | `대기` | 없음 |
| `skipped_self` | `—` | `건너뜀` | 없음 |
| `empty` · `blocked` | `—` | `담당 없음` | 없음 |

- 반려 단계에 `reason`이 있으면 결재란 바로 아래에 `반려 사유  {원문}` 한 줄(라벨 12px 600 + 값 12px, `break-inside: avoid`). 그 밖의 끝 줄(`endLines`)은 종이에 싣지 않는다.
- 결재선이 비어 있으면(결재 인스턴스 없음) `기안` 한 칸만 그리고 상태 글자는 `작성 중`, 일시 `—`.
- **결재선을 볼 수 없는 계급**(결재 인스턴스는 있는데 `steps`가 투영으로 빠짐 — `approval.value`가 없는 계급, RESEARCH Open Q8 · 사용자 카드 「기안 칸 하나만」): `기안` 한 칸만, 상태 글자 `상신`, 기안자 이름이 투영으로 빠지면 `—`. 결재자 이름 · 일시 · 반려 사유는 싣지 않고 「결재선 숨김」 같은 안내 문장도 없다. 번호 줄 상태 글자는 단계 이름 없이 `결재 중` · `반려` · `회수`.
- **결재란은 서류 맨 끝(첨부·목록 뒤)**에 두고 `h2 결재`와 칸 묶음 전체를 `break-inside: avoid` + `break-after: avoid`(제목)로 한 덩어리로 묶는다 — 결재란이 두 쪽으로 쪼개지지 않는다. 정본 목업 · SYSTEM §6-6 그림은 결재 → 첨부 순서(:617-621)인데, 결재란을 길이가 바뀌는 목록(첨부 · 정산 목록) 뒤 한 자리로 두면 세 서류가 같은 자리를 쓰고, 기안문의 「붙임 → 결재」 순서와도 같다 — 그래서 결재란을 맨 끝 한 자리로 고정하고 이 차이를 DECISIONS · SYSTEM에 남긴다(디자인 검토 B2 ⑥). 직원 서명 이미지 · 직인 · 도장 칸은 없다(D-7403, SYSTEM §6-6 U2). 처리자 이름 + 처리 일시 글자가 서명 역할이다.

## P2. 연차 신청서 (`app/print/leaves/[id]`)

260907 필드(`LeaveForm.tsx:1046-1068`)에서 입사일만 뺀 일곱 행이다(D-7413 · 사용자 카드 2026-11-04 13:57 「입사일 빼기」 — 사람 관리 권한자만 보는 값이라 종이 · 새 DTO에 없다). 레이아웃은 위 공용 틀(260907의 세로 Timeline 결재 · 여백 14/12/14/16mm는 따르지 않는다, D-7410).

- `PrintFields` 행(순서 고정, **정확히 7행**): `신청인` · `소속` · `갈래` · `기간` · `일수` · `사유` · `잔여`.
  - `소속` = 본부 · 팀 · 계급 이름을 ` · `로. 본부 · 팀은 **지금 차수 결재선의 기안자 소속 스냅숏**(결재선을 짠 그 출처 — 다시 신청 전 팀을 옮겼으면 새 팀), 팀이 없던 기안자면 사람의 본부 칸, 계급은 사람의 계급 칸. 못 보는 정보 항목의 조각은 빠진다.

  - `기간` = `2026-11-10 ~ 2026-11-12`(물결 양쪽 공백, 같은 날이면 하나).
  - `일수` = 연차 상세 화면과 같은 값 그대로(`3일` · `4.5일` — 이미 「일」이 붙은 값, 「일」은 한 번, 소수는 최대 2자리).

  - `잔여` = `부여 15일 · 사용 4.5일 · 잔여 10.5일`(조정이 있으면 부여 뒤 `조정 {일}`, 결재 중이 있으면 사용 뒤 `결재 중 {일}`). 연차 줄과 월차 줄이 둘 다 있으면(입사 다음 해) `연차 부여 … · 잔여 …` / `월차 적립 … · 잔여 …` 두 줄. 월차 소멸일은 싣지 않는다(입사 연도가 드러난다). **(사용자 카드 대기 — E2 · RESEARCH Open Q 11: D-7413 확정 문구 「부여/사용/잔여」대로 적었다. 답이 「남음만」이면 이 줄을 화면 잔고 행 꼴로 바꾼다.)**
  - 라벨 `갈래` · `사유` · `잔여`는 D-7413 확정 문구다 — 화면 상세의 `종류` · `비고` · `잔고`와 같은 낱말로 맞출지는 사용자 결정(디자인 검토 F8, 계획 쪽이 바꾸지 않는다).

### 인쇄 기록 (D-7415)

- 기록 시점: 갈래 M = 1차 `인쇄 · PDF 저장` 클릭, 갈래 A = 자동 인쇄 한 번(페이지 로드마다 1건 — 새로 고침 · 다시 열기는 새 로드). 아래는 갈래 M 기준이고 갈래 A는 클릭 대신 자동 호출이 같은 서버 액션을 부른다(`인쇄 · PDF 저장` 재클릭은 `beforeprint` 5초 중복 규칙에 걸리면 1건).
- 1차 `인쇄 · PDF 저장` 클릭 → 서버 액션 `{ kind: "expense" | "leave" | "settlement", id }`로 행동 로그 1건(누가 · 어떤 서류) 후 응답을 기다리지 않고 `window.print()`. `beforeprint`(Ctrl+P · 메뉴)도 같은 기록(5초 안 중복은 1건). **갈래 M에서는 열기만으로 기록 없음**(갈래 A는 열기 = 자동 인쇄 = 기록 1).
- 기록이 실패해도 인쇄는 그대로 진행하고 **화면에 아무것도 띄우지 않는다**(재량 결정 8). 행동 로그 종류 추가에 마이그레이션이 들면 D-7415대로 이 기록 호출을 통째로 뺀다 — 버튼 동작은 변하지 않는다.

### DOM 합격 단언 (독립 감사, `CI=true`, 스크린샷 육안 판정 금지)

1. **갈래 M**: 열기만 → 인쇄 기록 0, `인쇄 · PDF 저장` 클릭 → 기록 1. **갈래 A**: 열기 → 자동 `window.print()` 1회 + 기록 1(`data-ready` 뒤), 새로 고침 없이 `beforeprint` 재발생 · 버튼 재클릭은 5초 안 중복 1건. 두 갈래 공통: `beforeprint` 두 번 연속 → 기록 1. 어느 갈래가 활성인지는 실행 시점 SYSTEM.md §6-6 문구와 일치해야 한다.
2. 종이 `.sheet` 계산 폭 = 210mm(≈793.7px) 모든 화면 폭에서. 화면 바 계산 폭 = min(793.7px, 창 폭). print 미디어 에뮬레이트에서 화면 바 · 버튼 · `outline` `display:none`/없음, `@page` 크기 A4 세로.
3. print 미디어에서 계산된 색 ⊂ {`--print-ink` 해당 값 `#000`, `#FFFFFF`, `--print-rule` 해당 값, `--print-line` 해당 값}. `--status-danger` 등 상태색 0.
4. 구조 선(제목 괘선 · 표 머리 · 합계 · 결재 칸)이 `border`로 그려지고 `background-image`/`background-color` 의존 0 (배경 그래픽 끔에서도 인쇄).
5. 서류별 라벨 문자열이 위 Copywriting 표와 정확히 일치 — 지출결의서 dt `프로젝트` `지급처` `증빙` `지급 방식` `지급 예정일` `비고` · 합계 행 라벨 `지급 총액`(원천징수 문서면 `실지급액`) · 종이 안 「합계」 글자 0 / 연차 신청서 dt **정확히 7개** `신청인` `소속` `갈래` `기간` `일수` `사유` `잔여`(이 순서, 입사일 dt 0) / 정산서 `프로젝트` `기간` `PM` `견적가 합` `실행가 합` · 구매 요청 머리 `예상 금액`(「금액」 단독 머리 0) / 공통 `결재` `기안`. 세로 테두리(`border-left/right`) 0, 표 격자 0.
6. 승인 완료가 아닌 서류: 번호 줄에 상태 글자 정확히 1개 존재(`{단계} 결재 중` · `결재 중` · `반려` · `회수` · `작성 중` · `종결`). 승인 완료 서류: 상태 글자 0.
7. 결재란: 칸 수 = 1 + 단계 수(결재선을 못 보는 계급은 `기안` 한 칸), 칸마다 `data-state`(값 ⊂ {`submitted`, `draft`, `approved`, `rejected`, `pending`, `skipped`, `empty`, `self`}) · 상태 글자 · (처리된 칸) 일시. 반려 서류에 `반려 사유` 행 1.
8. 금액 못 보는 계급(F-E4): 금액 열 · 합계 행(`지급 총액` · `실지급액`) · 한글 금액 · `계산 불가` 글자 DOM 0. pnl 못 보는 계급(F-S2): `손익` · `수익금` · `수익률` 단어 DOM 0.
9. 회사 정보: 다섯 채움 → A줄 회사명 + B줄 네 항목. 이름만 채움 → B줄 DOM 0. 전부 비움 → A줄에 `출력`만, 빈 요소 높이 0.
