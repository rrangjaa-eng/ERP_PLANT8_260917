## Screens

### S1. `/admin/field-definitions` — 대상 고르기

```
PC
│ 화면 항목                                                 화면 항목 추가 │ ← 1차(기존 자리, 고른 대상에 추가)
│ [프로젝트 ▾]  보관 포함                                                   │ ← filters 슬롯: 대상 select → 3차 토글
╞══════════════════════════════════════════════════════════════════════════╡
│ 이름        타입   필수  정렬  선택지        상태  동작                    │ ← 고른 대상의 칸만
```

- **고르개**: 네이티브 `<select>`(`ui/select` 모양, 폭 `--field-w-select`) 하나, 맨 앞. 값 = `?target=vendor|project|quote_line`, 없거나 모르는 값이면 `vendor`. 바꾸면 즉시 이동(필터 줄 select 관례 — 제출 버튼 없음)하며 `includeArchived`는 지키고 `?new=`·`?editId=`는 버린다(폼 패널 닫힘). 선택지 순서 = `FIELD_DEFINITION_TARGETS` 상수 순서(거래처 · 프로젝트 · 견적 줄), 한 상수가 select·노출표·보관함을 모두 정한다(기준 1).
- **대상이 하나뿐일 때(Z 이전)는 select를 그리지 않는다** — 빈 UI 금지.
- **목록**: 고른 대상의 정의만. 열 · 보관 포함 토글 · 정렬 순서 · 행 「수정」 `aria-label` · `DeleteToArchive` 04.5 그대로. 「대상」 열은 없다(select가 말한다).
- **EMPTY는 대상별**: 고른 대상의 보관 포함 0건이면 머리 1차를 숨기고 `ListEmpty` 「등록된 화면 항목이 없습니다 · 화면 항목 추가」(DR5 A 그대로). 다른 대상에 칸이 있어도 이 대상이 0이면 EMPTY다. select는 EMPTY에서도 보인다. 기본(보관 제외) 0건 + 보관 ≥1건 → 「조건에 맞는 건이 없습니다 · 필터 지우기」(기존).
- **폼**: 대상은 입력 칸이 아니다 — 등록 시 현재 `?target=`을 숨은 값으로 보내고 서버가 enum 검사한다(`.strict()`, 임의 문자열 거부). 수정에서는 바뀌지 않는다. 패널 제목에 대상 이름이 들어가는 것이 유일한 표시다. 정렬 순서 기본값 = 그 대상의 `min(활성 최대 + 1, 999)`. 이름 유일성은 대상 안에서만(`(entity, label)`): 거래처 「비고」와 프로젝트 「비고」는 공존한다.
- 등록 성공 줄의 「정보 노출표 보기」 · 「하나 더 추가」(같은 대상 유지) · 「닫기」 04.5 그대로.
- **폭**: 1280/768 필터 줄 한 줄, 375/320은 select가 `--field-w-select`에서 `--s-4`·`--s-1`을 뺀 상한(§6-1 폰 select 규칙)으로 줄을 이룬다. 폰 표 P1/P2는 04.5 그대로.
- 권한 · 보관 · 버전 잠금 · 노출표 자동 등록은 04.5 계약 그대로(대상만 인자).

### S2. 프로젝트 등록 폼 — 추가 칸 묶음

- **자리**: `PanelForm` 안 마지막 기본 칸(환율 조건부 칸 · 숨은 값) 뒤, 서버 오류 상자 앞. 맨 위에 구분선 `1px --border-row` + 위아래 `--s-6`(거래처 폼 04.5와 같은 구분선, 머리 글자 없음). 묶음 안 순서 = 정렬 순서 → 내부 키.
- **칸**(`CustomFieldInput`, panel 배치 = 라벨 위 · 전폭 · 입력 높이 `--field-h`): 텍스트 `TextField`(한 줄) · 숫자 `TextField type="number"`(거래처 폼 오늘의 꼴, D-7519) · 날짜 `TextField type="date"`(네이티브 달력, 값은 `YYYY-MM-DD`만 보낸다 — 서버도 엄격 ISO, D-7521) · 선택 `Select`(첫 옵션 「—」 = 선택 없음). 라벨 = 칸 이름, `*` 없음.
- **이름**: `cf_<key>`로 FormData에 싣고 `customFields` 객체로 보낸다. 등록은 빈 값을 보내지 않는다.
- **노출**: 이 사람이 입력할 수 있는 칸(활성 ∧ `project.value` 보임 ∧ `cf.project.<key>` 보임)만 렌더. 0개면 구분선 포함 묶음 전체 없음.
- **필수**: 등록 모드라 필수 빈칸은 막힌다 — 서버 오류가 칸 아래 `Form.Error`(`TextField error`/`Select error`)로 오고, 1차 옆 이유 자리(`PanelForm reason`)는 기존 막힘 이유 목록 끝에 `등록 실패 · {칸 이름} {N}칸`으로 센다. 첫 오류 칸 포커스(`[aria-invalid="true"]` 기존 로직).
- **입력 버리기**: `PRISTINE_FIELDS`(처음 연 값)에 추가 칸 이름을 동적으로 포함 — 추가 칸만 고쳐도 패널 닫을 때 「입력 버리기」 확인이 뜨고 부제 칸 수에 센다.
- **복사 등록**(`copyFromProjectId`): 추가 칸 값은 복사하지 않는다 — 빈 칸으로 시작(기본값을 채우는 대상이 아니라 행사마다 달라지는 값). 
- 값 보존: 오류 뒤에도 입력값 유지(UX-04). 폰: 라벨 위 · 전폭 · 입력 40(기존 패널 규칙).

### S3. 프로젝트 상세 정보 면 — 「추가 항목」 섹션 (07.2-17 최종 모양 위에)

- **자리**: `infoSections` 안에서 「기본」 바로 뒤 새 `infoSection`(제목 `infoSectionTitle` 「추가 항목」). 07.2-17 최종 섹션 순서가 다르면 「기본」 바로 뒤라는 **상대 위치**만 지킨다. 1280 3열 · 768 2열 · 375/320 1열은 기존 flex-wrap 규칙이 그대로 정한다.
- **읽기 상태**: `infoItem`(라벨 `--text-muted` + 값) 칸 이름 순서 = 정렬 순서. 값이 없으면 `—`(SYSTEM §2-4, 「있는데 값이 없을 때만 —」). 텍스트는 줄바꿈 허용(`overflow-wrap: anywhere` 상속, 말줄임 없음). 숫자 `Num unit="quantity"`, 날짜 `YYYY-MM-DD`(연도가 달라질 수 있어 월-일 축약 안 함), 선택은 값 글자(보관 선택지면 `{값} (보관됨)`).
- **고치기**: 기본 정보 「고치기」가 열려 있을 때 같은 섹션이 `CustomFieldInput`(S2와 같은 칸 꼴)으로 바뀐다. 별도 3차 버튼 · 별도 저장 없음 — draft는 4칸 정보 draft와 한 묶음이고 저장은 화면 1차 「일괄 저장 Ctrl+S N」 하나(DC-9, `Form.Actions` 없는 칸 규칙 §7-15). 고친 칸은 `--surface-dirty` + 삼각형, `N`에 센다.
- **편집 권리**: 기본 정보를 고칠 수 있는 사람과 같다(D-7516) — 완료 뒤에도 편집(D-7218). 그 밖의 사람은 읽기 값만, 고치기 버튼이 없다.
- **필수**: 수정 모드 — 저장값이 비어 있으면 안 바꿈으로 통과, 값이 있었는데 지우면 칸 아래 「필수 칸이 비어 있습니다 · 값 입력」(04.5 필수 판정 표 그대로). 오류가 있으면 화면 전체 거부(§7-3), 첫 오류 칸 포커스.
- **동시 수정**: 07.2-17 `projects.version` 충돌 문구 그대로(추가 칸 따로 잠그지 않음, D-7520).
- **0칸이면** 섹션 자체가 없다(제목 포함).
- 폰: 정보 면은 접힘 기본(K22) 그대로 — 펼치면 1열. 폰은 읽기만(셀 편집 없음 규칙과 별개로, 기본 정보 고치기가 폰에서 되는 범위는 07.2-17 계약을 따른다).

### S4. 견적 줄 표 — 오른쪽 끝 열

- **열 순서**(논리 순서 = 붙여넣기 순서 = Tab 순서): … · 내부 비고 · 고객 비고 · 중분류 · **추가 칸들(정렬 순서)** · 행동. 행동 열은 격자 로빙 · 붙여넣기에서 빠진다(기존). `columns`와 `pasteColumns`에 같은 위치 · 같은 키(`cf_<key>`)로 넣는다.
- **머리글**: 칸 이름(≤20자, 줄바꿈 허용). 필수 표시 없음. 편집 가능 셀이 있으면 `--surface-selected` 머리글(기존 신호).
- **열 우선순위**: `p3` — 폰(<700)에서 열이 아니라 **행 시트 `KvList`**에 `{칸 이름}: 값`(없으면 `—`)으로 나온다(읽기 전용, 폰 셀 편집 없음). 700~1023은 기존대로 보기 전용(편집 없음), 열은 보인다. `collapseBelow`는 기본 없음 — 1024 · 768에서 `scrollWidth ≤ clientWidth`가 깨지면 DOM 감사가 접는 순서를 `번호 → 내부 비고 → 중분류 → 추가 칸(오른쪽 열부터) → 소분류 → 고객 비고 → 차익`으로 두고 `collapseBelow` 1280/1024를 배정해 DECISIONS에 기록한다(07.2 S4 접는 순서에 한 항목을 끼운 것).
- **열 개수**: 보이는 활성 칸 중 정렬 순서 앞 **3개**까지 열이 된다(표 폭 보호). 4번째부터는 표에 없고 값은 서버에 그대로 남는다.
- **셀(타입별, 기존 부품만)**: 텍스트 = `textEditCell`(폭 `--field-w-select`, 줄바꿈 허용 `keep-all` + `overflow-wrap: anywhere`) · 숫자 = `NumericEditCell` quantity 꼴(우측, 쉼표, 소수 2자리, 폭 `12ch`) · 날짜 = 텍스트 편집 셀 + 엄격 `YYYY-MM-DD` 검사(폭 `12ch`, 날짜 편집 부품은 새로 만들지 않는다 — 붙여넣기 열 종류도 text 취급) · 선택 = `selectEditCell`(폭 `--field-w-select`, 선택지 = 활성 선택지, 첫 옵션 「—」 = 비움).
- **편집 규칙 = 내부 비고(`note`)와 같다**(D-7517): 같은 잠금 · 읽기 전용 · 권한 밖 줄 판정, 같은 `editability` 함수를 쓴다. 연결 문서가 있는 줄 · 고객 승인된 차수에서도 비고처럼 편집되고, 완료 프로젝트 · 권한 밖 줄에서는 잠김 모양(`aria-readonly="true"`, 표 위 한 줄 기존 문구 — 새 문구 없음).
- **붙여넣기 · 복사**: 숫자 = 쉼표 · 공백 정리 후 숫자(아니면 오류 셀 「숫자 아님 · 1.5처럼」). 날짜 = 앞뒤 공백 제거 후 `YYYY-MM-DD`만 인정, 2026-02-31 · `11/4/2026` 같은 값은 오류 셀 「날짜 아님 · 2026-11-04처럼」. 선택 = 옵션 라벨 글자로 찾기, 없으면 오류 셀 「목록에 없는 값 · {글자}」 + 합계 행 요약 `{칸 이름} 칸 n개 모르는 값`(SYSTEM §7-3 select 셀). 빈 문자열은 비움. `Ctrl+C`는 숨은 열 포함 논리 열 순서의 TSV로 추가 칸을 싣는다. 앱 형식 클립보드(`application/x-plant8-quote-lines+json`)는 추가 칸 값을 싣지 않는다 — TSV 위치 규칙만.
- **필수 칸**: 새 줄(Ctrl+Enter · 복제 · 가져온 줄)은 비어 있으면 저장 때 오류 셀 + 「필수 칸이 비어 있습니다 · 값 입력」, 합계 행 `오류 N칸 · 전부 거부`(기존 흐름). 기존 줄의 빈 필수 칸은 건드리지 않는다(D-7507). 값이 있던 필수 칸을 지우면 오류 셀. 복제(`Ctrl+D`) 줄은 원본 값을 함께 복사한다(D-7518).
- **보관된 선택지가 저장값**: 셀 글자 `{값} (보관됨)`, 건드리지 않으면 그대로 저장, 새로 고르면 목록에 없음(보관 선택지는 옵션에 없다).
- **dirty · 충돌 · 미저장 복원**: 기존 표 계약 그대로 — 고친 추가 칸 셀 왼쪽 위 삼각형 · 오류 셀 고정 · 미저장 편집 보관(`추가 칸 값도 보관본에 포함`). 추가 칸만 바뀐 동시 수정은 기존 줄 버전 충돌 폴백을 쓴다(셀 단위 baseline에 추가 칸을 넣지 않는다 — 최소안).
- **차수 복사 · 줄 복사**: 추가 칸 값이 함께 따라간다(D-7518, 서버 복사가 열째 복사). 화면에 별도 표시 없음.
- **고객 견적서 인쇄 · 견적 엑셀 가져오기**: 추가 칸 없음(D-7513) — 화면 변경 0.
- 힌트 줄(§7-9) 변경 없음.

### S7. 정보 노출표 · 보관함 이름

- 노출표는 항목이 **행**, 계급이 **열**이다(SYSTEM §7-13 — 04.5 문서의 「열 이어 붙이기」는 옛 방향). 새 칸은 `INFO_ITEMS` 뒤에 이어 붙는다: 거래처 칸 → 프로젝트 칸 → 견적 줄 칸 순(대상 상수 순서), 각 대상 안은 정렬 순서.

- 행 이름이 항목 열 240보다 길면 줄바꿈(기존). 체크박스 `aria-label` · 폰 「계급 고르기 → 항목 목록」 `KvList` 라벨은 같은 이름을 쓴다. 컴포넌트 · CSS 변경 0.
- 새 칸은 생성 tx에서 전 계급 보임으로 등록(D-7508) — 관리자가 계급별로 끈다. 꺼진 칸은 화면 · 액션 응답 · CSV 어디에도 없다.
- **보관함(`/admin/archive`)** 필드 정의 행 이름도 `{대상} · {칸 이름}`(대상 접두) — 대상이 달라도 같은 이름의 정의가 둘 이상일 수 있다.

## 검증 계약 (독립 DOM 감사 · E2E 입력)

- S1: 대상 select 변경 → 목록이 그 대상 칸만, `?new=`/`?editId=` 제거, 대상 1개뿐이면 select DOM 0. 대상별 EMPTY 문구.
- S2: 활성 칸 0 → 구분선 DOM 0. 필수 칸 빈 등록 → 칸 오류 + 이유 `등록 실패 · … 1칸`. 날짜 `type="date"`.
- S3: `고치기` → 추가 칸 입력, 저장은 「일괄 저장 N」 하나(1차 버튼 수 불변). 편집 권리 없는 사람은 입력 DOM 0.
- S4: 머리글 순서 = 논리 순서(추가 칸은 중분류 뒤 · 행동 앞). 날짜 붙여넣기 `2026-02-31` → 오류 셀. 폰 375 · 320: 추가 칸 열 DOM 0, 행 시트에 값. 기존 줄 빈 필수 칸 → 다른 칸 수정 저장 통과.
- S5: 칸 숨김 계급은 열 · 필터 · 검색 결과 어디에도 없음. `cf_<key>` 필터 → 행 수와 합계 줄이 같은 집합.
- S6: CSV 머리글 = 9칸 + 보이는 칸, 칸 0개면 9칸. 수식 시작 글자(`=`)는 이스케이프.
- S7: 노출표 행 이름 `프로젝트 · 비고` 형식, 거래처 칸도 접두.
- 폭: 1280 · 768 · 375 · 320 모두 가로 넘침 0(375와 320은 `scrollWidth ≤ clientWidth`만).
- 새 색 · 서체 · radius · 토큰 0(린트).
