- **대상 링크 줄**: 필터 줄 맨 앞 `<nav aria-label="대상">` 안에 링크 셋(글자 = `TARGET_LABELS`). 모양은 옆 관리 화면의 선택 링크 줄과 같다 — 화면 3차 링크 `.toggle` + 현재 대상 `aria-current="page"`(강한 글자 700 · 밑줄 없음 — 거래처 「갈래」 vendors/page.tsx:131-143 · 코드표 code-tables/page.tsx:92-99 선례, SYSTEM §7-16). 링크 href = `?target=vendor|project|quote_line` + `includeArchived` 유지 · `?new=`·`?editId=` 없음(폼 패널 닫힘), 없거나 모르는 값이면 `vendor`. 링크 순서 = `FIELD_DEFINITION_TARGETS` 상수 순서(거래처 · 프로젝트 · 견적 줄), 한 상수가 링크 줄·노출표·보관함을 모두 정한다(기준 1). 링크라 보이는 라벨 · select 폭 상한 문제가 없다(이전 안의 라벨 없는 select는 `ui/select` `width: 100%`로 필터 줄을 채운다 — 디자인 1회차 B4).
- **대상이 하나뿐일 때(Z 이전)는 링크 줄을 그리지 않는다** — 빈 UI 금지.
- **목록**: 고른 대상의 정의만. 열 · 보관 포함 토글 · 정렬 순서 · 행 「수정」 `aria-label` · `DeleteToArchive` 04.5 그대로. 「대상」 열은 없다(현재 링크가 말한다).
- **EMPTY는 대상별**: 고른 대상의 보관 포함 0건이면 머리 1차를 숨기고 `ListEmpty` 「등록된 화면 항목이 없습니다 · 화면 항목 추가」(DR5 A 그대로). 다른 대상에 칸이 있어도 이 대상이 0이면 EMPTY다. 대상 링크 줄은 EMPTY에서도 보인다(0건 가드는 「보관 포함」 토글에만). 기본(보관 제외) 0건 + 보관 ≥1건 → 「조건에 맞는 건이 없습니다 · 필터 지우기」(기존).
- **폼**: 대상은 입력 칸이 아니다 — 등록 제출 객체(`createState.execute({ …, target })` — 이 폼은 FormData를 쓰지 않아 숨은 input은 서버로 가지 않는다)에 현재 대상을 싣고, 서버 액션 스키마가 target 필수 · enum 검사를 한다(`.strict()`, 누락 · 임의 문자열 거부). 수정에서는 바뀌지 않는다. 패널 제목에 대상 이름이 들어가는 것이 유일한 표시다. 정렬 순서 기본값 = 그 대상의 `min(활성 최대 + 1, 999)`. 이름 유일성은 대상 안에서만(`(entity, label)`): 거래처 「비고」와 프로젝트 「비고」는 공존한다.
- 등록 성공 뒤 흐름 · 「정보 노출표 보기」는 04.5 그대로(「하나 더 추가」 링크는 지금 화면에 없다). 대상을 잃는 링크는 수정 패널 「새 화면 항목 추가」(`NEW_HREF` — field-definition-form.tsx:58 · :305) 하나 — 현재 대상을 싣는 `newHref(target)`으로 바꾼다.
- **폭**: 모든 폭에서 링크 셋 + 「보관 포함」이 한 줄 흐름(셋 이하 — SYSTEM.md:229의 폰 2열 격자는 넷 이상만). 폰 링크 터치 목표는 기존 `.toggle` 폰 규칙(`--touch-min`). 폰 표 P1/P2는 04.5 그대로.
- 권한 · 보관 · 버전 잠금 · 노출표 자동 등록은 04.5 계약 그대로(대상만 인자).

### S2. 프로젝트 등록 폼 — 추가 칸 묶음

- **자리**: `PanelForm` 안 마지막 기본 칸(환율 조건부 칸 · 숨은 값) 뒤, 서버 오류 상자 앞. 맨 위에 구분선 `1px --border-row` + 위아래 `--s-6`(거래처 폼 04.5와 같은 구분선, 머리 글자 없음). 묶음 안 순서 = 정렬 순서 → 내부 키.
- **칸**(`CustomFieldInput`, panel 배치 = 라벨 위 · 전폭 · 입력 높이 `--field-h`): 텍스트 `TextField`(한 줄) · 숫자 `TextField type="number"`(거래처 폼 오늘의 꼴, D-7519) · 날짜 `TextField type="date"`(네이티브 달력, 값은 `YYYY-MM-DD`만 보낸다 — 서버도 엄격 ISO, D-7521) · 선택 `Select`(첫 옵션 「—」 = 선택 없음). 라벨 = 칸 이름, `*` 없음.
- **이름**: `cf_<key>`로 FormData에 싣고 `customFields` 객체로 보낸다. 등록은 빈 값을 보내지 않는다.
- **노출**: 이 사람이 입력할 수 있는 칸(활성 ∧ `project.value` 보임 ∧ `cf.project.<key>` 보임)만 렌더. 0개면 구분선 포함 묶음 전체 없음.
- **필수**: 등록 모드라 필수 빈칸은 막힌다 — 서버 오류가 칸 아래 `Form.Error`(`TextField error`/`Select error`)로 오고, 1차 옆 이유 자리(`PanelForm reason`)는 기존 막힘 이유 목록 끝에 `등록 실패 · {칸 이름} {N}칸`으로 센다. 첫 오류 칸 포커스(`[aria-invalid="true"]` 기존 로직). 기본 필수 칸(클라이언트 · 이름 · PM · 팀)과 같은 길이다 — 이 폼은 네이티브 `required`를 쓰지 않고(project-form.tsx:55-58) 이유 자리 원소가 모두 서버 응답에서 온다(:158-189). 추가 칸만 제출 전에 막으면 한 폼에 두 규칙이 된다.
- **칸 사이 간격**: 추가 칸 사이 `--s-4`(TextField 줄 · 선택 칸 감싸개 — 옆 패널 규칙 SYSTEM.md:510). 감사가 기본 칸 사이 · 추가 칸 사이 · 구분선 위아래를 함께 잰다.
- **입력 버리기**: `PRISTINE_FIELDS`(처음 연 값)에 추가 칸 이름을 동적으로 포함 — 추가 칸만 고쳐도 패널 닫을 때 「입력 버리기」 확인이 뜨고 부제 칸 수에 센다.
- **복사 등록**(`copyFromProjectId`): 추가 칸 값은 복사하지 않는다 — 빈 칸으로 시작(D-7523 사용자 확정 — 복사하는 사람에게 안 보이는 칸 값을 옮기는 길이 없고, 행사마다 다른 값이 기본값으로 남지 않는다). 견적 줄 값은 D-7518대로 복사된다.
- 값 보존: 오류 뒤에도 입력값 유지(UX-04). 폰: 라벨 위 · 전폭 · 입력 40(기존 패널 규칙).

### S4. 견적 줄 표 — 오른쪽 끝 열(행동 열 바로 앞)

- **열 순서**(논리 순서 = 붙여넣기 순서 = Tab 순서): … · 내부 비고 · 고객 비고 · 중분류 · **추가 칸들(정렬 순서)** · 행동. 행동 열은 격자 로빙 · 붙여넣기에서 빠진다(기존). `columns`와 `pasteColumns`에 같은 위치 · 같은 키(`cf_<key>`)로 넣는다.
- **머리글**: 칸 이름(≤20자, 줄바꿈 허용). 필수 표시 없음. 편집 가능 셀이 있으면 `--surface-selected` 머리글(기존 신호).
- **열 우선순위**: `p3` — 폰(<700)에서 열이 아니라 **행 시트 `KvList`**에 `{칸 이름}: 값`(없으면 `—`)으로 나온다(읽기 전용, 폰 셀 편집 없음). 700~1023은 기존대로 보기 전용(편집 없음), 열은 보인다. `collapseBelow`는 기본 없음. 처방은 이 문서가 정하고 감사는 재기만 한다: 1024 · 768에서 표 `scrollWidth > clientWidth`면 **추가 칸 열만 오른쪽부터 하나씩** 접는다 — 1024~1279에서 넘치면 그 열에 `collapseBelow: 1280`, 700~1023에서만 넘치면 `collapseBelow: 1024`, 한 열 접을 때마다 다시 재서 넘침이 사라지면 멈춘다(P3 열만 숨긴다는 SYSTEM.md:430 ⑶ 안 · 기존 열 접힘은 main 그대로 — 접힌 추가 칸 값은 그 열이 보이는 폭 · 폰 행 시트에서 본다). 접었으면 DECISIONS에 한 줄(측정값 · 접은 열). 1280에서 넘치면 `ui/table` 접힘 단계(`collapseBelow` 1280 · 1024 둘뿐 — ui/table/types.ts:50)로 구제할 수 없으므로 실행자는 멈추고 보고한다(텍스트 · 선택 열은 `overflow-wrap: anywhere`라 최소 폭이 거의 0이고, 넘침이 나면 원인은 `12ch` 숫자 · 날짜 열이다).
- **열 개수**: 보이는 활성 칸 중 정렬 순서 앞 **3개**까지 열이 된다(표 폭 보호). 4번째부터는 견적 줄의 입력 밖이다(D-7525) — 표 · 폰 행 시트 · 붙여넣기 어디에도 없고, 기존 줄 저장값은 그대로 남는다. 견적 줄에는 폼 · 상세가 없어 4번째 이후 칸을 볼 · 채울 곳이 없다(「표 밖 칸 있음」 신호는 백로그 후보 — 이 페이즈 범위 밖).
- **셀(타입별, 기존 부품만)**: 텍스트 = `textEditCell`(열 옵션 `cellWidth: "field"` — 칸 안 감싸개 폭 상한 `--field-w-select`, 줄바꿈 허용 `keep-all` + `overflow-wrap: anywhere`) · 숫자 = `NumericEditCell` quantity 꼴(우측, 쉼표, 소수 2자리, 폭 `12ch`) · 날짜 = 텍스트 편집 셀 + 엄격 `YYYY-MM-DD` 검사(폭 `12ch`, 날짜 편집 부품은 새로 만들지 않는다 — 붙여넣기 열 종류도 text 취급) · 선택 = `selectEditCell`(폭 `--field-w-select`, 선택지 = 활성 선택지, 첫 옵션 「—」 = 비움).
- **편집 규칙 = 내부 비고(`note`)와 같다**(D-7517): 같은 잠금 · 읽기 전용 · 권한 밖 줄 판정, 같은 `editability` 함수를 쓴다. 연결 문서가 있는 줄 · 고객 승인된 차수에서도 비고처럼 편집되고, 완료 프로젝트 · 권한 밖 줄에서는 잠김 모양(`aria-readonly="true"`, 표 위 한 줄 기존 문구 — 새 문구 없음).
- **붙여넣기 · 복사**: 숫자 = 쉼표 · 공백 정리 후 숫자(아니면 오류 셀 「숫자 형식 오류 · 12,400,000처럼」 — 공용 붙여넣기 글자 그대로). 날짜 = 앞뒤 공백 제거 후 `YYYY-MM-DD`만 인정, 2026-02-31 · `11/4/2026` 같은 값은 오류 셀 「날짜 아님 · 2026-11-04처럼」. 선택 = 옵션 라벨 글자로 찾기, 없으면 오류 셀 「목록에 없는 값 · {글자}」 + 합계 행 요약 `{칸 이름} 칸 n개 모르는 값`(SYSTEM §7-3 select 셀). 빈 문자열은 비움. `Ctrl+C`는 숨은 열 포함 논리 열 순서의 TSV로 추가 칸을 싣는다. 앱 형식 클립보드(`application/x-plant8-quote-lines+json`)는 추가 칸 값을 싣지 않는다 — TSV 위치 규칙만.
- **필수 칸**(판정 집합 = 화면 열 앞 3개 — D-7525): 새 줄(Ctrl+Enter · 복제 · 가져온 줄 · 붙여넣기 새 줄)은 열로 보이는 필수 칸이 비어 있으면 저장 때 오류 셀 + 「필수 칸 비어 있음 · 값 입력」, 합계 행 `오류 N칸 · 전부 거부`(기존 흐름). 4번째 이후 필수 칸은 새 줄을 막지 않는다(그 키는 버린다). 기존 줄의 빈 필수 칸은 건드리지 않는다(D-7507). 값이 있던 필수 칸을 지우면 오류 셀.
- **복제 · 복사**: 복제(`Ctrl+D`) 줄은 원본의 **보이는** 추가 칸 값을 편집 원문(날짜 앞 10자 · 숫자 쉼표 없는 글자)으로 복사하고 보관 선택지 값은 뺀다(새 줄 = 등록 판정이라 보관 선택지는 거부된다 — D-7518). 차수 복사 · 프로젝트 복사 등록의 줄 복사는 숨은 · 보관 칸 값까지 그대로 옮긴다(D-7518 · D-7523).
