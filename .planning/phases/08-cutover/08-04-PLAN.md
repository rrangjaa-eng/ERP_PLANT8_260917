## 결정 변경 기록 (decision delta)

- **concurrency 그룹 `deploy` 공유(Discretion):** restore-rehearsal.yml은 별도 그룹이지만 전환은 마이그레이션 · 배포와 겹치면 안 된다(삭제 중 스키마 변경) — deploy.yml 그룹을 같이 쓴다. GitHub는 그룹마다 대기 실행을 하나만 두고 새 대기가 옛 대기를 취소하므로, 전환일 머지 동결(CUTOVER §3)이 전제다.
- **로그 읽기:** 08-02 CLI는 `lib/log`의 한 줄 JSON을 쓴다 — Cloud Logging은 그 줄을 `jsonPayload`로 파싱하므로 account.yml · restore-rehearsal.sh의 `value(textPayload)` 꼴로는 빈 값이다(lib/log.ts:1). 이 워크플로는 `jsonPayload.event`로 거르고 `--format`으로 칸을 뽑는다(jq 없이 gcloud 형식만 — 새 도구 없음).
- **「정리 결과 로그 늦음」 = 경고(디자인 검토 1회차 2026-11-04 (F10)):** eng 검토 2회차는 이 갈래를 exit 1(고아 목록 없이 초록으로 끝내지 않기)로 정했지만, 이 갈래는 전환이 커밋되고 정리도 끝난 성공 실행이다 — 빨간 실패로 끝나면 사람이 apply를 다시 돌리려 하고, 08-07 Task 3 · 08-08 Task 1 verify(성공 실행만 고른다)가 이 실행을 놓친다. 그래서 `::warning::` + exit 0으로 끝내고, 고아 목록 확인은 요약 문장 + 08-07 §3 7번 장부 줄(Logging의 `cutover.objects` orphanKeys)이 맡는다. 거부 갈래(종료 1)는 그대로.
