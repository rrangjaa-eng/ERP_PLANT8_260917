<objective>
프로젝트 목록(/projects)에서 수익률이 관리자 설정 「수익률 기준선(%)」(기본 15) 미만인 행의 수익률 글자만 `--status-danger` 색으로 보인다. 수익률이 없는 행(—)은 그대로다.

사용자 결정(2026-10-04 카드): 기준선은 설정 화면 값, 기본 15%. 이 결정은 바꾸지 않는다.

Purpose: 경영관리·대표가 목록을 훑을 때 기준 아래 프로젝트를 글자를 읽고 계산하지 않아도 색으로 알아본다(화면 사용성 원칙: 상태는 색·배지로).
Output: 설정 키 1개(마이그레이션 없음), 순수 판정 함수 1개, 목록 칸 색 배선, 단위·E2E 테스트, design-gate 점검표, DECISIONS·SYSTEM §6-1 기록.

Claude 재량으로 정한 것(실행자는 그대로 따른다):
- 키 이름 `project.profit_rate.threshold`, 상수 `PROJECT_PROFIT_RATE_THRESHOLD`, namespace 「프로젝트」(기존 `project.customer_approval_gate`와 같은 섹션), 값은 퍼센트 정수(15 = 15%) — 라벨이 「(%)」이고 설정 화면 숫자 칸이 `type="number"`(step 1)라 정수 0~100으로 둔다.
- 판정은 화면에 보이는 값으로 한다: 칸은 `profitRate * 100`을 `formatPercent`(소수 1자리 반올림)로 그리므로, 같은 산술(`Math.round(profitRate * 100 * 10) / 10`)로 반올림한 값이 기준선보다 작을 때만 위험 색. 이유: 화면에 「15.0%」가 빨갛게 보이는 모순(실제 14.96%)을 막고, `0.29 * 100 = 28.999…` 같은 부동소수 오차로 「같음」이 「미만」이 되는 것도 막는다.
- 합계 줄(list-totals.tsx)의 수익률은 칠하지 않는다 — 결정 문장이 행 단위(「계산 불가 행은 그대로」)다. 오케스트레이터에 열린 해석으로 보고한다.
- 화면 읽기 사용자용 숨김 글자는 더하지 않는다 — 수익률 숫자 자체가 정보이고 색은 강조다(SYSTEM §10 「상태는 글자」는 숫자 글자로 이미 충족). DECISIONS 항목에 이 판단을 한 줄로 남긴다.
