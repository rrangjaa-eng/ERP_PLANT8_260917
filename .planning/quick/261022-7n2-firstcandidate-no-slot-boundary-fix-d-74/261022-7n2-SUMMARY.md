# Quick 261022-7n2: firstCandidate no-slot 경계 수정 (D-741 · D-749) 요약

지급 요일 anchor가 창 안인데 영업일로 맞춘 날이 기준일 이하로 떨어지면, 창 밖 날짜를 `pushReason: null`(「마지막 금요일」)로 돌려주던 결함을 no-slot 절(기한 이하 마지막 영업일)로 고쳤다.

## 커밋

- `daa8e7d` fix: firstCandidate no-slot when pay weekday falls on or before base date (D-749) — 두 파일만(`domain/payments/pay-schedule.ts` +7/-4, `test/unit/payments/pay-schedule.test.ts` +13/-1)

## RED 증거 (고치기 전 코드)

`pnpm vitest run test/unit/payments/pay-schedule.test.ts` → `Tests 2 failed | 15 passed (17)`

- (a) D-749 · 기준 07-01 · 기한 2 · 07-02·07-03 공휴일:
  ```
  AssertionError: expected { payDate: '2026-07-01', …(6) } to match object { payDate: '2026-07-01', …(2) }

  ```
- (b) D-741 · 기준 07-01 · 기한 5 · 같은 공휴일:
  ```
  AssertionError: expected { payDate: '2026-07-01', …(6) } to match object { payDate: '2026-07-06', …(2) }
  -   "autoPayDate": "2026-07-06",

  -   "pushReason": "no-slot",
  +   "autoPayDate": "2026-07-01",
  +   "payDate": "2026-07-01",
  +   "pushReason": null,
  ```

예상한 이유(pushReason null · payDate 07-01)로만 실패했다.

## 수정

`firstCandidate`: `anchor > baseDate`일 때만 `prevBusinessOnOrBefore(anchor)`를 셈하고(no-slot 경로에서는 걷지 않음), 그 값이 `> baseDate`이면 `{ payDate, pushReason: null }`, 아니면 기존 no-slot 반환 줄로 간다. 주석은 firstCandidate 위 두 줄과 PayPushReason 주석의 「기한 창에 영업일로 맞춘 지급 요일이 없어」 구절만 바꿨다. 시그니처 · autoSchedule · resolvePaySchedule · payRuleLine은 그대로다.
