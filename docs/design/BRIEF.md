## 제품이 하는 일 (한 문장)

BTL 광고대행사 PLANT8의 전 직원이 프로젝트·견적 줄·지출결의·법인카드를 한 곳에 입력해, 기획본부와 경영관리본부가 프로젝트마다 **같은 숫자**를 보는 사내 업무 시스템.

## 주 사용자 / 사용 상황

역할마다 다르다. 하나의 사용 패턴으로 수렴시키지 않는다.

| 역할 | 기기 | 빈도 | 성격 | 화면에서 하는 일 |
|---|---|---|---|---|
| 기획 PM (최다수) | PC 상주 | 하루 여러 번 | 입력이 곧 업무 | 견적 줄, 지출결의, 카드 사용 등록 |
| 경영관리 담당 | PC | 하루 여러 번 | 마감 전후로 급함 | 결재, 지급 처리, 증빙 확인, 대리 등록 |
| 팀장 · 본부 책임자 | 폰 우선 / PC 병행 | 하루 1~2회 | 짧고 잦음 | 폰으로 승인·반려, PC로 팀 손익·목표 |
| 대표 | 폰 우선 / PC 병행 | 하루 1~2회 | 짧고 잦음 | 폰으로 승인, PC로 전사 손익·인센티브 |
| 시스템 관리자 (= 사용자 본인) | PC | 주 단위 | 느긋함 | 설정·권한·정보 노출표 |
| 외부 인력 (수령자) | 폰 전용 | 평생 1회 | 낯섦, 로그인 없음 | QR로 들어와 본인 정보 입력 + 터치 서명 |

**급함의 실체**: 결재 마감은 지급일 전 영업일 14시(EXP-12). 그 직전이 이 시스템에서 가장 급한 시간이고, 그때 막히면 돈이 한 주 밀린다.

## 가장 잦은 작업 3개

1. **견적 줄 입력·수정** — 프로젝트 원장에 견적가·실행가를 여러 줄 한꺼번에. 엑셀식 표 입력의 핵심
2. **지출결의 작성·제출** — 견적 줄에서 올려 증빙 첨부까지 화면 하나에서 끝
3. **법인카드 사용 등록** — 견적 줄 / 견적 외 비용 / 팀 비용 중 하나에 연결. 폰에서도 발생

빈도 근거(인트라넷 2026-01~09 실적): 견적 줄 1,379행 · 지출결의 464건 · 카드 433건 · 프로젝트 125건.
→ **첫 화면의 히어로는 이 셋 중 역할에 맞는 하나.** 프로젝트 등록은 히어로가 아니다.

## 성공 기준

**빠름**과 **규율**이 공동 1순위다. 신뢰감·즐거움은 따라오는 것이지 목표가 아니다.

- **빠름** = 클릭 수와 화면 이동이 인트라넷보다 적다. 키보드만으로 끝난다. 표는 엑셀과 같은 키 구성. 같은 값을 두 번 적지 않는다
- **규율** = 막을 것은 확실히 막고 다음 행동을 강하게 유도한다. 안내 문구로 가르치지 않고 화면의 상태로 가르친다

**둘이 충돌하는 지점이 이 프로젝트의 진짜 디자인 문제다.** 규율(증빙 첨부·결재·필수 항목)은 기획본부의 업무를 인트라넷보다 **늘린다**. 그래서 규율은 빠름을 깎는 방식으로 구현하면 안 된다:
- 막을 때는 **이유 + 다음 한 수**를 같은 자리에 같이 준다. 막기만 하는 화면은 실패
- 규칙 때문에 늘어난 단계는 자동 채움·연결·연속 처리로 상쇄한다

## 제약

**기술**
- Next.js 16 App Router(RSC + Server Actions). 서버 렌더가 기본, 클라이언트 상호작용은 표 입력 등 필요한 곳만
- 새 의존성은 이유 + 승인. 무거운 UI 프레임워크·컴포넌트 라이브러리를 전제로 설계하지 않는다
- 유지 인력은 비개발자 1인 + Claude Code. **컴포넌트 수는 적게, 규칙은 한 줄로 말할 수 있게**

**화면**
- 반응형 360–1440px. 폰에서 **결재·조회·지출결의 작성**이 된다(UX-03)
- **인쇄 출력 필수**: 지출결의서, 기타소득 확인증. 인쇄 레이아웃을 SYSTEM.md에 정식 템플릿으로 포함한다
- 다크모드 **불필요**. 다국어 **불필요**(한글 전용)
- 접근성: 텍스트 대비 4.5:1 / UI 3:1, 모든 행동 키보드 도달, `:focus-visible`, `prefers-reduced-motion`
- 한글: `word-break: keep-all`, 행간 1.6+, 자간 -0.01~-0.02em

**정보 구조상의 제약 (이 프로젝트 고유)**
- 같은 화면이 계급마다 **다른 칸 수**를 보인다(정보 노출표). 기획본부에는 손익·계산식·근거 줄이 아예 안 보인다
- 따라서 레이아웃은 칸이 빠져도 무너지지 않아야 하고, **숨겨진 자리가 빈 구멍으로 티나면 안 된다**. 고정 그리드에 큰 숫자를 박아 두는 구성은 위험
- 금액은 전부 공급가액 기준, 원화 정수. 외화는 통화·환율·원화 환산 병기 → **금액 한 칸이 두 줄이 될 수 있다**
- 표 입력은 일괄 저장(전부 저장 또는 전부 거부)이고 충돌·오류 칸을 표시해야 한다

**참고 금지**
- 260907(이전 시도)의 화면·정보구조·UI 흐름·틀·토큰. 업무 규칙·용어만 참고 가능

## 피해야 할 것

사용자가 네 가지를 모두 지목했다. §2에서 이 인상으로 가는 안은 후보에서 제외한다.

1. **관공서·구형 사내망** — 회색 테두리 촘촘한 표, 파란 밑줄 링크, 작은 글씨, 버튼이 어디 있는지 모를 화면. *지금 인트라넷의 인상*
2. **흔한 AI 대시보드** — 똑같은 둥근 카드 타일, 큰 숫자 4개 히어로, 그라디언트, 보라 포인트. 어떤 제품이든 똑같아 보이는 화면
3. **회계 소프트웨어** — 수십 개 메뉴, 전문 용어, 교육받아야 쓰는 화면
4. **장난감 같은 툴** — 둥글둥글·파스텔·과한 여백으로 돈을 다루는 시스템의 무게가 안 느껴지는 화면

추가로 `docs/DESIGN.md` §5 안티슬롭 목록 전부를 §2 발산 단계에서 제외한다.

## 디자인의 핵심 질문

> **"지금 이 화면에서 내 손이 멈추지 않고, 30초만 들러도 뭔가 하나 끝내고 나갈 수 있다."**

사용자가 고른 두 답(「손이 멈추지 않는다」 + 「수시로 들러도 되겠다」)을 한 문장으로 합친 것이다.
앞의 절은 **빠름**, 뒤의 절은 **규율**에 대응한다. 몰아서 입력하는 지금 습관을 깨는 것이 뒤 절의 목적이다.

**모든 화면이 통과해야 하는 검증 질문 3개**
1. 다음 한 수가 보이는가? 막혀 있다면 **막힌 이유와 그 다음 한 수**가 같은 자리에 있는가?
2. 마우스를 한 번도 잡지 않고 끝낼 수 있는가?
3. 30초 안에 끝낼 수 있는 일이 이 화면에 하나라도 있는가?
