서체 Pretendard 단일. 레이아웃: 딥그린 상단 바 유지, 표를 흰 종이 한 장(1px `#E1E3DE` · radius 6 · `0 1px 2px` 그림자)에 올린다.
```
▓PLANT8 프로젝트 …▓
 2026 현대자동차 아이오닉9 …   [복사][상태][일괄 저장 3]
 견적 48,000,000  예상 비용 …
╭──────────────────────────────╮  ← 흰 종이, 1px 선, 옅은 그림자
│ 번호 항목 거래처 … (옅은 머리글) │
```

- 핵심 질문(신뢰·빠름)에 답하는 방식: 원장의 정렬·숫자 위계는 그대로 두고 「조립된 화면」의 딱딱함만 뺀다.

- 위험·비용: 가장 싸다(토큰 + 표 래퍼 하나). 변화가 작아 "여전히 옛 화면"으로 읽힐 수 있다.

## §5 실물 보드 (2026-09-27 사용자: 「아티팩트로만 보면 예쁘다, 실제 페이지가 되면 안 예쁘다」)
- 목업은 실제 CSS 모듈(38개 · 4,177줄)이 아니라 새로 짠 CSS였다. 실제 모듈은 `var(--radius)`를 12곳만 쓰고 토큰 없는 값이 117줄이라, **tokens.css만 바꾸면 목업처럼 되지 않는다**.
- 그래서 실제 앱을 로컬에서 띄우고(실제 데이터: 아이오닉9 등 8개 프로젝트 · 거래처 12곳) 세 화면에 오버레이 CSS를 얹어 찍었다: `docs/design/explore-skin/real/` — `index.html` 보드 · `shots/` 30장(5안 × 3화면 × PC 1280 · 폰 390, 가로 넘침 0) · `overlay-*.css` · `_common.css` · 촬영 스크립트 `shoot.spec.ts.txt`(test/e2e에 복사해 `SHOT_OUT=… SKINS=now,a,b,c,d pnpm exec playwright test …`).
- 안: **A 정돈**(안전, 이전 A의 웜톤을 차가운 회색 `#F2F5F4`로) · **B 스튜디오**(과감) · **C 스테이지**(브랜드 띠) · **D 사이드바**(A 피부 + 왼쪽 딥그린 사이드바 232px, 폰은 A와 같음 — 사용자 요청).
- **등록 모달**(사용자 요청 「기본 페이지 목록이 계속 밀린다」): A~D 모두 거래처 등록 폼을 목록 위 모달로 띄운 모습. D-39(검색 파라미터 토글로 목록 위에 여는 폼)를 뒤집는 **구조 결정**이라 선택 뒤 DECISIONS.md에 기록한다.
- **모달은 한 건 등록 폼에만**(사용자 2026-09-27): 거래처·사람·법인카드·코드표처럼 목록 위에 열리던 등록·수정 폼만 모달(PC 가운데 창 · 폰 아래 시트) 또는 옆 패널 후보로 둔다. **견적 줄 입력은 절대 모달로 옮기지 않는다** — 표 안에서 엑셀처럼(칸 바로 입력 · Tab·방향키 이동 · Ctrl+V 여러 줄 붙여넣기 · Ctrl+Enter 새 줄 · Ctrl+S 저장). 스킨은 이 표의 겉모양만 바꾼다.
- **웜톤 바탕 금지**(사용자 2026-09-27): 모든 안에서 뺐다. 확정 때 DECISIONS.md에 올린다.
- 촬영 중 발견(스킨과 무관, 별도 확인 필요): 거래처 동작 열 「수정숨기기삭제」가 간격 없이 붙어 보인다(새 안의 `_common.css`는 간격을 넣어 찍었다).
