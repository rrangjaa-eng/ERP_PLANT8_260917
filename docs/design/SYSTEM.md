## 0. 방향

**이름: 원장(元帳)** — 안 A. 색 구성은 안 C(작업대)의 그린 톤온톤을 흡수했다.

**한 줄 원칙**
> 화면 전체가 하나의 원장이다. 카드도 패널도 그림자도 없다. 깊이는 선 두께 2단계와 그린 명도 단계로만 만든다.

이 한 줄이 이 제품이 남과 다른 지점이다. 「흔한 AI 대시보드」(둥근 카드·그림자·그라디언트·보라 포인트)로 가는 길을 구조적으로 막고, 「관공서 사내망」(회색 격자·작은 글씨)과는 선 두께의 위계와 여유 있는 행 높이로 갈라진다.

**채택 이유 3줄**
1. 가장 잦은 작업(견적 줄 표, 연 1,379행)을 표 자체가 화면인 틀이 정면으로 푼다. 표를 「나중에 따로」 만드는 안은 시스템 두 벌이다.
2. 계급마다 칸 수가 달라지는 정보 노출표에 가장 잘 견딘다. 원장은 칸이 빠지면 폭이 재분배될 뿐, 빈 타일이 남지 않는다.
3. 컴포넌트 수가 가장 적고 규칙이 한 줄로 말해진다. 비개발자 1인이 6개월 뒤에도 고칠 수 있다.

### 1-3. 색 사용 규칙

1. **포인트 색(`--accent`)을 쓰는 곳은 다섯 곳뿐**: ① 내 차례 태그·행동 링크 ② 편집 중 셀·행 ③ 1차 버튼 ④ 포커스 링 ⑤ 현재 위치(내비게이션 밑줄). 그 밖의 장식(아이콘 색, 제목 색, 구분선 색)에는 쓰지 않는다.
2. **배경 틴트는 바탕(`--bg`) 위에 세 단계(`--surface` → `--g-50` → `--g-100`)만 쓰고 중첩하지 않는다.** 틴트 위에 틴트를 올리지 않는다. 틴트 위에 두 번째 깊이가 필요하면 선(2px)으로 만든다.
3. 상태색은 **글자·태그 테두리·약한 배경** 세 형태로만 쓴다. 상태색으로 넓은 면을 채우거나(행 전체 붉게), 상태색 버튼을 만들지 않는다. 막힘 행의 배경은 `--danger-weak`이 아니라 태그만 붉다. 오류 **셀**만 `--danger-weak`으로 채운다.
4. 상단 바(`--bar`)는 앱 전체에서 **딥그린 면이 나오는 유일한 곳**이다. 1차 버튼은 면이 아니라 컨트롤이다. 하단 힌트 줄·푸터는 흰 바탕에 `--faint` 글자다.
5. 검정 `#000000`(`--print-ink`)은 인쇄 템플릿의 글자에만 쓴다(§6-6). 화면 글자는 `--fg`다. 인쇄물의 구조 선(2px)은 `--print-rule`(= `--g-700`) — 화면 `--line-strong`의 인쇄판이며, 포인트 색 다섯 곳 규칙(위 1)은 화면 규칙이다
6. 새 색을 만들지 않는다. 필요하면 `--g-*` 단계에서 고르고, 없으면 `DECISIONS.md`에 이유를 남기고 단계를 추가한다.

### 2-1. 서체 확정

| 항목 | 결정 |

| 인쇄 | 같은 Pretendard. 명조 없음 |
| 폴백 | `'Pretendard Variable', Pretendard, 'Apple SD Gothic Neo', 'Malgun Gothic', system-ui, sans-serif` |
| 굵기 | 400(본문) · 600(라벨·버튼·태그) · 700(제목·합계). **세 단계만**. 800은 로고 워드마크에만 |

시스템 스택을 버린 이유: 회사 PC는 Windows가 많아 시스템 스택이면 맑은 고딕이 되고, 맑은 고딕은 tabular-nums를 지원하지 않아 표의 자릿수 정렬이 깨진다. 표가 화면인 시스템에서 이건 비용이 아니라 성립 조건이다. 서브셋 첫 로드는 약 200–300KB, 사내 고정 사용자라 캐시 후 0이다.

**파일과 `@font-face` 계획 (확정 2026-09-18, `DECISIONS.md` 「서체 파일 리포 커밋」)**

출처는 npm 패키지 `pretendard@1.3.9`(2023-11-05, OFL-1.1, GitHub `orioncactus/pretendard` 릴리스 v1.3.9와 같은 파일). 패키지 의존은 만들지 않고 tarball에서 파일만 복사한다. 리포에 들어가는 것:

```
public/fonts/pretendard/
  LICENSE.txt                              ← OFL 1.1 원문(dist/LICENSE.txt 그대로). 재배포 조건
  pretendard-dynamic-subset.css            ← dist/web/variable/pretendardvariable-dynamic-subset.css
  woff2-dynamic-subset/PretendardVariable.subset.{0..91}.woff2   ← 92개, 합계 3.1MB
```

css는 원본을 그대로 쓴다 — 이미 `font-family: 'Pretendard Variable'` · `font-display: swap` · `font-weight: 45 920` · `format('woff2-variations')` · unicode-range 92분할이고, `src: url(./woff2-dynamic-subset/…)`가 상대 경로라 css와 폴더를 같은 자리에 두면 고칠 것이 없다.

```html
<!-- app/layout.tsx <head> — 이 한 줄뿐 -->
<link rel="stylesheet" href="/fonts/pretendard/pretendard-dynamic-subset.css">
```

```css
/* 전역 CSS는 tokens.css의 --font-sans만 쓴다. @font-face를 다시 쓰지 않는다 */
body { font-family: var(--font-sans); }
```

- 단일 파일(`woff2/PretendardVariable.woff2`, 2.0MB)은 쓰지 않는다 — 첫 화면에 필요한 글자 범위만 받는 서브셋이 200–300KB로 끝난다. preload 없음(범위별 지연 로드가 목적)
- 캐시: Cloud Run 정적 자산 기본 헤더. 파일명에 해시가 없으므로 버전을 올릴 때 폴더째 바꾼다(`pretendard/` → `pretendard-1.3.10/`)
- 검수(Phase 2): Windows Chrome/Edge에서 표의 자릿수 정렬 스크린샷 — 맑은 고딕 폴백과 Pretendard `tnum`을 나란히. 첫 로드 전송량 200–300KB 확인
- 실제 파일은 **Phase 1(앱 스켈레톤, `public/`) 머지 뒤 Phase 2 앱 코드**에서 넣는다(U3). `docs/design/`에는 바이너리를 두지 않는다

### 2-2. 스케일 6단계 (px)

- 폰(<700px)에서는 `--fs-base`가 15px가 된다. 그 밖의 단계는 그대로.

### 2-3. 행간 · 자간 · 줄 길이

- 한글 본문: `line-height: 1.6`, `letter-spacing: -0.015em`, `word-break: keep-all`, `overflow-wrap: anywhere`(긴 영문 거래처명 대비)
- 표 셀: `line-height: 1.5` (밀도). 단, 셀 내용이 2줄이 되면(항목명 줄바꿈·외화 병기) 행 높이는 내용을 따른다. 행 높이를 고정하지 않는다
- 제목(`--fs-lg` 이상): `letter-spacing: -0.02em`
- 숫자: `letter-spacing: 0` (자간 음수를 풀어 자릿수 폭을 지킨다)
- 줄 길이: 산문(안내·설정 설명)은 `max-width: 64ch`. 데이터 표·체크박스 매트릭스·대시보드는 컨테이너 폭을 따른다. 폼·설정 필드 묶음·`dl` 라벨·값 목록·계층 목록·한 칸짜리 링크 목록처럼 가로 비교가 목적이 아닌 한 열 콘텐츠는 `max-width: var(--form-max)`(720px)이고 컨테이너 왼쪽에 붙는다 — 적용·제외 목록 전문은 §3 「단일 기둥 최대 폭」

| 음수 | 하이픈 마이너스, 괄호 금지, 붉은색 금지 | `-1,200,000` |
| 0과 빈 값 | 0은 `0`. 값이 없으면 `—`(em dash) 하나. 빈칸을 두지 않는다 | `—` |
| 계산 불가 | `계산 불가` + 이유는 hover/폰에서 탭 | `계산 불가 · 환율 없음` |
| 외화 | **두 줄 병기**. 1행 원화 환산액(정수), 2행 `--fs-sm --muted`로 `통화 금액 @환율`. 외화 소수 2자리, 환율 소수 4자리는 서버 표시값 그대로 | `5,800,000`<br>`USD 4,400.00 @1,318.1818` |
| 비율 | 소수 1자리 + `%` | `25.2%` |
| 날짜 | ISO, 하이픈 | `2026-09-18` |
| 같은 해 날짜(표 안) | 월-일만 | `09-18` |
| 기간 | 물결 양쪽 공백 | `09-12 ~ 09-16` |

## 3. 간격

- 기본 단위 **4px**. 토큰 `--s-1`(4) `--s-2`(8) `--s-3`(12) `--s-4`(16) `--s-6`(24) `--s-8`(32) `--s-12`(48)
- 컨테이너: `max-width: 1280px`, 좌우 패딩 PC 20px(`--s-5`=20, 예외 허용) · 폰 14px. 가운데 정렬하지 않고 **왼쪽 정렬**(원장은 왼쪽에서 시작한다). 1440에서 오른쪽이 비는 것을 받아들인다
- **단일 기둥 최대 폭**(2026-09-22 `DECISIONS.md`): 가로 비교가 목적이 아닌 한 열 콘텐츠는 `width: 100%; max-width: var(--form-max)`(720px)이고 컨테이너 **왼쪽**에 붙는다(가운데 정렬하지 않는다). 폰(<700px)은 가용 폭이 720보다 좁아 자연히 전폭이 된다. 새 토큰 없이 `--form-max` 하나를 폼 밖까지 넓혀 쓴다
  - 적용: 폼(§6-3 폼 화면, 내 계정, 관리자 마스터 화면의 등록·수정 폼과 그 결과 패널) · 설정 필드 묶음(§7-2 자동 생성 설정 화면의 섹션 전체 — 2px 섹션 선과 그 안의 §7-14 이력 목록 포함) · `dl` 라벨·값 목록(§6-8 시스템 상태, 사람 상세) · 계층 목록(조직의 본부·팀) · 한 칸짜리 링크 목록(§6-10 「관리」 인덱스)
  - 제외 — 컨테이너 폭 그대로: 데이터 표(§7-3 — 원장·관리자 마스터 목록), 체크박스 매트릭스(§7-13), 대시보드(§6-4), 표 자리의 EMPTY 한 줄(§7-7), 배너(§7-11), 화면 제목 줄(`PageHeader` — 제목·부제만 있는 줄은 폭이 보이지 않는다). 한 화면에 표와 폼이 함께 있으면 폼만 720이고 표는 컨테이너 폭이다
  - 목록 머리글의 필터·등록 행동 줄(§6-1)은 그 아래 콘텐츠와 같은 폭이다 — 표 위면 컨테이너 폭, 한 열 목록(조직) 위면 720
  - 제목 줄 오른쪽에 요소(상태·버튼)가 붙는 폼 화면은 §6-3 「머리 줄도 폼 열 720에 맞춘다」를 따른다
  - 구현: `app/globals.css`의 전역 유틸리티 `.single-column` 하나로 건다(`.sr-only`와 같은 자리). 적용 대상 묶음의 바깥 요소 — 폼이면 `<form>` 자신 — 에 `className="single-column"`을 붙인다. 화면별 모듈 CSS에 같은 `max-width`를 다시 쓰지 않는다
- 그리드: 열 그리드를 두지 않는다. 정렬 기준은 **표의 열 정렬**(문자 좌·숫자 우)이다. 「내 차례」의 금액은 행동 버튼 왼쪽의 고정 최소폭(11ch) 칸에 우측 정렬한다 — 아래 표의 열과 억지로 맞추지 않는다
- 표 셀 패딩: `6px 8px`(PC) · `10px 8px`(폰, 터치 목표 44px 확보). 그룹 머리글 행은 위로 `--s-3` 추가
- 섹션 사이: 2px 강한 선 위 `--s-6`, 아래 `--s-3`
- 폼: 라벨-입력 세로 4px, 항목 사이 16px, 묶음 사이 24px + 1px 선
- 터치 목표: 폰에서 모든 행동 요소 최소 44×44. PC 버튼 높이 32, 폰 40

## 4. 형태

### 4-1. radius 위계표

| 요소 | radius |
|---|---|
| 버튼 · 입력 · 태그 · 모달 · 시트 · 토스트 · 첨부 영역 | **0** |
| 카드 | 해당 없음 — **카드를 만들지 않는다** |
| 아바타·QR 등 외부 이미지 | 0 |

직각은 이 시스템의 형태 원칙이다. 「둥글둥글 = 장난감」을 배제한 브리프의 직접 결과다.

### 4-2. 테두리 (선 3단계 + UI 경계 1)

| 종류 | 두께 · 색 | 쓰는 곳 |
|---|---|---|
| 강한 선 | `2px solid --line-strong` | 섹션 시작(내 차례 위, 표 머리글 아래), 합계 행 위, 상단 바 아래, 모달 테두리 |
| 약한 선 | `1px solid --line` | 표 행 사이, 목록 항목 사이, 폼 묶음 사이 |
| 점선 | `1px dotted --line` | 「내 차례」 항목 사이 (표가 아님을 표시) |
| UI 경계 | `1px solid --line-ui` | 입력 테두리(대기 상태), 체크박스, 2차 버튼이 아닌 3차 컨트롤 |

세로선은 표 안에서 쓰지 않는다(격자 = 관공서 인상). 열 정렬은 정렬 방향(문자 좌 · 숫자 우)과 패딩으로 만든다. 예외: 인쇄 템플릿의 괘선(§6-6).

### 4-3. 그림자 · 깊이

- **그림자 없음.** `box-shadow`는 인셋 선(`inset 0 -2px 0 --accent` 현재 탭 밑줄, `inset 2px 0 0 --danger` 오류 셀 좌측)에만 쓴다
- 깊이는 세 수단만: 선 두께(2px/1px) · 배경 한 단계(`--surface`/`--g-50`/`--g-100`) · 가림막(`--scrim`)
- 모달·시트: `--bg` 면 + `2px solid --line-strong` 테두리 + 뒤에 `--scrim`. 그림자 없음
- 고정(sticky) 요소: 표 머리글은 스크롤 시 상단에 붙고 아래 1px `--line-strong`으로 구분. 그림자로 띄우지 않는다

### 4-4. 브라우저 기본 표면 (기본값으로 두지 않는다)

| 표면 | 값 |
|---|---|
| 텍스트 선택 `::selection` | 배경 `--g-100`, 글자 `--fg` |
| 캐럿 `caret-color` | `--accent` |
| 네이티브 체크박스·라디오·진행 `accent-color` | `--accent` |
| 스크롤바 `scrollbar-color` | `--line-ui` on `--bg`, `scrollbar-width: thin`. 커스텀 스크롤바 그리지 않는다 |
| 3차 버튼 밑줄 | `text-underline-offset: 2px`, 두께 1px → hover 2px |
| 포커스 링 | `:focus-visible` 2px `--focus` offset 2px. `:focus`(마우스)에는 링 없음. **예외 — 전체 폭 목록 행**(행 자체가 링크이고 좌우 여백이 없는 것: 「더보기」 시트 목록 행 · 폰 하단 탭 · 「관리」 인덱스 항목 행)은 `outline-offset`을 안쪽으로 준다(`calc(-1 * var(--focus-w))`) — 바깥에 링을 그릴 여백이 없어 잘리거나 옆 행 경계와 겹치기 때문이다. 굵기·색·표시 조건은 같다(2026-09-22 DECISIONS.md). **예외 — 상단 바(`--bar`) 위 링크·트리거**는 색만 `--bar-fg`다 — `--focus`(`--g-700`)는 `--bar`(`--g-900`) 위에서 보이지 않는다(2026-09-24 DECISIONS.md) |
| 탭 크기 `tab-size` | 4 (코드표·문서 번호 모노 없음이라 거의 안 쓰임) |

브라우저 기본값이 남은 곳이 「조립된 화면」의 가장 싼 티다. 위 값은 `tokens.css`의 `--sel-bg` 등을 그대로 쓴다.

**원칙: 응답형만.** 사용자의 입력에 즉시 반응하는 상태 변화 외에는 움직이지 않는다.

|---|---|---|---|

| 모달 열림 | `opacity` | 120ms | `ease-out` |
| 진행 표시(로딩) | 상단 2px 바 `width` | 무한, 1.2s | `linear` |

### 금지 목록
섹션 fade-up · 카드/행 hover 확대(`scale`) · 페이지 전환 애니메이션 · 숫자 카운트업 · 스켈레톤 반짝임(shimmer) · 패럴랙스 · 그라디언트 이동 · 아이콘 회전(로딩 스피너 포함 — 상단 진행 바로 대체) · 자동 슬라이드

### `prefers-reduced-motion: reduce`
모든 `transition-duration`·`animation-duration`을 `0.01ms`로. 진행 바는 정지된 `--accent` 2px 선으로 대체. 시트·모달은 즉시 나타남.

## 6. 레이아웃 템플릿

모든 화면은 아래 템플릿 중 하나에서 시작한다. 새 템플릿이 필요하면 먼저 여기에 추가한다.

### 6-0. 공통 셸

```
PC (≥1024)
┌──────────────────────────────────────────────────────────────────┐
│▓PLANT8   프로젝트  지출결의  법인카드  결재  손익   ⌘K   박서연·기획1팀▓│ ← --bar 38px
╞══════════════════════════════════════════════════════════════════╡  ← 2px
│ (main, max 1280, 좌측 정렬, 패딩 20)                                  │
│                                                                  │
│  이동 Tab ↑↓  범위 복사 ⌘C/⌘V  취소 Esc  새 줄 ⌘↵  저장 ⌘S          │ ← 단축키 힌트 줄(표 화면만)
└──────────────────────────────────────────────────────────────────┘

폰 (<700)
┌──────────────────────┐
│▓PLANT8      박서연  ≡▓│ ← --bar 44px, 메뉴는 ≡ 뒤 시트로
```

- 상단 바: 앱 유일의 딥그린 면. 로고 워드마크는 **흰색 반전판**(잎 `--g-400`)을 쓴다 — 브랜드 자산은 검정 워드마크 하나지만 딥그린 위 반전 사용을 사용자가 승인했다(2026-09-18, `DECISIONS.md` U1). 워드마크는 PC·폰 모두 「내 차례」(`/`)로 가는 링크다 — 셸에서 홈으로 상시 돌아가는 길이다(2026-09-24 사용자 결정, /design-review FINDING-001). 보이는 글자는 `PLANT8` 그대로, 접근 이름은 `PLANT8 내 차례`. 누르는 영역은 바 전체 높이(PC 38 · 폰 44, 폰 전용 규칙 없음). hover는 밑줄(`text-underline-offset: var(--underline-offset)`), 포커스 링은 상단 바 메뉴 링크와 같다(`--focus-w` 굵기 · `--bar-fg` 색, §4-4 상단 바 예외). 1차 메뉴가 아니므로 `aria-current`를 두지 않는다. Tab 순서는 스킵 링크 → 워드마크 → 1차 메뉴 → 사용자 메뉴(폰은 1차 메뉴 없음). 1차 메뉴 5개 · 명령 팔레트 `⌘K` · 사용자. 현재 메뉴는 `--bar-fg` 700 + 아래 2px `--g-400` 밑줄
- 정보 노출표로 메뉴가 빠지면(기획본부에 「손익」 없음) 남은 메뉴가 왼쪽으로 붙는다. 빈 자리를 두지 않는다
- 폰 하단 탭: 역할별 첫 화면(UX-02)에 따라 4개. 글자만, 아이콘 없음
- 브레드크럼 없음. 화면 제목(`--fs-lg`) + 부제(`--fs-sm --muted`)가 위치를 말한다
- **태블릿 700–1023**: PC 셸을 그대로 쓴다(상단 바 메뉴 유지, 하단 탭 없음). 표는 P3 열만 숨긴다. 별도 레이아웃을 만들지 않는다
- **폰 하단 탭 4개는 역할별 첫 화면(UX-02)을 따른다.** 1번 탭이 곧 첫 화면이고 「내 차례」 건수를 라벨에 붙인다(`내 차례 3`). 4번은 항상 「더보기」

| 계급 | 탭 1 | 탭 2 | 탭 3 | 탭 4 |
|---|---|---|---|---|
| 대표 | 내 차례 | 결재 | 손익 | 더보기 |
| 본부 책임자 | 내 차례 | 결재 | 손익 | 더보기 |
| 팀장 | 내 차례 | 결재 | 손익 | 더보기 |
| 기획 PM | 내 차례 | 프로젝트 | 지출결의 | 더보기 |
| 시스템 관리자 | 내 차례 | 결재 | 손익 | 더보기 |

앞 세 계급(대표·본부 책임자·팀장)은 §6-4가 첫 화면을 손익 대시보드로 규정한 계급이고, 기획 PM 행은 Phase 2의 「직원」 행을 그대로 물려받았으며, 시스템 관리자 행은 Phase 2의 「관리자」 행을 그대로 물려받았다.

- **(a) PC 상단 바 우측 사용자 진입점**: 사용자 이름을 클릭하면 작은 메뉴가 열린다 — 내 정보 · 로그아웃(권한표에서 view 권한이 있는 관리자 화면이 하나라도 있는 계급만 그 위에 「관리」(§6-10) 항목이 하나 더 보인다 — 개별 관리자 화면(시스템 상태 · 코드표 · 권한표 …)의 이름은 이 메뉴에 나오지 않고 「관리」 인덱스에서 세 그룹으로 고른다, D-17). Esc로 닫히고 포커스가 원래 요소로 돌아온다 — §7-8 시트와 같은 결의 동작이 PC에 하나 더 생긴 것이다. 알림함(§7-12, 구현은 Phase 7)이 생기면 이 메뉴 안의 한 항목으로 들어간다
- **(c) 소속 표기**: 상단 바 사용자 표기는 **이름만**이다. `lib/viewer.ts`의 `SessionUser`에 소속 필드가 없어 위 실물 그림의 「박서연·기획1팀」처럼 소속을 병기하지 않는다 — Phase 3이 소속 필드를 추가하면 그때 병기한다

- **색 하나 = 뜻 하나.** 팀 색 2개(`--viz-1` 기획1팀 = 그린, `--viz-2` 기획2팀 = 파랑)와 상태색(`--warning` `--danger` `--success`)만. 팀 색은 목표 막대 · 매출 비중 띠 · 순위 막대에서 같은 색으로 이어진다. 구성 비율은 그린 단계(`--seg-*`). 그 밖의 장식색(주황 선 · 보라·적갈 칩) 없음
- **차트 종류**: 추세선(KPI) · 진행 막대(목표) · 월별 묶음 막대 + 선 · 비중 띠 · 도넛(구성 비율) · 순위 막대 · 미니 막대. **이 화면 밖의 차트는 여전히 인라인 막대 하나**(§7-3 「목표 대비」 열)다. 원형·꺾은선을 다른 화면에 옮기지 않는다
- 용어는 시스템대로 「매출 = 견적 합계」 「실행가 = 확정 비용」이라 부제로 병기한다(대시보드 라벨 「연간 매출 · 견적 합계」)
- 정보 노출표: 팀장에게는 자기 팀 숫자만 온다 — 다른 팀 · 전사 블록 자체가 없다. 기획본부에는 이 화면이 없다(메뉴에서 빠짐)
- 태블릿(700–1023): KPI 2열 · 나머지 전폭. 폰: KPI 2열(`--fs-xl`), 블록 한 열, 하단 탭. 도넛은 폭에 맞춰 축소
- 아래 각주 한 줄: `프로젝트별 견적 · 비용 · 수익률은 프로젝트 목록에서 · 숫자는 09-18 06:00 기준 · 정산 스냅샷 포함`

### 6-5. 외부 수령자 화면 (기타소득 지급 확인 = 경품 수령 확인, 폰 전용, 로그인 없음)

실물: `system/external-cert.html`(빈 폼 · 서명만 남음 · 오류 · 제출됨 · 만료 · 택배). 확정 2026-09-18(`DECISIONS.md` 「외부 수령자 화면 실물 확정」). **기타소득은 거의 경품(현물)이다** — 현금 지급액·계좌·세금 줄은 이 화면에 없다(사용자 결정).

- 평생 1회 쓰는 낯선 사용자. 이 화면만 `--fs-md` 본문·입력 48px·한 열·`~해 주세요`체. 시스템의 다른 규칙(직각·틴트·색)은 그대로
- **경품 블록은 경품명 한 줄**(`--fs-lg` 700). 시가 · 원천징수 · 제세공과금 · 지급액 · 계좌 · 「미리 채운 내용」 안내 — 전부 없다. 세금 계산은 내부(인쇄 템플릿 §6-6 · 세무)에서만
- **전달 방법은 담당자가 링크를 만들 때 정한다**(현장 수령 기본 / 택배). 택배일 때만 「주소」 칸이 「택배로 보내 드립니다」 부제로 나타나고, 막힘 이유와 동의 문장의 수집 항목에도 「주소」가 들어간다. 수령자가 고르는 선택지는 없다
- **주민등록번호 확인 = 검사 규칙만**(서버): 형식(6+7) · 앞 6자리가 실제 날짜 · 뒷자리 첫 숫자가 생년 세기와 일치 · 검증번호(2020-10 이전 발급분만). 신분증 첨부 · 본인인증 없음(v1). 오류는 한 문장 `주민등록번호가 맞지 않습니다 · 앞 6자리(생년월일)와 뒤 7자리를 다시 확인해 주세요`, 틀린 칸만 `--danger` 테두리
- **개인정보 수집·이용 동의**: 서명 바로 위, 1px 선으로 묶은 체크박스 + 요약 문장(수집 항목 · 목적 「기타소득 원천징수 신고와 경품 전달」 · 보존 5년 · 미동의 시 지급 불가) + 3차 「전문 보기」. 동의 없으면 제출 막힘. 「안내 문구 없음」 규칙의 예외 — 법적 고지다. **문장은 법무 확인 전 초안**, 골격은 확정
- 다섯 상태: 막힘 = 1차 버튼 비활성 + 빈 칸 전부 나열 → 서명만 남으면 `서명을 해 주세요` 한 마디. ERROR = 틀린 칸 + 제출 줄 `주민등록번호를 고쳐 주세요 · 나머지는 채워졌습니다`. SUCCESS = 폼이 사라지고 `제출되었습니다 · 이 링크는 닫혔습니다` + `김하늘 · 2026-09-20 18:42 제출 · 갤럭시 탭 S10 1개 현장 수령`(택배면 `적은 주소로 보내 드립니다`) + `확인이 필요하면 담당자 박서연 · PLANT8 경영관리에 연락해 주세요`. **만료**(이미 제출된 링크 재진입) = `이미 제출된 링크입니다` + `이름 · 제출 일시 제출됨. 내용을 고치려면 담당자 … 에 연락해 주세요` — 경품·입력 내용은 다시 보이지 않는다
- 제출 줄은 `main` 안 sticky(폰 하단). 1차 버튼 라벨은 실제 동작 「확인증 제출」. 확인증 PDF 링크(CERT-05)는 **v2** — v1에서 수령자는 확인증 인쇄물을 보지 않는다(내부·세무 보관용)

### 6-6. 인쇄 템플릿 (지출결의서 · 기타소득 확인증)

실물: `system/print-expense.html` · `system/print-cert.html`. 확정 2026-09-18(`DECISIONS.md` 「인쇄물 재디자인 확정」 4건). 발산 기록 `system/print/`.

인쇄는 화면과 **같은 토큰, 다른 레이아웃**이다. `@media print`로 화면을 숨기는 방식이 아니라 인쇄 전용 라우트(`/print/…`)가 아래 템플릿을 A4 세로로 렌더한다. 브라우저 인쇄 → PDF. 템플릿이 쓰는 색 토큰은 셋뿐: `--print-ink`(글자·서명) · `--print-rule`(구조 선 2px, 그린) · `--print-line`(구분 가로선 1px, 회색).


- **세로선 없음.** 라벨·값은 1px `--print-line` 가로선으로만 나눈다. 격자는 만들지 않는다(관공서 인상)
- **2px 선은 전부 `--print-rule`(그린)**: 제목 아래 괘선 · 명세 표 머리와 합계 · 결재 칸 위 · 확인증 금액 블록의 실지급액 위. 워드마크도 같은 색. 그 밖의 글자·숫자·서명은 `--print-ink`
- **금액**: 지출결의서는 명세 표(구분 · 내용 · 금액)로, 합계 행에 `--fs-xl` 700 + 한글 금액 병기(「금 일천삼백육십사만 원정」). 확인증은 오른쪽 90mm 금액 블록(지급액 · 원천징수 + 내역 2행 · 실지급액 `--fs-xl` + 한글 금액)
- 결재 칸: **이름 + 결재 일시 텍스트**. 직원 서명 이미지는 쓰지 않는다(사용자 결정 U2). 서명 이미지는 확인증의 수령자 터치 서명만
- 기타소득 확인증: 같은 골격. 제목 「기타소득 지급 확인증」, 부제 = 확인증 번호 + 연결 지출결의 번호, 지급 내용(프로젝트 · 항목 · 소득 종류 · **경품**(현물이면 품목 · 수량, 현금이면 「—」, 2026-09-18 추가) · 지급일), 「수령자」 표(이름 · 주민등록번호 뒷자리 마스킹 · 주소 · 연락처 · 계좌), 금액 블록, 확인 문장 한 줄(「위 금액을 기타소득으로 지급받았음을 확인합니다.」), 하단에 지급자(회사명 · 지급일) · 수령자(이름 · 제출 일시) · 터치 서명 이미지(64mm, 아래 1px 선). **v1에서 수령자는 이 인쇄물을 보지 않는다**(내부·세무 보관용, §6-5)
- 인쇄 규칙: 그린 틴트 면 · 상단 바 · 버튼 · 힌트 줄 · 상태 태그 **전부 없음**. 페이지 나눔은 표 행 안에서 일어나지 않게 `break-inside: avoid`. 첨부 이미지는 2장부터 한 장에 하나, 긴 변 맞춤
- 화면에서 「인쇄」는 2차 버튼. 새 탭으로 인쇄 라우트를 열고 자동 `window.print()`

```
│ 이메일 또는 비밀번호이    │ ← role="alert", 로그인 실패 시(A②), 같은 자리에 계정 잠금 안내(A③)
│ 올바르지 않습니다.       │
│                        │
│      [로그인]           │
└────────────────────────┘
```

- 틀 폭: `max-width: var(--auth-max)`(360px), 가운데 정렬, PC·폰 공통(폰은 가용 폭이 더 좁으면 그 폭)
- 워드마크는 §6-0의 상단 바 반전판이 아니라 `--fg` 그대로, **폼 위 가운데** 정렬(A①)
- 로그인 실패 문구는 **폼 위 한 줄**, `role="alert"`, `--danger`: `이메일 또는 비밀번호가 올바르지 않습니다.`(이메일·비밀번호 오류를 구분하지 않는다, AUTH-04 재량)(A②)
- **계정 잠금 안내는 실패 문구와 같은 자리, 문구만 다르다**(A③) — 문구의 정본은 `domain/auth/locked-message.ts`다: `로그인 시도가 너무 많습니다. 15분 뒤 다시 시도하거나 관리자에게 문의하세요.`(남은 시간은 표시하지 않는다)
- 비밀번호 변경 뒤 돌아온 안내는 **같은 폼 위 자리, 실패 문구보다 위, `role="status"`**: `비밀번호가 바뀌었습니다. 다시 로그인하세요.`(문구·URL 패턴은 `test/e2e/change-password.spec.ts`가 이미 단언 — 이 문구를 바꾸지 않는다, F-1)
- 세션 만료로 돌아온 경우의 안내는 **자리만 위와 같이 계약하고, Phase 2는 이 신호를 만들지 않는다**(`lib/viewer.ts`의 `requireSession`은 이유 없이 `/login`으로 보낸다 — 이유를 붙이는 것은 이후 페이즈, F-2)
- **임시 비밀번호 배너(D-08)는 이 화면에 뜨지 않는다** — 로그인 직후 **내 계정 화면 상단**(§6-3 폼 템플릿, §7-11)에 뜬다(A④). 로그인 화면 자체는 배너를 갖지 않는다
- 다섯 상태:
  - LOADING: 제출 버튼이 §7-1 진행 중 상태(라벨 뒤 `…`, 다른 입력 비활성)
  - EMPTY: **해당 없음** — 폼은 항상 이메일·비밀번호 두 입력칸과 함께 렌더되고 빈 상태가 없다(A⑤)
  - ERROR: 위 로그인 실패 문구 자리(§7-2 필드 단위 서버 검증과는 별개 — 필드가 아니라 전역 실패)
  - SUCCESS: 이 화면 안에 성공 UI가 따로 없다 — 제출이 성공하면 `/account`로 즉시 이동하고, 그 화면 전환 자체가 결과 표시다
  - PARTIAL: **해당 없음** — 로그인 폼은 부분 계산·부분 표시 개념이 없는 단일 제출 폼이다(A⑤)

### 6-8. 시스템 상태 화면 (권한표의 시스템 상태 보기 권한이 있는 계급만, D-17 — 권한이 없으면 404)

```
│ 시스템 상태                                    │ ← --fs-lg 화면 제목
│ DB 커넥션이 한도의 92%를 넘었습니다              │ ← §7-11 배너, 경고 등급, 화면 제목 위(B③)
├────────────────────────────────────────────┤
│ 배포 버전    a1b2c3d4 · 2026-09-19 · production│ ← dl, 라벨 96(PC)/84(폰)
│ DB 커넥션    18 / 20
│ 마지막 백업  성공 · 2026-09-19 03:00
```

- **라벨·값 목록**(`dl`, §7-8 시트 상세와 같은 골격): 라벨 `--fs-sm --muted` 600, 폭 96(PC)/84(폰), 행 사이 점선 `--line`(B①)
- 세 항목: 배포 버전(SHA·배포 시각·환경), DB 커넥션(현재/최대), 마지막 백업(상태·종료 시각)
- **「확인 불가」는 값 자리에 §7-5 상태 태그**(`--muted`)로 표시한다: `확인 불가`(B②)
- DB 커넥션 한도 경고는 **§7-11 배너**, 경고 등급, **화면 제목 위**(B③, D④)
- 「관리」 인덱스(§6-10)의 「운영 기록」 그룹이 이 화면의 진입점이고, PC 사용자 메뉴(§6-0 (a))·「더보기」 시트(§7-8)의 「관리」 한 줄이 그 인덱스로 간다
- 다섯 상태:
  - LOADING: §7-7 표 골격과 같은 방식 — 세 항목 자리에 `--surface` 뼈대 3줄, 스피너 없음
  - EMPTY: **해당 없음** — 볼 권한이 있는 계급이 들어오면 항상 세 항목이 조회되고 빈 목록이 아니다
  - ERROR: 조회 자체가 실패하면(예: Cloud SQL Admin API 오류) 화면 제목 아래 한 줄 `--danger`: `상태를 불러오지 못했습니다 · 다시 시도`
  - SUCCESS: **해당 없음 — 조회 전용 화면**이라 사용자 행동의 결과를 표시할 자리가 없다(§7-7 손익 원장 행과 같은 논리)
  - PARTIAL: 일부 항목만 「확인 불가」 상태 태그로 표시되고 나머지 항목은 정상 값을 보인다

### 6-9. 오류 페이지 (404 · 권한 없음 · 세션 만료)

```
│ (셸 그대로: 상단 바·하단 탭 유지)                 │
│                                              │
│ 페이지를 찾을 수 없습니다                        │ ← --fs-2xl, tokens.css 토큰 안에서 렌더
│ 이 페이지가 없거나 옮겨졌습니다                    │
│           [첫 화면으로]                        │ ← 1차 버튼, 다음 한 수
```

- 404 · 권한 없음 · 세션 만료 셋은 **한 템플릿의 세 변종**이다 — 제목(상태 문구) · 설명 한 줄 · 1차 버튼(다음 한 수)만 바뀐다(C①)
- 셋 모두 **셸 안에서** 렌더된다(상단 바·하단 탭 유지) — 로그인 화면(§6-7)과 달리 이미 인증된 사용자가 보는 화면이므로 내비게이션이 남아 있어야 다음 행동이 쉽다(C②)
- 셋 모두 프레임워크 기본 오류 화면을 쓰지 않고 `tokens.css` 토큰 안에서 렌더된다
- 다음 한 수(C③): **404 → 첫 화면**(D-17에 따라 권한이 없는 사람은 권한 없는 리소스도 404로 본다 — 이 404는 로그인한 사람이 보는 404다), **권한 없음 → 첫 화면**(2026-09-24 사용자 확인 — 02-01 추천안의 「로그인으로」 대신, `DECISIONS.md`), **세션 만료 → 로그인**(재인증 필요)
- 다섯 상태:
  - LOADING: **해당 없음** — 오류 상태 자체가 이미 확정된 결과이고, 렌더 전의 로딩은 이전 화면의 LOADING이다
  - EMPTY: **해당 없음** — 오류 페이지는 항상 제목·설명·버튼 셋을 채운 채로 렌더되고 빈 콘텐츠가 없다
  - ERROR: 이 화면 자체가 ERROR 상태의 표현이다 — 제목·설명·1차 버튼(§7-7 ERROR 「무엇이 안 됐다 · 다음 행동」과 같은 구조)
  - SUCCESS: **해당 없음** — 오류 페이지는 행동의 결과를 표시하는 화면이 아니다
  - PARTIAL: **해당 없음** — 오류 상태는 전부-아니면-전무이고 부분 표시가 없다

### 6-10. 「관리」 인덱스 화면 (관리자 화면 10개의 단일 진입점)

```
│ 관리                                          │ ← --fs-lg 화면 제목
├────────────────────────────────────────────┤
│ 마스터                                        │ ← 그룹 머리글, --fs-sm --muted 600
│ 사람                                          │ ← 항목 행, --touch-min 높이 링크
│ 거래처
│ 법인카드 마스터
│ 코드표
│
│ 설정·권한
│ 권한표
│ 정보 노출표
│ 시스템 설정
│
│ 운영 기록
│ 시스템 상태
│ 행동 로그
│ 보관함
```

- **그룹과 순서가 정본인 표**(role-menu.ts의 `adminIndexGroups`가 이 표와 원소 단위로 같아야 한다, 단위 테스트가 대조한다):

| 그룹 | 항목 |
|---|---|
| 마스터 | 사람 · 거래처 · 법인카드 마스터 · 코드표 |
| 설정·권한 | 권한표 · 정보 노출표 · 시스템 설정 |
| 운영 기록 | 시스템 상태 · 행동 로그 · 보관함 |

- 진입점은 PC 사용자 메뉴(§6-0 (a))와 「더보기」 시트(§7-8)의 「관리」 한 줄뿐이고, 개별 관리자 화면 이름은 그 두 표면에 나오지 않는다. 관리자 화면이 늘어도 셸의 줄 수는 그대로다.
- 행 모양: 그룹 머리글은 §7-3 그룹 머리글 행 규칙을 **그대로** 쓴다 — `--fs-sm --muted` 600, 위 12px 여백, **아래 `1px --line-strong`**(세 항목 모두. 아래 선이 빠지면 머리글이 항목 사이 `--line` 잔선과 시각 무게가 같아져 그룹이 갈라지지 않는다). 항목은 §7-8 시트 목록 행과 같은 높이(`--touch-min`)의 링크. 카드 없음, 아이콘 없음, 설명 문구 없음(§8).
- 서버가 거른다: 권한표에서 view 권한이 있는 항목만 서버가 보낸다(§7-3 「칸 수 가변」과 같은 원칙 — 클라이언트에서 숨기지 않는다). 항목이 하나도 없는 그룹은 머리글도 렌더하지 않는다.
- 볼 수 있는 항목이 0개인 계급에게는 이 화면이 404이고(D-17) 「관리」 줄도 없다.
- 다섯 상태:
  - LOADING: **해당 없음** — 서버 렌더 한 번에 목록이 확정되고 추가 조회가 없다
  - EMPTY: **해당 없음** — 볼 항목이 0개면 빈 화면이 아니라 404다
  - ERROR: **해당 없음** — 조회할 데이터가 없다(세션·권한 실패는 §6-9가 받는다)
  - SUCCESS: **해당 없음** — 이동 전용 화면이라 사용자 행동의 결과를 표시할 자리가 없다
  - PARTIAL: 계급에 따라 일부 그룹·항목만 보인다, 빠진 자리를 `—`로 채우지 않는다

## 7. 컴포넌트 규칙

모든 컴포넌트는 LOADING · EMPTY · ERROR · SUCCESS · PARTIAL 다섯 상태를 정의한다(UX-01). 상태별 규칙은 §7-7.

### 7-1. 버튼 위계

| 위계 | 모양 | 한 화면에 | 예 |
|---|---|---|---|
| 1차 | `--accent` 면 + 흰 글자 600 · hover `--accent-hover` | **1개** | 일괄 저장 · 제출 · 승인 |
| 2차 | 흰 면 + `1px --line-strong` 테두리 + `--fg` 600 · hover `--surface` | 필요한 만큼 | 복사해 새 차수 · 인쇄 · 반려 |
| 3차 | 테두리 없음, `--accent` 글자 600 + 아래 1px 밑줄 · hover 밑줄 2px | 표·목록 행 안 | 증빙 올리기 · 견적 열기 · 바꾸기 |

- 높이 PC 32 · 폰 40. 패딩 좌우 12. `--fs-sm` 600. radius 0
- 단축키가 있는 버튼은 라벨 오른쪽에 `kbd`(`--fs-xs`, `1px --line`, `--faint`)로 병기: `일괄 저장 ⌘S`
- **1차 버튼(`--accent` 면) 위의 `kbd` 테두리는 기본 규칙(`1px --line`)이 아니라 `1px var(--on-accent-weak)`를 쓴다** — 어두운 면 위에서 밝은 회색 `--line`은 보이지 않는다. 실물(`system/preview.html`)의 `rgba(255,255,255,.5)` 리터럴을 값 그대로 옮긴 토큰이다(`tokens.css`, D-20 stylelint 리터럴 금지를 새 토큰으로 통과)
- 건수가 있으면 라벨 뒤에 숫자: `일괄 저장 3`
- **비활성 버튼은 이유를 옆에 글자로 쓴다.** `--surface` 면 + `--faint` 글자 + `cursor: not-allowed`. 이유 텍스트 `--fs-sm --danger` + 다음 한 수 3차 버튼. 이유 없는 비활성 버튼은 금지(UX-06)
- 위험 행동(삭제·반려)은 색이 아니라 **확인 모달**로 구분한다. 붉은 버튼 없음
- **진행 중(서버 액션 대기)**: 누른 버튼은 비활성 + 라벨 뒤 `…`(`일괄 저장…`), 같은 폼의 다른 버튼도 비활성. 300ms 넘으면 상단 바 아래 2px 진행 바(§7-7 LOADING). 스피너 없음. 응답이 오면 라벨 자리에 결과(§7-7 SUCCESS) 또는 이유(ERROR)
- 버튼 라벨 = 실제 동작(§8). `확인` `제출` 같은 빈 라벨 금지

### 7-2. 입력 · 오류 표시

- 텍스트 입력: 높이 32(PC)/40(폰)/48(외부 수령자). `1px solid --line-ui`, 배경 `--bg`, 패딩 `0 8px`, `--fs-base`. focus: `outline 2px --focus offset 2px`, 테두리는 그대로. radius 0
- 표 안 입력: 테두리 없이 아래 `1px --accent` 밑줄 + focus 링. 셀 배경 `--g-50`
- 라벨: 입력 위(폰) 또는 왼쪽 96px(PC 폼). `--fs-sm --muted` 600. 필수 표시 `*` 없음 — 필수인데 비면 제출 버튼이 이유를 말한다
- 자리표시자(placeholder)는 형식 예만: `2026-09-18`, `12,400,000`. 안내문 금지
- 금액 입력: 타이핑 중 쉼표 자동 삽입, 우측 정렬, `tabular-nums`
- 선택(select): 네이티브 `<select>` 그대로 + 시스템 테두리. 커스텀 드롭다운 만들지 않는다
- 오류(서버 검증, UX-04): 입력 테두리 `--danger` 1px + 입력 아래 `--fs-sm --danger` 한 줄 **「원인 · 다음 행동」**. 예: `날짜 형식이 아닙니다 · 2026-09-18처럼 적어 주세요`. 아이콘 없음. 입력값은 지우지 않는다
- 자동 채움된 칸: 입력 대신 텍스트 + 「바꾸기」 3차 버튼

**자동 생성 설정 화면 필드 렌더 규칙(ADMN-05, 03-04)** — registry 타입 → 위 입력
매핑:

| registry 타입 | 입력 | 비고 |
|---|---|---|
| boolean | 체크박스(네이티브, §4-4 `accent-color`) | 라벨 = 설정 이름, 라벨 자체가 클릭 영역 |
| number | 텍스트 입력, 우측 정렬 `tabular-nums` | 퍼센트·정수 등 단위는 입력 밖 정적 글자로 병기(`10` `%`) — 단위를 입력 안에 넣지 않는다(위 "자리표시자는 형식 예만") |
| string | 텍스트 입력 기본 | |
| enum | 네이티브 `<select>` | 커스텀 드롭다운 금지 규칙 그대로 |
| 이력형(모든 하위 타입) | §7-14 이력 목록 | 이력형 여부는 값 타입과 독립된 별도 축 — 이력형 + number면 이력 목록의 "값" 칸이 숫자 입력 |

설정 저장 시점: 비이력형 필드는 §7-13과 같은 즉시 저장(텍스트는 blur, 체크박스·select는
change) — 검증 실패(zod)는 위 오류 규칙(입력 아래 원인·다음 행동)으로, 별도 「저장」
버튼·일괄 저장 없음. 이력형은 §7-14의 「새 이력 추가」 자체가 저장 동작이다.

설정 항목 설명 문구: **라벨(짧은 이름) + 선택적 힌트(한 문장, 최대 한 줄) 두 가지만
둔다. 긴 설명은 두지 않는다.** 그보다 긴 설명이 필요한 항목은 설정 값이 아니라
문서에 적어야 할 정책이다(03-UI-SPEC.md unresolved 항목의 해소, 03-04 objective 결정).

설정 화면 구성: §6-2 상세 화면처럼 탭 없이 섹션(2px 선)으로 이어진다. 섹션 = registry
키의 namespace(예: 「세율」 「로그인 잠금」). 섹션 안 필드는 §6-3 폼의 라벨-입력 규칙
(라벨 96px, `--fs-sm --muted`)을 그대로 쓴다.

### 7-3. 표 (이 시스템의 중심 컴포넌트)

**구조**
- 머리글: `--fs-sm --muted` 600, 아래 `1px --line-strong`. 스크롤 시 sticky. 읽기용 표(목록)는 흰 바탕, **편집용 표(견적·카드·목표)는 `--g-100` 바탕 + `--g-950` 글자** — 편집 가능한 표임을 머리글 색으로 안다
- 행: 아래 `1px --line`. hover `--surface`. 높이는 내용 따라(최소 36 PC / 44 폰)
- 그룹 머리글 행: `--fs-sm --muted` 600, 위 12px 여백, 아래 `1px --line-strong`
- 합계 행: 위 `2px --line-strong`, `--fs-base` 700. 편집용 표에서는 `--g-100` 바탕. **저장 결과 메시지가 이 행 오른쪽 끝에 붙는다**(아래)
- 세로선 없음. 첫 칸(행 번호) `--fs-xs --faint`, 폭 28
- 열 폭: 문자 열은 `auto`, 숫자 열은 내용 최대 자릿수에 고정(`ch` 단위). 항목명은 줄바꿈 허용(`keep-all`), 거래처는 한 줄 말줄임

**편집 (UX-05, 엑셀과 같은 키)**
- 셀 클릭 또는 Enter → 편집. Tab/Shift+Tab 좌우, Enter 아래, 방향키 이동, Esc 취소(값 되돌림), ⌘C/⌘V 범위 복사·붙여넣기(붙여넣기 범위가 표를 넘으면 새 줄 자동), ⌘↵ 새 줄, ⌘S 일괄 저장, ⌘E 현재 줄로 지출결의, ⌘D 줄 복제, Delete 줄 삭제(확인 모달)
- 편집 중 행: 배경 `--g-50`, 셀에 `--accent` 밑줄. 저장 대기(dirty) 셀: `inset 0 0 0 1px --g-600` 외곽선. 선택 범위: `--g-50`, 활성 셀 `2px --accent` 외곽선
- **일괄 저장은 전부 저장 또는 전부 거부.** 실패 시: 오류 셀은 `--danger-weak` 배경 + 좌측 `2px --danger` 인셋 선으로 **고정**(다른 셀을 편집해도 남는다), 셀 hover/포커스에 이유 한 줄(`--fs-sm --danger`, 셀 아래 인라인). 합계 행 오른쪽에 `오류 1칸 · 전부 거부` 붉게. 성공 시 같은 자리에 `저장됨 6줄 14:02` `--success`, 편집 행 배경이 600ms 동안 `--g-50` → `--bg`
- 충돌(다른 사람이 먼저 저장): 해당 셀을 오류 셀과 같은 모양으로 고정, 이유 `다른 사람이 14:01에 9,800,000으로 바꿈 · 덮어쓰기 / 그 값으로`
- 읽기 모드와 편집 모드를 나누지 않는다. 편집 권한이 있으면 표는 항상 편집 가능하다

**외화 병기 (행 높이 규칙)**
- 금액 셀은 `vertical-align: top`. 외화가 있는 행만 금액 셀이 두 줄(1행 원화, 2행 `--fs-sm --muted` `USD 4,400.00 @1,318.18`)이 되고, 같은 행의 다른 셀은 첫 줄 기준으로 정렬된다. 행 높이는 두 줄 셀을 따른다. 고정 높이 금지
- 편집은 원화가 아니라 **외화 금액·환율** 두 칸에서 하고 원화는 계산값(읽기 전용)이다
- 합계 행은 원화만. 외화 합계는 만들지 않는다
- 폰에서는 2행이 접힌 줄(P2)로 내려간다

**폰 전략 = 칸 접기 (가로 스크롤 금지 · 카드 전환 금지)**
- 모든 열은 우선순위 **P1 / P2 / P3**을 선언한다. `<700px`에서 P1만 열로 남고 P2는 각 행 아래 **접힌 줄** 하나(`--fs-sm --muted`, `라벨 없이 값 · 값 · 값`, 순서는 열 순서)로 들어가고 P3은 숨는다(상세에서 본다)
- P1은 **항목(문자 1개) + 금액(숫자 1개) + 상태 또는 행동(1개)**, 최대 3열. 그 이상 P1을 두면 시스템 위반
- 접힌 줄에 외화 2행·거래처·날짜·오류 이유가 들어간다. 그 대신 P1 셀 안의 2행(외화·오류 이유)은 폰에서 숨긴다 — 같은 정보를 두 번 보이지 않는다. 행은 두 줄이 되고 터치 목표 44px가 확보된다
- 합계 행의 부제(`공급가액 · 6줄`)는 폰에서 숨긴다. 네 숫자 줄(PNL)은 숨기지 않고 `--fs-sm`으로 줄바꿈한다
- 그룹 머리글·합계 행은 폰에서도 그대로. 합계는 P1 금액 열만
- 폰에서 셀 편집 없음. 행 탭 → 하단 시트(§7-8)에서 상세와 행동
- 표를 카드로 바꾸지 않는다. 카드가 없는 것이 이 시스템의 원칙이고, 접힌 행이 카드의 일을 한다

**칸 수 가변(정보 노출표) 대응**
- 열은 서버가 계급에 따라 **아예 보내지 않는다**. 클라이언트에서 숨기지 않는다(누수 방지)
- 빠진 열의 폭은 문자 열이 흡수한다. 숫자 열은 자릿수 고정폭이라 흔들리지 않는다
- 「차익」「손익」 열이 빠져도 합계 행은 남은 열만으로 성립한다. 빈 칸 자리를 `—`로 채우지 않는다(있는데 값이 없을 때만 `—`)

**(가) 셀 편집 가능성 3단계 — 서버가 셀마다 판정해 보낸다(클라이언트 추론 금지)**

| 단계 | 언제 | 모양 | ARIA |
|---|---|---|---|
| 편집 | 기본 | 흰 셀. 클릭 또는 Enter로 편집 | `aria-readonly="false"` |
| 읽기 전용 | 연결 문서가 있는 줄의 금액 셀(수량·단가·실행가·환율) — 항목명·비고는 편집(D-66). 계산 열(견적가·차익·잔액)도 항상 이 단계 | 값만, 배경 없음. 포커스는 되지만 편집에 들어가지 않는다. 편집 시도 시 셀 아래 한 줄 `--fs-sm --muted` 이유(§7-2와 같은 자리) | `aria-readonly="true"` |
| 잠김 | 완료(정산) 프로젝트의 견적 줄 전체(D-47) | 읽기 전용과 같고, 표 위에 한 줄 `--fs-sm --muted` `완료(정산) · 견적 줄이 잠김` | 〃 |

머리글 바탕은 "이 사람이 이 표에서 편집할 수 있는 셀이 하나라도 있는가"로 정한다 — 있으면 `--g-100` + `--g-950`(편집 가능 신호), 없으면 흰 바탕(읽기용 표). 완료 프로젝트를 보는 PM은 흰 바탕, 같은 화면을 보는 경영관리는 `--g-100`(「견적 외 비용 줄 추가」가 가능하므로)이다. 사람마다 다르고 화면 안에서 바뀌지 않는다. 편집 가능한 셀이 하나도 없는 표는 `role="grid"`가 아니라 `<table>` + 시각적으로 숨긴 `<caption>`으로 렌더한다(§10). **이것은 모드 토글이 아니다** — 위 §7-3 본문의 「읽기 모드와 편집 모드를 나누지 않는다」는 그대로다. 이 절은 사용자가 켜고 끄는 모드가 아니라 **편집 가능한 셀 수가 0일 때 컴포넌트가 자동으로 취하는 렌더 형태**이고, 그 판정은 서버가 보낸 셀 단계에서 파생된다.

**(나) 줄 버전 충돌(D-65)**

각 줄은 `version`을 함께 받고 함께 보낸다. 저장 요청이 읽은 버전과 다르면 그 줄에서 실제로 값이 달라진 셀만 오류 셀과 같은 모양으로 고정하고, 이유 한 줄에 실제 바뀐 값·사람·시각을 적는다: `다른 사람이 14:01에 9,800,000으로 바꿈 · 덮어쓰기 / 그 값으로`. 두 다음 한 수는 3차 버튼이다. 충돌이 하나라도 있으면 「전부 저장 또는 전부 거부」대로 배치 전체를 거부하고 합계 행에 `충돌 1줄 · 전부 거부`. 다른 셀의 편집값은 그대로 남는다.

**(다) 붙여넣기 정규화(D-67)**

클립보드 `text/plain`을 TSV로 읽는다(행 `\n`, 칸 `\t`). 활성 셀에서 오른쪽·아래로 채운다. 숫자 열은 쉼표·공백·통화 기호를 지우고 숫자로 읽는다 — 그래도 숫자가 아니면 그 셀을 오류 셀로 고정한다(조용히 버리지 않는다). 문자 열은 그대로, 앞뒤 공백만 지운다. 읽기 전용·잠김 셀에 값이 떨어지면 건너뛰지 않고 오류 셀로 표시한다. 아래를 넘으면 새 줄 자동, 오른쪽을 넘는 칸은 버리고 합계 행에 `붙여넣기 · 오른쪽 2칸 버림`(`--warning`)을 남긴다. ⌘C 범위 복사도 같은 TSV를 클립보드에 써서 다른 프로젝트의 표에서 그대로 붙는다.

**(라) 줄 순서와 그룹 머리글(D-62·D-63)**

그룹 머리글 = 대분류. 줄의 소분류 열 값에서 파생되고 그룹 순서는 코드표 `sort_order`다 — 대분류 열을 따로 두지 않는다. 그룹 머리글 행은 편집 대상이 아니고 포커스를 받지 않는다(방향키가 건너뛴다). 그룹 안에서 만든 새 줄(⌘↵)은 그 그룹의 대분류를 물려받는다. 줄 이동은 `Alt+↑`/`Alt+↓`. 줄 순서는 입력 순서 값으로 저장한다(정렬이 아니라 값이다).

**(마) 미저장 편집 복원(D-68)**

dirty 셀이 하나라도 있으면 `beforeunload`로 이탈을 경고한다. 편집은 브라우저 저장소에 임시 보관한다(키는 프로젝트 id + 차수 id). 다시 열었을 때 보관된 편집이 있으면 표 위 한 줄로 알린다: `저장 안 한 편집 3칸 · 복원 / 버림`. §7-11 배너가 아니다 — 한 표에 붙은 상태다.

**(바) 폰 행 시트(D-69)**

§7-8 시트 골격. 머리 = 항목명(`--fs-lg`) + 부제 `{소분류} · {거래처}`. 본문 = `KvList`로 접힌 P2·P3 전부. **행동 줄을 두지 않는다 — 보기 전용이다.** 폰에서 셀 편집은 없다(§6-2).

**(사) 저장 범위와 1차 버튼**

화면의 1차 버튼 「일괄 저장 ⌘S N」 하나가 그 화면의 모든 편집 표 + 표 밖의 편집 칸의 dirty를 한 트랜잭션으로 저장한다. `N` = 화면 전체 dirty 칸 수. 저장 범위는 「이 화면에서 고칠 수 있는 것 전부」이지 「표」가 아니다 — 표 밖에 편집 칸이 하나라도 있으면 그 칸도 같은 1차 버튼·같은 트랜잭션에 들어간다. 결과는 고친 자리에 붙는다(표의 dirty는 그 표의 합계 행에, 표 밖 칸의 dirty는 그 칸 자리에). 오류·충돌이 한 칸이라도 있으면 화면 전체가 거부된다. 표가 여럿이어도 저장 자리는 하나다.

**(아) `role="grid"` 키보드 계약(§10 보강)**

표 전체가 탭 정지 1개. 안에서는 방향키 로빙 `tabindex`로 움직인다. `Esc`: 편집 중이면 그 셀 값을 되돌리고, 편집 중이 아니면 범위 선택을 해제한다. `Delete`: 줄 삭제 확인 모달. 오류·충돌 셀은 `aria-invalid="true"` + `aria-describedby`로 이유 줄을 가리킨다. 합계 행의 저장 결과는 `aria-live="polite"`. 힌트 줄(§7-9, 최대 7개)은 화면마다 실제로 되는 것만 적는다.

### 7-4. 「내 차례」 목록

- 역할별 첫 화면 최상단. 위 `2px --line-strong`, 항목 사이 `1px dotted --line`. 최대 **6줄**, 넘으면 `더 보기 4건` 3차 버튼
- 한 줄 = `[태그] 대상 — 상황(이유)  금액  다음 한 수(3차 버튼)`. 이유와 다음 한 수는 **반드시 같은 줄**에 있다(브리프 검증 질문 1)
- 태그(§7-5) 순서 고정: 막힘(`--danger`) → 오늘(`--warning`) → 결재(`--accent`) → 대기(`--accent`)
- 폰: 두 줄(1행 태그·대상·행동, 2행 금액·이유)
- 항목이 0이면 이 블록은 **사라진다**. 「할 일이 없습니다」를 쓰지 않는다. 대신 목록 화면이 위로 올라온다

### 7-5. 상태 태그

- `--fs-xs` 600, `1px solid currentColor`, 패딩 `1px 6px`, radius 0, 배경 없음. 색은 의미 토큰 하나: `--danger`(막힘·증빙 없음·반려) · `--warning`(오늘·마감 임박) · `--accent`(내 차례·결재 중·편집 중) · `--success`(승인·연결·저장됨) · `--muted`(대기·미착수·임시)
- 표 상태 열에서는 태그 대신 **색 글자만**(`--fs-xs` 600). 테두리 태그는 「내 차례」와 화면 제목 옆에서만
- 태그 글자는 두 글자~네 글자 명사: `막힘` `오늘` `결재` `대기` `승인` `반려` `편집 중`. 문장 금지
- **(Phase 4 보강) 의미 목록에 낱말 다섯을 더한다**: `진행`→`--accent` · 차수 `현재`→`--accent` · `완료(정산)`→`--success` · `미수주`→`--muted` · 견적 줄 `취소`→`--muted`. `--accent` 예약 ①(내 차례 태그·행동)이 이 다섯 중 `진행`·`현재`(상태 태그)를 덮는 근거다 — §1-3 ①의 「태그」가 상태 태그 전반을 가리킨다
- **길이 규칙**: 업무 용어로 잠긴 상태 값은 네 글자 명사 + 괄호 한정어 하나를 허용한다(괄호 안 두 글자, 문장 금지는 유지). `완료(정산)`이 이 규칙의 대상이다(D-41·ROADMAP Phase 4 성공 기준 4가 잠근 업무 용어이지 예외가 아니다)

### 7-6. 토스트

- 화면 하단 왼쪽(폰은 하단 탭 위), `--bg` 면 + `2px --line-strong` 테두리, `--fs-sm`, 최대 1개. 4초 뒤 사라짐, 오류는 닫을 때까지
- 내용 = **버튼과 같은 단어 + 결과**: `일괄 저장 · 6줄 저장됨` `제출 · 결재 요청됨 → 김팀장`. 실행 취소가 가능하면 3차 버튼 `되돌리기`
- 표 저장 결과는 토스트를 띄우지 않는다(합계 행에 이미 있다). 화면 이동이 따르는 행동(제출·승인)만 토스트

### 7-7. 다섯 상태 (LOADING · EMPTY · ERROR · SUCCESS · PARTIAL)

| 상태 | 모양 | 규칙 |
|---|---|---|
| LOADING | 상단 바 아래 `2px --accent` 진행 바 + 표는 머리글·합계 행 뼈대만 그리고 본문 자리는 `--surface` 행 3개(반짝임 없음) | 스피너·스켈레톤 애니메이션 없음. 300ms 안에 끝나면 아무것도 보이지 않게(지연 표시) |
| EMPTY | 표 본문 자리에 한 줄: **「무엇이 없다 · 다음 한 수」** `--fs-base --muted` + 3차 버튼. 그림·일러스트 없음 | 예: `이 프로젝트에 견적 줄이 없습니다 · 첫 줄 만들기 ⌘↵` / `결재할 건이 없습니다 · 지출결의 목록 보기`. **「내 차례」가 비면 블록 자체가 없다**(§7-4). 필터 결과 0은 `조건에 맞는 건이 없습니다 · 필터 지우기` |
| ERROR | 표 본문 자리 또는 폼 상단에 한 줄 `--danger`: **「무엇이 안 됐다 · 다음 행동」** + 2차 버튼 `다시 시도` | 사과 문구 없음. 입력값은 보존. 예: `저장하지 못했습니다 · 네트워크 · 다시 시도` |
| SUCCESS | 행동한 자리에서 결과가 보인다: 합계 행 `저장됨 6줄`, 제출 버튼 자리에 `결재 요청됨 → 김팀장` | 성공 화면·체크 아이콘·확인 모달 없음 |
| PARTIAL | 일부만 보이거나 계산되지 않은 상태: `계산 불가 1건`처럼 건수 배지(`--fs-xs --muted` 테두리 태그) + 합계는 계산된 것만 | 빈 자리를 0으로 채우지 않는다 |

### 7-8. 모달 · 시트

실물: `system/sheet-modal.html`(폰 결재 시트 · 반려 확인 시트 · 더보기 시트 · PC 반려 모달). 확정 2026-09-18(`DECISIONS.md` 시트·모달 5건).

- 모달(PC): 폭 480 고정, `--bg` + `2px --line-strong`, 제목 `--fs-lg`(= 실제 동작, `지출결의 반려`) + 부제 `--fs-sm --muted`(문서 한 줄), 하단 오른쪽에 2차 「취소 Esc」 + 1차 행동 「반려 ⌘↵」. 위험 행동 확인에만 쓴다(삭제·반려·덮어쓰기). 폼을 모달에 넣지 않는다 — 폼은 화면이다. **예외 하나: 확인의 근거인 「사유」 한 칸**은 모달·시트 안에 둔다. 사유가 비면 1차 버튼 비활성 + 왼쪽에 `사유 없음 · 한 줄 적어 주세요`(§7-1). 결과는 입력 아래 한 줄 `--fs-sm --muted`(`기안자 박서연에게 돌아갑니다 · 내 차례에서 사라집니다`)
- 시트(폰): 하단에서 올라옴, 높이 내용 따라 최대 85vh, 위 `2px --line-strong`, 머리(제목 `--fs-lg` + 부제 + 닫기 x 20)·행동 줄은 고정하고 본문만 스크롤. 표 행의 상세·행동, 메뉴(≡)에 쓴다. **폰의 위험 행동 확인도 시트**다(모달과 같은 내용을 시트 골격에)
- 시트 상세 = 라벨 · 값 목록(`dl`): 라벨 `--fs-sm --muted` 600, 폭 폰 84 · PC `--label-w`, 행 사이 점선 `--line`. 표에서 접힌 P2·P3 열이 여기로 내려온다. 값이 두 줄이면 2행 `--fs-sm --muted`(외화 2행과 같은 모양). 첨부는 썸네일 72×96 + 파일명·장수·용량 + 3차 「크게 보기」
- 시트 행동 줄: 버튼 높이 `--touch-min`(44), 1차가 2차의 2배 폭, `--fs-base`. 시트 밖 폰 버튼은 그대로 40(§7-1)
- 「더보기」 시트(§6-0): 첫 항목 검색(`--surface` 면), 하단 탭에 없는 1차 메뉴 + 오른쪽 건수(`진행 12` · `이번 달 41` · `미연결 3`), 권한표에서 view 권한이 있는 관리자 화면이 하나라도 있으면 「관리」 한 줄(§6-10 — 그룹 머리글 없이 목록 행 하나), 「계정」 그룹(내 정보 · 설정 · 로그아웃). 목록 행 44, 아이콘 없음. 검색 행에는 대상 목록(`프로젝트 · 지출결의 · 거래처`)
- 둘 다 `--scrim` 뒤, Esc로 닫힘, 포커스 트랩, 열릴 때 첫 행동 요소에 포커스(승인 / 사유 칸 / 검색), 닫힐 때 원래 요소로 복귀. 아이콘은 닫기(x)만
- **(Phase 4 보강) 2차 라벨이 1차와 겹칠 때**: 위 규칙은 2차를 「취소 Esc」로 고정하지만, **1차 라벨에 「취소」가 들어가면 그 모달·시트의 2차는 「닫기 Esc」로 적는다**(예: 1차 「견적 줄 취소」·「승인 표시 취소」). 그 밖에는 언제나 「취소 Esc」다. 라벨만 바뀌고 동작(Esc · 포커스 복귀 · 아무 일도 일어나지 않음)은 그대로다 — 화면별 예외가 아니라 1차 라벨에서 기계적으로 파생되는 규칙이다

### 7-9. 단축키 힌트 줄 (C에서 흡수)

- 편집용 표가 있는 화면 하단에 **항상** 보인다. `--fs-sm --faint`, 항목 사이 16px, `kbd`는 `--fs-xs` `1px --line`
- 내용은 그 화면에서 실제로 되는 것만, 최대 7개: `이동 Tab ↑↓←→ · 범위 복사 ⌘C / 붙여넣기 ⌘V · 취소 Esc · 새 줄 ⌘↵ · 저장 ⌘S · 지출결의 ⌘E`
- 폰에서는 숨는다(키보드가 없다)
- 명령 팔레트 `⌘K`: 상단 바에 글자로 상시 노출. 열면 검색 입력 하나 + 결과 목록(원장 행 모양). 명령 파서는 만들지 않는다 — 검색과 이동만

### 7-10. 첨부 영역

- `--surface` 면 + `1px dashed --line-ui`, 높이 96(PC)/72(폰). 안의 글자 한 줄 `--fs-sm --muted`: `파일을 끌어 놓거나 ⌘U · 이미지·PDF 10MB`
- 첨부된 파일은 목록 행(파일명 · 크기 · 날짜 · 3차 「삭제」). 썸네일은 이미지일 때 48px 정사각, radius 0
- 폰: 영역 탭 → 카메라/사진/파일 네이티브 선택
- 업로드 중: 행 아래 `2px --accent` 진행 바. 실패: 행이 오류 셀 모양(§7-3)

### 7-11. 배너

- **위치: 화면 제목 위 지역**(전역 아님, D③) — 임시 비밀번호 배너(§6-3/§6-7 이후 내 계정 화면), DB 커넥션 한도 배너(§6-8)가 이 자리를 쓴다
- **지속 시간: 조건이 사라질 때까지**(D①). 닫기 버튼 없음 — 사용자가 배너를 닫아 위험 상태를 잊는 것을 막는다
- 한 화면 **최대 1개**(D②)
- **등급 둘**: **안내**(`role="status"`, 예: 임시 비밀번호 사용 중) · **경고**(`role="alert"`, `--warning`/`--warning-weak`, 예: DB 커넥션 한도 초과)(D④). 색은 §1-2 의미 토큰만 쓴다
- **§7-6 토스트와의 경계**(D⑤): **토스트 = 화면 이동이 따르는 행동의 결과**(일시적, 최대 4초). **배너 = 화면에 걸린 조건**(지속적, 조건이 해소될 때까지). 저장·제출 같은 1회성 행동 결과는 토스트, 임시 비밀번호·한도 초과 같은 상태는 배너
- 다섯 상태:
  - LOADING: **해당 없음** — 배너는 조회가 끝나 조건이 확인된 뒤에만 렌더된다
  - EMPTY: **해당 없음** — 조건이 없으면 배너 자체가 렌더되지 않는다(빈 배너라는 상태는 없다)
  - ERROR: **해당 없음** — 배너 자체가 오류 상태를 갖지 않는다(경고 등급이 표시하는 조건이 오류일 뿐, 배너 컴포넌트의 실패는 아니다)
  - SUCCESS: **해당 없음** — 배너는 조건이 사라지면 사라질 뿐 성공 결과를 표시하지 않는다(그 역할은 §7-6 토스트가 한다)
  - PARTIAL: **해당 없음** — 배너는 단일 조건의 유무만 표시하고 부분 상태를 갖지 않는다

### 7-12. 알림함 · 배지 (계약만 — 구현은 Phase 7)

- **읽음/안 읽음**: 안 읽은 행만 좌측 인셋 선(§7-3 오류 셀 패턴과 같은 시각 언어)(E①)
- **§7-4 「내 차례」와의 차이**(E②): 「내 차례」는 **내가 할 일**(행동 유도, 다음 한 수 버튼 항상 있음), 알림함은 **나에게 일어난 일**(과거형 이벤트 로그, 다음 한 수 버튼 없음)
- **진입점**(E③): **PC는 §6-0 (a) 사용자 메뉴 안의 한 항목**(내 정보·로그아웃과 나란히), **폰은 「더보기」 시트**(§7-8)
- **건수 배지**(E④): **안 읽은 알림 수 하나만** 센다. §7-5 상태 태그 · §7-7 PARTIAL 배지 · §6-0 하단 탭 「내 차례 N」 건수와 **자리를 나눠 쓰고 같은 자리에서 합산하지 않는다** — 넷은 각각 다른 것(상태 · 계산 불가 · 할 일 · 안 읽은 알림)을 센다
- 다섯 상태:
  - LOADING: 목록 자리에 §7-7 표 골격과 같은 `--surface` 뼈대
  - EMPTY: `--muted` 한 줄 `알림이 없습니다`(다음 한 수 없음 — 알림함은 행동을 유도하는 화면이 아니다)
  - ERROR: 목록 자리 `--danger` 한 줄 `불러오지 못했습니다 · 다시 시도`
  - SUCCESS: **해당 없음** — 알림함은 조회 전용이라 행동 결과를 표시하지 않는다(읽음 처리는 인셋 선이 조용히 사라지는 것으로 반영, 별도 성공 표시 없음)
  - PARTIAL: **해당 없음** — 알림 목록은 전부 오거나 오류이거나 둘 중 하나이고 부분 조회 개념이 없다(v1 범위, Phase 7 구현 시 재검토 가능)

### 7-13. 체크박스 매트릭스 (권한표 · 정보 노출표)

§7-3 표와 분리된 별개 컴포넌트다(D-40) — 정적 격자 + 체크박스이며 다행 편집·범위 복사·오류 셀 inset 선 같은 §7-3의 기계장치가 없다. `ui/permission-grid/`에 둔다(두 화면이 재사용, `DESIGN.md` §4 규칙 3 — 새 컴포넌트는 두 곳 이상에서 쓰일 때만).

**구조**
- `<table>` + 시각적으로 숨긴 `<caption>`. `role="grid"`가 **아니다** — 셀 편집이 없어 §7-3의 grid 기계장치(활성 셀·`aria-selected`·`aria-readonly`)가 필요 없다. 행 머리글 `<th scope="row">`(계급 이름), 열 머리글 `<th scope="col">`
- **권한표**: 행 = 계급(시드 5종 + 추가분), 열 = 메뉴 × 동작(보기/쓰기/승인) 2단 머리글 — 1행은 메뉴 이름(`colspan=3`), 2행은 동작 이름. 셀 = 체크박스 1개
- **정보 노출표**: 행 = 계급, 열 = 정보 항목(단일 단 머리글, 그룹 없음). 셀 = 체크박스 1개
- 머리글: `--fs-sm --muted` 600, §7-3의 「편집 가능한 표」 신호를 그대로 물려받아 `--g-100` 바탕 + `--g-950` 글자 — 체크박스 격자도 값을 바꾸는 컨트롤이기 때문이다
- **열이 많아지면(권한표, 메뉴×동작 조합) 가로 스크롤.** 행 머리글(계급 열)은 `position: sticky; left: 0` + 오른쪽 `1px --line-strong` 구분선. 열 머리글은 `position: sticky; top: 0`(정보 노출표는 항목 수가 늘면 세로 스크롤도 생기므로 함께 필요). 두 sticky가 겹치는 좌상단 모서리 셀은 `--g-100`으로 채워 배경이 끊기지 않게 한다
- 세로선 없음(§4-2). 메뉴 그룹 경계만 `1px --line`으로 표시

**체크박스**
- 네이티브 `<input type="checkbox">`. `accent-color`는 §4-4의 `--native-accent` — §1-3의 「포인트 색 다섯 곳」 규칙과는 **별개**이며 여섯 번째 accent 사용처를 추가하는 것이 아니다
- 터치 목표: 체크박스를 감싸는 `<td>`의 클릭 영역을 PC 32×32 · 폰 44×44로 채운다(§3). 셀 전체가 클릭 가능
- 화면에 텍스트 라벨을 두지 않는다(격자 좌표가 라벨이다) — 대신 `aria-label="{계급} · {메뉴} · {동작}"`(권한표) / `aria-label="{계급} · {정보 항목}"`(정보 노출표)로 접근성 트리에 좌표를 문장으로 만든다

**전체 · 행 · 열 선택**
- 열 머리글에 체크박스 하나 — 그 열 전체를 켜고 끈다. 값이 섞여 있으면 네이티브 `indeterminate`(중간 상태)로 보인다
- **행(계급) 단위 전체 선택은 두지 않는다.** 계급 하나에 딸린 모든 항목을 한 번에 켜는 것은 실수로 광범위한 권한을 부여하는 사고 위험이 크고, 열 단위 선택으로 이미 대량 변경이 가능하다(YAGNI)
- 열 머리글 체크박스 클릭 = 그 열의 모든 셀에 개별 저장 호출을 순차로 보낸다(배치 API 없음 — 이 페이즈의 액션은 셀 단위 하나뿐, D-38)

**저장 시점과 피드백**
- **셀 하나 = 즉시 저장.** 클릭하면 체크 상태가 먼저 바뀌고(낙관적) 서버 호출이 뒤따른다. 「일괄 저장」 버튼이 없다 — 성공 기준 2(「바꾸면 즉시 메뉴·동작·응답 필드가 바뀐다」)가 이것을 요구한다
- 성공: **체크 상태 자체가 결과다.** 별도 토스트·완료 표시 없음(§7-1 SUCCESS 「행동한 자리에서 결과가 보인다」와 같은 논리)
- 300ms 넘게 걸리면 그 셀만 `--surface` 배경으로 지연 표시(§7-7 LOADING 지연 규칙), 짧으면 아무것도 보이지 않는다
- 실패: 체크 상태를 원래 값으로 되돌리고(낙관적 되돌림) 그 셀에 `1px --danger` 테두리 + hover/focus 시 이유 한 줄(§7-2와 같은 자리, 「원인 · 다음 행동」: `저장하지 못했습니다 · 다시 시도`) + **§7-6 토스트**로도 같은 메시지(`권한 저장 실패 · 다시 시도`) — 화면을 안 보고 있어도 알아야 하는 드문 실패라 토스트를 쓴다(§7-3 「표 저장 결과는 토스트 없음」의 예외 — 이 격자는 합계 행이 없어 결과를 모아 보여줄 자리가 없다)
- 열 머리글 일괄 토글 중 일부만 실패하면(PARTIAL) 실패한 셀만 원위치 + 오류 표시, 나머지는 성공 상태 유지, 토스트는 한 번(`권한 저장 · N칸 중 M칸 실패 · 다시 시도`)

**다섯 상태**

| 상태 | 모양 |
|---|---|
| LOADING | 머리글 뼈대 + `--surface` 행 3개(§7-7과 같음) |
| EMPTY | **해당 없음** — 계급은 시드 5종이 항상 있고(ADMN-08) 메뉴·정보 항목도 코드 레지스트리 시드가 항상 있다. 빈 격자가 되는 경우가 없다 |
| ERROR | 격자 자리에 한 줄 `--danger`: `권한표를 불러오지 못했습니다 · 다시 시도`(정보 노출표는 같은 문구를 그 이름으로) |
| SUCCESS | **해당 없음** — 「저장 시점과 피드백」대로 체크 상태 자체가 결과이고 별도 SUCCESS 표시가 없다 |
| PARTIAL | 열 일괄 토글 중 일부 실패(위) 또는 계급별로 서버가 아예 안 보낸 열(정보 노출표가 자기 자신에게 적용될 때 — §7-3 「칸 수 가변」 규칙과 같은 논리, 서버가 안 보낸 열은 클라이언트가 숨기지 않고 처음부터 없다) |

**키보드 · 스크린리더**
- 별도 방향키 로빙 없음 — 네이티브 `<table>` + 체크박스이므로 `Tab`/`Shift+Tab`이 DOM 순서(행 우선, 왼쪽→오른쪽)대로 이동하는 것으로 충분하다(§7-3의 `role="grid"` 방향키 기계장치를 다시 만들지 않는다 — D-40의 취지)
- `Space`로 체크 토글(네이티브 동작)
- 스크린리더 읽기 순서는 DOM 순서와 같다: 계급 행 진입 시 `<th scope="row">`가 먼저 읽히고, 각 체크박스는 `aria-label`로 메뉴·동작(또는 정보 항목)을 반복해 말한다 — 좌표를 시각적 위치가 아니라 문장으로 전달한다
- 열 머리글 체크박스의 `aria-label`: `"{메뉴} · {동작} 전체 선택"`(권한표) / `"{정보 항목} 전체 선택"`(정보 노출표)

**폰(375px)**
- 격자를 그대로 그리지 않는다(가로 스크롤 금지 원칙은 §7-3과 같다 — 이 컴포넌트는 §7-3이 아니지만 같은 원칙을 물려받는다). 대신 **선택→목록**으로 축을 접는다: 화면 위에 계급을 고르는 네이티브 `<select>`(§7-2) 하나, 그 아래 선택된 계급의 항목을 §7-8 「시트 상세」와 같은 `dl` 골격(`KvList` 재사용 — 라벨 = 메뉴·동작 또는 정보 항목, 값 자리에 체크박스, 터치 44×44)으로 세로 나열
- 이 화면은 관리자 전용 설정 화면이라(ADMN-01/02, 관리자 운영 콘솔) PC 사용이 기본이고 폰은 확인·긴급 수정용이다 — 위 대안은 그 용도로 충분하다(모든 조합을 폰에서 빠르게 편집하는 것을 목표로 하지 않는다)

### 7-14. 이력 목록 (이력형 설정 값 · 발령일 이력)

두 곳에서 재사용된다: 설정 레지스트리의 이력형 키(예: 부가세율)와 사람 폼의 팀 소속
발령일 이력(MAST-02) — 두 곳 이상에서 쓰이므로 정식 컴포넌트로 둔다(`ui/history-list/`).

**구조**
- §6-3 폼 화면의 한 섹션(2px 선으로 시작)에 §6-1 목록과 같은 얇은 표: 열 = 적용
  시작일 · 값 · 상태 · (동작). 적용 시작일 내림차순(최신이 위)
- 오늘 기준으로 유효한 행(가장 최근의 「적용 시작일 ≤ 오늘」인 행)에 §7-5 상태 태그
  `적용 중`(`--success`, text 변형 — 표 안이므로). 미래로 예정된 행은
  `예정`(`--muted`)
- 각 행 값은 레지스트리 스키마 타입에 따라 §7-2 「자동 생성 설정 화면 필드 렌더
  규칙」과 같은 매핑으로 렌더한다 — 읽기 전용 텍스트, 입력이 아니다
- **추가는 새 행, 수정은 없다.** 「새 이력 추가」 3차 버튼이 폼 하단에 열리고(모달
  아니다 — §7-8 모달은 위험 행동 확인용이라 이 목적에 맞지 않는다) 적용
  시작일(날짜 입력) + 값(타입별 §7-2 입력) 두 칸을 이 표의 맨 위 행 자리에 편집
  가능한 행으로 펼친다. 저장하면 새 행이 되고 취소(Esc)하면 사라진다
- **미래로 예정된(`예정`) 행만 취소할 수 있다.** 3차 「취소」 버튼 + §7-8 확인
  모달(사유 불필요 — 아직 적용되지 않은 예정값을 지우는 것은 되돌릴 수 있는
  일이다). 이미 적용된(`적용 중` 또는 과거) 행은 동작 칸이 비어 있다 — 이력은
  append-only다(행동 로그·보관함과 같은 감사 원칙)
- 이력 목록이 1건일 때와 N건일 때 같은 행 템플릿을 쓴다 — append-only라 과거 행이
  사라지지 않는다

**다섯 상태**

| 상태 | 모양 |
|---|---|
| LOADING | 행 3개 `--surface` 뼈대 |
| EMPTY | `이 값의 이력이 없습니다 · 새 이력 추가`(다음 한 수 포함) — 대부분 시드가 항상 1행 있어 드문 경우다 |
| ERROR | `이력을 불러오지 못했습니다 · 다시 시도` |
| SUCCESS | 새 행 추가 성공 시 그 행이 목록에 나타나는 것 자체가 결과(§7-7 표 SUCCESS와 같은 논리), 토스트 없음 |
| PARTIAL | **해당 없음** — 이력 목록은 전부 오거나 오류이거나 둘 중 하나다 |

### 7-15. 폼 (`ui/form` · `ui/select`) — 신설 (Phase 4)

§6-3이 폼 **화면**의 레이아웃이고 §7-2가 **입력 하나**의 규칙이라면, 이 절은 그 둘을 잇는 **컴포넌트 계약**이다. Phase 4가 만들고(사용처 둘 — 프로젝트 등록 폼 · 매출 계약 금액 칸) **Phase 7**이 관리자 폼 8개와 `/account`를 이 계약으로 이관한다(03-OPEN-ITEMS A-H2·A-H3).

**구성**

- `Form` — `<form noValidate>` + 한 열, `max-width: var(--form-max)`(720), 왼쪽 정렬. 항목 사이 `--s-4`, 묶음 사이 `--s-6` + `1px --line`
- `Form.Field` — 라벨 열(PC `--label-w` 96, `--fs-sm --muted` 600) + 컨트롤. 폰(<700px)에서 라벨이 위로 올라가고 컨트롤은 전폭
- 칸 폭 **3종만**: select 200 · 짧은 칸(금액·날짜·수량·환율) 280 · 긴 칸(이름·비고) 480
- `Form.Hint` — 컨트롤 바로 아래 한 줄 `--fs-sm --muted`, 숫자만 700. 서버 계산 값의 자리(§6-3). 읽기 전용 행을 따로 두지 않는다
- `Form.Error` — 컨트롤 아래 한 줄 `--fs-sm --danger` 「원인 · 다음 행동」. 컨트롤의 `aria-describedby`가 이 줄을 가리킨다
- `Form.Actions` — 폼 맨 아래 한 줄: 1차(제출) + 옆에 막힘 이유(`--fs-sm --danger`) + 다음 한 수 3차, 오른쪽 끝에 2차. 1차 버튼의 `aria-describedby`가 이유를 가리킨다(`role="alert"`가 아니다 — 누르기 전에 읽혀야 한다, §10)
- **`Form.Actions`는 폼이 자기 제출을 가질 때만 둔다.** `Form.Actions`는 1차 버튼을 데려오므로, 이미 1차를 가진 화면 안에 섞여 들어간 칸에 이것을 두면 한 화면에 1차가 둘이 된다(§7-1 「한 화면에 1개」). 그런 칸은 `Form.Field` + `Form.Hint`/`Form.Error`만 쓰고 **`Form.Actions` 없는 단일 칸 폼**으로 렌더한다 — 제출은 그 화면의 1차 「일괄 저장 ⌘S N」 하나이고, 칸이 dirty면 `N`에 1칸으로 합류해 §7-3 「전부 저장 또는 전부 거부」에 같이 걸린다(위 (사)). `<form>` 요소는 그대로 두되 `Enter` 기본 제출을 막고 ⌘S에 맡긴다. 이것은 화면별 예외가 아니라 §7-15의 일반 규칙이다 — 「이 칸의 저장은 누구 책임인가」를 폼이 아니라 화면이 답한다
- `Select` — 네이티브 `<select>` + 시스템 테두리(§7-2). 커스텀 드롭다운을 만들지 않는다. 고를 것이 없으면 첫 옵션이 `—`이고 제출이 막히며 이유는 `Form.Actions`에 쓴다
- 자동으로 채워진 칸은 입력이 아니라 텍스트 + 「바꾸기」 3차 버튼(§6-3)

**검증 관문은 서버 하나**(A-H3 해소)

- 네이티브 `required`·`pattern`·`type="number"` **검증 위임을 걷어낸다.** 브라우저 기본 말풍선(영문·시스템 서체)이 §7-2의 「원인 · 다음 행동」을 가로채기 때문이다. `noValidate`를 `<form>`에 둔다
- 필수 표시 `*`를 두지 않는다(§7-2). 필수인데 비면 **제출 버튼이 이유를 말한다**: `등록할 수 없음 — 클라이언트 · 담당 PM 2칸 · 클라이언트 고르기`
- 서버가 돌려준 필드 오류는 해당 `Form.Error`에, 폼 전체 오류는 `Form.Actions`의 이유 자리에. **폼 상단 오류 상자를 두지 않는다**(§7-7 폼 행 "상단 한 줄 없음")
- 입력값은 오류 뒤에도 남는다(UX-04)

**다섯 상태**

| 상태 | 모양 |
|---|---|
| LOADING | **해당 없음** — 서버 컴포넌트가 기본값을 채워 렌더한다. 제출 중은 §7-1 버튼 규칙(라벨 뒤 `…`, 같은 폼의 다른 버튼도 비활성, 300ms 넘으면 상단 2px 진행 바) |
| EMPTY | **해당 없음** — 폼은 항상 칸이 있다 |
| ERROR | 위 「검증 관문」 |
| SUCCESS | 화면이 바뀌는 폼(등록 → 상세)은 이동 + §7-6 토스트. 화면이 그대로인 폼은 버튼 자리에 결과 텍스트, 입력은 읽기 전용 |
| PARTIAL | 제출 버튼 비활성 + 옆에 `…할 수 없음 — 이유 · 다음 한 수`(§6-3·UX-06) |

## 8. 카피 규칙

1. **버튼 = 실제 동작.** `제출` `확인` `저장` 단독 금지. `지출결의 제출` `일괄 저장 3` `증빙 올리기` `복사해 새 차수`
2. **토스트·결과 = 버튼과 같은 단어.** 버튼이 「일괄 저장」이면 결과는 「일괄 저장 · 6줄 저장됨」. 다른 동사로 바꿔 말하지 않는다
3. **오류 = 원인 · 다음 행동.** 가운뎃점으로 나눈 한 줄. `증빙 없음 · 증빙 올리기` `날짜 형식이 아닙니다 · 2026-09-18처럼`. 원인만 쓰고 끝내지 않는다
4. **사과·감탄·이모지·느낌표 없음.** 「죄송합니다」「성공했습니다!」 금지. `저장됨` `제출됨` `결재 요청됨`
5. **안내 문구 없음(UX-06).** 「이 화면에서는 …할 수 있습니다」류 설명을 두지 않는다. 다음 한 수를 버튼으로 보인다
6. 문장은 **명사형 종결** 우선(`저장됨` `증빙 14일 경과`). 외부 수령자 화면과 오류의 「다음 행동」만 `~해 주세요`체 허용
7. 용어는 앱 전체에서 하나: 지출결의(결의서 X) · 견적 줄(항목 X) · 실행가(원가 X) · 증빙(첨부 X) · 결재(승인 요청 X) · 지급 예정일 · 법인카드 사용 · 기타소득 확인증. 용어표는 `.planning/research/ERP260907-CONTEXT.md`의 업무 용어를 따른다
8. 숫자 앞에 「총」「약」을 붙이지 않는다. 합계 행이 합계다
9. 대소문자: 라틴 고유명사만 원문대로(`USD` `QR` `PDF`). 영문 버튼·라벨 없음

## 9. 아이콘

- 세트 **Lucide 하나**. 패키지 의존 없이 필요한 아이콘의 SVG를 `components/icons/`에 인라인으로 복사한다(ISC). 다른 세트와 섞지 않는다
- 크기 2단계: **16**(표·목록·버튼 안) · **20**(폰 하단 탭·시트 제목). `stroke-width: 1.75` 고정, `currentColor`
- 쓰는 곳은 **의미가 글자보다 빠른 곳만**: 첨부(paperclip) · 검색(search) · 닫기(x) · 메뉴(menu) · 정렬 방향(arrow-up/down) · 외부 링크(external-link) · 인쇄(printer). 상태·의미를 아이콘으로 전달하지 않는다 — 상태는 글자다
- 아이콘 단독 버튼은 `aria-label` 필수. 폰 하단 탭은 아이콘 없이 글자만
- 장식 아이콘(제목 옆, EMPTY 일러스트, 성공 체크) 금지

## 10. 접근성 계약

- 랜드마크: `<header>`(상단 바) · `<nav aria-label="주 메뉴">` · `<main>` · 폰 `<nav aria-label="하단 탭">`. 첫 포커스 요소는 「본문으로 건너뛰기」 스킵 링크(포커스 시에만 보임, 1차 버튼 모양)
- 표: 읽기용은 `<table>` + `<caption>`(시각적으로 숨김). 편집용은 `role="grid"`, 셀 `role="gridcell"`, 활성 셀 `aria-selected`, 편집 중 `aria-readonly="false"`. 오류 셀 `aria-invalid="true"` + `aria-describedby`로 이유 연결
- 실시간 알림: 합계 행의 저장 결과와 토스트는 `aria-live="polite"`, 제출 불가 이유는 `role="alert"`가 아니라 버튼의 `aria-describedby`(사용자가 누르기 전에 읽힌다)
- 색은 의미의 유일한 매체가 아니다: 상태는 항상 **글자**(태그·상태 열)다. 오류 셀은 배경 + 좌측 선 + 이유 텍스트 셋
- 포커스 순서 = 시각 순서. 모달·시트는 포커스 트랩 + Esc + 닫힐 때 원래 요소로 복귀
- 아이콘 단독 버튼 `aria-label`. 3차 버튼은 `<button>`(페이지 이동이면 `<a>`)
- 터치 목표 폰 44×44. PC 32px 컨트롤은 마우스·키보드 전용 화면이라 허용
- 표 셀 본문 14px(폰 15px)는 업무 표의 밀도를 위한 의도적 선택이다. 산문·외부 수령자 화면은 15px 이상
- 확대 200%에서 PC 레이아웃이 폰 레이아웃으로 자연히 전환된다(브레이크포인트가 px라서). 가로 스크롤 금지 규칙이 여기서도 지켜진다
