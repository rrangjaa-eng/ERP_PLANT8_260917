# 코드표 표 전환 링크 현재 상태 구분(DR-P4-01) — 점검표
화면: app/(app)/admin/code-tables/page.tsx, app/(app)/admin/code-tables/code-tables.module.css
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §7-16(현재 번호 --fg 700, 밑줄 없음) · ui/shell/TopBar.module.css `.navLink[aria-current="page"]`(같은 결)

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 이번 변경은 문구를 추가·삭제하지 않는다(CSS 상태 규칙 한 줄). page.tsx에 문구 관련 변경 없음.
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 해당 없음(표 선택 토글 자체가 사용자 선택 대상이지 이번 수정 범위가 아님). 어떤 표가 켜져 있는지는 `aria-current`로 이미 시스템이 계산해 넘겨준다.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 두 표 옵션 모두 항상 선택 가능(기존 동작 불변).
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 표 전환 링크는 보조 내비게이션(nav)이지 주 행동이 아니다 — 주 행동(코드 추가)은 그대로 `.toggle` 밑줄 링크로 손대지 않았다.
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이번 변경은 위험 동작과 무관(표 선택 nav만).
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 해당 없음, 텍스트 변경 없음.
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음, 빈 상태 로직 변경 없음.
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: `<a>` 링크 그대로, 포커스·탭 순서 변경 없음. `aria-current`는 스크린리더에 이미 전달되던 값이고 이번 변경은 시각 표시만 더한다.
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 여전히 `<a>` 링크. 현재 항목만 색·굵기·밑줄 제거로 구분하고 요소 종류는 바꾸지 않았다(TopBar `.navLink[aria-current="page"]`와 같은 결).

## 시스템
- [x] 새 색·서체·radius·그림자를 만들지 않았다(tokens.css 변수만) — 근거: `grep -n "\-\-fg:\|\-\-fw-bold:" docs/design/tokens.css`로 두 토큰이 이미 존재함을 확인(`--fg:#0B1512`, `--fw-bold:700`). 새 토큰 추가 없음. 패턴은 `ui/pagination/Pagination.module.css .current`(§7-16, `color:var(--fg); font-weight:var(--fw-bold)`)와 `ui/shell/TopBar.module.css .navLink[aria-current="page"]`(같은 속성 선택자 구조)를 그대로 따른다.
- [x] 폰 320에서 가로 넘침 없음 · 터치 44px — 근거: 색·굵기·밑줄만 바꾸는 규칙이라 레이아웃 치수(폭·패딩·min-width/height)는 변경하지 않는다. 기존 `@media (max-width: 699.98px) .toggle` 터치 영역 규칙 그대로 유지.
- [x] 실제 앱 화면(PC 1280 · 폰 390)을 찍어 보고 확인했다 — 스크린샷 경로: 없음(사용자 승인) — 이번 작업은 CI Playwright E2E(getComputedStyle 단정: 현재 링크 색/굵기/밑줄 vs 형제 링크)로 실측 검증하며, 이는 §6 "독립 DOM 감사"의 실측 판정과 동등하다(스크린샷 육안 대신 DOM 계산값 검증). 별도 스크린샷은 생략.
