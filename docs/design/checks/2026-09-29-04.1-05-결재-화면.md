## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 시트 · 문서 화면에 설명문 없음. 새 글자는 반려 막힘(도메인 상수 `사유 없음 · 사유 적기` · `사유 500자 넘음 · 줄여 적기`) · 회수 결과 줄(되돌릴 수 없는 일 — `결재 멈춤 · {담당}의 결재함에서 빠짐`) · 동시 처리 거부 한 줄(서버 문구)뿐 — error-copy-noun-style 테스트 통과
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 잔고와 결재선 담당은 서버가 계산해 보인다. 승인은 입력 없이 한 번. 다시 신청 폼은 반려된 문서 값으로 채워져 열린다(E2E toHaveValue)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 시트 · 문서 화면 행동 줄은 서버 가능 행동 목록만 그린다(담당 = 승인 + 반려, 기안자이면서 담당 = 승인 + 회수, 기안자 = 회수, 반려된 기안자 = 다시 신청 폼). PC 행은 승인 · 반려만. 빈 사유면 1차 반려 aria-disabled. 제출 중 나머지 버튼 aria-disabled(T7 E2E)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 시트 1차 `승인`(첫 포커스) · 문서 화면 1차 `승인 Ctrl+Enter` 또는 `연차 다시 신청` · 확인 모달 1차 `반려`/`회수` 하나. 기안자 · 결재 중은 1차 없이 2차 `회수`만(UI-SPEC S3)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 반려 · 회수는 2차(문서 화면 행동 줄 오른쪽 끝)이고 ui/confirm-dialog 확인을 거친다. PC 행 승인↔반려 --s-4 · coarse 44. 붉은 버튼 없음(§7-1 — 반려 · 회수는 확인으로 구분)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 잔고 행이 있으면 `일수` 행 없음 · 시트 안 `이번 신청` 1회(E2E 단언). `내 결재` 행 상태 칸 비움. 동시 처리 한 줄은 서버 문구 끝 `새로 고침`을 버튼으로 바꿔 두 번 쓰지 않는다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 결재함 EMPTY는 04.1-02 그대로(`연차 목록 보기`) — 이번 변경 없음
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 행 탭 대상이 button · 링크(Tab 도달, Enter), 시트 · 확인은 네이티브 dialog(포커스 트랩 · Esc · 닫히면 트리거로 복귀 — E2E toBeFocused), 문서 화면 승인 Ctrl+Enter · 반려 확인 Ctrl+Enter(E2E)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 이동(처리함 행 · PC 문서 칸)은 링크, 시트 열기(폰 내 결재 행)는 button + aria-haspopup="dialog"
