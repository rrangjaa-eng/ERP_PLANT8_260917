지금 화면(고치기 전): 결재 시트는 반려 왼쪽·승인 오른쪽인데 사이 12px, 문서 화면 폰 행동 줄은 승인 왼쪽·반려 오른쪽 · 12px. 다시 신청 모드의 결재선 한 줄이 폼 밖(행동 줄 여백 뒤)에 있어 폰 375에서 43px가 고정 행동 줄에 가림(DOM 감사 blocker).

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 이번 수정은 글자를 더하거나 빼지 않았다(CSS 순서·간격과 결재선 자리만 — diff에 문구 변경 없음)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 입력 칸·기본값 변경 없음, 결재선은 서버가 계산한 그대로 그린다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 서버 가능 행동(actions) 그대로 버튼을 그리는 규칙 불변
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 시트·문서 화면 모두 1차 `승인` 하나, 다시 신청 모드 1차 `연차 다시 신청` 하나(E2E mobile-leave-approval · leave-list 다시 신청 사례 통과)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 반려↔승인 사이를 --s-4(16px)로 넓혔고 E2E가 두 화면 모두 간격 ≥ 16을 잰다(mobile-leave-approval 「반려가 왼쪽」 사례)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 결재선은 `결재선` 라벨 행 하나로만 나온다(폼 밖 중복 렌더 제거)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 변경 없음(해당 없음)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: PC는 DOM·시각 순서 모두 1차 먼저 그대로, 폰만 CSS order로 자리 교체(Ctrl+Enter 승인·Tab 순서 불변, leave-document E2E 통과)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 폰 결재 행동 줄 두 곳이 같은 순서·간격 규칙 하나(SYSTEM §7-8)
