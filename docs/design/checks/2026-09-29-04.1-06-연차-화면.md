# 04.1-06 연차 화면(계정 그룹 「연차」 · 연차 목록 · 신청 폼 · 관리자 사람 상세 연차 섹션) — 점검표

기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §6-0 · §6-1 · §6-3 · §7-8 · §7-15 · §8

변경 범위(이 커밋까지): A4 개정(DECISIONS.md → SYSTEM.md §6-1 · §6-3) · A1 개정(DECISIONS.md → SYSTEM.md §6-0 (a) · 「더보기」 시트 · §7-8)과 `ui/shell/role-menu.ts` 계정 그룹 「연차」(같은 커밋). 목록 · 폼 · 사람 상세 화면은 이 점검표의 「화면:」 줄을 늘려 그 화면 기준으로 다시 확인한다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 계정 그룹에 더한 것은 항목 이름 `연차` 하나뿐, 설명 없음
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 진입점 노출은 서버(layout allowedMenus)가 권한표로 정한다 — 사용자가 고를 것이 없다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: `leave` view가 없으면 항목 자체가 없다(role-menu.test.ts 「allowedMenus에 leave가 없으면」 단언)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 메뉴 항목 추가라 주 버튼 변화 없음(1차 메뉴 다섯 · 하단 탭 넷 불변 단언)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험 동작 없음 — 로그아웃은 여전히 계정 그룹 맨 끝
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: `연차` 진입점은 계정 그룹 한 자리(1차 메뉴 · 하단 탭에 넣지 않음)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 이 변경에는 빈 화면이 없다
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: PC 사용자 메뉴의 기존 role="menu" 방향키 이동에 항목 하나가 늘 뿐(TopBar 합성 불변, keyboard-nav · user-menu E2E 회귀 실행)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: `연차`는 `내 정보`와 같은 link 항목(`{kind: "link", href: "/leave"}`)

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 셸 색 · 모양 변경 없음, 항목 데이터만 늘었다

## 시스템
- [x] 새 색·서체·radius·그림자를 만들지 않았다(tokens.css 변수만) — 근거: CSS 변경 없음
- [x] 폰 320에서 가로 넘침 없음 · 터치 44px — 근거: 「더보기」 시트 계정 그룹 행은 기존 목록 행(44) 모양 그대로 — mobile-shell E2E의 시트 행 높이 단언이 새 행에도 걸린다
- [x] 실제 앱 화면(PC 1280 · 폰 390)을 찍어 보고 확인했다 — 스크린샷 경로: 해당 없음 — CLAUDE.md §6 「스크린샷 육안 판정 금지」, 실제 앱 E2E(CI=true)로 DOM을 실측하고 폭 1280 · 1024 · 375 독립 DOM 감사는 오케스트레이터가 별도 에이전트로 한다
