바꾼 것(지금 화면 기준으로 어긋나 있던 것 → 고친 것):
- ① 폰 문서 화면 행동 줄: 보이는 순서 반려 → 승인인데 DOM · Tab은 승인 → 반려(§10 위반) → 수화 뒤 폰 폭이면 DOM도 반려 → 승인, PC는 승인 → 반려 그대로(사용자 결정 A).
- ② 반려 확인 사유 칸: 한 줄 input이라 긴 사유가 가로로 밀림 → textarea, 글자에 따라 2~4줄, 넘치면 칸 안 세로 스크롤(사용자 결정 A).
- ③ SYSTEM §3 「폰 모든 행동 요소 44」 vs §7 「폰 버튼 · 입력 40」 충돌 → 「행동 버튼 · 행 탭 44, 폼 입력 · 시트 밖 보조 버튼 40」(§3 · §10 문구, 사용자 결정 A — 구현 불변).
- ④ 동시 처리 줄의 `새로 고침`이 손으로 만든 버튼이라 폰 높이 20px → `ui/button` 3차(폰 44 · hover), 복제 CSS 두 벌 삭제.
- ⑤ 폰 고정 행동 줄 아래 여백이 행동 줄보다 짧아(충돌 줄이 뜨면 더) 본문 끝이 가려짐 → 행동 줄 실측 높이로 여백(수화 전 기본값도 패딩 · 윗선 포함으로 고침).
- ⑥ 관리자 사람 상세: 연차 정보가 가려진 계급이면 입사일 · 퇴직일 칸이 빈 채로 보여 덮어쓸 위험 → 가려졌으면 두 칸을 그리지 않음.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 문구 없음(① ② ④ ⑤ ⑥은 순서 · 입력 모양 · 여백 · 칸 유무만 바꿈), error-copy-noun-style 단위 테스트 통과
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: ⑥은 확인할 수 없는 값(가려진 입사일)을 빈 칸으로 보여 사용자가 잘못 채우게 하던 결정 자체를 없앴다. 그 밖 입력 기본값 변경 없음
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: ⑥ 가려진 날짜는 입력을 숨김. 설정 화면 비활성 칸은 같은 묶음의 「N단 사용」 체크가 상태를 보이므로 그대로(§7-1 이유 규칙은 버튼 대상 — /design-review에서 재판정)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 행동 줄 1차 `승인` 하나 그대로(① 순서만), 확인 창 1차 `반려` 그대로
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 반려 · 승인 사이 `--s-4` 그대로(폰), 반려는 확인 모달 · 시트(SYSTEM §7-1 — 붉은 버튼 없음)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: ④ 서버 문구 끝 `새로 고침`이 버튼 하나(기존 규칙 그대로), 사유 칸 라벨 `사유` 하나
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 화면 변경 없음
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: ① 폰 Tab 반려 → 승인(E2E `mobile-leave-approval` Tab 단언), 사유 칸에서 Ctrl+Enter 반려 그대로(E2E `leave-document` 반려 모달 테스트)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: ④ `새로 고침`이 다른 3차 행동과 같은 `ui/button` tertiary
