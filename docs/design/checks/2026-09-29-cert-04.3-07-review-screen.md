## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 상시 설명문 없음. 남은 줄은 상태 표시 셋(`등록 이름 {이름}` 힌트 — 다를 때만 · `수령자 서명 · 고칠 수 없음` · `· 저장 안 함`)과 오류 · 실패(칸 아래 `Form.Error` · 버튼 옆 `저장 실패 · …` · `번호 불러오기 실패 · 다시 시도` · `서명 이미지 불러오기 실패 · 다시 시도`), 인쇄 미디어 전용 한 줄(UI-SPEC 문장 그대로 — 오류가 아니라 인쇄 상태 안내라 화면에서는 숨김)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 이름 · 연락처 · 주소는 제출값이 채워진 입력. 바뀐 칸은 화면이 계산해 1차가 켜지고, 저장 결과의 칸 이름 · 시각은 서버가 준다. 주민등록번호는 「전체 보기」 뒤 전체 값이 채워진 칸
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 전체 보기 권한 없으면 「전체 보기」를 렌더하지 않는다(vendors 선례) → 주민등록번호 입력 칸도 없다. 쓰기 권한 없으면 입력은 읽기 전용 · 제출 줄 없음. 서명에는 컨트롤 없음. 바뀐 칸 없으면 1차 비활성 + `바뀐 칸 없음`(`info`)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 1차는 「고친 내용 저장」 하나. 「전체 보기」 · 「가리기」 · 「다시 불러오기」 · 「다시 시도」는 3차. 머리 「인쇄」 2차는 04.3-11(자리만 비움 — 빈 버튼 없음)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 해당 없음 — I4에 삭제 · 되돌릴 수 없는 동작 없음(정정은 버전으로 거부 · 다시 고칠 수 있음)
