> 지금: (01) 폰 복원 줄 「복원」·「버림」이 min-height만 있어 폭이 글자 폭(32.3) — 44 미만. (02) 편집 없는 비활성 「일괄 저장」 안 kbd가 on-accent 값(opacity 0.8 · 흰 반투명 테두리)이라 --surface 면 위 대비 3.34. (04) 「번호」 본문 칸 글자가 14px 본문 색이라 §7-3 첫 칸 행 번호 모양(--fs-xs · --faint)이 아니다. (05) 폰 머리 줄 DOM 순서가 복사 묶음 → 상태 바꾸기 → 일괄 저장이라 보이는 순서(CSS order)와 Tab 순서가 다르다.
> 고칠 계획: (01) 상세 · 리저브 폰 .restoreAction에 min-width: var(--touch-min) 한 줄. (02) 비활성 1차의 kbd는 기본 kbd 값(opacity 1 · --line 테두리 · 글자 --faint). (04) 「번호」 본문 칸 글자를 .rowNumber 한 요소(--fs-xs · --fw-medium 600 · --faint · 최소 폭 28 — SYSTEM §2-2 --fs-xs 표의 굵기, /review 지적으로 굵기 추가)로 감싼다 — td의 오른쪽 정렬 · tabular-nums · nowrap은 그대로. (05) 폰(<700)에서만 수화 뒤 DOM 순서를 상태 바꾸기 → 일괄 저장 → 더보기 묶음으로 바꾼다(usePhoneWidth 재사용, 폰 CSS order 규칙은 한 줄도 바꾸지 않음).

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 문구 0. 복원 줄 · kbd · 번호 글자 모두 기존 글자 그대로이고 크기 · 색 · 순서만 바뀐다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 사용자 입력 · 선택지 변화 0, 행 번호는 시스템이 세는 값 그대로
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 비활성 「일괄 저장」 규칙(aria-disabled · 이유) 그대로, 모양만 면(--surface)에 맞는 kbd 값으로
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 1차 「일괄 저장」 위계 무변경, 활성 1차의 kbd(opacity 0.8)는 그대로 — E2E DR-104-02가 활성 kbd 0.8을 가드
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험 동작 배치 · 색 무변경(「버림」은 되돌리기 알림이 있는 기존 규칙)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 글자 중복 추가 0, 번호 열 머리글 「번호」와 본문 숫자는 그대로
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 구성 무변경
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 폰 머리 줄 Tab 순서 = 보이는 순서(SYSTEM §10) — mobile-touch-targets 「DR-104-05」가 폰 Tab 네 번과 PC Tab 세 번을 실측
