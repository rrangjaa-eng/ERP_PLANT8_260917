# 설정 힌트 aria-describedby · 이력 숫자 쉼표 — 점검표
화면: app/(app)/admin/settings/, ui/input/
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §2-4 · §7-2 · §7-14 · §10 · docs/reviews/phase-04/pr104-qa.md ISSUE-001 · pr104-design-review.md DR-104-03

> 지금: 설정 칸 8곳의 힌트 <p>에 id가 없고 칸의 aria-describedby가 힌트를 가리키지 않아 스크린 리더가 힌트를 칸과 이어 읽지 못한다(ISSUE-001). 이력 목록 숫자는 String(value)라 125000이 쉼표 없이 그려진다(DR-104-03). 폰 결재선 복원 줄 「복원」·「버림」은 min-height만 있어 폭 32.3 — 44 미만(PR #112 /review Red Team, DR-104-01과 같은 결함).
> 고칠 계획: 힌트 <p>에 id `setting-{key}-hint`를 붙이고 칸(TextField hintId · select · 체크박스 · fieldset · 이력 묶음 role=group)의 aria-describedby에 오류 id 뒤로 더한다. 이력 숫자는 기존 lib/format-number 포맷터로 그린다(정수 → formatCount, numberKind → 해당 포맷터, 비율 소수는 저장값 그대로). 문구 · 레이아웃 · CSS 변경 없음. 「설정 내보내기」 안내 줄은 설정 칸이 아니라 범위 밖(사용자 확인 2026-09-30). 폰 .restoreAction에 min-width: var(--touch-min) 한 줄(상세 · 리저브와 같은 규칙).

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 힌트 문구는 SETTING_DEFS의 기존 hint 그대로이고 새 글자 0, id · aria-describedby 속성만 더한다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 사용자 입력 · 선택지 변화 없음, 이력 숫자 표기만 시스템이 쉼표로 그린다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: disabled · activeWhen 판정 무변경(결재선 단계 칸 비활성 규칙 그대로)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 버튼 구성 무변경(「N단 저장」 · 「설정 내보내기」 · 이력 추가 버튼 그대로)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이력 「취소」 등 위험 동작 배치 · 색 무변경
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 힌트는 한 번만 그려지고 id로 칸에 이어질 뿐 글자를 되풀이하지 않는다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 구성 무변경(이력 행이 없을 때의 추가 폼 그대로)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: DOM 순서 · 포커스 이동 무변경, 이력 묶음에 role=group을 더해 스크린 리더 탐색이 나아진다
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 행동 요소 종류 무변경
