# 04.3-14 수집 안내 v3 · 개인정보 화면 세션 · 접속기록 — 점검표
화면: app/c/[token]/, app/(app)/certs/submissions/[id]/, app/(app)/certs/events/[id]/, app/print/certs/[id]/, app/(auth)/login/
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §6-5(E′4 수집 안내) · §6-6(인쇄) · §6-7(로그인) · 04.3-14-PLAN 「수집 안내 v3 문구」(카피 계약) · UI-SPEC 「개정 (2026-10-01 결정 확정)」

지금 화면(실행 전): E4는 v2 「개인정보 수집·이용 동의」 체크 · 요약 · 전문(문장이 화면 파일 `consent-block.tsx`에 있고 전문은 `<p>` 나열) · 막힘 이유 낱말 `동의` · I4 줄 `동의 · 동의함 · {일시}`. I4 · 인쇄는 조회 기록이 없고(I3 「제출 내용」 링크는 04.3-17이 이미 `prefetch={false}`), 비활동 한도 120분(10~120) · 평문 가림이 그 설정을 따르며, 끊기면 이유 없이 `/login`으로 가고 다시 로그인하면 `/account`다. I3(`app/(app)/certs/events/[id]/`)는 이 플랜이 고치지 않는다 — 미리 가져오기 회귀를 E2E로 고정만 한다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: Task 1은 문장을 더하지 않는다(기록 실패는 새 문구 없이 기존 오류 경계 `app/(app)/error.tsx` · 인쇄 오류 경계 — G0 DR-13). Task 2가 더한 문장은 로그인 화면 이유 줄 하나 `개인정보 화면 · 다시 로그인`(명사형 · 잠김 상태 · 카피 계약)이고, 비밀번호 변경 줄과 같은 자리 · 같은 모양(`role="status"`, SYSTEM §6-7). 무입력 이동 부품(`privacy-idle-logout.tsx`)은 화면에 그리는 것이 없다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 접속지 IP · 조회 기록은 서버가 요청 헤더에서 정한다. 끊긴 뒤 다시 로그인하면 원래 보던 I4 · 인쇄로 시스템이 돌려보낸다(`next=` — 사용자가 다시 찾아가지 않는다, U5 a). 평문 가림 3분은 고정값이라 묻지 않는다(결정 ③)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 볼 수 없는 사람은 지금처럼 404(조회 기록 0줄 — 통합 `cert-access-log`). 한도를 넘긴 개인정보 화면은 열리지 않고 로그인 화면으로 간다(첫 접근 판정 — E2E)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 버튼을 더하거나 바꾸지 않는다 — 로그인 화면의 1차 「로그인」 하나 그대로
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험한 동작을 더하지 않는다
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 로그인 화면 이유 줄은 비밀번호 변경 줄과 함께 뜨지 않는다(reason 값이 하나) · 실패 문구(`role="alert"`)와 다른 자리 규칙 그대로
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 없음(해당 없음)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 키보드 경로 변경 없음 — I3 「제출 내용」 링크는 그대로(04.3-17). 키 입력도 무입력 시계를 다시 건다(누름 · 키 · 입력 셋)
