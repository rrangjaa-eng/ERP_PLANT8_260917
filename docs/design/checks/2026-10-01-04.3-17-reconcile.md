# 04.3-17 확인증 대조 · 「링크 닫기」 · 「신청 취소」 · I4 수량 · 파기 대상 · 「대조 제외」 — 점검표

기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §2-4 · §6-2 ⑯ · §7-3 (가) · (라) · (바) · ⑮ · §7-5 · §7-8 · §7-17 · DECISIONS D-c · D-c 보충 · 2026-09-30 §7-17 실패 줄 · D-c 보충 2 · UI-SPEC 「개정 (2026-09-30 새 흐름)」 I′3 · I′4 + 「개정 (2026-10-01 결정 확정)」 T2 · T3 · T4 · T8 · Copywriting

지금 화면(실행 전): I′3에는 머리 · QR · 경품 섹션뿐이라 경영관리가 행사 뒤 제출을 현장 추첨 결과와 맞출 자리가 없고, 「링크 닫기」 · 「신청 취소」가 없어 닫으려면 마감을 기다려야 하고 잘못 신청한 행사를 지울 길이 없다. 닫힌 행사의 경품 표에는 당첨됐는데 안 낸 과세 대상 신호(`미제출`)가 없다. I4에는 수량 정정 칸 · 파기 대상 표시 · 「대조 제외」가 없고, 주민등록번호만 비운 제출(04.3-12 파기 적용 뒤)은 I4가 404라 목록 링크가 끊긴다. `RowSheet`에는 행동 자리가 없고, 확인 모달에는 다시 누를 수 있는 실패 줄이 없다. 고칠 계획이 아래 항목의 답이다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 제출 섹션은 그룹 머리글(건수) · 색 글자(`파기 대상` · `같은 연락처 {N}건` · `같은 이름 {N}건` · `초과 {N}건` · `대조 제외`)뿐 설명 없음. 확인 창 결과 줄은 되돌릴 수 없는 일(링크 닫기 · 대조 제외)에만, 실패 줄은 `닫지 못했습니다 · 다시 시도` / `제외하지 못했습니다 · 다시 시도`(UI-SPEC 카피 계약 문장 그대로), 「신청 취소」 막힘은 이유 한 줄(`경품 {N}줄 있음 · …`). 새 문장은 UI-SPEC 카피 계약 밖에 없다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 그룹 N(대조 제외 뺀 수) · 초과 · 같은 연락처 · 같은 이름 · 파기 대상 · `미제출 {k}`는 서버 · 미리 보기가 계산해 색 글자로 보인다. 화면은 대조를 판정하지 않는다(N13 a — 대조 완료 표시 없음). 수량 칸은 저장된 값이 기본
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 제출 섹션은 I4를 열 수 있는 사람(DTO `submissions` 키)일 때만 · 「링크 닫기」는 접수 중 + `certs.qr` 쓰기만 · 「신청 취소」는 신청됨 + 서버와 같은 조건(H-2)만, 경품 줄이 있으면 비활성 + 이유 · 「대조 제외」는 쓰기 ∧ `cert_submission.value` ∧ 대표 아님 ∧ 제외 안 된 제출에서만(숨김) · 주민번호만 비운 I4는 전체 보기 · 주민번호 정정 · 인쇄가 없다 · 제외된 I4는 정정 칸 · 저장 · 전체 보기 · 인쇄가 없다
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: I′3 1차는 그대로 경품 표 1차 하나(`QR 생성` / `일괄 저장`) — 「링크 닫기」 · 「신청 취소」는 머리 2차. I4 1차는 「고친 내용 저장」 하나, 「대조 제외」는 머리 2차(「인쇄」 왼쪽). 확인 창 1차는 실제 동작 이름(`링크 닫기` · `대조 제외`)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 되돌릴 수 없는 「링크 닫기」 · 「대조 제외」는 머리 2차(1차와 떨어진 자리 — 「대조 제외」는 정정 1차 「고친 내용 저장」과 반대쪽 머리)이고 확인 창(§7-17)을 거친다. 「신청 취소」는 경품 0일 때만 켜지고 지워지는 것이 칸 둘이라 확인 없이(§7-8 「같은 값으로 다시 넣을 수 있는 행」). 위험 색은 버튼이 아니라 확인 창의 결과 줄이 말한다(§7-17 기존 모양 — 새 색 없음)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 모자람(`미제출`)은 경품 표 한 자리, 넘침(`초과`)은 제출 섹션 한 자리(「신호는 한 자리」 — T 패스 1). 제외된 줄은 `대조 제외` 하나만(다른 색 글자 없음). 경품 표 숫자 셀은 숫자만(열 머리글이 단위), 그룹 머리글은 단위 붙임(DR-15)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 제출 섹션 EMPTY `제출이 없습니다` — 경영관리가 할 다음 한 수가 없다(수령자가 제출해야 생긴다). 첫 행동은 이미 QR 섹션(링크 복사)이 갖는다
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 제출 섹션은 읽기 `<table>`(grid 아님 — DR-8)이라 「제출 내용」 링크가 줄마다 보통 Tab 정지, 접근 이름이 줄마다 다름(`제출 내용 · {이름} · {MM-dd HH:mm}`). 확인 창은 열릴 때 1차 포커스 · `Esc` 취소 · `Ctrl+Enter` 1차(§7-17 부품). I4 수량 칸은 폼 Tab 순서 안
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 다른 화면으로 가는 「제출 내용」은 링크(`next/link` `prefetch={false}`) — PC 표 · 폰 `RowSheet` `action` 둘 다 링크. 같은 화면 안 행동(링크 닫기 · 신청 취소 · 대조 제외)은 버튼
