# 견적 분류 코드표 — 점검표
화면: app/(app)/admin/code-tables/, app/(app)/projects/[id]/
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §7-16(전환 링크) · D-62(소분류 = 그룹 머리글)

지금 화면(고치기 전): 코드표 화면의 표 전환 링크는 「프로젝트 상태 · 증빙 종류」 둘 — 견적 분류(quote_subcategory)는 고칠 화면이 없다. 견적 표의 소분류 이름 목록은 활성 · 미보관 항목만 실어, 분류를 끄거나 보관하면 그 분류를 쓰던 줄이 코드값(`e2e_off_…`)으로 보인다.
고칠 계획: 전환 링크에 「견적 분류」 하나를 더한다(표 · 폼 · 열은 범용 그대로). 견적 표는 이름표(subcategoryLabels — 비활성 · 보관 포함)로 이름을 읽고, 편집 선택지는 활성 목록 그대로.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 설명문 추가 0 — 링크 이름 「견적 분류」 하나만 늘었다. 견적 표는 코드값 대신 이름을 보일 뿐 문구 변경 없음
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 입력 칸 · 기본값 변경 없음. 새 줄 기본 분류는 활성 목록 첫 항목 그대로(subcategories[0])
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 끈 · 보관 분류는 편집 선택지(select)에 나오지 않는다 — c3 E2E가 option 목록에 그 값이 없음을 단언(통과). 이름 읽기만 subcategoryLabels. 끈 분류를 쓰는 줄은 그 현재 값만 선택지에 남겨, 칸을 열었다 나가도 값이 지워지지 않는다(독립 검토 지적 — quote-readonly-labels 「toHaveValue · 소분류 필요 0」 단언). 끈 분류 줄에서 Ctrl+Enter · Ctrl+D로 만든 새 줄은 끈 분류를 물려받지 않고 첫 켠 분류다(/review red team — 같은 스펙 「끈 분류 행 1개」 단언)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 버튼 추가 0. 코드표 화면 · 프로젝트 화면 주 버튼 구성 그대로(전체 E2E 698/698 통과)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 삭제 · 비활성 버튼은 기존 범용 코드표 열 그대로(배치 · 색 변경 없음)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 그룹 머리글과 소분류 칸이 같은 이름을 보이는 것은 D-62 기존 구성 그대로. 새 링크 이름은 부제(현재 표 이름)와 같은 TABLE_OPTIONS 한 곳에서 온다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 변경 없음(견적 분류 표는 시드 4건이 있다)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 전환 링크는 기존 <a>, 견적 표 키 구성 변경 없음 — c3가 Enter로 소분류 select를 열어 확인(통과), quote-table.spec 전체 통과
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 「견적 분류」는 기존 두 전환 링크와 같은 .toggle 링크 — 현재 표 구분(aria-current)도 같은 규칙(code-tables.spec 형제 2개 단언 통과)
