# 수집 안내 v4 — 점검표
화면: app/c/[token]/consent-block.tsx
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §6-5 수집 안내 줄(510행)

변경 범위: 수집 안내 전문 두 절(받는 근거 · 제공)의 문장과 판 표기(v3 → v4)뿐이다. 문장 정본은 `domain/certs/consent.ts`이고 `consent-block.tsx`는 import만 하므로 이 화면 코드는 바뀌지 않는다(컴포넌트 · dl 8절 구조 · 버튼 · 키보드 동작 무변경).

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 요약 문장 · 절 구성은 그대로이고 바뀐 두 절은 법정 고지 본문이라 줄이지 않는다. 「받는 근거」 끝 문장을 한 문장으로 맞추고 「제공」을 조건 문장 하나로 줄였다(v3의 「제공」 세 문장 → 두 문장). 문구를 더한 곳 없음.
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 수령자가 고를 것은 안내 확인 체크박스 하나뿐이고 이번 변경은 이를 건드리지 않는다. 가액에 따른 변형을 사용자나 수령자에게 묻지 않고 한 문장으로 통일했다.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 선택지 변화 없음(체크박스 · 전문 보기/접기 그대로). consent-block.tsx 무변경.
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 버튼 구성 무변경. 전문 보기/접기는 3차, 제출 주 버튼은 이 블록 밖 그대로.
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 해당 동작 없음(수집 안내 읽기 · 확인 화면).
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: v4 「받는 근거」 끝 문장(「…따로 동의를 받지 않습니다」)과 「제공」 문장이 겹치지 않고, 「제공」은 v3의 「법령상 의무입니다」를 빼 「소득세법 제164조」 근거 한 번만 말한다.
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 없음. 수집 안내는 서명 바로 위의 고정 블록이다.
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 체크박스 · 전문 보기/접기 버튼 · `aria-expanded` · `aria-describedby` 동작 무변경(consent-block.tsx 무변경).
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 행동 요소 추가 · 변경 없음. 문의 전화 `tel:` 링크 형식 그대로.

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 색 · 표 · 패널 · 스킨 변경 없음. 문장과 판 표기만 바뀐다. 수령자 금지어 넷(원천징수 · 지급명세서 · 등록한 이름 · 당첨자로 등록)은 두 변형의 요약 · 전문 8절에 0건이다(SYSTEM §6-5 규칙 예외 없음 — 사용자 결정 2026-10-02 채팅, 「제공」은 「세무 신고 대상이면 …」으로 시작).
- [x] 가액 정보 없음: 구간별 변형을 만들지 않았다 — 근거: 「제공」은 두 변형(현장 · 택배)이 같은 조건 문장 하나이고 가액 · 금액 · 구간 문장이 없다(`consent-notice.test.ts` 판별 전문 toEqual이 고정).
