# 확인 모달 SUCCESS · 「새로 고침」 꼬리 · 근거 칸 이유 자리 — 점검표
화면: docs/design/SYSTEM.md(§7-7 · §7-8 · §7-17), ui/confirm-dialog/, app/(app)/approvals/decision-dialogs.tsx
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §7-7 · §7-8 · §7-17 · §8

> 지금 어긋난 점 세 가지(PR #121 독립 검토):
> ① §7-7 시트/모달 SUCCESS 칸은 「결과 한 줄을 보인 뒤 닫히고 토스트」라고 쓴다. 그런데 ConfirmDialog 호출처 12곳은 모두 바로 닫힌다. 토스트도 일부(반려 · 회수 · 새 차수 · 상태 바꾸기)만 띄운다.
> ② §7-17 ERROR는 서버 거부를 「그대로」 붙인다고 쓴다. 결재 확인은 꼬리 ` · 새로 고침`을 떼고 3차 버튼으로 바꾸지만, 상태 바꾸기 · 차수 확인은 꼬리를 글자 그대로 둔다. 같은 거부가 화면마다 다르게 보인다.
> ③ §7-8 모달 첫 줄은 「근거 칸 오류 = 1차 왼쪽 이유」라고 쓴다. 그런데 날짜 칸 오류는 칸 아래에 붙는다(`blockedBy`). 예시 문구 `한 줄 적어 주세요`는 §8-3에 어긋나고, 실제 문구(`사유 없음 · 사유 적기`)와도 다르다.
> 고칠 계획: ① · ③은 문서를 구현에 맞춘다. ②는 사용자 선택(「버튼으로 통일」)에 따라 꼬리 → 3차 「새로 고침」을 ConfirmDialog가 강제하게 한다. 버튼은 화면을 다시 받고 다이얼로그를 닫는다. 결재 확인의 자체 처리는 지운다. 색 · 토큰 · 레이아웃은 바꾸지 않는다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자 0. 서버 거부 글자는 오히려 짧아졌다(꼬리 ` · 새로 고침` 제거). DOM 감사 9회 모두 이유 글자 = 머리(`상태가 미수주로 바뀜` · `다른 사람이 먼저 새 차수를 만듦` · `견적이 바뀜`)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 근거 칸 기본값(승인일 = 오늘) 무변경. 「새로 고침」 한 번이 다시 받기 + 닫기를 함께 한다(사용자가 닫기를 따로 고르지 않는다)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 거부가 붙은 동안 1차 `aria-disabled="true"`, Ctrl+Enter도 서버 액션 0건(DOM 감사 9/9)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 1차 하나 무변경. 「새로 고침」은 3차(tertiary)라 1차와 무게가 겹치지 않는다
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 행동 줄 순서 이유 → 새로 고침 → 2차 → 1차(감사 9/9 좌→우 실측), 막힘 이유 `--danger`(.reason) 무변경

- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음 — 확인 모달은 빈 상태가 없다(§7-17 다섯 상태 EMPTY 해당 없음), 변경 없음

- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 같은 거부가 결재 확인 · 상태 바꾸기 · 차수 확인 · 결재 동시 처리 줄(conflict-line)에서 모두 3차 버튼 「새로 고침」으로 같아졌다(컴포넌트가 강제)
