## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 패널에 새로 생긴 글자는 제목(거래처 등록/수정) · 라벨 · 버튼(취소 Esc / 거래처 등록 Ctrl+Enter) · 막힘 이유 한 줄 · 결과 한 줄(「거래처 등록됨」)이 전부다. 「입력 버리기」 확인 창만 되돌릴 수 없는 일(바뀐 칸 n칸)에 한 번 뜬다. 스크린샷 panel-pc.png · panel-phone.png(세션 스크래치)에서 설명문 없음을 봤다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 열리면 첫 칸(이름)에 포커스가 가 있고(side-panel.spec.ts 첫 테스트) 등록 성공 뒤 패널이 열린 채 칸이 비어 이어서 입력한다(UQ-8 B, 사용자 답). 닫을 때 확인은 바뀐 칸이 있을 때만 뜬다(DR1 A, 사용자 답)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 쓰기 권한이 없으면 패널과 「거래처 등록」 링크가 렌더되지 않는다(E2E 「쓰기 권한이 없는 계급」). 빈 목록이면 머리 1차를 숨기고 빈 화면 버튼 하나만 둔다(DR5 A, 사용자 답 — page.tsx `vendors.length > 0`). 제출 중에는 1차가 「진행 중」 · aria-disabled이고 닫기가 무시된다(D7 E2E)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 패널은 행동 줄에 1차 하나(`거래처 등록`/`거래처 수정`, `--accent` 면) + 2차 「취소」, 목록 머리에는 1차 링크 하나 — panel-pc.png
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이 슬라이스는 삭제 동작을 새로 만들지 않았다. 행의 삭제 링크는 기존 `RowActions` 그대로(맨 끝에 떨어짐)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 패널 제목과 1차 라벨이 같은 동사(거래처 등록)지만 제목은 위치 알림 · 버튼은 행동이라 역할이 다르다(SYSTEM §6-3). 칸 안 자리 표시 글자 없음, 힌트는 칸 아래 한 줄(계좌번호 현재 값)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 목록은 「등록된 거래처가 없습니다 · 거래처 등록」 한 줄과 버튼 하나(panel-pc.png 왼쪽 뒤 화면)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 열기 Enter(링크) → 첫 칸 포커스 → Tab이 패널 안에서 돈다(wrapTab, E2E 「Tab은 패널 안에서 돈다」) → Ctrl+Enter 제출 → Esc 닫기 → 포커스가 여는 링크로 복귀(E2E D12 넷)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 목록 머리 「거래처 등록」은 `next/link`이지만 `buttonStyles.btn primary`를 써 버튼 모양이다. 패널 안은 전부 `Button`이다. 행의 「수정」은 기존 행동 링크 그대로 + 누른 직후 「…」 처리 중 표시(LinkPending)

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 한 건 폼은 옆 패널(PC 오른쪽 480 · 폰 아래 시트) 그대로이고 견적 줄 입력은 건드리지 않았다. 바탕은 `--surface-base`/`--surface-actions` 역할 토큰뿐(웜톤 없음). 뒤 막기(Q1 A) · 성공/닫기(UQ-8 B · DR1 A · DR5 A)는 사용자가 2026-10-01~02에 고른 답(`04.6-ANSWERS.md`)을 그대로 구현했다
