# 04.6-05 공용 표현 컴포넌트(Num · RowActions · TableSkeleton · StaticTable · 상태 배지 한 표 · 빈 화면) — 점검표
화면: ui/num/, ui/row-actions/, ui/table/
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §7-3 · §7-5 · §7-7 · UI-SPEC 「공용 컴포넌트 계약」

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 컴포넌트가 만드는 글자는 호출부가 넘긴 값뿐이다. 새로 생긴 문구는 대기 중 sr-only 「처리 중」(Button과 같은 글자)과 비활성 이유(호출부가 준 한 줄) 둘이고 설명문은 0이다(`ui/num` · `ui/row-actions` · `ui/table` 소스 전체를 훑음)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: `Num`은 `unit` 기본 원화 · 서식은 `lib/format-number.ts`가 정한다. `TableSkeleton` 행 수 3은 고정이고 호출부가 고르지 않는다. `RowActions`는 danger를 맨 끝으로 시스템이 옮긴다(호출부가 순서를 외우지 않는다 — presentational.test.ts 「danger는 가운데 넣어도 DOM 맨 끝」)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: `RowAction` button 형은 `disabled`면 aria-disabled + 이유 글자(이유 없는 비활성은 타입 오류 — `@ts-expect-error` 케이스), 대기 중 클릭·Enter는 무시(`rowActionClickHandler` 단위 테스트). href 형에는 pending·disabled 속성이 없다
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 이 플랜은 1차 버튼을 만들지 않는다. 행동 링크는 3차 모양(밑줄 글자)이라 1차와 겹치지 않는다
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: `RowAction danger`는 DOM 맨 끝 · 앞 간격 `--s-8`(= 사이 `--s-4` + 여백 `--s-4`) · `--status-danger` 글자(`RowActions.module.css` `.dangerEnd` `.danger`)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: `StaticTable` 접힌 줄의 머리글 라벨은 sr-only(스크린리더용)이고 보이는 글자는 값뿐이다. 구분자 「 · 」는 보이는 값 사이에만(단위 테스트 「정확히 하나」)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 이 플랜의 `TableSkeleton`은 불러오는 중 뼈대(빈 화면 아님). 빈 화면(`ListEmpty`)은 같은 플랜 Task 2에서 점검표를 더한다
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: `RowAction` button 형은 네이티브 `<button>`이라 Tab·Enter·Space가 된다. 비활성은 aria-disabled라 탭 순서에 남고 포커스를 유지한다(DR-11). `Table.tsx`의 키 구성은 변경하지 않았고 견적·키보드 E2E(`quote-table` · `keyboard-nav` · `excel-paste-final`)가 기대 변경 없이 초록이다(SUMMARY 검증 증거)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: `RowAction` href 형(`<a>`)과 button 형이 같은 클래스(`.action`)를 쓴다(단위 테스트 「같은 클래스를 쓴다(같은 모양)」)

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 견적 줄 입력은 `Table.tsx`의 숫자 값(number) 반환 열에만 `Num`을 씌웠고 편집 키·칸 입력 코드는 건드리지 않았다. 문자열을 돌려주는 기존 열은 그대로(단위 테스트). 색은 역할 토큰뿐이다(웜톤 없음)

## 시스템
- [x] 새 색·서체·radius·그림자를 만들지 않았다(tokens.css 변수만) — 근거: 새 CSS 3개(`Num.module.css` · `RowActions.module.css` · `TableSkeleton.module.css`)는 `--text-aux` `--text-muted` `--text-link` `--text-faint` `--status-danger` `--surface-muted` `--border-row` `--border-strong` `--underline-w-hover` `--s-*` `--touch-min` `--row-h` `--line-w` `--underline-offset` 역할 토큰만 쓴다. stylelint(`pnpm lint`) 0 error
- [x] 폰 320에서 가로 넘침 없음 · 터치 44px — 근거: `RowActions.module.css` 폰 미디어 쿼리에서 `.action`에 `--touch-min` 최소 폭·높이, 목록은 `flex-wrap: wrap`이라 좁은 폭에서 줄을 바꾼다(가로 넘침 없음). 실측은 이 컴포넌트를 쓰는 화면 플랜(04.6-11 이후)과 04.6-13 독립 DOM 감사가 맡는다 — 이 플랜은 호출부를 바꾸지 않는다
- [x] 실제 앱 화면(PC 1280 · 폰 390)을 찍어 보고 확인했다 — 스크린샷 경로: 해당 없음(이 플랜은 호출부 0 · 새 컴포넌트는 아직 어떤 화면에도 그려지지 않는다. `Table` 숫자 열 경로만 실제 화면에 닿고 그 화면(견적 줄 표 · 프로젝트 목록)은 `CI=true` E2E 6스펙이 초록으로 잰다). 독립 DOM 감사는 04.6-13이 컴포넌트 모음 페이지에서 한 번에 한다(공통 §7)
