# 04.6-06 상세 화면 틀 · 컴포넌트 모음 뼈대 — 점검표
화면: ui/detail-screen/, app/(app)/dev/components/
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §6-2 · §7-20 · UI-SPEC 「화면 틀 계약」 DetailScreen · 「컴포넌트 모음 페이지」

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: DetailScreen은 제목·메타 한 줄·섹션 제목뿐이고 설명문 prop이 없다. 모음 페이지는 구역 제목(버튼 위계 · 기본 · 비활성 · 진행 중)과 비활성 이유 한 줄(Button의 disabledReason)만 둔다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 틀은 제목 크기·섹션 선·행동 순서를 스스로 정하고 화면은 내용만 넣는다. 모음 페이지는 사용자가 정할 것이 없는 읽기 화면이다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 비활성 표본은 `aria-disabled` + 이유 한 줄(네이티브 disabled 없음). 운영(prod)에서는 페이지 자체가 404다
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: DetailScreen `actions.primary`는 하나뿐이고 오른쪽 끝이다. 모음 페이지는 위계 표본 구역이라 1차가 여럿인 것이 의도(공통 §10 — 원칙 점검 대상이 아니다)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이 플랜은 삭제 동작을 만들지 않았다
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 제목 「컴포넌트 모음」 하나, 섹션 제목과 버튼 라벨이 겹치지 않는다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면이 없는 화면이다(해당 없음)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: actions의 DOM 순서 = Tab 순서(2차 → 1차)를 E2E가 Tab으로 확인한다
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 표본은 모두 `Button` 컴포넌트(variant만 다름)이고 3차도 `variant="tertiary"` 그대로다

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 바탕·면·글자는 역할 토큰뿐(웜톤 없음), 섹션 시작은 위 1px `--border-row`(스킨 A: 2px 아님). 견적·패널은 건드리지 않았다

## 시스템
- [x] 새 색·서체·radius·그림자를 만들지 않았다(tokens.css 변수만) — 근거: 새 CSS 둘 다 `--s-*` `--text-*` `--fw-bold` `--lh-*` `--line-w` `--border-row` `--text-strong` `--text-muted` 역할 토큰뿐이고 `pnpm lint`(stylelint 역할 토큰 규칙)가 0 error다
- [x] 폰 320에서 가로 넘침 없음 · 터치 44px — 근거: 머리·행동 묶음이 `flex-wrap`이라 좁으면 줄을 바꾼다. 버튼 높이는 `Button`이 정한다(터치 44는 Button 몫, 이 플랜 변경 없음)
- [x] 실제 앱 화면(PC 1280 · 폰 390)을 찍어 보고 확인했다 — 스크린샷 경로: 사진 대신 `test/e2e/dev-components.spec.ts`가 `CI=true` 실제 화면에서 DOM(제목 h1 · 섹션 h2 · 행동 x 좌표 · Tab 순서)을 실측한다(스크린샷 육안 판정 금지 — CLAUDE.md §6)
