## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 이 플랜은 CSS 값만 바꾼다(문구 변경 0 — 마크업 변경은 `Button.tsx`의 1차 `data-ui` 속성 하나뿐). 더보기 시트의 비활성 「검색」 이유 줄은 기존 그대로
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 사용자 입력 요소를 더하지 않았다. 바 높이는 PC·폰 한 토큰(`--bar-h`)이라 폰 전용 분기를 걷었다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 변경 없음 — 시트 검색 행은 기존대로 `cursor: not-allowed` 비활성 면(`--surface-muted` · `--text-faint`)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 셸·제목 머리·버튼 범위라 화면 단위 주 버튼 배치는 바뀌지 않았다. 스킵 링크만 1차 모양(`--accent` 면 · `--text-on-accent`)을 역할 토큰으로 옮김. `Button`은 1차에만 `data-ui="primary-button"` 훅을 달아 원칙 점검(04.6-29)이 화면의 1차 수를 센다(`button.test.ts` · `mobile-touch-targets.spec.ts`)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 해당 요소 없음(셸 범위 — 사용자 메뉴의 「로그아웃」 위치·색은 변경 없음)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 문구 변경 0
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음(빈 화면 컴포넌트는 이 범위 밖)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 탭 순서·마크업 불변. 바 위 포커스 윤곽은 `--focus-on-bar`로 유지되고 `page-chrome.spec.ts`가 윤곽색을 단언(바 밖 사용자 메뉴 항목은 키보드로 열어 `--focus` 단언)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 버튼과 링크 버튼(`buttonLinkClassName`)이 같은 `.btn` 클래스라 radius·높이·글자가 한 곳이다. 메뉴 링크 · 사용자 트리거 · 워드마크 세 포커스 규칙이 같은 `--focus-on-bar` 한 이름

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 바탕 `--surface-canvas`(n-75 #F2F5F4 — R ≤ G, R ≤ B 차가운 회색)·딥그린 바 유지(`--bar-bg`)·2px 진한 선 제거(하단 탭·시트 위 선 → 1px `--border-surface`, 시트는 선 없음). 현재 메뉴 밑줄은 2px `--underline-w-hover`(SYSTEM §6-0 「아래 2px `--g-400` 밑줄」 그대로)
