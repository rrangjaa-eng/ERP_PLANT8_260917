## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 목록 부제 「프로젝트 원장」은 틀(ListScreen)에 부제 prop이 없어 사라졌다. 남은 문장은 합계 제목·제외 건수(`ListTotals`), 필터 빈 화면·오류(`ListEmpty`), 입력 오류 한 줄, 막힘 이유 한 줄(`PanelForm reason`)뿐 — page-chrome.spec 「부제 0개」 · principles 막는 모드 테스트(`/projects` · `?new=1` · `&copyFrom=`)로 확인
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 등록 패널의 담당 PM · 팀 · 환율은 `creatorDefaults` · `usdDefaultFxRate`로 미리 채워진다(`page.tsx`), 복사는 `copyFrom`이 칸을 채운다. 저장 뒤는 상세로 이동(R9 D)이라 「계속 등록할지」를 묻지 않는다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 등록 권한이 없으면 `?new=1`은 패널이 없고(R15 E2E dialog 0개) 머리 1차도 없다(`canCreate`). 필수 칸이 비면 주 버튼이 막힘 이유와 함께 잠긴다(`reason={blockedReason}`)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 머리 1차 「프로젝트 등록」 하나(`ListScreen primaryAction`), 빈 목록이면 머리 1차를 숨기고 빈 화면 버튼 하나(DR5 A · `empty`), 패널 안은 「등록」 하나(`PanelForm`)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이 화면에 삭제·되돌릴 수 없는 행동이 없다(목록은 읽기+등록). 「입력 버리기」 확인 창의 버리기만 위험 행동이고 `ConfirmDialog`가 닫기(취소)와 떨어뜨려 위험 색으로 그린다(04.6-04 계약)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 상태 열은 `StatusTag`(글자 태그) 하나, 열 머리글 이름은 `PROJECT_COLUMN_LABELS` 하나가 표 머리글과 뼈대 머리글을 함께 그린다(`projects-loading.test` 머리글 일치).
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 목록은 `ListEmpty`의 「프로젝트 등록」 버튼이 먼저(DR5 A), 필터 0건은 「필터 지우기」 한 행동(`emptyKind` 갈래, projects-list.spec 「사용자 필터 0건」)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 머리 1차는 링크라 Enter, 행은 번호 링크 하나가 행 전체 링크, 패널은 Esc 닫기 · 입력이 있으면 확인 창 · Tab은 패널 안에서 돈다(04.6-04 `wrapTab`). 포커스 순서 = 시각 순서는 projects-list.spec (F4) 폰 접힘·펼침·PC 1280 단언으로 확인(1차는 필터 줄 마지막 줄 오른쪽 끝)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 패널을 여는 모든 행동은 `next/link scroll={false}` + `LinkPending`(머리 1차 · 빈 화면 버튼 · `RowAction href`)이고 누른 직후 같은 「진행 중」 표기를 쓴다(`row-actions-link-pending.test`, side-panel.spec D6)
