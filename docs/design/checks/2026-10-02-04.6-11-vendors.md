## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 목록 부제 설명문 없음(page.tsx에 설명 `<p>` 0개). 남은 문구는 확인 줄(대상 이름 · 보관함 이동 · 복원 가능)과 오류 「번호 불러오기 실패 · 다시 시도」 · 「같은 이름의 거래처가 이미 있습니다 · 확인」 뿐이며 이 플랜이 바꾸지 않았다. 「바뀐 칸 없음」은 04.6-04가 스크린리더 설명만 남겼다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 이 플랜은 표·행동 링크·필터만 옮겼고 폼 입력·기본값은 04.6-04 판 그대로다(`vendor-form.tsx`는 행 행동 두 컴포넌트만 바뀜). 필터는 한 링크 토글(숨김 포함/제외)로 선택 UI가 없다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: page.tsx의 `canWrite`·`canArchive`·`canReveal` 분기를 그대로 두어 권한 없는 행동은 렌더하지 않는다(보관된 거래처 행도 행동 칸 비움 `vendor.archivedAt ? null`)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 머리 1차 「거래처 등록」 하나(`ListScreen.primaryAction`), 빈 목록이면 머리 1차 없음 + `ListEmpty` 버튼 하나(DR5 A, `vendors.length > 0` 조건 보존). 원칙 막는 모드 E2E가 세 라우트에서 경고 0
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: `RowActions`의 danger가 맨 끝 · 앞 간격 `--s-8` · `--status-danger` 글자. E2E 「행 행동 간격이 글자 박스 기준 --s-4 · 삭제 앞 --s-8」 1280·768·700 초록, 위험 색은 「삭제」 하나뿐(수정·숨기기 같은 색, 삭제 다른 색)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 상태 칸은 `StatusTag status`(「보관됨」/「숨김」) 한 번이고 폰 접힌 줄은 `StaticTable`이 같은 칸 값을 한 번 더 보이는 PC/폰 택일 표시(PC에서는 CSS가 숨김)라 한 화면에 두 번 보이지 않는다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: `ListEmpty message="등록된 거래처가 없습니다" action=거래처 등록` 그대로(page.tsx)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 읽기 표(편집 칸 없음)라 엑셀 키 대상이 아니다. 행동은 네이티브 링크·버튼이라 Tab·Enter로 닫히고(`RowAction`) 확인 줄도 버튼 둘이다
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 「수정」 링크 · 「숨기기」 버튼 · 「삭제」 버튼이 `RowAction` 한 컴포넌트라 글자 크기·굵기·밑줄이 같다(E2E에서 세 행동의 font-size · font-weight · text-decoration-line 동일을 단언). 원칙 점검이 전에 냈던 「같은 행동은 같은 모양」 경고(12px / 14px)가 이 이관으로 사라졌다
