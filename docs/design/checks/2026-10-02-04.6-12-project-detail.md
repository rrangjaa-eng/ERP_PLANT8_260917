## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 이 플랜은 문구를 더하지도 바꾸지도 않았다. 부제 문구(`{번호} · 상세 견적 {n}차`)는 메타 한 줄로 글자 그대로 옮겼고(E2E `toHaveText`), 잠김 줄·복원 줄·매출 부제(「공급가액 기준」)는 기존 그대로다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 권한·상태 판정은 서버(page.tsx)가 그대로 하고 화면은 추론하지 않는다. 상태 배지 낱말은 `status`(ProjectStatus)에서 표 하나로 정해진다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: `statusChange`·`copyProjectHref`·`newRevision`·「일괄 저장」 렌더 조건 식을 건드리지 않았다(수용 기준 grep · hidden-references E2E 초록)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 머리 행동 실측 결과 1차는 「일괄 저장」 하나뿐이다. E2E가 보이는 `[data-ui="primary-button"]` 1개 · DOM 마지막 · x 오른쪽 끝을 단언한다
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 삭제 동작·확인 창(`ConfirmDialog`)은 손대지 않았다
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 제목 하나(h1), 상태는 배지 하나, 상태 변경일 줄(`{상태} {날짜}`)은 기존 그대로 유지했다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 표의 `emptyAction`(Table 몫)을 건드리지 않았다
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 편집 훅·키 처리·저장 경로 diff 0, quote-table·keyboard-nav·excel-paste-final E2E가 기대 변경 없이 초록(115 passed)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 「프로젝트 복사」는 기존 그대로 `next/link` + 2차 모양 링크, 나머지는 `Button` — 모양은 `variant`가 정한다
