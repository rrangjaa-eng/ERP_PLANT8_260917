## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 구역 제목 19개와 표본 라벨뿐이고 설명문 없음. 남은 문구는 입력 오류 표본 「형식 오류」·「숫자 입력」(명사형), 비활성 이유 「권한 없음 · 담당에게 요청」(06 기존), 배너·토스트 표본 문구(상태 표본). `error-copy-noun-style.test.ts` 초록
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 읽기 전용 개발 화면. 사용자가 정할 것이 없고 값은 코드 안 고정 표본이다(합계 7,140,000도 고정 표본)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 비활성 표본은 `aria-disabled` + 이유 한 줄(Button 규약), 운영(prod)은 페이지 404(06 게이트 그대로)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 모음 페이지는 위계 표본 구역이라 1차가 여럿인 것이 의도(공통 §10 — 원칙 점검 대상 아님). 옆 패널 표본의 행동 줄은 `PanelForm`이 2차 → 1차 하나로 그린다
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 행 동작 표본 3개짜리의 「삭제」는 `RowAction danger`라 `RowActions`가 DOM 맨 끝에 놓고 위험 색을 건다(E2E가 자식 수 1·2·3을 확인)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 구역 제목과 표본 라벨이 겹치지 않는다(「1차 기본」 등 06 라벨 불변). 상태 배지는 낱말마다 tag·text 둘이지만 변형 비교가 목적이다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 목록 구역이 `ListEmpty`(「표본 없음」 + 「표본 추가」 버튼)로 같은 규칙을 보인다
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 편집 표 표본이 `enableGridKeyboard`(role="grid")이고 토스트·모달·패널 표본은 버튼·링크라 Tab·Enter·Esc로 열고 닫힌다(E2E가 Esc로 모달 닫힘 확인)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 이동은 `next/link`(옆 패널 열기 = `buttonLinkClassName` 2차 모양, 행 동작 「수정」 = `RowAction href`), 비이동은 `Button`·`RowAction onClick`

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 면·글자·선은 역할 토큰뿐(웜톤 없음), 편집 표는 `Table` 격자 그대로(모달로 옮기지 않음), 옆 패널은 `SidePanel`(PC 오른쪽 480 · 폰 아래 시트)를 그대로 쓰고 E2E가 PC `[1280, 480]`·폰 `[0, 390, 844]`를 잰다

## 시스템
- [x] 새 색·서체·radius·그림자를 만들지 않았다(tokens.css 변수만) — 근거: 새 CSS는 `--s-*` `--text-body|aux|tag` `--fw-bold` `--line-w` `--border-surface` `--radius-surface|tag` `--surface-base|muted` `--text-strong|muted` 역할 토큰뿐이고 `pnpm lint`(stylelint) 0 error · `mark-legacy --audit` 출력 없음
- [x] 폰 320에서 가로 넘침 없음 · 터치 44px — 근거: 표본 묶음이 모두 `flex-wrap`/`grid`이고 `.frame`은 `min-width: 0`. 터치 44는 `Button`·`RowActions`·`ListEmpty` 몫(변경 없음). 320 실측은 공통 §7 독립 DOM 감사 대상(SUMMARY 「감사 대상」)
- [x] 실제 앱 화면(PC 1280 · 폰 390)을 찍어 보고 확인했다 — 스크린샷 경로: 사진 대신 `test/e2e/dev-components.spec.ts`가 `CI=true` 프로덕션 빌드에서 DOM(구역 제목 · 배지 수 · 패널 상자 · 시트 상자)을 실측한다(스크린샷 육안 판정 금지 — CLAUDE.md §6). 기준 사진은 공통 §9 0단계가 CI에서 만든다
