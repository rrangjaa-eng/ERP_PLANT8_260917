## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 네 화면 모두 목록 부제 설명문 없음(`ListScreen`·`DetailScreen`에 부제 prop이 없고 page.tsx에 설명 `<p>` 0개). 남은 문구는 잠김 한 줄 「정보 노출표 · 사람 정보 잠김」 · 초기 비밀번호 결과의 「이 비밀번호는 다시 볼 수 없습니다 · 지금 전달하세요」(되돌릴 수 없는 일) · 서버 오류 줄(`PanelForm` reason)뿐이고 문구는 바꾸지 않았다. 원칙 막는 모드 E2E 9개 라우트 경고 0
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 「팀 추가」는 눌린 본부 행의 id를 `orgUnitId`로 실어 팀 패널의 본부 칸이 미리 골라진다(DR3 B — 보관된 · 모르는 값은 빈 기본값). 패널 칸 · 기본값은 그대로이고 입사일 필수 · 발령일은 팀을 골랐을 때만 보내는 규칙도 그대로다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 사람 `canWrite`·`canArchive`, 조직·계급은 `can(admin.people, write)`·`can(admin.archive, write)`로 1차 링크 · 패널 · 「팀 추가」 · 「삭제」를 렌더하지 않는다(권한 없는 직접 URL은 패널 없음). 시드 계급 · 보관된 행은 삭제 버튼 자체가 없고 보관된 본부 행에는 「팀 추가」도 없다
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 머리 1차 하나(`ListScreen.primaryAction` — 「사람 등록」 · 「본부 추가」 · 「계급 추가」), 빈 목록이면 머리 1차 없음 + `ListEmpty` 버튼 하나(DR5 A). 조직의 「팀 추가」는 본부 행 행동 링크라 1차가 아니다 — E2E 「1차는 「본부 추가」 하나」가 `[data-ui="primary-button"]` 1개를 센다
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 삭제는 `DeleteToArchive`의 `RowAction danger`라 `RowActions` 맨 끝 · 앞 간격 `--s-8` · `--status-danger` 글자(04.6-11 계약 그대로). 사람 「삭제」 간격 E2E(상세↔삭제 `--s-4` 이상) 초록
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 상태 칸은 `StatusTag status`(「보관됨」 · 두 로그인 배지)가 한 번이고 폰 접힌 줄은 `StaticTable`이 P2 값을 PC/폰 택일로 보인다(접근성 트리에서 셀 한 번 — E2E). 사람 상세 제목 아래 메타(이메일)와 KvList 「이메일」은 이관 전부터 있던 둘이라 이 플랜이 바꾸지 않았다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: `ListEmpty message="등록된 사람이 없습니다" · 「등록된 본부가 없습니다」 · 「등록된 계급이 없습니다」`에 쓰기 권한이 있을 때만 등록 버튼 하나(문구 그대로)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 읽기 표(편집 칸은 계급 이름 · 업무 범위 입력이 이전과 같은 네이티브 입력)라 엑셀 키 대상이 아니다. 패널은 첫 입력 포커스 · Tab 가둠 · Esc 닫기 · Ctrl+Enter 제출(`PanelForm`)이고 E2E가 첫 칸 포커스 · Esc 뒤 연 링크로 포커스 복귀를 잰다
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 「상세」 링크 · 「팀 추가」 링크 · 「삭제」 버튼이 모두 `RowAction`이다(글자 크기 · 굵기 · 밑줄 같음 — `admin-people-detail-link.spec.ts`가 `--text-link` · `--text-aux` · `--fw-medium` 계산 값과 비교)
