## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 문구를 더하거나 바꾸지 않았다. 내 계정 부제(이메일)는 `DetailScreen` 메타 한 줄로 글자 그대로 옮겼고, 임시 비밀번호 배너 · 설정 힌트 · 복원 줄 · 가져오기 안내는 기존 그대로다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 폼 동작 · 검증 · 액션(`actions.ts` diff 0)과 설정 켜짐 판정(`isSettingActive`) 불변
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 설정 비활성 select는 `disabled` + `--text-faint` on `--surface-muted` 그대로(settings-approval-route E2E 초록)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 내 계정은 「비밀번호 변경」 1차 하나 · 로그아웃은 2차. 설정은 칸별 저장이고 1차 추가 없음
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 해당 동작 없음. 로그아웃은 폼과 1px 선으로 떨어진 묶음(`accountActions`)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 섹션 제목은 `DetailScreen.Section` h2 하나(내 계정의 「비밀번호 변경」 h2는 폼 안에서 섹션 틀로 옮김 — 중복 없음)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 없음(해당 없음)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 칸 순서·`label`·`aria-describedby` 연결 불변, settings.spec ISSUE-001 · change-password.spec E2E 초록
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 복원/버림은 기존 3차 버튼 모양 그대로(hover 두께만 `--underline-w-hover`)
