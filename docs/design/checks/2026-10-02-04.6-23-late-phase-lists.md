## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 목록 부제 설명문 없음(`ListScreen`에 부제 prop 없음). 남은 문구는 04.3이 정한 막힘 이유 한 줄(「당첨일 비어 있음 · 당첨일 적기」 등 `request-rules.ts` — diff 없음) · 결과 모름 줄 · 계산 줄(열림/마감)뿐이고 이 플랜이 바꾸지 않았다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 이 플랜은 틀 · 여는 방식만 옮겼고 칸(행사 이름 · 당첨일)과 기본값은 04.3 그대로다. 「지금」은 서버가 렌더 때 준 시각(`nowIso`)이라 사용자가 정하지 않는다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 신청 권한(`certs.events` 쓰기)이 없는 계급은 머리 1차 · 빈 화면 링크 · 패널 모두 렌더하지 않는다(`page.tsx` `canRequest`) — E2E 「신청 권한이 없는 계급은 ?new=1로 와도 패널 없이 목록만」 · 막힘은 1차 `aria-disabled` + 이유 줄(PanelForm `blockedReason`)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 머리 1차 「QR 생성 신청」 링크 하나(`ListScreen.primaryAction`), 빈 목록이면 머리 1차 없음 + `ListEmpty` 링크 하나(DR5 A) — E2E (f-0-b) `[data-ui="primary-button"]` 0 + 빈 화면 링크 `href="/certs/events?new=1"`
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이 화면(목록 · 신청 패널)에는 삭제 동작이 없다 — 해당 없음
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 칸 라벨 「행사 이름」 · 「당첨일」은 `TextField` 라벨 하나이고 칸 안 글자(placeholder)가 없다. 열린 동안 「QR 생성 신청」은 여는 링크(뒤, 비활성) + 패널 안 1차 버튼 각각 한 번씩이라 같은 역할이 한 화면에 두 번 활성으로 보이지 않는다(E2E 링크 1 · 버튼 1)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: `ListEmpty message="확인증 행사가 없습니다" action=QR 생성 신청` 링크(권한 있을 때) — 한 줄 「없다 · 다음 한 수」
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 읽기 표라 엑셀 키 대상이 아니다. 링크 Enter로 패널이 열리고 첫 칸 포커스 · Ctrl+Enter 제출 · Esc 닫기(`PanelForm`/`SidePanel` 그대로) — E2E 직접 URL 테스트가 Esc 닫기 · 여는 링크 포커스 복귀를 잰다
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 여는 요소 둘(머리 1차 · 빈 화면 행동)은 둘 다 `next/link`(`scroll={false}`)이고 패널 안은 `PanelForm` 버튼이다. 옛 상태 기반 `Button`을 지워 링크/버튼이 섞이지 않는다
