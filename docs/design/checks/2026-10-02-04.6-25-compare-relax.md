이 작업은 앱 화면 코드를 바꾸지 않는다(`app/`·`ui/`·`docs/design/tokens.css` 변경 0). 비교 오버레이는 `docs/design/explore-skin/relax/`에만 있고 앱이 읽지 않는다.

## 원칙
- [x] 안내 문구: 앱 화면에 문구를 더하지 않았다(앱 변경 0). 보드의 글은 후보 설명 · 비용 · 사실 두 줄뿐이다 — 근거: `relax/index.html`의 NOTES는 후보마다 값 한 줄 + 비용 한 줄
- [x] 결정 최소: UQ-4는 후보별 넣음/안 넣음 한 번, UQ-5는 4를 고를 때만 묻는다 — 근거: SUMMARY 「사용자 결정 질문(채팅)」
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 보드에서 사진이 없는 조합(후보 9의 세 화면 외 · 폰 더보기 · PC 편집)은 「이 조합의 사진은 없습니다」로 안내한다
- [x] 주 버튼 하나: 해당 없음(앱 화면 변경 0) — 근거: 앱 코드 변경 없음
- [x] 위험한 동작은 떨어뜨려 두고 위험 색이다: 해당 없음 — 근거: 앱 코드 변경 없음
- [x] 같은 말을 두 번 하지 않는다 — 근거: 후보 8 사실 두 줄은 보드와 질문에 같은 문장 그대로(복사)이고 설명을 덧붙이지 않았다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다: 해당 없음 — 근거: 앱 코드 변경 없음
- [x] 키보드만으로 끝난다: 해당 없음 — 근거: 보드는 버튼(`button`) 토글이고 포커스 링을 둔다
- [x] 같은 종류의 행동은 같은 모양이다 — 근거: 보드 토글은 전부 같은 `.seg button`

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다 — 근거: 비교는 실제 앱 화면(프로덕션 빌드)에 오버레이를 얹은 사진이다(목업 HTML 아님 · 2026-09-27 결정). 웜톤 바탕 없음 · 견적 줄 입력은 표 안(사진 `edit-*`도 표 안 편집) · 옆 패널 그대로(`vendors-*`)
