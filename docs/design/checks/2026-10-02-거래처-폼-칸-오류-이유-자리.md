# 거래처 폼 칸 오류 · 이유 자리 · 보관 선택지(04.5-06) — 점검표
화면: app/(app)/admin/vendors/vendor-form.tsx, app/(app)/admin/vendors/vendors.module.css
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §6-3 · §7-15 · UI-SPEC(04.5) 화면 3

지금 화면 기준(고치기 전): 서버 오류가 폼 상단 오류 상자(FormAlert)로 폼 맨 아래 자리에 보이고, 커스텀 칸 오류는 어디에도 그려지지 않으며(05가 서버 계약만 만들었다), 커스텀 칸에 브라우저 필수 속성이 붙어 서버 판정보다 먼저 말풍선이 제출을 막는다. 보관된 선택지가 저장값이면 select가 그 값을 잃고 「선택 없음」으로 보여 저장하면 값이 지워진다. 고칠 계획: 칸 아래 오류 + 1차 옆 이유 자리 하나(칸 오류 요약 / 서버 오류) + noValidate + 구분선 + 「(보관됨)」 활성 옵션.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새로 생긴 글자는 칸 오류(「필수 칸 비어 있음 · 값 입력」 등 preserve.ts 상수), 1차 옆 이유 한 줄(「등록할 수 없음 — {칸} N칸 · {칸} 고치기」 · 「수정할 수 없음 — 보관된 거래처 · 새로 불러오기」)과 옵션 글자 「{값} (보관됨)」뿐. 설명문 추가 0 — 모두 오류·잠김이고 명사형이며 error-copy-noun-style 단위 테스트가 통과한다.
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 보관된 현재 값이 select의 선택된 값으로 그대로 남는다(사용자가 다시 고르지 않는다). 막힘 뒤 「{칸} 고치기」가 포커스를 그 칸으로 보내 어디를 고칠지 찾지 않게 한다. 오류 뒤 입력값은 비제어 폼이라 그대로 남는다.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 보관·권한 회수로 재시도해도 안 되는 서버 오류면 1차를 `disabled` + 이유 글자로 막고 다음 한 수 「새로 불러오기」만 둔다(1차 켠 채 같은 실패를 되풀이시키지 않는다). 새 거래처·다른 거래처 폼에는 「(보관됨)」 옵션이 나오지 않는다(저장값이 있을 때만).
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 1차 「거래처 등록/수정」 하나 그대로. 「{칸} 고치기」 · 「새로 불러오기」는 3차(밑줄 텍스트) 버튼이다.
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 해당 없음 — 삭제 버튼·배치를 건드리지 않는다.
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 서버 오류 글자는 이유 자리에 한 번만 나온다(차단이면 Button의 disabledReason 한 곳, 3차 버튼은 글자 없이 「새로 불러오기」만 — E2E가 「수정할 수 없음」 글자 수 1을 단언). 칸 오류는 칸 아래 한 줄, 요약은 칸 이름 + 칸 수만 말해 칸 오류 문구를 되풀이하지 않는다.
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음 — 커스텀 칸이 0개면 구분선을 포함한 묶음 전체를 그리지 않는다(빈 머리·빈 구분선 없음, E2E 「0칸」).
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 칸 순서 그대로 Tab, 「{칸} 고치기」가 button이라 Tab·Enter로 닿고 `document.getElementById(...).focus()`로 그 칸에 포커스한다(E2E toBeFocused). Enter 제출은 그대로.
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 이유 옆 다음 한 수는 모두 ui/button 3차(field-definition-form과 같은 모양). 「취소」는 기존 링크 그대로.

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 옆 패널 폼의 구조·위치를 바꾸지 않았다. 폼 안 줄 하나(이유 자리)·칸 아래 오류·구분선만 더했다. 색은 var(--danger)·var(--line)만 쓴다.
