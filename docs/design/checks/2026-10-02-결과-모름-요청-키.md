## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 두 화면 모두 문구를 더하지 않았다. 결과 모름 줄(`REQUEST_UNKNOWN_TEXT` · `GENERATE_UNKNOWN_TEXT`)과 토스트는 그대로이고, 토스트는 이제 실제로 생긴 행사 이름을 말한다.
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 「같은 요청인가」를 사용자에게 묻지 않는다 — 같은 내용이면 같은 키, 고쳐 보내면 새 요청으로 시스템이 정한다. 결과 모름 동안 칸을 얼리지 않아 오타를 고친 채 바로 다시 보낼 수 있다.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 막힘 판정(`requestBlockReason` · 경품 표 막힘)과 `pending` 동안의 읽기 전용 · `saveLocked`는 그대로다. 선택지 추가 · 제거 없음.
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 패널 1차 「QR 생성 신청」 · 상세 1차 「QR 생성」 하나씩 그대로(JSX 무변경).
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 고친 내용으로 보냈는데 첫 신청이 이미 커밋됐으면 행사가 둘 생긴다 — 확인 창 대신 상세 머리 「신청 취소」로 되돌린다(기존 동작 · 위치 · 색 그대로).
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 문구 · 라벨 변화 없음.
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: EMPTY 3차 「QR 생성 신청」 · 경품 표 「첫 줄 만들기」 그대로.
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 칸 · 표 키 처리 무변경. 결과 모름 뒤 Enter로 다시 보내기도 그대로이고, 경품 표는 결과 모름 뒤에도 엑셀식 편집이 열려 있다.
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 행동 요소 추가 · 변경 없음.
