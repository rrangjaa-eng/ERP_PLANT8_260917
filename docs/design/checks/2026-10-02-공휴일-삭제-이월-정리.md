# 공휴일 삭제 이월 정리 · 빈 목록 「다시 시도」 44px — 점검표

기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §3 터치 · §7-7 EMPTY/ERROR

> 지금 어긋난 점(04.2 /review·/design-review 이월, `.planning/todos/pending/2026-09-26-04-2-review-deferred-p3.md`):
> 1. 결과 줄 칸이 하나라 A를 지운 뒤 B를 지우면 A의 `되돌리기`가 조용히 사라진다.
> 2. 화면을 연 뒤 지울 수 없게 된 행(규칙 행으로 바뀜·자정 지남)을 지우면 `삭제 실패 · 다시 시도`가 뜨지만 다시 해도 성공할 수 없다.
> 3. `ui/list-empty` `.secondary`(ERROR의 「다시 시도」)가 폰에서 69×40 — 옆 `.tertiary`와 달리 700px 미만 44px 규칙이 없다.
> 고칠 계획: 1은 결과 줄이 지운 행을 쌓아 두고 맨 나중 것을 보인다 — 되돌리면 그 앞 것이 다시 보인다(새 글자 없음).
> 2는 서버 거절(루트 오류)이면 원인 앞부분을 실어 `삭제 실패 · 지울 수 없는 공휴일`로 보이고 `삭제`를 치운다(되돌리기 실패와 같은 규칙).
> 연결·서버 실패는 지금처럼 `삭제 실패 · 다시 시도`. 3은 `.secondary`에 폰 `min-height: var(--touch-min)`.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자는 거절 원인 한 줄(`삭제 실패 · 지울 수 없는 공휴일`, 명사형)뿐 — 서버 원인 문구의 앞부분을 쓴다. 결과 줄 글자는 그대로(감사 3폭 lineText)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 되돌리기 순서를 사용자가 고르지 않는다 — 맨 나중 것부터 자동으로 이어 보인다(감사 1b: B 되돌린 뒤 A 줄 · 되돌리기 1개)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 거절된 행은 `삭제` 버튼을 치운다(감사 2: 버튼 0개, 3폭). 연결 실패만 `삭제`를 남겨 다시 시도
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: main 1차 버튼 1개(확정) 그대로 — 감사 primary=1(3폭). 되돌리기·삭제는 3차
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 삭제 모양·자리 변경 없음. 실패 문구 색 = --danger 실측 rgb(155,28,28)(3폭)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 결과 줄에 한 건만 보인다(쌓인 건수를 따로 말하지 않음). 실패 문구에 `다시 시도`와 버튼을 겹쳐 두지 않는다

- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 되돌리면 복원된 행의 `삭제`가 포커스(감사 1b·1c activeElement, 3폭). 새로 지울 때만 `되돌리기`가 포커스를 받는다(E2E)
