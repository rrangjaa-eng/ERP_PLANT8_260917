# I4 정정 주민등록번호 되물음 — 점검표
화면: app/(app)/certs/submissions/[id]/review-form.tsx, app/(app)/certs/submissions/[id]/actions.ts
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md(I4 정정 폼 — 배치 무변경)

변경 범위: 고친 주민등록번호의 검증번호가 맞지 않으면(mismatch, 권고일 뿐 거절 아님) 첫 저장은 저장하지 않고 번호 칸 아래 오류 한 줄만 띄운다 — 같은 번호로 다시 저장하면 저장된다(수령자 제출 `app/c/[token]/intake-flow.tsx`와 같은 규약, QA-001). 번호를 다시 고치면 확인 표시는 풀린다. 마크업 · 클래스 · 색은 그대로이고 상태 하나와 저장 처리만 바뀌며, 문구는 기존 번호 오류 줄(`주민등록번호 맞지 않음 · 앞 6자리와 뒤 7자리 확인`)을 그대로 쓴다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 문구 없음. 되물음은 기존 번호 오류 줄(`fieldErrorText` rrn) 한 줄을 재사용하고 수령자 화면의 되물음도 같은 줄을 쓴다.
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 「확인했다」 체크나 확인 창을 더하지 않았다. 같은 번호로 다시 저장하면 확인으로 보고(시스템이 판정), 번호를 고치면 다시 되묻는다.

- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 「고친 내용 저장」 하나 그대로(JSX 무변경). 되물음 뒤에도 같은 버튼을 다시 누른다.
