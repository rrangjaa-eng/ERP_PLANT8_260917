## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: page.tsx·field-definition-form.tsx에 설명문 0개(제목 「화면 항목」 · 부제 「거래처」 · 칸 라벨 넷 · 버튼 둘뿐). 오류·막힘 문구는 08(E2 행)이 Copywriting 표대로 더한다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 키는 서버가 만들고 화면에 없음(UI-SPEC 화면 2 「키」), 대상은 서버 상수 「거래처」(선택 UI 없음), 타입 기본 「텍스트」. 정렬 기본값(활성 최대 + 1)은 08의 E2 행
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: write 권한이 없으면 「화면 항목 추가」 링크와 폼 자체를 렌더하지 않음(`?new=1`로 와도 폼 없음, page.tsx showForm) · view 없으면 404(E2E 기획 PM 스펙). 타입은 이 플랜이 받는 셋(텍스트·숫자·날짜)만 옵션
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 1차는 폼 제출 「화면 항목 추가」 하나, 목록 행동 링크는 3차(buttonLinkClassName("tertiary")), 「취소」는 2차
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이 플랜에 위험한 동작 없음(삭제·보관은 04)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 필수 체크박스는 라벨 열 「필수」 하나로만 이름 붙임(칸 옆 같은 글자 반복 없음) · 자리 표시 글자 없음 · 폼이 열리면 필터 줄 「화면 항목 추가」 링크를 렌더하지 않음(UI-SPEC 화면 1)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 목록 표가 아직 없는(08) 이 화면의 유일한 내용이 「화면 항목 추가」 링크다 — 설명문 없음. 목록 빈 상태(ListEmpty + 첫 행동)는 08의 E1 행
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 네이티브 input·select·checkbox·submit 버튼·링크뿐이라 Tab 순서대로 이동하고 Enter로 제출된다(이름 칸 autoFocus). 표가 없는 화면
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 이동(「화면 항목 추가」·「취소」)은 링크에 buttonLinkClassName, 제출만 Button(§7-1 「이동은 링크」, holiday-form 선례)
