## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자는 잠김 한 줄 「{등록|수정}할 수 없음 — 화면 항목 변경됨 · 」(명사형, error-copy-noun-style 통과)뿐. 타입 라벨 수정은 글자 변화 없음
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 폼에 없는 칸 오류는 시스템이 판정해 다음 한 수(새로 불러오기)만 내놓음. 입력 칸·기본값 변화 없음
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 폼에 없는 칸 오류면 1차 「거래처 등록|수정」 비활성 + disabledReason(E2E 「필수 칸이 생기면」이 toBeDisabled 단언)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 1차는 그대로 하나, 「새로 불러오기」는 기존 막힘 이유와 같은 3차 버튼
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험 동작 추가 · 이동 없음
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 낡은 칸 이유는 기존 blocked 경로(disabledReason 한 곳 + 3차 버튼)를 그대로 써 이유 글자가 한 번. 낡은 칸이면 칸 오류 요약(fieldErrorsReason)은 내지 않음
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 변화 없음
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 「새로 불러오기」는 네이티브 button(Tab · Enter). 타입 글자는 `<output>`이라 라벨 「타입」이 접근성 이름으로 붙음(E2E getByLabel("타입") 단언)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 새로 불러오기는 보관 · 권한 회수 막힘과 같은 3차 버튼
