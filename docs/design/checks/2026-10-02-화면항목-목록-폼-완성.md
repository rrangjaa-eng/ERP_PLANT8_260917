## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 설명문 0개. 남은 글자는 제목 「화면 항목」 · 부제 「거래처」 · 칸 라벨 · 버튼 · 표 머리글, 그리고 UI-SPEC Copywriting 표 원문인 칸 오류 둘(이름 빈칸 · 정렬 범위) · 이름 충돌 둘 · 폼 이유 줄 · 결과 줄뿐(모두 「원인 · 다음 행동」 또는 결과 한 줄). 목록 빈 상태는 「등록된 화면 항목이 없습니다」 + 첫 행동 링크(쓰기 권한 없는 열람자는 한 줄만)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 타입 기본 「텍스트」, 정렬 순서 기본 = min(활성 최대값 + 1, 999)(활성 없으면 1)를 서버가 계산해 채움(`nextSortOrder`), 키는 서버 생성·화면에 없음, 「하나 더 추가」가 타입·정렬 기본값까지 초기화하고 이름 입력으로 포커스를 보냄
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 쓰기 권한 없으면 「화면 항목 추가」와 폼 자체가 없음 · 「정보 노출표 보기」는 admin.visibility 보기 권한일 때만 · 「보관함에서 복원」은 두 쓰기 권한 + admin.archive 보기 권한이 다 있을 때만(아니면 「이름 바꾸기」 평문) · 재시도로 풀리지 않는 원인(권한 회수)은 1차를 비활성 + 이유 + 「새로 불러오기」
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 폼 1차는 「화면 항목 추가」 하나, 성공하면 그 자리가 결과 줄로 바뀌고 남는 행동은 3차 둘(「정보 노출표 보기」 · 「하나 더 추가」)과 2차 「닫기」. 목록 화면의 행동은 3차 링크 하나
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이 플랜에 위험한 동작 없음(삭제·보관은 04). 서버 오류 줄만 `--danger`
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 막힘 이유는 1차 `Button`의 disabledReason 한 곳에만 쓰고 이유 자리에 다시 쓰지 않음(「추가할 수 없음」 글자 1개를 E2E가 셈) · 폼이 열려 있으면 필터 줄 「화면 항목 추가」 링크를 렌더하지 않음 · 키는 어느 열에도 없음
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 목록이 비면 ListEmpty 「등록된 화면 항목이 없습니다 · 화면 항목 추가」 한 줄(§7-7). 등록 폼은 빈 상태 없이 기본값이 채워진 채 열림
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 네이티브 input·select·checkbox·submit 버튼·링크뿐이라 Tab·Enter로 끝남(이름 칸 autoFocus, 성공하면 결과 줄 포커스, 「하나 더 추가」는 이름 칸 포커스). 읽기용 표(셀 편집 없음)라 엑셀 키 구성 해당 없음
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 이동은 링크(「화면 항목 추가」 · 「취소」 · 「정보 노출표 보기」 · 「보관함에서 복원」), 같은 화면에서 일어나는 일은 버튼(제출 · 「하나 더 추가」 · 「새로 불러오기」 · 「닫기」) — §7-1 「이동은 링크」. 제출 중 「취소」는 비활성 표현의 같은 모양 요소로 바뀜
