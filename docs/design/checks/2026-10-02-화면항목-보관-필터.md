# 화면 항목 보관 · 보관 포함 필터 · EMPTY · ERROR · 폰(04.5-04) — 점검표
화면: app/(app)/admin/field-definitions/
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §6-1 · §7-3 · §7-7 · 04.5-UI-SPEC 화면 1 · E1 · E3(개정 3)

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자는 토글 「보관 포함」/「보관 제외」 · 상태 「보관됨」 · EMPTY 「조건에 맞는 건이 없습니다 · 필터 지우기」(SYSTEM §7-7 필터 결과 0 원문) · ERROR 「화면 항목 불러오기 실패 · 다시 시도」뿐. ERROR는 UI-SPEC 「…불러오지 못했습니다」를 error-copy-noun-style(사용자 결정 2026-09-26)에 맞춰 명사형으로(공휴일 · 노출표 화면과 같은 꼴). 삭제 확인 문구는 공유 `DeleteToArchive` 그대로(기록된 예외 SYSTEM.md 715행)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 필터 기본값 = 보관 제외. 두 EMPTY 중 어느 것을 보일지는 서버가 보관 포함 건수로 가른다. 토글 · 필터 지우기 · 수정 링크가 열린 폼과 필터 쿼리를 지켜 사용자가 다시 고르지 않는다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 「삭제」는 `admin.archive` write AND `admin.field-definitions` write일 때만 렌더(소스 검사 단위 + 권한 조합 E2E 두 건). 보관 행은 「수정」 · 「삭제」 없음(복원은 보관함), `?editId=<보관 id>`도 폼 없음. 칸 관리 보기 권한이 없으면 보관함 목록에 칸 정의 행이 없어 누를 수 없는 「복원」이 없다
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 목록 화면의 행동(토글 · 화면 항목 추가 · 수정 · 삭제 · 필터 지우기)은 전부 3차. 1차는 폼 제출과 삭제 확인의 「삭제」뿐(공유 컴포넌트)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 「삭제」는 「수정」에서 `--s-4` 떨어진 3차(행 동작 간격 vendors와 같은 값), 되돌릴 수 있는 보관이라 확인은 인라인 두 단계(SYSTEM §7-1 · 715행 기록된 예외 — 붉은 버튼 쓰지 않음)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 보관 행의 「보관됨」은 PC에서 상태 열 하나, 폰에서는 상태 열이 숨고 동작 자리 하나(같은 순간 둘 다 보이지 않음 — `.phoneOnly`). 폼이 열리면 「화면 항목 추가」 링크가 필터 줄 · EMPTY 어디에도 없다(E2E가 0개를 셈). 접힌 줄에 상태를 넣지 않는다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 전체 0건이면 「등록된 화면 항목이 없습니다 · 화면 항목 추가」(쓰기 없음 · 폼 열림이면 한 줄만), 필터 0건이면 「필터 지우기」가 다음 한 수
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 토글 · 수정 · 필터 지우기 · 다시 시도는 링크(Tab · Enter), 삭제 · 확인 · 취소는 버튼. 읽기용 목록이라 셀 편집 없음
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 이동(토글 · 화면 항목 추가 · 수정 · 필터 지우기 · 다시 시도)은 링크, 같은 화면에서 일어나는 일(삭제 · 확인 · 취소)은 버튼. 토글은 「화면 항목 추가」와 같은 3차 링크 모양
