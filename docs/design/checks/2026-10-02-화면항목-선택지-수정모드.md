# 화면 항목 선택지 편집기 · 수정 모드 · 보관 선택지(04.5-02) — 점검표

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 설명문 0개. 새로 생긴 글자는 칸 라벨 「새 선택지」 · 버튼(「선택지 추가」 · 「삭제」 · 「새 화면 항목 추가」 · 「새로 불러오기」 · 「목록으로」 · 「닫기」) · 오류/잠김 한 줄(「선택지 비어 있음 · 선택지 적기」 · 「이미 있는 선택지 · 다른 이름 적기」 · 「선택지는 30개까지 · 쓰지 않는 선택지 삭제」 · 「추가|수정할 수 없음 — …」)뿐이고 모두 「원인 · 다음 행동」 명사형(UI-SPEC의 「~습니다」는 error-copy-noun-style 테스트와 사용자 결정 2026-09-26에 맞춰 뜻 그대로 명사형으로 옮김). 타입을 바꾸는 길(새 칸 만들기)은 설명 없이 3차 링크 「새 화면 항목 추가」로만 보임
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 수정 폼은 이름·필수·정렬·선택지를 연 행 값으로 채움, 보관 선택지 목록은 서버가 `(저장 ∪ 보관) − 제출`로 파생해 사용자는 보관을 따로 고르지 않음, 보관 선택지와 같은 글자를 다시 적으면 활성으로 돌아와 「복원」 결정이 없음, 숨은 `version`은 폼이 싣고 사용자는 모름
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 활성 30개면 「선택지 추가」 비활성 + 이유, 선택형 활성 0개면 1차 비활성 + 이유, 보관된 칸·없는 칸·권한 회수는 1차 비활성 + 이유 + 다음 한 수 3차, 타입은 수정 모드에서 텍스트로만 보임(select 아님), 보관 선택지에는 버튼 없음, 쓰기 권한 없으면 목록 「수정」 링크 없음
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 폼 1차는 「화면 항목 추가」 또는 「화면 항목 수정」 하나. 선택지 추가·삭제, 새 화면 항목 추가, 새로 불러오기, 목록으로는 3차(밑줄 글자)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 선택지 「삭제」는 저장 전엔 목록에서 빠지고 저장 후엔 보관으로 옮겨질 뿐 되돌릴 수 있어(같은 글자를 다시 적으면 활성 복귀) 확인 창 없음. 영구 삭제 동작 없음. 오류 줄만 `--danger`
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 재시도 불가 이유는 1차 `disabledReason` 한 곳에만(E2E가 「수정할 수 없음」 글자 1개를 셈), 보관 선택지는 텍스트 + 「보관됨」 한 번, 폼이 열려 있으면 필터 줄 「화면 항목 추가」 링크를 렌더하지 않음
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 선택형 활성 0개면 선택지 목록은 비고 바로 아래 새 선택지 입력 + 「선택지 추가」가 첫 행동, 1차 이유 「선택지 0개 · 선택지 추가」. 보관 선택지 0개면 펼침 자체를 렌더하지 않음
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 새 선택지 입력의 Enter가 제출 대신 추가(한글 조합 중 Enter는 무시 — 소스 검사 단위 테스트), 추가·삭제 뒤 포커스는 새 선택지 입력, 「새로 불러오기」 뒤 이름 입력 포커스, 성공 뒤 결과 줄 포커스, 보관 펼침은 네이티브 `details`/`summary`(Enter·Space 토글)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 이동은 링크(「수정」 · 「새 화면 항목 추가」 · 「취소」), 같은 화면에서 일어나는 일은 버튼(「선택지 추가」 · 「삭제」 · 「새로 불러오기」 · 「목록으로」 · 「닫기」), 보관 펼침 `summary`는 3차 버튼과 같은 글자 모양
