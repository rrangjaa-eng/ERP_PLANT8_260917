## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 문구를 더하지 않았다. `PanelForm.handleSubmit`의 동기 제출 잠금(ref)만 더했고 DOM 출력은 그대로다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 입력·기본값 변경 없음. 연속 제출은 사용자가 막을 것 없이 시스템이 한 번으로 줄인다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 제출 중 1차 `pending` · Ctrl+Enter 무시는 그대로, 같은 틱의 두 번째 제출도 같은 방식으로 무시한다
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 행동 줄 마크업·순서 불변(취소 → 1차)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 해당 동작 없음(코드 변경 없음)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 문구 변경 없음
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 아님(패널 폼 내부 로직만)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: Ctrl+Enter 제출 · Esc 닫기 불변. 연타는 한 번으로 줄고 `side-panel.spec.ts` 연타 단언이 그대로 선다
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 버튼 컴포넌트 변경 없음
