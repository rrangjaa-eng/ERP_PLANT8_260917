# 표 마지막 행 선 없음 F1(04.6-07) — 점검표
화면: ui/table/
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §2-4

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 문구를 더하거나 바꾸지 않았다. CSS 선택자 한 줄만 바꾼다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 사용자 입력·결정이 없는 표 선 규칙이다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 선택지를 건드리지 않았다
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 버튼을 건드리지 않았다
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 행 행동을 건드리지 않았다
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 문구 변화 없음
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면을 건드리지 않았다
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 키 동작 변화 없음
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 행동 모양 변화 없음

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 스킨 A의 「마지막 행 선 없음」(SYSTEM §2-4)을 PC 폭에서도 지키게 하는 수정이라 결정을 어기지 않는다

## 시스템
- [x] 새 색·서체·radius·그림자를 만들지 않았다(tokens.css 변수만) — 근거: 기존 `--line-w` 선 토큰을 쓰는 규칙의 선택자만 바꿨고 새 값이 없다
- [x] 폰 320에서 가로 넘침 없음 · 터치 44px — 근거: 폰(<700) 규칙은 그대로이고 `mobile-320-no-overflow.spec.ts`(`expectFoldAttached`)가 초록이다
- [x] 실제 앱 화면(PC 1280 · 폰 390)을 찍어 보고 확인했다 — 스크린샷 경로: 찍지 않음 — 화면 판정은 `CI=true` DOM 실측이다(CLAUDE.md §6). 증명: `vendors.spec.ts` 「거래처 표 마지막 행 선 없음」 1280 computed border-bottom-width
