## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 두 화면 목록 부제 설명문 없음(`ListScreen`에 부제 자리가 없다). 법인카드 소유자 변경 패널의 「{별칭} 소유자 변경」 한 줄(`.hint`)은 대상 표시이고 기존 문구 그대로, 오류는 패널 행동 줄 위 한 줄(`PanelForm reason`)뿐이다. 코드표는 고른 표 이름을 부제 대신 현재 링크 표시(색·굵기·밑줄)와 표 caption이 맡는다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 등록 성공 뒤 패널이 열린 채 칸이 비고 첫 칸에 포커스(UQ-8 B)라 이어서 입력하며 닫기 위해 따로 결정할 것이 없다. 폼 입력 칸·기본값은 바꾸지 않았다(종류 select 기본 「개인」 · 코드 추가 칸 그대로)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: `canWrite`·`canArchive` 분기를 그대로 둬 권한 없는 행동·패널은 렌더하지 않는다(`code-tables-write-gate.spec.ts`가 `?new=1`에서 `dialog` 0개 단언). 보관된 카드는 행동 칸을 비운다(`card.archivedAt ? null`)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 머리 1차 「법인카드 등록」·「코드 추가」 하나(`ListScreen.primaryAction`), 빈 목록이면 머리 1차 없음 + `ListEmpty` 버튼 하나(DR5 A). 원칙 막는 모드 E2E(`corp-cards.spec.ts`)가 두 화면 여섯 라우트에서 경고 0
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: `RowActions`의 danger가 맨 끝 · 앞 간격 `--s-8` · `--status-danger` 글자(04.6-11이 만든 공용 모양). 법인카드·코드표 행 동작 간격 E2E(1280·768·700)로 확인
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 상태는 `StatusTag status`(「보관됨」·「비활성」) 한 번이고, 폰 접힌 줄은 `StaticTable`이 같은 칸을 PC/폰 택일로 보이는 것이다. 패널 제목 「법인카드 등록」과 1차 라벨 「법인카드 등록」은 04.6-04 패널 틀의 기존 구조(제목 = 대상, 1차 = 행동)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: `ListEmpty message=… action={법인카드 등록 | 코드 추가}` 그대로
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 읽기 표라 엑셀 키 대상이 아니다. 패널은 `PanelForm`의 Ctrl+Enter 제출 · Esc 닫기(DR1 A) · 행동은 네이티브 링크·버튼(`RowAction`)이라 Tab·Enter로 닫힌다
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 「수정」 링크 · 「활성화/비활성화」·「삭제」 버튼이 `RowAction` 한 컴포넌트라 글자 크기·굵기·밑줄이 같다(원칙 막는 모드 테스트가 같은 행동 모양 경고를 잡는다)

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 한 건 폼(법인카드 등록·소유자 변경·코드 추가)은 옆 패널(PC 오른쪽 480 · 폰 아래 시트)이고 목록을 밀지 않는다. 표는 `StaticTable`(흰 표 면 r8 · 1px)이며 새 색을 만들지 않았다. 견적 표와 무관한 화면이다
