## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 상태 줄을 문단(`p`)에서 `div`로 바꿔 「확정 · 시각 확정자 · 공휴일 N일」이 설명문이 아니라 값 줄이 되었다(원칙 점검 「긴 설명」 경고 1건이 이 때문에 사라짐 — 막는 모드 E2E 4개 라우트 경고 0). 남은 문구는 막힘 이유 · 「추가 실패 · 다시 시도」 · 삭제 실패 · 「되돌리기 실패 · 원인」 · 결과 줄 「삭제됨」 뿐이고 이 플랜이 바꾸지 않았다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 종류는 「임시공휴일」이 미리 골라져 있고(`holiday-form.tsx` 기본값 그대로) 날짜 `min`·`max`는 서버가 계산한다. 확정 버튼은 확정 가능한 해(`canConfirmYear`)에만 보인다. 확정 뒤에 묻는 것은 없다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 쓰기 권한 없는 계급은 「공휴일 추가」·확정·삭제와 패널 자체를 렌더하지 않는다(`holidays.spec.ts` R15 — 권한 없는 `?new=1`에서 `dialog` 0개). 삭제 거부 행의 「삭제」는 이유를 단 `aria-disabled`(`RowAction disabled disabledReason`). 입력이 덜 찬 폼은 이유를 단 비활성 1차
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: DR2 A(`04.6-ANSWERS.md`) — 확정 버튼이 보이는 해는 「{year}년 공휴일 확정」이 1차이고 「공휴일 추가」는 필터 줄 2차 링크, 그 밖의 해는 「공휴일 추가」가 `primaryAction`. E2E가 확정 전 해·확정 뒤 해 두 URL에서 `[data-ui="primary-button"]` 1개를 단언. 빈 목록은 머리 1차 없이 `ListEmpty` 버튼 하나(DR5 A)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 「삭제」는 `RowAction danger`(맨 끝 · `--status-danger`), 결과 줄 「되돌리기」는 `danger` 없는 `RowAction`이라 위험 색이 아니다(D21 — E2E가 두 계산 색을 비교)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 「공휴일 추가」는 한 화면에 진입 링크 하나만 있다(1차와 필터 줄 링크를 같이 그리지 않고 빈 목록의 버튼도 머리 1차와 겹치지 않는다 — E2E DR5 A). 상태는 `StatusTag status` 한 번. 폰 접힌 줄은 `StaticTable`의 PC/폰 택일 표시
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: `ListEmpty message="등록된 공휴일이 없습니다"` + 쓰기 권한이면 「공휴일 추가」 버튼 하나(`page.tsx`)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 읽기 표라 엑셀 키 대상이 아니다. 패널은 `SidePanel`/`PanelForm`의 Esc 닫기·Ctrl+Enter 제출·첫 입력 포커스를 그대로 쓴다. 삭제 뒤 결과 줄 「되돌리기」에 포커스가 가고 복원된 행의 「삭제」가 `autoFocus`를 받는다(`holidays.spec.ts` 포커스 단언 초록)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 행 행동 「삭제」와 결과 줄 「되돌리기」가 둘 다 `RowAction` 한 컴포넌트다(링크가 아닌 버튼 형)
