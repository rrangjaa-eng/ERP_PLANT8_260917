## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 목록 부제 설명문 다섯(내 차례 「지금 처리할 항목」 · 지출결의 · 법인카드 · 손익 · 설정)을 `PageHeader subtitle`에서 지웠고 `ListScreen`에는 부제 prop이 없다. 남은 문구는 빈 화면 한 줄 · 오류 화면 「화면 불러오기 실패」 · 404 「페이지 없음 또는 이동됨」 · 알림함 「불러오기 실패」 · 「이메일 발송 실패」뿐이고 문구는 바꾸지 않았다(막는 모드 E2E 여섯 라우트 경고 0건)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 입력 칸이 없는 조회 화면이다. 알림함은 열면 읽음 처리가 자동이고(`openInboxAction` 불변) 「모두 읽음」 같은 선택이 없다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 손익의 「리저브 대장」 링크는 `pnl` 보기 + `reserve.amount` 노출일 때만 그린다(조건 불변). 더 보기 요청 중 버튼은 `pending`으로 비활성이고 열기 전에도 비활성(경합 방지, 불변)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 여섯 화면 모두 머리 1차가 없고(조회·자리 화면 — `ListScreen primaryAction` 없음, `[data-ui="primary-button"]` 0개 · 원칙 점검 「1차 버튼」 경고 0) 다음 행동은 빈 화면의 2차 버튼 하나다
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 해당 없음 — 이 여섯 화면과 오류·404에 삭제·되돌릴 수 없는 행동이 없다. 오류 톤은 `ListEmpty tone="error"`가 글자 색만 바꾼다
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 제목은 틀의 `h1` 하나이고 알림함 표 캡션 「알림함」은 `sr-only`다. 안 읽음은 `sr-only` 글자 + 왼쪽 선 하나(색만이 아닌 글자 대체)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 자리 넷 · 내 차례 · 오류 · 404 모두 `ListEmpty` 한 줄 + 2차 버튼 하나(`page-chrome.spec.ts` 「자리 화면 넷」이 `[data-ui="empty-state"]` 안 링크 하나를 단언). 알림함 0건은 행동 없는 정상 빈 상태라 명시 생략(SYSTEM §7-12, 기존 그대로)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 알림함 표는 읽기 표(엑셀 키 대상 아님). 더 보기 · 다시 시도는 `Button`이라 Tab·Enter이고, 더 보기 뒤 새 행에 포커스가 가는 동작을 `[data-inbox-row]`(tabIndex -1)가 그대로 맡는다(`notify-inbox.spec.ts` 「51건」 포커스 단언 초록)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 빈 화면 행동은 전부 `ListEmpty`의 2차 링크이고 오류 경계의 「다시 시도」만 이동이 아니라 같은 2차 모양의 버튼이다(`ListEmpty` 기존 규칙). 손익의 「리저브 대장」 3차 링크는 이 플랜이 건드리지 않았다
