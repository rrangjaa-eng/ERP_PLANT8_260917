## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 두 화면의 부제 설명문은 이미 없었고(`PageHeader title`만) `ListScreen`에는 부제 prop이 없다. 남은 문구는 빈 화면 「기록된 행동이 없습니다」 · 「조건에 맞는 건이 없습니다」 · 「보관함이 비어 있습니다」, 정리 확인 줄 「N건을 정리합니다 · 정리 기록은 남습니다」(되돌릴 수 없는 일), 토스트 「복원 · 실패 · 원인」뿐이고 이 플랜이 바꾸지 않았다 적립금: 제목 아래 설명형 부제 「클라이언트별 리저브 입출금」을 삭제했고(`ListScreen`에는 부제 prop이 없다) 힌트 줄을 문단(`p`)에서 `div`로 바꿔 원칙 점검의 「긴 설명」 경고 1건이 사라졌다 — 막는 모드 E2E `/pnl/reserves` 경고 0. 남은 문구는 빈 화면 · 오류 · 복원 줄 · 저장 이유뿐이고 바꾸지 않았다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 필터는 모두 「전체」 기본이고 값을 바꾸면 즉시 조회한다(이 플랜이 바꾸지 않음). 보관함 복원은 확인 없이 즉시 실행하고 결과를 토스트로 알린다(되돌리기 대신 확인 창을 두지 않는 기존 동작 그대로) 적립금: 표 안 편집 · 저장 · 붙여넣기 · 쪽 이동 동작과 `actions.ts`는 바꾸지 않았다(reserves.spec 36건 초록)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 고를 사람이 없으면 「사람」 칸째 숨김(`filter-bar.tsx` `people.length > 0` 그대로 — `action-log-filter-people.test.ts` 초록). 복원할 수 없는 행(지난 날짜 공휴일 · 날짜 점유 · 도메인 거부)은 「복원」 대신 칸에 「—」(`restorable` · `rejected` 조건 그대로). 정리할 행이 0건이면 이유를 단 `aria-disabled`(`action-log.spec.ts` DR-11 초록) 적립금: 쓰기 권한 없는 계급은 「일괄 저장」 · 줄 추가가 없고 편집 칸도 열리지 않는다(reserves.spec 읽기 표 테스트 초록)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 두 화면 모두 읽기 중심이라 머리 1차가 없다(`ListScreen primaryAction` 없음). 행동 로그의 「Excel 내보내기」는 2차, 「정리」는 3차, 보관함 「복원」은 행 행동이다 적립금: 1차는 표 위 오른쪽 끝 「일괄 저장」 하나(보이는 `primary-button` 1개 — E2E), 뼈대에는 1차 없음(D10 E2E)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 보관함 「복원」은 위험 동작이 아니라 `RowActions` 안 `RowAction`(위험 색 없음 — E2E가 계산 색이 `--status-danger`가 아님을 잰다). 행동 로그 「정리」는 두 단계 확인(확인 줄에 정리 기록이 남는다고 명시)이고 이 플랜이 바꾸지 않았다. 이 화면에는 삭제가 없다(`DeleteToArchive`는 다른 화면이 쓰며 파일 diff 없음) 적립금: 줄 삭제는 확인 창 뒤 일괄 저장으로 보관되고 이 플랜이 바꾸지 않았다(reserves.spec 삭제 테스트 초록)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 표 머리글과 칸 값이 겹치지 않는다. 폰 접힌 줄은 `StaticTable`이 P2 값 앞에 머리글 라벨을 붙이고(PC에서는 숨김) 값 칸이 「—」면 줄에 그대로 둔다(거래처 표와 같은 규칙) 적립금: 금액 · 잔액 · 세금계산서 번호는 `Num` 한 곳에서 서식한다(표 칸과 그룹 머리글 문장은 서로 다른 값)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 행동 로그 빈 화면은 `ListEmpty` + 「필터 지우기」 링크 그대로. 보관함이 비어 있는 것은 해소할 상태가 아니라 정상이라 행동을 두지 않는다(DECISIONS 2026-09-20 EMPTY 예외 — `archive-table.tsx` 주석 그대로) 적립금: 빈 대장은 `Table`의 `emptyMessage` + 「리저브 줄 추가」 버튼 그대로(reserves.spec 트레이서 초록)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 두 표는 읽기 전용이라 엑셀 키 대상이 아니다. 필터 select · 날짜 · 체크박스는 네이티브 칸이고 「복원」 · 「필터 지우기」는 Tab으로 닿는다(`RowAction` 네이티브 button · `next/link`) 적립금: 엑셀 키(방향키 · Enter · Ctrl+V · Ctrl+Enter · Ctrl+S)는 `Table` 그대로이고 reserves.spec 붙여넣기 · 저장 테스트가 초록이다
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 보관함 행 행동이 손으로 만든 3차 버튼에서 공용 `RowAction`으로 바뀌어 다른 관리 표(거래처 · 공휴일)의 행 행동과 모양 · 간격이 같다. 「필터 지우기」는 `next/link` 3차 링크 하나. 적립금: 「복원」 · 「버림」은 기존 3차 버튼 모양 그대로(폰 44 E2E 초록), 쪽 이동은 공용 `Pagination`
