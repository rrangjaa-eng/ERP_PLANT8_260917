## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 행사 상세의 긴 메타 한 줄(당첨일 · 담당 · 마감)은 원칙 점검이 「긴 설명」으로 잡아 라벨·값 목록(`KvList` — 당첨일 / 담당 / 마감 또는 신청)으로 바꿨다. 확인증 정정 메타는 「번호 · 제출 시각」으로 줄이고 행사 이름·대조 제외 시각은 `KvList` 행(행사 / 대조 제외)으로 옮겼다. 남은 문구는 「제출이 없습니다」 · 닫힘 줄 · 오류·막힘 이유 줄뿐이다. 외부 수령자 문의 한 문장은 CSS 전용 플랜이라(문구 diff 0) 지우지 못했고 `principles-certs.spec.ts`가 그 문장만 허용한다 — 사용자 질문 후보로 SUMMARY에 적었다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 화면은 대조를 판정하지 않는다(N13 a) — 초과 건수 · 같은 연락처 · 파기 대상은 서버가 준 값을 그대로 그린다. 입력 칸·기본값·확인 흐름은 바꾸지 않았다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 머리 2차 「링크 닫기」 · 「신청 취소」 · 「대조 제외」 · 「인쇄」의 서버 판정 분기(`canClose` · `cancelRole` · `canExclude` · `excluded || rrnCleared`)와 비활성 이유(`disabledReason`)는 코드 그대로고 `DetailScreen` 행동 자리로 자리만 옮겼다
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 행사 상세 머리에는 2차만(`actions.secondary`) · 1차는 경품 표 아래 「QR 생성」 · 「일괄 저장」 하나(`primaryRow`, 코드 그대로). 정정은 머리 2차 + 폼 1차 「고친 내용 저장」 하나. 원칙 막는 모드 E2E `principles-certs.spec.ts`(다섯 라우트 경고 0)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 삭제 없음. 「대조 제외」(되돌릴 수 없음)는 확인 창(`ConfirmDialog`)을 거치고 머리에서 「인쇄」 왼쪽 · 정정 1차와 반대쪽 끝이다(UD-2 a — 위치 그대로)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 상태는 `StatusTag status` 낱말 하나(제목 옆), 제출 표 그룹 머리글에 상태 글자 없음. 폰 접힌 줄은 `ui/table` 폰 전용 표시(PC에서 숨김)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 제출이 없으면 「제출이 없습니다」 한 줄(읽기 전용 목록 — 행동 대상 없음, 지금 문구 그대로), 경품 표 빈 상태는 `Table`의 `emptyMessage` · 첫 줄 만들기(코드 그대로)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 제출 표는 읽기 표(편집 칸 0)라 엑셀 키 대상이 아니다. 「제출 내용」 링크는 줄마다 Tab 정지(`cert-reconcile` tracer가 Tab으로 다음 줄 링크 포커스 확인), 폰 접힌 줄은 `td[role=button]` Enter·Space(`Table` 공용). 경품 편집 표 키보드(`enableGridKeyboard`)는 그대로
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 「제출 내용」은 줄 링크 · 시트 링크 둘 다 같은 3차 링크 모양(`rowLink`, hover 밑줄 `--underline-w-hover`). 미리 가져오기 금지(`prefetch={false}`)라 `RowAction`이 아니라 `next/link`를 그대로 쓴다
