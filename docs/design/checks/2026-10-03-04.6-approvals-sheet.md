# 결재함 PC 행 → 오른쪽 480 결재 시트 (DR4 A 이행) — 점검표
화면: app/(app)/approvals/, docs/design/SYSTEM.md, docs/design/DECISIONS.md
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §6-1 결재함 줄 · §7-8 시트 줄

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 문구를 더하지 않았다. 행의 문서 칸이 링크에서 같은 글자의 버튼으로 바뀌었을 뿐이다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 시트를 열면 첫 포커스가 「승인」이라 결재자가 고를 것이 없다(SidePanel 계약 그대로). 입력 칸 없음
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 시트 행동 줄은 서버 가능 행동(`item.actions`)만 그린다 — 코드 변경 없음. 결재 정보가 꺼진 계급은 `row.sheet`가 null이라 시트 대상 자체가 없고 문서 링크가 남는다
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 시트 안 1차는 「승인」 하나(반려는 2차). 목록 머리에 1차 없음(D10) 그대로
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 행의 승인↔반려 간격 `--s-4`, 시트에서는 반려 왼쪽·승인 오른쪽 `--s-4` 이상 — 변경 없음
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: PC 문서 칸에 링크와 버튼을 함께 두지 않고 시트 대상 행은 버튼 하나만 둔다(같은 문서 글자 한 번)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 목록 경로(ListScreen) 변경 없음
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 문서 칸 버튼에 Tab으로 가서 Enter가 시트를 열고, 첫 포커스 「승인」, Esc가 닫고 연 버튼으로 돌린다 — E2E `PC 1280/768 … Enter` 실측
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 문서 칸 버튼은 3차 링크 모양(`--accent` 밑줄)이라 처리함 행의 문서 링크와 같은 모양으로 읽히고, 폰은 기존 전폭 행 모양 그대로
