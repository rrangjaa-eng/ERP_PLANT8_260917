## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 문구 변경 없음, CSS만 바뀜
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 사용자 입력 변화 없음
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 선택지 변화 없음
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 버튼 변화 없음
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 동작 변화 없음
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 글자 변화 없음
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 변화 없음
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 포커스·키 동작 변화 없음
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 행동 변화 없음

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 색·간격·글자 척도 불변, white-space 두 줄만 추가

## 시스템
- [x] 새 색·서체·radius·그림자를 만들지 않았다(tokens.css 변수만) — 근거: `white-space: nowrap`만 추가, 새 값 없음
- [x] 폰 320에서 가로 넘침 없음 · 터치 44px — 근거: mobile-history-list.spec.ts D1 DOM 실측(@320·@375 문서 scrollWidth ≤ clientWidth, 날짜 칸 Range 줄 수 1, 「값」「상태」「동작」 머리글 줄 수 1) 통과, 터치 목표 기존 스펙 통과
- [x] 실제 앱 화면(PC 1280 · 폰 390)을 찍어 보고 확인했다 — 스크린샷 경로: 육안 판정 금지 규칙에 따라 DOM 실측(Playwright)으로 대체
