# 04.6-19 인쇄 확인증 404 화면 틀 이관 — 점검표
화면: app/print/certs/not-found.tsx
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §6-9

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 문구는 그대로 「페이지 찾을 수 없음」 제목 + 「페이지 없음 또는 이동됨」 한 줄(app/not-found.tsx와 같은 말). 더한 문구 없음
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 입력 없는 오류 화면. 돌아갈 곳은 「첫 화면으로」 하나
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 선택지 없음(링크 하나)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: ListEmpty의 「첫 화면으로」 하나만 있고 틀 머리 행동(actions)은 비어 있다
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험 동작 없음
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 제목(찾을 수 없음)과 메시지(없음 또는 이동됨)는 기존 문구 그대로이고 이번에 바뀌지 않았다. PageHeader 제거로 제목은 h1 하나뿐
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: ListEmpty 구조 변경 없음(메시지 한 줄 + 첫 화면으로 버튼)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 링크 하나, Tab/Enter. DetailScreen h1은 tabIndex -1(탭 순서에 안 들어감)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: app/not-found.tsx와 같은 ListEmpty 행동

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 인쇄 라우트 바탕(print-cert.module.css .root)은 그대로, 틀은 이미 이관된 app/not-found.tsx와 같다. 새 결정 없음(오케스트레이터 결정 2026-10-03: 갭 플랜 대신 합본 처리)

## 시스템
- [x] 새 색·서체·radius·그림자를 만들지 않았다(tokens.css 변수만) — 근거: CSS 파일을 건드리지 않았다. 제목 크기는 DetailScreen 역할 토큰(--text-title)로 옛 titleSize 2xl이 사라진다
- [x] 폰 320에서 가로 넘침 없음 · 터치 44px — 근거: DetailScreen·ListEmpty는 이관된 공용 틀(W5 감사에서 넘침 0). 이 경로의 4폭 실측은 웨이브 합본 감사 대상에 넣는다
- [x] 실제 앱 화면(PC 1280 · 폰 390)을 찍어 보고 확인했다 — 스크린샷 경로: 이 커밋에서는 찍지 않음. cert-print.spec 404 3곳이 제목 heading 가시성을 실측하고, 4폭 캡처·DOM 실측은 웨이브 합본 감사(오케스트레이터) 대상 /print/certs/<없는 id>
