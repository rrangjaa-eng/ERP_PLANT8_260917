## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 문구를 더하지 않았다. 바뀐 것은 PC 폼 라벨 칸 폭(CSS 한 규칙)뿐이다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 입력·기본값 로직 변경 없음
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 선택지 변경 없음
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 버튼·행동 줄 변경 없음
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험 동작 변경 없음
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 라벨·칸 글자 변경 없음
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 변경 없음
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 마크업·탭 순서 변경 없음(CSS만)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 행동 요소 변경 없음

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 색·패널·견적 표 변경 없음. 입력 칸 x(라벨 열 96 + --s-2)와 폭은 그대로라 SYSTEM §6-3 「PC 폼 라벨은 왼쪽 96px」 열이 유지된다

## 시스템
- [x] 새 색·서체·radius·그림자를 만들지 않았다(tokens.css 변수만) — 근거: `calc(var(--label-w) + var(--s-1))` · `calc(-1 * var(--s-1))`뿐이다. stylelint로 확인
- [x] 폰 320에서 가로 넘침 없음 · 터치 44px — 근거: 규칙은 `@media (min-width: 700px)` 안이라 폰(<700)에는 적용되지 않는다
- [x] 실제 앱 화면(PC 1280 · 폰 390)을 찍어 보고 확인했다 — 스크린샷 경로: 찍지 않음 — 판정은 `CI=true` DOM 실측(CLAUDE.md §6). 증거: `test/e2e/safari-width-headroom.spec.ts`(768·1280 라벨 칸 100 · 입력 x 104)
