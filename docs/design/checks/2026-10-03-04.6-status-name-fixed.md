## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 문구 없음. 코드표 이름 칸은 입력 대신 글자만(셀 단계 읽기 전용 모양), 이유 문구를 화면에 두지 않는다. 서버 거부 문구 「프로젝트 상태 이름은 고정 · 변경 불가」는 화면에서 입력이 없어 우회 호출에만 나온다(명사형 한 줄)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 상태 이름을 관리자가 정하던 결정이 사라졌다(고정 낱말 한 표 domain/projects/status-word.ts)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: project_status 다섯 값의 이름 입력 칸을 없애고 글자로 보인다. 다른 표·다른 열(설명·정렬·활성)은 그대로
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 변경 없음(코드표 「코드 추가」 1차 그대로)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 변경 없음(RowActions 그대로)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 같은 상태가 코드표 라벨과 배지 두 이름으로 보이던 것을 한 표로 모았다. 목록·상세에 중복이던 PROJECT_STATUS_WORD 둘도 한 모듈로
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 변경 없음
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 이름 칸이 입력에서 글자로 바뀐 것뿐, 설명 입력 등 나머지 탭 순서 그대로
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 보관·쓰기 불가 행과 같은 결(글자만)
