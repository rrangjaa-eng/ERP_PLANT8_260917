## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 문구를 더하지 않았다. 바꾼 것은 칸 우선순위(P1→P2)·여백·낱말 줄바꿈 CSS뿐이다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 입력·기본값 변경 없음(`roles-client.tsx`는 `priority` 두 값만 바뀜)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 권한·비활성 로직을 건드리지 않았다(diff에 `can`·`disabled` 변경 0줄)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: `ListScreen` 1차 구조 그대로, 조직·계급·공휴일 모두 `[data-ui="primary-button"]` 불변
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: `RowActions` danger 구조 그대로(행동 칸 코드 변경 없음)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 공휴일 날짜를 P1 열에서 P2 접힌 줄로 옮겨 한 곳에만 보인다(폰은 접힌 줄, PC는 열 — `StaticTable`의 택일 표시)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: `ListEmpty` 경로 변경 없음
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 입력·RowActions 마크업 순서 불변. 날짜 입력 포커스 링은 `w14-fixes.spec.ts`가 Tab 실측으로 확인(`:focus-visible` 참 · outline 2px solid · offset 2px)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 행동 컴포넌트 변경 없음
