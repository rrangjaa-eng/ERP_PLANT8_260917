## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 더한 글자는 단위 `MB`(정적 단위, 설명문 아님) · 키 힌트 한 줄(UI-SPEC S13 원문 `폰 사진은 줄여서 올림 · PDF는 원본 크기` — 설정 힌트는 사용자 결정 ⑩으로 그대로 두는 축) · 칸 오류 `숫자 형식 오류 · 10처럼`(명사형, 앞의 `저장 실패 · `는 이 폼의 기존 errorMessageOf 규칙 그대로)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 기본 10이 채워져 열린다(registry default). 바이트 환산은 서버(domain/evidence)가 한다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 새 선택지 없음(숫자 칸 하나, 범위 1~100은 서버 검증)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 즉시 저장(blur) 그대로, 버튼 추가 없음
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험 동작 추가 없음
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 라벨 `증빙 크기 한도` · 단위 `MB` · 힌트가 서로 겹치지 않고, 단위는 입력 안(자리표시자)에 넣지 않았다(SYSTEM §7-2 number 비고)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음(빈 화면 없음)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 칸은 기존 TextField 그대로(Tab 이동 · blur 저장), 단위 글자는 포커스 대상이 아니다
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 행동 모양 변경 없음

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 입력 칸 높이 · 테두리(UQ-7 · ②) 그대로 TextField. 간격은 --s-2 · --s-4(UQ-1 척도)

- [x] 새 색·서체·radius·그림자를 만들지 않았다(tokens.css 변수만) — 근거: 단위 글자는 같은 폼 .hint와 같은 --text-aux · --text-muted, 높이는 --field-h/--control-h, 간격 --s-2 · --s-4 — tokens.css 변경 0
