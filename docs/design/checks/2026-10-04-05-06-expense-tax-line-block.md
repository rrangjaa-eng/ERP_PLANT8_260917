# 05-06 지출결의 폼 계산 한 줄 즉시 재계산 · 문서 화면 세율 바뀜 · 제출 막힘 이유 — 점검표
화면: app/(app)/expenses/[id]/
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §6-3(:479 · :483) · §7-1(:753-775) · §7-15(:1169) · 05-UI-SPEC S3 · S5 · S6 · Copywriting 「막힘 — 제출」 · 「표시 — 계산 한 줄」 · 「표시 — 세율 바뀜」

지금 화면(고치기 전): 계산 한 줄은 처음 그린 서버 값 그대로라 증빙 종류 · 공급가액을 바꿔도 안 바뀐다 · 한 줄이 `Form.Hint`가 아닌 자체 span이고 숫자 조각이 `Num`이 아니다 · PM 계급은 코드표 메뉴가 없어 증빙 종류 · 지급 방식 선택지가 지금 값 하나뿐(바꿀 수 없음) · 문서 화면에 세율 바뀜 줄이 없다 · 제출 1차는 올리는 중에만 막히고 서버 막힘(①~⑨)은 누른 뒤에야 실패 줄로 나온다 · 첫 포커스가 정해져 있지 않다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 계산 한 줄은 값 줄이라 `<p>`(`Form.Hint`)가 아닌 같은 모양 span(`.taxLine` — 색 · 크기 같음)이라 `design-principles` 「긴 설명」에 잡히지 않는다(desktop · mobile-375 통과). 새 글자는 서버 문자열뿐 — 계산 한 줄(규칙 넷 · 외화 · 계산 불가), `세율 바뀜 · …`, 막힘 ①~⑨(UI-SPEC Copywriting 원문 · 단위/통합 테스트가 글자 그대로 단언). 출처 꼬리 글자 없음, 기준일은 쓰지 않는다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 사람은 공급가액만 적고 세금 · 지급 총액은 서버 미리보기가 계산해 보낸다(화면은 `domain/money`를 import하지 않음 — grep 0). 회사 대납 기본값 22% gross-up
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 막히면 1차 `aria-disabled` + 이유 글자 + 다음 한 수 3차(E2E `막힘 이유`), 비활성 1차 누름은 서버 요청 0건. 선택지는 지출결의 쓰기 권한으로 받은 활성 코드만
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 1차 `지출결의 제출` 하나 그대로, 다음 한 수는 이유의 마지막 ` · ` 뒤 낱말을 3차로 바꾼 한 덩어리(`.blockedLine` — 05-05 제출 줄의 이유 자리, 폰은 버튼 아래 한 줄 그대로). E2E `막힘 이유` · `design-principles`(1차 1개) 통과
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험 동작 추가 · 변경 없음
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 이유는 1차 옆 한 곳(올리는 중 이유도 같은 자리 — `submitBlockReason`), 실패 줄은 이유가 없을 때만
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 없음(작성 중 문서). 증빙 0이면 첫 포커스가 첨부 영역(E2E `toBeFocused`)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 첫 포커스 = 막힘 대상 칸(없으면 1차), 비활성 1차에서 Enter · Ctrl+Enter = 대상으로 포커스, `Ctrl+U` 파일 고르기 그대로
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 다음 한 수는 칸 포커스 · 첨부 = 3차 버튼, 페이지 이동(프로젝트 상세 · 지출결의 열기) = 3차 모양 링크(§7-1 이동은 링크)
