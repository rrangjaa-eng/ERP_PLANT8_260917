# 05-07 새 지출결의(팀 비용) · 골라내기 — 점검표
화면: app/(app)/expenses/, ui/pick-dialog/
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §6-3(바꾸기 = 목록 골라내기) · §7-8(폰 시트) · §7-17(모달 틀) · UI-SPEC S3 · S14

지금 화면(고치기 전): `/expenses/new`는 없다(404). 문서 화면(`/expenses/[id]`)은 견적 줄 문서만 그린다 — 팀 비용 문서는 프로젝트 · 견적 줄 값이 비어 `—`만 줄지어 선다. 골라내기(거래처 · 견적 줄 목록에서 검색해 고르기)는 컴포넌트가 없어 `바꾸기` · `고르기` 3차가 갈 곳이 없다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: `/expenses/new`에 설명문 `<p>`는 0(스크린샷 new-pc.png — 칸 라벨 · 값 · 3차뿐), 문구는 막힘 이유 `증빙 없음 · 증빙 올리기`와 칸 오류 `사용일에 소속 팀 없음 · 사용일 고치기` · `날짜 없음 · 날짜 고르기`뿐. 골라내기 문구는 `조건에 맞는 거래처가 없습니다 · 검색 지우기` · `목록 불러오기 실패 · 다시 시도` · `50건 넘음 · 검색으로 좁히기`(0건 · 실패 · 상한)뿐이며 design-principles 막는 모드가 전 화면 27개 경고 0건으로 통과.
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 사용일 = 서울 오늘, 팀 = 사용일 소속(칸 없이 읽기 텍스트 — 사용일을 바꾸면 다시 옴), 종류만 사용자의 유일한 결정(`—` 시작), 거래처를 고르면 증빙 종류가 그 거래처 기본값으로 채워진다(E2E: 증빙 종류 `tax_invoice`), 번호 · 귀속 팀은 서버가 정한다.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 골라내기 주 버튼 `이 거래처로`는 고른 행이 있어야 켜진다(aria-disabled 단언), 견적 줄 문서에는 거래처 `바꾸기` 3차를 그리지 않는다(거래처는 줄이 정한다), 증빙을 올리기 전에는 1차 `지출결의 제출`이 막힘 이유와 함께 aria-disabled.
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 폼은 1차 `지출결의 제출` 하나(05-05 틀 그대로), 골라내기 모달은 1차 `이 거래처로` 하나 + 2차 `취소`. 나머지 `견적 줄 고르기` · `거래처 고르기` · `바꾸기` · `다시 시도` · `검색 지우기`는 3차. design-principles 통과.
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이 화면에 삭제 · 되돌릴 수 없는 동작이 없다(고른 거래처는 `바꾸기`로 되돌린다 — 확인 창 없음). 오류 글자만 `--status-danger`.
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 머리 줄 `지출결의 — {팀}`은 `팀` 값 행과 같은 팀 이름이지만 머리는 문서 이름 · 행은 칸 값이라 05-05 문서 화면(`지출결의 — {프로젝트} · {줄}` + 프로젝트 행)과 같은 구조. 골라내기 제목 `거래처 고르기`와 검색 칸 자리표시자 `거래처 이름 검색`은 다른 말(동작 · 입력 안내)이고 라벨은 그리지 않는다.
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 골라내기 0건 · 담당 줄 없음 모두 설명 뒤 3차 버튼(`검색 지우기` · `검색으로 찾기` · `다시 시도`)이 한 줄에 선다. `/expenses/new` 자체는 빈 화면이 아니라 첫 포커스 3차 `견적 줄 고르기`(R6-06 사용자 확정).
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: E2E — 거래처 고르기: 검색 칸 첫 포커스 → 입력 → ↓ 첫 행(aria-selected) → Enter 고르기, Esc 닫기 후 트리거로 포커스 복귀, 폼 Ctrl+U(파일 · 새 문서는 첫 저장) · Ctrl+Enter(제출), 막힘 3차가 대상 칸으로 포커스.
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: `견적 줄 고르기` · `거래처 고르기` · `바꾸기` · 막힘 다음 한 수 모두 `Button variant="tertiary"`(밑줄 텍스트). 골라내기 안의 `검색 지우기` · `다시 시도`도 같은 3차. 이동이 아니라 모달을 여는 일이라 전부 button.

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 폼은 05-05의 `DetailScreen` + `Form layout="page"` 한 열(UI-SPEC S3 틀)이라 옆 패널 결정(한 건 등록 폼)과 무관한 문서 화면이고, 골라내기는 §6 「팝업 = 잠깐 고르기 · 모달 = 끝내야 하는 한 건」 중 뒤를 막는 모달(PC 폭 `--dialog-w` · 폰 아래 시트)이다. 색 · 서체는 토큰만(웜톤 없음). 확인 창 폭 480(UQ-6)은 `--dialog-w`를 그대로 쓴다. 입력 칸 높이 40 · 행동 버튼 44(②)는 `--field-h` · `--touch-min`.
