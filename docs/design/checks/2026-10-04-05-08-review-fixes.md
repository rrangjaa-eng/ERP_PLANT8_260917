# 05-08 검토 수정 — 문서 화면 읽기 전용 결재선 · 빈 목록 상태 필터 — 점검표

기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §6-1(목록 = 원장) · UI-SPEC S7 · S8

지금 화면(고치기 전): ① 결재 당사자가 아닌 팀장 · 전사 보는 사람(대표 · 본부 책임자 · 시스템 관리자)이 `/expenses/[id]`를 열면 상태 배지가 없고 결재선 칸이 빈 목록이다 — 문서가 「결재 중」인지 「승인」인지 알 수 없다(05-08 Opus 검토 #1). ② 보임 범위 안 지출결의가 하나도 없는 `/expenses`에 걸러 낼 것이 없는 `상태` select가 남는다 — 쓸 수 없는 선택지(wave10 N2).

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자 0. 문서 화면은 기존 상태 배지 · 결재선 목록(당사자가 보던 것과 같은 컴포넌트)을 비당사자에게도 채울 뿐이고, 빈 목록은 select를 빼기만 한다(review-doc-ceo-1280.png · review-empty-writer-390.png).
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 상태 · 지금 단계는 서버가 계산해 배지 · 결재선으로 보인다(사람이 결재함에서 찾아볼 필요 없음). 빈 목록에서 고를 것이 사라졌다.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 비당사자 문서 화면의 행동은 `actions: []`(통합 「읽기 전용 갈래」 · E2E 승인 · 반려 · 회수 버튼 0). 빈 목록은 `filters`를 넘기지 않아 select 0(E2E `form "지출결의 보기"` 0, 쓰기 · 보기만 둘 다), 보기 때문에 0건인 목록에는 select가 남는다(E2E combobox `상태` 보임).
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 비당사자 문서 화면은 행동이 없어 1차 0(읽기). 빈 목록은 DR5 그대로 빈 화면 2차 `새 지출결의` 하나 · 머리 1차 0(E2E 기존 단언 유지).
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 두 화면 모두 이번 변경으로 생긴 동작이 없다(반려 · 회수 버튼은 비당사자에게 나오지 않는다).
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 머리 배지 `결재 중`과 결재선 줄의 `팀장 · 결재 중`은 당사자 화면과 같은 기존 구성(05-05) — 새 중복 없음.
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 목록은 `등록된 지출결의가 없습니다 · 새 지출결의` 한 줄 위에 select가 더는 없다(review-empty-writer-1280/390.png).
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 빈 목록의 탭 순서가 select를 건너 바로 `새 지출결의`로 간다. 문서 화면은 읽기 칸만 늘어 초점 대상이 바뀌지 않는다.
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 새 행동 없음. 결재선은 `ApprovalRoute mode="list"` 그대로.

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: DR5(빈 목록이면 머리 1차를 숨기고 빈 화면 버튼 하나)를 그대로 지키고 select만 더 뺐다. ⑤ 상태 배지 고정 — 같은 `StatusTag` 자리. N2 select 숨김은 사용자 지시(10/5 00:55)에 따라 추천안 적용.
