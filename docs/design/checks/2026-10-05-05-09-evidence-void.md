# 05-09 제출 뒤 증빙 — 결재 중 잠김 한 줄 · 권한자 붙이기 · 무효 처리 확인 창 · 무효 행 — 점검표

지금 화면(고치기 전): ① 문서 화면 `증빙` 섹션은 누구에게나 `크게 보기`만 — 결재 중 기안자는 왜 못 붙이는지 알 수 없고, 결재 중 증빙 붙이기 권한자도 붙일 길이 없다. ② 승인 뒤 잘못 붙은 증빙을 처리할 길이 없다(무효 처리 없음). ③ 무효 행 표시가 없다 — 페이지가 무효 파일을 목록에서 빼 버린다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자는 잠김 한 줄 `결재 중 · 증빙은 경영관리`(결재 중 기안자에게만 — 0509-review-drafter-1280.png) · 확인 창 막힘 `사유 없음 · 사유 적기`(04.1 상수 그대로) · 실패 `무효 처리 실패 · 다시 시도` · 무효 행 2행 `무효 · {처리자} · MM-DD HH:mm · {사유}` — 전부 UI-SPEC 308 · 473–474행 원문, 명사형.
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 누가 무엇을 할 수 있는지는 서버 `getEvidenceActions`가 정해 내려 주고(화면 추론 없음) 사용자는 고르지 않는다. 무효 처리에서 사용자가 적는 것은 사유 하나(처리자 · 시각은 서버가 채움).
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 결재 중 기안자 · 결재자에게 「하나 더」 · `삭제` 0, 승인 문서 기안자에게 `삭제` · `무효 처리` 0, 무효 행에는 `크게 보기`만(E2E `제출 뒤 증빙` 세 사례 단언). 사유가 비면 확인 버튼 `aria-disabled` + 이유 한 줄(0509-void-dialog-390.png).
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 문서 화면 1차는 그대로 04.1 행동 줄(결재 중 기안자 = `회수`), 파일 행 행동은 전부 3차 `RowAction`. 확인 창 1차는 `무효 처리` 하나(2차 `취소`).
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: `무효 처리`는 `RowAction danger`(DOM 맨 끝 · `--status-danger` 글자 · 앞 간격 넓음 — 0509-approved-manager-390.png), 되돌릴 수 없는 일이라 확인 창을 거친다(CLAUDE.md §7). E2E 폰 375 사례: 두 3차 사이 16 이상.
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 무효 행은 태그 `무효` + 2행 `무효 · …`이 UI-SPEC 474행 원문 그대로(태그는 상태 낱말, 2행은 처리 기록 — §7-10 B8). 성공 토스트 없음(행이 그 자리에서 바뀌고 aria-live가 읽음 — E2E `getByRole("status")` /무효/ 0).
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 제출된 문서에는 증빙이 늘 1개 이상(⑧)이라 빈 영역이 나오지 않는다. 더할 수 있는 사람에게 빈 영역이면 기존 05-05 끌어 놓기 상자(버튼)가 먼저 선다(`canAdd && empty`).
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: `무효 처리`는 버튼(Tab · Enter), 확인 창은 04.1 ConfirmDialog 그대로(사유 textarea 포커스 · `Ctrl+Enter` 확인 · `Esc` 취소 — 0509-void-dialog-390.png 단축키 표시).
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 파일 행 3차는 `RowActions` 한 줄(`크게 보기`는 새 탭 링크 — 앱 밖 서명 주소라 DECISIONS 2026-09-30 예외 그대로), `삭제` · `무효 처리`는 같은 `RowAction danger` 모양. 확인 창은 04.1 반려 확인과 같은 `ConfirmDialog` + 같은 `.reason` CSS 모듈(`decision-dialogs.module.css`)을 그대로 쓴다.
