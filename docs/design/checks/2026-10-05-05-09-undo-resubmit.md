# 05-09 지출결의 되돌리기 · 반려/회수 폼 · 다시 제출 — 점검표
화면: app/(app)/expenses/[id]/
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §7-6(토스트) · UI-SPEC 확정 #2 · S3 「반려 · 회수 뒤」 · Copywriting 「SUCCESS — 토스트」 · 「거부 — 늦은 되돌리기」

지금 화면(고치기 전): ① 제출 착지 토스트 `지출결의 제출 · 결재 요청됨 → {담당}`에 3차가 없다 — 잘못 올린 문서를 되돌릴 길이 문서 화면 `회수`(확인 창) 하나뿐이고, 회수된 문서는 다시 제출할 수 없는 문서 화면으로 남는다(새 지출결의를 다시 만들고 증빙을 다시 붙여야 함). ② 반려된 문서도 기안자에게 읽기 화면뿐이다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자는 토스트 결과(`되돌리기 · 결재 멈춤` · `지출결의 다시 제출 · 결재 요청됨 → {담당}`)와 늦은 되돌리기 오류 한 줄(`{이름}이 HH:MM에 승인함` + 3차 `문서에서 회수`)뿐 — UI-SPEC Copywriting 원문. 폼 위 읽기 행은 라벨 `회수`/`반려` + 값(시각 · 처리자 · 사유)이라 설명문이 아니다(0509-withdrawn-form-1280.png).
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 회수된 폼은 제출 때 값이 그대로 채워져 오고(공급가액 12,400,000 · 거래처 · 증빙), 세금 한 줄은 지금 기준으로 서버가 다시 계산한다(getExpense editable → computeExpenseTax). 되돌리기는 차수만 보내고 version은 서버가 읽는다.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 되돌리기 3차는 결재 중 · 기안자(가능 행동에 회수)일 때만 렌더. 폼 모드는 가능 행동에 `다시 신청`이 있을 때만(기안자 · 반려/회수 · 쓰기 권한). 이미 처리된 문서의 되돌리기는 서버가 거부하고 다음 행동만 3차로 준다.
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 회수 폼의 1차는 `지출결의 다시 제출 Ctrl+Enter` 하나(2차 `임시 저장`), 머리 줄 `actions` 없음(E2E `getByRole("button", { name: /^지출결의 다시 제출/ })`).
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 되돌리기는 되돌릴 수 있는 일(다시 제출)이라 확인 창 없이 토스트 3차 — CLAUDE.md §7 「확인 창 대신 되돌리기」. 받은 승인을 지우는 문서 화면 `회수`는 04.1 확인 창 그대로.
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 머리 배지 `회수` · 읽기 행 라벨 `회수` + 시각 — 배지는 상태, 행은 언제(UI-SPEC S3 「반려 · 회수 뒤」 원문 구성, 연차 반려 화면 선례). 결재선 끝 줄 `회수 MM-DD HH:mm`은 폼 모드에서 그리지 않는다(폼 결재선은 다시 제출 때의 한 줄 미리보기).
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 없음(이 변경은 값이 채워진 폼 · 토스트만).
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 회수 폼에서 공급가액 칸 `Ctrl+Enter` → 다시 제출(E2E expense-undo-resubmit 단언). 토스트 3차는 버튼이라 Tab으로 닿는다.
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 토스트 3차는 `ui/toast` `actionLabel` 한 가지 모양(되돌리기 · 문서에서 회수 · 새로 고침 · 오류 토스트 닫기 모두 같은 버튼).
