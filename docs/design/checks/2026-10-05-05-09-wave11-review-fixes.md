# 05-09 웨이브 11 화면 검토 수정 D1–D5 — 점검표
화면: ui/confirm-dialog/, ui/toast/, app/(app)/expenses/[id]/, app/(app)/leave/[id]/document-actions.tsx
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §7-6 토스트 · §7-17 확인 모달 · UI-SPEC :313(폰 kbd 없음) · 웨이브 11 검토 README D1–D5

지금 화면(고치기 전, 웨이브 11 실측): D1 폰 확인 시트 행동 줄에 kbd `Esc` · `Ctrl+Enter`가 보인다. D2 무효 처리 시트가 사유 첫 글자에 29px 내려앉는다(막힘 줄이 사라져 아래 붙은 시트가 줄어듦). D3 폰 제출 · 되돌리기 토스트가 고정 행동 줄(`회수` · `승인` · `임시 저장`)을 4초간 가린다. D4 무효 처리 확인 뒤 포커스가 BODY로 빠진다. D5 결재선 노출 항목이 없는 계급(경영관리)에 빈 `결재선` 행이 선다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자 0. 빈 `결재선` 행(값 없는 라벨)을 없앴고(D5, E2E `dt 결재선` 0), 막힘 줄 `사유 없음 · 사유 적기`는 그대로(shots/void-empty-390.png).
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 토스트 위치는 화면이 고정 행동 줄 높이를 실측해 정하고(Toast.tsx `--toast-lift`), 포커스 복귀도 화면이 정한다 — 사용자 결정 추가 없음.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 폰에서 누를 수 없는 단축키 표시(kbd)를 숨겼다(D1, E2E `kbd:visible` 0). 버튼 · 막힘 규칙은 그대로.
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 토스트가 더는 행동 줄 1차를 가리지 않는다(D3 E2E — `회수` 가운데 점의 elementFromPoint가 `회수` 버튼, shots/toast-390.png). 1차 구성은 바꾸지 않았다.
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 무효 처리 시트의 2차 왼쪽 · 1차 오른쪽 · 1차 두 배 폭 그대로(shots/void-typed-390.png). 위험 동작 배치 변경 없음.
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 바뀐 글자 없음. kbd를 숨긴 폰 버튼 글자는 `취소` · `무효 처리` 하나씩.
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음(빈 화면을 건드리지 않았다). 빈 값 행(D5)은 아예 그리지 않는다.
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 무효 처리를 키보드로 확인하면 포커스가 사라진 버튼 대신 증빙 영역(tabIndex -1)으로 돌아와 다음 Tab이 그 자리에서 이어진다(D4 E2E `activeElement.closest('#evidence')`). PC kbd는 그대로 보인다(shots/void-empty-1280.png).
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 컴포넌트 모양 변경 없음 — 확인 시트 kbd 규칙을 PickDialog(웨이브 9 D4)와 같게 맞췄다.

## 사용자 결정(§1)
