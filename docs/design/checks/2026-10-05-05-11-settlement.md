## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 설명문 0. 머리 줄은 버튼 글자 `정산 결재 올리기`뿐이고 실패만 버튼 옆 한 줄(`styles.doorFailure`), 미저장 편집 비활성 이유는 기존 DR-6 함수(`unsavedEditsReason`) 그대로. 문서 화면 오류는 `정산 결재 불러오기 실패` 한 줄(error.tsx), 늦은 되돌리기는 서버 원문을 마지막 ` · `에서 나눈 토스트 한 줄 + 행동.
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 올리기는 입력 없이 한 번(결재선은 설정 `정산 결재선`으로 서버가 짠다), 견적가 합 · 실행가 합은 서버가 원화로 환산해 합한다(통합 `settlement-approval.test.ts` 두 합 사례 · E2E 문서 화면 dd `26,900,000` · `23,200,000`), 승인 = 완료 전환을 같은 tx로 시스템이 한다.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 정산에서 `상태 바꾸기`를 그리지 않는다(E2E `상태 바꾸기` 0). 담당 PM이 아니면 올리기 버튼 없음(`canSubmit` 서버 판정), 문서가 있으면 버튼 대신 상태 링크, 미저장 편집이 있으면 비활성 + 이유. 승인 · 반려는 결재 당사자에게만(04.1 `getApprovalView` actions).
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 머리 줄 `정산 결재 올리기`는 2차(실측 1280 · 390 · 320에서 1차 0개 — 견적 저장 1차는 편집 때만), 문서 화면은 `승인` 1차 하나 + `반려` 2차(폰 버튼 순서 `반려`·`승인`, shots11/doc-390.png).
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 반려는 04.1 행동 줄 그대로(폰 2차 왼쪽 · 1차 두 배 폭), 회수는 확인 없는 토스트 `되돌리기`로만(확정 #3 · #4). 삭제성 동작 신설 없음.
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 문서 제목 `정산 결재 — {프로젝트명}` + 태그 `결재 중`, 메타는 프로젝트 번호만. 읽기 칸 `프로젝트` 행은 번호 · 이름 링크 한 번. 머리 줄 링크 `정산 결재 중`은 프로젝트 태그(`정산`)와 다른 사실(결재 상태)이다.
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 이 화면에 빈 목록 없음. 문서가 없을 때 그 자리 자체가 첫 행동 `정산 결재 올리기`다. 오류 화면은 `다시 시도` 버튼(ListEmpty tone=error).
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 머리 줄 버튼 · 링크는 Tab · Enter, 문서 화면 `승인 Ctrl+Enter`(04.1 DocumentActions 그대로, PC 1280 kbd 2개), 토스트 `되돌리기`는 기존 Toast 포커스 계약.
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 페이지 이동(`정산 결재 {상태}` · 문서 화면 `프로젝트`)은 3차 링크 모양(`buttonLinkClassName("tertiary")` · 지출결의 문서 화면 선례 `expense-document.tsx`), 서버 행동(올리기)은 버튼.
