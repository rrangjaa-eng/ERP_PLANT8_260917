# 첨부 영역 버튼의 접근 이름 = 보이는 글자 — 점검표
화면: ui/attachments/
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §10 접근성 · 05-UI-SPEC a11y S4 backstop(「영역 = `<button>`(접근 이름 = 보이는 글자)」)

지금 화면(고치기 전): 지출결의 폼의 첨부 영역 버튼(`#evidence-picker`)은 칸 라벨 `<label for>` `증빙`이 접근 이름을 덮어, 화면 낭독기가 보이는 글자(`파일을 끌어 놓거나 Ctrl+U · 이미지·PDF 10MB` · 폰 `사진·파일 올리기 …`) 대신 `증빙`만 읽는다(05-13 `expense-a11y.spec.ts` 실측 — Chrome AX 트리도 `증빙`). `하나 더` 버튼도 같다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자 0(접근 이름 연결만).
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 변경 없음.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 변경 없음(canAdd 갈래 그대로).
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 변경 없음.
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 변경 없음.
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 보이는 글자 그대로가 이름이다(숨은 폭의 글자는 display: none이라 이름에서 빠짐 — Chrome AX 트리 실측).
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음.
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 버튼 · id · Ctrl+U · 첫 포커스 대상(`#evidence-picker`) 그대로, 칸 라벨 클릭도 그대로.
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 모양 변경 없음.
