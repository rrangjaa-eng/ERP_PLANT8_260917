# 05 /review C8 결과 줄 라이브 영역 상자 · C9 승인 응답 유실 문구 — 점검표
화면: app/(app)/expenses/[id]/expense-form.tsx, app/(app)/expenses/[id]/expense.module.css, app/(app)/approvals/approval-sheet.tsx, app/(app)/approvals/inbox-table.tsx, app/(app)/home-approval-actions.tsx
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §10 실시간 알림(저장 결과 `aria-live="polite"`) · §6-3 폰 제출 줄 · 04.1-05 결재 시트 거부 한 줄(ConflictLine)

지금 화면(고치기 전):
- C8: 지출결의 폼 결과 줄(임시 저장됨 · 실패 · 제출 결과)을 감싼 polite 라이브 영역이 `display: contents` 요소다(B4). WebKit · 일부 스크린 리더는 contents 요소의 라이브 영역을 읽지 않을 수 있다(폰 Safari 결재 흐름). 또 B4로 결과 줄이 감싸이면서 폰 규칙 `.formBar > div > .successLine` 등이 결과 줄에 닿지 않게 되었다(폰에서 결과 줄이 두 버튼 아래 제 줄로 가던 B4 전 배치가 깨질 수 있음).
- C9: 결재 시트(결재함 · 홈)에서 승인 요청의 응답을 잃으면 「승인 실패 · 새로 고침」 — 서버가 이미 승인했을 수 있어 틀린 말일 수 있다.

고친 뒤:
- C8: 라이브 영역은 일반 상자(`inline-flex`, 결과 줄 사이 간격 = 행동 줄 간격 `--s-3`)이고, 비었을 때는 `:empty`에서 흐름 밖(`position: absolute`, 0 크기)이라 행동 줄 배치에 끼지 않는다(상자는 계속 있어 라이브 영역이 먼저 있다). 폰은 비지 않은 영역이 두 버튼 아래 제 줄 전체 폭(`order: 3` · `flex-basis: 100%`)이고 결과 줄마다 한 줄 — B4 전 배치.
- C9: 통신 실패(응답 유실)만 「결과 확인 안 됨 · 새로 고침」(끝 낱말이 기존 3차 `새로 고침` 버튼). 입력 오류처럼 승인하지 않은 것이 확실한 실패는 「승인 실패」 그대로.
