이 플랜은 화면 컴포넌트를 짓지 않는다 — 문서 아홉 절과 상태 낱말 표(색 글자 낱말 아홉)만 더한다. 낱말의 화면 반영은 각 화면 플랜의 CI=true DOM 감사와 묶음 PR-B `/design-review`가 본다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: status-map.ts 변경은 낱말 → 색 줄 아홉뿐이고 화면 문구가 없다. SYSTEM 개정 문구는 UI-SPEC 원문(막힘 이유 · `…` · 담당 표기)을 옮겼고 새 설명문을 만들지 않았다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: SP-1 서버가 행마다 고를 수 있음을 보냄 · SP-9 빈 행 = 검사 없음(사용자가 결정할 칸 최소). 코드는 낱말 표만이라 결정이 없다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: SP-1 못 고르는 행 `aria-disabled` + 이유 글자 · primaryAction 버튼 1024 미만 미렌더 · SP-8 겹침 둘까지(SYSTEM 문장으로 고정)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: SP-1 1차는 표 위 행동 줄 하나 · SP-3 상태 × 권한으로 `actions.primary` 하나 · SP-7 모달 1차 하나
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이 플랜은 삭제 동작을 더하지 않았다(SP-6 마지막 증빙 삭제 확인은 철회)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: SP-2 낱말은 `status-map.ts` 한 표만 정본이고 페이즈 전용 표를 만들지 않았다(`git ls-files 'app/(app)/status-display.ts'` 비어 있음) · 맨 낱말 `신청` · `요청` · `없음` · `종결` 0줄
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: SP-8 EMPTY 세 갈래가 이유 줄 + 다음 한 수 3차로 정의됨(SYSTEM §7-8), 이 플랜이 새 빈 화면을 그리지 않는다
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: SP-1 `Space` 행 고르기 · `Ctrl+Enter` 화면 1차 · SP-8 `Esc`는 목록만 닫음 · SP-9 §7-13 체크박스 매트릭스 키 그대로
