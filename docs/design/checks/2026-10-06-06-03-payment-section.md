지금 화면(착수 전): 결재 통과 문서에 지급 섹션 · 지급 행동이 없다. 05 행동 줄(`DocumentActions`)은 approved에서 가능 행동이 0이라 그리지 않는다 — 1차가 둘이 될 자리 없음.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 문구는 담당 표기 `지급은 경영관리`(권한 밖 다음 한 수 — UI-SPEC S5 「그 밖의 사람」 칸 2행), 로드 오류 `지급 정보 불러오지 못함 · 다시 시도`(C13), 충돌 줄(서버 문구 그대로 · 응답 없음 `결과를 받지 못함 · 새로 고침`) 셋뿐이고 모두 명사형 한 줄. 설명문 · 도움말 없음
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 지급일은 오늘(KST)을 서버가 정해 보이고 그대로 보낸다 · 지급 총액 · 공급가 역산은 서버 `decidePayable`만 계산(클라이언트 금액 셈 0 — O-18). 이 플랜엔 입력 칸이 없다(이체액 · 지급일 칸은 06-04)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 1차는 서버 `resolveExpenseActionRow` 결과 그대로 — 지급 권한 없는 사람(대표 포함)은 버튼 요소 0(E2E 「대표 — 이 페이즈 버튼 0」 · DOM 실측 P4-ceo 4폭 btns []), 결재 통과 전 · 05 C1 작성 중 문서는 섹션 요소 0(E2E 「쓰기 권한 없는 기안자 작성 중 문서 — 지급 섹션 없음」)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: P4 지급 권한자에게 1차 `지급 완료` 하나(approved 문서는 05 가능 행동 0이라 `DocumentActions`가 그리지 않음 — 1차 둘 없음). P6은 1차 없이 결과 글자 + `지급 완료` 태그
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이 플랜에 위험 동작 없음(지급 취소 2차는 06-04). 지급 완료는 되돌리기(지급 취소)가 있는 행동이라 확인 모달 없이 1차(UI-SPEC S5)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 지급 섹션이 서면 위 읽기 칸의 `지급 예정일` · `지급 방식`을 빼 한 자리에만 둔다(DOM 실측 dt 각 1개 — 4폭 · P4/P6). 지급 뒤 05 세율 바뀜 줄은 그리지 않는다(E-22 — E2E 「지급된 문서 — 지급 기록이 정본 · 세율 바뀜 줄 없음」). 태그 `지급 완료` + 결과 글자 `지급 완료 → 날짜 · 시각`은 UI-SPEC S5가 정한 1차 자리 모양(태그 = 상태, 글자 = 처리 시각)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 상태 없음(섹션은 결재 통과 문서에만 서고 항상 값이 있다). 로드 오류는 한 줄 + 2차 `다시 시도`
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 1차 `지급 완료` = Ctrl+Enter(버튼에 단축키 표기) — DOM 실측에서 Ctrl+Enter로 지급 완료 뒤 포커스가 결과 글자(`data-testid=payment-result`, tabindex -1 · role=status)로 갔다(r2 F5). E2E도 클릭 뒤 toBeFocused
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 1차는 `ui/button` primary, 다시 시도는 secondary 버튼. 행동 줄 틀은 05 문서 행동 줄 CSS(`document-actions.module.css` bar · buttons · primaryWrap · spacer)를 그대로 써 같은 자리 · 같은 폰 고정
