# 06-04 독립 검토 · DOM 감사 수정(지출결의 문서 화면 지급 섹션 S5) — 점검표

기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §6-3 · §7-1 · §7-17 · 06-UI-SPEC S5 · 06-04 검토 P2-1 · P3-2 · P3-3 · DOM 감사 O1

지금 화면(고치기 전): 지급된 상태로 연 문서에서 지급을 취소하면 지급일 칸에 옛 지급일이 기본값으로 남는다(P2-1). 기준일이 지급 예정일인 규칙은 예정일 칸 힌트가 서지 않고, 저장 뒤 첫 `지급 완료`가 `지급 총액 바뀜`으로 한 번 거부된다(P3-2). 취소 모달이 동시성 거부를 받아도 문서를 다시 읽지 않아 같은 거부가 되풀이된다(P3-3). 지급 총액을 못 보는 지급 권한자에게 쓸 수 없는 빈 이체액 칸이 서 있다(O1).
고칠 계획: 패널이 지급 뒤 → 지급 전 전이를 렌더 파생 상태로 잡아 칸 · 미리보기를 새 서버 값으로 다시 세운다(P2-1). 예정일 칸 미리보기에 예정일을 함께 싣고 저장 뒤 미리보기를 다시 받는다(P3-2). 취소 모달 서버 거부 뒤 router.refresh()(P3-3). AMOUNT_HIDDEN이면 이체액 칸 · 차이 사유 칸을 그리지 않는다(O1).

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 문구 0. 막힘 이유 `지급 총액 볼 권한 없음 · 노출 설정은 관리자`는 그대로(사용자 결정 2026-10-06 18:30:26 KST, DECISIONS.md 기록)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 취소 뒤 지급일 기본값이 다시 오늘, 이체액 기본값이 지금 지급 총액(P2-1). 저장 뒤 지급 총액을 서버가 다시 셈해 칸이 따른다(P3-2)

- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 1차는 서버 행(resolveExpenseActionRow) 그대로, 변경 없음

- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 새 글자 없음. 취소 모달 거부 이유의 `새로 고침` 꼬리는 기존 ConfirmDialog 3차 그대로
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음(빈 화면 없음)
