## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자는 줄 아래 힌트 `남은 실행가 {값} · 카드 사용 {N}건 {합}`(상태 값 — UI-SPEC S9) · 막힘 `연결 없음 · 연결 고르기` · `실행가 초과 · 남은 실행가 {값} · 다른 줄 고르기` · 고르기 목록 2행 이유(서버 판정)뿐, 설명문 없음(card-usage-form.tsx · link-picker.tsx)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 남은 실행가 · 공급가 · 고를 수 있음은 서버가 셈해 보낸다(link-targets.ts `searchLinesForCardLink` · `lineRoomHint`), 실행가 · 공급가 칸 입력 없음. 직전 연결 기본값(M-4)은 Task 2 몫
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 반대쪽 · 실행가 소진 · 완료 줄은 `selectable: false`(PickDialog `aria-disabled` + 2행 이유), 프로젝트를 고르기 전에는 `견적 줄` 행 자체를 그리지 않는다
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 패널 1차 `카드 사용 등록 Ctrl+Enter` 하나, 목록은 1차 `이 프로젝트로` / `이 줄로` 하나(PanelForm · PickDialog 그대로)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이 작업에 위험한 동작 없음(등록 · 고르기만)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 값은 텍스트 한 번 + 3차 `바꾸기`(접근 이름은 `프로젝트 바꾸기` · `견적 줄 바꾸기`, 보이는 글자는 `바꾸기` — UI-SPEC S9), 라벨 열이 칸 이름을 한 번 말한다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 비어 있는 프로젝트 · 줄은 `—` + 3차 `고르기`(가맹점 빈 값과 같은 꼴). 고르기 목록의 빈 갈래 세 개(UI-SPEC 「Empty — 연결 고르기 목록」)는 Task 2에서 3차 `견적 외 비용으로`와 함께 더한다
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 3차 버튼 → 목록 검색 칸 첫 포커스 → 방향키 · Enter로 고르기 → 포커스가 다음 빈 `견적 줄 바꾸기`로 → `Ctrl+Enter` 저장(E2E `[06-07 트레이서]`가 `견적 줄 바꾸기` 포커스를 단언)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: `가맹점 바꾸기` · `프로젝트 바꾸기` · `견적 줄 바꾸기` 모두 `Button variant="tertiary"` 같은 줄 꼴
