고칠 계획: 목록(번호 · 요청일 · 품목+링크 아이콘 · 연결 · 요청자 · 예상 금액 · 상태) + 1차 「구매 요청」 → 옆 패널(연결 · 품목 · 링크 · 예상 금액 · 메모). 연결 고르기는 카드 사용과 같은 팝업(`mode="purchase"`)을 쓰고 온라인구매 협력사 줄만 고를 수 있게 한다. 새 색 · 서체 · radius 없음.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: purchase-request-form.tsx · page.tsx · purchase-list.tsx의 새 글자는 라벨(품목 · 링크 · 예상 금액 · 메모 · 연결 · 프로젝트 · 견적 줄)과 막힘 · 오류 한 줄(`품목 · 예상 금액 2칸 비어 있음 · 품목 적기` · `연결 없음 · 연결 고르기` · `실행가 초과 · 남은 실행가 … · 다른 줄 고르기` · `링크 형식 오류 · https://로 시작하는 주소` · `거래처 … · 지출결의로`)과 빈 화면 한 줄뿐이다. 설명문 없음.
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: `?new=1&line=` 진입이면 프로젝트 · 견적 줄을 텍스트로 채워 연다(E2E 트레이서 통과). 번호 · 공급가 추정 · 남은 실행가는 서버가 계산한다(통합 purchase-requests 7건 통과). 사용자가 적는 것은 품목 · 예상 금액뿐이고 링크 · 메모는 선택이다.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 연결 고르기 줄 목록에서 온라인구매 협력사가 아닌 줄 · 실행가 소진 줄은 `aria-disabled` + 이유 한 줄(`searchLinesForPurchaseLink`의 `reason` — 통합 테스트로 확인). 줄이 하나뿐이면 라디오는 `견적 줄` 하나(팀 비용 선택지 없음).
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 목록 머리 1차는 「구매 요청」 하나(빈 목록이면 머리 1차를 숨기고 빈 화면 버튼 하나 — DR5, page.tsx `empty`). 패널 안 저장 버튼 하나(PanelForm). `프로젝트 바꾸기` · `견적 줄 바꾸기`는 3차 버튼.
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이 화면에 삭제 · 취소 동작이 없다(신청만. 구매 완료 · 취소는 06-09).
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 링크 칸은 라벨 「링크」 + 자리 글자 `https://`(형식 예시 한 개뿐). 상태는 `StatusTag variant="text"` 한 곳, 목록 머리에 같은 말 부제 없음.
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: page.tsx 빈 갈래 셋: 전체 0건 `구매 요청이 없습니다` + 「구매 요청」, 기본 보기 0건은 권한자 `처리할 구매 요청이 없습니다` + 「전체 보기」 · 요청자 `신청한 구매 요청이 없습니다` + 「구매 요청」, 필터 0건 `조건에 맞는 구매 요청이 없습니다` + 「필터 지우기」.
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 패널 폼은 PanelForm(Ctrl+Enter 제출 · 저장 뒤 첫 칸 포커스 — E2E 트레이서가 Ctrl+Enter 저장 · 품목 칸 포커스를 단언). 연결 고르기는 기존 PickDialog(방향키 · Enter). 필터는 네이티브 select.
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 목록 필터는 projects 화면의 select 규칙(`filterStyles`)을 그대로 쓰고, 연결 바꾸기는 법인카드 사용 폼과 같은 3차 버튼 + 같은 PickDialog 팝업이다. 번호 · 품목 링크는 기존 식별자형 링크 규칙(`--accent`).
