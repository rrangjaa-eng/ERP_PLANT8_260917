# 06-30 관리자 법인카드 종류 「공용」 — 점검표
화면: app/(app)/admin/corp-cards/
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §6-1(관리자 마스터 목록 · 옆 패널) · §6-3(폼 템플릿) · 06-UI-SPEC Q5

지금 화면(고치기 전): 등록 · 소유자 변경 패널의 「종류」 select가 `개인` · `팀` 둘뿐이라 공용 카드(소지자 · 팀 없는 카드, Q5 · C8)를 만들 수 없다. 목록 종류 열은 `개인`이 아니면 전부 `팀`으로 그려 공용 행이 생기면 `팀` · 소유 `—`로 잘못 읽힌다.
고칠 계획: 종류 select에 `공용` 옵션 하나(새 칸 · 새 문구 없음) — 고르면 소유 칸을 렌더하지 않는다. 목록 종류 열 `공용`, 소유 열 `—`.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 설명문 0. 옵션 낱말 `공용` 하나만 더했다. 위조 입력(공용 + 소유 칸) 거부만 `소유 칸 조합 오류 · 공용에 맞는 칸만`(명사형 한 줄, 서버 오류 자리). 기존 문구(`소지자·팀 중 하나 필요 · 하나만 선택` 등)는 그대로
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 새 카드 기본 종류는 그대로 `개인`(성공 뒤에도 `개인`으로 돌아감 — E2E가 `toHaveValue("personal")` 단언). 소유자 변경 폼은 카드의 지금 종류(`공용` 포함)에서 시작(E2E `toHaveValue("shared")`). 공용이면 소유 칸 자체가 없어 고를 것이 없다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 공용을 고르면 소지자 · 팀 select를 렌더하지 않는다(E2E `getByLabel("소지자"/"팀")` count 0 — 새 카드 · 소유자 변경 둘 다)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 패널 1차 `법인카드 등록` / `소유자 변경` 그대로, 버튼 추가 없음
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 행 동작(`수정 · 비활성화 · 삭제`) 변경 없음 — 기존 `DeleteToArchive` 그대로
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 공용 행의 소유 칸은 `공용`을 되풀이하지 않고 `—`(종류 열이 이미 말함)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 목록(`ListEmpty` + `법인카드 등록`) 변경 없음
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 네이티브 `<select>` 옵션 하나 추가라 기존 Tab · 방향키 · Ctrl+Enter 제출 그대로. 공용이면 칸이 하나 줄어 Tab 순서가 별칭 → 종류 → 행동 줄
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 새 행동 없음
