지금 화면(착수 전, 06-06): 05 폼의 증빙 묶음은 첨부 영역뿐이라 증빙 없이 먼저 결제한 건(선결제)을 제출할 수 없고(⑧ 증빙 없음 막힘), 기안자가 증빙 금액 · 증빙일을 적는 칸이 없다. 문서 화면 증빙 섹션에는 3차 `증빙 면제`가 없어 증빙을 끝내 받지 못한 문서가 지급 게이트 · 미결 점검에서 영원히 막힌다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자는 칸 이름 넷(`증빙 금액` · `증빙일` · `선결제` · `선결제 사유`), 힌트 한 줄 `증빙 기한 지급일부터 {N}일`(UI-SPEC S6 원문 — 숫자만 설정 값), 칸 오류 원문(서버 글자 그대로: 선결제 사유 없음 · 숫자 아님 · 증빙 금액 0 이하 · 부가세 포함 금액 · 날짜 형식), 면제 확인 모달(Copywriting 「Destructive — 증빙 면제」 원문 — 되돌릴 수 없는 일)뿐이다. 설명문 · 도움말 · 자리 표시 설명 0
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 선결제는 꺼짐이 기본, 사유 칸은 켤 때만 선다(끄면 적은 사유는 서버가 버린다). 증빙 금액 · 증빙일은 제출 필수가 아니다(비면 경영관리가 확인 때 적는다 — 승인액으로 몰래 채우지 않는다). 기한 일수 · 부가세 포함 판정은 서버(설정 · `isTaxInclusiveEvidenceAmount`)만 셈한다 — 화면은 셈하지 않는다. 면제 모달의 결과 줄 갈래(지급 전 · 지급 뒤 · 선결제)는 서버가 준 사실로 고른다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 선결제 사유 칸은 선결제를 켠 때만 렌더(끄면 칸 없음). 제출 뒤 문서 화면에는 선결제를 켜고 끄는 칸이 없다(O-4 — E2E `getByLabel("선결제")` toHaveCount(0)). 3차 `증빙 면제`는 서버 행(`actionRow.tertiary === "waive"`)이 세운 지급 권한자에게만 렌더 — 권한 없는 사람에게는 버튼 요소 0. 사유가 빈 면제 모달 1차는 비활성 + `사유 없음 · 사유 적기`
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 폼의 1차는 05 `지출결의 제출` 하나 그대로(칸을 더했을 뿐, 선결제 · 증빙 칸 옆에 저장 버튼 없음). 문서 화면의 행동 줄 1차는 06-03 · 06-04 표 그대로이고 `증빙 면제`는 같은 줄 3차라 1차가 둘이 되지 않는다(UI-SPEC 「증빙 면제의 자리」)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 면제는 증빙 게이트를 닫는 길이라 3차(tertiary)이고 확인 모달(`ui/confirm-dialog`)을 지난다 — 모달 제목 `증빙 면제` · 결과 줄로 무엇이 일어나는지 말하고 사유가 필수다(UI-SPEC Destructive 원문). 06-04 지급 취소 모달과 같은 컴포넌트
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 체크박스 라벨 `선결제`가 칸 이름 하나이고 칸 안 글자 없음. 읽기 줄은 라벨 `선결제 사유` + 원문 한 번(`선결제` 낱말 · 기한 2행은 06-06 확인 줄이 이미 그려 다시 그리지 않는다)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 없음. S4 empty `증빙 없음 · 기안자 {이름}`은 06-06 확인부가 그리고 같은 줄 3차 `증빙 면제`가 첫 행동이다. 값 없는 읽기 줄(선결제 사유 없음)은 줄 자체를 그리지 않는다
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 선결제 체크박스 · 사유 칸 · 증빙 금액 · 증빙일은 05 폼 칸과 같은 네이티브 입력이라 Tab 순서(증빙 첨부 → 증빙 금액 → 증빙일 → 선결제 → 사유 → 결재선 → 제출). 제출 막힘 시 `Ctrl+Enter` · 1차 누름이 사유 칸으로 포커스(`TARGET_FIELD.prepaidReason`). 면제 모달은 `Ctrl+Enter` 확인 · `Esc` 취소(`ConfirmDialog` 기본)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 체크박스는 05 `분할 지급` 체크(`installmentCheck` 클래스)와 같은 모양, 금액 칸은 공급가액과 같은 `useCommaInput("krw")` · `textInput numeric` · `Form.Field width="short"`, 날짜 칸은 지급 예정일과 같은 모양. 3차 `증빙 면제`는 06-04 `지급 예정일 바꾸기` · 06-06 `바꾸기`와 같은 `Button variant="tertiary"`
