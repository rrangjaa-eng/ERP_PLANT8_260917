## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자 없음. 폰 행 시트(보기 전용)는 요청일 · 연결 · 요청자 값만(라벨 + 값), 설명문 없음
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: S13 기본값 · 서버 계산은 그대로. 폰에서 `신청됨` 행 탭은 고르는 단계 없이 바로 S13(06-09 카드 사용 표 「권리가 있으면 수정 패널」 선례)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 구매 완료 · 취소 행 탭은 보기 전용 행 시트(행동 없음, Q2). 폰 행 탭은 구매 권한자에게만(`canComplete`) — 그 밖의 사람은 지금처럼 접힌 줄만
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: S13 1차 `구매 완료 Ctrl+Enter` 하나 그대로. 칸 안 `Enter`는 이제 제출하지 않는다 — 처리는 `Ctrl+Enter` · 1차 버튼(포커스가 1차에 있을 때 Enter = 버튼 누름)만(E2E O-2)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이번 변경에 위험 동작 없음. 되돌릴 수 없는 구매 완료가 실수 `Enter`로 나가지 않게 막았다
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 행 시트 제목 = 품목, 부제 = `{번호} · {상태}`, 본문은 접힌 P2 값(요청일 · 연결 · 요청자)만 — 번호를 본문에 다시 쓰지 않는다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 목록 갈래 변경 없음(06-08 그대로)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: PC는 행 `구매 완료` 링크 → `Ctrl+Enter` → 다음 `신청됨` 행 포커스 그대로(E2E 트레이서 · I-1 `전체` 보기). 폰은 행 탭 자리(`{번호} 상세 보기`, tabIndex 0 · Enter/Space)로 열고, 성공 뒤 포커스는 다음 `신청됨` 행의 탭 자리로
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: PC 행동은 `RowAction` 링크 그대로, 폰 행 탭은 Table `onRowTap`(06-09 `/cards` 표와 같은 계약)
