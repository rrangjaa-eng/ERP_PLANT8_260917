지금 화면(06-08 · 06-12 끝): S12는 견적 줄 연결만(라디오 `견적 줄` 하나) · 원화 예상 금액만 · S10 구매 요청 모드에 3차 없음 · S11은 필터 + 읽기 표 + `구매 완료` 행동뿐(취소 · 그룹 · 합계 · 외화 계산 없음) · S8 필터 묶음 끝 링크 없음. 계획: 아래 항목대로 더한다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: S12 새 글자는 막힘 문구(`{이름} {MM-DD} 소속 없음 · 소속 발령은 관리자` · `환율 없음 · USD 환율 적기`)와 외화 원화 환산 숫자 하나뿐이고 팀 값에 설명형 힌트가 없다(M-5). S10 3차 `팀 비용으로`는 다음 한 수 버튼. S11 결과 줄 `구매 요청 취소됨 · {번호}`는 마지막 한 건 상태 한 줄
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 목록 1차는 연결 `팀 비용`이 골라진 채 열리고 팀은 서버가 요청자 오늘 소속으로 채운다(고르는 칸 없음). 환율 기본값 = 설정 최근 환율, 원화 환산액 · 공급가 추정은 서버 계산. 본인 취소는 사유 없이 즉시
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: `팀 비용`에는 프로젝트 · 견적 줄 「바꾸기」가 서지 않는다. S11 `요청 취소`는 `신청됨` 행 · 취소 가능한 사람에게만 렌더(구매 완료 · 취소 행 0). 소속이 없으면 1차 비활성
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: S12 1차 `구매 요청 Ctrl+Enter` 하나(PanelForm), S11 머리 1차 `구매 요청` 하나. 행 `요청 취소` · `되돌리기`는 3차 행동
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: S11 `요청 취소`는 행동 칸 맨 끝 `RowAction danger`, 남의 요청 취소는 사유 확인 창(1차 `구매 요청 취소` · 2차 `닫기 Esc`)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 행 3차 접근 이름 `{번호} 요청 취소`(번호는 sr-only), 결과 줄은 번호만 한 번. 합계 줄은 `합계 ({보기} · N건)` 한 번
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: S11 빈 목록 갈래는 06-08 그대로(첫 행동 `구매 요청`) · S8은 쓸 카드가 0장이라 필터 줄이 없는 빈 화면의 행동 한 개가 같은 하위 링크(`구매 요청 {N}`)를 맡는다(카드 없는 직원도 구매 요청을 하는데 길이 막히지 않게)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: S12 `Ctrl+Enter` · 행 `요청 취소` Enter → 결과 줄 포커스 `되돌리기`(Enter로 되돌림). 확인 창은 첫 포커스 사유 칸 · Ctrl+Enter
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 행 행동은 `RowAction`(링크 `구매 완료` · 버튼 `요청 취소`) — 06-09 `삭제`와 같은 모양, 결과 줄 `되돌리기`도 `RowAction`

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: S12 = 옆 패널(PC 480 · 폰 시트) 그대로, 등록 뒤 패널 유지(UQ-8), 확인 창은 되돌릴 수 없는 남의 요청 취소에만(본인은 되돌리기). 새 색 · 간격 없음
