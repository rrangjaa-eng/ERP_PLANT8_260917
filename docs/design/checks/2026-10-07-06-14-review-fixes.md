## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자 없음. `요청 취소` · 사유 창 문구는 06-14 UI-SPEC Copywriting 그대로 재사용(패널 안 행동 이름 `{번호} 요청 취소`도 행과 같다)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 본인 요청은 사유 없이 즉시(되돌리기), 남의 요청만 사유 창 — PC와 같은 서버 갈래(`cancelBranch`, 서버가 정한다)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 패널의 `요청 취소`는 `신청됨`이고 취소 권한이 있을 때만(`cancelBranch` null이면 렌더 0), PC(≥700)에서는 행 행동이 이미 있어 숨긴다
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 패널의 1차는 `구매 완료 Ctrl+Enter` 하나 그대로, `요청 취소`는 품목 줄 옆 3차(danger 글자)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: `RowAction danger` 그대로(`--status-danger`), 행동 줄(1차 · 2차)이 아니라 품목 줄에 떨어져 있다
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 접근 이름은 `{번호} 요청 취소`(번호 sr-only), 보이는 글자는 `요청 취소` 하나 — 행과 같은 규칙
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 갈래는 건드리지 않았다
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 새 3차는 `button`(Tab · Enter), 사유 창 첫 포커스 사유 칸 · Ctrl+Enter 그대로. 취소 뒤 포커스를 `되돌리기` · 되살린 행 · 화면 제목으로 돌려 키보드 흐름이 끊기지 않는다(E2E `toBeFocused`)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 행 `요청 취소`와 같은 `PurchaseCancelButton`(RowAction danger) 재사용

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 옆 패널 · 시트 골격 · 확인 창 폭 480(UQ-6) 그대로, 패널 닫기 규칙(DR1)은 `requestClose("success")`로 기존 경로 사용, 새 색 · 간격 없음
