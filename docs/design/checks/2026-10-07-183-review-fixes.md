지금 화면(9b257db): ① 완료 프로젝트에서 실행가를 넘긴 구매 완료 건을 고치면 `실행가 초과 · … · 다른 줄 고르기` 막힘이 서고 1차가 비활성인데, 연결을 바꿀 수 없어 `다른 줄 고르기`가 갈 데가 없다(/review I-1). 메모만 고쳐도 저장되지 않는다. ② 구매 요청 진입 줄 모드가 서버 거부 꼬리 `· 카드 사용은 다른 줄`을 떼지 않아 할 수 없는 다음 한 수가 보인다(m-1). ③ 폰 S13 패널 · 행 시트의 본인 `요청 취소`가 거부돼도 모달이 닫혀 결과를 모달 뒤에서만 말한다(m-4). 계획: ① 연결 고정 건은 화면 상한 막힘을 세우지 않고 서버(담당 PM 갈래)에 맡기며, 연결 · 금액 칸이 저장값 그대로인 수정은 막힘을 세우지 않는다. ② 진입 모드도 두 꼬리를 뗀다. ③ 거부면 모달을 열어 두고 버튼 옆에 거부 한 줄(role=alert).

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자 없음. ③의 한 줄은 서버 거부 문구 그대로(`다른 저장이 먼저 됨 · 새로 고침` 등, 결과 줄과 같은 글자), ②는 글자를 빼기만 한다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: ①은 금액이 늘지 않는 수정을 시스템이 통과시켜 사람이 「다른 줄」을 고민하지 않는다(서버도 같은 판정 — `split.supplyKrw <= storedSupplyKrw`)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: ① 연결 고정 건에 `다른 줄 고르기` 버튼을 그리지 않는다(`!linkLocked`), ② 진입 줄 모드에서 `카드 사용은 다른 줄` 꼬리를 뗀다(줄을 바꿀 수 없다) — E2E `[183 I-1]` · `[183 m-1]`이 글자 0을 단언
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 패널 1차(`카드 사용 저장` · `구매 요청` · `구매 완료`)는 그대로 하나, ①은 막힘이 사라져 1차가 활성(E2E `aria-disabled` 아님 단언)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: `요청 취소`는 기존 RowAction danger 그대로, 거부 한 줄은 기존 `.undoFailed`(`--status-danger`)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: ③ 거부 한 줄은 모달 안에서만 보인다 — 모달이 열린 동안 뒤 결과 줄은 inert 뒤에 가려 같은 글자가 두 번 읽히지 않고, PC 행(모달 없음)은 결과 줄 하나만 쓴다(`onDone` 없으면 버튼 옆 줄 없음)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 갈래는 건드리지 않았다
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: ① 메모 칸에서 Ctrl+Enter로 저장 → 닫힘(E2E), ③ 모달이 열린 채라 포커스가 버튼에 남고 Tab 흐름이 끊기지 않는다
