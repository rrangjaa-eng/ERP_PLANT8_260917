# 06.2-09 계급 「보는 범위」 열 · 지출결의 결재선 낱말 · 범위 밖 프로젝트 링크 — 점검표
화면: app/(app)/admin/people/roles/roles-client.tsx, app/(app)/expenses/[id]/page.tsx, app/(app)/expenses/[id]/expense-document.tsx
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §7-2 · §7-3 · §7-13(06.2 보강) · §8 · 06.2-UI-SPEC S1 · S5 · S6

지금 화면(고치기 전): 계급 표에 보는 범위 열이 없어 관리자가 행 범위를 화면에서 바꿀 수 없다(DB · 도메인만 06.2-01) · 작성 중 지출결의 결재선이 문서 정보 없는 미리보기라 1단 담당자 이름이 비어 있다 · 지출결의 문서의 프로젝트 칸이 늘 상세 링크라 결재 차례로만 문서를 보는 사람에게 404로 가는 죽은 링크다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자는 열 머리글 `보는 범위` · 선택지 `전사` `본부` `팀` `본인` · 폰 읽기 글자 `보기 {낱말}` · 저장 실패 한 줄(서버 원문, 없으면 `저장 실패 · 다시 시도`)뿐. 저장 성공 · 반영 시점 안내 문구 없음(값 자체가 결과). 결재선 · 프로젝트 칸은 새 문구 0(죽은 링크 대신 같은 글자, 설명 없음)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 새 계급은 DB 기본 `팀`(계급 추가 패널에 칸을 더하지 않음, D-6203). 결재선 담당자는 서버가 문서 팀(프로젝트 팀 · 귀속 팀)으로 푼다 — 기안자가 고르지 않는다. 링크 여부는 서버 불린(`canOpenProject`)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 보관된 계급 select `disabled`(업무 범위 칸과 같음). 열 수 없는 프로젝트는 링크를 그리지 않는다. 쓰기 권한 없는 사람의 렌더 조건은 업무 범위 칸과 같게 두었다(UI-SPEC A-14 — 서버가 거부)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 계급 화면 1차 `계급 추가` 그대로, select 셀은 즉시 저장이라 버튼 없음. 지출결의 폼 · 문서 화면의 1차는 바뀌지 않았다(결재선 한 줄 · 프로젝트 칸 글자만 바뀜)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 새 위험 동작 없음 — 계급 `삭제`는 기존 동작 열 그대로
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 폰 접힌 줄은 라벨 없이 값만이라 `보기 팀`으로 업무 범위 `자기 팀`과 가른다(design I8). select 선택지에는 접두가 없다. 결재선 단계 이름은 `approval_steps.label` 하나(목록 상태 열만 A-9 「목록만 줄임」으로 `팀장 결재 중`)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 보는 범위 select는 늘 값이 있다(06.2-01 이행이 모든 계급을 채움) — 빈 상태 없음. 계급 0 빈 화면은 기존 `ListEmpty` + `계급 추가` 그대로
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 네이티브 select(Tab으로 가서 화살표로 고르면 change → 저장). 접근 이름 `{계급 이름} 보는 범위`. 프로젝트 칸은 링크면 Tab 대상, 아니면 글자
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 보는 범위 칸은 업무 범위 칸과 같은 `styles.select` · 같은 실패 줄 자리(`registeredHint`). 프로젝트 칸 링크 모양은 기존 3차 그대로, 링크가 아닐 때는 KvList 값 글자

## 알려 둘 것 (감사자용)
