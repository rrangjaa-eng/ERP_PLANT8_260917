## Task 1 — 조직 화면 팀장 · 책임자 중복(D-6405 · D-6413 · D2 · D10)

지금 화면(고치기 전): 조직 화면 팀 · 본부 줄은 이름 입력 + 행동(`RowActions` 안 「팀 추가」 · 「삭제」)뿐이고 팀장 · 책임자 이름이 없다. 06.4 전에 저장된 중복 · 리포지토리 발령 중복이 있어도 화면 어디에도 드러나지 않고, 사람 목록에는 팀 거르기가 없어 정리할 사람을 찾을 길이 없다. 이번 변경: 겹치는 보유자가 2명 이상인 줄에만 기존 `RowActions` 첫 자리에 기존 `StatusTag variant="text"` 글자 `팀장 {n}명` · `책임자 {n}명`(warning) + 보유자 이름 `RowAction` 링크(그 사람 상세). 새 컴포넌트 · CSS · 토큰 없음.

## 원칙

- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 노출(`admin.people` 보기 ∧ `person.value` ∧ `team.value`)이 없는 뷰어에게는 서버가 prop 자체를 보내지 않아 태그 · 링크가 없다(통합 게이트 사례 3). 한 명이거나 없는 줄은 아무것도 없다(E2E 한 명 팀 줄 0)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 머리 1차 「본부 추가」 그대로, 새 1차 0. 보유자 링크는 행 행동(3차 모양 `RowAction`)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 「삭제」(`DeleteToArchive` danger)는 `RowActions`가 맨 끝으로 보내고 앞 여백 --s-4를 더한다(기존 규칙) — 태그 · 이름 링크는 그 앞
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 개수는 태그에, 이름은 링크에 한 번씩. 줄의 이름 입력(팀 · 본부 이름)과 겹치는 낱말 없음
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음(빈 화면 변경 없음 — 본부 0이면 기존 「본부 추가」 하나)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 보유자 이름은 `<a>`(`RowAction href`)라 Tab 정지점 · Enter로 상세 이동. 태그는 비대화형 글자라 정지점이 아니다. 상세에서 계급 select로 강등 → 조직 화면 재방문 때 사라짐(D10 무효화, E2E)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 보유자 이름은 같은 줄 「팀 추가」와 같은 `RowAction` 링크 모양, 태그는 기존 `보관됨`과 같은 `StatusTag variant="text"`

## Task 2 — 등록 패널 · 사람 상세의 계급 자리(D-6402 · D-6414 · D3 ~ D9)

지금 화면(고치기 전): 등록 패널 계급 select · 상세 계급 변경 select가 보관 안 된 계급 전부를 보여 위임받은 사람은 고를 수 없는 계급(시스템 관리자 등)을 고른 뒤에야 서버 거부를 본다. 통과 계급이 없어도 1차 「사람 등록」이 있고, 하나뿐이어도 「계급 선택」부터 골라야 한다. 상한 밖 사람 · 자기 상세 · 쓰기 없는 계정에도 계급 변경 select가 있고, 거부되면 select에 거부된 값이 남는다. 이번 변경: 서버가 계산한 통과 계급만 · 0이면 1차 숨김(낡은 주소 패널은 첫 옵션 `—` + `PanelForm blockedReason`) · 1이면 미리 선택 · 상세는 서버 상태표(줄 없음 / `Form.Hint` 이유 한 줄 / select) · 제어 select(거부 → 저장값, 저장 중 `aria-busy`). 새 컴포넌트 · CSS · 토큰 없음.

- [x] 할 수 없는 선택지는 숨긴다(D-6402 · CLAUDE.md §7) — 근거: 등록 · 상세 select 재료가 `listAssignableRoles`(서버 상한 계산) — E2E 「등록」 · 「상세 통과」가 옵션에 `시스템 관리자` 없음을 단언. 숨김은 UX이고 서버 거부(06.4-01 · 02)가 관문

## Task 3 — 「삭제」 · 퇴직일 칸 상태(D-6417 · R2) · 삭제 거부 사유(D-6418 · R3)

지금 화면(고치기 전): 사람 목록 「삭제」가 본인 줄 · 상한 밖 대상 줄에도 있어 누르면 언제나 거부되고, 거부되면 `삭제 실패 · 다시 시도`라 원인이 가려진다(다시 해도 같은 거절). 상세 퇴직일 칸은 상한 밖 대상에도 있고, 거부된 날짜가 칸에 남는다. 이번 변경: 목록 행 조건에 본인 · 상한 밖 제외(계급 id 한 번에 판정), 상세 퇴직일 칸은 상한 밖이면 없음(입사일 칸 그대로), 날짜 칸은 제어 값(거부 → 저장값), 사람 「삭제」 거부는 `삭제 실패 · {서버 문구}`. 새 JSX 요소 · CSS · 토큰 없음.

- [x] 할 수 없는 행동은 자리째 없다(D-6417) — 근거: 본인 · 상한 밖 줄 「삭제」 0, 상한 밖 대상 상세 `#resignationDate` 0 · `#hireDate` 1(E2E 「삭제 숨김」 · 「퇴직일 칸」). 마지막 관리자 대상은 숨기지 않는다(판정에 전원 조회 — D-6418 사유로)

- [x] 시스템(새 색 · 서체 · radius · CSS 없음) — 근거: `.css` 변경 0(`people.module.css` 무변경). 320 폭 확인 줄 넘침 · 44px · Tab 순서는 독립 DOM 감사 ⑦ 몫 — 결과 `/mnt/project-files/06.4-prep/design-review/dom-audit.md`(독립 DOM 감사에서 — 실행자 판정 아님)

## Task 4 — 조직 화면 중복 줄 폰 「더보기」(DOM 감사 ① · 결정 카드 추천안 (가) · DECISIONS 2026-10-13 SP-64-2)
