지금 화면(고치기 전, 06-15 결과): 「지급 대상」 표의 이체액 열은 지급 총액을 읽기로 되풀이하고 차이 사유 열은 늘 `—` — 실제 이체액이 다른 건(수수료)은 일괄 흐름에서 적을 수 없어 문서 화면으로 하나씩 가야 한다. 고른 건 합이 없어 은행 합계와 맞춰 볼 수 없다. 선택은 지금 쪽 행만 남고(쪽을 넘기면 사라짐), 번호 셀은 글자뿐이라 문서 화면으로 가는 길이 「프로젝트 · 항목」 링크 하나다. `확인 전` 행은 문서 화면으로 가서 확인한 뒤 돌아와야 한다. 모달 지급일은 열 때마다 오늘로 돌아간다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자는 칸 오류(`숫자 아님 · 13,640,000처럼` · `이체액 0 이하 · 금액 고치기` · `차이 사유 없음 · 사유 적기` — action-row.ts 상수 그대로) · 합 실패 `합계를 받지 못함` + 2차 `다시 시도`뿐. 사유 칸에 자리 표시 설명 없음, 합계 줄은 `고른 N건 · 이체액 {합}` 값 줄
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 이체액 기본값 = 서버 지급 총액(편집 칸 initial), 고치면 그 행이 저절로 골라짐(체크를 따로 할 필요 없음 — E2E 「이체액 고침 → 자동 선택」 checked 단언). 합 · 차이는 서버 액션 값(sumSelectedTransfers — sumKrw · diffKrw), 사유 칸은 이체액 ≠ 지급 총액일 때만 선다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 편집 칸은 selectable(서버 판정) · ≥1024 행에만(editability `edit`), 막힌 행은 읽기 값. 사유 칸은 차이 없으면 `—` 읽기 전용(aria-readonly) — E2E가 편집 전 `차이 사유` 칸 0개를 단언
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 1차는 06-15 `지급 완료 N` 하나 그대로 — 오류 칸이 있으면 모달 없이 첫 오류 칸으로(firstIssueSignal), 합 실패 `다시 시도`는 2차(variant secondary)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 삭제 행동 없음. 되돌릴 수 없는 일괄 지급은 06-15 확인 모달(S2) 그대로 — 이번에 부제 합계가 붙어 무엇을 지급하는지 금액으로 보인다
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 차이는 이체액 셀 2행 한 자리(사유 칸에 다시 쓰지 않음), 칸 오류는 그 셀 아래 한 줄(표가 aria-describedby로 묶음). 합 실패 글자는 합계 줄 · 모달 막힘 자리 중 보이는 한 곳
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 06-15 빈 화면(`지급할 건이 없습니다 · 지급 완료 보기` · `필터 지우기`) 그대로 — 이 플랜이 바꾸지 않음(E2E 「빈 지급 대상」 녹색)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 이체액 · 사유 칸은 04.6 ui/table 편집 칸 계약(editCell — Enter 편집 · Enter 확정 · Esc 되돌림 · Tab/방향키), 쉼표는 05 useCommaInput이 자동. Space 고르기 · 표 안 Ctrl+Enter = 1차(06-29 onPrimary) 그대로
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 편집 칸 입력 모양은 리저브 대장 셀 입력과 같은 토큰(accent-weak 면 · accent 아래선), `다시 시도`는 §7-7 로드 오류와 같은 2차 버튼
