지금 화면(고치기 전, 06-15 결과): 「지급 대상」 표의 이체액 열은 지급 총액을 읽기로 되풀이하고 차이 사유 열은 늘 `—` — 실제 이체액이 다른 건(수수료)은 일괄 흐름에서 적을 수 없어 문서 화면으로 하나씩 가야 한다. 고른 건 합이 없어 은행 합계와 맞춰 볼 수 없다. 선택은 지금 쪽 행만 남고(쪽을 넘기면 사라짐), 번호 셀은 글자뿐이라 문서 화면으로 가는 길이 「프로젝트 · 항목」 링크 하나다. `확인 전` 행은 문서 화면으로 가서 확인한 뒤 돌아와야 한다. 모달 지급일은 열 때마다 오늘로 돌아간다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자는 칸 오류(`숫자 아님 · 13,640,000처럼` · `이체액 0 이하 · 금액 고치기` · `차이 사유 없음 · 사유 적기` — action-row.ts 상수 그대로) · 합 실패 `합계를 받지 못함` + 2차 `다시 시도`뿐. 사유 칸에 자리 표시 설명 없음, 합계 줄은 `고른 N건 · 이체액 {합}` 값 줄

## Task 2 — 지급일 재계산 막힘 · 지급일 기억 · 합 실패 · 결과 줄 ③ · 일괄 결과 알림(DR-6 · H-3)

지금 화면(고치기 전): 지급일 세율로 막힌 행은 이유 줄만 서고 지급 총액 셀은 옛 값이라 재시도가 같은 이유로 다시 막힌다. 모달 지급일은 모달 안 상태라 화면이 다시 마운트되면(쪽 이동) 오늘로 돌아간다. 처리 뒤 포커스는 모달을 연 요소로만 돌아간다.

- [x] 결정 최소(O-3) — 근거: 모달 지급일은 방금 고른 날을 기본값으로(화면 밖 기억 — 같은 필터 키) · 필터를 바꾸면 오늘(E2E 「모달 지급일 기억(O-3)」). 재시도는 새 지급 총액으로 보내 사람이 다시 고칠 것이 없다(E2E 「일괄 결과 알림」 재시도 단계 · 통합 「새 값 재시도 → 처리」)
- [x] 상태는 글자 · 색으로(문구 최소) — 근거: 결과 글자는 06-15의 처음부터 있는 빈 `aria-live` 한 곳(E2E ⑴ 빈 요소 1개 → ⑵ `{시:분} 지급 완료 1건 · 막힘 2건`), 막힌 행 이유는 06-15 위험 색 줄 그대로 — 새 문구 없음. 결과 줄 ③은 해당 묶음만(둘 다 없으면 줄 없음)
- [x] 키보드 · 포커스(DR-6) — 근거: 모달이 닫히면 첫 막힌 행 체크박스(`aria-disabled`여도 — SYSTEM §10), 막힘 0이면 1차 버튼(E2E 「막힘 0」). 막힌 행 체크박스 `aria-describedby` = 게이트 이유 글자 id + 이유 줄 id 둘(E2E ⑶)
- [x] 할 수 없는 선택지는 비활성(H-3) — 근거: 게이트로 막힌 행은 선택 · 편집이 풀리고 체크박스 `aria-disabled`, 지급일 세율 막힘 행은 선택 유지(E2E ⑸ · 단위 「처리 결과 적용」)
- [x] 새 토큰 · 폭 없음 — 근거: 모달 폭은 06-29 ConfirmDialog `--dialog-w` 그대로(`--modal-w` grep 0), CSS 추가 없음

## Task 4 — 제자리 증빙 확인(DR-4 · S1) · 증빙 금액 초과 한 줄(Q-F) · 짝 막힘 · 보관 되살리기 검증(C-1)

지금 화면(고치기 전): `확인 전` 행의 증빙 칸은 글자뿐이라 확인하려면 문서 화면으로 가서 확인하고 돌아와야 한다. 돌아오면 그 행을 다시 찾아 골라야 하고, 확인한 증빙이 모달을 연 뒤 바뀌었는지 알 길이 없다.

- [x] 안내 문구 최소 · 명사형 — 근거: 새 글자는 거부 이유뿐이다 — `증빙 불러오지 못함` · `확인 전 아님 · 새로 고침` · `없는 지출결의 · 새로 고침` · 06-06 동시성 글자 `{이름}이 HH:MM에 증빙을 바꿈 · 새로 고침` 그대로. 토스트 없음(grep 0). 초과 한 줄은 서버 글자 그대로이고 숫자 조각만 굵게
