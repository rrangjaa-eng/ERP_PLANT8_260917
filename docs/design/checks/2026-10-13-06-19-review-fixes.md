지금 화면(고치기 전, 감사 /mnt/project-files/notes/06-review/06-19-dom-audit.md): 폰(<700)에서 행동 3차가 따로 P1 열이라 미결 지출결의 표가 P1 넷(항목 · 금액 · 상태 · 행동 — SYSTEM 「P1 최대 3열」 위반)이고 항목 칸이 320에서 46~50px로 눌려 17 · 28줄로 꺾인다(D-1). 320 · 실행가 상한 줄에서 미매칭 표가 본문보다 12px 넓다(D-2). 행 3차 접근 이름에 행 구분이 없다(`지출결의 열기` ×2, D-3). 1280에서 `점검 보기`가 제목을 창 맨 아래(top 768/800)에 두어 점검 행이 화면 밖이다(D-5). 제목 h2에 `id="pre-settle-check"`가 없다(O-1 · 플랜 ⑥).

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 이번 수정은 보이는 글자를 더하지 않는다. 접근 이름 앞 조각(`{번호} ` · `{번호} {항목} `)은 sr-only라 화면 글자가 늘지 않는다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 입력 칸 없음 그대로. 행의 문은 서버 DTO가 정한다(F-1로 쓰기 권한 없는 사람 · 범위 밖 문서는 문 자체가 오지 않는다)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 쓰기 권한이 없으면 문 대신 `담당 PM {이름}`(기존), 범위 밖 마지막 문서의 `지출결의 열기`는 그리지 않는다(404로 가는 링크를 두지 않음)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 섹션에 1차를 더하지 않는다. 행 3차의 자리만 폰에서 항목 셀 2행으로 옮긴다
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이 섹션에 위험 동작 없음(변화 없음)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 행동은 폭마다 한 자리에만 보인다 — ≥700은 행동 열(P3), <700은 항목 셀 2행(`.preSettlePhoneLine`). 다른 쪽은 display:none이라 접근성 트리에도 하나뿐이다(E2E `getByRole … exact` 1건)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 상태 `미결 없음`은 바꾸지 않는다
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: `점검 보기` → 제목 `#pre-settle-check`(tabIndex -1)에 포커스 + 제목이 창 위(상단 바 아래)로 스크롤, 다음 Tab은 첫 행 3차. E2E가 `#pre-settle-check` 포커스 · 행 toBeInViewport · 제목 top < 창 절반을 단언
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 같은 RowAction(이동 = 링크, 화면 안 만들기 = 버튼)을 자리만 바꿔 쓴다

## 사용자 결정(§1)
