지금 화면(고치기 전): S17 메모 칸 `max-width: min(24em, 100%)`의 백분율 상한이 auto 표 최소 폭 계산에서 빠져 200자 메모 한 건이 표를 2.7k px로 늘린다(D-1, 4폭 모두 넘침). 폰 320 · 375는 긴 값 없이도 프로젝트 칸 9em nowrap + 금액 2행 `합계 8,800,000` nowrap 때문에 표 최소 폭 369px로 넘친다(D-2). 1024 미만에서 `?issueRequest`로 `신청됨` 요청에 오면 수화 스냅숏(넓은 폭)의 `발행 줄로`에 포커스했다가 그 버튼이 사라져 BODY다(D-3). 확인 모달 1차 뒤 트리거 칸(메모 td)이 읽기 칸이 되어 포커스를 못 받아 BODY다(D-4). 프로젝트 링크 색이 UA 기본 파랑이다(D-5). 취소로 바뀐 상태 칸에 dirty 표시가 없다(D-6). 상태 필터는 ArrowDown 한 번에 이동하고 포커스를 잃는다(D-7).

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 이번 수정은 보이는 글자를 하나도 더하지 않는다(메모 · 프로젝트는 같은 글자를 말줄임, `합계 {금액}`은 같은 글자에 줄바꿈 자리만)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 입력 칸 · 선택지 변화 없음. 도착 · 취소 뒤 포커스를 화면이 정해 사용자가 줄을 다시 찾지 않는다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 1024 미만 보기 전용 · 행 3차 숨김 그대로. 도착 포커스가 1024 미만에서 (사라지는) `발행 줄로`가 아니라 줄 자체로 간다
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: S16 1차 `일괄 저장 Ctrl+S N` · S17 1차 없음 그대로
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 취소 흐름(Delete → 확인 모달) 그대로. 확인 뒤 포커스만 취소한 줄로
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: dirty 표시는 상태 칸 외곽선 · 면 색뿐(글자 없음), 상태 낱말 `취소` 하나 그대로
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 변화 없음(`처리할 발행 요청이 없습니다 · 전체 보기`)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 900 · 375 도착 시 그 요청 줄(tr tabindex -1)에 포커스 + 화면 안(E2E toBeFocused · toBeInViewport), 확인 모달 1차 뒤 취소한 줄에 포커스(E2E toBeFocused) → Ctrl+S. D-7 상태 필터의 「ArrowDown 한 번에 이동 · 이동 뒤 BODY」는 프로젝트 목록 상태 필터와 같은 공용 동작(실측 — 프로젝트 목록도 ArrowDown 한 번에 `?status=bidding…`로 이동, 이동 뒤 BODY · 지출결의 StatusFilter도 같은 onChange 즉시 제출 코드)이라 바꾸지 않고 관찰로 둔다
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: S17 프로젝트 칸 링크가 프로젝트 목록 · 지출결의 목록의 식별자 링크와 같은 `projects.module.css .link`(--accent · 밑줄 1px → hover 2px)를 쓴다(E2E color === --accent)
