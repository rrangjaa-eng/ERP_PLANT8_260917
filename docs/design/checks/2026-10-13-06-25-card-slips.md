## 원칙
- [x] 안내 문구: 새로 만든 설명문이 없다 — 근거: 증빙 칸은 05 `Attachments`(라벨 `증빙`, 버튼·목록 글자는 컴포넌트 소유)를 그대로 쓰고, 이 화면이 더한 글자는 목록 열 값 `있음`/`—` 뿐이다. 막힘 이유와 서버 거부는 기존 `reason` 줄(`blockedReason` · `serverError`)을 재사용 — 새 글자 0. 독립 DOM 감사 뒤 수정(D-1)에서 더한 `증빙 올리는 중 · 잠시 뒤 제출`은 지출결의 폼의 `UPLOADING_REASON`(SYSTEM §7-10 원문)을 그대로 가져온 것이라 새 글자가 아니다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 새 건에서 파일을 놓으면 같은 카드 사용 저장을 먼저 돌리고(`saveForSlip`) 올린 뒤 수정 패널로 넘어간다 — 사용자는 저장 순서를 고르지 않는다. 용량 상한은 설정값(`EVIDENCE_MAX_SIZE_MB`)을 서버가 내려준다. 폰 사진은 `prepare-file`이 최대 변 2000으로 줄인다(사용자 선택 없음)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 읽기만 되는 사람(`canAdd=false`)은 추가 버튼이 없고 삭제는 `deletableIds`에 든 파일에만 열린다. S13 구매 완료 패널은 `slip`을 넘기지 않아 증빙 칸 자체가 없다(E2E 단언)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 패널 1차는 기존 `카드 사용 등록`/`저장` 하나 그대로. 증빙 칸의 `파일 추가`는 컴포넌트 내부의 보조 행동이고 1차 버튼을 늘리지 않는다
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 파일 삭제는 `Attachments`의 행별 삭제(05 계약 그대로 · 위험 색은 컴포넌트 소유). 마지막 전표 삭제에도 확인 창을 만들지 않는다(되돌릴 수 있는 일 — 되돌리기 기준)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 감사 D-3 수정 — 막힌 새 건에 놓은 파일은 `refuseWhileBlocked`가 받지 않아 같은 막힘 문구가 막힘 줄 한 곳에만 선다(실패 파일 행 0, E2E `fileRows(sheet)` 0 · 문구 `toHaveCount(1)`). 목록 열 머리글 `증빙`과 값 `있음`/`—`은 한 번씩, RowSheet(폰)에도 `증빙` 항목 한 줄. 패널 라벨 `증빙`은 칸 라벨 하나이고 칸 안에 같은 글자를 되풀이하지 않는다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 전표가 없을 때 증빙 칸은 컴포넌트의 파일 추가 행동이 먼저 보이고 설명문은 없다. 목록 빈 화면은 기존 그대로
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 올리는 동안은 클릭 · Ctrl+Enter 모두 막혀 저장이 나가지 않는다(D-1 E2E: 서버 액션 POST 0 · version 그대로). 올리는 동안 떠나면 브라우저 기본 경고 `beforeunload`가 뜨고 끝나면 없다(E2E `page.close({ runBeforeUnload })`). `Ctrl+U`가 파일 고르기(`isCtrlCombo(event, "u")` → `openSignal`), Tab으로 증빙 칸의 버튼에 닿고, 제출은 기존 Ctrl+Enter. 구매 완료 패널의 Enter 차단은 그대로
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 06-16 결재 증빙 칸과 같은 `Attachments` 컴포넌트 · 같은 `field-row` 한 줄 · 같은 `Form.Field` 라벨. 목록 증빙 열은 지출결의 목록 증빙 열 표기(`있음`/`—`)와 같은 꼴
