# 06 교차 검토 U1-2 「내 차례」 계산 한 요청 한 번 — 점검표
화면: app/(app)/layout.tsx, app/(app)/page.tsx
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §7-7 「내 차례」(출력 무변경 확인용)

지금 화면(고치기 전): 레이아웃이 폰 탭 `내 차례 N` 건수를 얻으려고 `listNextTurnItems(viewer)`를, 홈이 목록을 위해 `listNextTurnItems(viewer, { withDetails: true })`를 따로 불러 홈 요청 하나에서 같은 계산(결재함 · 막힘 · Phase 6 묶음 · 정산 점검)을 두 번 한다. 화면 출력(태그 · 글자 · 건수 · 버튼)에는 문제가 없다 — 이번 변경은 서버 계산 경로만 바꾸고 JSX · CSS는 그대로다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 글자 변경 0(두 파일의 diff는 import 한 줄 · 호출 한 줄씩). 홈 오류 줄 `내 차례 불러오지 못함`과 레이아웃 실패 시 라벨 `내 차례` 갈래 그대로
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 입력 칸 · 선택지 없음. 건수는 같은 공급 함수의 길이 그대로(S19 묶음 1줄 = 1건 정의 무변경)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 선택지 변화 없음 — 항목 · 행동 링크는 공급 함수가 그대로 정한다
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 홈 · 셸 구성 무변경(JSX diff 0)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험한 동작 추가 · 변경 없음
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 글자 변경 0. 폰 탭 건수와 홈 목록이 이제 같은 계산 결과를 쓰므로 둘이 어긋날 틈이 오히려 준다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 상태 갈래(`표시할 항목이 없습니다`) · 건수 0이면 탭 숫자 없음 그대로
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 마크업 변경 0 — 기존 링크 · 버튼 그대로
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 행동 컴포넌트 변경 0(ui buildNextTurnView · 셸 그대로)

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 바탕 · 패널 · 시트 · 토큰 무변경, 서버 데이터 읽기 경로만 바뀐다
