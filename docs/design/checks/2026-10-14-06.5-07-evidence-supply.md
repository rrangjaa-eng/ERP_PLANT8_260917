## 지금 화면 기준으로 어긋난 것(고치기 전)
- S4 증빙 섹션에 `증빙 금액` 행 · 입력자 2행 · 증빙 금액 칸(F2 빈 금액이면 처음부터 열림) · Q-F 넘침 줄이 있다 — D-6520으로 대상이 없어졌다.
- 1차 글자가 `증빙 확인` 하나 — 값을 고쳐도 글자가 같아 버튼이 실제 동작을 말하지 않는다(§8).
- 지급 뒤(P5)에도 `바꾸기`가 서서, 누르면 서버가 LOCKED로 막는다(할 수 없는 선택지가 보임).
- (Task 2 · S1) 지급 대상 제자리 확인 모달 부제 끝이 `증빙 금액 {금액}`, 결과 줄 다음에 Q-F 넘침 줄, 1차 `증빙 확인`. 증빙 금액이 빈 `확인 전` 행(R10-F2)은 ≥1024에서도 모달 대신 문서 화면 링크라 행마다 행동이 달랐다. 고친 뒤에도 부제 끝 `공급가액 {금액}`(V8 S1)은 남는다 — 보기 DTO(domain/payments/targets.ts · 06.5-09 소유)에 공급가가 없어 06.5-07-SUMMARY 「열린 일」로 넘긴다.
- (후속 · 06.5-09 뒤) S1 모달 부제가 `{번호} · {프로젝트 · 항목}`에서 끝나 V8 S1의 `공급가액 {금액}`(문서 통화)이 없었다 — 보기 DTO `EvidenceConfirmView`에 `supply`(통화 · 금액, 정보 항목 expense.amount)를 싣고 부제 끝에 그린다.
- (Task 2 · S4) 고침 미리보기가 원화 문서만 다시 셈했고, 상한을 넘는 값은 1차를 눌러야 칸 오류가 섰다.

S1은 빈 증빙 금액 행도 같은 모달 하나로 확정한다(payment-targets-table.tsx · S3 paid-list.tsx의 R10-F2 갈래 지움 — E2E payment-batch 「금액 빈 확인 전도 모달」 · 「S3 제자리 증빙 확인」).
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: `바꾸기`는 서버 행 P2(tertiary "change")에서만 렌더(P5는 action-row.ts가 tertiary null — 단위 시험), 빈 칸이면 1차 aria-disabled + 이유(E2E P2), 금액을 못 보는 사람에게는 공급가 투영이 빠져 행 자체가 없다.
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 행동 줄 1차 자리 하나에 `공급가액과 같음` / 값이 다를 때만 `공급가액 고쳐 확인`(payment-action-row.tsx confirmLabel) — 칸 옆 저장 버튼 없음(SP-3 ①). S1 모달 1차는 `공급가액과 같음` 하나(CONFIRM_SUPPLY_SAME · Ctrl+Enter, 고침 칸 없음).

- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 빈 칸 이유는 1차 옆 한 자리에만 서고 칸 오류로 되풀이하지 않는다(confirmBlock은 fieldError가 없을 때만 · E2E에서 `#corrected-supply-error` 0). 자리표시자 · 단위 글자 없음. S1 부제 끝 공급가액은 결과 줄(TaxParts — 원화 환산 · 부가세 · 지급 총액)에 없는 값이라 되풀이가 아니다(domain/expenses/tax.ts 결과 줄 조각에 공급가 칸 없음).
