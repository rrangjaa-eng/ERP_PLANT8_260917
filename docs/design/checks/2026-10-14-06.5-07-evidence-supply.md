## 지금 화면 기준으로 어긋난 것(고치기 전)
- S4 증빙 섹션에 `증빙 금액` 행 · 입력자 2행 · 증빙 금액 칸(F2 빈 금액이면 처음부터 열림) · Q-F 넘침 줄이 있다 — D-6520으로 대상이 없어졌다.
- 1차 글자가 `증빙 확인` 하나 — 값을 고쳐도 글자가 같아 버튼이 실제 동작을 말하지 않는다(§8).
- 지급 뒤(P5)에도 `바꾸기`가 서서, 누르면 서버가 LOCKED로 막는다(할 수 없는 선택지가 보임).

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: S4에 새로 선 글자는 빈 칸 이유 `공급가액 비어 있음 · 공급가액 적기`(오류) · 상한 칸 오류 `남은 실행가 … 넘음 · 공급가액 고치기`(오류) · P5 잠김 줄 `지급 완료 문서 · 공급가액 못 바꿈 · 지급 취소 뒤 고치기`(잠김) 셋뿐이고, 힌트 `확인하면 {전} → {후}`는 서버 계산 값의 자리(§6-3). 입력자 2행 · 넘침 줄은 지웠다(evidence-review-section.tsx).
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 고침 칸은 지금 공급가액으로 채워 열리고 전체 선택된다(openEdit). 원화 환산 · 남은 실행가는 서버(moneyToColumns · supplyCorrectionCap)가 셈하고 환율 칸은 없다. 고치지 않으면 1차 한 번으로 끝난다.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: `바꾸기`는 서버 행 P2(tertiary "change")에서만 렌더(P5는 action-row.ts가 tertiary null — 단위 시험), 빈 칸이면 1차 aria-disabled + 이유(E2E P2), 금액을 못 보는 사람에게는 공급가 투영이 빠져 행 자체가 없다.
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 행동 줄 1차 자리 하나에 `공급가액과 같음` / 값이 다를 때만 `공급가액 고쳐 확인`(payment-action-row.tsx confirmLabel) — 칸 옆 저장 버튼 없음(SP-3 ①).
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 해당 없음 — 이번 변경에 새 위험 동작이 없다(기존 2차 `지급 취소` 자리 · 모양 그대로).
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 빈 칸 이유는 1차 옆 한 자리에만 서고 칸 오류로 되풀이하지 않는다(confirmBlock은 fieldError가 없을 때만 · E2E에서 `#corrected-supply-error` 0). 자리표시자 · 단위 글자 없음.
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음 — 빈 목록 화면이 아니다. 빈 고침 칸은 1차 비활성 + 이유 한 줄.
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: `바꾸기` → 칸 포커스 · 전체 선택, `Esc`는 서버 값으로 되돌려 닫고 포커스를 `바꾸기`로, `Enter`는 제출하지 않고 `Ctrl+Enter` = 1차(SupplyInput onKeyDown · 행동 줄 keydown 그대로). 칸 오류 뒤 포커스는 고침 칸(E2E P2 `toBeFocused`).
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: `바꾸기`는 기존 3차 Button(variant tertiary) 그대로, 접근 이름 `공급가액 바꾸기`. LOCKED 서버 거절은 기존 충돌 갈래(ConflictLine + `새로 고침`)로만 선다.
