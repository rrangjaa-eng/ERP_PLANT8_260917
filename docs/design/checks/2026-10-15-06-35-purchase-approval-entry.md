지금 화면(고치기 전, Task 1): 진행 · 고객 승인 전 프로젝트의 견적 줄 표에서 온라인구매 줄 행에 `구매 요청` 링크가 열려 있다(지출결의 문은 표 위 `1차 고객 승인 전 · 고객 승인 표시` 한 줄로 닫혀 있는데 구매 요청 문만 열림 · `Ctrl+E`도 이동). 구매 요청 패널 `견적 줄 바꾸기` 목록의 바닥 줄 이유가 프로젝트 전체 이유와 무관하게 언제나 `온라인구매 줄 없음`이다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 문장 0. 표 위 `{n}차 고객 승인 전 · 고객 승인 표시`는 지출결의 문이 이미 쓰던 기존 잠김 한 줄(`doorGateLine`)이고, 줄 고르기 2행 · 바닥 줄은 서버(`projectBlockedReason` · `reason`)가 보낸 같은 문자열이다. 폰 행 시트는 기존 `styles.doorNote` 한 줄
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 고객 승인 판정은 서버(`tableGateReason` · `projectBlockedReason`)가 하고 화면은 문자열만 읽는다. 사용자 입력 칸 추가 0
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 고객 승인 전에는 표 셀의 `구매 요청`을 그리지 않고(숨김 · 이유는 표 위 한 줄), 줄 고르기는 줄이 aria-disabled + 2행 이유 + 1차 `이 줄로` 비활성(PickDialog 기존 동작). E2E `[G-06-D]`가 링크 0 · aria-disabled · 바닥 줄 글자를 DOM으로 단언
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 버튼 추가 · 변경 없음. 줄 고르기 1차 `이 줄로` 하나 그대로(비활성일 때 바닥 줄이 이유)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 해당 없음 — 위험 동작 추가 · 변경 없음
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 표 전체 이유는 표 위 한 줄 하나뿐이고 줄마다 비활성 `구매 요청` + 이유로 반복하지 않는다(셀은 아무것도 그리지 않음 · 지출결의 갈래와 같은 처리). 줄 고르기의 행 2행 이유와 바닥 줄 이유는 PickDialog 기존 구조(행별 이유 + 바닥 줄 한 자리)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음 — 빈 상태 변경 없음. 줄 0 · 고를 수 있는 줄 0의 다음 한 수 `팀 비용으로`는 그대로
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 막힌 표에서 `Ctrl+E`는 무동작(`opensPurchase`가 `tableGateReason`을 따름 · 지출결의 갈래와 같은 조건). 승인되면 `Ctrl+E`가 구매 요청으로 이동(기존 `quote-line-status` 사례). 줄 고르기는 PickDialog 기존 키 구성
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 열린 `구매 요청`은 기존 `RowAction` 링크 그대로, 새 모양 없음
