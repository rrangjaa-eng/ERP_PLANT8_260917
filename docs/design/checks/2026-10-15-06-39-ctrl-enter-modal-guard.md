# 06-39 열린 모달 안 Ctrl+Enter 가드(G-06-H) — 점검표
화면: app/(app)/expenses/[id]/payment-action-row.tsx, app/(app)/projects/[id]/settlement/settlement-actions.tsx
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §7-9 「그때 보이는 1차」

지금 화면(고치기 전): 지출결의 문서 화면에서 `증빙 무효 처리` 모달 사유 칸의 Ctrl+Enter 한 번이 모달 1차(`무효 처리`)와 함께 화면 1차(`지급 완료`)까지 서버 액션으로 보낸다(E2E가 `expectedPayableKrw`를 실은 POST 1건으로 실측) — 원 증상은 행동 줄의 거짓 `다른 사람이 … 바꿈 · 새로 고침` 줄.
지금 화면(고치기 전): 같은 모달의 사유가 빈 칸이어서 모달 1차가 막혀 있어도 Ctrl+Enter가 화면 1차 `지급 완료`를 보내 지급 기록(`expense_payments` 1행) · 행동 로그 `payment_process`가 남는다(실제 돈 이동).
지금 화면(고치기 전): 반려된 정산 결재 문서 화면 폰 「더보기」 시트 안 Ctrl+Enter가 `정산 결재 다시 올리기` 서버 액션을 부른다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 글자 추가·삭제 0. 키 입력 리스너 첫머리에 조건 한 줄만 더했다(두 파일 diff에 문자열 리터럴 변경 없음)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 사용자 결정이 늘지 않는다. 오히려 모달에서 습관대로 누른 Ctrl+Enter가 그 모달의 일 하나만 하게 되어 따라 일어나던 지급 판단이 사라진다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 막힌 모달 1차(사유 빈 칸)는 그대로 비활성이고, 그 상태의 Ctrl+Enter가 화면 1차로 새던 경로를 닫았다(E2E ⓑ). 버튼·선택지 변화 0
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 화면 모양 변화 0. 지급 행동 줄 1차 `지급 완료`(또는 그때 보이는 1차) · 정산 `정산 결재 다시 올리기` 하나씩 그대로이고, 모달이 열린 동안의 1차는 모달 1차 하나다
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 해당 없음 — 버튼 추가·이동 0. 오히려 의도하지 않은 지급(돈 이동) 경로를 닫았다
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 글자 변경 0. 거짓 `다른 사람이 … 바꿈 · 새로 고침` 줄이 자기 변경을 남의 변경처럼 두 번 말하던 경로를 닫았다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음 — 빈 화면 변경 0
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 모달 안 Ctrl+Enter = 모달 1차(ConfirmDialog 불변), 모달 밖(지급일 · 지급 예정일 칸 포함) Ctrl+Enter = 화면 1차 그대로. E2E ⓒ와 payment-single 「예정일 저장」 Ctrl+Enter 사례, settlement-approval 「다시 올리기」 Ctrl+Enter 사례가 지킨다
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 모양 변화 0. 열린 `dialog[open]` 안 키는 모달 몫이라는 규칙이 `leave/[id]/document-actions.tsx`(`dialogOpen`으로 거름)와 같은 결과로 세 문서 화면에 통일된다
