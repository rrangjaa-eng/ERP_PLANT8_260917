## 지금 화면 기준으로 어긋난 것(고치기 전)
- (Task 1 · V5) 지급 대상에서 고른 계좌이체 건을 은행에 올릴 파일로 받는 길이 없다 — 경영관리가 계좌 · 금액을 손으로 옮겨 적는다(옛 CSV도 막힘 판정 · 기록 없음).
- (Task 2 · V5) 파일에 못 담는 건(현금 · 계좌 없음 · 은행 이름 오류 등)을 화면이 말하지 않고, 이미 받은 건인지 알 길이 없다(이중 이체 위험).
- (Task 3 · V14) `지급 완료` 확인 창에 같은 지급처로 가는 여러 건의 합이 보이지 않는다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: (Task 1) 더한 글자는 버튼 이름 `이체 파일 받기` · 비활성 이유 `고른 건 없음`(1차와 같은 글자 · info 톤) · 결과 글자 `{HH:mm} 이체 파일 {N}건`(기존 결과 글자 자리 · aria-live) · 실패 토스트 `이체 파일 받기 · 실패 · 다시 시도` — 설명문 0. (Task 2) 막힌 행 아래 한 줄은 UI-SPEC V5 이유 표 문구(원인 · 고칠 일 명사형 — 서버가 고른다) + 끝 3차 링크 하나, 담김 줄 `{HH:mm} 이체 파일에 담김` 한 줄 — 한 행 아래 줄은 하나(막힘 > 정보, 단위 시험). (Task 3) 결과 글자는 줄 수 ≠ 문서 수일 때만 `{K}줄 · 문서 {N}건`(같으면 `{N}건` 한 번) · 소계 칸 행 `{지급처} {합} · {n}건` 명사형 — 칸 제목 · 빈 문구 · 읽는 중 문구 · 실패 문구 0(E2E R-5: 대화상자 안 `실패|오류|소계` 글자 0).
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: (Task 1) 확인 창 없음 — 지금 고른 행(모든 쪽)과 표의 이체액 편집값을 그대로 보내고, 은행 코드 · 계좌 · 금액 글자 · 파일 이름은 서버가 만든다. (Task 2) 막힌 이유와 고치러 가는 길(링크 대상 · 권한별 평문 담당)은 서버가 판정한다 — 화면은 받은 글자 · 링크만 그린다. (Task 3) 지급처 묶음 · 합은 서버가 센다(화면이 더하지 않음) — 2건 이상 지급처만 행, 사용자가 고를 것 없음.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: (Task 1) 고정 게이트(지급 쓰기 ∧ 계좌 해제 ∧ 금액 보임)가 거짓이거나 1024 미만이면 버튼 · 이유 둘 다 DOM에 없다(page.tsx canExportBankTransferFile → prop). 고른 건 0이면 aria-disabled + 이유(E2E 「고른 건 0」). (Task 2) 거래처 관리 쓰기가 없으면 링크 대신 평문 담당 `· 거래처 수정은 경영관리`(통합 · E2E 0건 변형). 1023 · 768 · 375 폭 · 계좌 해제 없음 · 금액 숨김 계급은 버튼 DOM 0(E2E). (Task 3) 소계 읽기가 실패해도 1차는 막지 않는다 — `loading` 미사용(grep 0) · E2E R-5에서 aria-disabled 아님 · 지급 완료 끝남.
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 1차는 `지급 완료 N` 그대로, `이체 파일 받기`는 2차(variant="secondary"). (Task 3) 대화상자 1차 `지급 완료 {n}건` 하나 — 소계 칸은 버튼 0.
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 해당 없음 — 파일 받기는 되돌릴 수 있는 읽기 동작(UI-SPEC Destructive confirmation).
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 결과 글자는 일괄 지급 결과와 같은 한 자리(가장 마지막 동작만 — 파일 요청 때 지급 결과를, 지급 확인 때 파일 결과를 지운다). 고른 건 0 이유는 UI-SPEC V5 「비활성」 행대로 버튼마다 선다(같은 reasonId 공유는 선택 사항). (Task 2) 선택 칸 이유와 같은 글자면 막힘 줄을 다시 쓰지 않는 기존 규칙 유지. 막힘이 있으면 담김 줄은 서지 않는다. (Task 3) 소계 행은 결과 줄에 넣지 않는다(SYSTEM §7-17 결과 줄 0~3 — E2E 결과 줄 칸 p 1 · 소계 글자를 담은 p 0) · 한 건뿐인 지급처는 행 없음(부제 합계와 같은 수를 두 번 쓰지 않는다).
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음 — 빈 화면 변경 0(빈 목록에서도 필터 줄은 그대로).
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 2차는 필터 줄의 일반 button(Tab · Enter · Space), 비활성도 aria-disabled라 탭 순서에 남는다(§7-1 개정 ⑦). (Task 2) 막힌 줄 id · 담김 줄 id를 체크박스 aria-describedby가 가리킨다(단위). 끝 링크는 a 요소라 Tab으로 닿고 새 탭으로 열려 선택 · 편집이 남는다. (Task 3) 소계 칸 `tabindex=0` · `role=group` · 접근 이름 `지급처 소계`(단위 · E2E) — 넘치면 Tab으로 닿아 화살표로 칸 안 스크롤, :focus-visible 안쪽 링(--focus-w · --focus). 첫 포커스는 그대로 `지급일`(E2E toBeFocused).
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 파일 받기는 action-log `Excel 내보내기`와 같은 2차 버튼 · 같은 Blob 다운로드 · 같은 실패 토스트 꼴. (Task 2) 끝 링크는 SP-65-5 ① `buttonLinkClassName("tertiary")` — 다른 화면의 3차 이동 링크와 같은 모양(E2E: 14px · 600).
