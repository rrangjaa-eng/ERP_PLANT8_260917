## 지금 화면 기준으로 어긋난 것(고치기 전)
- 지출결의 목록 필터 줄에는 상태 select(와 팀 · 증빙 · 월 select)뿐이라 번호 · 지급처로 건을 찾으려면 쪽을 넘기며 눈으로 찾아야 한다(gap-verdicts G20). 검색 칸을 맨 앞에 더한다.
- 검색으로 0건이 되는 화면이 없다 — 0건이어도 필터 줄 · 검색어가 남고 빠져나갈 2차 버튼(`필터 지우기`)이 서야 한다(EP1-13).

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자는 라벨 `검색` 하나와 0건 한 줄 `조건에 맞는 건이 없습니다`(S1이 이미 쓰던 문구)뿐이다. 자리표시자 · 도움말 · 검색 대상 설명 없음(git diff 문자열 확인).
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 검색 대상 열은 사용자가 고르지 않는다(보기 × 정보 항목으로 서버가 정함). 제출은 Enter 하나, 검색어는 다른 select를 바꿔도 남는다(E2E 「상태를 바꿔도 q가 남고」).
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 문서가 하나도 없으면 검색 칸이 있는 필터 줄 전체를 숨긴다(`list.hasAny` 거짓 → `filters` 없음, 기존 `등록된 지출결의가 없습니다`). 검색 0건은 `hasAny`가 검색과 무관해 줄이 남는다.
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 머리 1차 `새 지출결의` 변경 0. 검색 칸에는 제출 버튼을 더하지 않았다(Enter).
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 해당 없음 — 위험 동작 변경 0.
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 라벨 `검색` 하나, 칸 안 글자(자리표시자) 없음. 검색어를 합계 줄에 되풀이하지 않는다(합계 줄 제목 그대로).
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 검색 0건 빈 자리는 한 줄 + 2차 `필터 지우기` 하나(`ListEmpty` action). E2E 「0건이면 필터 줄 · 검색어가 남고 … 필터 지우기가 q를 지운다」.
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 검색 칸 → `Tab` → 상태 select 순서(DOM 첫째), Enter로 제출, blur 제출 없음 — E2E 「Tab으로 상태로 가도 주소가 바뀌지 않고 … Enter」(DM-1) 통과.
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: `필터 지우기`는 다른 목록(프로젝트 · 거래처 · 작업 기록)의 0건 빈 화면과 같은 `ListEmpty` 2차 링크.

## Task 2 — 지급 대상 · 지급 완료 검색 · 발행 줄 이름 · 거래처 포커스 (같은 화면 기준으로 다시 확인)
