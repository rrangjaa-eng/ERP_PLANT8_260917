## 지금 화면 기준으로 어긋난 것(고치기 전)
- 상태 낱말 여섯(`미공개` · `팀 공개` · `본부 공개` · `붙음` · `확인 필요` · `카드 미등록`)이 `status-map.ts`에 없어 06.1 화면이 색을 즉석으로 정하게 된다 → SYSTEM §7-5 기록 뒤 표에 더한다(새 색 0).
- 폰 행 시트 `action` 자리는 3차 한 개뿐이라 줄 행동이 둘인 구매 요청 `신청됨` 행을 그릴 수 없다 → `.action`이 자식을 세로로 쌓는다(prop 불변).
- 첨부 영역은 이미지·PDF 올리기뿐이고 엑셀·CSV 결과 슬롯이 없다(Task 2) · 고르기 목록은 `noun` 셋 · 미리 고르기 · 다중 상한 · 단일 거부 자리가 없다(Task 3).
- 쇼케이스(`/dev/components`)에 06.1 표본(S3 패널 · S7 떼기 모달 · 두 3차 시트)이 없다 → 기존 컴포넌트 조합으로만 더한다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 쇼케이스 표본의 문구는 UI-SPEC Copywriting 글자 그대로 잠김 줄 `결재 중 문서에 붙음 · 금액 잠김` · 막힘 `사유 없음 · 사유 적기` · 영역 한 줄 `파일을 끌어 놓거나 Ctrl+U · 홈택스·카드사 엑셀·CSV 1MB`뿐이고 설명문·도움말을 더하지 않았다.
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 컴포넌트는 서버 DTO(숫자 · 조각 · 미리 고름)를 그리기만 하고 판정·계산이 없다(`preselect` · `kind` · 결과 줄은 호출 화면이 서버 값으로 넘긴다). 공급가는 한 칸만 입력하고 세액 · 합계는 읽기다.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 막힌 행 `aria-disabled` + 2행 이유 · 사유 빈 동안 1차 `aria-disabled` · 거절 행에는 2차 버튼 자체가 없다(DA-2) · 0인 조각은 DOM에 없다.
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 표본 패널 · 모달 · 고르기 목록 모두 1차 하나(`증빙 금액 저장` · `증빙 떼기` · `이 문서에 붙이기` · `증빙 붙이기 N`)이고 나머지는 2차 `취소 Esc` · 3차 링크다.
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 떼기는 확인 모달 안에서만(사유 필수) 서고, 시트의 두 3차는 줄 행동이 둘인 행에만 서고 위 = 문서를 바꾸지 않는 행동이다(SP-6107, 순서는 호출 화면이 정한다). 위험 색은 `--status-danger` 한 표(조각 `카드 미등록`)뿐이다.
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 거부 줄은 바닥 줄 하나(거부 > 상한 > 결과 줄 우선순위)이고 `새로 고침`은 글자가 아니라 3차 버튼이다. 조각 숫자는 링크 글자와 한 요소다.
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 목록 글자는 기존 `pickEmptyText`(noun만 늘림) 그대로이고 다음 한 수 3차를 쓴다. 새 빈 화면을 만들지 않았다.
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 고르기 목록의 검색 칸 첫 포커스 · `↓` 로빙 · `Enter` · `Esc`는 기존 그대로(E2E `dev-components.spec.ts` 고르기 절이 지킨다). 일괄 등록 변형은 `Ctrl+U` + `파일 고르기` 버튼을 병기한다.
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 시트의 두 3차는 같은 `Button variant="tertiary"`이고 결과 슬롯 링크 조각은 3차 링크 색 하나다.
