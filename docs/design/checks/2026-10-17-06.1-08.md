## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자는 트리거 `증빙 고르기 {N}` · 제목 `증빙 고르기` · 검색 이름 `거래처 · 금액` · 1차 `증빙 붙이기` · 결과 줄 `고른 {n}건`뿐이고 설명문 · 도움말 0. 거부 줄(`20건 상한 · 나눠 붙이기` · `다른 사람이 먼저 붙임 · {거래처} 외 {k}건 · 새로 고침` · `다른 사람이 {HH:mm}에 바꿈 · 새로 고침` · `붙이지 못함 · 다시 시도`)은 서버가 거절한 글자 그대로이거나 06.1-06이 이미 쓴 글자다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 순위 · 고를 수 있음 · 이유 · 상한은 서버(SQL 순위 · 05 규칙표 권리 · 짝)가 정하고 1위가 고를 수 있으면 `preselect`로 미리 골라 둔다 — 사람은 Enter 한 번. 붙이기 입력에 금액 · version 칸 없음(D-6520). 경영관리가 결재 중 문서에서 열면 미리 고름을 비운다(DB-5)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 트리거는 서버가 모드 ≠ none ∧ 후보 ≥ 1일 때만 값을 준다(아니면 DOM 0 · E2E가 붙인 뒤 `toHaveCount(0)`로 잰다). 짝 아닌 행은 `selectable` 거짓 + 이유(PickDialog 기본). 상한에 닿으면 고르지 않은 행 토글이 무반응이고 바닥 줄에 막힘 이유
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 모달 1차 `증빙 붙이기 {n}`(PickDialog 기본 kbd Enter) 하나. 트리거는 3차(밑줄 텍스트)라 문서 화면 1차(제출)를 건드리지 않는다
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이 플랜의 화면에는 삭제 · 떼기 새 동작이 없다(Task 3의 자기 떼기는 06.1-06 `RowAction danger` 그대로)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 부제는 `{문서 번호} · 후보 {n}` 하나이고 트리거 숫자와 같은 값을 다시 설명하지 않는다. 결과 줄은 고른 수만(금액을 다시 적지 않는다)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 붙은 증빙이 0건이어도 후보가 있으면 섹션에 트리거만 서고(빈 표 · 빈 문구 없음), 둘 다 없으면 섹션 자체를 그리지 않는다. 검색 0건은 PickDialog 기본 빈 줄
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 트리거 Enter → 검색 칸 포커스 → 방향키/Space → Enter(PickDialog 기본). E2E `evidence-pick.spec.ts`가 검색 칸 포커스 · `aria-multiselectable` · `aria-selected` · Enter 붙임을 잰다. 붙인 뒤 포커스는 트리거(남아 있으면) 아니면 새 읽기 행의 첫 행동
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 트리거는 공용 `Button variant="tertiary"`, 고르기는 06.1-06 S4와 같은 PickDialog. 읽기 행은 06.1-06 StaticTable 그대로
