# 06.1-09 DOM 감사 D1 — S2 막힌 이유 글자 크기 — 점검표
화면: app/(app)/expenses/evidence/evidence-table.tsx
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §7-3(행 행동 · 막힌 행동의 이유 글자) · UI-SPEC Copywriting(「`--text-aux` 글자, 버튼 아님」)

## 지금 화면 기준으로 어긋난 것(고치기 전)
- S2 전부 막힌 카드 줄의 행 행동 자리 이유 `<span>`에 클래스가 없어 표 본문 14px을 물려받는다 — 같은 행의 RowAction(13px)과 크기가 다르다(06.1-09-DOM-AUDIT.md D1 · 1280 · 1024 실측).
- 고칠 계획: 기존 표 이유 글자 클래스 `ui/table/Table.module.css` `.selectReason`(`--text-aux` · `--text-muted`)을 붙인다. 새 클래스 · 색 · 크기 0. RowActions 줄은 `align-items: baseline`이라 `.selectReason`의 위 여백(`--s-1`)은 글자 기준선을 옮기지 않는다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 이 고침은 글자를 더하지 않는다. 이유 글자(`증빙 있음 · K번호` 등)는 막힌 까닭 한 줄 그대로(잠김 예외).
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 입력 · 선택지 변화 없음(글자 크기 · 색만).
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 막힌 줄은 `붙이기` · `대리 등록` DOM 0 그대로(감사 스펙 「전부 막힘 줄 — 붙이기 · 대리 등록 DOM 0」).
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 화면 머리 1차 버튼 변화 없음.
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 보관(danger RowAction) 자리 · 색 그대로.
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 이유 글자 한 번(감사 스펙 「이유 글자 하나」).
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 변화 없음.
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 이유 글자는 탭 정지가 아니다(버튼 · 링크 아님 — 감사 스펙 inButton=false) · 로빙 그대로.
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 행동이 아닌 이유 글자를 표의 다른 이유 글자(`.selectReason`)와 같은 모양으로 맞췄다.

## 시스템
- [x] 새 색·서체·radius·그림자를 만들지 않았다(tokens.css 변수만) — 근거: 기존 `tableStyles.selectReason` 재사용 — CSS 파일 변경 0.
- [x] 폰 320에서 가로 넘침 없음 · 터치 44px — 근거: 1024 미만은 행 행동 열이 없다(06.1-05 설계 · 감사 스펙 「1024 미만 — 행 행동 열 없음」) — 이 글자는 폰에 그려지지 않는다. 13px로 줄어 PC 폭도 넓어지지 않는다.
- [x] 실제 앱 화면(PC 1280 · 폰 390)을 찍어 보고 확인했다 — 스크린샷 경로: 판정은 DOM 실측 — `CI=true` 감사 스펙 `test/e2e/evidence-reconcile-audit.spec.ts` 「S2 이유 글자 크기 = --text-aux 13px」 1280 · 1024 통과(이 커밋의 검증 실행). 스크린샷 육안 판정은 하지 않는다(CLAUDE.md §6).
