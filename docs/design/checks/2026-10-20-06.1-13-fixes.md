## 지금 화면 기준으로 어긋난 것(고치기 전)
- D1: 붙여넣기로 바뀐 공개 칸에 모르는 값을 다시 붙이면 오류 셀이 앞 편집 글자를 보이고 1차 `공개 범위 저장 N`이 dirty 칸 수보다 크다(감사 두드림 N 3 · dirty 2).
- D2: 쇼케이스 `SelectPasteSample` 공개 열이 P1이라 폰에서 실제 증빙 표(P2)와 모양이 다르다.
- P3-1: 표 아래로 넘친 붙여넣기 줄이 요약 없이 사라진다(§7-3 「조용히 버리지 않는다」).
- P3-2: 같은 라벨이 둘이면 조용히 첫 것을 고른다(공유 select 붙여넣기는 오류 셀).
- P3-5: 결과 0건에도 `파일 받기`가 살아 있어 머리줄뿐인 파일을 준다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자는 합계 행 조각 `아래 n줄 버림`(기존 `오른쪽 n칸 버림` 조각과 같은 꼴 · warning · piece)과 오류 셀 이유 `같은 이름 여럿 · 목록에서 고르기`(공유 `applyPaste`의 기존 글자)뿐. `파일 받기` 비활성 이유는 새 글자를 쓰지 않고 이미 보이는 빈 줄 「조건에 맞는 증빙이 없습니다」를 `aria-describedby`로 가리킨다.
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 오류가 된 칸은 앞 편집을 지워 기준 값으로 돌아간다(사람이 지울 일 없음 · E2E D1 회귀). 같은 이름 여럿은 시스템이 짐작하지 않고 select로 고르게 한다.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 결과 0건이면 `파일 받기` aria-disabled(네이티브 disabled 아님 — `Button` DR-11 계약), 클릭 · Enter 모두 서버 0 · 내려받기 0(E2E P3-5).
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 1차 `공개 범위 저장 {N}` 그대로, N이 dirty 칸 수와 같아졌다(E2E D1 회귀 N 1 = dirty 1).
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험 동작 변화 없음.
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 비활성 이유를 버튼 옆에 다시 쓰지 않고 빈 줄을 가리킨다. 오류 셀은 앞 편집 글자 + 이유를 함께 보이던 것을 기준 값 + 이유로.
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 줄의 첫 행동(`필터 지우기` 등) 그대로 · `파일 받기`는 비활성이라 그 행동과 겨루지 않는다.
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 붙여넣기 · Ctrl+S 경로 그대로. 비활성 `파일 받기`는 탭 순서에 남고 Enter가 아무 일도 하지 않는다(E2E).
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: `Button variant="secondary"` 그대로 · 비활성 꼴은 공유 Button의 aria-disabled 꼴.
