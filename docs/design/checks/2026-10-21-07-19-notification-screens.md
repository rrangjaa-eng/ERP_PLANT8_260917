## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 화면에 설명문 0(제목 `알림 규칙` · 표 머리글 `규칙 · 일수 · 켬 · 받는 사람 · 이메일`뿐), 글자는 오류 줄 `켬 저장 실패 · 다시 시도` 한 줄만 — rules-client.tsx · 1280/375 촬영본
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 종류 이름 · 순서 · 단위(`7일`/`3영업일`) · 기본 받는 사람은 모두 등록부(CONDITION_KINDS)에서 읽고 관리자가 고르는 것은 켬/끔뿐(Task 1) — 일수 · 받는 계급 · 이메일은 패널에서 바꿀 때만(Task 2)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 쓰기 권한이 없으면 체크박스 대신 글자 `켬`/`끔`(canWrite 분기, rules-client.tsx), 지급 완료·취소 규칙 행은 만들지 않음(D-744 — 결재 결과 하나가 맡음, E2E 「지급 완료/취소 행 없음」)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 이 화면은 체크박스 즉시 저장이라 1차 버튼이 없고(SC-05 1차는 패널의 `규칙 저장` 하나 — Task 2) 화면 머리에 버튼을 더하지 않음
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 삭제 동작 없음 · 오류 줄만 `--status-danger`(notification-rules.module.css `.alert`)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 체크박스 이름은 `aria-label="{규칙} 켬"`이고 보이는 글자는 머리글 `켬` 하나, 꺼 둔 상태는 색(muted)과 체크 해제 — 「꺼짐」 글자 없음
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음(등록부 종류가 항상 있어 표가 비지 않음, SC-05 EMPTY 해당 없음)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 체크박스는 네이티브 Space, 오류 줄 `다시 시도`는 Enter(E2E 「켬 저장이 끊기면 … 다시 시도」가 Enter로 눌러 통과)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 켬은 체크박스 하나, 재시도는 3차 `Button variant="tertiary"`(다른 화면 오류 줄 재시도와 같은 부품)
