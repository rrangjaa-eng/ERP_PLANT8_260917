## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 화면에 설명문 0(제목 `알림 규칙` · 표 머리글 `규칙 · 일수 · 켬 · 받는 사람 · 이메일`뿐), 글자는 오류 줄 `켬 저장 실패 · 다시 시도` 한 줄과 패널의 읽기 줄 `기본 받는 사람 · {글자}` · 범위 aux `{min}~{max}`뿐(문장 없음) — rules-client.tsx · 1280/375 촬영본 · 패널 촬영본
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 종류 이름 · 순서 · 단위(`7일`/`3영업일`) · 기본 받는 사람은 모두 등록부(CONDITION_KINDS)에서 읽고 관리자가 고르는 것은 켬/끔뿐— 일수 · 받는 계급 · 이메일은 패널에서 바꿀 때만이고 패널 일수 칸은 기존 값 · 단위 · 범위(종류 daysRange)로 채워 열린다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 쓰기 권한이 없으면 체크박스 대신 글자 `켬`/`끔`(canWrite 분기, rules-client.tsx), 지급 완료·취소 규칙 행은 만들지 않음(D-744 — 결재 결과 하나가 맡음, E2E 「지급 완료/취소 행 없음」)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 표는 체크박스 즉시 저장이라 1차 버튼이 없고 패널의 1차는 `규칙 저장` 하나(2차 `취소 Esc`), 화면 머리에 버튼을 더하지 않음 — panel-1280.png
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 삭제 동작 없음 · 오류 줄만 `--status-danger`(notification-rules.module.css `.alert`)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 체크박스 이름은 `aria-label="{규칙} 켬"`이고 보이는 글자는 머리글 `켬` 하나, 꺼 둔 상태는 색(muted)과 체크 해제 — 「꺼짐」 글자 없음
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음(등록부 종류가 항상 있어 표가 비지 않음, SC-05 EMPTY 해당 없음)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 체크박스는 네이티브 Space, 오류 줄 `다시 시도`는 Enter(E2E 「켬 저장이 끊기면 … 다시 시도」가 Enter로 눌러 통과)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 켬은 체크박스 하나, 한 건 수정은 행동 링크 `수정`(RowAction), 재시도는 3차 `Button variant="tertiary"`(다른 화면과 같은 부품)

## 알림함 SC-06 (Task 3 — 문장 링크 · 같은 종류 5건 이상 접힘 · loading 머리글)
- [x] 안내 문구를 더하지 않았다 — 근거: 화면에 새로 생긴 글자는 접힘 줄 `{종류} · N건`(사실 한 줄)과 3차 버튼 `펼치기`/`접기`뿐이고 설명문 0 — inbox-list.tsx · 1280/375 촬영본
- [x] 결정 최소: 사용자가 정할 것이 없다 — 근거: 링크 여부는 서버가 그 viewer가 볼 수 있는 문서인지로 정하고(href 없으면 글자 — 이유 문구 없음), 접힘은 규칙(같은 날 · 같은 종류 · 5건 이상)이 정해 사용자 설정이 없다
- [x] 할 수 없는 선택지는 숨겼다 — 근거: 볼 수 없는 문서의 알림은 링크 모양을 만들지 않고 글자로 남는다(E2E 「볼 수 없는 문서는 글자」), 등록부 밖 확인증 알림은 접힘 대상이 아니라 펼치기 버튼이 없다
- [x] 같은 말을 두 번 하지 않는다 — 근거: 접힘 줄 제목 `결재 차례 · 6건` 한 번이고 버튼 이름은 `펼치기`/`접기`(종류는 `aria-describedby`로 읽힌다 — E2E accessible description)
- [x] 키보드만으로 끝난다 — 근거: 문장 링크는 Tab/Enter, 펼치기/접기는 네이티브 button의 Space/Enter이고 누른 뒤 포커스가 그 버튼에 남는다(E2E 「Space」 · `toBeFocused`)
- [x] 같은 종류의 행동은 같은 모양이다 — 근거: 이동은 문장 링크(글자색 `--text-strong`, 밑줄은 hover · focus만), 행 안 조작은 3차 `Button`(다른 화면과 같은 부품) — 링크와 버튼을 섞지 않음
- [x] 상태는 색 · 배지로 보인다(안 읽음 선) — 근거: 묶음의 안 읽은 건이 0이면 선 없음 · 1 이상이면 선(E2E 「모두 읽은 묶음은 왼쪽 선이 없다」), 펼친 행도 읽음 규칙(S1-d) 그대로
- [x] 새 색 · 서체 · radius · 그림자를 만들지 않았다 — 근거: inbox-list.module.css는 `--text-strong` `--focus` `--focus-w` `--focus-offset` `--line-w` `--underline-offset` `--touch-min` `--s-2` `--s-4`만(stylelint 통과 · var() 외 값 없음)
- [x] 사용자 결정(§1)을 어기지 않았다 — 근거: 표 면 · 머리글 · 날짜 그룹 줄은 공용 `ui/table` 그대로(`headerClassName` 한 칸만 더함), 모달 · 팝업 없음, 접힘은 펼침 상태를 날짜+종류 키로 들어 `더 보기`에도 유지
- [x] 폰 320 · 375에서 가로 넘침 없음 · 터치 44px — 근거: CI=true 프로덕션 빌드 실측(임시 zz 스펙, 커밋 안 함) 1280 · 768 · 375 · 320 모두 `scrollWidth == innerWidth`, 375 · 320에서 링크 상자 높이 44 · 펼치기 버튼 44×44(1280 · 768은 링크 16 · 버튼 24×22), 링크 있는 행은 행 전체(시각 칸 포함)가 누름 자리(E2E mobile-375 「행 전체가 링크」)
- [x] 실제 앱 화면(PC 1280 · 폰 375 · 320)을 찍어 보고 확인했다 — 스크린샷 경로: 세션 scratchpad `shots/inbox-1280-folded.png` `inbox-1280-open.png` `inbox-768-open.png` `inbox-375-folded.png` `inbox-375-open.png` `inbox-320-folded.png` `inbox-320-open.png` (CI=true 빌드 · 저장소 밖 · 커밋 안 함) — 링크 행과 시각이 한 줄 가운데로 맞는지(폰), 펼친 행 들여쓰기와 시각 칸 정렬(PC)을 보았다
