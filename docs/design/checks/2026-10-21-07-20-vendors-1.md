# 07-20 거래처 관리 화면(SC-16 목록 · SC-17 패널) — 점검표
화면: app/(app)/admin/vendors/
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §7-2 · §7-8 · §7-15 · 07-UI-SPEC SC-16 · SC-17 · 공통 계약 1~10

## 지금 화면 기준(실행 첫 확인, 2026-10-23)
- SC-16: 필터 줄 = 갈래 nav(aria-label `구분`) · `숨김 포함` 토글만 — 검색칸 · `파일 받기` 없음. 열 머리글 `구분`. 걸러보기 EMPTY `조건에 맞는 건이 없습니다`.
- SC-17: 필드 순서 이름 → 구분(네이티브 select) → 사업자 번호 → 기본 증빙 종류(네이티브 select, `선택 없음`) → 계좌 은행 · 예금주 · 계좌번호 → 사용자 정의 칸(select면 네이티브). 지급 기한 칸 없음 · version 비교 없음(나중 저장이 덮어씀) · 수정 1차 `거래처 수정` · 계좌 칸은 권한 판정 없음 · 계좌번호 자릿수 판정 없음 · 사업자 번호 오류는 제출 뒤에만.
- 행동 줄: PanelForm이 이미 하단 고정(.fields만 스크롤, `--surface-actions`) — 고칠 일 없음(ui/side-panel 안 고침).

## 사용성 두 질문
- SC-16 문구 없이 이해되나: 검색칸 하나(라벨 `검색` · 칸 안 글자 `거래처 이름·사업자 번호` — 라벨을 `거래처 이름·…`로 두면 패널 `이름` 칸과 접근 이름이 겹쳐 `검색`으로 바꿨다, 지출결의 검색칸과 같은 라벨) · 낱말 `갈래` 하나 · `파일 받기` 2차 하나. 남은 결정: 없음(정렬 · 쪽 나눔 현행, 파일 열은 고정).
- SC-17 문구 없이 이해되나: 라벨 · 단위 `일` · aux `1~180` · 한 줄 오류뿐. 남은 결정: 없음 — 갈래 기본 `협력사`(D-745), 지급 기한 빈 칸 = 회사 기본(placeholder가 그 값), 클라이언트로 바꾸면 칸이 사라지고 값은 시스템이 비운다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자는 오류 줄(`이미 등록됨 · {이름}` · `사업자 번호 확인 · 다시 입력` · `숫자 10~16자리 · 다시 입력` · `지급 기한 1~180 · 다시 입력` · `파일 받기 실패 · 다시 시도` · `5,000곳 넘음 · 갈래나 검색으로 줄이기`)과 FormAlert `다른 사람이 먼저 수정 · 새로 불러오기`뿐, 지급 기한은 단위 `일` · aux `1~180`만(설명 문장 없음 — vendor-form.tsx).
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 갈래 기본 `협력사`(D-745, E2E 「갈래 기본값」), 지급 기한 빈 칸 = 회사 기본(placeholder = 설정 `payment.term_days`), 클라이언트로 바꾸면 칸이 사라지고 값은 서버가 NULL로(resolvePaymentTermDays), 계좌번호 `-`·공백은 blur에서 시스템이 지운다.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: `vendors.account` 쓰기 권한 없으면 계좌 칸 대신 읽기 KvList(E2E R8), 클라이언트 갈래면 지급 기한 칸 없음, 폰 · 태블릿 세로에서 `파일 받기` 없음(K12, mobile-vendors E2E), 5,000곳 넘으면 `파일 받기` disabled + 이유 한 줄.
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 목록 1차 `거래처 등록` 하나(머리), `파일 받기`는 2차(E2E `toHaveClass(/secondary/)`), 패널 1차 `거래처 저장` · `거래처 등록` 하나(PanelForm 하단 고정), FormAlert의 `새로 불러오기` · 오류 줄의 `열기` · `갈래 더하기`는 3차.
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 숨기기 · 보관은 이번에 안 건드렸다(기존 행 행동 · `계좌번호 지우기` 체크박스 그대로), 새 행동에 파괴 동작 없음.
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 검색칸 라벨 `검색` · 칸 안 글자 `거래처 이름·사업자 번호`(다른 말), 지급 기한 placeholder는 숫자(회사 기본값)만 · 단위는 칸 밖 `일` 한 번, 열 머리글 · nav · 패널 라벨이 모두 `갈래`(`구분` 낱말 0 — E2E).
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 거래처 0곳 = 기존 EMPTY + `거래처 등록`, 검색 · 갈래 결과 0 = `조건에 맞는 거래처가 없습니다` + 3차 `필터 지우기`(ListEmpty, E2E 「검색 0건」).
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 검색은 GET form Enter 제출(E2E `press("Enter")`), FormAlert 뒤 포커스가 알림으로(E2E U12 `toBeFocused`), 오류 줄의 `열기` · `갈래 더하기`는 Tab 순서 안 링크 · 버튼, `/` 단축키는 만들지 않음(UI-SPEC 07.1).
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 이동(`열기` ?editId= · `지우기` · `필터 지우기` · 갈래 nav)은 링크, 그 자리 실행(`파일 받기` · `새로 불러오기` · `갈래 더하기`)은 Button — 증빙 `파일 받기`와 같은 secondary.

## 감사 수정(DOM 감사 P2 · 2026-10-23)
- [x] 단위 `일`이 입력 칸 세로 중심에 선다 — 근거: Form.module.css `.panel [data-ui="field-row"] { display: block }`(클래스 + 속성)이 `.withUnit > :first-child`(클래스 + 의사 클래스, 같은 특이도)를 뒤에서 이겨 줄이 `contents`가 아니었다. vendors.module.css 선택자에 `[data-ui="field-row"]`를 더해 한 단계 높였다(공유 TextField 불변, 새 색·서체·radius 0). E2E 「단위 일 … ±4px」 375 · 1280.
- [x] 새로 불러오기 뒤 포커스가 body로 떨어지지 않는다 — 근거: 폼 key(id + version)가 바뀌어 재마운트되며 눌렀던 단추가 사라진다. 새 폼이 서면 이름 칸(`#name`)으로 포커스를 옮긴다(안내 문구 추가 0). E2E 동시 수정 흐름 `#name` toBeFocused.
