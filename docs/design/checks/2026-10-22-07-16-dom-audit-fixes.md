## 시작 상태(코드 전 — 감사 실측)
- #1 P1 상세 `지급 예정일`(수동 지정): 375 · 320에서 `.valueRow > .fill` 0px — 날짜 10줄, 규칙 줄 6줄, 3차 둘이 235px(375) · 180px(320) 차지.
- #2 P2 같은 자리(자동 · 밀림) 320: `.fill` 55px, 날짜 2줄, 규칙 줄 6줄.
- #3 P1 폰 결재 중 행 제목 3~7줄 — 말줄임이 `.titleCell .link`에만 걸려 링크 없는 span에 닿지 않음.
- #4 P2 결재 중 하위 그룹이 그 주 그룹이 두 쪽에 걸치면 쪽마다 되풀이(쪽마다 findLastIndex).
- #5 P2 행 `이번 주로` 뒤 버튼이 사라지며 포커스가 BODY로 — 결과 줄은 뷰포트 밖, `되돌리기`까지 Tab 16번.
- #6 P3 폰 결재 중 행 접힌 줄 `— · —`(정보 없음).
- #7 P3 폼 희망 지급일 `min` 없음 — 과거 날짜를 고른 뒤 저장해야 오류.
- #8 P3 상세 KvList `희망 지급일` MM-DD, 바로 아래 `지급 예정일` ISO — 표 밖 날짜는 ISO(SYSTEM §2-4).
- #9 P3 사유만 보낸 저장의 `희망 지급일 없음 · 날짜 선택`이 사유 칸으로 — 날짜가 비면 사유 칸이 없어 보이지 않음.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 문구 없음. #9는 기존 문구(`희망 지급일 없음 · 날짜 선택`)를 받는 칸만 날짜 칸으로 옮김
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: #7 희망 지급일 칸 `min=오늘(KST)`(서버 seoulToday)로 과거 날짜를 고를 수 없게 — 저장 뒤 오류 대신 입력 칸이 형식을 잡는다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: #7 과거 날짜 비활성(date 입력 min), #6 정보 없는 접힌 줄을 그리지 않음(summary null → ui/table이 접힌 줄을 세우지 않음)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 1차 버튼 변경 없음 — 상세 3차 둘은 폰에서 값 아래 줄로 내려갈 뿐 variant tertiary 그대로(E2E payment-schedule `편집 중 1차 하나` 유지)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 새 위험 동작 없음
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: #4 결재 중 하위 그룹을 그 주 그룹이 끝나는 쪽 하나에만(서버 approvingByWeek[].page), #6 빈 접힌 줄 제거 — 상태 · 금액은 이미 주 행 p1 칸
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 갈래 변경 없음(결재 중만 있으면 1쪽 머리글 하위 그룹 그대로 — 그 주 지급 대상이 없으면 page 1)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: #5 행 · 일괄 `이번 주로`가 옮기면 포커스를 결과 줄 `되돌리기`로(상세 `자동으로 되돌리기`와 같은 꼴) — Enter 한 번으로 되돌린다(E2E payment-move-this-week toBeFocused)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 버튼 종류 · 모양 변경 없음
