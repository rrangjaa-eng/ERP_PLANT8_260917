# 07-17 DOM 감사 P2 — 결과 단계 값 라벨 `임시 비밀번호` — 점검표
화면: ui/confirm-dialog/, app/(app)/admin/people/[id]/
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §7-17(개정 7 결과 단계) · §7-8 라벨·값(KvList dt) · UI-SPEC SC-12 카피 목록

지금 화면(고치기 전): 결과 단계 값은 `<p tabindex=0>` 하나 — role · 접근 이름 없음. 첫 포커스가 이름 없는 요소에 떨어져 화면 리더는 무슨 값인지 모른다. 창 어디에도 `임시 비밀번호` 글자가 없다(SC-12 카피 목록 누락, 감사 #1 P2 4폭). 결과 단계(`result` prop)는 사람 상세 비밀번호 초기화 한 곳만 쓴다.

고칠 계획: `result`에 `label`(필수)을 더한다. 값 줄 위에 라벨 한 줄(KvList dt와 같은 aux · medium · muted 토큰), 값은 `role="textbox"` · `aria-readonly="true"` · `aria-labelledby` → 라벨. 호출자는 `label: "임시 비밀번호"`. `result`가 없는 다른 확인 창 마크업은 그대로.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 더한 글자는 값의 라벨 `임시 비밀번호`(명사, SC-12 카피 목록 그대로) 하나뿐 — 설명문 0. aux `닫으면 다시 볼 수 없음` · 실패 줄은 그대로
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 값은 그대로 선택된 채 열리고 첫 포커스도 같은 값 요소(E2E U1 toBeFocused · getSelection = 값). 사용자에게 새로 묻는 것 없음
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 행동 변화 없음 — 결과 단계는 여전히 `복사` · `닫기`만(단위 「result가 있으면 … 1차 닫기만」 녹색)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 1차 `닫기` 하나 그대로, 라벨은 버튼이 아닌 글자
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험 동작 없음(바꾸지 않음) — 확인 단계 1차 `비밀번호 초기화` 그대로
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: `임시 비밀번호`는 창 안에 라벨 한 번뿐(제목은 `비밀번호 초기화`), 값의 접근 이름은 aria-labelledby로 같은 글자를 가리킨다(aria-label로 다시 쓰지 않음)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음 — 빈 화면 없는 일회성 값 단계
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: Tab 순서 값 → `복사` → `닫기` 그대로(라벨은 포커스 받지 않는 글자), 첫 포커스 = 이름 있는 값(E2E getByRole textbox name `임시 비밀번호` toBeFocused 녹색)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 행동 모양 변화 없음. 라벨 모양은 KvList 라벨(dt)과 같은 aux · medium · muted
