# F24 퇴직자 정보 변경 잠금 — 점검표
화면: app/(app)/admin/people/[id]/, ui/history-list/
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §7-15(Form.Hint) · §7 개정 10(잠김 한 줄 · 컨트롤 렌더 안 함) · §8 카피

지금 화면(변경 전): 퇴직자 상세에도 계급 변경 select · 입사일 칸 · 연차 조정 폼 · `계좌 바꾸기` · `새 이력 추가`가 그대로 보였다 — 서버가 받는 일과 화면이 어긋났다(F24 이전엔 서버도 받았다).

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 더한 글자는 잠김 한 줄 `퇴직한 사람 · 정보 변경 없음`(Form.Hint, 명사형) 하나뿐이고 퇴직자 상세에만 나온다(E2E person-payout-account 「퇴직자 상세」가 toHaveCount(1)로 잰다).
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 새 입력 칸 없음. 퇴직 판정은 서버 isRetiredOn(퇴직일 다음 날부터)과 같은 함수로 화면이 계산한다.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 퇴직자에게 계급 변경 · 입사일 칸 · 연차 조정 폼 · `계좌 바꾸기` · 패널 주소(`?editAccount=1`) · `새 이력 추가`를 렌더하지 않는다(SYSTEM 개정 10과 같은 「렌더 안 함 + 한 줄」). E2E가 각 요소 count 0을 잰다. 독립 DOM 감사 P1 뒤: ui/history-list가 예정 줄 `취소`도 canAdd에 묶어 쓸 수 없는 목록에서는 그리지 않고, 사람 상세는 `canAdd={canWrite && editable}`(보기만 계정도 숨김, 감사 P3). E2E person-history-lock이 퇴직자 · 보기만 둘 다 `취소` · `새 이력 추가` 0개를 잰다. 설정 화면 caller는 canAdd를 넘기지 않아(기본 참) 그대로다.
- [x] 퇴직한 해 연차 조정(카드 2026-10-23 11:14 KST): 퇴직자는 퇴직일이 든 해를 볼 때만 연차 조정 폼이 있고 잔고 고르기에 `월차`가 없다(이유 줄 없이 뺌 — 고를 수 없는 선택지 숨김). 다른 해에는 폼 없음, 잠김 한 줄은 그대로 — 근거: E2E admin-person-leave 「지난해 퇴직」이 퇴직 연도 폼 · 월차 없음 · 조정 추가 · 올해 보기에서 폼 0을 잰다. 서버 assertLeaveAdjustableInTx가 같은 판정.
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 퇴직자 상세는 퇴직한 해를 볼 때만 1차 `연차 조정 추가` 하나, 다른 해에는 1차가 없다. 재직자 화면은 바뀌지 않았다.
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험 동작을 더하거나 옮기지 않았다.
- [x] 실패는 말한다: 예정 줄 `취소`가 서버에 거부되면 표 아래 오류 한 줄(기존 `addError` 꼴 · `--status-danger` · role=alert) — 근거: 이전엔 잡히지 않은 거부로 화면 변화 0(감사 P1). E2E 「낡은 화면」이 alert 글자 · 줄 남음 · pageerror 0을 잰다. 새 CSS 없음.
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 잠김 줄은 위 단일 기둥에 한 번만, 섹션마다 되풀이하지 않는다. 로그인 섹션의 `퇴직` 낱말은 상태값이고 잠김 줄은 이유라 겹치지 않는다.
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 발령 이력이 비면 ListEmpty가 canAdd=false라 버튼 없이 한 줄(기존 상한 밖 대상과 같은 모양).
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 새 컨트롤 없음 — 남은 퇴직일 칸 · 번호 보기 버튼은 기존 그대로.
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 새 행동 없음.

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 옆 패널(지급 계좌 수정)은 그대로, 퇴직자에게만 열리지 않는다. 색 · 크기 결정에 손대지 않았다.
