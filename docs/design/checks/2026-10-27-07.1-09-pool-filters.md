| # | 건 | 지금 화면(어긋남) | 고칠 계획 |
|---|---|---|---|
| 1 | W10 C-92 추천 | 증빙 고르기 추천이 문서 증빙 종류와 다른 증빙(카드 영수증 등)을 점수로만 뒤로 보내 같은 목록에 섞인다 — 세금계산서 문서에 카드 영수증을 잘못 붙일 수 있다 | 검색어가 없을 때 서버 WHERE로 같은 종류만(후보 집합). 검색어가 있으면 다른 종류도 나오고 그 줄 제목 앞에 `{종류} · ` |
| 2 | W10 부제 | `{번호} · 후보 {N}` — 종류 낱말이 없고 N이 모든 종류 수라 목록과 어긋난다 | (#320 B-1) 부제 `{번호} · {증빙 종류}` — `후보 N` 없음. 트리거 `증빙 고르기 {N}`의 N = 추천 수(같은 종류, 0이면 숫자 없이 `증빙 고르기`). 문서 종류가 비면 종류 낱말 없이 N = 모든 종류 수 |
| 3 | W10 빈 목록 | 추천 0이면 일반 빈 목록 문구 | 기존 슬롯 `emptyDefault`: `{종류} 증빙이 없습니다` + 기존 3차 `검색으로 찾기`. 트리거는 다른 종류 후보가 있으면 남는다(새 버튼 0) |
| 4 | W11 필터 줄 | 메인 목록 필터가 검색 · 상태뿐 — 팀장이 자기 팀 · 이번 달 건을 바로 거르지 못한다 | 상태 뒤에 `팀`(범위 안 팀이 둘 이상일 때만) · `월` select와 네이티브 `내 것만` 체크박스(기존 `.select` · `.selectLabel`, 내 것만은 활동 기록 필터와 같은 `.checkboxLabel` 선언 — #320 B-2). 0건이면 `조건에 맞는 건이 없습니다 · 필터 지우기`가 셋을 모두 지운다 |

- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 버튼 구성 변화 0(목록 머리 1차 `새 지출결의` · 고르기 1차 `증빙 붙이기` 그대로), `검색으로 찾기`는 기존 3차
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험 동작 추가 0 — 해당 없음
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 다른 종류 줄은 종류를 제목 앞에만 붙이고 부제에서는 뺀다(`카드 전표 · 거래처` / `기획1팀 공개`), 같은 종류 줄은 부제에 종류 그대로. 트리거 N(모든 종류)과 부제 N(추천)이 다른 수라는 점은 `/design-review` 판정 사항으로 남김
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 필터 0건은 `필터 지우기` 하나, 추천 0은 `검색으로 찾기` 하나(E2E P7 · 목록 W11)
