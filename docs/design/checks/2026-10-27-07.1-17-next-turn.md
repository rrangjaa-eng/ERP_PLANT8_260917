### /design-review 항목 (사용자 결정 또는 디자인 검토 몫)
- #321 화면 게이트 지적(폰 그리드 2행 4번째 칸이 비어 이유 칸이 좁다)을 `ui/next-turn/NextTurn.module.css` 폰 `.why`의 `grid-column: 3` → `3 / -1` 한 줄로 고쳤다(새 클래스 · 토큰 0). 위 표는 고친 뒤 값이다. 고친 뒤 375는 Phase 6 줄 전부 이유가 안 잘리고, 320에서는 지급(오늘) `예정일 지남·오늘 · 확인 전 12건` + 금액 9자리(`123,456,789`) 한 줄만 잘린다(title = 전체 이유). 처음에 낸 「25px 모자람」은 하네스가 대체 서체로 그린 값이라 틀렸다 — 실제 서체(Pretendard) + 숫자 모듈(tabular-nums)로 잰 값은 아래 「#321 재검토」 절. 줄 높이(67/66) · 금액 칸 · 행동 칸 자리는 고치기 전 기준값과 ±1px 안에서 같다(E2E 단언). 터치 기기는 title이 안 보이므로 이 한 줄은 `/design-review` 항목으로 남긴다.
- **#321 재검토(밑줄 회귀):** `.action .tertiary`의 `padding: var(--s-3) 0; margin: calc(-1 * var(--s-3)) 0`이 링크 상자를 글자 높이 25px가 아니라 49px로 키워 밑줄(border-bottom)을 상자 맨 아래, 곧 글자 아래 15px에 그렸다. 이유 칸이 `3 / -1`로 4번째 칸까지 넓어지자 그 자리가 이유 글자 줄이 되어 밑줄이 글자를 가로질렀다(320에서 건수 · 날짜가 취소선처럼 보임). 고침: `.action a.tertiary`에서 padding · 음수 margin을 빼고 `position: relative` + `::after { content: ""; position: absolute; inset: calc(-1 * var(--s-3)) 0 }`로 누르는 영역만 늘렸다(새 클래스 · 토큰 0). 선택자를 `.action .tertiary`가 아니라 `.action a.tertiary`로 좁힌 까닭: 결재 줄 열기 단추(`.phoneTap`, 같은 `.tertiary` 클래스)는 자기 `::after`가 `li:has(.phoneTap){position:relative}`를 기준으로 행 전체를 덮는데, 단추에 `position: relative`를 주면 그 범위가 단추 크기로 줄어든다.
- 실측(CI=true · mobile-375 / desktop · `--no-deps`): 링크 상자 높이 49 -> 25(홈 DOM), 밑줄과 이유 글자 겹침 375 · 320 모두 0(고치기 전 하네스 375 1건 · 320 3건, 실제 홈 375 1건), 누르는 영역(가운데 세로선 elementFromPoint 구간) 44 이상.
- 잘림 크기 상한(`KNOWN_CLIPPED_MAX_PX` · `TEN_DIGIT_CLIPPED_MAX_PX` · 실제 홈 시험): 실제 홈에서 잰 값 — 320 지급(오늘) 금액 9자리 4px, 10자리 15px, 375는 둘 다 0. 하네스에 Pretendard와 숫자 모듈을 얹어 실제 홈과 같은 값(4 · 15)이 나오게 맞췄고(금액 칸 폭 하네스 71 -> 78, 실제 홈 78), 상한을 넘으면 실패한다. 4px · 15px는 한 줄 CSS로 못 닫아 /design-review 항목이다(title은 있음).

- 완료 전 점검 줄: 처음에는 label 2줄 clamp(06-23 D-1) 때문에 320에서 짧은 이름도 2줄로 감겨 줄 전체 3줄이라 사용자 결정으로 올렸고, **사용자 결정(10/28 05:31Z, 코디네이터 전달 「사용자 카드 결정」)으로 다른 묶음 줄과 같은 꼴로 바꿨다** — label = 프로젝트 이름, 이유 칸 = `완료 전 점검 {n}건`(아래 표). 긴 이름은 D-1 clamp가 받아 label 2줄(이유 1줄)이다 — 줄 전체 3줄이 되는 경우는 이름이 한 줄을 넘을 때뿐이다.
