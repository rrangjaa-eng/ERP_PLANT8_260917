# 설정 묶음 링크 — 점검표
화면: app/(app)/admin/settings/
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §7-2(설정 자동 생성 화면) · §3 터치 목표 · g3-analysis.md §6 ④-1

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 이번 변경이 더한 글자는 묶음 이름 링크와 select 라벨 「묶음」뿐, 설명문 추가 없음(기존 내보내기 힌트는 범위 밖이라 그대로)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 값 없음·없는 이름이면 첫 묶음이 기본(resolveSettingsGroup 단위 테스트), 사용자가 고르는 것은 묶음 하나
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: PC는 링크, 폰은 select 하나만 보이고 다른 쪽은 display:none(e2e에서 폰 링크 줄 hidden 단언)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 설정 화면은 칸 즉시 저장형이라 주 버튼이 없고(SYSTEM §7-2), 이번 변경은 이동 수단만 더함
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험 동작 추가 없음
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 링크 줄과 select는 한 번에 한쪽만 보이고, 섹션 제목은 현재 묶음 하나만 그려 중복 제목이 줄었다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 없음(레지스트리에서 자동 생성)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 링크는 Tab·Enter, select는 네이티브 키 조작
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 코드표 선택 링크 줄(.tableNav/.toggle)과 같은 모양·같은 토큰

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 색·면 변경 없음, 결정 DR1(입력 있으면 「입력 버리기」 확인)을 링크·select 둘 다 같은 확인 창으로 지켰다
