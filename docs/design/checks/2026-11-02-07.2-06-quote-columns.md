## 지금 화면 기준(코드 전)
- 견적 표 열: 번호 · 소분류 · 항목 · 거래처 · 수량 · 단가 · 견적가 · 실행가 · 차익 · 상태 · 비고 · 행동 — 일수 · 고객 비고 · 중분류가 없고 견적가 = 수량 × 단가.
- 대분류 그룹 머리글은 소분류에서만 파생(저장 대분류 없음). 수수료 줄 종류 · 계산 패널 없음.
- 고칠 계획: UI-SPEC S4 열 순서 · 붙여넣기 순서를 열 key 배열 하나에서, 일수 P2 · 고객 비고 · 중분류 P3(1024 미만 접힘), 수수료 줄(S5 앞부분) · 옆 패널(SidePanel + PanelForm).

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자는 열 머리글(일수 · 내부 비고 · 고객 비고 · 중분류)과 오류 셀 `숫자 아님 · 1.5처럼`(UI-SPEC S4 error) 하나뿐. 새 안내 문단 0(quote-table.tsx diff에 설명문 없음). 계산 패널 글자는 라벨 `율(%)` · `기준`, 결과 한 줄 `기준 합 N · 수수료 M`(기준 합 0이면 `기준 합 0 · 기준 바꾸기`), 막힘 `율 없음 · 율 적기`, 오류 `숫자 아님 · 5처럼` — 모두 UI-SPEC S5 문구, 설명 문단 0
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 새 줄 일수 기본 1(newDraftLine `days: 1`), 견적가는 서버가 수량 × 단가 × 일수로 계산(셀 읽기 전용), 대분류는 머리글로 파생(저장값 ?? 소분류) — 고르는 칸 없음. 수수료 줄은 수량 · 일수 1 · 거래처 없음 · 실행가 0 · 소분류를 서버가 고정(normalizeForKind) — 사람이 고르는 칸은 항목 · 단가뿐. 계산 패널은 율 하나만 적고(기준 기본 `전체`) 기준 합 · 수수료는 표 값으로 계산(domain/quotes/commission · commissionAmount), 고객 비고가 비었으면 `{율}%`를 채운다. 율은 저장하지 않는다(E2E 「율은 저장하지 않는다」 — 줄 칸에 율 칸 0)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 일수 칸 단계는 서버 셀 판정(cells.days — 승인 · 정산 새 줄 · 연결 문서 · 견적 외 비용 · 조정 줄 잠김) 그대로 그린다. 「수수료 줄 추가」는 승인 차수 · 정산 · 1024 미만이면 렌더 0(E2E quote-line-kinds 「고객 승인 차수에는 … DOM에 없다」), 상한 300이면 비활성 + 상한 이유를 가리킨다. 수수료 줄 거래처 · 실행가 칸은 읽기 전용 `—`. 「계산」은 ≥1024 · 단가를 고칠 수 있는 수수료 줄만(승인 차수 렌더 0, E2E 768 · 375 DOM 0), 율이 비면 1차 「금액 채우기」 aria-disabled + `율 없음 · 율 적기`
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 1차는 기존 「일괄 저장」 하나 그대로, 새 열은 셀 편집뿐. 새 버튼은 2차 「수수료 줄 추가」 하나(UI-SPEC S5 · 444행 2차 줄) — 주 버튼 수 변화 0. 계산 패널 안 1차는 「금액 채우기」 하나(PanelForm 행동 줄: 2차 취소 Esc → 1차)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 삭제 경로 변경 0(기존 ConfirmDialog 그대로)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 폰 접힌 줄은 일수 ≠ 1일 때만 `{n}일`(1이면 그리지 않음 — summary null), 비고는 `내부 비고` / `고객 비고`로 갈라 같은 이름 두 열이 없다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: EMPTY 경로 변경 0(quoteTableEmptyState 그대로)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 새 열 셋은 격자 로빙 · Enter 편집 · Tab 이동 · 붙여넣기 열 순서(pasteColumns를 columns 열 key 배열 하나에서 만든다)에 들고, 행동 열은 그 밖(SYSTEM.md §7-3 (아)). E2E quote-table.spec 「일수 · 고객 비고 · 중분류 열」 · 「편집 중 Tab … 쪽 마지막 편집 셀(중분류)」. 「계산」 셀 3차는 로빙 밖(tabIndex -1)이고 키보드 경로는 그 줄 Ctrl+E(onOpenRow). 패널은 첫 포커스 율 · Ctrl+Enter 채우기 · Esc 닫기, 닫히면 그 줄 단가 칸 포커스(E2E 「금액 채우기 → … 포커스」 · 「Esc로 닫으면 … 포커스」)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 새 열 편집기는 기존 숫자 칸(NumericEditCell)과 글자 칸(textEditCell)을 그대로 쓴다. 「수수료 줄 추가」는 기존 줄 추가 버튼 묶음(styles.addLineButton) 안 같은 Button 컴포넌트. 「계산」은 행 행동 열의 RowAction(지출결의 올리기 · 거래처 고르기와 같은 3차 모양)
