## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: ReasonField가 새로 더하는 글은 자리표시 옵션 `사유 고르기` 하나(고르개 안 글)뿐이고 설명문 0. 오류는 기존 `사유 너무 김 · 500자까지` · `사유 없음 · 사유 적기` 그대로(행동 줄이 가진다). 칸 아래 안내 추가 0
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 항목을 고르면 글이 문구로 채워지고(직접 치지 않아도 됨) 덧붙임은 선택. 등록 항목 0이면 고르개 DOM 0이라 사용자가 고를 것이 없는 선택지를 보지 않는다. 결정 1개(무엇을 쓸까)가 0~1개(고르기)로
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 항목 0건 → select 렌더 안 함(숨김). 보관 · 비활성 항목은 reader가 제외. 제출 중에는 고르개 `aria-disabled` + 글 칸 `readOnly`
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 반려 확인 창 1차 `반려` 하나 그대로(행동 줄 변경 0), 지출결의 폼 1차 `지출결의 제출` 그대로. ReasonField는 버튼을 더하지 않는다
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이 플랜은 위험 동작을 새로 만들지 않는다. 반려 확인 창의 기존 모양 그대로(ConfirmDialog 행동 줄 변경 0)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 라벨 `사유`는 호출부 1개(글 칸에 건다)이고 고르개는 시각 라벨 없이 `aria-label="항목"` + 자리표시 `사유 고르기`. `기타`는 고정 옵션 1개이고 reader가 등록 항목 중 같은 label을 걸러 중복 없음
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음(빈 화면 신설 0). 사유 목록 0건은 글 칸만 서는 자유 입력(지금과 같은 모양)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 네이티브 select(타이핑 점프 · 방향키) + textarea Tab 순서(고르개 → 글). `기타` 선택 시 글 칸 포커스. 반려 창 Ctrl+Enter 제출은 ConfirmDialog 그대로
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 반려 · 선결제 · 희망 지급일 세 쓰임이 같은 `ReasonField` 하나. 코드표 3종은 기존 코드표 화면(`admin/code-tables`)을 변경 없이 그대로 쓴다
