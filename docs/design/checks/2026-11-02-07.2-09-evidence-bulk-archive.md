# 07.2-09 증빙 목록 다중 선택 보관 · 한 번 되돌리기 (X1 · S23) — 점검표

## 지금 화면 (손대기 전)
- 증빙 목록은 줄마다 행 행동 `보관`(확인 없이 즉시 + 결과 줄 `되돌리기`)뿐이라 잘못 올린 수십 건을 한 건씩 보관해야 한다.
- 1차는 필터 줄 오른쪽 끝 `공개 범위 저장 Ctrl+S` 하나. 1024 미만은 보기 전용(선택 · 편집 · 1차 없음).
- 이 PR이 더하는 것: 선택 열(`Table.selection`) · 표 앞 막대(`선택 N건` · 2차 `보관 N` · `?batch=`일 때 3차 `묶음 전체 고르기 N`) · 필터 줄 `aria-live` 결과 글자 + 3차 `되돌리기`.

## 원칙
- [x] 안내 문구: 새 설명문 없음. 남긴 글자는 막힘 이유(`붙은 문서 있음 · 먼저 떼기` · `저장 안 한 칸 · 먼저 저장` · `300건까지` · 서버가 돌려준 `다른 사람이 … 바꿈 · 새로 고침`)와 결과 글자(`HH:MM 보관 N건 · 막힘 N건` · `보관 실패 · 다시 시도`)뿐이다 — 근거: evidence-table.tsx COPY 항목 · 확인 창 · 도움말 · 자리 표시 설명 없음, E2E가 `dialog[open]` 0 단언
- [x] 결정 최소: 사용자가 정하는 것은 고르기뿐이다. 시각은 서버가 한국 시각으로 주고 보관 가능 줄 판정은 서버 `rowAction`이며 묶음 전체 id는 서버가 준다 — 근거: archiveEvidenceBatchAction이 `time`을 만들고 page.tsx가 `listArchivableEvidence`로 묶음 id · version을 읽는다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 붙은 줄 체크박스 `aria-disabled` + 이유, 보관된 줄은 칸이 비어 있고(hidden), 1024 미만은 선택 열 · 막대 자체가 없고, 저장 안 한 칸이 있으면 `보관 N` `aria-disabled` + 이유, 300 넘으면 `묶음 전체 고르기` 비활성 + `300건까지`
- [x] 주 버튼 하나: 화면 1차는 기존 `공개 범위 저장 Ctrl+S` 하나다. `보관 N`은 막대 2차이고 단축키가 없다(DC-8 · SYSTEM.md:973) — 근거: E2E가 `공개 범위 저장` 버튼 1개 · `보관 N`에 `kbd` 0 · `aria-keyshortcuts` 없음을 단단히 확인
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 보관은 확인 없이 되돌릴 수 있는 일이라 위험 색이 아니다(단건 행 행동 `보관`의 danger는 그대로). 되돌릴 수 없는 일은 없다
- [x] 같은 말을 두 번 하지 않는다 — 근거: 붙은 줄의 이유는 Table 선택 칸 이유(첫 칸 2행) 한 번만 쓰고 막힘 이유 줄(`blockedReason`)은 같은 글자면 null로 뺀다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 상태 · 빈 필터 결과 문구와 `전체 보기` · `필터 지우기`는 바꾸지 않았다(막대 · 선택 열은 줄이 있을 때만)
- [x] 키보드만으로 끝난다 — 근거: 표 안 Space(선택) → Shift+Tab(머리글 `이 쪽 전체 고르기`) → Shift+Tab(막대 `보관 N`) → Enter를 E2E가 통과, 막대는 DOM에서 표 앞(`compareDocumentPosition`), 표 안 Ctrl+Enter는 보관하지 않는다
- [x] 같은 종류의 행동은 같은 모양이다 — 근거: 막대 `보관 N`은 Button 2차, `묶음 전체 고르기`는 Button 3차, `되돌리기`는 단건 결과 줄과 같은 RowAction 3차
