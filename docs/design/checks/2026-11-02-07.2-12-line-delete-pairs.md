## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 지우기는 확인 창 문구를 없애고 상태 낱말 `삭제 예정`·`취소 예정`(StatusTag) 하나만 남겼다. 쌍은 항목 2행 `상대 {번호} {이름}`(사실)과 짝도 지워진다는 `상대 줄도 삭제` 한 줄(되돌릴 수 없는 일의 범위)뿐, 고르기 빈 목록은 `고를 프로젝트가 없습니다` + 다음 한 수. 서버 거부 문구(`상대 프로젝트 완료 · 조정 불가`)는 기존 합계 행 거부 자리 그대로.
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 짝 줄의 부호 · 금액 · 항목명 · 차수 · 순서는 서버가 정한다(domain/quotes/adjustment-pair.ts planPairWrites · pairedMoneyColumns). 사람의 결정은 상대 프로젝트 한 번 고르기뿐. 완료 프로젝트에서는 쌍을 만들 수 없으므로 고르기를 띄우지 않고 지금처럼 한쪽 조정 줄을 바로 더한다.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 완료 프로젝트 행은 `aria-disabled` + 2행 이유(E2E quote-adjustment-pair.spec.ts 1번 사례), 자기 프로젝트는 목록에 없다(같은 사례 · 0행), 권한 없는 계급은 `조정 줄 추가`가 없다(quote-line-kinds.spec.ts PM 사례). 지우기 표시 줄의 `되돌리기`는 편집 폭 · 지울 수 있는 줄에만.
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 표의 1차는 그대로 `일괄 저장 N`(지우기 표시 줄도 N에 센다 — quote-table.spec.ts S6). 고르기의 1차는 `이 프로젝트로 Enter` 하나.
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 지우기는 즉시 지워지지 않고 저장 전 표시 + 3차 `되돌리기`(확인 창 대신 되돌리기 — frontend.md). 저장 뒤에도 보관함 복원(쌍은 짝도 함께 복원). 새 색을 만들지 않고 muted 표시 + 취소선.
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 지우기 표시 줄은 상태 낱말 한 번 + 취소선 항목명, 되돌리기 버튼의 접근 이름 `{항목} 삭제 되돌리기`는 sr-only로만 앞말을 붙였다(보이는 글자는 `되돌리기`). 쌍 2행은 `상대` 한 낱말 뒤 번호 · 이름.
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 고르기 빈 목록은 PickDialog `emptyDefault` 사실 한 줄 `고를 프로젝트가 없습니다` 뒤 `emptyNextStep` 3차 `프로젝트 목록 보기`(새 탭 — 저장 안 한 표를 떠나지 않는다, counterpart-picker.tsx). 빈 목록 그리기는 PickDialog 공용 동작(dev-components.spec.ts 빈 목록 표본)이고, 이 화면의 빈 목록 E2E는 공유 시험 DB에서 조정 범위(회사 전체)가 빈 상태를 만들 수 없어 돌리지 않았다.
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: Delete로 지우기 표시, 다시 Delete로 되돌림(quote-table.spec.ts S6 · use-grid-keyboard onDeleteRow), 저장 안 한 새 줄은 Delete로 바로 사라진다. 고르기는 PickDialog(검색 · 방향키 · Enter · Esc — Esc 뒤 포커스가 `조정 줄 추가`로 돌아온다, E2E 1번 사례).
- [x] 리뷰 P2-3 — `삭제 예정` 줄은 고칠 수 없다(저장 때 보관되어 칸 값이 버려지므로): 칸이 읽기 전용이고, 그 줄의 칸 오류 · 충돌은 저장을 막지 않으며, 다시 Delete로 되돌리는 키는 그대로다 — 근거: quote-table.tsx `columns` · `pasteColumns`가 `pendingDelete === "delete"` 줄을 `readonly`/편집 불가로 낮추고 `quoteHasIssue`가 그 줄을 뺀다. 읽기 전용 칸의 Delete는 막힌 칸 경로(`onBlockedEdit`)로 오므로 누른 키를 함께 넘겨(use-grid-keyboard.ts · Table.tsx — 다른 표는 인자를 무시, 동작 그대로) 삭제 예정 줄의 Delete만 토글한다. E2E quote-table.spec.ts `(07.2-12 S6 · 리뷰 P2-3)` — `aria-readonly="true"` · Enter에 편집기 0 · 단가 칸 오류가 남은 채 저장 → 보관 · 합계 1000(CI=true), `(h · 07.2-12 S6)` Delete 두 번 토글 통과.
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: `되돌리기`는 표의 다른 행 동작과 같은 RowAction, `조정 줄 추가`는 형제 추가 버튼과 같은 3차 Button 그대로, 고르기는 다른 고르기 화면과 같은 PickDialog.
