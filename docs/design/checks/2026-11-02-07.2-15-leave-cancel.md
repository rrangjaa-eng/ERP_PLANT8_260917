## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글은 창 결과 줄 `결재 → {이름} · 승인 시 잔고 복귀`(누구에게 가고 무엇이 바뀌나) 하나와 막힘 자리(`사유 없음 · 사유 적기` · 서버 `이미 처리됨 · 새로 고침`)뿐. 입구 · 상태 칸에 설명문 0(cancel-request.tsx · page.tsx)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 결재자는 엔진 미리보기(previewLeaveCancel)가 고르고 창은 이름만 보인다 — 사용자 입력은 사유 한 칸(선택지 0, S18 「결정·문구 점검」)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 입구는 서버 판정(previewLeaveCancel 통과 · cancelState none · 취소 결재 없음 또는 엔진 resubmit 허락)일 때만 렌더 — E2E 팀장 화면 `취소 요청` 0 · 제출 뒤 0 · 취소됨 뒤 0. 사유가 비면 1차 aria-disabled(E2E 확인). 게이트 지적 반영: 취소됨 연차는 머리 줄 「인쇄」를 그리지 않고 인쇄 주소는 기존 404 막기를 재사용(새 문구 0, E2E 단언)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 승인된 문서는 1차 없음 · 2차 `취소 요청` 하나(S18), 창은 1차 `취소 요청` 하나 · 2차 `닫기`(ConfirmDialog 규칙). 반려 뒤는 3차 `취소 다시 요청` 하나
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 취소 요청은 결재를 거치는 요청이라 위험 색이 아니다. 2차 자리(PC 행동 줄 오른쪽 끝 · secondaryWrap)에 혼자 있고 회수 · 반려 모양은 바꾸지 않았다
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 창 부제는 `{종류} {기간}`만(제목이 이미 `연차 취소 요청`). 머리 상태 `취소 요청 중`과 결재선 지금 단계 `취소 요청 중`은 원 연차의 `결재 중` 머리 · 결재선 짝과 같은 기존 규칙(routeListSteps)을 따랐다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 해당 없음 — 빈 목록 · 빈 화면을 새로 만들지 않았다(문서 화면 행동 줄 · 목록 상태 낱말 · 목록 끝 묶음 `취소됨`만 — 빈 묶음은 기존대로 머리글째 없다)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 입구는 Button(Tab 도달) → 창 열면 사유 칸 첫 포커스 → Ctrl+Enter 제출 · Esc 닫기(ConfirmDialog). E2E 「기안자만 …」에서 사유 포커스 · Ctrl+Enter 제출로 통과
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 입구는 ui/button `secondary`(다시 요청은 `tertiary`), 창은 반려 · 회수와 같은 ConfirmDialog + ReasonField + decision-dialogs.module.css `.reason`
