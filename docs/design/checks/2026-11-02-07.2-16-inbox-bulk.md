## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 글자는 막힘 이유(`고른 건 없음` · `결재할 건 없음` · `100건까지` · `정산 결재 · 건별 승인` · 엔진 거부 원문)와 결과 줄(`HH:mm 승인 N건 · 막힘 N건`) · 실패 줄(`일괄 승인 실패 · 다시 시도`) · 라벨(`지난 반려` · `사후 추인`)뿐이다. 설명문 0(approvals-bulk.spec.ts · expense-inbox.spec.ts가 글자를 정확히 단언)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 막대 합계(지출결의 금액 · 연차 일수 · 잔여 초과 건수)와 사후 추인(상신일 > 행사 시작일)은 시스템이 계산하고, 고를 수 없는 행은 이유와 함께 막혀 있어 사용자가 판단할 것이 없다. 반려 사유만 묻는다(되돌릴 수 없는 일)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 정산 결재 · 101번째 행은 체크박스 aria-disabled + describedby 이유, 승인 막힘(approveBlockedReason) 행 · 처리함 행은 체크박스를 그리지 않음, 내 결재가 0이면 선택 열 자체가 없음(E2E `처리함 행만 있는 계정` 체크박스 0 · 막대 0). 일괄 반려는 단건 반려가 열린 행만 센다 — 본인 기안(본인 승인 차례)은 고른 채 승인에만 남고 막대 `반려 N`의 N · 반려 창 건수 · 보내는 행에서 빠진다, 반려할 행이 0이면 `반려` 버튼을 그리지 않는다(#377 리뷰 L1 · E2E `본인 기안 + 다른 사람 문서`)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 필터 줄 오른쪽 끝 1차 `승인 N` 하나(ListScreen 버튼 갈래), 막대 안 1차 0 · 2차 `반려 N`(E2E `bar … primary-button` 0 단언)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 일괄 반려는 1차와 떨어진 막대 오른쪽 2차이고 확인 창 + 사유 필수(빈 사유면 1차 aria-disabled `사유 없음 · 사유 적기`). 승인도 되돌릴 수 없어 확인 1회(D-7270)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 승인 막힘 이유가 이미 행에 있는 행은 체크박스를 숨겨 같은 이유를 두 번 쓰지 않는다. 사후 추인은 상세 머리 한 자리만(KvList 상신일 뒤 중복 표기 안 함 — 세 자리 각각 정확히 1회 E2E). 지출결의 목록 폰은 상태 칸 조각을 숨기고 접힌 줄 끝에만
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 결재할 건이 하나도 없으면 page.tsx가 기존 ListEmpty 그대로(1차 없음 · DR5), 표가 있을 때만 InboxTable이 1차를 그린다
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: Tab → Space → Ctrl+Enter(표 안 = 1차) → Ctrl+Enter(확인)로 일괄 승인 완료(approvals-bulk.spec.ts 105건 테스트), 결과 뒤 포커스 = 첫 막힌 행 체크박스 또는 1차(부분 성공 테스트)
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 1차는 ListScreen 버튼 갈래(Button primary), 2차 `반려 N`은 Button secondary, 막힘 이유의 `새로 고침`은 기존 선택 표 3차 링크(blockedLink) 그대로
