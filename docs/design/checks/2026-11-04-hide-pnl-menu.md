## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 셸 메뉴 항목만 바뀐다(「손익」 삭제 · 「리저브」 추가). 설명문 추가 0, 라벨은 짧은 명사 「리저브」
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 「리저브」 노출은 layout이 can(pnl view) ∧ visible(reserve.amount)로 계산한다. 사용자가 고를 것 없음
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 대장이 열리지 않는 계급(기획 PM · 노출 꺼진 계급)에는 「리저브」 항목 자체를 만들지 않는다(404로 가는 링크 없음, T-q-01). 단위 + E2E로 부재 단언
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 해당 없음 — 셸 메뉴 항목 목록 변경이고 화면 본문 버튼은 건드리지 않는다
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험 동작 추가 0
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 「손익」(자리표시자)과 「리저브」가 동시에 나오지 않는다. 폰 탭 3 「프로젝트」는 「더보기」 시트 차집합으로 시트에서 빠져 중복 없음(BottomTabs 변경 0)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 변경 0
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 레일 링크는 기존 `<a>` 그대로. keyboard-nav.spec.ts Tab 도달 순서(스킵 링크 → 워드마크 → 프로젝트 → 지출결의 → 법인카드 → 결재 → 사용자 메뉴)로 확인
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 「리저브」는 기존 1차 메뉴 항목과 같은 MenuLink(레일 `<a>`) 한 종류
