## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 종이에는 설명문이 없다(라벨·값·표·결재란뿐). 화면에 남는 글자는 오류 경계 「인쇄물 만들기 실패 ·」와 준비 전 한 줄뿐이고 확인증과 같은 문구다. 입구 「인쇄」는 라벨 한 낱말이다
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 열면 자동으로 인쇄 창이 뜨고(갈래 A) 서류 값 · 결재선 · 출력 일시는 모두 서버가 채운다. 사용자가 고를 것은 프린터뿐이다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 결재 인스턴스가 없는 작성 중 문서에는 「인쇄」 링크를 만들지 않고, 폰(<700)에서는 입구를 CSS로 숨긴다(PcOnly). 금액을 못 보는 계급의 종이에는 금액 열 · 세금 · 합계가 흔적 없이 빠진다
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 인쇄 라우트 화면 바의 1차는 「인쇄 · PDF 저장」 하나, 「닫기」는 3차. 상세 화면의 1차 버튼 수는 바뀌지 않고 「인쇄」는 기존 「종결」과 같은 2차다
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험 동작 추가 0
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 기안자 행을 두지 않고 결재란 첫 칸 「기안」이 같은 정보를 맡는다. 상태 글자는 번호 줄에만 있다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 404는 확인증 인쇄와 같은 「페이지 찾을 수 없음」 + 「첫 화면으로」 버튼. 그 밖 빈 화면 추가 0
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 화면 바는 버튼 둘(Button 컴포넌트, Tab 순서 = 닫기 → 인쇄 · PDF 저장)이고 종이는 읽기 전용이다. 표 편집 없음
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 입구 「인쇄」는 이동 링크이고 기존 2차 버튼 클래스(btn secondary)를 그대로 쓴다(holidays 선례 — 이동은 링크, §7-1)
