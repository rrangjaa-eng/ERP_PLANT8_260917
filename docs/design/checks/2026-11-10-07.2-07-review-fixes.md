# 07.2-07 ReasonField 리뷰 지적 수정 — 점검표
화면: ui/reason-field/, app/(app)/expenses/[id]/expense.module.css
기준: BRIEF.md · frontend.md 화면 사용성 원칙 · CHECKLIST.md §1 · SYSTEM.md §7-2 ReasonField

## 고치기 전
- `기타`를 고르면 직접 쓴 글까지 지워졌다(사용자 카드 답: 직접 쓴 글은 남기기). 항목 문구 교체가 maxLength를 넘길 수 있었다. 글을 모두 지워도 고르개가 이전 항목을 보였다. 폰에서 고르개 높이 40. 선결제 사유 읽기 줄이 줄바꿈을 뭉갰다.

## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 새 문구 0.
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 글을 지우면 고르개가 저절로 처음 상태가 된다.
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 변경 없음(locked 유지).
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 버튼 변경 0.
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험 동작 없음.
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 문구 추가 0.
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 빈 화면 변경 0.
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 네이티브 select/textarea 그대로.
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 변경 없음.

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 입력 칸 높이 40/행동 44(②)는 유지, 폰 select만 기존 textarea와 같은 --touch-min 규칙.

- [x] 새 색·서체·radius·그림자를 만들지 않았다(tokens.css 변수만) — 근거: 추가 CSS는 --touch-min과 white-space뿐, 새 클래스명 0.
- [x] 폰 320에서 가로 넘침 없음 · 터치 44px — 근거: 폰 breakpoint(699.98px) 안에서 select min-height --touch-min, E2E mobile-375 재실행.
- [x] 실제 앱 화면(PC 1280 · 폰 390)을 찍어 보고 확인했다 — 스크린샷 경로: 육안 판정 안 함(CLAUDE.md §6), E2E DOM 단언 몫.
