## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 인쇄 화면에는 안내문이 없고(제목 QUOTATION · 필드 라벨 · 표만), 차수 표에 더한 글자는 입구 `견적서 인쇄`와 상태 `보냄 MM-DD`뿐이다. 줄 0 차수의 비활성 이유 `줄 없음 · 줄 만들기`는 잠김 이유 한 줄(플랜 S8 empty)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 번호(`{프로젝트 번호}-{차수}`) · 고객사 · 행사명 · AE · 소계 · 합계는 서버가 채우고 계산한다. 사용자가 고르는 것은 `인쇄 · PDF 저장` 한 번뿐이다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 금액 비노출 · 읽기만 · 완료 · 보관 프로젝트에는 입구 DOM이 없고(서버 요약 `printable`), 375px 폭에서는 `PcOnly`로 숨긴다. 줄 0 차수만 비활성 + 이유 (E2E quote-revisions 07.2-10 블록)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 인쇄 화면 바의 `인쇄 · PDF 저장`이 주 버튼, `닫기`는 보조(공용 PrintBar 그대로). 차수 표 입구는 기존 tertiary 버튼 꼴 하나
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 이 화면들에는 삭제·되돌릴 수 없는 동작이 없다(읽기 + 인쇄 기록 1건)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 인쇄 본문은 라벨 12개가 각 1회(E2E `getByText(label, {exact:true})` toHaveCount(1)). 상태 칸의 `보냄`은 StatusTag 낱말 하나 + 날짜뿐이다
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 줄 0 차수는 인쇄 화면 대신 입구 자체가 비활성이고 이유가 `줄 만들기`로 다음 행동을 가리킨다
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 입구는 `<a>`(Tab · Enter), 인쇄 화면 바는 버튼 둘(Tab · Enter). 편집 표가 아니라 읽기 화면이다
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 입구는 07.4 지출결의 `인쇄` 새 탭 링크 꼴(`target=_blank` `rel=noopener` `prefetch=false`, `buttonLinkClassName("tertiary")`)을 그대로 따랐다. 이동이 아닌 동작 칸 버튼(승인 증빙 · 차수 열기)과 나란히 같은 tertiary 모양이다

## 사용자 결정(§1)
- [x] §1의 결정을 하나도 어기지 않았다(웜톤 · 견적 엑셀식 · 옆 패널 · 스킨 A …) — 근거: 인쇄 화면은 흰 종이 바탕 + 공용 인쇄 토큰만 쓰고 웜톤이 없다. 견적 줄 입력 화면은 건드리지 않았고(읽기 투영만), 새 패널·모달이 없다. 상태 배지 `보냄`은 기존 StatusTag muted 변형 한 칸 추가(⑤ 상태 배지 고정과 같은 방식)
