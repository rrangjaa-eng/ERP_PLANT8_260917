## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 더한 글자는 머리글(칸 이름) · 셀 값 · 거르개 라벨(칸 이름) · 첫 옵션 「전체 {칸 이름}」 · 폰 요약 조각 `{칸 이름} {값}`뿐, 설명문 · placeholder 0. 값 없음 「—」, 보관 선택지 `{값} (보관됨)` 상태 글자. 필터 중 EMPTY는 기존 「조건에 맞는 프로젝트가 없습니다」 + 「필터 지우기」 그대로(새 문구 0)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 열 · 검색 키 · 거르개는 서버가 「보이는 활성 칸」 집합 하나로 정한다(사용자가 열 · 검색 대상을 고르지 않음). 검색 칸 · 문구 무변경 — 같은 키워드로 추가 칸도 찾는다
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 안 보이는 · 보관 칸은 열 · 거르개 · 검색에서 서버가 뺀다, 거르개 옵션은 활성 선택지만, 칸 0개면 거르개 · 열 DOM 0. 추가 칸 머리글은 정렬 링크 없음(정렬할 수 없다 — Issue 13)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 「프로젝트 등록」 1차 그대로, 거르개는 제출 버튼 없이 select 변경 즉시 제출(기존 필터 select와 같은 동작), 내보내기 버튼 0(D-7511)
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험 동작을 더하지 않음(목록 읽기 열 · 필터 select만)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 거르개 라벨 = 칸 이름, 첫 옵션 「전체 {칸 이름}」은 기존 「전체 상태」 · 「전체 팀」과 같은 꼴(값 빈 옵션의 이름)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 거르개 결과 0건은 기존 필터 중 EMPTY(「필터 지우기」 링크) — `isUserFiltered`가 추가 칸 거르개를 센다
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 거르개는 네이티브 select(`<label for>` 연결 · 키보드 선택 즉시 제출 · 기본 포커스 링), 목록은 읽기 표
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 추가 칸 거르개는 같은 필터 줄의 기존 select 꼴(`selectLabel` · `select` 클래스 그대로) — 새 클래스 0
