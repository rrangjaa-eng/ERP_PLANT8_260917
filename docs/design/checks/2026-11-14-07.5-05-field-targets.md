## 원칙
- [x] 안내 문구: 화면의 모든 설명문을 셌다. 남긴 것은 오류·되돌릴 수 없는 일·잠김뿐이고 명사형 한 줄이다 — 근거: 더한 글자는 대상 링크 글자 셋(거래처 · 프로젝트 · 견적 줄)과 패널 제목 앞 대상 이름뿐 — 설명문 · placeholder 0. 대상별 EMPTY는 기존 「등록된 화면 항목이 없습니다 · 화면 항목 추가」 그대로(새 문구 0)
- [x] 결정 최소: 알 수 있는 값은 기본값으로 채웠고, 시스템이 계산할 것을 묻지 않는다 — 근거: 대상은 폼 입력 칸이 아니다 — 지금 고른 링크(`?target=`)가 등록 제출 객체에 실린다. 없거나 모르는 값은 거래처. 정렬 순서 기본값은 그 대상 활성 정의로 계산(`nextSortOrder(activeDefs)` — 목록이 대상별)
- [x] 할 수 없는 선택지는 숨기거나 비활성화했다 — 근거: 수정 패널에 대상 변경 길 없음(수정 입력 스키마가 target 거부) · 대상이 하나뿐이면 링크 줄 DOM 0(조건 코드 `FIELD_DEFINITION_TARGETS.length > 1`)
- [x] 주 버튼 하나: 이 화면의 다음 행동이 주 버튼 하나로 보인다 — 근거: 1차는 기존 「화면 항목 추가」 하나(고른 대상에 추가) · 대상별 EMPTY면 DR5 A대로 EMPTY 액션 하나. 대상 링크는 3차 `.toggle`
- [x] 위험한 동작(삭제 등)은 떨어뜨려 두고 위험 색이다 — 근거: 위험 동작을 더하지 않음(행 「삭제」 = 보관은 04.5 그대로)
- [x] 같은 말을 두 번 하지 않는다(라벨과 칸 안 글자, 태그와 줄 등) — 근거: 「대상」 열을 두지 않는다(현재 링크가 말한다). 패널 제목 「프로젝트 화면 항목 추가」와 제출 버튼 「화면 항목 추가」는 04.5 제목 · 버튼 관계 그대로(대상 이름만 제목에). 복원 알림 이름 접두 — 그대로: `복원 · 프로젝트 · 비고 복원됨`은 「·」가 두 번 서지만 기존 `복원 · {name} 복원됨` 꼴에 접두 이름이 들어간 것뿐이라 새 문구를 만들지 않는다(eng C-9 · UI-SPEC 문구표 S7)
- [x] 빈 화면은 설명보다 첫 행동 버튼이 먼저다 — 근거: 대상 0건이면 ListEmpty + 「화면 항목 추가」(그 대상 `?target=…&new=1`), 대상 링크 줄은 EMPTY에서도 보인다(0건 가드는 「보관 포함」 토글에만 — eng C-7)
- [x] 키보드만으로 끝난다(표는 엑셀 키 구성) — 근거: 대상 링크는 `next/link` 앵커 — Tab · Enter · 기본 포커스 링(새 포커스 규칙 0). 필터 줄 Tab 순서 = 대상 링크 셋 → 「보관 포함」 → 1차
- [x] 같은 종류의 행동은 같은 모양이다(링크·버튼 섞지 않음) — 근거: 대상 링크 · 「보관 포함」 모두 같은 `.toggle` 3차 링크, 현재 대상만 `aria-current` 강한 글자(거래처 「갈래」 · 코드표 선례와 같은 값)
