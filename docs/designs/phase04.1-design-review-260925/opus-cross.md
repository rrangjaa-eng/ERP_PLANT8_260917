- 관점: 폰으로 결재하는 팀장 · 처음 연차를 내는 신입 · 관리자. "처음 쓸 때 막히는 곳 / 틀린 선택이 가능한 곳 / 문서끼리 어긋나는 곳 / SYSTEM.md에 없는 걸 슬쩍 만드는 곳"

## 패스 1 — 정보 구조 (처음 점수 7/10)
- 화면마다 첫눈에 보이는 순서는 좋다: S1 잔고 줄 → 필터·1차 → 상태 그룹(UI-SPEC:232-245), S4 `내 결재` 먼저(UI-SPEC:327), S3 KvList → 결재선 → 행동 줄(UI-SPEC:289-302).
- 감점: S1에서 연도 하나를 **세 자리**에 적는다 — 부제 `2026 회계연도` + 필터 `[2026 ▾]` + EMPTY `2026 회계연도에 …`(UI-SPEC:234,237,196). P0 「같은 사실 두 자리 금지」(UI-SPEC:181)와 충돌한다.
- 감점: 제목 구분자가 화면마다 다르다. 문서 화면은 `연차 — 종일 …`(UI-SPEC:289), 시트·결재함은 `연차 · 종일 …`(UI-SPEC:350,211).
- **10이 되려면:** S1에서 연도는 한 번만 보이고(select), 제목 구분자를 하나로 맞춘다.

## 패스 2 — 상태 (처음 점수 6/10)
- 좋은 점: 상태 표가 47행(UI-SPEC:426-488)이고, 잔여 초과를 「막힘이 아님」으로 가른 것(UI-SPEC:280)이 정확하다.
- 감점 ① UI-SPEC은 S3 로딩이 「해당 없음 — 서버 초기 렌더」라고 한다(UI-SPEC:437). 그런데 05 T3은 `app/(app)/leave/[id]/loading.tsx`로 뼈대를 만든다(05-PLAN:313 files, :321). 두 문서가 서로 다른 말을 한다.
- 감점 ② 처리함 행을 폰에서 탭했을 때의 상태가 두 문서에서 다르다(UI-SPEC:351 대 05-PLAN:47). 아래 X-01.
- 감점 ③ 제출 중 「나머지 버튼」 상태가 계약마다 다르다. UI-SPEC:284·360과 §7-17은 `aria-disabled`, 05-PLAN:48·218·275는 실제 `disabled`다. 아래 X-03.
- 감점 ④ 회수 결과 줄 `결재 멈춤 · 김팀장의 결재함에서 빠짐`(UI-SPEC:217)에서 담당이 여럿(`이수아 외 2명`)이거나 없을 때(`담당 없음`)의 모양이 정해져 있지 않다.
- **10이 되려면:** 위 네 가지를 UI-SPEC 한 곳에 확정하고, 플랜은 그 줄만 가리키게 한다.

## 패스 3 — 사용자 여정 (처음 점수 6/10)
- **신입(연차 신청):** 더보기 → 계정 → 연차(A1, CEO 리뷰 IA 확정 `plant8-erp-phase04.1-ceo-review-260924.md:556`) → `/leave` → `연차 신청` → 폼.
  - 폼에서 막히는 곳: 종류·시간 select에 공용 `ui/select`가 **항상** `—` 옵션을 먼저 그린다(`ui/select/Select.tsx:29`). 종류 `—`나 반차 시간 `—`를 고르면 무엇이 보이는지(칸 구성, 막힘 문구)가 UI-SPEC 어디에도 없다(UI-SPEC:201-204에 `종류`·`시간` 막힘 문구가 없다).
  - 하루짜리 종일 연차도 시작일·종료일을 **둘 다** 적어야 1차가 켜진다(UI-SPEC:203,277 「하루면 같은 날」). 종료일 = 시작일을 기본값으로 채우지 않는다.
- **폰 팀장(결재):** 하단 탭 결재 → `내 결재` 행 탭 → 시트 → `승인`. 흐름은 짧고 좋다.
  - 그런데 승인한 행이 `처리함`으로 내려간 뒤 **같은 행을 다시 탭하면 동작이 바뀐다**. 시트가 아니라 `/leave/[id]`로 이동한다(05-PLAN:47,218). UI-SPEC:351(시트, 행동 줄 없이)과 반대다.
- **본인 승인(팀장이 기안하고 자기 승인 설정 = `본인 승인`):** 행동이 `승인` + `회수`로 **UI-SPEC에 없는 다섯 번째 갈래**다(05-PLAN:50,218,275 대 UI-SPEC:307-312·193). 이 경우 PC 결재함 행에 3차 `회수`가 `승인` 바로 옆에 붙는다.
- **반려당한 신입:** 반려 문서는 `/leave` 맨 위 그룹에 남고(UI-SPEC:250), 다시 신청 말고는 나갈 길이 없다. 회수는 결재 중에만 된다(02-PLAN:66, UI-SPEC:311). 다시 내지 않기로 한 문서가 그해 내내 「다시 신청할 것」 자리에 고정된다.
- **10이 되려면:** select의 `—`와 기본값을 정하고, 처리함 탭과 본인 승인 갈래를 UI-SPEC에 확정하고, 반려 문서의 종착 위치를 결정한다(패스 7).

## 패스 5 — SYSTEM.md·토큰 정렬 (처음 점수 7/10)
- UI-SPEC이 참조하는 토큰 29개가 전부 `tokens.css`에 있다(검사함). 새 색·서체·radius는 0개다. A1~A4는 DECISIONS → SYSTEM 순서를 지킨다.
- 위반·이탈:
  - (X-03) 제출 중 나머지 버튼을 실제 `disabled`로 만든다. Phase 4 §7-17(`origin/…e1nzgu:SYSTEM.md:1073` 「나머지 `aria-disabled`」)과 UI-SPEC:284·360에 어긋난다.
  - (X-07) 반려 사유 칸 「긴 칸 480」이 480 모달 안에 들어가지 않는다. 실물은 라벨 96 + `1fr`, `width:100%`다(`sheet-modal.html:134-136`).
  - (X-08) S9에 UI-SPEC에 없는 요소가 플랜에서만 생긴다(연도 링크 · 월차 옵션 빠짐 + 한 줄).
  - (X-15) `—`의 뜻이 둘로 갈린다. §7-15에서는 「고를 것 없음/비어 있음」(SYSTEM.md:985)인데 설정 3단 계급에서는 「계급 조건 없음」이다.
- **10이 되려면:** 위 넷을 UI-SPEC 또는 SYSTEM 개정 제안(A-계열)으로 올리고 화면 하나만의 모양을 0으로 만든다.

## 패스 6 — 반응형(1024·375)·접근성 (처음 점수 6/10)
- 좋은 점: P1 3열 + 접힌 줄, 폰 행 44, 700 경계에서 모달↔시트, 포커스 복귀, 숨긴 caption, 상태를 글자로 전달(UI-SPEC:466-471).
- 감점 ① 실제 `disabled`는 누른 버튼의 포커스를 `body`로 떨어뜨린다. 키보드 사용자가 `Ctrl+Enter`로 승인하면 위치를 잃는다(X-03).
- 감점 ② 폰 결재함 행을 「행 링크」라고 부르지만(UI-SPEC:159,343) 실제로는 시트를 여는 트리거다. 역할과 `aria-haspopup="dialog"`가 정해져 있지 않다(X-17).
- 감점 ③ 태블릿(≥700) 결재함 행의 3차 `승인`·`반려`가 32px 높이로 붙어 있다(UI-SPEC:341). SYSTEM:193의 44는 폰에만 걸린다. 규정 위반은 아니지만 터치 기기에서 즉시 승인이 오탭될 위험이 있다(X-11·X-23).
- **10이 되려면:** pending 규칙을 §7-17대로 되돌리고, 폰 행 트리거의 역할을 명시하고, 태블릿 행 행동의 간격 또는 행동 자체를 정한다.
