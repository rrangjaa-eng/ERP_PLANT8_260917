### 2. 발견 (심각도 · 근거 · 고칠 것)

**F1 [critical] 「경품 1개 가액」이 한 행사에 하나인데 경품명은 당첨자 줄마다 다르다 — 담당자가 답할 수 없는 결정**
- 근거: P15:68 · P15:485(칸 하나) · UI-SPEC I2 예시 표(한 행사에 `갤럭시 탭 S10` · `스타벅스 기프티콘`, UI-SPEC:477 · :479 — I3 예시, E2 예시 :325) · P15:502(「세무 확인 4 — 운영 기준은 사용자 · 세무가 정한다 · 화면에 안내 문장을 더하지 않았다」).
- 문제: 1등 · 2등이 섞인 행사에서 담당자는 어느 경품 값을 적을지 모른다. 싼 쪽을 적으면 과세 대상에게서 주민번호를 받지 못하고, D-B2 (a)로 첫 제출 뒤 잠겨 되돌릴 수 없다. 규칙이 계획 밖(운영)에만 있으니 화면이 사람을 틀린 행동으로 이끈다(frontend.md 「사용자 결정 최소」 위반). 「가액」의 기준(구입가 · 시가 · 부가세 포함)도 정해지지 않았다.
- 고칠 것(사용자 결정 필요 — U2에 안 (c) 추가): ① 가액을 당첨자 표의 줄 칸으로(경품명이 줄 칸이니 가액도 줄 칸 — 판정이 이미 당첨자 단위라 모델이 맞다) 또는 ② 최소한 라벨에 규칙을 넣는다 `가장 비싼 경품 1개 가액` — 안내 문장 없이 라벨이 규칙을 말한다. 기준(구입가 등)은 세무 확인 뒤 라벨 보조 글자(`labelSub`)로.

**F2 [high] I3 「가액 저장」 2차 버튼 + 새 §6-2 규칙이 기존 SYSTEM 규칙과 부딪힌다**
- 근거: P15:390(섹션 칸 + 2차 「가액 저장」 · `Enter` = 저장) · P15:251(§6-2에 「속성 하나만 고치는 칸 = 섹션 안 칸 + 2차 저장」 규칙 추가) vs `docs/design/SYSTEM.md:1076`(「이미 1차를 가진 화면 안에 섞인 칸은 `Form.Actions` 없는 단일 칸 폼 — 제출은 그 화면의 1차 「일괄 저장 Ctrl+S N」 하나, dirty면 N에 1칸으로 합류 · 화면별 예외가 아니라 일반 규칙」) · `SYSTEM.md:835` §7-3 (사) · `SYSTEM.md:845` 끝(「일괄 저장은 표 밖 편집 칸이든 표 셀이든 N ≥ 1이면 항상 렌더」).
- 문제: 한 화면에 저장 경로가 둘 — 가액과 당첨자를 함께 고친 뒤 `Ctrl+S`를 누르면 가액은 저장되지 않는다(이탈 경고 · dirty 셈에 가액이 드는지 계획에 없음). 판정 줄이 DTO의 저장된 수량으로 계산돼 표에서 고친(미저장) 수량과 어긋난다(P15:390 「`page.tsx`가 상세 DTO 당첨자의 `quantity` 목록을 넘긴다」). 이미 있는 규칙을 두고 새 규칙을 만드는 것은 「화면 하나만 예외」의 변형이다.
- 고칠 것: D-B1에 안 (c)를 올린다 — 가액 칸은 §7-15 단일 칸 폼으로 1차 「일괄 저장 N」에 합류(한 트랜잭션, 잠금 순서 = 행사 행 먼저), 판정 줄은 표의 현재(미저장 포함) 수량으로. 2차 버튼 · 새 §6-2 줄 · CHECKLIST §1 이탈 기록이 모두 필요 없어진다. 자리는 표 바로 위(판정 줄이 표를 설명하므로), QR 아래 첫 자리는 비운다.

**F3 [high] E4에서 주민번호 칸이 「왜 받는지」보다 먼저 나온다**
- 근거: `app/c/[token]/intake-flow.tsx:1021`(RrnFields) → `:1059`(ConsentBlock, 서명 바로 위) · P14:382(자리 · 모양 「지금 그대로」).

- 고칠 것: 새 문장 · 새 부품 없이 기존 패턴을 쓴다 — 주소 칸의 `labelSub`(`택배로 보내 드립니다`)처럼 주민번호 라벨 옆에 `세무 신고용` 한 조각(R 변형만). 안내 블록 위치는 그대로.

**F4 [high] N 변형 요약이 세법 신고가 없는 수령자에게 「법령에 따라 · 법정 신고기한」을 말한다**

- 문제: 3만원 경품 수령자에게 「세무 신고」는 빠졌는데 「법령에 따라 받습니다 · 법정 신고기한이 지난 날부터」는 남아 스스로 모순된다 — 읽는 사람은 「그럼 세금 대상인가?」를 묻게 된다. 법무 판단 이전에 문장이 자기 설명을 못 한다.
- 고칠 것: D-A2는 (b) 쪽을 권한다(UX 근거). (a)로 가더라도 N 요약에서 `법령에 따라`는 뺀다.

**F5 [high] 화면 비활동 타이머(U4)와 서버 판정이 다른 것을 센다 — 정정 중 저장이 로그인으로 튕긴다**
- 근거: P14:325(화면 타이머는 누름 · 키 · 입력마다 다시 건다) · P14:321(서버는 `privacy_session_activity` — 개인정보 요청 때만 갱신).
- 문제: 10:00에 I4를 열고 전화로 수령자와 확인하며 35분 동안 칸을 고치면 화면 타이머는 계속 살아 있지만, 「고친 내용 저장」 순간 서버는 35분 무활동으로 보고 세션을 지운다 → 로그인 → 고친 값이 사라진다(개인정보라 보관도 못 한다). 사용자는 「계속 일하고 있었는데」 쫓겨난다.

**F6 [high] 비활동 이동 뒤 「뒤로」가 개인정보 화면을 되살린다**
- 근거: P14:325(`window.location.assign`) · P14:67(「브라우저 뒤로 가기의 클라이언트 캐시 복원은 0」 — 복원이 기록 없이 일어남을 계획이 이미 인정).

- 고칠 것: `location.replace` + I4 · 인쇄에 `pageshow`(`event.persisted`면 다시 불러오기). E2E: 이동 뒤 `page.goBack()` → 이름 글자 0개.

**F7 [medium] 첫 접근 판정 만료가 ERP 세션 전체를 지운다 — 다른 탭의 미저장 편집이 함께 날아간다**

**F8 [medium] 로그인 뒤 되돌아가기가 기록에 로그인 화면을 남긴다**

### 3. 빠진 상태
- I3 가액: pending(저장 중) · 이탈 경고(dirty) 합류 여부 · 표 미저장 수량과의 동기 — 미정(F2 · F9).
- I4: 비활동 이동 직전 경고 없음(의도로 보이나 미저장 정정이 사라진다는 사실을 계획에 명시) · 뒤로 복원(F6).
- 인쇄: 비활동 이동이 인쇄 미리보기 중이면? 타이머가 멈추는지 명시 없음(낮음).
- E4: 경합으로 판정이 바뀌어 E3로 돌아갈 때 수령자가 보는 줄이 「만료」 일반 문장뿐 — 드물어 수용 가능, 계획에 명시만.
- 로그인: `next`가 거부됐을 때(→ `/account`) 이유 줄은 남는데 목적지가 다르다 — 수용 가능, 명시만.

### 4. 사용자 여정 끊김 요약
1) 담당자: I2에서 1 · 2등 경품이 섞인 가액을 적을 기준 없음(F1) → I3에서 가액 · 표를 함께 고치고 `Ctrl+S`하면 가액 누락(F2).
2) 수령자: 주민번호 칸에서 이유 없이 멈춤(F3) → N 변형 안내가 「법령 · 신고기한」으로 혼란(F4) → 문의 전화 탭 불가(F10).
