## 패스별 발견

### Pass 1 — 정보 구조

### Pass 2 — 상호작용 상태
- **F-1 (새로 찾음, D1로 묶음) 재시도 불가 원인에 「다시 시도」.** `formReason`(08 L150)은 원문에 「 · 」가 없으면 무조건 「 · 다시 시도」를 붙인다.
  - 08 L37·L110·L132·L200: 등록 중 권한 회수 → 「추가할 수 없음 — 권한 없음 · 다시 시도」(OPEN 1-A).
  - 02 L203·L207: 수정 대상 없음 → 「수정할 수 없음 — 화면 항목 없음 · 다시 시도」(OPEN 2-B).
  - 06 L28·L130: 거래처 수정 중 보관 → 원문이 `domain/vendors/index.ts:301` 「보관되었거나 존재하지 않는 거래처는 수정할 수 없습니다.」이므로 화면은 「수정할 수 없음 — 보관되었거나 존재하지 않는 거래처는 수정할 수 없습니다. · 다시 시도」 — 「수정할 수 없」 중복 + 문장 중간 마침표 + 성공할 수 없는 다음 행동. 권한 회수 시에도 「수정할 수 없음 — 거래처 수정 권한이 없습니다. · 다시 시도」(`domain/vendors/index.ts:292`). 06 E2E(L130)가 이 문구를 **단언**하므로 그대로 두면 테스트가 결함을 고정한다.
  - §8 규칙 3(「원인 · 다음 행동」)과 CLAUDE.md §7(「무엇을 하면 되는지를 말한다」) 위반. → **U1(사용자 결정)**.
- **1-B** 거래처 폼 이유 자리 요약이 기본 칸 「이름」을 세지 않으면, 이름만 비운 제출에서 1차 옆이 비고 칸 아래에만 오류가 나온다(06 L99·L107). SYSTEM.md 992행 「필수인데 비면 제출 버튼이 이유를 말한다」와 어긋남 → D3.
- 5-A·5-B: 기존 문구 재사용은 적절. 커스텀 숫자·날짜 칸은 네이티브 `type=number/date`라 브라우저가 형식 오류 값을 빈 값으로 바꿔 보내므로(`vendor-form.tsx:227-229`) 타입 오류 문구는 정상 화면에서 거의 나오지 않는다. 5-B는 위조 요청에서만 나온다 → 수용.
