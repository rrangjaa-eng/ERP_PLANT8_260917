   **결과:** 편집 후 완료로 전환하면 방금 입력한 내용을 저장할 수 없게 됩니다. 자정 자동 정산도 같은 종류의 막힘을 만듭니다. **수정:** 수동 전환은 미저장 편집 처리 후 허용하고, 외부·자동 전환으로 거부되면 바뀐 상태와 영향받은 칸을 알리며 입력 복사·복구 경로를 남기십시오.

5. **high — ‘수익금’이 첫 분할 발행 순간 다른 의미의 숫자로 바뀐다.**  
   발행 줄이 하나라도 생기면 견적 전체 대신 누적 발행액에서 실행가 전체를 뺍니다. 합계 수익률도 두 기준을 섞지만 합계에는 그 구성이 드러나지 않습니다. [04-UI-SPEC.md:1010](.planning/phases/04-project-quote-ledger/04-UI-SPEC.md:1010), [979](.planning/phases/04-project-quote-ledger/04-UI-SPEC.md:979)  
   **결과:** 견적 1억·실행가 8천만인 프로젝트가 3천만만 발행하면 `+2천만`에서 `−5천만`으로 바뀝니다. PM은 수익성 악화로 읽습니다. **수정:** 계산 정책을 유지하더라도 `견적 기준 예상이익`과 `발행 기준 차액`을 구별하고, 합계에 혼합 기준임을 표시하십시오. 목록에도 `원화·공급가액`을 명시해야 합니다.

6. **high — 계산 결과가 상한을 넘는 ERROR 상태가 없다.**  
   계획은 입력 금액의 범위 오류를 설명하지만, 수량×단가의 계산값 초과는 DB 오류로 남긴다고 명시합니다. [04-UI-SPEC.md:1101](.planning/phases/04-project-quote-ledger/04-UI-SPEC.md:1101), [04-40-PLAN.md:362](.planning/phases/04-project-quote-ledger/04-40-PLAN.md:362)  
   **결과:** 각각 허용되는 수량 3·단가 10억원을 입력해도 일괄 저장 전체가 실패하며 고칠 칸을 알 수 없습니다. **수정:** 계산값 상한도 셀 오류로 정의하고 `견적가가 저장 상한을 넘습니다 · 수량 또는 단가를 고쳐 주세요`와 실제 상한을 표시하십시오. 13자리 표시 폭과 한 값의 저장 가능 범위도 구분해야 합니다.

7. **high — S6의 375px 설계는 ‘3열이니 들어간다’는 가정이다.**  
   날짜·금액·메모를 모두 P1로 두면서 외화와 공급가액을 같은 보조줄에 붙이고 3행은 금지합니다. 최대 숫자·메모에 대한 실제 배치 규칙이 없습니다. [04-UI-SPEC.md:480](.planning/phases/04-project-quote-ledger/04-UI-SPEC.md:480), [1216](.planning/phases/04-project-quote-ledger/04-UI-SPEC.md:1216)  
   **결과:** 긴 외화·환율·공급가액 조합에서 가로 넘침이나 숫자 잘림으로 계약을 깨게 됩니다. **수정:** 폰은 날짜·금액을 주 열로, 메모를 접힌 줄로 보내십시오. 외화와 공급가액은 각각 독립된 값 묶음으로 줄바꿈하고, 숫자 자체만 꺾지 않는 규칙으로 바꾸십시오.

8. **medium — 폰 첫 화면은 업무 우선순위 없이 컨트롤을 쌓는다.**  
   목록 필터는 전부 `flex-wrap`, 상세 버튼도 전부 유지한 채 아래로 내립니다. [04-UI-SPEC.md:952](.planning/phases/04-project-quote-ledger/04-UI-SPEC.md:952), [437](.planning/phases/04-project-quote-ledger/04-UI-SPEC.md:437)  
   **결과:** 현장에서 프로젝트를 찾고 금액을 확인하려는데 필터·긴 부제·복사 버튼부터 스크롤합니다. **수정:** 폰에서는 검색·현재 필터 요약을 앞에 두고 상세 필터를 펼치게 하십시오. 상세는 프로젝트명·상태·기간을 우선하고 복사·차수 작업은 추가 행동으로 묶으십시오. 표의 P1/P2 전략을 화면 전체에도 적용해야 합니다.

9. **medium — 등록 폼의 Esc가 입력 전체를 버리는 단축키다.**  
   명세는 오류 뒤 값 보존만 정하고, 계획은 Esc를 즉시 목록 이동으로 연결합니다. dirty 확인이나 등록 초안 복원은 없습니다. [04-UI-SPEC.md:429](.planning/phases/04-project-quote-ledger/04-UI-SPEC.md:429), [04-08-PLAN.md:149](.planning/phases/04-project-quote-ledger/04-08-PLAN.md:149)  
   **결과:** 선택 메뉴를 닫으려던 Esc로 프로젝트명·기간·예상가까지 잃습니다. **수정:** 내부 컨트롤이 Esc를 먼저 처리하고, 변경된 폼을 닫을 때만 입력 버리기 확인을 제공하십시오. 빈 폼은 즉시 닫아도 됩니다.

10. **medium — ‘총 매출 예상가’는 입력 후 확인할 곳이 없다.**  
    등록에서 받지만 계획은 상세에 표시 자리가 없다고 명시합니다. [04-UI-SPEC.md:1040](.planning/phases/04-project-quote-ledger/04-UI-SPEC.md:1040), [04-15-PLAN.md:177](.planning/phases/04-project-quote-ledger/04-15-PLAN.md:177)  
    **결과:** PM은 저장 여부·환산 결과를 검증할 수 없고 오입력을 바로잡을 수도 없습니다. **수정:** 상세 기본정보에 같은 라벨과 외화·환율을 표시하고 수정 경로를 정하십시오. 현재 차수 견적 합계와는 별도 값으로 보여야 합니다.

11. **medium — 코드표 설명은 오류가 나면 고쳐야 할 입력을 지운다.**  
    40자 초과나 저장 실패 시 서버 값으로 되돌리도록 명세와 계획이 모두 지시합니다. [04-UI-SPEC.md:539](.planning/phases/04-project-quote-ledger/04-UI-SPEC.md:539), [04-10-PLAN.md:140](.planning/phases/04-project-quote-ledger/04-10-PLAN.md:140)  
    **결과:** 41자를 쓴 사용자가 한 글자를 줄이는 대신 문장 전체를 다시 작성해야 합니다. **수정:** 실패한 입력을 유지하고 오류·재시도·서버 값으로 되돌리기를 제공하십시오. blur 저장의 진행·성공 상태도 해당 칸에서 구별해야 합니다.

12. **medium — 연도와 기간의 교집합이 비는 상태를 ‘검색 결과 없음’으로 처리한다.**  
    올해가 기본 선택인데 기간은 그 연도와 교집합으로 적용됩니다. 계획도 다른 연도 기간을 입력하면 빈 결과를 반환합니다. [04-UI-SPEC.md:960](.planning/phases/04-project-quote-ledger/04-UI-SPEC.md:960), [04-17-PLAN.md:188](.planning/phases/04-project-quote-ledger/04-17-PLAN.md:188)
