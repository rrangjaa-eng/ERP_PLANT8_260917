## 이 값들은 PLANT8의 값이다

이 폴더의 값은 **시스템의 규칙이 아니라 PLANT8이라는 회사의 값**이다. 나중에 다른 회사에서 이 시스템을 쓸 수 있게 하기 위해, 회사별 값은 코드에 박지 않고 세 층으로 나눈다.

| 층 | 어디 사는가 | 다른 회사에서 | 이 폴더의 예 |
|---|---|---|---|
| **마스터 데이터** | DB 행 | 화면에서 새로 입력 | 조직·사람·계급 이름, 거래처, 클라이언트, 법인카드, 견적 분류, 지급 방식, 증빙 종류, 공휴일 표, 권한표·노출표 값, 알림 규칙 |
| **설정 키 기본값** | 코드 registry에 default 한 줄, 값은 DB | 설정 화면에서 변경 | 세율·절사·기준일, 지급 기한 60일, 마감 14시, 알림 09시, 선결제 14일, 문서 번호 서식, 매출 기준, 연도 귀속, 연차 회계연도 |
| **코드** | 코드 | **코드 수정 필요** | 세금 규칙 종류 4가지, 알림 조건 종류, 결재 단계 정의 방식(계급 × 조직 범위), 프로젝트 상태 전이, 비용 우선순위, 팀 손익 공식, 조직 2계층(본부 > 팀), 공휴일 생성 규칙 |

**확장 방식 = 인스턴스 복제** (사용자 결정 2026-09-18). 회사마다 배포를 하나씩 띄운다. 배포 하나에 여러 회사를 담는 멀티테넌시는 **하지 않는다** — 모든 표에 `company_id`, `scopeFor()`에 회사 경계, 누수 스캔·백업·이전에 회사 단위 분리가 필요해 Phase 3·8이 크게 불어난다. 회사 10곳 이상을 내다볼 때만 값이 있고, 지금 프로젝트의 가장 큰 위험은 "또 너무 많이 만드는 것"이다(PROJECT.md).

**이미 있는 것**: OPS-01(배포 스크립트 한 번으로 새 GCP 프로젝트에 기동, 프로젝트 ID·리전·DB는 환경 변수)과 ADMN-06(설정을 JSON으로 내보내 빈 환경에 가져오면 같은 동작)이 이 메커니즘을 이미 요구한다. PROJECT.md는 그 목적을 "재해 복구·스테이징 재현"으로 적었지만 다른 회사에 쓰는 것과 **같은 메커니즘**이다.

**Phase 3에서 할 일 하나**: 시드를 코드에 박지 말고 `seeds/plant8.json` 파일로 분리한다. ADMN-06의 설정 JSON 내보내기가 이미 그 형태라 사실상 공짜다. 다른 회사는 `seeds/회사B.json`을 만든다.

**기술보다 큰 제약 — 업종**: 이 시스템의 뼈대는 "프로젝트(행사) 하나에 견적 줄이 있고, 지출은 반드시 견적 줄에서만 올라온다"이다. BTL 대행사·이벤트사·건설사처럼 **프로젝트 단위로 원가를 잡는 회사**에는 그대로 맞지만, 제조업(제품 원가)·SI(공수 기반)·유통에는 맞지 않고 설정으로 고칠 수 없다. 한국 세무 제도(부가세·원천징수·세금계산서·근로기준법 연차) 종속은 다른 한국 회사라면 문제가 없고, 해외 회사라면 위 표의 '코드' 층을 다시 짜야 한다.
