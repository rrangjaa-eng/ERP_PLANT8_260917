## 1. 프로젝트 상태 — ⚠ 요구사항 보강 후보

**사용자 결정**: 수주중 → 진행 → 완료(정산), 그리고 수주실패.

| 상태 | 뜻 | 그때 쓴 돈은 |
|---|---|---|
| 수주중 | 제안·PT 단계. 아직 수주 안 됨 | 그 프로젝트의 **수주 비용**으로 자동 분류 |
| 진행 | 수주 확정, 실행 중 | 프로젝트 비용. **수주중일 때 쌓인 비용도 그대로 프로젝트 비용이 된다** |
| 완료(정산) | 잠김, 새 지출 불가 | — |
| 수주실패 | 수주 못 함, 닫음 | 그 비용이 **팀 손익의 수주 실패 비용**으로 내려간다 |

**왜 이렇게 정했나**: PROJECT.md는 "수주 실패 비용(제안·PT 등, **수주되면 프로젝트 비용**)"을 이미 요구한다. 그런데 수주 단계를 담을 그릇이 없으면 그 비용을 팀 이름 지출로 올린 뒤 수주 성공 시 사람이 하나씩 찾아 프로젝트로 다시 연결해야 한다. 상태 하나를 더 두면 상태만 바꿔서 비용이 따라 움직인다.

**현재 요구사항과의 차이 (계획 때 반영 필요)**

| 문서 | 지금 적힌 것 | 보강할 것 |
|---|---|---|
| PROJ-04 | "진행 → 완료(정산)" 2단계 | 수주중·수주실패 2개 상태 추가 |
| EXP-08 | 수주 실패 비용을 "프로젝트 없이 팀 이름으로" 올린다 | 수주중 프로젝트에 붙는 경로를 더한다 (팀 이름 경로는 프로젝트가 아예 안 열린 건을 위해 남긴다) |
| PNL-07 | 팀 손익 = 프로젝트 합 − 수주 실패 비용 − 관리비 | "수주 실패 비용" = 수주실패로 닫힌 프로젝트의 비용 합으로 정의를 굳힌다 |
| ROADMAP Phase 4 기준 4 | 진행 → 완료 전환 | 수주중 → 진행 전환과 수주중 → 수주실패 전환을 게이트에 더한다 |

**계획 때 정할 남은 것**
- 수주중 프로젝트에 프로젝트 번호를 언제 매기나 (등록 시 vs 진행 전환 시). 등록 시 매기면 수주 실패분이 결번이 된다 — 결번 허용은 이미 확정 규약이다(ROADMAP Phase 4 기준 1)
- 수주중 상태에서 지출결의를 올릴 수 있나. 고객 승인 게이트(아래 3)와 충돌하므로 수주중에는 게이트를 어떻게 적용할지 정해야 한다
- 수주실패 → 진행으로 되살릴 수 있나 (뒤늦은 수주)

## 4. 매출 칸 (확정 — 다시 묻지 않음)

계약 금액 · 세금계산서 발행일 · 발행액 · 입금일 · 입금액 (PROJ-03).

- 계약 금액·발행액은 **공급가액**으로 적고 부가세·합계는 서버가 계산

## 5. 문서 번호 서식 — 260907 안 채택

| 문서 | 서식 | 부여 시점 |
|---|---|---|
| 프로젝트 | `26001` (연도 끝 두 자리 + 순번) | 등록 시 (수주중 단계 포함 여부는 위 1 참조) |
| 견적 | `26001-1차` | 차수 생성 시 |
| 지출결의 | `26001-0001` (전사 통합 순번) | **제출 시** |
| 지출결의 — 일반관리비 | `26GA-0007` (가름 글자 GA, 영문 고정, 지출결의와 같은 순번 통) | 제출 시 |
| 구매 요청 | `26001-C0001` (C = 법인카드, 별개 순번 통) | **생성 시** (취소해도 안 뺌) |
| 구매 요청 — 일반관리비 | `26GA-C0007` | 생성 시 |
| 법인카드 사용 | `26001-K0001` (K, 구매 요청과도 별개 순번) | 생성 시 |

출처: 문답 (260907 서식 채택). 규칙: 가름 글자는 반드시 영문. 서식을 바꿔도 이미 매긴 번호는 유지(앞으로만 적용). 프로젝트 번호는 재사용하지 않는다.

**인트라넷과의 호환**: 인트라넷 사내번호도 `26xxx` 형식이라 직원이 이미 익숙하고, 이전 문서 번호를 옛 id에서 결정적으로 파생시킬 때(MIG-01) 서식이 맞는다.

## 8. 견적 외 비용 줄
